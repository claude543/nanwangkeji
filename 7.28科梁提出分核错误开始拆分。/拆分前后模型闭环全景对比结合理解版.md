# 0. 先给出最终结论

拆分前后的**控制目标和主要物理对象没有改变**，真正改变的是实时计算的组织方式。

拆分前：

```text
顶层
├─ sm_circuit        ← 几乎全部实时电气对象、六台设备、上层控制都在这里
└─ sc_display        ← 上位机显示
```

拆分后：

```text
顶层
├─ SM_Master         ← 公共10 kV网络、PCC、高压侧边界、上层控制
├─ SS_Slave          ← EV1 + EV2低压功率级、本地控制、PWM
├─ SS_Slave2         ← ESS1 + ESS2低压功率级、本地控制、PWM
├─ SS_Slave3         ← PV1 + PV2低压功率级、本地控制、PWM
├─ SC_Console        ← 显示、调试，不参与目标机闭环
└─ 18条差分Stubline ← 连接SM与三个SS的真实电气边界
```

最核心的变化可以压缩成四句话：

1. **原来一整台设备都在 `sm_circuit` 内；现在每台设备在变压器低压绕组端被切开。**
2. **真实三相电气功率跨任务依靠 PMIOPort + 顶层差分 Stubline；普通控制数据跨任务依靠 Memory + OpComm。**
3. **六套快速本地控制器/PWM基本没有改变，只是从原设备子系统中移动到了三个SS，并把隐藏的 `GridOn` 改成显式输入。**
4. **PCC、Supervisory、PVmax、SOC、基础AGC仍在SM；六台设备实际功率Pmeas从SS重新反馈回SM。**

当前 K10 已经形成完整的纯 RT-LAB 本地闭环：

```text
PCC测量
→ MATLAB基础AGC
→ 六路Pref
→ 三组24维SM→SS通信
→ 六套本地Control System
→ PWM
→ 六台Two-Level Converter
→ Stubline
→ 变压器/馈线/公共母线
→ PCC重新测量
```

同时，当前模型仍保留 V3.2 验收所需的 400xx/401xx 模型接口和双方心跳逻辑，但 **40101～40114目前仍是验收测试源，并未正式替换为真实PCC、PVmax、SOC和六路Pmeas**。因此当前 K10 的准确定位是：

> **物理实时模型、本地AGC闭环和V3.2安全框架均已跑通，但真实V4点表输入尚未正式接入。**

# 第一篇 先建立理解：能量流 → 控制信号流 → 分层

## 一、从"能量流"串一次：以PV2为例

先完全不考虑控制，只看电是怎么走的。

以一台设备为例，比如PV2。

### PV2物理能量流

从设备往电网送电时：

```text
PV直流能源
    ↓
Two-Level Converter
    ↓
SS中的逆变器侧测量 inv
    ↓
L1/C1等低压滤波网络
    ↓
SS低压边界V-I Measurement
    ↓
SS中的Delta(D1)三相节点
    ↓
6个PMIO端点
    ↓
3条差分Stubline
    ↓
SM侧三只单相变压器低压绕组端点
    ↓
磁耦合到10 kV高压侧
    ↓
prim_PV2 ABC
    ↓
prim_PV2 abc
    ↓
PV2line
    ↓
设备公共母线
    ↓
PCC ABC
    ↓
PCC abc
    ↓
断路器 / Grid
```

这就是一条完整物理能量通道。

---

## 二、为什么每台设备要6个PMIO，而不是3个

因为我们不是简单把：

```text
A
B
C
```

三根相线切开。

官方模板采用的是：

```text
每相低压绕组两个端点都跨任务传递。
```

所以三相：

```text
A_pos
A_neg

B_pos
B_neg

C_pos
C_neg
```

总共：

```text
6个端点
```

每相通过一条：

```text
2 with differential inputs Stubline
```

因此每台：

```text
3条Stubline
6个PMIO
```

六台：

```text
18条Stubline
36个SM PMIO
```

当前任务级物理映射已经固定。

---

## 三、为什么SS要重新组成Delta(D1)

因为变压器低压侧原来是：

```text
Delta
```

但我们把三只单相变压器的低压绕组两个端点全部穿过Stubline拿到了SS。

于是SS必须重新接成：

```text
A节点 = A_pos + C_neg
B节点 = A_neg + B_pos
C节点 = B_neg + C_pos
```

所以这里不是随便"两个端点并一下"。

它是在重建：

```text
三角形绕组闭环
```

**确切端口映射**（对应第二篇 §八 "SS中为什么还要重新接Delta"）：

第一台设备：

```text
Port1 + Port6  → A
Port2 + Port3  → B
Port4 + Port5  → C
```

第二台：

```text
Port7  + Port12 → A
Port8  + Port9  → B
Port10 + Port11 → C
```

**红线：** 如果把同一个绕组的正负端直接接到同一点，就等于错误短接；如果交叉顺序错误，会改变相序和Delta相移。所以Delta修正属于**物理拓扑**，不是显示问题。

---

## 四、控制信号流：SM把"电网侧眼睛"送给SS

现在完全不看电能，来看信息怎么跑。这是与能量流平行的另一个闭环。

### 4.1 SM先测设备当前状态

每台设备高压侧：

```text
prim_device
    ↓
Vabc = 3维
Iabc = 3维
```

同时SM还有上层控制量：

```text
Fref
Vref
Droop_On
Pref
Qref
GridOn
```

于是每台组成12维：

```text
device_io12 =

[Vabc_A
 Vabc_B
 Vabc_C

 Iabc_A
 Iabc_B
 Iabc_C

 Fref
 Vref
 Droop_On
 Pref
 Qref
 GridOn]
```

### 4.2 同类两台合成24维

例如EV组：

```text
EV2_io12
+
EV1_io12
      ↓
EV_io24
```

ESS：

```text
ESS1_io12
+
ESS2_io12
      ↓
ESS_io24
```

PV：

```text
PV1_io12
+
PV2_io12
      ↓
PV_io24
```

**确切块名**（对应第二篇 §十一）：SM中形成

```text
EV1_IO_Mux12 + EV2_IO_Mux12
→ EV_Group_Mux24
→ EV_IO_Memory24
→ ev_io_vec

ESS1_IO_Mux12 + ESS2_IO_Mux12
→ ESS_Group_Mux24
→ ESS_IO_Memory24
→ ess_io_vec

PV1_IO_Mux12 + PV2_IO_Mux12
→ PV_Group_Mux24
→ PV_IO_Memory24
→ pv_io_vec
```

### 4.3 SM把24维送到对应SS

结构：

```text
SM内部24维向量
      ↓
Memory / 状态边界
      ↓
SM Outport
      ↓
模型顶层普通Simulink通信线
      ↓
SS Inport
      ↓
SS OpComm
```

**顶层连接**（对应第二篇 §十一）：

```text
SM out3 ev_io_vec  → SS_Slave
SM out4 ess_io_vec → SS_Slave2
SM out5 pv_io_vec  → SS_Slave3
```

**注意两条通道，永远不要混为一谈：**

```text
普通数值信号走 OpComm。

电气能量走 Stubline。
```

项目任务级拆分从一开始就固定了这两类跨子系统连接方式。

### 4.4 进入SS以后怎么拆

例如SS_Slave有：

```text
EV2 + EV1
```

24维进入：

```text
SS Inport
 ↓
OpComm
 ↓
Demux [12 12]
```

得到：

```text
EV2_io12
EV1_io12
```

然后每个12维再：

```text
Demux
[3 3 1 1 1 1 1 1]
```

还原成：

```text
Vabc
Iabc
Fref
Vref
Droop_On
Pref
Qref
GridOn
```

这就是每个控制器真正收到的信息。

### 4.5 Memory为什么必须放在24维输出前

如果SM当前100 μs步刚算出的信号要求SS在**同一个步**立即使用，同时SS当前步的电气结果又反过来影响SM，就可能形成任务直接依赖，RT-LAB无法并行调度。

Memory使发送量变成已经确定的上一时步状态：

```text
SM在第k步计算 C[k]
Memory在第k步输出 C[k-1]
SS第k步使用 C[k-1]
```

所以：

```text
Group_Mux24
→ Memory
→ SM Outport
```

**不是为了模拟网络故障，而是为了任务时序解耦。** 同理，SS返回Pmeas前也使用Memory，目的也是让SS→SM普通数值反馈不形成当前步直接传递。

## 五、SS的Control System内部在干什么

从功能层面可以理解成：

```text
Vabc / Iabc
    ↓
PLL / 频率相位识别
    ↓
P/Q测量
    ↓
Droop / 功率控制
    ↓
电压/电流控制
    ↓
调制量
    ↓
PWM
    ↓
g
    ↓
Two-Level Converter
```

具体内部还有dq变换、PI等控制结构，但对当前全局理解，你需要先记住：

```text
SM给SS的是"测量 + 参考值"；SS控制器把它变成"PWM门极脉冲"。
```

## 六、低层闭环：SM与SS如何共同构成一个闭环

PWM改变：

```text
g
```

于是：

```text
Two-Level Converter开关状态改变
```

于是：

```text
交流输出改变
```

然后经：

```text
滤波器
→ Delta
→ Stubline
→ Transformer
→ prim
→ feeder
→ PCC
```

产生新的：

```text
Vabc
Iabc
Ppcc
Pmeas
```

然后下一周期又重新送回控制器。

所以低层闭环实际是：

```text
             ┌──────────────────────┐
             │                      ↓
SM prim测量 → 24维通信 → SS控制器 → PWM
   ↑                               ↓
   │                           Converter
   │                               ↓
   └← Transformer ← Stubline ← AC输出
```

这就是：

```text
SM和SS共同构成一个闭环。
```

并不是：

```text
SM算SM
SS算SS
彼此独立
```

## 七、AGC在哪一层：只产Pref，不产PWM

AGC在SM里，是比六台设备本地控制器更上层的控制。

它不直接产生PWM。

AGC只产生：

```text
Pref
```

当前六路：

```text
PV1 Pref
PV2 Pref
ESS1 Pref
ESS2 Pref
EV1 Pref
EV2 Pref
```

### 本地AGC的完整闭环

从PCC开始：

```text
PCC V-I Measurement
        ↓
      Ppcc
        ↓
     SM AGC
```

AGC同时接：

```text
Ptarget
PVmax1
PVmax2
SOC1
SOC2
Enable
```

然后计算：

```text
六路Pref
```

于是：

```text
AGC Pref
   ↓
device_io12
   ↓
24维
   ↓
SS Control System
   ↓
PWM
   ↓
Converter
   ↓
实际设备功率改变
   ↓
Stubline / Transformer
   ↓
PCC功率改变
   ↓
新的Ppcc
   ↓
AGC下一次计算
```

这就是完整的：

```text
PCC上层功率闭环。
```

## 八、两层嵌套闭环：100μs快环与1s慢环

非常重要。现在模型里其实嵌套了两层闭环。

### 快速低层闭环

在100 μs实时框架中不断运行：

```text
设备V/I
→ PLL/功率/电压/电流控制
→ PWM
→ Converter
→ 新V/I
```

### 慢速上层AGC闭环

每1 s更新：

```text
PCC
→ AGC
→ Pref
→ 六设备
→ PCC
```

所以：

```text
低层控制器
负责"把设备功率指令执行出来"

AGC
负责"六台设备应该分别执行多少"
```

不要把这两层混在一起。

## 九、Supervisor在哪：SM上层的Fref/Vref

Supervisor仍位于SM上层。

目前统一：

```text
Droop_On：3 s投入

Supervisor Ctrl_On：5 s投入
```

Supervisor根据系统状态形成例如：

```text
Fref
Vref
```

然后这些也进入：

```text
device_io12
```

发送给SS控制器。

因此SM并不是只有AGC。

SM上层大概可以理解成：

```text
PCC / Grid measurement
        ↓
 ┌───────────────┐
 │ Supervisory   │ → Fref/Vref
 │ AGC           │ → Pref
 │ PVmax         │
 │ SOC           │
 │ 状态/通信     │
 └───────────────┘
        ↓
六台device_io
        ↓
3组24维
        ↓
3个SS
```

## 十、六路Pmeas从哪里回来

六台设备各自的最终实测有功：

```text
PV1_Pmeas
PV2_Pmeas
ESS1_Pmeas
ESS2_Pmeas
EV1_Pmeas
EV2_Pmeas
```

是在设备控制/测量链中形成的最终measurements数据。

然后通过普通数值观测链返回SM/SC，用于：

```text
观察实际执行；
后续40109～40114；
论文状态失配研究。
```

当前基础AGC不使用这六路Pmeas。

也就是说当前AGC是：

```text
PCC反馈
+
内部历史命令
```

不是：

```text
PCC
+
六台实际Pmeas
```

这正是后续论文会改进的地方。

## 十一、SC在哪：为什么SC坏了不影响闭环

SC不在电气能量闭环里。

也不直接控制PWM。

它是：

```text
观察层。
```

现在主要：

```text
SM信号
 ↓
SM Outport
 ↓
SC Inport
 ↓
SC OpComm
 ↓
Demux
 ↓
Scope / Display
```

因为当前AGC控制路径是：

```text
SM内部PCC
→ SM内部AGC
→ Pref
→ SS
```

没有经过：

```text
SC
```

所以之前SC出现：

```text
15 s的Enable
看成40 s
```

Target上的真实AGC仍然15 s正常执行。

这就是为什么我们最后可以明确说：

> SC是观察者，不是控制闭环参与者。

正式Target记录同样从SM的AGC_CORE_MUX23直接分支到OpWriteFile，不经过SC。

## 十三、一台设备的完整循环：EV1从Pref到PCC的11步

以EV1为例。

假设当前：

```text
EV1 Pref = -0.6 pu
```

### 第1步：SM准备EV1的参考和测量

SM中：

```text
prim_EV1
→ Vabc
→ Iabc
```

再加：

```text
Fref
Vref
Droop_On
Pref=-0.6
Qref
GridOn
```

形成：

```text
EV1_io12
```

### 第2步：EV1和EV2合成24维

```text
EV2_io12
+
EV1_io12
↓
EV_group_io24
```

### 第3步：传到SS_Slave

```text
SM Outport
→ 顶层普通通信
→ SS Inport
→ OpComm
→ Demux
```

重新得到：

```text
EV1_io12
```

### 第4步：EV1控制器计算

控制器看到：

```text
我要 -0.6 pu
现在V是多少
现在I是多少
当前频率/相位是多少
Droop是否投入
```

然后计算控制量。

### 第5步：PWM驱动EV1逆变器

```text
Control System
→ PWM
→ g
```

## 十六、为什么必须从一个SM拆成1SM+3SS

原六逆变器模型把以下计算全部集中在一个实时任务中：

```text
公共电网
PCC
线路
六台变压器
六台开关级变流器
六套LC滤波器
六套PLL/功率环/电流环
六套PWM
Supervisory
AGC
测量
通信仿真
策略
```

即使给原单SM内部SSN配置多个CPU核，也不能把所有普通Simulink控制计算自动变成多个独立实时任务。

此前实测已经证明：

```text
六逆变器单任务约 970～981 μs / 步
目标基本步长只有 100 μs
```

所以真正要解决的问题不是再调整一个参数，而是：

> **把一个巨大实时任务拆成多个可以并行执行的目标机任务。**

最终选择：

```text
SM_Master：公共网络和上层逻辑
SS_Slave：两台EV
SS_Slave2：两台ESS
SS_Slave3：两台PV
```

现在每个100 μs周期内，SM和三个SS是**并行任务**，不是：

```text
SM算完 → SS1算 → SS2算 → SS3算
```

四个任务都使用已经确定的上一时步边界状态计算当前步，因此可以并行。

## 十九、为什么旧三相变压器要拆成三台单相变压器

旧的三相Yg/Delta变压器只向外暴露：

```text
高压A/B/C
低压a/b/c
```

内部六个低压绕组首尾端已经封装，无法在每个绕组两端插入差分Stubline。

K10中每台设备改用三只 `Multi-Winding Transformer`，分别表示A、B、C三个单相绕组。

模型本体确认六台设备共18只单相变压器，参数完全一致：

```text
NominalPower       = [110000/3, 50]
NominalVoltages    = [10000/sqrt(3), 480]
WindingResistance  = [0.0015, 0]
WindingInductance  = [0.03,   0]
Rm = 200
Lm = 200
```

这里：

- 三相总容量110 kVA按三相分成 `110000/3 VA`；
- 10 kV是线电压，高压Y接单相绕组承受 `10000/sqrt(3) V`；
- 低压Delta每个绕组承受480 V；
- 变压器第二绕组内部R/L设为0；
- 原本应存在于这一侧的串联阻抗由Stubline承担，避免重复。

## 二十、18条Stubline究竟是什么，不是什么

K10模型本体确认18条Stubline参数完全相同：

```text
Phases = 2 with differential inputs
pu     = on
Rpu    = 0.0015
Lpu    = 0.03
Sbase  = 110000/3
Vbase  = 480
Fbase  = 50
Ts     = 1e-4 s
```

每台设备3条：

```text
A相：A_pos / A_neg
B相：B_pos / B_neg
C相：C_pos / C_neg
```

所以：

```text
6台 × 3相 = 18条Stubline
```

Stubline不是普通Simulink信号线，也不是简单的"延时块"。

它承担两件事：

1. 维持SM侧与SS侧真实电气电压、电流和功率关系；
2. 给电气网络引入可被ARTEMiS识别的状态边界，打断SM和SS在同一100 μs时刻互相等待的直接代数依赖。

因此：

```text
Vabc/Iabc通过OpComm传过去
```

**不能替代Stubline**。

Vabc/Iabc只是控制器看到的数字；Stubline才让SS变流器注入的实际电流能够反过来改变SM中的变压器、馈线和PCC。

## 二十二、原六台设备的10 kV馈线拓扑有没有被改变

## 二十四、prim测量为什么非常关键

拆分前每台完整设备内部都有一个高压侧 `prim` 测量。

拆分后，这个测量被明确留在SM中：

```text
prim_EV1
prim_EV2
prim_ESS1
prim_ESS2
prim_PV1
prim_PV2
```

最终统一方向是：

```text
三只单相变压器高压端
→ prim_* 的 ABC侧

prim_* 的 abc侧
→ 馈线/公共母线
```

其Vabc/Iabc普通数值输出送给对应设备控制器。

曾经EV1错误接用了ESS1的Vabc/Iabc，导致EV1控制器看到的并不是自己的电气状态。现在已修正为：

```text
prim_EV1 → EV1控制
prim_ESS1 → ESS1控制
```

当前功率方向因此保持旧模型定义：

```text
PV发电        Pmeas > 0
ESS放电       Pmeas > 0
ESS充电       Pmeas < 0
EV充电        Pmeas < 0
```

**补充理解（来自《8.6发现prim方向问题理解》）：** prim不是只用于画图的测量块，它是低层控制器的反馈传感器。若方向接反，Pmeas符号翻转会形成闭环反馈符号错误，导致几十pu振荡（曾出现EV1/EV2 Pmeas mean ≈ -10.2 pu、瞬时几十pu）。Vabc对左右交换不敏感（A仍对a、B仍对b、C仍对c时），但Iabc符号和功率方向会跟着反；若相序也接错，PLL/dq变换会看到错误相位关系，问题更严重。所以必须同时保持：

```text
A ↔ a
B ↔ b
C ↔ c
```

以及整体参考方向一致。

## 二十六、Memory为什么必须放在24维输出前

已在第一篇§4.5讲清原理。补充关键结论：

```text
Group_Mux24
→ Memory
→ SM Outport
```

Memory使发送量变成已经确定的上一时步状态 `C[k-1]`，SS在第k步使用的正是该值，避免SM与SS在当前步互相依赖、RT-LAB无法并行调度。同理，SS返回Pmeas前也使用Memory，目的也是让SS→SM普通数值反馈不形成当前步直接传递。**这是任务时序解耦，不是模拟网络故障。**

## 二十八、SS内部现在真正做什么

以一台设备为例，SS中的闭环是：

```text
24维组通信
→ 拆出本设备12维
→ Control System
→ Vpwm
→ PWM Generator
→ 六路门极g
→ Two-Level Converter
→ inv测量
→ L滤波器/C滤波支路
→ 低压侧测量/Delta节点
→ Stubline
```

所以本地快速控制器和开关级功率器件被放在同一个SS中。

这个分配非常重要，因为PWM与Converter是最快的局部环节。如果把PWM留在SM、Converter放到SS，就会让高速门极控制本身跨任务，增加不必要的实时依赖。

因此现在的原则是：

```text
慢的上层决策在SM
快的设备本地控制+PWM+Converter在SS
```

## 二十九、六路Pmeas为什么必须从SS重新返回SM

拆分前，设备完整子系统就在同一个SM内，所以顶层可以直接从六个设备的 `measurements` 总线中选出Pmeas。

拆分后，真正的设备Control和功率级位于SS，因此Pmeas也在SS产生。

```text

→ Mux2

→ SS Outport
```

```text
→ ESS_Pmeas_vec2_to_SM

[PV1_Pmeas, PV2_Pmeas]
```

顶层反向连接：


SM内统一由 `OpComm3` 接收三组反馈，再恢复成六路。

这六路现在用于观察、Target记录和未来真实40109～40114；**当前基础AGC仍然不使用它们计算。**

## 三十五、旧AGC命令到设备与K10最大的区别

这是拆分前后上层控制链最重要的区别之一。

### 35.1 `shiyansan`

旧模型不是AGC直接把六路命令送设备。

路径是：

```text

→ 六路AGC原始命令
→ AGC_Modbus_RS485_Link
→ Modbus RTU编码/解码
→ RS485 delay
→ packet loss
→ CRC / Last Good
→ 六路decoded Pref
→ 六台设备
```

`AGC_Modbus_RS485_Link` 本身有28个输入、12个输出，并包含：

```text

RS485_Delay_Steps
RS485_Packet_Loss_Mask

6个packet loss Switch
```

它是以前离线通信异常试验的关键软件仿真层。

### 35.2 K10

K10已经把这套内部RS485/Modbus仿真层删除。

当前本地基线直接：

```text
MATLAB基础AGC
→ 六路Pref
→ 六个IO_Mux
→ Memory/OpComm
→ 三个SS
→ 六台设备
```

因此K10当前本地AGC闭环代表：

> **理想的模型内部上层命令路径 + 真实分核任务边界。**

这一步的目的，是先证明实时模型和基础AGC本身可以正确闭环。

以后V4/V5使用的是**真实外部板 + Modbus TCP**，所以不需要把旧 `AGC_Modbus_RS485_Link` 重新搬回K10。

## 四十七、当前基础AGC为什么即使不使用Pmeas也能闭环

基础AGC直接使用：

```text
PCC
PVmax
SOC
```

不使用六台Pmeas。

但设备真实Pmeas的物理作用最终都会汇总到PCC：

```text
AGC Pref
→ 设备真实出力变化
→ 六设备净功率变化
→ PCC变化
→ 下一AGC周期读取新PCC
```

所以它形成的是总量反馈闭环。

问题是：AGC知道PCC总结果，却不知道具体每台设备实际执行到哪里。

这正是后来出现长期PV/EV资源对冲，以及论文要研究"控制器历史命令状态与设备实测执行状态失配"的原因。

## 四十八、当前V4-shadow接入后模型会怎样变化

V4阶段不改变上述本地物理闭环。

板端未来会：

```text
RT-LAB 40101～40116
→ FC03
→ 板端V3.2状态机
→ C版基础AGC
→ 40001～40009
→ 加40010～40012
```

但是V4阶段：

```text

```

所以：

```text
MATLAB AGC → 六设备 → PCC
```

仍是真正的物理闭环；

而：

```text
真实测量 → 板端C AGC → 400xx
```

只是影子计算链，用于逐周期比较MATLAB与C的一致性。

## 五十一、拆分前后最容易产生的十个误解

**误解1：3个SS只是为了画面整洁**

错误。它们是三个独立目标机实时任务。

**误解2：Vabc/Iabc已经传给SS，所以不需要Stubline**

错误。Vabc/Iabc只是控制器数值输入，不能形成电气功率反作用。

**误解3：Stubline等于一根普通电线**

错误。它是有状态的ARTEMiS电气任务边界。

**误解4：Memory是模拟通信延时**

当前分核主通信中的Memory主要用于任务解耦，不是论文中的网络延时故障。

**误解5：SC是闭环的一部分**

当前K10不是。SC没有输出回SM，只负责观察。

**误解6：六台Control System因为分核被重写了**

没有。内部逻辑基本完全保留，主要只是GridOn显式化。

**误解7：六路Pmeas已经进入基础AGC**

没有。它们当前用于观察和未来状态重建。

**误解8：40101～40114现在已经是真实量**

没有。K10当前仍是V3.2验收测试源。

**误解9：以后板端联调完全不需要Modbus**

不准确。是不需要恢复旧内部RS485仿真模块，但真实RT-LAB Modbus TCP接口仍必须使用。

**误解10：15项策略没恢复，所以当前模型不完整**

对当前V4/V5主线不是。它们没有形成六设备最终控制仲裁，当前基础PCC闭环不依赖它们。

## 五十二、用一句完整因果链理解拆分后的K10

当前K10可以完整理解成：

```text
上级10 kV电网与六台设备通过旧模型一致的PCC和馈线拓扑相连；

SM_Master负责公共电网、PCC、六台高压侧prim和三台/设备的单相变压器，
同时负责Supervisory、PVmax、SOC、基础AGC及V3.2管理逻辑；

每台变压器的低压三个绕组六端通过6个PMIO暴露，
再通过顶层3条差分Stubline进入所属SS；

SS内按照D1重新组成Delta，保留原来的低压功率级、Control System、PWM和Converter；

SM将每台设备需要的Vabc、Iabc、Fref、Vref、Droop、Pref、Qref、GridOn打成12维，
同类两台合成24维，经Memory和OpComm送入对应SS；

SS根据这些给定控制两台开关级逆变器，真实电流再经Stubline反作用到SM中的变压器、馈线和PCC；

六台Control产生的最终Pmeas又通过SS→SM的Memory/OpComm反馈回来，
供SC、Target记录和未来40109～40114使用；

PCC有功重新进入SM中的基础AGC，形成1 s外层联络线有功闭环；

整个过程中SM、三个SS每100 μs并行计算，SC只观察，不参与闭环。
```
