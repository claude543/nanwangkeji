# 8.6 发现prim方向问题理解

## 一、先真正理解 Three-Phase V-I Measurement 是什么

MathWorks 的 Three-Phase V-I Measurement 是一个串联在三相电气线路中的测量元件，它同时提供：

```text
Vabc
Iabc
```

并具有六个电气端口：

```text
A B C
a b c
```

官方文档明确说明它用于测量三相瞬时电压和线电流，A/B/C与a/b/c都是三相电气 conserving ports。

先不要把：

```text
ABC = 输入
abc = 输出
```

理解成普通Simulink模块那种单向输入输出。

它实际上更像：

```text
       三相串联电流传感器

A ─────────────── a
B ─────────────── b
C ─────────────── c

        ↓
     Vabc
     Iabc
```

电可以：

```text
ABC → abc
```

也可以：

```text
abc → ABC
```

因为交流网络中的能量本来就可能双向交换。

ABC/abc真正重要的作用，是给这个传感器建立"测量参考方向"。

---

## 二、ABC和abc到底是什么意思？

这里必须把三个概念分开。

### 1. A/B/C 和 a/b/c 都代表三相

它们分别对应：

```text
A ↔ a：A相
B ↔ b：B相
C ↔ c：C相
```

大小写本身并不天然代表：

```text
ABC = 高压
abc = 低压
```

也不天然代表：

```text
ABC = 电源
abc = 负载
```

而只是同一个三相串联块的两侧端口命名。官方参考手册也是分别将A/B/C和a/b/c定义为相A/B/C对应的电气端口。

所以：

```text
ABC/abc本身没有"必须哪边接电网"的物理规定。
```

真正的规定来自：

```text
我们希望这个测量块的正方向怎么定义。
```

---

## 三、为什么我们的prim必须"变压器 → ABC，abc → 母线"？

我们现在六个prim\_\*最终统一为：

```text
设备/变压器高压端
       ↓
     A B C
   ┌─────────┐
   │  prim   │
   └─────────┘
     a b c
       ↓
馈线 / 公共母线 / 电网
```

也就是：

```text
变压器高压端
→ prim ABC
→ prim abc
→ 馈线/公共母线
```

项目当前已经冻结这套方向，并且恢复后六设备Pmeas和PCC重新回到了正常范围。

但重点不是"因为原模型这么画"，而是为什么从控制理论上我们必须这样定义。

---

## 四、我们希望整套系统采用什么功率正方向？

当前模型内部统一采用：

```text
设备 → 电网 = 正

电网 → 设备 = 负
```

所以：

### PV

PV发电：

```text
PV → 电网

P > 0
```

### ESS

ESS放电：

```text
ESS → 电网

P > 0
```

ESS充电：

```text
电网 → ESS

P < 0
```

### EV

EV充电：

```text
电网 → EV

P < 0
```

于是两台EV各：

```text
-0.6 pu
```

对应约：

```text
-60 kW
-60 kW
```

两台总和约：

```text
-120 kW
```

这正是我们后来重新恢复正确拓扑后得到的基线：EV1、EV2约-0.6 pu，PCC约-120 kW。

---

## 五、于是prim方向就被这个符号约定唯一确定了

既然我们要求：

```text
设备向外送电 = 正
```

那么设备支路测量块的正电流参考方向自然就应该是：

```text
设备
 ↓
prim ABC
 ↓
prim abc
 ↓
母线
```

于是定义为：

```text
Iabc > 0
```

时表示：

```text
电流正在从设备侧流向母线侧
```

对应：

```text
设备发电 / 放电
```

而如果EV正在充电，真实电流方向反过来：

```text
母线
 ↓
prim abc
 ↓
prim ABC
 ↓
EV
```

于是测得：

```text
Iabc < 0
```

进一步得到：

```text
Pmeas < 0
```

整个符号体系非常统一。

---

## 六、如果把prim完全反过来会发生什么？

假设接成：

```text
公共母线
→ prim ABC
→ prim abc
→ 设备
```

那么我们就人为定义了：

```text
母线 → 设备 = 正方向
```

这和当前控制系统所期待的：

```text
设备 → 母线 = 正方向
```

完全相反。

### 第一层影响：Iabc的正负号反了

例如一个PV真实正在：

```text
PV → Grid
```

本来应该：

```text
Iabc > 0
Pmeas > 0
```

反接以后可能变成：

```text
Iabc < 0
Pmeas < 0
```

于是系统会把：

```text
"PV正在发电"
```

看成：

```text
"PV正在吸收功率"。
```

---

## 七、为什么不是"Pmeas符号反一下"这么简单？

这是这次最关键的理解。

如果 prim 只是接一个Scope：

```text
prim Iabc
→ Scope
```

那么方向反了，最多就是：

```text
+60 kW 变成 -60 kW
```

我们看图的时候乘个-1就可以。

但我们现在不是这样。

我们的prim Vabc/Iabc是控制反馈的一部分。

当前每台设备的SM→SS普通控制向量固定为12维：

```text
[Vabc(3);
 Iabc(3);
 Fref;
 Vref;
 Droop_On;
 Pref;
 Qref;
 GridOn]
```

两台同类设备再组成24维送往对应SS。

所以实际上：

```text
prim
 ↓
Vabc / Iabc
 ↓
SM中的device_io12
 ↓
24维通信
 ↓
SS
 ↓
Control System
```

这意味着：

> prim不是一个只用于画图的测量块，它是低层控制器的反馈传感器。

---

## 八、反prim以后为什么会出现几十pu振荡？

因为这会变成一个真正的闭环反馈符号错误。

正常情况下可以粗略理解为：

```text
Pref
 ↓
控制器：我想输出多少功率
 ↓
PWM
 ↓
逆变器
 ↓
真实电流/功率
 ↓
prim测量
 ↓
反馈给控制器
```

正常控制：

```text
"我要求-0.6 pu"
↓
实际测到-0.55
↓
还差一点
↓
继续调整到-0.6
```

但假设反馈方向错了：

实际：

```text
-0.55 pu
```

控制器收到的测量却可能表现成：

```text
+0.55 pu
```

于是控制器会认为：

```text
我要求 -0.6
但你却在 +0.55
误差非常大
```

于是继续大幅调整。

设备真实响应进一步增大以后，测量符号仍然反着告诉控制器。

就容易形成：

```text
测错方向
→ 控制器朝错误方向补偿
→ 实际状态更偏
→ 控制器继续补偿
→ 大幅振荡
```

这就是为什么当时我们看到的不是简单：

```text
+0.6 ↔ -0.6
```

而是一度出现：

```text
EV1 Pmeas mean ≈ -10.23 pu
EV2 Pmeas mean ≈ -10.18 pu
```

并且瞬时达到几十pu

最终把PCC也拉到数百kW强烈振荡。恢复PCC边界、设备测量源、prim及馈线关系后，EV重新稳定在约-0.6 pu，PCC重新稳定在约-120 kW。

所以：

> prim方向是闭环控制反馈方向问题，不只是画图符号问题。

---

## 九、那Vabc会不会也反？

这里要细一点。

Three-Phase V-I Measurement串联在线路中，测量的是该点的三相电压和通过它的三相电流。官方文档说明它可以输出相地或相间电压以及三相线电流。

如果你只是把整个传感器左右两侧交换，而：

```text
A仍对应a
B仍对应b
C仍对应c
```

由于这个传感器本身近似理想串联测量元件，该节点电压本身不会因为你把测量块画反就发生巨大变化。

最直接受到方向影响的是：

```text
Iabc符号
```

然后：

```text
P = V × I
```

的功率方向跟着改变。

所以我们当时出现严重控制异常的主要敏感点是：

```text
Iabc以及由Iabc参与形成的功率/电流闭环反馈。
```

但如果你不是简单左右反，而是：

```text
A/B/C相序也接错
```

例如A相接到了B相，那么问题更严重：

```text
相序错误；
PLL / dq变换会看到错误相位关系；
电流环、电压环都会出问题。
```

所以一定要同时保持：

```text
A ↔ a
B ↔ b
C ↔ c
```

以及整体参考方向一致
