# 拆分后模型整个闭环工作过程理解

## 三、改造后整个模型怎样运行

先建立一个最重要的认识：

> 模型中不存在"SM 完全算完以后，三个 SS 再依次计算"的全局顺序。

SM 和三个 SS 是四个并行实时任务。每个任务使用上一时刻已经确定的边界状态，同时计算当前步。

使并行成为可能的是两种状态边界：

```text
普通数值信号：
Memory + OpComm

电气物理信号：
差分 Stubline
```

---

## 四、整个模型的静态分工

### 1. SM_Master

SM 负责公共部分：

```text
10 kV电网源
→ Grid V-I Measurement
→ 电网等值阻抗
→ PCC断路器
→ PCC V-I Measurement
→ PCC公共母线
   ├→ Load1
   ├→ Load2
   ├→ EV1/EV2高压馈线
   ├→ ESS1/ESS2高压馈线
   └→ PV1/PV2高压馈线
```

每台设备在 SM 中还保留：

```text
设备馈线
→ prim_* 一次侧V-I测量
→ 三台单相变压器高压侧
→ 高压侧Yg连接
→ 三个低压绕组的六个端点
→ 六个PMIOPort
```

SM 还负责上层计算：

```text
PCC/Grid测量
Supervisory
AGC
PVmax
SOC
15项策略
Modbus和安全状态
```

当前最终设计中，AGC 和策略可以转移到板端；但你要求假设它们都在 SM 中，下面按这个假设串联。

### 2. 顶层边界

每台设备有三条差分 Stubline：

```text
A_pos/A_neg → A相Stubline
B_pos/B_neg → B相Stubline
C_pos/C_neg → C相Stubline
```

六台设备总计：

```text
6台 × 3条 = 18条Stubline
```

它们负责真实电气边界。

另外有三条普通数值通信：

```text
EV 24维 → SS_Slave
ESS 24维 → SS_Slave2
PV 24维 → SS_Slave3
```

### 3. 三个 SS

每个 SS 有两台设备。

每台设备包含：

```text
六个PMIO端点
→ Delta(D1)
→ 低压侧三相V-I测量
→ 两电平变流器
→ LC滤波器
→ 直流源或设备等效模型
```

同时包含本地快速控制：

```text
Control System
→ PWM
→ 六路门极g
→ Two-Level Converter
```

三个 SS 的具体分工为：

```text
SS_Slave：
EV1 + EV2

SS_Slave2：
ESS1 + ESS2

SS_Slave3：
PV1 + PV2
```

### 4. SC_Console

SC 只负责：

```text
接收信号
显示波形
保存数据
监控状态
```

它不参与目标机实时闭环。SC 出错时，SM 和三个 SS 仍可运行，所以你之前仍能看到 Monitoring 正常、Overrun 为 0。

---

## 五、一个 100 μs 周期内发生什么

设当前步为第 k 步。

### 第 0 阶段：周期开始前已有的状态

四个任务已经保存了上一周期的状态：

```text
电感电流；
电容电压；
PLL、PI、控制器内部状态；
PWM状态；
SOC状态；
AGC历史状态；
Memory 的上一周期输出；
Stubline 的上一周期边界状态。
```

因此，当前步不是从零开始。

---

## 六、SM 在第 k 步做什么

### 1. 电网源产生当前瞬时电压

```text
J1_Grid_Source
→ 当前时刻三相电压
```

例如 50 Hz 三相正弦波在 t=kTs 时的 A、B、C 相瞬时值。

### 2. Grid 测量

```text
电网源
→ J2_Grid_VI
```

得到：

```text
Vabc_grid
Iabc_grid
```

进入 `J2_Grid_Measurements` 后计算：

```text
Freq_grid
Pgrid_kW
Qgrid_kvar
Vab_rms_grid
```

### 3. 经过电网等值阻抗和断路器

```text
J2_Grid_VI
→ 三相R-L阻抗
→ J1_PCC_Breaker
```

断路器闭合时，电网连接到 PCC。

### 4. PCC 测量

```text
断路器
→ Three-Phase V-I Measurement3
→ PCC公共母线
```

该块输出：

```text
Vabc_pcc
Iabc_pcc
```

然后 `J2_PCC_Measurements` 计算：

```text
Freq_pcc
Ppcc_kW
Qpcc_kvar
Vab_rms_pcc
```

正式输出关系已经在 J2 中确定。

---

## 七、SM 中两条上层控制环开始计算

### 1. Supervisory 电压、频率环

Supervisory 输入：

```text
PCC原始三相Vabc
Ctrl_On
```

它不能使用标量 `Vab_rms_pcc`，必须使用三相瞬时 Vabc。

Supervisory 内部完成：

```text
PCC Vabc
→ 频率/电压测量和滤波
→ 与50 Hz、10 kV参考比较
→ PI调节
→ 输出Fref、Vref
```

当前 K1B 中：

```text
0～5 s：Ctrl_On=0
5 s后：Ctrl_On=1
```

Supervisory 输出：

```text
Fref
Vref
Supervisor状态
```

其中 Fref、Vref 已经通过 Goto/From 接到六台设备的 IO Mux。

### 2. AGC 有功功率环

假设 AGC 位于 SM。

输入包括：

```text
P_target
Ppcc_kW
PV1_max、PV2_max
SOC1、SOC2
AGC enable
P_unit
死区
SOC上下限
AGC周期
初始功率
```

AGC 计算：

```text
dP = P_target - Ppcc
```

然后按照资源顺序分配：

```text
dP > 0：
PV增发
→ ESS放电
→ EV减少充电

dP < 0：
EV增加充电
→ ESS充电
→ PV降低
```

输出：

```text
PV1 Pref
PV2 Pref
ESS1 Pref
ESS2 Pref
EV1 Pref
EV2 Pref
AGC_STATUS
dP
remain
```

如果 AGC 周期为 1 s，它并不是每个 100 μs 都更新命令：

```text
1 s / 100 μs = 10000步
```

即每 10000 个电气仿真步更新一次，其他时间保持上一命令。

## 八、PVmax 和 SOC 在闭环中的位置

### PVmax

```text
Clock
→ 光伏曲线Lookup Table
→ PV1_max、PV2_max
→ AGC上限约束
```

它表示光伏当前最大可发能力，不是实际功率。

### SOC

```text
ESS1/ESS2实际功率
→ SOC离散积分
→ SOC1、SOC2
→ AGC充放电约束
```

正放电使 SOC 下降，负充电使 SOC 上升。

因此形成约束反馈：

```text
ESS功率
→ SOC变化
→ AGC下一轮可用能力变化
```

## 九、SM 怎样形成送给 SS 的命令

每台设备形成一个 12 维向量：

```text
device_io12 = [
    Vabc(3)
    Iabc(3)
    Fref
    Vref
    Droop_On
    Pref
    Qref
    GridOn
]
```

两台同类设备组成一个 24 维向量：

```text
EV1_IO12 + EV2_IO12
→ EV_Group_Mux24

ESS1_IO12 + ESS2_IO12
→ ESS_Group_Mux24

PV1_IO12 + PV2_IO12
→ PV_Group_Mux24
```

完整通信结构已经按该顺序建立。

然后：

```text
Group_Mux24
→ Memory
→ SM Outport
→ 顶层普通Simulink线
→ 对应SS Inport
```

### Memory 为什么存在

Memory 输出的是上一时刻已经确定的值。

因此在第 k 步：

```text
SM正在计算新的命令 C[k]
SS读取的是已经保存的命令 C[k-1]
```

这样 SS 不需要等待 SM 在当前步先计算完成，四个任务可以并行。

---

## 十、三个 SS 在第 k 步同时做什么

三个 SS 与 SM 大致同时启动。

以某台 EV 为例。

### 1. 读取 24 维普通控制数据

```text
SS Inport
→ OpComm
→ Group Demux [12 12]
→ 设备 Demux [3 3 1 1 1 1 1 1]
```

得到：

```text
Vabc
Iabc
Fref
Vref
Droop_On
Pref
Qref
GridOn
```

### 2. 接收电气边界

与此同时，三个 Stubline 给出该设备三个低压绕组的六个端点：

```text
A_pos、A_neg
B_pos、B_neg
C_pos、C_neg
```

这些边界值来自上一周期 Stubline 已经保存的传播状态。

### 3. 重建 Delta(D1)

六个端点连接成三角形：

```text
A_pos + C_neg → A节点
A_neg + B_pos → B节点
B_neg + C_pos → C节点
```

这三个节点形成变流器看到的三相交流端。

### 4. 本地测量和控制

低压 V-I Measurement 得到设备本地电压、电流。

Control System 根据：

```text
Vabc、Iabc
Fref、Vref
Pref、Qref
Droop_On、GridOn
```

进行：

```text
PLL或角度同步
→ abc/dq变换
→ 功率环
→ 电压/电流环
→ 调制电压参考
```

### 5. PWM 生成门极

```text
调制参考
→ PWM
→ g1～g6
→ Two-Level Converter
```

### 6. 变流器产生实际电流

两电平变流器根据：

```text
直流侧电压；
六路门极；
交流侧电压；
LC滤波器状态；
```

产生新的三相电压和电流。

这些电流通过：

```text
变流器
→ LC滤波器
→ 低压Delta
→ Stubline边界
```

反作用到变压器和电网。

## 十一、第 k 步结束时发生什么

所有任务完成本步计算后：

### 普通信号状态更新

```text
Memory输入保存SM新生成的24维命令
```

下一步 SS 才会读到。

### Stubline状态更新

Stubline 保存：

```text
SM侧本步边界结果
SS侧本步边界结果
```

下一步分别提供给对侧。

### 控制器与电气状态更新

保存：

```text
PI积分器；
PLL；
电感电流；
电容电压；
PWM状态；
AGC状态；
SOC状态。
```

---

## 十二、第 k+1 步闭环怎样继续

在第 k+1 步：

```text
SS收到SM在第k步生成的新Fref/Vref/Pref
```

设备控制器开始按照新指令调节。

SS 在第 k 步形成的电气边界变化，经 Stubline 在第 k+1 步进入 SM：

```text
设备电流变化
→ 变压器高压侧电流变化
→ PCC功率变化
```

SM 再测量新的 PCC：

```text
新的PCC
→ Supervisory和AGC
→ 形成下一轮命令
```

于是闭环为：

```text
PCC测量
→ Supervisory/AGC
→ 24维控制向量
→ Memory/OpComm
→ SS本地控制器
→ PWM
→ 变流器
→ Stubline
→ 变压器/线路/PCC
→ 新PCC测量
```

---

## 十三、两个 100 μs 级边界延迟

从 PCC 发生变化到完整反馈，至少经过两类状态边界：

### 命令方向

```text
SM新命令
→ Memory
→ 下一步到SS
```

约一个仿真步。

### 电气反馈方向

```text
SS新电流
→ Stubline
→ 下一步影响SM/PCC
```

约一个仿真步。

所以最低层闭环包含大约两个 100 μs 级状态传播边界。

这不是通信故障，而是为了让四个任务能够并行而主动引入的确定性状态边界。相对于设备约 1 s 的功率响应，它很小，但在拓扑上非常重要。

---

## 十四、SC 在整个周期中处于哪里

SC 不是闭环的一环。

它的路径是：

```text
SM/SS计算完成的信号
→ Outport
→ SC Inport
→ SC OpComm/REC
→ Scope、Display、记录
```

即使 SC 无法接收：

```text
SM + 3SS
```

仍在 OP5700 上正常运行。

因此当前 SC 报错不会改变设备控制结果，只会让你看不到波形。

---

## 最后压缩成一句话

改造后的模型本质是：

> SM 负责公共电网、测量和上层决策；三个 SS 分别负责两台设备的本地快速控制和开关级电路；普通命令通过 Memory＋OpComm 跨任务，真实电气功率通过差分 Stubline 跨任务；各任务用上一周期边界状态并行计算，再在下一周期相互影响，最终通过 PCC 测量闭合整个控制环。
