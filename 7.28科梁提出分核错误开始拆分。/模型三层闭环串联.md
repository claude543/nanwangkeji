# 模型三层闭环串联

## 十九、现在正式把整个拆分模型从"能量流"串一次

先完全不考虑控制，只看电是怎么走的。

以一台设备为例，比如PV2。

### PV2物理能量流

从设备往电网送电时：

```text
PV直流能源
    ↓
Two-Level Converter
    ↓
SS中的逆变器侧测量 inv
    ↓
L1/C1等低压滤波网络
    ↓
SS低压边界V-I Measurement
    ↓
SS中的Delta(D1)三相节点
    ↓
6个PMIO端点
    ↓
3条差分Stubline
    ↓
SM侧三只单相变压器低压绕组端点
    ↓
磁耦合到10 kV高压侧
    ↓
prim_PV2 ABC
    ↓
prim_PV2 abc
    ↓
PV2line
    ↓
设备公共母线
    ↓
PCC ABC
    ↓
PCC abc
    ↓
断路器 / Grid
```

这就是一条完整物理能量通道。

---

## 二十、为什么每台设备要6个PMIO，而不是3个？

因为我们不是简单把：

```text
A
B
C
```

三根相线切开。

官方模板采用的是：

```text
每相低压绕组两个端点都跨任务传递。
```

所以三相：

```text
A_pos
A_neg

B_pos
B_neg

C_pos
C_neg
```

总共：

```text
6个端点
```

每相通过一条：

```text
2 with differential inputs Stubline
```

因此每台：

```text
3条Stubline
6个PMIO
```

六台：

```text
18条Stubline
36个SM PMIO
```

当前任务级物理映射已经固定。

---

## 二十一、为什么SS要重新组成Delta(D1)？

因为变压器低压侧原来是：

```text
Delta
```

但我们把三只单相变压器的低压绕组两个端点全部穿过Stubline拿到了SS。

于是SS必须重新接成：

```text
A节点 = A_pos + C_neg
B节点 = A_neg + B_pos
C节点 = B_neg + C_pos
```

交接中已经将这套Delta连接固定。

所以这里不是随便"两个端点并一下"。

它是在重建：

```text
三角形绕组闭环
```

## 二十二、再从"控制信号流"串一次

现在完全不看电能，来看信息怎么跑。

这是另一个闭环。

同时SM还有上层控制量：

```text

```

```text
device_io12 =

 Iabc_B
 Iabc_C

 Vref
 Droop_On
 Pref
 Qref
 GridOn]
```

这正是当前固定的设备普通通信定义。

例如EV组：

```text
EV2_io12
+
EV1_io12
      ↓
EV_io24
```

ESS：

```text
ESS1_io12
+
ESS2_io12
      ↓
ESS_io24
```

PV：

```text
PV1_io12
+
PV2_io12
      ↓
PV_io24
```

当前分组和任务映射已经固定。

## 二十五、第三步：SM把24维送到对应SS

结构：

```text
SM内部24维向量
      ↓
Memory / 状态边界
      ↓
SM Outport
      ↓
模型顶层普通Simulink通信线
      ↓
SS Inport
      ↓
SS OpComm
```

注意：

```text
普通数值信号走OpComm。
```

而：

```text
电气能量走Stubline。
```

这两种通道永远不要混为一谈。项目任务级拆分从一开始就固定了这两类跨子系统连接方式。

## 二十六、进入SS以后怎么拆？

例如SS_Slave有：

```text
EV2 + EV1
```

24维进入：

```text
SS Inport
 ↓
OpComm
 ↓
Demux [12 12]
```

得到：

```text
EV2_io12
EV1_io12
```

然后每个12维再：

```text
Demux
[3 3 1 1 1 1 1 1]
```

还原成：

```text
Vabc
Iabc
Fref
Vref
Droop_On
Pref
Qref
GridOn
```

这就是每个控制器真正收到的信息。

## 二十七、SS的Control System内部在干什么？

从功能层面可以理解成：

```text
Vabc / Iabc
    ↓
PLL / 频率相位识别
    ↓
P/Q测量
    ↓
Droop / 功率控制
    ↓
电压/电流控制
    ↓
调制量
    ↓
PWM
    ↓
g
    ↓
Two-Level Converter
```

具体内部还有dq变换、PI等控制结构，但对当前全局理解，你需要先记住：

```text
SM给SS的是"测量 + 参考值"；SS控制器把它变成"PWM门极脉冲"。
```

## 二十八、然后又回到物理能量流

PWM改变：

```text
g
```

于是：

```text
Two-Level Converter开关状态改变
```

于是：

```text
交流输出改变
```

然后经：

```text
滤波器
→ Delta
→ Stubline
→ Transformer
→ prim
→ feeder
→ PCC
```

产生新的：

```text
Vabc
Iabc
Ppcc
Pmeas
```

然后下一周期又重新送回控制器。

所以低层闭环实际是：

```text
             ┌──────────────────────┐
             │                      ↓
SM prim测量 → 24维通信 → SS控制器 → PWM
   ↑                               ↓
   │                           Converter
   │                               ↓
   └← Transformer ← Stubline ← AC输出
```

这就是：

```text
SM和SS共同构成一个闭环。
```

并不是：

```text
SM算SM
SS算SS
彼此独立
```

## 二十九、那AGC又在哪一层？

AGC在SM里，是比六台设备本地控制器更上层的控制。

它不直接产生PWM。

AGC只产生：

```text
Pref
```

当前六路：

```text
PV1 Pref
PV2 Pref
ESS1 Pref
ESS2 Pref
EV1 Pref
EV2 Pref
```

```text
      Ppcc

     SM AGC
```

AGC同时接：

```text

PVmax2
```

然后计算：

```text
六路Pref
```

于是：

```text
AGC Pref
   ↓
device_io12
   ↓
24维
   ↓

   ↓

   ↓

   ↓

```

这就是完整的：

```text
PCC上层功率闭环。
```

## 三十一、所以现在模型里其实嵌套了两层闭环

非常重要。

### 快速低层闭环

在100 μs实时框架中不断运行：

```text
设备V/I
→ PLL/功率/电压/电流控制
→ PWM
→ Converter
→ 新V/I
```

### 慢速上层AGC闭环

每1 s更新：

```text
PCC
→ AGC
→ Pref
→ 六设备
→ PCC
```

所以：

```text
低层控制器
负责"把设备功率指令执行出来"

AGC
负责"六台设备应该分别执行多少"
```

不要把这两层混在一起。

---

## 三十二、Supervisor又在哪里？

Supervisor仍位于SM上层。

目前统一：

```text
Droop_On：3 s投入

Supervisor Ctrl_On：5 s投入
```

Supervisor根据系统状态形成例如：

```text
Fref
Vref
```

然后这些也进入：

```text
device_io12
```

发送给SS控制器。

因此SM并不是只有AGC。

SM上层大概可以理解成：

```text
PCC / Grid measurement
        ↓
 ┌───────────────┐
 │ Supervisory   │ → Fref/Vref
 │ AGC           │ → Pref
 │ PVmax         │
 │ SOC           │
 │ 状态/通信     │
 └───────────────┘
        ↓
六台device_io
        ↓
3组24维
        ↓
3个SS
```

---

## 三十三、六个Pmeas现在又从哪里回来？

六台设备各自的最终实测有功：

```text
PV1_Pmeas
PV2_Pmeas
ESS1_Pmeas
ESS2_Pmeas
EV1_Pmeas
EV2_Pmeas
```

是在设备控制/测量链中形成的最终measurements数据。

然后通过普通数值观测链返回SM/SC，用于：

```text
观察实际执行；
后续40109～40114；
论文状态失配研究。
```

当前基础AGC不使用这六路Pmeas。

也就是说当前AGC是：

```text
PCC反馈
+
内部历史命令
```

不是：

```text
PCC
+
六台实际Pmeas
```

这正是后续论文会改进的地方。

---

## 三十四、SC在整个系统里面到底在哪？

SC不在电气能量闭环里。

也不直接控制PWM。

它是：

```text
观察层。
```

现在主要：

```text
SM信号
 ↓
SM Outport
 ↓
SC Inport
 ↓
SC OpComm
 ↓
Demux
 ↓
Scope / Display
```

例如：

```text
Ptarget；
Ppcc；
Enable；
AGC status；
dP；
remain；
六路cmd；
六路Pmeas；
PVmax；
SOC。
```

---

## 三十五、为什么SC坏了也不会让AGC闭环坏？

因为当前AGC控制路径是：

```text
SM内部PCC
→ SM内部AGC
→ Pref
→ SS
```

没有经过：

```text
SC
```

所以之前SC出现：

```text
15 s的Enable
看成40 s
```

Target上的真实AGC仍然15 s正常执行。

这就是为什么我们最后可以明确说：

> SC是观察者，不是控制闭环参与者。

正式Target记录同样从SM的AGC_CORE_MUX23直接分支到OpWriteFile，不经过SC。

## 三十七、再把一台设备的"完整循环"按时间顺序讲一遍

以EV1为例。

假设当前：

```text
EV1 Pref = -0.6 pu
```

### 第1步：SM准备EV1的参考和测量

SM中：

```text
prim_EV1
→ Vabc
→ Iabc
```

再加：

```text
Fref
Vref
Droop_On
Pref=-0.6
Qref
GridOn
```

形成：

```text
EV1_io12
```

### 第2步：EV1和EV2合成24维

```text
EV2_io12
+
EV1_io12
↓
EV_group_io24
```

### 第3步：传到SS_Slave

```text
SM Outport
→ 顶层普通通信
→ SS Inport
→ OpComm
→ Demux
```

重新得到：

```text
EV1_io12
```

### 第4步：EV1控制器计算

控制器看到：

```text
我要 -0.6 pu
现在V是多少
现在I是多少
当前频率/相位是多少
Droop是否投入
```

然后计算控制量。

### 第5步：PWM驱动EV1逆变器

```text
Control System
→ PWM
→ g
→ Two-Level Converter
```

### 第6步：真实电流从电网流向EV

由于EV充电：

```text
Grid
→ PCC
→ feeder
→ prim_EV1
→ Transformer
→ Stubline
→ Delta
→ filter
→ converter
→ DC侧
```

这个真实功率方向和我们定义的"设备→电网为正"相反。

所以：

```text
EV1 Pmeas < 0
```

### 第7步：prim重新测量

新的：

```text
Vabc/Iabc
```

再次在SM被测出来。

下一100 μs计算周期又被送给SS。

于是EV1低层控制闭环不断运行。

### 第8步：六台设备一起改变PCC

两台EV都充电：

```text
Ppcc ≈ -120 kW
```

### 第9步：AGC在15 s投入

AGC看到：

```text
Ptarget = -100
Ppcc = -120
```

所以：

```text
dP ≈ +20
```

按照优先级先提高PV命令。

### 第10步：PV控制器执行新Pref

PV功率增加：

```text
P_PV > 0
```

于是PCC从：

```text
-120
```

向：

```text
-100
```

靠近。

### 第11步：PCC把结果反馈给AGC

新的PCC：

```text
Pcc ≈ -100
```

AGC下一次1 s更新重新计算。

于是：

```text
AGC → Pref → Local controller → PWM → plant → PCC → AGC
```

整个大闭环闭合。

## 三十八、最后用三个层级记住整个系统

以后看到模型很复杂，可以永远只分三层。

### 第一层：物理电气层

回答：

```text
电真正从哪里流到哪里？
```

```text
Converter
↔ Filter
↔ LV VI
↔ Delta
↔ Stubline
↔ Transformer
↔ prim
↔ feeder
↔ PCC
↔ Grid
```

### 第二层：快速设备控制层

回答：

```text
每台设备如何执行Pref？
```

```text
prim V/I
→ SM→SS通信
→ Control System
→ PWM
→ Converter
→ 物理网络
→ prim V/I
```

周期：

```text
100 μs级实时框架
```

### 第三层：慢速协调控制层

回答：

```text
六台设备各自应该出多少？
```

```text
PCC
→ AGC
→ 六路Pref
→ 六台设备
→ PCC
```

当前：

```text
Ts_AGC = 1 s
```

而SC是第四个"旁观层"：

```text
只看
不控制
```
