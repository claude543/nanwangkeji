# 旧分核问题以及新分核初步办法

## 当前结论

现在遇到的核心问题不是模型不能运行，而是：

> **完整开关级模型在 100 μs 步长下计算不完，模型时间无法与现实时间保持 1∶1。**

目前已知性能大致为：

```text
六逆变器：约 981 μs/步
三逆变器：约 700 μs/步
目标预算：100 μs/步
```

三逆变器模型在 `Cores=1` 和 `Cores=4` 时都约为 700 μs，说明原 SSN 方案虽然在 RT-LAB 界面上确实分配了 4 个核，但没有获得有效的并行加速。

---

## 一、之前的分核方案为什么没有效果

之前采用的是：

```text
顶层只有：
SM_circuit
SC_display

SM_circuit 内部：
用 SSN Interface 把 PV、ESS、EV 和公共电网分组

RT-LAB 设置：
SM_circuit 分配 4 核
XHP 开启
SSN 开启
```

这个方案理论上允许 SSN 组在多个核之间分配计算，但实际没有明显加速，原因可能有三类：

1. **各 SSN 组计算量不均衡**
   其中某一组仍然很重，其他核很快完成后只能等待。

2. **公共节点矩阵仍由单个核计算**
   ARTEMiS 资料明确说明，SSN 节点矩阵会集中在一个核上计算，因此节点多、各支路耦合强时，会形成串行瓶颈。资料也建议各 SSN 组大小尽量接近，并减少公共节点数量。

3. **大量控制计算没有被 SSN 拆开**
   PLL、功率环、电流环、PWM、测量、AGC 和其他 Simulink 计算仍然全部位于同一个 `SM_circuit` 实时任务中。SSN 主要优化电气状态空间求解，不会自动把整个 SM 里的普通控制计算拆到不同核。

所以原方法不能说"没有配置四核"，准确说法是：

> **四核配置已经生效，但重计算任务没有得到有效并行，最终性能仍接近单核。**

---

## 二、现在准备尝试的新分核方法

新方法不再只给一个 `SM_circuit` 分配 4 核，而是把模型真正拆成 4 个独立实时任务：

```text
SM_Grid
├─ 电网
├─ PCC 公共母线
├─ 负荷和线路
├─ PCC 测量
├─ AGC、SOC、PV 曲线
└─ 公共控制与通信管理

SS_PV
├─ PV1 完整支路
└─ PV2 完整支路

SS_ESS
├─ ESS1 完整支路
└─ ESS2 完整支路

SS_EV
├─ EV1 完整支路
└─ EV2 完整支路

SC_Display
└─ Scope、Display 和上位机操作
```

然后分配：

```text
SM_Grid → 核1
SS_PV   → 核2
SS_ESS  → 核3
SS_EV   → 核4
```

RT-LAB 通用模型规则是一个模型只能有一个 SM，可以有多个 SS；SM 和 SS 都是实时计算任务，SC 在上位机运行且不占实时核。

这一方案的目的不是形式上增加几个 SS，而是把六台逆变器的开关电路、滤波器、变压器和本地控制真正分散到不同 CPU 核。

---

## 三、新方案中两类跨子系统连接

### 1. 普通数值信号使用 OpComm

例如：

```text
Pref、Qref
Fref、Vref
SOC
PV 最大出力
设备实测功率
状态量
控制使能
```

这些都是普通 Simulink 数值。它们从一个 SM/SS 进入另一个 SM/SS 时，需要先通过 OpComm。

OpComm 的作用是：

> 在不同实时任务之间，按照指定采样周期传递一组普通数值信号。

RT-LAB 资料要求实时子系统的输入在参与计算前先经过 OpComm。

### 2. 三相电气连接不能使用 OpComm

逆变器支路连接 PCC 的 A、B、C 端口属于电气物理连接，不只是三个独立数值。

这些端口同时包含：

- 电压关系；
- 电流平衡；
- 电感、电容状态；
- 开关状态；
- 电气网络约束。

因此不能把三相线剪断后，用普通 Inport、Outport 和 OpComm 代替。

跨 SM/SS 传递电气连接时，需要 ARTEMiS 电气解耦线路，例如：

- Distributed Parameters Line；
- Stubline。

对微电网内较短的支路，更可能采用 Stubline。资料指出，Stubline 可以模拟短 R-L 线路并解耦线路两端的状态空间方程，但必须比较加入前后的动态响应。

## 四、原 SSN 节点怎样处理

需要区分两个模型。

### 原始基线模型

原模型中的 SSN Interface 全部保留，不修改，用于保存现有性能和波形基准。

### 新的任务分核副本

如果某个原 SSN 节点正好位于：

```text
逆变器支路—PCC 母线
```

而该位置将改用 Stubline 跨 SM/SS 连接，则这一位置的原 SSN Interface 应删除，由 Stubline 承担跨实时任务的电气解耦。

不建议在同一分界处采用：

```text
SSN Interface
+
Stubline
```

否则会叠加两种解耦机制，难以判断模型动态变化和性能变化的来源。

如果某个 SM 或 SS 内部仍然包含较大的完整电气网络，内部是否继续使用 SSN 可以后续单独评估。

## 五、新分核方法的执行顺序

虽然最终目标是六逆变器，但不能一次性把六条支路全部拆完，否则一旦 Build 失败，很难判断是哪一个接口出错。

### 第 0 步：冻结基线

保留：

```text
6INV_Original_Baseline.slx
6INV_TaskSplit_Development.slx
```

记录原模型：

- 仿真步长；
- PCC、六台设备功率；
- PLL、电压、电流；
- RT-LAB Monitoring；
- Overrun；
- 原 SSN 配置。

### 第 1 步：设计，不修改模型

先形成一张明确的拆分表：

| 内容 | 所属子系统 |
| ---- | ---------- |
| 电网、PCC、负荷 | SM |
| PV1、PV2 | SS_PV |
| ESS1、ESS2 | SS_ESS |
| EV1、EV2 | SS_EV |
| 显示 | SC |

同时列出每条跨边界信号：

- 信号名称；
- 发送端；
- 接收端；
- 普通数值还是电气端口；
- 使用 OpComm 还是 Stubline；
- 采样周期；
- 是否已经存在 Unit Delay 或状态。

### 第 2 步：六逆变器副本中只拆一条完整支路

例如先拆 PV1：

```text
SM_Main
├─ 其余 5 台逆变器
├─ PCC、电网和负荷
└─ 公共控制

SS_PV1
└─ PV1 完整支路
```

先验证：

- 普通 Simulink 能否运行；
- Stubline 参数是否合理；
- 两个任务能否真正并行；
- PV1 和 PCC 波形是否仍与原模型一致；
- 性能是否有改善。

### 第 3 步：扩展成四个实时任务

单支路成功后，再形成：

```text
SM_Grid
SS_PV
SS_ESS
SS_EV
SC_Display
```

第一版全部保持 100 μs，不同时进行多速率修改。

### 第 4 步：性能和等效性验收

必须同时检查：

```text
每个 SM/SS 的最大计算时间 < 100 μs
模型无持续 overrun
模型时间与现实时间 1∶1
```

并与原模型比较：

- PCC 功率；
- 六台设备功率；
- 母线电压和频率；
- PLL；
- 三相电流；
- 稳态误差；
- 超调和响应时间。

### 第 5 步：必要时再研究多速率

只有分核结构正确后，才考虑：

```text
快速电气和控制：100 μs
部分较慢控制：200 或 400 μs
AGC、Modbus、SOC 等：更慢周期
```

不能在第一次拆分时同时改变分核、模型结构和采样周期，否则结果无法归因。

## 六、新方法可能遇到的问题

### 1. Stubline 会改变模型

Stubline 不是完全透明的理想连接，它包含：

- R、L；
- 根据步长形成的等效电容；
- 一个仿真步的传播延迟。

它可能影响：

- 高频谐波；
- 支路谐振；
- PLL；
- 暂态响应；
- PCC 超调。

所以即使分核后能够实时，也必须证明模型仍然代表原系统。

### 2. SM 和 SS 可能无法真正并行

如果 SM 本步需要 SS 本步的结果，同时 SS 又需要 SM 本步的结果，就会出现：

- 串行执行；
- 代数环；
- 任务死锁。

RT-LAB 资料要求实时任务尽量通过带状态的信号交互，Memory、Unit Delay 或积分器可以打断同一步的直接依赖；但额外 Delay 会改变模型动态，必须谨慎。

### 3. 可能重复增加延迟

逆变器原控制中已经可能存在：

```text
控制器输出
→ Unit Delay
→ PWM
```

如果拆分后再盲目增加 Memory，可能从原来一拍延迟变成两拍延迟，影响电流环稳定性。

所以必须先识别原有状态，再决定是否需要新增 Memory。

### 4. OpComm 会产生通信和同步开销

分得过细、跨子系统信号过多，会造成：

- OpComm 数据量增加；
- CPU 核间同步开销增加；
- 计算时间反而上升。

因此应传递必要信号，不应把整个大型诊断总线全部以 100 μs 跨任务传输。

### 5. 四个任务可能负载不均衡

即使总计算量下降，只要其中一个任务仍超过 100 μs，整个模型仍不能实时。

需要分别检查：

```text
SM_Grid
SS_PV
SS_ESS
SS_EV
```

每个任务的 Mean 和 Max，而不能只看总平均时间。

### 6. 四核仍可能不够

六逆变器原始计算约 981 μs，理想平均分到 4 核也约 245 μs。Stubline 和矩阵解耦可能进一步降低计算量，但不能预设一定能够达到 100 μs。

因此任务分核值得尝试，但仍可能出现：

```text
正确分核后性能明显改善
但仍达不到 100 μs
```

这时 eHS 仍然是后续主要路线，而不是继续无限拆分 CPU 模型。

## 七、当前最准确的阶段结论

目前已完成的是：

```text
确认原模型无法在 100 μs 实时运行
确认三逆变器 1 核和 4 核性能几乎相同
确认原 SSN 四核方案没有获得有效加速
明确了真正的任务级分核原理
明确了 OpComm、Memory 和 Stubline 的作用
形成了六逆变器四任务初步结构
```

目前尚未完成的是：

```text
正式确定六条支路的解耦位置
确定 Stubline 具体 R、L 参数
列出全部跨子系统信号
检查原模型中的 Unit Delay 位置
建立单支路原型
验证模型等效性
验证四任务实时性能
```

### 当前决定

现在不开始正式拆分。

下一步先完成一份六逆变器模型的"分核设计稿"，明确：

```text
每个模块放在哪里
每条跨边界信号怎样传
哪条是 OpComm
哪条是 Stubline
哪里已有状态
哪里可能需要 Memory
每个任务采用什么采样周期
如何验证改造前后等效
```

设计稿确认后，再在六逆变器副本中从一条支路开始实施。
