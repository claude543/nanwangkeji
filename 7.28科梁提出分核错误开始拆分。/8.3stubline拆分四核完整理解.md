# Stubline拆分四核完整理解

## 核心结论

这次改造的本质是：

> **把原来完整连在一起的一条设备支路，在变压器低压绕组端子处切开；电网、线路和变压器留在 SM，变流器、滤波器、本地控制器和 PWM 放到 SS；两边的电气联系由顶层差分 Stubline维持，控制和测量数值由 OpComm 传递。**

因此，当前模型中存在两套完全不同的跨任务联系：

1. **电气联系**：PMIOPort + 顶层差分 Stubline
   它维持电压、电流和功率交换关系。
2. **普通数值联系**：Mux + Memory + Outport/Inport + OpComm + Demux
   它传递 `Vabc、Iabc、Fref、Vref、Pref` 等控制数据。

只理解其中一套，就无法完整理解当前拆分。

---

## 一、原来的结构是什么，为什么不能继续使用

原来每台设备的整条支路基本都在同一个 `sm_circuit` 中：

```text
PCC公共母线
→ 设备馈线 Line_EV
→ 三相10 kV/480 V变压器
→ 低压侧母线
→ 两电平变流器
→ LC滤波器
→ 直流侧设备

同时在同一个任务中：
→ 测量
→ PLL
→ 功率环
→ 电流环
→ PWM
→ 六路门极信号g
```

六台设备都放在一个 SM 后，结果是：

```text
一个公共电气网络
+
六个开关级变流器
+
六套控制器和PWM
+
公共测量与上层控制
```

全部由一个实时任务按顺序计算。

给这个 SM 设置多个核，并不等于自动形成多个独立实时任务。此前三逆变器在 `Cores=1` 和 `Cores=4` 时都约为 700 μs，六逆变器约为 970～981 μs，说明主要计算仍集中在一个任务里。

所以必须把顶层改成：

```text
SM_Master
SS_Slave
SS_Slave2
SS_Slave3
SC_Console
```

其中前四个是四个独立实时计算任务。

---

## 二、我们究竟把什么拆开了

不是简单把一个 Simulink 框复制到另一个框，而是同时完成了四层拆分。

### 1. 任务拆分

原来：

```text
1个SM实时任务
```

现在：

```text
SM_Master     公共电网、PCC、负荷、六套高压侧边界
SS_Slave      EV1、EV2
SS_Slave2     ESS1、ESS2
SS_Slave3     PV1、PV2
```

这样 RT-LAB 才能把四个任务并行调度。

### 2. 电气网络拆分

原来六台变流器与公共电网属于一个大电气求解问题。

现在被分成：

```text
1个公共电网网络
+
6个彼此独立的六开关变流器网络
```

当前 `Ctrl+D` 已经显示：

- SM 主网络只剩三相断路器的 3 个开关；
- 六台逆变器分别形成六个独立的 6 开关网络。

这说明 ARTEMiS 的状态空间网络已经真正被切开，而不是只在画布上分了几个框。

### 3. 变压器表示方式拆分

原来通常是一个封装好的三相变压器：

```text
三相高压Yg
→ 三相低压Delta
```

现在改为三台独立的单相变压器：

```text
A相单相变压器
B相单相变压器
C相单相变压器
```

这样每一相低压绕组的两个端点都能显式暴露出来：

```text
A_pos、A_neg
B_pos、B_neg
C_pos、C_neg
```

有了这六个端点，才能把每相绕组通过一条"2 with differential inputs"差分 Stubline 跨越 SM/SS 边界。官方成功母版采用的正是这一结构。

### 4. 信号路径拆分

电气网络切开后，本地控制器被移动到了 SS，但部分测量和上层给定仍在 SM。

因此必须显式传输：

```text
Vabc(3)
Iabc(3)
Fref
Vref
Droop_On
Pref
Qref
GridOn
```

一台设备共 12 维，两台同类设备合并为 24 维。

## 三、第一张图：SM_Master 中究竟发生了什么

第一张图显示的是 EV2 的 SM 侧结构。

可以分成两条互不相同的路径来看。

---

### 路径一：真正的电气功率路径

从下方的 `Line_EV2` 开始：

```text
PCC公共母线
→ Line_EV2
→ prim_EV2三相V-I测量
→ 三台单相变压器的高压绕组
→ 三台变压器的低压绕组端子
→ 六个PMIOPort
→ 顶层三条差分Stubline
```

#### 1. `Line_EV2`

这是 EV2 原来的高压侧馈线，仍留在 SM 中。

原因是：

- PCC、公共线路和高压馈线属于公共电网侧；
- 它们应该由 SM 统一计算；
- 不应把公共母线拆散到多个 SS。

#### 2. `prim_EV2`

这是高压侧三相 V-I Measurement。

它有两类端口：

- `A/B/C → a/b/c`：真正的三相电气穿越端口；
- `Vabc、Iabc`：普通 Simulink 数值输出。

电气端口让三相线路继续接到三台单相变压器。

普通输出则可以作为控制器的测量输入，经过 Mux 后发给 SS。

要注意：

> `Vabc/Iabc` 数值输出不能替代电气连接。

它只是测量得到的几个数字，并不能让变流器真正与电网交换电流和功率。

#### 3. 三台单相变压器的高压侧

每台单相变压器的：

```text
1+
1-
```

是高压绕组端点。

三台变压器的 `1+` 分别接 A、B、C 三相，三个 `1-` 接成公共中性点并接地，因此形成高压侧 Yg。

参数按单相计算：

```text
单相容量 = 110000 / 3 VA
高压绕组电压 = 10000 / √3 V
低压绕组电压 = 480 V
```

原因是：

- 10 kV 是三相线电压；
- Y 接每相绕组承受的是相电压 `10000/√3`；
- 总三相容量 110 kVA，需要分给三台单相变压器，每台 `110/3 kVA`；
- Delta 每个低压绕组两端承受线电压，因此填 480 V。

#### 4. 三台变压器的低压绕组端点

每台变压器的：

```text
2+
2-
```

是低压绕组的两个端点。

在第一张图中它们没有在 SM 内接成 Delta，而是分别引出：

```text
EV2_A_pos
EV2_A_neg
EV2_B_pos
EV2_B_neg
EV2_C_pos
EV2_C_neg
```

对应 PMIO 端口 1～6。

这里是整个拆分中最关键的一步：

> 原来低压三角形连接位于变压器块内部或同一电气网络中；现在故意不在 SM 中闭合，而是把六个绕组端点送到 SS，再由 SS 重建 Delta。

如果在 SM 中已经把 Delta 接好，再通过三根线送到 SS，就无法形成当前官方差分 Stubline 边界。

---

### 路径二：普通控制数据路径

第一张图左侧还可以看到：

```text
Fref
Vref
Droop_On
Pref
GridOn
```

以及 `prim_EV2` 输出的：

```text
Vabc
Iabc
```

这些信号被组合成单设备 12 维向量：

```text
EV2_IO12 =
[Vabc(3);
 Iabc(3);
 Fref;
 Vref;
 Droop_On;
 Pref;
 Qref;
 GridOn]
```

在当前完整 EV 组中：

```text
EV1_IO12
+
EV2_IO12
→ EV_Group_Mux24
→ Memory
→ SM Outport ev_io_vec
```

Memory 的作用是让发送到 SS 的数据成为上一计算步已经确定的状态量，避免 SS 必须等待 SM 在同一步先算完。

因此：

```text
Memory
```

不是用于电气解耦，而是用于普通数字信号的任务时序解耦。

## 四、顶层 Stubline 究竟怎样连接两张图

顶层没有显示在这两张截图中，但它是 SM 和 SS 真正建立电气关系的位置。

以 EV2 为例：

```text
SM_Master端口1  EV2_A_pos ─┐
                           ├→ A相差分Stubline → SS_Slave端口1/2
SM_Master端口2  EV2_A_neg ─┘

SM_Master端口3  EV2_B_pos ─┐
                           ├→ B相差分Stubline → SS_Slave端口3/4
SM_Master端口4  EV2_B_neg ─┘

SM_Master端口5  EV2_C_pos ─┐
                           ├→ C相差分Stubline → SS_Slave端口5/6
SM_Master端口6  EV2_C_neg ─┘
```

每条 Stubline 不是一根单线，而是处理一对差分端点：

```text
相绕组正端
相绕组负端
```

所以一台设备需要：

```text
3相 × 每相2端 = 6个PMIOPort
3相 × 每相1条差分Stubline = 3条Stubline
```

六台设备因此需要：

```text
6 × 3 = 18条Stubline
6 × 6 = 36个SM侧PMIO端口
```

---

### PMIOPort 与 Stubline 的区别

#### PMIOPort

PMIOPort 只是把电气端点暴露到子系统外部。

它相当于说明：

```text
这个端点属于SM内部电气网络，
但需要在顶层继续连接。
```

PMIOPort 本身不负责计算解耦。

#### Stubline

Stubline 才是真正使两侧可以独立计算的电气元件。

它依据一个仿真步的传播关系，让：

```text
SM在本步计算时
不需要等待SS本步结果

SS在本步计算时
也不需要等待SM本步结果
```

两边使用已经确定的边界状态完成本步计算，然后更新下一步所需的边界量。

因此 Stubline 同时完成两件事：

1. 保持电压、电流和功率交换关系；
2. 打断同一时刻的直接代数依赖，使两侧可以并行。

这就是为什么普通电线不能直接跨 SM 和 SS。

## 五、第二张图：SS_Slave 中究竟发生了什么

第二张图显示的是 EV1，而不是 EV2。

从端口编号可以看出来：

```text
EV1_A_pos = 7
EV1_A_neg = 8
EV1_B_pos = 9
EV1_B_neg = 10
EV1_C_pos = 11
EV1_C_neg = 12
```

这说明 EV1 是 `SS_Slave` 中的第二台设备：

- EV2 使用 SS 端口 1～6；
- EV1 使用 SS 端口 7～12。

---

### 1. 六个 PMIO 端点进入 SS

顶层三条 EV1 Stubline 到达 SS 后，仍然是六个独立绕组端点：

```text
A_pos、A_neg
B_pos、B_neg
C_pos、C_neg
```

此时还没有形成三相 Delta。

---

### 2. 在 SS 内重新组成 Delta(D1)

正确连接为：

```text
A相线路节点 = A_pos + C_neg
B相线路节点 = A_neg + B_pos
C相线路节点 = B_neg + C_pos
```

也就是：

```text
C绕组末端 → A绕组首端
A绕组末端 → B绕组首端
B绕组末端 → C绕组首端
```

形成闭合三角形。

这是标准的绕组首尾交叉连接，不是随意把六根线两两组合。当前项目已明确按以上关系构成低压 Delta。

如果错误地接成：

```text
A_pos + A_neg
```

相当于把同一绕组两端直接接在同一个节点，可能造成绕组短接或完全错误的拓扑。

如果三个交叉顺序接错，则可能出现：

- 相序错误；
- 30°相移方向错误；
- 电压或功率方向异常；
- 三相不平衡。

---

### 3. Three-Phase V-I Measurement

Delta 的三个线路节点接入低压侧三相 V-I Measurement。

该块有：

```text
A/B/C
a/b/c
```

三相电气穿越端口，继续接到两电平变流器交流侧。

它还输出：

```text
Vabc
Iabc
```

普通数值测量。

在当前模型中，如果这些低压测量输出暂时没有使用，应在 SS 内部接 Terminator，但不能删除电气穿越连接。

---

### 4. Two-Level Converter

两电平变流器有三类关键接口：

```text
A/B/C   三相交流电气端口
+/-     直流侧电气端口
g       六路门极控制信号
```

`g` 来自 PWM。

`BL=0` 表示不进行门极封锁。

所以电气链为：

```text
Stubline到达的变压器低压端
→ Delta
→ 三相V-I测量
→ Two-Level Converter
→ inv测量
→ L2
→ C2
→ 后续交流滤波连接
```

或者按照模型具体方向理解为变流器通过 LC 滤波器连接至变压器低压母线。画布左右并不决定功率方向，实际要看电气端口连接。

---

### 5. Control System 与 PWM

控制器需要：

```text
Vabc
Iabc
Fref
Vref
Droop_On
Pref
Qref
GridOn
```

这些不是从 Stubline 中直接抽取出来的，而是从普通通信向量中获取。

第二张图左上角：

```text
ev_io_vec
→ OpComm
→ 组级Demux
→ 设备级Demux
→ Control System1
```

完整过程是：

```text
24维EV组向量
→ [12 12] Demux
→ EV1的12维
→ [3 3 1 1 1 1 1 1] Demux
→ EV1 Control System
```

控制器输出：

```text
Vpwm或调制参考
→ PWM
→ 六路g
→ Two-Level Converter
```

因此本地快速控制器、PWM 和变流器都在同一个 SS 中，不需要把六路高速门极信号跨任务传输。

这是合理的安排，因为：

- 变流器和 PWM 联系最紧密；
- 门极信号每步都更新；
- 如果控制器在 SM、变流器在 SS，就会引入额外的同一步通信依赖；
- 把控制器和变流器放在同一任务内，局部闭环计算更直接。

## 六、Stubline 和 OpComm 为什么必须同时存在

这是最容易混淆的地方。

### Stubline 负责的不是测量数据

Stubline 负责：

```text
电气端口电压
电气端口电流
网络状态
功率交换关系
```

它连接的是物理电气端口。

### OpComm 负责的不是功率传输

OpComm 负责：

```text
Vabc测量值
Iabc测量值
Fref
Vref
Pref
Qref
状态开关
```

它传递的是普通 double 数值。

即使你通过 OpComm 把三相电压和三相电流数值发给 SS，也不能让变流器真正接入电网。

因为控制器只知道：

```text
现在测得多少伏、多少安
```

但电气网络仍然不知道：

```text
变流器注入的电流怎样反过来改变PCC电压
```

这个双向电气作用必须由 Stubline 维持。

所以当前结构实际存在两条并行路径：

```text
电气路径：
Grid → Transformer → Stubline → Converter

信息路径：
Measurement/References → Memory → OpComm → Controller → PWM
```

## 七、一个 100 μs 仿真步内，四个任务大致怎样工作

设当前计算步为第 `k` 步。

### SM_Master

使用已经确定的边界状态计算：

```text
电网
PCC
负荷
馈线
三台单相变压器
高压侧V/I
```

同时形成下一次需要发送的控制向量。

### SS_Slave / SS_Slave2 / SS_Slave3

分别使用：

```text
Stubline提供的边界状态
+
OpComm收到的控制数值
```

计算：

```text
Delta低压网络
变流器开关状态
LC滤波器
本地控制
PWM
```

### 计算结束

各任务更新：

- 下一步的 Stubline 边界状态；
- 下一步普通通信数据；
- 内部电气和控制状态。

由于 Stubline 和 Memory 都提供了状态边界，SM 与三个 SS 不需要在同一步形成：

```text
SM等SS
同时SS又等SM
```

因此能够并行。

你刚才实际 Execute 的 Monitoring 已经证明这种并行不是停留在理论上：

- 四个任务平均执行时间约 6.6～7.1 μs；
- 100 μs 步长；
- 运行约 317 s；
- Overrun 为 0。

## 八、为什么必须采用三台单相变压器，而不是继续用一个三相块

核心原因是需要暴露六个低压绕组端点。

一个封装的三相 Yg/Delta 变压器通常只在外部暴露：

```text
高压侧A/B/C
低压侧a/b/c
```

内部 Delta 的六个绕组首尾端已经封装在块内部，无法在中间插入三条差分 Stubline。

拆成三台单相变压器以后，每相都有：

```text
一次侧1+、1-
二次侧2+、2-
```

这样才能：

1. 在 SM 内显式组成高压 Yg；
2. 把三个低压绕组的六个端点引到顶层；
3. 每个绕组通过一条差分 Stubline；
4. 在 SS 内重新组成低压 Delta。

这就是官方母版结构能够形成有效 RT-LAB 电气边界的原因。

## 九、变压器阻抗与 Stubline 参数是什么关系

当前结构不是在原变压器后面随意多加三条线。

当前参数为：

```text
单相变压器：
额定 [110000/3, 50]
绕组电压 [10000/√3, 480]
R = [0.0015, 0] pu
L = [0.03, 0] pu

Stubline：
Rpu = 0.0015
Lpu = 0.03
Sbase = 110000/3
Vbase = 480
Fbase = 50
Ts = 1e-4
```

含义是：

- 变压器第一绕组保留相应串联阻抗；
- 第二绕组内部对应阻抗设置为 0；
- 低压侧需要的那部分串联电气特性由 Stubline 表示；
- 不能在第二绕组和 Stubline 中重复计入相同阻抗。

早期直接使用普通三相 Stubline 替代小电感线路时，自动电容引入约 2.04 Mvar 无功，说明 Stubline 不是透明电线。后来才改用官方差分绕组边界结构。

## 十、从原设备开始，实际改造顺序是什么

以一台 EV 为例，正确理解顺序如下。

### 第一步：确定切割位置

选择：

```text
变压器三个低压绕组的六个端点
```

作为 SM/SS 的电气分界。

不是在：

- PCC 处切；
- 控制器中间切；
- PWM 与变流器之间切；
- 普通 Vabc/Iabc 信号处切。

### 第二步：SM 保留高压侧

SM 中保留：

```text
PCC
设备高压馈线
Line_EV
prim V-I测量
三台单相变压器
高压侧Yg
```

### 第三步：低压绕组端子不在 SM 内闭合

三台变压器的：

```text
2+/2-
```

分别引出成六个 PMIOPort。

### 第四步：顶层增加三条差分 Stubline

每相一条：

```text
A_pos/A_neg
B_pos/B_neg
C_pos/C_neg
```

### 第五步：SS 建立六个对应 PMIOPort

确保端口号和正负端完全对应。

### 第六步：SS 中重建 Delta

按：

```text
A = A_pos + C_neg
B = A_neg + B_pos
C = B_neg + C_pos
```

连接。

### 第七步：把低压主电路移入 SS

包括：

```text
低压V-I测量
直流源或电池/PV模型
Two-Level Converter
LC滤波器
本地Control System
```

## 十一、如何推广到 PV 和 ESS

PV、ESS 和 EV 的 AC 侧拆分骨架完全相同：

```text
PCC馈线
→ 三台单相变压器
→ 六个PMIO
→ 三条差分Stubline
→ SS内Delta
→ 两电平变流器
→ LC滤波器
```

不同的只是设备自身功能。

### PV 与 EV 的区别

PV 的 SS 中需要保留：

- PV 直流源或光伏等效源；
- PV1/PV2 控制器；
- 对应 PV 的 Pref、Qref；
- 后续 PVmax 对 Pref 的限制。

不能把 EV 的充电功率符号和初值直接复制给 PV。

### ESS 与 EV 的区别

ESS 的 SS 中需要保留：

- 储能直流源；
- ESS 控制器；
- 充放电双向 Pref；
- SOC 对充放电能力的约束。

尤其要核对：

```text
正功率是放电还是充电
负功率是放电还是充电
```

### 可以直接复制的部分

若额定参数相同，可以复制：

- 三台单相变压器结构；
- PMIO 排列；
- 三条差分 Stubline；
- Delta 连接；
- 低压 V-I Measurement；
- Converter + LC 的 AC 侧拓扑；
- 12 维通信接口形式。

### 不能机械复制的部分

不能机械复制：

- Pref 符号；
- 直流侧源；
- 控制器参数；
- SOC/PVmax 逻辑；
- 设备名称；
- PMIO 编号；
- Mux 中设备顺序。

## 十二、当前六台设备的端口对应

| 设备   | SM 端口 | 对应 SS 端口 |
| ------ | :-----: | :----------: |
| EV2    |  1–6    |  SS_Slave 1–6   |
| EV1    | 19–24   |  SS_Slave 7–12  |
| ESS1   |  7–12   |  SS_Slave2 1–6  |
| ESS2   | 25–30   | SS_Slave2 7–12  |
| PV1    | 13–18   |  SS_Slave3 1–6  |
| PV2    | 31–36   | SS_Slave3 7–12 |

SM 端口没有按设备类别连续排列，是逐步 Build 恢复过程中形成的历史顺序。

它不影响电气功能。

真正重要的是每台设备的六个端口保持：

```text
奇数 = 正端
偶数 = 负端

第1对 = A相
第2对 = B相
第3对 = C相
```

画布上摆放在左边还是右边没有电气意义，端口编号和实际连线才有意义。

## 十三、你自己复制其他设备时必须检查的项目

### 电气侧

- 三台单相变压器容量是否为总容量除以 3；
- 高压绕组是否为 `VLL/√3`；
- 高压侧是否正确组成 Yg；
- 六个低压端是否全部独立引出；
- 每相 Stubline 的正负端有没有接反；
- SM 和 SS 端口编号是否一一对应；
- Delta 是否按交叉关系连接；
- 变压器第二绕组和 Stubline 阻抗有没有重复；
- 原设备支路是否已经删除，避免重复设备。

### 普通信号侧

- 一台设备是否严格为 12 维；
- 12 维顺序是否一致；
- 两台设备合并顺序是否与 SS 的 `[12 12]` Demux 一致；
- Memory 是否在 SM Outport 之前；
- SS Inport 后是否先进入 OpComm；
- 是否仍存在跨 SM/SS 的隐藏 Global Goto/From；
- `GridOn、Fref、Vref、Pref` 是否都已显式传递。

### 控制侧

- PWM 输出是否真正接到 Converter 的 `g`；
- 原固定 `zeros(6,1)` 是否已经删除；
- `BL` 是否为预期状态；
- PV、ESS、EV 的 Pref 符号是否分别正确；
- 测量来源是否符合原控制器设计。

### 测量块

- 复制后的 `SetLabelV/SetLabelI` 是否关闭；
- 没有进入 Mask 内部修改 Goto；
- 未使用的普通 Vabc/Iabc 输出是否在所属 SS 内接 Terminator；
- 电气 `A/B/C、a/b/c` 端口不能接 Terminator。
