# 阶段性总结：截止7.30第一次解耦分核失败

## 一、问题是怎样暴露出来的

原三逆变器模型采用：

```
顶层：
sm_circuit
sc_display

sm_circuit 内部：
ARTEMiS-SSN 分组
XHP 开启
Cores = 4
```

最初以为这已经实现了四核并行。后来工作人员指出，顶层只有一个实时计算子系统，没有拆成多个 `SS_` 任务，因此可能没有形成真正的任务级并行。

随后做了严格对照：

```
同一个三逆变器模型
SSN、XHP、100 μs 步长均不变
只修改 Cores：4 → 1
```

结果为：

```
Cores = 4：约 700 μs/步
Cores = 1：约 700 μs/步
```

因此得到的准确结论是：

> RT-LAB 界面确实给 `sm_circuit` 分配了 4 个核，但模型主要计算没有被有效并行化，实际性能仍接近单核串行。

不是完全没有分配 4 核，而是 **分配后没有获得有效加速**。

RT-LAB 资料说明，任务级分核需要将顶层划分为一个 `SM_` 和多个 `SS_` 实时子系统；SM 和 SS 承担实时计算，SC 只负责上位机显示。

---

## 二、针对问题制定了什么计划

决定不再继续调整原 SSN 核数，而是转向真正的任务级分核：

```
原方案：
一个 sm_circuit 内部使用 SSN
→ 给同一个 SM 分配 4 核

新方案：
一个 SM ＋ 三个 SS
→ 形成 4 个独立实时任务
→ 分别分配到 4 个 CPU 核
```

同时确定以下原则：

1. 使用最终希望采用的六逆变器完整模型，不再以三逆变器作为主模型。
2. 所有修改在 Simulink 副本中完成，原模型永久保留。
3. 第一版所有实时任务均保持 100 μs，不同时引入多速率。
4. 普通控制和测量数值通过 `OpComm` 传递。
5. 三相电气物理连接不能通过普通 OpComm 传递，需要使用 ARTEMiS 电气解耦线路。
6. 暂时不增加 Memory，避免与设备控制器原有 Unit Delay 叠加。
7. 拆分后先做离线等效性验证，通过后才能进入 RT-LAB 测试。

培训资料说明，实时子系统输入需要先经过 OpComm；为实现并行，实时任务之间最好交换带状态的信号，否则可能串行或死锁。

---

## 三、为什么采用 Stubline

六台逆变器通过三相电气线路接入 PCC，不能简单剪断 A、B、C 线后用普通 Inport、Outport 和 OpComm 连接。

因此采用：

| 数据类型 | 传输方式 |
|---------|---------|
| Pref、Fref、Vref、Droop、Qref 等普通数值 | → OpComm |
| A、B、C 电压电流网络（三相电气连接） | → ARTEMiS Stubline |

Stubline 的作用是：

- 保留两侧的电气物理连接；
- 将原来一个大状态空间网络拆成多个小网络；
- 使不同 SM/SS 能够分别计算；
- 通过一个仿真步的传播关系实现计算解耦。

ARTEMiS 资料指出，跨顶层 SM/SS 的电气连接应使用 ARTEMiS 线路；短线路可采用 Stubline，但使用前后必须比较动态响应。

---

## 四、最终采用了怎样的第一版任务划分

没有直接按照 PV、ESS、EV 类别均匀分组，而是优先利用现有电气线路位置，减少拓扑改动。

形成：

```
sm_circuit
├─ PV1
├─ PCC、电网、负荷
├─ 三相断路器
├─ 公共测量
├─ 监督控制
└─ AGC、通信和公共逻辑

ss_feeder1
├─ ESS1
├─ ESS1 与 EV1 之间原 RL 线路
└─ EV1

ss_pv2_ess2
├─ PV2
└─ ESS2

ss_ev2
└─ EV2

sc_display
└─ 显示和上位机交互
```

四个电气分界为：

1. PCC 到 ESS1/EV1 馈线的第一段 RL 线路
2. Line_PV2
3. Line_ESS2
4. Line_EV2

这些原 RL 线路均被顶层三相 Stubline 替换。

Stubline 初始参数沿用了原线路参数：

```
三相
R = 0.065 Ω
L ≈ 0.00066845 H
Ts = 100 μs
```

## 五、实际完成了哪些改造步骤

### 5.1 建立顶层任务结构

在六逆变器副本中建立：

```
sm_circuit
ss_feeder1
ss_pv2_ess2
ss_ev2
sc_display
powergui
ARTEMiS Guide
```

### 5.2 迁移 ESS1 和 EV1

将：

- ESS1
- ESS1—EV1 之间 RL 线路
- EV1

迁入 `ss_feeder1`。

建立 7 路普通控制向量：

```
Fref
Vref
Droop_On
ESS1_Pref
EV1_Pref
ESS1_Qref
EV1_Qref
```

在 SS 内部通过：

```
Inport → OpComm → Demux(7)
```

送到两台设备。

### 5.3 迁移 PV2 和 ESS2

将 PV2、ESS2 迁入 `ss_pv2_ess2`。

建立 7 路控制向量：

```
Fref
Vref
Droop_On
PV2_Pref
ESS2_Pref
PV2_Qref
ESS2_Qref
```

并分别使用两条 Stubline 连接 PV2、ESS2 到 PCC。

### 5.4 迁移 EV2

将 EV2 迁入 `ss_ev2`。

建立 5 路控制向量：

```
Fref
Vref
Droop_On
EV2_Pref
EV2_Qref
```

并使用一条 Stubline 连接到 PCC。

### 5.5 完成 ARTEMiS 结构检查

最终 `Ctrl+D` 无错误。

ARTEMiS 日志显示原来的 39 个开关被拆成：

| 子系统 | 开关数 |
|--------|-------|
| sm_circuit | 9 个开关 |
| ss_feeder1 | 12 个开关 |
| ss_pv2_ess2 | 两个独立的 6 开关网络 |
| ss_ev2 | 6 个开关 |

即：

```
9 + 12 + 6 + 6 + 6 = 39
```

说明电气网络拆分在结构上已经成功，不再是一个 39 开关的大型单组。

| 信号 | 原模型 | 拆分模型 | 结果 |
|------|--------|---------|------|

## 八、为什么出现约 2.04 Mvar 无功

每条 Stubline 参数显示：

```
L ≈ 0.6684 mH
R = 0.065 Ω
C ≈ 14.96 μF
```

Stubline 为了实现一个步长传播，会根据采样时间和电感自动形成等效电容。

当前使用 4 条 Stubline，每条产生约 510 kvar 容性无功：

```
约 510 kvar × 4
≈ 2040 kvar
```

实际拆分模型 PCC 无功约为：

```
2042.8 kvar
```

两者几乎完全对应。

因此根因已经明确：

> 原线路电感过小，直接将其替换为 Stubline 后，Stubline 自动形成了较大的等效电容，造成约 2.04 Mvar 容性无功，进而抬升 PCC 电压约 4%。

## 九、当前得到的阶段结论

### 已证明的内容

1. 原 SSN 四核方案没有获得有效并行加速。
2. `SM ＋ 3 个 SS` 的任务级分核结构在模型中可以建立。
3. 普通信号通过 OpComm 传递的方法可行。
4. 三相电气网络可以通过顶层 Stubline 拆成多个独立网络。
5. 原 39 个开关已经成功拆分为多个较小计算组。
6. 当前任务分组本身没有被否定。
7. 当前失败主要来自 Stubline 参数和电气等效问题，而不是 SM/SS 结构错误。

### 当前不能接受的内容

当前使用：

```
R = 0.065 Ω
L = 0.668 mH
Ts = 100 μs
```

直接替换原 RL 线路的 Stubline 方案，导致：

- 约 2.04 Mvar 额外容性无功；
- PCC 电压提高约 4%；
- 原模型与拆分模型不等效。

因此暂时不能：

```
导入 RT-LAB
分配四核
测试实时性能
```

即使实时性能改善，运行的也已经不是原来的物理系统。
