# 分核中名词解释

## 先把整体关系说明白

你现在要做的事情，本质上是把原来由一个 CPU 核完成的"大计算任务"，拆成几个能同时运行的小任务：

```text
SM_Grid        → 核1
SS_PV          → 核2
SS_ESS         → 核3
SS_EV          → 核4
SC_Display     → 上位机显示，不占实时核
```

拆开后会出现两类跨子系统连接：

```text
普通数值信号：
Pref、Fref、测量值、门极脉冲等
→ 使用 OpComm

三相电气物理连接：
逆变器支路与 PCC 母线之间的 A/B/C 电气端口
→ 使用 ARTEMiS Stubline 或分布参数线路
```

Memory 解决的是多个实时子系统之间"谁先算"的问题；OpComm 解决的是普通数值怎样跨实时子系统传递；Stubline 解决的是电气端口怎样跨实时子系统连接。

---

## 1. 添加 Memory 的作用是什么

Memory 的作用是：**输出上一个仿真步保存的数值，而不是立即输出本仿真步刚算出的数值。**

例如模型步长为 100 μs：

```text
当前时刻：1.0000 s
Memory输出：0.9999 s 时保存的值

当前计算结束后
把 1.0000 s 的新值保存起来
供 1.0001 s 使用
```

可以简单理解成：

```text
输入 x(k)
→ Memory 保存
→ 当前输出 x(k-1)
```

RT-LAB 资料把 Memory、Unit Delay 和积分器称为具有"状态"的模块，因为它们可以根据自己保存的历史值产生输出，不必立即等待本步的输入。资料第 16—25 页展示了完全并行、部分并行、串行和死锁的区别，并在 PID 示例中通过增加 Memory 使两个实时任务能够并行。

### 对我们模型有什么作用

假设把电气系统放在 SM，把逆变器控制器放在 SS：

```text
SM 电气系统
→ 计算 Vprim、Iprim
→ 发给 SS 控制器

SS 控制器
→ 根据 Vprim、Iprim 计算门极 g
→ 发给 SM 电气系统
```

如果双方都要求使用"当前 100 μs 这一步"的最新值，就会变成：

```text
SM：我要等 SS 先算出当前门极 g
SS：我要等 SM 先算出当前电压电流
```

双方互相等待，无法真正同时计算。

加入 Memory 或已有的 Unit Delay 后，可以改成：

```text
第 k 步：

SM 使用上一拍门极 g(k-1)
计算当前电气量 V(k)、I(k)

SS 使用收到的测量量
计算下一拍门极 g(k)

第 k+1 步：

SM 使用 g(k)
```

这样双方不必在同一步内互相等待。

### Memory 与 Unit Delay 的区别

两者作用接近，但使用方式略有不同：

| 模块 | 主要特点 |
| ---- | -------- |
| Memory | 保存上一个主要仿真步的值，常用于打断直接传递关系 |
| Unit Delay | 明确保存一个离散采样周期，采样时间和初值更容易控制 |
| Integrator | 保存连续或离散积分状态，不只是简单延迟一拍 |

你们的逆变器控制中原本可能已经存在：

```text
调制波
→ Unit Delay
→ PWM Generator
```

如果这个 Unit Delay 正好位于准备拆分的边界，就可能已经具备状态，不需要再额外增加 Memory。

**不能看到教程有 Memory 就直接添加。** 如果原模型已经有一拍延迟，再加一个 Memory，可能变成两拍延迟：

```text
原来延迟：100 μs
修改后延迟：200 μs
```

这会影响电流环、PWM 和稳定性。

## 2. SM 和 SS 之间的 OpComm 起什么作用

OpComm 是 RT-LAB 实时子系统之间传递普通 Simulink 数值信号的通信接口。

可以理解为：

```text
SM 和 SS 是两个独立计算任务
OpComm 是它们之间的同步数据入口
```

例如把 PV 控制器放到 `SS_PV` 中，SM 向它提供：

```text
Vprim 三相电压
Iprim 三相电流
Pref
Qref
Fref
Vref
GridOn
Droop_On
```

这些信号进入 `SS_PV` 后，必须先经过 OpComm，才能被该 SS 内的控制模块使用。

`SS_PV` 计算出的信号，例如：

```text
三相调制波
或
六路门极脉冲 g
```

返回 SM 时，SM 端的对应输入也需要通过 OpComm 接收。

RT-LAB 资料第 10—15 页明确规定，实时子系统的输入应先经过 OpComm；实时同步信号和来自 SC 控制台的异步信号通常使用不同的 OpComm 接收。

### OpComm 不做什么

OpComm 本身不负责：

- 计算控制算法；
- 添加或减少功率；
- 改变数值含义；
- 自动解决电气网络；
- 直接连接三相电气物理端口。

它只负责：

```text
把一组数值
按照设定的周期
从一个实时任务传到另一个实时任务
```

### 对我们模型的具体用途

如果采用"只拆控制器"的方案：

```text
SM_Electrical
   │
   ├─ Vprim、Iprim、Pref 等数值
   ↓ OpComm
SS_PV_Control
   │
   ├─ Vpwm 或门极 g
   ↓ OpComm
SM_Electrical
```

这时全部跨边界内容都是普通数值，可以使用 OpComm。

如果采用"完整电气支路拆分"：

```text
SS_PV 完整电气支路
↔ PCC 母线
```

A、B、C 端口不是普通数值信号，不能用 OpComm 直接连接。这时需要 Stubline。Pref、SOC、测量总线等普通信号仍使用 OpComm。

## 3. "实时子系统间尽量交换带状态的信号"是什么意思

它想表达的是：

> 为了让不同 CPU 核同时计算，两个实时子系统不能在同一个仿真步里互相依赖对方刚刚算出的结果。

### 没有状态时

假设：

```text
SM 输出 A 取决于 SS 当前输出 B
SS 输出 B 又取决于 SM 当前输出 A
```

即：

```text
A(k) 需要 B(k)
B(k) 又需要 A(k)
```

这叫同一步的直接依赖。

RT-LAB 可能出现三种情况：

#### 情况一：串行运行

```text
先算 SM
→ 再算 SS
```

虽然模型能运行，但两个核没有真正同时工作，分核没有性能收益。

#### 情况二：代数环

软件需要反复迭代求解 A 和 B，增加计算时间。

#### 情况三：任务死锁

```text
SM 等待 SS
SS 等待 SM
```

模型不能执行。

RT-LAB 资料第 18—22 页分别展示了完全并行、部分并行、串行和死锁，并说明适当使用 Delay 可以把直接信号转成状态信号，但必须核对它对动态的影响。

### 加入状态以后

把关系改成：

```text
A(k) 使用 B(k-1)
B(k) 使用 A(k-1) 或本地已有状态
```

双方都已经拥有上一步保存的数据，可以同时开始计算。

### 对我们的作用

无论是拆逆变器控制器，还是拆完整电气支路，都必须检查跨 SM/SS 闭环是否存在同一步互相等待。

这决定了：

- 分核后能否真正并行；
- 是否仍然接近 700 μs；
- 是否会 Build 失败；
- 是否会形成死锁；
- 是否需要 Memory、Unit Delay 或 Stubline；
- 是否会额外改变控制动态。

## 4. SPS 在这里是什么意思

SPS 原名是：

```text
SimPowerSystems
```

现在 MathWorks 通常称为：

```text
Simscape Electrical Specialized Power Systems
```

在你们模型中，以下模块基本都属于 SPS 电气模型：

- Three-Phase Source；
- Two-Level Converter；
- Universal Bridge；
- 三相变压器；
- RLC 线路和负荷；
- 三相断路器；
- 电压电流测量；
- powergui；
- LC 滤波器；
- 电网和 PCC 物理网络。

这些模块不是普通的加法、乘法或逻辑块。它们共同形成一个三相电气网络，软件需要根据基尔霍夫定律、开关状态、电感和电容状态，统一求解电压和电流。

ARTEMiS 是在 SPS 模型基础上进行实时求解优化的工具，包括：

- 优化状态空间矩阵；
- 预计算开关拓扑；
- 对大型电路进行解耦；
- 使用 SSN；
- 使用 Stubline 或分布参数线路。

相关资料说明，SPS 会形成状态空间矩阵，开关状态变化会导致矩阵拓扑变化；ARTEMiS 通过稀疏矩阵和预计算等方法提高实时性能。

### 对我们的意义

你们模型最耗时的部分，很大概率就是：

```text
六台开关级逆变器
＋滤波器
＋变压器
＋PCC 电气网络
```

也就是 SPS 电气网络求解，而不是单纯的 AGC 或 Modbus 逻辑。

因此，真正想显著降低每步计算时间，需要设法把这个大 SPS 网络拆成较小的电气子网络，而不仅是把几个普通算法模块移到 SS。

## 5. 为什么电气物理连接不能直接用 OpComm，而要用 DPL 或 Stubline

### 普通 Simulink 信号是什么

例如：

```text
PCC 功率 = -40 kW
Pref = 0.5 pu
电压测量 = [Va, Vb, Vc]
门极信号 = [0, 1, 0, 1, 0, 1]
```

这些都是已经算出来的数值，可以通过 OpComm 传输。

### 电气物理端口是什么

例如逆变器变压器出口的：

```text
A
B
C
```

它们不是简单的三个数字。

在这个连接点上，软件必须同时满足：

```text
两端电压关系
三相电流关系
基尔霍夫电流定律
线路 R、L、C 动态
开关状态
```

如果直接剪断电气线，把 A/B/C 转换成普通 Inport/Outport，原来的电气约束就被破坏了。

### DPL 和 Stubline 做了什么

DPL 是：

```text
ARTEMiS Distributed Parameters Line
分布参数线路
```

Stubline 是：

```text
ARTEMiS Stubline
短线路解耦模型
```

它们既是电气线路模型，又能在两端之间形成明确的传播时间。

于是：

```text
左侧子系统
只使用已经到达左端的历史波信息计算

右侧子系统
只使用已经到达右端的历史波信息计算
```

双方不需要在同一个仿真步里立即知道对方刚算出的电压和电流，因此可以放在不同 CPU 核上独立求解。

资料第 7—11 页说明，顶层 SM/SS 之间传递电气信号时需要使用 ARTEMiS 线路；长线路可使用分布参数线路，短线路可使用 Stubline。

### 对我们有什么帮助

例如将 PV1 完整支路放入 `SS_PV`：

```text
SS_PV
PV1 逆变器
→ 滤波器
→ 变压器
→ 三相 Stubline 的一端

另一端
→ SM_Grid 中的 PCC 母线
```

这样：

- PV1 的开关电路由一个核求解；
- PCC、电网和其他设备由另一个核求解；
- 两边通过 Stubline 保持电气连接；
- 不需要把物理 A/B/C 端口错误地变成普通数值线；
- 两个电气网络可以并行计算。

普通控制信号仍然走 OpComm：

```text
SM 中的 AGC Pref
→ OpComm
→ SS_PV

SS_PV 中的实测功率
→ OpComm
→ SM 中的 AGC 或记录模块
```

## 6. 解耦和 Stubline 到底是什么意思

### 什么是解耦

这里的"解耦"不是逆变器 dq 电流控制中的前馈解耦。

这里指的是**计算解耦**：

```text
原来：
六台逆变器＋PCC＋电网＋负荷
组成一个巨大的电气计算题

解耦后：
PV 部分一个较小计算题
ESS 部分一个较小计算题
EV 部分一个较小计算题
电网与 PCC 一个较小计算题
```

每个核分别计算一部分，再通过规定的接口交换结果。

资料第 4—6 页说明，大型电气系统会形成很大的状态空间矩阵；解耦后变成若干低阶矩阵，可能降低计算量并提高实时性能。

### Stubline 通俗理解

Stubline 可以理解成在两个电气子系统之间加入一段"很短但有明确传播时间的等效线路"。

它包含：

- 电阻 R；
- 电感 L；
- 根据步长计算的等效电容；
- 精确一个仿真步的传播延迟。

例如步长 100 μs：

```text
一端发生的电压电流变化
经过 100 μs 后
另一端才能感受到
```

正是这 100 μs 传播时间，使两端在当前步内不用互相等待。

### 为什么微电网通常考虑 Stubline

分布参数线路适合实际较长的输电线路。

资料给出的最短线路长度条件为：

```text
300000 × Ts 千米
```

当：

```text
Ts = 100 μs = 0.0001 s
```

对应：

```text
300000 × 0.0001 = 30 km
```

你们微电网内的逆变器到 PCC 显然不是 30 km 以上的线路，因此不适合为了分核虚构一条长线路。

Stubline 专门用于较短的 R-L 线路解耦。资料还指出，直流侧或变压器绕组侧有时是较合适的 Stubline 位置。

### 对我们模型的可能使用方式

六逆变器模型可能形成：

```text
SM_Grid
PCC、电网、负荷、中央控制

SS_PV
PV1、PV2 完整支路

SS_ESS
ESS1、ESS2 完整支路

SS_EV
EV1、EV2 完整支路
```

每台逆变器支路与 PCC 之间通过三相 Stubline 连接。

由于原来有六条独立支路，原则上需要六个对应的三相解耦接口，而不是只用一个 Stubline 把两台 PV 合并成一条支路。

## 最后把五种模块放在同一张关系图里

```text
                         普通数值信号
                  Pref、状态、测量、门极
               ┌──────── OpComm ────────┐
               │                         │
         SM_Grid                     SS_PV
     PCC、电网、负荷             PV 控制＋电气支路
               │                         │
               └──── 三相 Stubline ──────┘
                       电气物理连接
```

其中：

| 模块 | 作用 |
| ---- | ---- |
| SM/SS | 不同 CPU 核上的计算任务 |
| OpComm | 不同计算任务之间传输普通数值 |
| Memory / Unit Delay | 保存上一拍数值，打断同一步相互等待 |
| SPS | 三相电力系统和电力电子物理模型 |
| ARTEMiS | 优化 SPS 实时求解 |
| Stubline | 让两个实时任务之间保持电气连接，并通过一拍传播延迟实现计算解耦 |

当前阶段最关键的判断是：**OpComm 与 Stubline 不是二选一。** 完整支路分核时，两者通常同时存在：

- 普通控制和测量信号走 OpComm；
- A/B/C 电气物理连接走 Stubline；
- 必要位置利用已有 Unit Delay 或 Memory 形成状态边界。
