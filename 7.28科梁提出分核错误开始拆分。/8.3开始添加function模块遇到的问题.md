# 8.3开始添加Function模块遇到的问题

## 一、当前问题与分核方法的关系

需要准确区分：

- 不是差分 Stubline、三台单相变压器、PMIO、三组 24 维通信或任务数量设计错误。
- 问题确实发生在 RT-LAB 的多任务模型分离过程中。
- 更准确地说，是 RT-LAB 对分核模型中的 Stateflow/MATLAB Function 对象处理异常。

所以不能简单表述为"与分核完全无关"，应表述为：

> 分核拓扑和电气解耦方式已经通过 Build 验证；当前故障是 RT-LAB 在分离这个合法多任务模型时，对新增 Stateflow EMChart 对象的复制、修复和 Signals Database 扫描出现异常。

T0 只加入了一个无状态的 `y=u` Function，没有接入任何跨任务通信，也没有改变 Stubline、OpComm、PMIO或电气网络，仍然出现同一错误。这个证据已经足以把当前问题从业务模型和 AGC 算法中分离出来。

### 现有分核方法是否正确

正确。

OPAL-RT 官方文档明确说明：

- Stubline 可以作为不同 CPU 核之间的计算任务解耦元件；
- 用于 RT-LAB 分核时，Stubline 应位于模型顶层；
- 官方提供的 `artemis_Transfo_StublineRT` 示例就是针对变压器和 Stubline 的多核解耦；
- Stubline 可以代替变压器部分漏感，并通过一个步长的传播延迟分离两侧状态空间计算。

你们从官方示例出发，采用每台设备三台单相两绕组变压器、三条差分 Stubline、高压侧放 SM、低压侧放 SS，并逐步完成 A—J2 的 Build，符合官方任务级分核路径。六设备、3 个 SS、18 条 Stubline、六套控制器以及三组 24 维通信已经共同 Build 成功。

但还要区分两个未验证事项：

- Build 正确不等于 100 μs 实时运行已经成功；
- 官方分核结构正确不等于与原模型的电气动态已经完全等效。

这两项必须通过 Load、Execute、Monitoring 和原模型对比验证。

## 二、发给科梁工作人员的说明

> 下面这段可直接通过微信或技术支持工单发送。

您好，我们正在使用 OP5700 和 RT-LAB 搭建一个六逆变器微电网实时模型。

### 一、使用环境

- RT-LAB：v2024.1.1.38
- MATLAB/Simulink：R2023b，64 bit
- ARTEMiS：7.8.0.17
- 目标机：OPAL-RT OP5700，OPAL-RTLinux x86
- 固定步长：100 μs

### 二、模型结构

模型采用 1 个 SM、3 个 SS 和 1 个 SC：

```text
SM_Master：10 kV 电网、PCC、负荷、高压侧变压器边界、测量和上层控制
SS_Slave：2 台 EV
SS_Slave2：2 台 ESS
SS_Slave3：2 台 PV
SC_Console：控制台和监测
```

电气跨任务边界按照官方 `artemis_Transfo_StublineRT` 示例建立。每台设备采用三台单相两绕组变压器和三条差分 Stubline，Stubline 位于模型顶层。总计六台设备、18 条差分 Stubline、SM 侧 36 个物理端口。

普通控制信号通过 OpComm 传递。每类两台设备合成一条 24 维 SM→SS 通信，共三条。

### 三、已经成功验证的内容

我们从官方单设备模型开始逐步增加结构，每一步单独 Rebuild All，以下内容均已成功 Build：

- 1SM+1SS，一台完整逆变器；
- 1SM+1SS，同一 SS 两台设备；
- 1SM+2SS；
- 1SM+3SS；
- 3SS、六设备、每个 SS 两台设备；
- 六套本地控制器、PWM 和门极链；
- 三组 24 维 SM→SS OpComm 通信；
- 正式 10 kV 电网、PCC 断路器和两个负荷；
- PCC/Grid V-I 测量、PLL、频率、P/Q 和 RMS 计算。

当前成功基线模型为 `J2_FORMAL_MEASUREMENTS`。

### 四、最小复现方法

从 `J2_FORMAL_MEASUREMENTS` 成功母版新建副本，未改变任何电气连接、Stubline、OpComm、任务端口或原控制器。

只在 `SM_Master` 中增加：

```text
Constant(1)
→ MATLAB Function
→ Terminator
```

MATLAB Function 代码只有：

```matlab
function y = fcn(u)
y = u;
end
```

该 Function 不接 PCC、不接设备、不参与跨任务通信，也没有 persistent、数组或局部函数。

### 五、Build 结果

- 模型分离完成；
- 所有 SM、SS 的 C 代码生成完成；
- 参数数据库创建成功；
- 随后在 `Creating the signals database` 阶段失败。

核心错误为：

```text
Subsystem ###恢复的 Stateflow 图### not found.
Error generating C code for t0_simple_function_5_ss_slave3 subsystem.
```

### 六、分离模型中的异常证据

检查 RT-LAB 生成的 Opcommon 分离模型后发现：

- SM 分离模型中 Function 正常存在于：


- 所有 C 代码仍然能够生成，最终在 Signals Database 扫描恢复对象时失败。

## 三、日志分析

这段日志说明了两类情况，其中只有第一类与当前故障直接相关。

### 关键异常

下面两条警告大意是：

```text
未连接
t0_simple_function_5_ss_slave3/
###恢复的 Stateflow 图###/
SM_Master_MATLAB Function_repaired_1
的输入端口1

未连接该模块的输出端口1
```

它说明 RT-LAB 在生成 `SS_Slave3` 的分离模型时，错误地把原本只位于 `SM_Master` 中的 MATLAB Function 对应 Stateflow 图带入了 `SS_Slave3`。

原模型中的关系应是：

```text
SM_Master
└─ MATLAB Function
   Constant → Function → Terminator
```

正常情况下，这个 Function 不应出现在：

```text
t0_simple_function_5_ss_slave3
```

但实际分离后出现了：

```text
SS_Slave3
└─ ###恢复的 Stateflow 图###
   └─ SM_Master_MATLAB Function_repaired_1
```

而且这个恢复副本的输入、输出都没有连接。说明 RT-LAB/Stateflow 的处理过程大致是：

1. RT-LAB 分离 SM、SS1、SS2、SS3；
2. MATLAB Function 被识别为 `Stateflow.EMChart`；
3. Function 的 Stateflow 图元数据被错误带入 SS3；
4. SS3 中找不到它原本对应的 Simulink 块和连线；
5. Stateflow 将其判断为损坏对象，并生成 `repaired_1` 恢复副本；
6. 恢复副本没有真实输入、输出连接；
7. 后续 Signals Database 再扫描该临时恢复对象时，出现"恢复的 Stateflow 图不存在"。

因此，这两条警告支持的结论是：

> 当前问题不是简单 Function 的代码 `y=u` 写错，也不是它在 SM 中没有正确接线，而是 RT-LAB 多任务模型分离时错误处理了 MATLAB Function 的 Stateflow 图对象。

### `Three-Phase V-I Measurement6` 警告

另外两条大意是：

```text
SS_Slave3/Three-Phase V-I Measurement6
输出端口1未连接

输出端口2未连接
```

这是低压三相 V-I 测量块的普通信号输出：

- `Vabc`
- `Iabc`

暂时没有被其他普通 Simulink 模块使用。

它的三相电气端口仍然可以正常连接并参与电气网络计算，因此这种未连接输出通常只是警告。J2 成功模型中已经存在此类未使用测量输出，并且能够 Build、Load、Execute，说明它不是当前失败根因。

后续为了清理警告，可以在所属 SS 内将未使用的 `Vabc`、`Iabc` 接 Terminator，但现在没有必要为了这个警告修改模型。

### 乱码代表什么

例如：

```text
###»ָ´µÄ Stateflow ͼ###
```

实际是：

```text
###恢复的 Stateflow 图###
```

前面的乱码是中文日志被错误编码显示。乱码本身不是主要故障，真正异常是这个恢复图：

- 不应出现在 SS3；
- 被生成为 `repaired_1`；
- 输入和输出悬空；
- 后续又在 Signals Database 阶段找不到。

### 最准确的故障链

```text
SM中增加MATLAB Function
→ RT-LAB进行1SM+3SS模型分离
→ Function的Stateflow图错误进入SS分离模型
→ Stateflow生成repaired恢复副本
→ 恢复副本端口悬空
→ C代码仍可生成
→ 参数数据库仍可生成
→ Signals Database扫描恢复对象
→ 报"恢复的Stateflow图不存在"
→ Build失败
```

所以，这段日志进一步证明：**当前故障属于 RT-LAB 多任务分离与 Stateflow/MATLAB Function 对象之间的工具链异常，不是差分 Stubline、分核拓扑、SS3电气网络或简单 Function 接线造成的。**
