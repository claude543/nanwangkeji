## 三、PVmax 能否用标准 Simulink 模块实现

### 可以，而且能够与代码基本完全等价

上传的 PV 代码只做三件事：

1. 根据 `time_s` 对 `PV_time_s` 和 `PV_profile_pu` 做分段线性插值；
2. 将插值结果和 `P_unit_kW` 限制为非负；
3. 生成相同的 PV1、PV2 最大出力。

代码等价于：

```text
pu(t) = 线性插值(PV_time_s, PV_profile_pu)

Pmax = max(P_unit_kW,0) × max(pu(t),0)

Ppv_max1 = Pmax
Ppv_max2 = Pmax
```

### 推荐标准块结构

```text
Clock
  ↓
1-D Lookup Table
  ↓
Saturation（下限0）
  ↓
Product ← Saturation(P_unit_kW，下限0)
  ↓
Pmax
 ├→ Ppv_max1_kW
 └→ Ppv_max2_kW
```

#### 1-D Lookup Table 必须这样配置

- Breakpoints：`PV_time_s`
- Table data：`PV_profile_pu`
- 插值：Linear
- 小于第一个时间点：保持第一个表值
- 大于最后一个时间点：保持最后一个表值
- 输出下限：0

这与代码的行为一致：

- 时间早于第一点，返回第一个值；
- 中间采用线性插值；
- 时间晚于最后一点，返回最后一个值。

### 唯一需要确认的前提

原代码把：

```text
PV_time_s
PV_profile_pu
```

作为 Function 输入。

如果它们实际由 Constant 提供，只是配置参数，改成 Lookup Table 完全合理。

如果你要求在模型运行过程中在线修改整组曲线，则需要把表格数据设置为 RT-LAB 可调参数，而不是普通固定 Mask 参数。这仍可实现，但需要额外确认参数是否能在线更新。

### 对 PVmax 的结论

> **建议用标准 Simulink 模块重建，不需要 C，不需要 MATLAB Function。**

## 四、SOC 能否用标准 Simulink 模块实现

### 可以，而且固定步长条件下可以严格等价

SOC 代码的核心计算是：

```text
SOC新值
=
SOC旧值
-
Pess_pu × P_unit_kW × dt
/
(E_ess_kWh × 3600)
```

然后将结果限制在：

```text
[SOC_min, SOC_max]
```

正功率会使 SOC 下降，负功率会使 SOC 上升。

在当前固定步长模型中：

```text
dt = Ts
```

因此离散形式为：

```text
SOC[k]
=
Saturation(
SOC[k-1]
-
Pess_pu[k] × P_unit_kW × Ts
/
(E_ess_kWh × 3600)
)
```

### 推荐结构：Unit Delay 反馈，而不是直接用普通积分器

为了尽量与原代码逐步完全一致，每台 ESS 建议采用：

```text
Pess_pu
  ↓
Gain = -P_unit_kW × Ts / (E_ess_kWh × 3600)
  ↓
Sum ← 上一步SOC
  ↓
Saturation [SOC_min,SOC_max]
  ↓
SOC输出
  ↓
Unit Delay
  └────────返回Sum
```

Unit Delay：

```text
Initial condition = SOC0_ess1
```

ESS2 同理：

```text
Initial condition = SOC0_ess2
```

这种结构与代码的计算顺序最接近：

```text
上一时刻SOC
→ 加本步SOC变化量
→ 限幅
→ 保存为下一时刻状态
```

### 为什么不优先直接用 Discrete-Time Integrator

Discrete-Time Integrator 也能实现，但不同设置下可能存在：

- 输出限幅是在状态更新前还是更新后；
- 积分方法；
- 饱和恢复行为；
- 初始输出时序；

等细微差异。

使用：

```text
Unit Delay + Sum + Saturation
```

更容易逐步和代码结果一一对比。

### 原代码中的复位行为怎么实现

原代码在两种情况下重置：

- 第一次运行；
- `time_s < last_t`，即仿真时间回退。

在 RT-LAB 中 Stop、Reset、重新 Load 后，Unit Delay 会自动恢复初值，因此满足当前需求。

如果以后需要运行过程中主动复位 SOC，可以再增加：

```text
Resettable Subsystem
```

或：

```text
Switch：Reset时选择SOC0
```

### 对 SOC 的结论

> **建议用基础 Simulink 离散模块重建，可以等价实现，不需要 C，不需要 MATLAB Function。**

但必须先确认 ESS 功率正负号。当前代码明确采用：

```text
Pess > 0 → SOC下降
Pess < 0 → SOC上升
```

不得在迁移时凭感觉改变。

## 六、原 Modbus、延时和丢包模块怎么处理

### 原 Modbus 代码不是实际 Modbus TCP 通信

上传的 `modbus.m` 做的是：

- 六路指令缩放为寄存器整数；
- 生成从站地址、功能码、寄存器地址；
- 手工拼接字节；
- CRC16；
- 再在同一个函数中解码；
- 输出通信和 CRC 状态。

它本质上是：

```text
Modbus RTU/RS485软件仿真
```

不是 OP5700 与外部控制板之间真实的 TCP 网络接口。

因此最终模型中不建议把这段代码换成数百个基础块重新实现。

正确路线应是：

```text
RT-LAB实际Modbus TCP Slave
↕
控制板Modbus TCP Master
```

### `RS485_Delay_Steps`

这段代码只计算：

```text
delay_steps
=
round(delay_seconds / simulation_step)
```

并限制非负。

用标准块很容易替代：

```text
Divide
→ Rounding Function
→ Saturation
```

但最终实际 Modbus TCP 闭环中不需要它，除非专门做人工延时注入。

### `RS485_Packet_Loss_Mask`

它按照时间槽、通道和种子，用一个确定性公式生成六路通过/丢弃标志。

理论上也能用：

```text
Clock
Floor
Sin
Compare
Switch
```

实现，但没有必要。

更合理的故障注入方式是：

- 预先生成固定丢包序列；
- 使用 From Workspace/Lookup Table；
- 用 Switch 决定采用新命令还是保持上一命令；
- 或直接在板端通信状态机中模拟写入失败；
- 最终使用真实 TCP 断线和恢复试验。

### 对旧通信模拟层的结论

> 原 Modbus RTU、RS485 延时和丢包模块不应作为当前实时模型恢复的必选项。它们属于早期软件通信仿真，应与真实 Modbus TCP 闭环分开。
