# 1. 先看懂几个最基本的概念

## 1.1 PCC（公共耦合点）有功功率正负号

当前项目统一规定：

```
PCC（公共耦合点）功率 > 0
= 微电网向上级电网外送有功

PCC（公共耦合点）功率 < 0
= 微电网从上级电网进口有功
```

例如：

```
PCC（公共耦合点） = -100 kW
```

表示：

> 微电网正在从主网进口100 kW。

而：

```
PCC（公共耦合点） = +100 kW
```

表示：

> 微电网正在向主网外送100 kW。

---

## 1.2 Pref（有功参考值）

`Pref（有功参考值）` 是最终发给每台设备的有功指令。

### PV（光伏）

```
Pref（有功参考值） > 0
= 发电
```

### ESS（储能系统）

```
Pref（有功参考值） > 0
= 放电

Pref（有功参考值） < 0
= 充电
```

### EV（电动汽车充电负荷）

```
Pref（有功参考值） < 0
= 正在充电

Pref（有功参考值） = 0
= 停止充电
```

所以对于 EV（电动汽车充电负荷）：

```
-1.0 → -0.5
```

表示充电功率减小，相当于“减载”。

---

## 1.3 objective dP（主目标有功调节量）和 effective dP（最终有效有功调节量）

可以把它们理解成：

```
objective dP（主目标有功调节量）
= 系统“想怎么走”

effective dP（最终有效有功调节量）
= 考虑各种硬性限制以后“实际允许怎么走”
```

例如：

```
主控制想进口100 kW
但需量策略只允许进口50 kW
```

那么：

```
objective dP（主目标有功调节量）
```

必须被：

```
effective dP（最终有效有功调节量）
```

修正。

---

## 1.4 AGC（自动有功调节）

`AGC（自动有功调节）` 的作用不是决定“为什么要调功率”，而是：

> 已经知道总共需要调多少功率以后，决定2台光伏、2台储能、2台电动汽车分别承担多少。

因此：

```
策略
→ 决定“总共需要调多少”

AGC（自动有功调节）
→ 决定“6台设备各自调多少”
```

---

## 1.5 GFL（跟网型）和 GFM（构网型）

```
GFL（跟网型）
= 跟随已有电网的电压、频率和相位运行

GFM（构网型）
= 自己建立电压和频率基准
```

孤岛运行时必须至少有一台设备承担 GFM（构网型）角色。

当前测试默认：

```
ESS1（储能1）
= 孤岛构网主机
```

# 3. S1 需量控制

## 3.1 它要解决什么问题

S1的作用是：

> 防止微电网从主网进口的功率过大，超过设定的最大需量。

例如企业规定：

```
最多允许进口50 kW
```

那么：

```
PCC（公共耦合点）不能低于 -50 kW
```

---

## 3.2 验收怎么设计

先让 S7（联络线有功控制）希望：

```
PCC（公共耦合点） = -100 kW
```

也就是进口100 kW。

然后把 S1 的最大进口限制收紧到：

```
50 kW
```

于是形成非常明确的冲突：

```
S7（联络线有功控制）：
希望进口100 kW

S1（需量控制）：
最多只能进口50 kW
```

如果S1真的起作用，最终控制请求一定要被往“减少进口”的方向修正。

---

## 3.3 最终实际结果

专项 MAT（MATLAB数据文件）中：

```
S1执行许可真正开启后
S1约束持续被激活
```

并且：

```
effective dP（最终有效有功调节量）
相对
objective dP（主目标有功调节量）
最多向正方向修正约 +50 kW
```

这个 `+50 kW` 很合理：

```
原来想进口100
现在最多进口50
差值正好约50
```

六台设备的 `Final Pref（最终有功参考值）` 也随之改变。

---

## 3.4 为什么可以判通过

必须同时看到：

```
进口超限
→ S1产生纠偏量
→ S1约束真实激活
→ 最终有效有功请求被修正
→ 6台设备真实命令改变
```

以上全部成立。

**S1：PASS（通过）。**

# 5. S3 AVC（自动电压/无功控制）

## 5.1 它要解决什么问题

S3根据 PCC（公共耦合点）电压偏差产生无功需求。

例如：

```
电压偏低
→ 需要适当无功调节
```

最终不是只得到一个“总无功建议”，而要把无功分给6台变流器。

---

## 5.2 验收真正要证明什么

不是只看S3有没有算出 `qCmd（无功控制命令）`。

而是要证明：

```
S3无功请求
→ Q Allocator（无功分配器）
→ 6路 Qref（无功参考值）
→ 六台变流器真实执行
```

---

## 5.3 为什么不能6台平均分

每台设备当前的有功输出不同。

如果一台设备有功已经接近额定容量，它就没有很多余量再承担无功。

所以当前按：

```
剩余视在容量
```

分配无功。

通俗理解：

> 谁当前有功任务少、余量大，谁多承担一点无功。

---

## 5.4 最终实际结果

执行期间：

```
Q request（总无功请求）
=
Q applied（实际执行总无功）
```

最大误差为0。

同时：

```
allocator valid（无功分配器有效） = 1
Q saturated（无功饱和） = 0
selected source（当前无功控制来源） = 3
```

六台设备均产生真实 `Qref（无功参考值）`。

---

## 5.5 为什么可以判通过

说明：

```
S3不是只会“算建议”
而是真的完成了
总无功请求
→ 六设备分配
→ 真实Qref
```

**S3：PASS（通过）。**

原策略有：

```
2 kW deadband（死区）
```

作用：

> 防止系统在0附近因为很小的波动不断开关策略。

因此理论纠偏量大约：

```
100 - 0 - 2
= 98 kW
```

方向正确，因为：

```

```

---

## 6.5 为什么可以判通过

```

# 7. S5 防孤岛

## 7.1 它要解决什么问题

S5真正负责的是：

> 判断是否存在真实电气孤岛风险，并决定是否具备物理解列资格。

当前做了一个重要安全区分：

```
通信异常
≠
电气孤岛
```

也就是说：

```
通信故障可以报警
但不能单独把PCC断路器打开
```

---

## 7.2 为什么要做“正向”和“负向”两种测试

### 正向测试

验证：

```
真的出现电气异常
→ 必须能解列
```

### 负向测试

验证：

```
只有通信异常
→ 绝不能误解列
```

对于安全策略，只做正向测试不够。

---

## 7.3 正向测试怎么制造电气异常

并没有真的把10 kV电网降成5 kV。

而是把：

```
CFG_AA_v_nom_V（策略使用的额定电压基准）
10000 → 20000
```

真实电压仍约10 kV。

于是策略计算：

```
Vpu（电压标幺值）
≈ 10000 / 20000
≈ 0.5
```

明显超过允许偏差。

这样可以稳定制造：

```
electrical_bad（电气异常） = 1
```

这是“策略判据注入”，目的只是隔离测试执行链。

---

## 7.4 正向实际结果

约27.606 s：

```
electrical_bad（电气异常） 0→1
S5 execute（S5真实执行请求） 0→1
S15 transition（S15离网切换请求） 0→1
```

随后：

```
executed mode（真实执行模式）
0 → 3（孤岛模式）

island latch（孤岛锁存）
0 → 1

PCC breaker（PCC断路器）
闭合 → 断开

ESS1（储能1）
GFL（跟网型） → GFM（构网型）
```

---

## 7.5 负向测试怎么做

保持：

```
电压正常
频率正常
```

只让通信健康量低于原策略阈值：

```
comm（通信健康量） < 0.5
```

形成：

```
comm_bad（通信异常） = 1
```

同时保持真实模式执行和PCC断路器执行权限已经开启。

这样才有证明力。

---

## 7.6 负向实际结果

通信异常期间：

```
comm_bad（通信异常） = 1
electrical_bad（电气异常） = 0

S5 execute（S5真实执行请求） = 0
S15 transition（S15离网切换请求） = 0
island latch（孤岛锁存） = 0
```

PCC断路器保持闭合。

---

## 7.7 为什么可以判通过

正向：

```
电气异常
→ 真解列
```

负向：

```
纯通信异常
→ 不误解列
```

两边都正确。

**S5：PASS（通过）。**

# 8. S6 光伏功率平滑

## 8.1 它要解决什么问题

光伏可用功率可能快速上升或下降。

S6让储能做反向补偿：

```
光伏突然升高
→ 储能增加充电

光伏突然降低
→ 储能放电补上
```

目标：

> 降低光伏组合功率的快速波动。

---

## 8.2 为什么测试改 `PV_profile_pu(6)（光伏可用功率曲线第6个值）`

S6实际读取的是：

```
Ppv_max（光伏最大可用功率）
```

而不是光伏电气实测功率。

所以改PCC目标并不能保证S6被触发。

最终正确工况：

```
0.65 → 0.95
```

制造光伏快速上升。

然后：

```
0.95 → 0.55
```

制造快速下降。

最后：

```
0.55 → 0.65
```

恢复。

---

## 8.3 实际结果

光伏上升时：

```
S6 compensation（S6储能补偿量） < 0
```

储能进入充电方向。

最低约：

```
-0.600 pu（标幺值）
```

光伏下降时：

```
S6 compensation（S6储能补偿量） > 0
```

储能进入放电方向。

最高约：

```
+0.292 pu（标幺值）
```

同时：

```
request（请求量） = applied（实际执行量）
unserved（未满足量） = 0
```

---

## 8.4 为什么可以判通过

最关键的方向完全正确：

```
PV（光伏）升
→ ESS（储能）充

PV（光伏）降
→ ESS（储能）放
```

而且请求全部实际完成。

**S6：PASS（通过）。**

# 10. S8 低压/低频分级减载

## 10.1 它要解决什么问题

当系统低压或低频时，需要快速减少可控负荷。

当前选择：

```
EV2（电动汽车2）
→ EV1（电动汽车1）
```

依次减少充电功率。

---

## 10.2 为什么不直接制造真实低压和低频

本轮主要想验证：

```
策略判据
→ 分级
→ 真实EV减载
```

如果一开始真的把整个10 kV系统打到低压、低频，会同时触发大量其它动态。

所以通过修改阈值制造确定性越限。

---

## 10.3 一级减载怎么设置

默认：

```
CFG_AA_uv_threshold_pu（低压阈值） = 0.88
```

在线改为：

```
1.10
```

正常电压约：

```
1.0 pu（标幺值）
```

于是：

```
1.0 < 1.10
```

低压判据成立。

进入：

```
Stage 1（一级减载）
```

请求：

```
50 kW
```

---

## 10.4 二级减载怎么设置

继续把：

```
CFG_AA_uf_threshold_Hz（低频阈值）

# 2. 测试设计的四条总原则
