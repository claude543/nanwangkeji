# 1. 这轮改造到底是在做什么

在本轮改造开始以前，K26_V5继承的是已经验证成功的V5-A结构：

```text
外部控制板
    ↓ Modbus 40001~40006
BOARD_CMD
    ↓
板端有效性判断
    ↓
FINAL_APPLIED
    ↓
V5A_FINAL_PV1 / PV2 / ESS1 / ESS2 / EV1 / EV2
    ↓
六台设备各自控制Mux的Pref输入
    ↓
2PV + 2ESS + 2EV实时对象
```

这个结构已经证明：

```text
外部板不是Shadow
而是真正能够接管六台设备Pref
```

因此本轮不能为了做15策略而直接把旧链路拆掉重接。

我们的改造路线采用：

```text
先审计
↓
先搭参数框架
↓
先搭Shadow新算法
↓
证明新算法与旧算法完全等价
↓
以后再建立仲裁器
↓
以后再建立LOCAL15接管
↓
最后再建立BOARD15接管
```

也就是说，截至本文档对应阶段，**新增模块几乎全部是“参数层、观察层、Shadow算法层”**，并没有改变六台设备当前真正执行的Pref来源。

当前最重要的结论是：

> **S02已经证明：把基础AGC从“内部计算 `Ptarget-Ppcc`”改成“外部接收 `dP_request`”，不会改变原AGC的任何资源分配结果。**

这一步是以后把策略7、削峰填谷、计划曲线、新能源消纳、多目标等不同有功目标统一送入同一个AGC执行器的基础。

## 4.2 为什么必须设置 `DefaultParameterBehavior = Tunable`

后面我们有大量试验参数，例如：

```text
跑哪一个策略
当前是什么Profile
是否启用故障注入
故障注入哪台设备
执行S01还是S07

```

如果每改变一个试验值都重新Build：

```text
效率极低
且正式15策略测试会非常痛苦
```

所以目标工作流必须是：

```text
Build一次
↓
Load
↓
Variables Table修改参数
↓
Execute
↓
Reset
↓
修改下一组参数
↓
再次Execute
```

这就是Stage00锁定Tunable的原因。

---

## 4.3 `ParameterTunabilityLossMsg = error` 是做什么

它不是控制算法。

它的作用是：

> 如果后续模型优化或代码生成让本来应该可调的参数丢失可调性，不要静默继续，而是直接报错。

也就是把：

```text
“参数看起来在模型里，
但生成实时代码以后其实调不了”
```

这种风险尽量提前暴露。

# 5. 六设备控制Mux的当前语义必须保持不变

| 4 | Vref | 1 |
| 5 | Droop_On | 1 |

| 7 | Qref | 1 |
| 8 | GridOn | 1 |

因此：

```text

```

但：

```text

```

当前六设备Pref仍然进入：

```text
physical input 6
```

本轮S00～S02没有改动这里。

# 11. Stage02新增一：`AA15_AGC_INPUT_TAPS`

新增：

```text
SM_Master/AA15_AGC_INPUT_TAPS
```

这是一个非常关键但不参与控制的“信号分接器”。

---

## 11.1 为什么需要它

我们要验证：

```text
旧AGC
vs
新Shadow AGC
```

如果给两套AGC重新各接一套信号，很容易发生：

```text
Ppcc来源不同
SOC来源不同
PVmax来源不同
enable来源不同
初始参数不同
```

这样即使输出不一样，也不知道到底是算法不同还是输入不同。

所以本轮不重新找信号，而是：

> **直接从正在驱动旧AGC的15根真实输入线上分支。**

即：

```text
旧真实信号源
      ├────────→ 原AGC
      │
      └────────→ AA15_AGC_INPUT_TAPS
```

这保证：

```text
Old AGC input
=
Shadow AGC input
```

# 13. 为什么 `AA15_AGC_INPUT_TAPS`没有Outport

因为我们的模型后续会有很多新Subsystem读取同一组数据：

```text
Baseline AGC
Improved AGC
Strategy2
Strategy7
Diagnostics
Ablation
```

如果从一个Subsystem拉15根长线到各处：

```text
顶层模型会非常乱
```

所以这里采用：

```text
Input
↓
global Goto

其他Subsystem
↓
From
```

# 30. 内部MATLAB Function：`CFG15_Checksum`

接口：

```text
29 inputs
1 output
```

29个输入严格按S01参数定义顺序排列。

计算逻辑：

```text
checksum
=
1*p1
+2*p2
+3*p3
+...
+29*p29
```

也就是：

\[
Checksum=\sum_{i=1}^{29}i\,p_i
\]

这里的权重：

```text
1,2,3,...,29
```

不是算法权重。

它们只是为了让：

```text
不同参数位置对checksum产生不同贡献
```

方便检查。


它不代表：

```text
系统性能
策略得分
多目标代价
控制质量
```

所以它只进入：

```text

```

绝不能接设备。
