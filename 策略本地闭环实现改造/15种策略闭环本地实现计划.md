# 当前K14版 15策略最终接口—仲裁—执行—本地验证矩阵 V0.1

> 状态：**V0.1 已冻结**（大方向冻结，下一步进入精确接口设计阶段）

## 总原则

> **当前 `Advanced_Microgrid_15_Strategies` 本体尽量不改。**
> 它现在的 `status/alarm/metric/cmd` 继续作为"策略判断层"；真正新增的是它后面的 **Request Normalizer → Mode Manager → Arbiter → Executor**。

这和初始资料的定位一致：原15策略主要输出状态、告警、指标和建议控制量，真正闭环需要继续增加设备指令仲裁和功率分配。
但具体怎么仲裁、怎么执行，**全部以现在K14为准，不要求复现旧测试模型。**

## 二、Load1/Load2 处理决定

当前 `J1_Load1/J1_Load2` 是注释掉的，**不建议**为了15策略强行恢复。原因：

- 会改变当前V5-A已经验证好的工作点；
- 会增加电气拓扑改造；
- 我们本来就有 **2台EV充电桩**，它们本质就是可控负荷；
- S8"低压/低频减载"完全可以优先削减EV充电负荷；
- S14黑启动时也可以把EV作为最后恢复的非关键负荷。

### S8 减载执行对象

```text
一级减载：
优先降低一台EV充电功率

二级减载：
继续降低第二台EV充电功率
```

例如当前 `load_shed_step = 50 kW`：

```text
Stage 0
EV1、EV2正常

Stage 1
削减EV2 50 kW

Stage 2
再削减EV1 50 kW
总削减100 kW
```

具体先EV1还是EV2不具有理论意义，所以做成：

```text
CFG_SHED_PRIORITY
```

默认例如：

```text
EV2 → EV1
```

工程师以后也按这个配置实现。

**这样不用恢复两个固定Load，也不用新增三相Breaker。** 这个调整比上一版方案更适合我们现在真实的2PV+2ESS+2EV平台。

## 四、S1/S4/S11 不是3个互相抢控制权的控制器

它们都应该作为**有功硬约束**。

当前K14符号已经明确：

```text
PCC > 0 = 向主网出口
PCC < 0 = 从主网进口
```

### S1 需量

例如：

```text
最大允许进口 = 100 kW
```

就是要求：

```text
PCC >= -100 kW
```

### S4 防逆流

如果：

```text
不允许向主网出口
```

就是：

```text
PCC <= 0
```

### S11 自发自用/余电上网

如果允许：

```text
最多出口50 kW
```

就是：

```text
PCC <= +50 kW
```

如果S4和S11同时启用：

```text
S4：PCC <= 0
S11：PCC <= 50
```

最终：

```text
PCC <= 0
```

取更严格的边界。

所以正常有功目标最终应该是：

```text
原始目标Pbase
        ↓
需量下界
        ↓
防逆流/外送上界
        ↓
Ptarget_effective
```

再：

```text
S7
↓
dP_request
↓
AGC
```

这比"多个cmd相加"合理得多。

## 五、S7/S9/S10/S12/S13 属于"主有功目标"

这五个不能在同一时刻全部互相叠加。

所以增加一个：

```text
P_OBJECTIVE_MODE
```

建议编码：

```text
0 = TIE_LINE            S7
1 = PEAK_VALLEY         S9
2 = PERIODIC_PLAN       S10
3 = RENEWABLE_ABSORB    S12
4 = MULTI_OBJECTIVE     S13
```

### PROJECT_FULL 不是"五个同时控制"

> 五种功能全部在板端运行、都输出自己的状态/指标，但当前选择哪一种作为主运行目标，由运行模式决定。

例如日常：

```text

```

那么：

```text

↓
S1/S4/S11施加硬约束
↓
S7实时追踪最终目标
↓
AGC分配
```

这时S9/S12/S13仍然可以计算：

```text

```

但不拥有最终P主控制权。

## 七、S3 AVC 独立走 Q 通道

S3和有功AGC不应该互相"选一个"。

正常：

```text
P通道：
S7/当前P目标
→ AGC
→ Pref

Q通道：
S3
→ Q Allocator
→ Qref
```

同时运行。

Q分配V0.1采用剩余视在容量：

```
Q_cap,i = sqrt( max( S_rated,i^2 - P_i^2, 0 ) )
```

然后按：

```
Q_i = Q_request × Q_cap,i / ΣQ_cap
```

分给可用逆变器。

这样比六台平均分更合理。

但Q正负极性**不在文档阶段凭记忆写死**。本地第一次测试先人工给一台设备：

```text
Qref = + small value
```

看：

```text
Qmeas
PCC Q
PCC V
```

确认K14真实方向后，脚本里自动写入符号断言。

这样避免后面一整套AVC方向接反。

## 八、S8 现在彻底不动 Load1/Load2

这是相对前面方案的重要优化。

S8实际执行：

```text
cmd8 / shedStage
       ↓
EV Load-Shed Executor
```

假设：

```text
EV1 = -60 kW
EV2 = -60 kW
load_shed_step = 50 kW
```

Stage1：

```text
EV2：
-60 → -10 kW

释放50 kW负荷
```

Stage2：

```text
EV1：
-60 → -10 kW

总共释放100 kW
```

注意：

> 减载不是把EV功率变得更负，而是**减少充电幅度，让它靠近0**。

执行器内部还必须计算：

```text
实际可削减量
```

如果EV2当时只有20 kW充电：

```text
请求shed 50
实际只能shed 20
剩下30再交EV1
```

所以S8需要一个：

```text
shed_unserved_kW
```

日志，不能假装总能完成100 kW。

## 十一、系统 Mode Manager V0.1（正式冻结）

```text

1 GRID_CONNECTED_EMERGENCY
```
