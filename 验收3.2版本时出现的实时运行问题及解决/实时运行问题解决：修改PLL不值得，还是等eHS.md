# 实时运行问题解决：修改 PLL 不值得，还是等 eHS

---

老师提出的不是降低 4 kHz PWM 开关频率，而是：将 RT-LAB 全局固定求解步长从 100 μs 适当增大，同时修改 PLL 及控制系统中与 100 μs 采样时间相关的参数，使模型不再因为 PLL 约束报错，再观察能否实时运行以及控制效果是否还能接受。

## 结论

**这条路线值得做一次范围明确的可行性试验，但不建议投入大量时间把它作为替代 eHS 的主要路线。**

在已经确定：

- 不采用平均值逆变器
- 保留开关级逆变器
- 最终倾向恢复 2PV + 2ESS + 2EV 共 6 台逆变器
- PWM 频率保持 4 kHz

这些条件下，**eHS 仍然是最有可能实现正式实时运行的路线**。

原因不只是 PLL 限制，而是即使把 PLL 限制解除，增大的求解步长仍会与 4 kHz 开关模型产生根本矛盾。

---

## 一、PLL 报错只是目前遇到的第一道门槛

当前情况是：

```
全局固定步长 Ts = 100 μs
PLL 微分时间常数或内部采样参数 = 100 μs
```

当全局步长改成 1 ms 或 2 ms 时，PLL 内部出现类似报错：

```
PLL 相关时间常数 < 模型采样时间
```

所以模型直接报错。

老师提出的是先修改 PLL 相关采样参数，例如让它与新的模型步长匹配。这样做后，模型确实可能不再报这个错误。

但**这只能解决模型能否编译和运行，不能直接证明模型运行结果仍然正确、能够实时、开关过程仍然可信、控制系统仍然稳定。**

PLL 报错消失后，还要面对电流环、功率环、离散积分器、滤波器、延时模块和 PWM 开关分辨率等问题。

---

## 二、为什么只修改 PLL 仍然大概率解决不了最终问题

当前 4 kHz PWM 的周期为：

$$T_{\mathrm{PWM}} = \frac{1}{4000} = 250\ \mu s$$

也就是说，每 250 μs 完成一个 PWM 开关周期。

而当前的实时计算结果是：

| 模型 | 实际单步时间 |
|------|-------------|
| 3 逆变器 | ≈ 700 μs |
| 原 6 逆变器 | ≈ 981 μs |

要让 CPU 来得及完成计算，理论上需要固定步长至少接近 800 μs ～ 1 ms（3 逆变器）或更大（6 逆变器）。

但 1 ms 内已经包含 $\frac{1\ \mathrm{ms}}{250\ \mu s} = 4$ 个 PWM 周期。这意味着模型每计算一次，逆变器在现实中已经完成了 4 个 PWM 周期。**普通固定步长开关模型很难再准确表示这些开通、关断和占空比变化。**

MathWorks 对固定步长 PWM 仿真的说明是：开关事件会与仿真步长同步，仿真步长必须相对于 PWM 周期足够小；否则开关事件可能延迟一个仿真步，PWM 分辨率会明显下降。

因此：**即使把 PLL 采样时间修改到 1 ms，让模型不再报错，也不代表 1 ms 步长下的 4 kHz 开关级逆变器模型仍然可信。**

---

## 三、老师说 RT-LAB 能支撑 10～20 kHz，和我们当前情况并不矛盾

老师说的是 RT-LAB 平台具备运行较高开关频率模型的能力，这个判断本身没有问题。

但平台能否支撑某一开关频率，还取决于：

```
采用 CPU 还是 FPGA
使用什么电气求解器
模型包含多少台逆变器
电气网络复杂度
是否使用时间戳开关模型
固定求解步长
CPU 性能
```

例如，同样是 10 kHz 开关频率：**1 台简单逆变器** 和 **6 台逆变器 + 滤波器 + 变压器 + 线路 + 控制系统**，计算量完全不同。

所以当前实测结果更准确地说明了：**当前 OP5700 的 4 核 CPU，在现有普通开关模型和 100 μs 求解方式下，无法承载完整模型。**

这不是 4 kHz 本身过高，而是开关模型数量 + 电气网络计算 + 控制系统计算叠加后超过了 CPU 每一步的时间预算。

---

## 四、为什么此前说这条路线工作量大

这里要区分"试一下"和"把它做成正式方案"。

### 只做一次可行性试验

工作量不算特别大。可以：

```
复制现有 3 逆变器模型
修改全局固定步长
修改 PLL 中与采样时间直接相关的参数
保持现有 Kp、Ki 暂时不变
进行离线仿真
再选少量方案 Build 到 RT-LAB
```

这属于诊断性试验，值得做。

### 真正把增大步长作为最终方案

工作量会明显增加，因为需要逐项检查：

```
PLL 采样与滤波参数
电流内环离散化
功率外环离散化
离散积分器
延时和记忆模块
abc/dq 变换时序
PWM 生成时序
Rate Transition
保护与故障判断
所有滤波器截止频率
```

即使 Kp、Ki 数值暂时不变，离散控制器的实际动态也可能因为采样周期变化而改变。

例如，同样的积分增益，在 100 μs 执行一次和 1 ms 执行一次，每秒更新次数相差 **10 倍**。

如果是 Simulink 标准离散控制块，部分离散化系数会随采样时间变化；如果是自己编写的差分公式，则可能需要重新推导。第一轮试验可以不改增益，但正式采用前必须重新检查稳定性、带宽、超调和响应时间。

这就是此前所说"正式修改工作量大"的原因。

---

## 五、这条路线应该怎么试才不浪费时间

建议采用严格的停止条件，不进行无限制调参。

### 第一步：只在 3 逆变器副本上测试

不要立即恢复 6 逆变器。建立单独副本（如 `MicroGrid_3INV_Ts_Test`），保留 CPU-only 原始模型和 SSN + 4 核 + XHP 模型，不覆盖已有基线。

### 第二步：准确找到所有与 Ts 有关的参数

至少确认：

```
全局固定求解步长
powergui 离散步长
PLL 采样时间
PLL 微分或滤波时间常数
电流环采样时间
功率环采样时间
PWM 生成模块采样时间
离散滤波器和延时模块采样时间
```

不能只找到 PLL 里的一个 `1e-4` 就认为全部修改完成。

### 第三步：按有限阶梯测试

建议只测试：

| 方案 | 步长 | 说明 |
|------|------|------|
| 基线 | 100 μs | 当前状态 |
| 方案 1 | 200 μs | 小幅度增大 |
| 方案 2 | 250 μs | 等于 4 kHz PWM 一个周期 |

选择 250 μs，是因为它正好等于 4 kHz PWM 的一个周期。

但需要明确：**250 μs 只是诊断上限，不是理想的开关模型步长。** 固定步长 PWM 通常要求求解步长明显小于 PWM 周期，而不是等于 PWM 周期。

### 第四步：先做普通 Simulink 离线仿真

每个方案检查：

```
PLL 能否锁定
PLL 锁定时间
相角和频率是否正确
三相电流是否稳定
电流畸变是否明显增加
PCC 有功和无功
PV、ESS、EV 功率跟踪
直流侧电压
超调和振荡
```

第一轮按照老师意见保持 Kp、Ki 不变，只修改必须修改的采样参数，这样可以直接观察降低采样频率的影响。

### 第五步：再进行一次 RT-LAB 性能测试

只有离线结果正常的方案才进行 Build。重点看 Total step、Major computation、Total idle、Overrun。

---

## 六、应设定什么停止条件

建议明确规定：

> 如果 3 逆变器模型在 250 μs 固定步长下，实际计算时间仍然大于 250 μs，就停止继续通过增大步长解决问题。

因为再往上改成 500 μs、1 ms、2 ms，虽然可能逐渐满足 CPU 实时性，但已经跨越 2～8 个 PWM 周期，**不适合作为当前普通开关级模型的正式方案**。

500 μs 或 1 ms 最多可以做一次"计算边界试验"，用于证明步长达到多大以后 CPU 才能实时，但不应把其结果直接用于论文或硬件在环结论。

特别是 6 逆变器计算量比 3 逆变器更大。如果 3 逆变器在 250 μs 内仍无法完成，基本可以判定 6 逆变器无法仅靠这条路线、在保留当前开关模型的前提下实现实时。

---

## 七、eHS 为什么仍然更适合最终目标

eHS 不是通过把 CPU 固定步长增大到 1 ms 解决问题，而是把 6 台逆变器及其电气网络**转移到 FPGA 求解**。

官方资料显示，eHS 电气系统的求解时间根据电路复杂度可处于约 160 ns 至 4 μs 范围，并在 FPGA 中完成节点电压和支路电流求解。

最终可以形成：

```
FPGA / eHS：
以亚微秒或数微秒步长求解 6 台开关级逆变器

CPU：
以 100 μs 左右运行 PLL、控制器、AGC 和 Modbus
```

这样**不用为了让 CPU 算完而把整个电气模型步长增大到 1 ms**，也更符合：

```
保留 6 逆变器
保留 PWM 开关过程
支持专利中的同类多资源分配
支持小论文的 2PV + 2ESS + 2EV 场景
最终进行控制器硬件在环
```

eHS 支持 IGBT/二极管、Universal Bridge、RLC、变压器、线路和测量模块等规定范围内的 SPS 元件，但完整模型仍需进行容量和兼容性评估。

---

## 八、最终建议

当前不应在"等待 eHS"和"修改采样频率"之间二选一，而应这样安排：

```
主路线：
继续推进 eHS 许可、硬件、bitstream 和 6 逆变器容量确认

辅助验证路线：
对 200 μs 和 250 μs 进行一次受控采样频率试验
```

这次试验的目的不是证明一定可以取消 eHS，而是得到三个明确答案：

1. PLL 和控制器降低采样频率后能否保持稳定
2. 计算时间能降低到什么程度
3. 在不严重损失开关模型精度的范围内，CPU 是否有实时可能

按照当前约 700 μs 和 981 μs 的实测结果，预计结果很可能是：

> 修改 PLL 后模型可以在更大步长下运行，但在仍能合理描述 4 kHz PWM 的步长范围内，CPU 依然无法实时；因此最终 6 逆变器开关级实时模型仍需要 eHS。

因此，这条路线**值得用较小代价试一次并形成数据结论，但不值得在没有明显改善的情况下进行全面控制器重整定，更不应因此暂停 eHS 路线。**
