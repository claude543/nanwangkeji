# 8月1日至8月3日工作总结

## 一、总体任务与本阶段目标

项目最终目标是将六逆变器微电网模型：

```text
2台PV + 2台ESS + 2台EV
```

部署到RT-LAB/OP5700，以`Ts=100 μs`运行，并与外部控制板通过Modbus TCP形成双向闭环。

原完整模型存在两个核心问题：

1. 六台逆变器集中在一个SM和一个SSN网络中，单步计算时间远高于100 μs；
2. 即使设置多核，单个SSN网络仍不能真正拆成多个独立CPU任务，计算时间没有明显下降。

因此，8月1日至今的主要任务不是继续调原完整S3模型，而是：

> 从一个确认可Build的最小官方母版出发，重新建立真正的`1个SM + 3个SS + 1个SC`多任务模型，并逐层恢复六设备、电气网络、控制器、普通通信和正式测量功能，找出原S3失败的真正原因。

---

## 二、最终采用的分核结构

当前建立的目标结构为：

```text
SM_Master
├─ 10 kV上级电网
├─ 电网等值阻抗
├─ PCC断路器
├─ PCC公共母线
├─ Load1、Load2
├─ 六套高压侧变压器边界
├─ PCC/Grid测量
└─ 三组24维控制通信输出

SS_Slave
├─ EV1
└─ EV2

SS_Slave2
├─ ESS1
└─ ESS2

SS_Slave3
├─ PV1
└─ PV2

SC_Console
└─ 后续用于监测、记录和实时性能观察
```

任务之间采用两类连接。

### 电气连接

每台设备使用3条差分Stubline，对应A、B、C三相。

六台设备共：

```text
6台设备 × 3条 = 18条差分Stubline
```

SM侧有36个物理PMIO端口，每个SS有12个物理PMIO端口。

### 普通信号连接

每台设备控制接口固定为12维：

```text
[Vabc(3);
 Iabc(3);
 Fref;
 Vref;
 Droop_On;
 Pref;
 Qref;
 GridOn]
```

同一SS中的两台设备组合成一条24维向量：

```text
设备1的12维 + 设备2的12维 = 24维
```

SM侧结构：

```text
两个12维Mux
→ 24维组Mux
→ Memory，初值zeros(24,1)
→ SM Outport
```

SS侧结构：

```text
SS Inport
→ OpComm
→ Demux [12 12]
→ 两个设备级Demux [3 3 1 1 1 1 1 1]
→ 两套设备控制器
```

## 四、A—F逐级六设备骨架验证

### 试验A：一个SS内放两台设备

结构：

```text
1 SM + 1 SS
SS内2台EV型设备
6条Stubline
```

第二台设备先采用：

```text
g=zeros(6,1)
BL=0
```

不增加第二套控制器和普通通信。

Build成功。

**验证结论**

- 一个SS内可以同时存在两套独立6开关网络；
- 第二套PMIO端口7—12正确；
- 一个SS放两台设备不会自动造成任务串行错误。

---

### 试验B：增加第二个SS

结构：

```text
1 SM + 2 SS
每个SS一台设备
```

第二个SS采用零输入OpComm和固定门极设备。

Build成功。

**验证结论**

- RT-LAB可以处理第二个独立SS；
- 第二套SM—SS电气边界没有问题；
- 原S3失败不是"多个SS不被支持"。

---

### 试验C：增加第三个SS

结构：

```text
1 SM + 3 SS
每个SS一台设备
```

Build成功。

Ctrl+D显示三套独立设备网络，每套通常为：

```text
5 states
10 inputs
21 outputs
6 switches
```

**验证结论**

- 第三个SS可以正常加入；
- 1SM连接3个SS的基本任务结构成立；
- 三套独立Stubline边界可以同时Build。

---

### 试验D：四设备，分布2+1+1

结构：

```text
SS_Slave：2台
SS_Slave2：1台
SS_Slave3：1台
```

Build成功。

**验证结论**

- 3个SS与一个双设备SS可以共存；
- 不是只有单设备SS才能Build；
- SM侧第4套高压边界和PMIO端口19—24正确。

---

### 试验E：五设备，分布2+2+1

结构：

```text
SS_Slave：2台
SS_Slave2：2台
SS_Slave3：1台
```

SM侧增加第5套高压边界，PMIO扩展至30。

Build成功。

**验证结论**

- 两个SS同时放两台设备没有问题；
- 五设备规模不是原S3失败原因；
- `2+2+1`任务组合成立。

---

### 试验F：六设备，分布2+2+2

结构：

```text
SS_Slave：2台
SS_Slave2：2台
SS_Slave3：2台
```

最终达到：

```text
6台设备
18条Stubline
SM 36个物理PMIO
每个SS 12个物理PMIO
```

Build成功。

**验证结论**

这是六设备纯电气骨架的决定性验证，证明：

- 六设备规模可行；
- 3个SS均可放两台设备；
- 18条Stubline可同时存在；
- 36个SM物理端口不是限制；
- 原S3失败不是分核拓扑本身造成的。

## 六、恢复三组24维普通通信

### I1：EV组24维通信

将原单EV的12维通信扩展成：

```text
EV1 12维
+
EV2 12维
=
EV组24维
```

SM侧：

```text
EV1_IO_Mux
EV2_IO_Mux
→ EV_Group_Mux24
→ EV_IO_Memory24
→ ev_io_vec
```

SS侧：

```text
ev_io_vec
→ OpComm_EV_Group
→ EV_Group_Demux [12 12]
→ EV1_IO_Demux、EV2_IO_Demux
→ 两套EV控制器
```

Build成功。

**验证结论**

- 一条24维SM→SS通信可以正常Build；
- 一个OpComm可以接收24维向量；
- 两台控制器可由同一24维通信驱动；
- 24维普通通信与6条EV组Stubline可以共存。

---

### I2：同时恢复ESS组和PV组通信

一次性增加：

```text
ESS1+ESS2 → 24维 → SS_Slave2
PV1+PV2   → 24维 → SS_Slave3
```

最终形成：

```text
EV组24维 → SS_Slave
ESS组24维 → SS_Slave2
PV组24维 → SS_Slave3
```

三个SS中的OpComm均为：

```text
nbport=1
st=Ts
subsys_rate=Ts
```

Build成功。

**验证结论**

- 三组24维普通通信可以同时存在；
- 三个SS可以分别接收一条24维向量；
- 3条普通通信与18条Stubline没有必然串行冲突；
- 原S3错误不是标准三组24维通信造成的。

六路设备输出顺序为：


### 首次发现的维度问题

最初将：

```text
Vab_rms_pcc标量
→ Supervisory In1
```

但对原模型进行编译维度检查后确认：

```text
原Vpcc：宽度3
Supervisory In1：宽度3
Vab_rms_pcc：宽度1
```

因此正确接法应为：

```text
PCC三相Vabc
→ Supervisory In1
```

而：

```text
Ppcc_kW标量
→ AGC In3
```

是正确的。

这一维度问题已修正。

---

### J3 Build的新问题

修正维度后，J3的Build过程能够完成：

```text
SM和三个SS全部C代码生成
参数数据库创建
```

但在：

```text
Creating the signals database
```

阶段失败，核心错误为：

```text
Subsystem "###恢复的 Stateflow图###" not found
```

AGC本身是MATLAB Function块，在Simulink内部属于Stateflow EMChart。

## 十二、日志揭示的真正问题

在RT-LAB分离生成的多个SS模型中，日志出现：

```text
###恢复的 Stateflow图###
/SM_Master_Subsystem_T1C_AGC_Manual_repaired_1
```

AGC本来只属于SM，但RT-LAB在`SS_Slave`、`SS_Slave3`等分离模型中也生成了"修复后的AGC"临时副本。

这些临时副本：

```text
15个输入全部未连接
9个输出全部未连接
```

随后：

```text
C代码生成成功
参数数据库成功
Signals Database扫描恢复对象失败
```

最终报：

```text
Subsystem "###恢复的 Stateflow图###" not found
```

### 当前最准确的判断

这不是：

- AGC算法错误；
- AGC维度错误；
- AGC接设备错误；
- Supervisory错误；
- 六设备分核错误；
- Stubline错误；
- 普通通信错误。

而是：

> RT-LAB 2024.1.1.38在多任务模型分离过程中，对新增到SM的AGC MATLAB Function/Stateflow EMChart执行恢复和信号数据库扫描时出现对象路径不一致。

手动创建、脚本创建和普通Subsystem封装均未解决，因此脚本不是根因。
