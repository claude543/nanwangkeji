## 3. 今日发现并恢复的模型差异

## 3.1 PCC测量边界不同

### 原拆分模型状态

原K5中PCC测量块的电网侧和设备侧关系与旧模型相反，Load1、Load2与六台设备位于同一测量侧，因此PCC测得的是：

- 固定负荷约900 kW；
- 两台EV约120 kW；
- 线路和变压器损耗；

形成约1 MW的电网输入功率。

此前拆分模型实测：

- PCC均值约`+1064 kW`
- PCC标准差约`425 kW`

### 旧模型标准边界

旧模型为：

```text
设备网络
→ PCC V-I Measurement的ABC侧
→ PCC V-I Measurement的abc侧
→ Load1、Load2、PCC断路器和电网
```

Load1、Load2虽然在画面上也位于测量块右侧，但旧模型的设备位于测量块左侧，电网和Load位于右侧；原拆分模型则是电网在左、设备和Load在右。视觉位置相似，但电气边界不同。

### 今日处理

恢复为：

```text
设备网络
→ PCC测量
→ Load1、Load2、断路器、电网
```

并保持：

- PCC测量块ABC侧接设备网络；
- abc侧接Load1、Load2和PCC断路器；
- Vabc、Iabc普通测量信号不变；
- 不存在绕过PCC测量块的电气旁路线。

### 结论

旧模型是本项目的标准模型。本项目目标是对旧模型做任务级分核，不是重新定义微电网PCC边界，因此应沿用旧模型的边界。

---

## 3.2 六台设备馈线拓扑不同

### 原拆分模型状态

原拆分模型将六台设备基本设置为六条独立并联馈线，并给PV1增加了支路。

### 旧模型标准拓扑

旧模型为：

```text
设备公共母线
├─ PV1直接连接，无馈线
├─ PV2line  → PV2
├─ ESS2line → ESS2
├─ EV2line  → EV2
└─ ESS1line → 中间节点
               ├─ ESS1
               └─ EV1line → EV1
```

其中ESS1和EV1采用两级径向结构：

- ESS1和EV1共用第一段ESS1line；
- ESS1接在第一段线路末端；
- EV1还要经过第二段EV1line；
- ESS1line电流等于ESS1和EV1电流之和；
- EV1line只承载EV1电流。

### 今日处理

恢复为：

- PV1直接接公共母线；
- PV2、ESS2、EV2各自通过独立馈线接公共母线；
- ESS1line从公共母线到中间节点；
- 中间节点同时接prim_ESS1和EV1line；
- EV1line末端接prim_EV1；
- 动态负荷按用户决定不恢复。

### 结论

PV1不接支路是老师模型中的位置假设，表示其靠近公共母线、线路阻抗忽略。ESS1—EV1的两级结构表示两台设备处于同一径向馈线的不同位置。拆分模型必须保留该结构。

## 3.3 EV1错误使用ESS1的Vabc、Iabc

### 问题

上传的K5中发现：

```text
prim_ESS1的Vabc、Iabc
→ EV1_IO_Mux前两路
```

而prim_EV1自身Vabc、Iabc未正确送入EV1控制链。

### 影响

- EV1 PLL使用ESS1测量；
- EV1功率计算使用ESS1测量；
- EV1控制器与EV1物理逆变器不匹配；
- EV1 Pmeas不可信；
- EV1可能产生实际异常出力。

### 处理

改为：

```text
prim_EV1 Vabc、Iabc → EV1控制链
prim_ESS1 Vabc、Iabc → ESS1控制链
```

### 结论

每台设备控制器必须使用自身高压侧测量。

## 4. 今日最复杂问题：SM侧prim、SS侧测量块与线路方向

## 4.1 初始误判

最初根据EV1、EV2出现约`-10 pu`均值和几十pu振荡，曾直接判断六台`prim_*`方向全部错误。

随后用户指出：

- 旧模型中只有逆变器内部有prim；
- 拆分模型SS中新增了一个低压V-I测量块；
- SM中又存在prim；
- 不能把SS测量块和SM prim直接视为同一个点。

这一提醒是正确的，必须重新区分。

## 4.2 正确对应关系

旧模型内有：

- `inv`：逆变器输出侧测量；
- `prim`：变压器高压侧测量。

拆分后：

- SS中的`inv`仍对应逆变器侧测量；
- SS中新增的低压边界V-I测量块用于分核边界观察，当前Vabc、Iabc接Terminator；
- SM中的`prim_*`才对应旧模型的高压侧prim，并通过24维通信把Vabc、Iabc送给SS控制器。

因此：

> 当前Pmeas和控制方向主要由SM中的`prim_*`决定，SS低压边界测量块不应在本轮修改。

## 4.3 六个SM侧prim最终统一规则

六台设备全部恢复为：

```text
三台单相变压器高压端
→ prim_* 的A、B、C

prim_* 的a、b、c
→ 馈线或公共母线
```

即：

```text
ABC永远接三台单相变压器
abc永远接设备馈线或公共母线
```

这使prim的Iabc正方向保持旧模型定义：

```text
设备 → 公共母线/电网
```

因此：

- 正Pmeas表示发电或ESS放电；
- 负Pmeas表示EV充电或ESS充电。

## 4.4 馈线端口方向的最终恢复

所有馈线模块显示：

- 左侧：ABC
- 右侧：abc

为忠实复制旧模型，最终连接为：

### PV1

```text
变压器 → prim_PV1 ABC
prim_PV1 abc → 公共母线
```

### PV2、ESS2、EV2

```text
变压器
→ prim ABC
→ prim abc
→ 对应line ABC
→ 对应line abc
→ 公共母线
```

### ESS1—EV1

```text
公共母线
→ ESS1line ABC
→ ESS1line abc中间节点
   ├─ prim_ESS1 abc → prim_ESS1 ABC → ESS1变压器
   └─ EV1line ABC
      → EV1line abc
      → prim_EV1 abc
      → prim_EV1 ABC
      → EV1变压器
```

## 4.5 重要结论

线路本身为无源串联元件，单纯翻转线路端口通常不会像V-I测量块那样直接反转Pmeas符号；但本项目要求完整复制旧模型，因此线路端口方向也统一恢复。

由于今天不是每次只改一个变量后都单独Build/Execute，不能声称全部异常只由某一个模块独立造成。可以确定的是：

> PCC边界、馈线拓扑、EV1测量来源、GridOn/Droop状态、prim方向和馈线端口关系全部恢复后，异常完全消失。

## 7. 今日遇到的其他问题、原因、解决和结论

## 7.1 SC OpComm采样时间改成1 ms后Ctrl+D报错

### 现象

旧模型SC中的OpComm改为`0.001 s`后，Ctrl+D提示：

```text
SC OpComm输入：0.001 s
SM信号源：0.0001 s
多速率数据完整性错误
```

### 原因

旧单核模型中信号从SM直接进入SC OpComm，中间没有Rate Transition或任务通信隔离。

### 解决

- 旧模型OpComm恢复为`Ts = 0.0001 s`；
- 不使用诊断器自动修复；
- 用Scope Decimation降低记录点数。

### 结论

是否能直接把SC OpComm改慢，取决于具体任务边界和信号路径，不能一概而论。

## 7.2 `Vgrid_line=10000`每次写入InitFcn后自动消失

### 现象

手动在模型InitFcn增加：

```matlab
Vgrid_line=10000;
```

重新初始化后又消失。

### 原因

旧模型顶层存在带掩膜的`Model Initialization`模块，其内部初始化字段会自动重写模型InitFcn和PostLoadFcn。直接修改模型属性回调会被覆盖。

### 正确解决

在`Model Initialization`模块内部将初始化内容改为：

```matlab
Ts=100e-6;
Vgrid_line=10000;
```

### 结论

该变量必须在真正的初始化源头固定，而不是修改被自动生成的回调结果。

```text
索引不能超过2
```

### 原因

- EV1 Pmeas；

没有记录Pref。

```text
signals(1) = EV1 Pmeas
signals(2) = EV2 Pmeas
```

并直接与已知固定参考`-0.6 pu`比较。

### 结论
