## 五、开始K4A真实状态与观测链恢复

### 1. 六路Pmeas反馈链

完成三个SS向SM返回六路设备实际功率。

三个SS内部结构：

```text
两台设备Pmeas
→ Mux2
→ Memory
→ SS Outport
```

设备顺序：

```text
SS_Slave：EV1、EV2
SS_Slave2：ESS1、ESS2
SS_Slave3：PV1、PV2
```

SM中最初为三组反馈分别增加三块OpComm，Build时报错。随后修正为：

```text
一个统一的实时通信OpComm
输入口数量 = 3
```

连接：

```text
In1 = EV_Pmeas_vec2
In2 = ESS_Pmeas_vec2
In3 = PV_Pmeas_vec2
```

该结构Build成功。

### 2. 修正Pmeas取点方式

最初从Control内部的`[Pmeas]`信号直接分支新增Outport，观测结果不正确。对照以前设备基线试验后，确认原基线取点是：

```text
Control内部Pmeas/PmeasF
→ ConnectMode控制的Switch
→ meas总线
→ Control外层measurements总线
→ Bus Selector选择最终Pmeas
```

因此已将六台设备取点修改为：

```text
Control/meas
→ Bus Selector
→ 最终Pmeas
```

当前六路反馈已能够送到SC，但六路稳态均值尚未完成最终验收。该问题保留到后续继续检查，不阻塞PVmax、SOC和AGC结构恢复。

### 3. SC采集显示问题处理

初始Scope只显示接近停止时间的末尾波形。后续调整为：

```text
仿真停止时间 = 60 s
Pmeas SC OpComm采样周期 = 0.01 s
Scope Decimation = 1
Time span = 60 s
取消仅保留最后N个点
```

调整后已经能够显示完整运行过程。
