# 附：官方母版之前的路线回顾

在使用官方母版之前，我们走的是"**从原六逆变器微电网模型出发，直接对原模型进行任务拆分和 Stubline 改造**"的路线。虽然最终没有完成 RT-LAB 并行 Build，但这段尝试排除了大量错误方向，也为后续采用官方母版提供了明确依据。

## 一、最初为什么要改造

原六逆变器模型在：

```
Ts = 100 μs
```

条件下，单步计算时间约为：

```
970～981 μs
```

远高于 100 μs，无法实时运行。

此前尝试过：

```
SSN + XHP + Cores = 4
```

但三逆变器模型在 `Cores=1` 和 `Cores=4` 时均约 700 μs，说明当时只是给一个大任务配置了多个核，并没有把模型真正拆成多个可以并行调度的 RT-LAB 实时任务。

因此转向：

```
一个 SM
＋多个 SS
＋一个 SC
```

的任务级分核方案。

## 二、第一阶段：直接从原微电网拆成 SM 和多个 SS

最初按照原电气拓扑进行拆分，例如：

```
sm_circuit：
电网、PCC、负荷、公共控制和部分设备

ss_feeder1：
ESS1、EV1

ss_pv2_ess2：
PV2、ESS2

ss_ev2：
EV2
```

普通控制信号使用：

```
SM 中的 Mux
→ 顶层普通信号线
→ SS 中的 OpComm
→ Demux
→ 设备控制输入
```

电气连接使用顶层 ARTEMiS Stubline。

### 结果

`Ctrl+D` 能够通过，原来 39 个开关的大电气网络被分成多个较小网络，例如：

```
9 个开关
12 个开关
6 个开关
6 个开关
6 个开关
```

这说明：

> 电气网络在 Simulink/ARTEMiS 层面确实被拆开了。

但当时还没有证明 RT-LAB 能够将这些 SM、SS 任务并行生成代码。

## 三、普通 Stubline 导致严重不等效

最初直接将原线路参数用于 Stubline：

```
R = 0.065 Ω
L = 0.66845 mH
Ts = 100 μs
```

Stubline 为了实现一个步长传播延迟，会自动形成等效电容。由于电感过小，每条 Stubline 产生约：

```
C ≈ 14.96 μF
```

多条 Stubline 叠加后，模型出现：

```
PCC 无功约 2042.8 kvar
PCC 电压约 10422.8 V
```

而原模型约为：

```
PCC 无功约 0 kvar
PCC 电压约 10021.7 V
```

### 得出的结论

> Stubline 不能只看 R、L 是否与原线路相同，还必须考虑它根据步长自动形成的等效电容。

也就是说，Stubline 不是简单的"线路替代块"，其数值解耦机制会改变网络无功特性。

## 四、尝试补偿型 Stubline

随后尝试：

```
Coupled Stubline
＋ Compensation Block
```

希望补偿 Stubline 产生的附加电容。

但原线路只有 R、L，没有真实线路电容。当电容矩阵设置为 0 时，补偿模块出现：

```
NaN / Inf
补偿电感约 9.75 H
```

计算发生奇异。

### 结果

该路线被停止。

### 得出的启发

> 不能为了使用补偿模型而人为编造电容参数；没有真实线路电容数据时，补偿型 Stubline 并不适合当前模型。

## 五、迁移变压器漏阻抗的方法

随后发现，可以把变压器一侧的漏阻抗移到 Stubline 中，使 Stubline 使用更大的电感，从而降低其自动生成的电容。

原变压器高压侧漏阻抗换算约为：

```
R = 1.363636 Ω
L = 0.086812 H
```

将变压器高压侧漏阻抗清零，由 Stubline 承担后，Stubline 电容降到约：

```
0.1152 μF
```

先只改造 EV2 进行验证。

### EV2 单支路结果

改造前 PCC 无功约：

```
2042.8 kvar
```

改造 EV2 一支路后下降为：

```
1503.2 kvar
```

下降约：

```
539.6 kvar
```

而 EV2 有功基本不变。

### 得出的结论

> 将变压器漏阻抗迁移到 Stubline，能够明显降低附加电容造成的无功问题，而且不会明显改变设备有功。

这是当时第一个被数值验证有效的 Stubline 参数改造方法。

## 七、RT-LAB Build 仍然失败

虽然离线模型和 `Ctrl+D` 均能通过，但 RT-LAB Build 报错：

```

sm_circuit waits data from ss_pv / ss_ess / ss_ev
```

这说明：

> Simulink 中电气网络被分组，并不代表 RT-LAB 调度器已经认为这些任务能够并行执行。

随后进行了多轮排查。

## 八、尝试过的 Build 修复方法

### 1. 在 SM 控制向量输出前加 Memory

结构改成：

```
Mux
→ Memory
→ SM Outport
```

目的是打断 SM→SS 的同一步直接馈通。

#### 结果

仍报相同串行错误。

原因是日志显示的依赖方向主要为：

```
SS → SM
```

而 Memory 只处理了：

```
SM → SS
```

### 2. 清理隐藏的 GridOn 跨任务通信

发现三个 SS 内部均通过：

```
From [GridOn]
```

读取 SM 中的 `Goto [GridOn]`。

随后改为：

```
GridOn
→ 加入控制向量
→ Memory
→ OpComm
→ SS Demux
→ 设备显式 GridOn 输入
```

并确认三个 SS 内的 `From [GridOn]` 数量为 0。

#### 结果

Build 仍报串行错误。

### 3. 扫描所有普通跨任务信号

进一步检查发现：

- 三个 SS 没有普通 Outport；
- 没有 Data Store Read/Write；
- GridOn 已经显式传输；
- 控制量均经过 OpComm。

说明普通信号已经不是主要问题。

## 九、为什么最终转向官方母版

在分析官方 `artemis_Transfo_StublineRT` 后发现，官方真正经过 RT-LAB 多核验证的结构是：

```
三台单相变压器
＋
每相一条 "2 with differential inputs" 差分 Stubline
＋
SS 内部显式形成 Delta 连接
```

而之前我们使用的是：

```
完整三相变压器
＋
每台设备一条普通三相 Stubline
```

两者虽然离线数值可以接近，但 RT-LAB 对任务边界的识别方式不同。

同时还发现，单纯把官方模块复制到原微电网模型中，并不会带入官方模型的：

- 配置集；
- ARTEMiS Guide 环境；
- 模型回调；
- SM/SS 外层属性；
- 代码生成配置；
- 其他模型级设置。

这解释了为什么旧原型：

```
Ctrl+D 能够分组
离线基本等效
但 RT-LAB Build 仍认为串行
```

而官方模型可以正常 Build。

### 1. 电气网络分组不等于 RT-LAB 任务并行

```
Ctrl+D 成功
SSN 显示多个组
```

只能证明 Simulink/ARTEMiS 层面完成了网络拆分。

它不能证明：

```
RT-LAB 能够分离 SM/SS
任务不存在同一步依赖
C 代码能够并行生成
```

必须以 RT-LAB Build 结果为准。

### 2. 离线等效不等于实时调度可行

旧 2＋2＋2 模型离线结果已经很好，但仍无法 Build。

说明模型改造必须同时满足两个条件：

```
电气数值等效
＋
RT-LAB 任务调度规则
```

只满足其中一个不够。

### 3. Stubline 参数必须考虑自动电容

不能只按原线路 R、L 填写 Stubline。

必须检查：

```
自动生成的 C
无功变化
母线电压变化
```

这对低压、大功率、小电感模型尤其重要。

### 4. 变压器跨任务应优先采用官方结构

最终明确：

```
三台单相变压器
＋ 差分 Stubline
＋ 显式 Y/Delta 连接
```

比：

```
三相变压器
＋ 普通三相 Stubline
```

更适合作为 RT-LAB 多任务边界。

### 5. 模型级配置和模块本身同样重要

即使 Stubline 和 OpComm 的库链接都是 `resolved`，仅复制模块仍不足以复制官方模型的全部实时属性。

因此后续采用：

```
官方 Build 成功模型作为母版
→ 把微电网内容逐步迁入
```

而不是：

```
原微电网模型作为母版
→ 把官方模块复制进去
```

### 6. 应从单设备端到端验证后再扩展

之前一次直接建立完整 2＋2＋2，Build 失败后难以判断根因。

采用官方母版后，按以下顺序逐步验证：

```
官方原模型
→ EV2 主电路
→ 两绕组三 Stubline
→ 100 μs
→ 实际变压器参数
→ 实际 Stubline 参数
→ Line_EV2
→ EV2 控制器
→ OpComm
```

每一步 Build 成功后再继续，最终证明了完整单 EV2 链路可行。

启发是：

> 以后复杂实时模型应先建立一个最小可运行、可 Build 的单设备原型，再复制扩展，而不是先搭完整系统再集中排错。

## 总结

使用官方母版前的路线虽然没有最终通过 Build，但完成了三项重要工作：

1. 验证了 SM/SS、OpComm 和电气任务拆分的基本方向；
2. 找到了 Stubline 附加电容、变压器漏阻抗迁移和隐藏跨任务信号等关键问题；
3. 明确认识到"离线等效、SSN 分组、RT-LAB 并行 Build"是三个不同层级的验证目标。

最终最大的启发是：

> RT-LAB 多核改造不能只修改电气连接和模块参数，还必须继承一套已经被 RT-LAB 验证成功的模型级任务结构。因此，应以官方成功模型为骨架，将业务模型逐步迁入，而不是在原业务模型上不断修补。
