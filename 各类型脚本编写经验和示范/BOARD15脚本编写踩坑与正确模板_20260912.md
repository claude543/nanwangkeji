# BOARD15脚本编写踩坑、经验教训与正确模板
## 2026-09-12版｜按脚本类型说明“什么时候用、怎么写、错在哪里、怎样防返工”

> **定位**：本文件不是Python/MATLAB通用教程。  
> 它专门总结BOARD15在模型Patch、Verifier、RT-LAB Configuration、Target Verify、动态Runner、Board CSV、MAT提取、负责人出图和封装过程中真实踩过的坑。
>
> 目标是让后续脚本一次性更接近“工程可用”，避免同一类错误反复出现。

# 1. 先按用途区分脚本类型

本项目至少有8类脚本，不能混为一谈。

|类型|典型语言|什么时候用|核心职责|
|---|---|---|---|
|A. 模型Patch|MATLAB `.m`|需要真正修改Simulink结构/连线/在线参数暴露时|只做目标结构修改，不负责证明Target真实可调|
|B. 模型Verifier|MATLAB `.m`|Patch后、Build前|独立检查结构、连线、参数、维度、禁止项|
|C. RT-LAB Configuration连接|Python `.py`|OpInput/OpOutput映射变化时|建立/修复Host↔Target点表连接|
|D. Target Tunability Verify|Python `.py`|Build后需要证明Target参数唯一、可写、可恢复|唯一绑定、写/读回、恢复、信号可读|
|E. 动态验收Runner|Python `.py`|正式E1/E2/E3/E4动态运行|按时间轴配置、执行、取快照、安全退出、保存证据|
|F. Board CSV处理|Python `.py`|需要从连续板端日志选代表行时|精确阶段筛选；现在不再要求每轮必做|
|G. MAT提取/健康检查|MATLAB `.m`|从RT-LAB OpWrite原始MAT提取证据或诊断损坏|严格schema、Target Time、覆盖范围、不可伪造|
|H. 报告出图|MATLAB `.m`|数据已经冻结，只需要负责人波形|全量预检、简单图、事务式输出|
|I. 封装/审计|Python/MATLAB/PowerShell|冻结版本和交接|SHA256、清单、正确/废止版本索引|

最常见的返工来源：

> 用一种脚本去做另一种脚本应该承担的工作。

例如：

- Patch成功 ≠ Target已经可调；
- Runner跑完 ≠ MAT一定落盘；
- Plot识别失败 ≠ 原始MAT一定坏；
- MAT坏 ≠ 策略运行失败；
- Board CSV里strategy bit出现 ≠ 物理设备已经执行。

# 2. 所有脚本共同遵守的规则

## 2.1 `.m`和`.py`文件名、入口函数名必须ASCII

永久规则：

```text
正确：
BOARD15_NONISLAND_ACCEPT_E3_R2_LONGWINDOW.py
dabao_E3_final_report_R1.m

错误：
E3长窗口验收.py
打包E3最终波形.m
function 生图_E3(...)
```

原因：

- MATLAB/Windows函数入口对非ASCII标识符曾直接报“文本字符无效”；
- 文件名、函数名、内部local function要保持一致；
- 中文只用于注释、标题、legend、fprintf解释。

## 2.2 每次修一个错误后，要扫描整个文件同类模式

错误示例：

```text
发现一个中文函数名
→ 只改这一行
→ 后面local function仍有中文
→ 再报一次
```

正确：

```text
发现pattern
→ 全文件grep/regex同类模式
→ 一次性清掉
```

## 2.3 正式脚本必须版本化

不要覆盖：

```text
R1
```

再“悄悄改内容”。

应该：

```text
R1失败
→ R2修复
→ 正式说明R1废止，R2使用
```

典型历史：

```text
BOARD15_S8_TUNABLE_VERIFY_R1.m
字符向量未正常终止
→ 正式R2

BOARD15_E4_S8_MAT_COMPACT_EXTRACT_R1.m
10列预分配 vs 11字段
→ 正式R2

E3 Plot R4
字段名错误导致只生成两图
→ 正式R5
```

## 2.4 证据历史不可重写

Runner主Run发生：

```text
S6 INCONCLUSIVE
```

不能后来补测PASS后把原Run描述成：

```text
原Run 4/4 PASS
```

只能：

```text
主Run S6 INCONCLUSIVE
+ supplement S6 PASS
= E1最终4/4
```

# 3. A类：MATLAB模型Patch脚本

## 3.1 什么时候用

只有在以下场景才写Patch：

- 增加/修改Simulink block；
- 改连线；
- 增加Runtime Config；
- 暴露新的Target Tunable；
- 增加OpInput/OpOutput；
- 改真实执行链。

不要因为“想多留接口”就顺手开启孤岛、breaker、blackstart等未验功能。

## 3.2 正确结构

```matlab
function PATCH_EXAMPLE_R1
mdl = bdroot(gcs);

% 1) 前置身份检查
assertModelIdentity(mdl);

% 2) 必需块存在性
requireBlock(...);

% 3) 禁止部分Patch重复执行
assertNoPartialPatch(...);

% 4) 只做当前目标改动
add_block(...);
add_line(...);

% 5) 关键参数设置
set_param(...);

% 6) 保存一次
save_system(mdl);

% 7) 输出mapping
writeMappingTxt(...);
end
```

## 3.3 最重要经验：Patch和Verifier必须分离

错误思路：

```text
Patch脚本自己说“修改成功”
→ 就认为模型正确
```

正确：

```text
Patch
→ 保存
→ 关闭修改逻辑
→ 独立Verifier重新扫描
→ Build
```

理由：

> Patch是“写入者”，Verifier必须是“只读审计者”。

# 4. B类：MATLAB模型Verifier脚本

## 4.1 什么时候用

Patch以后、Build以前。

检查：

- block存在；
- 输入/输出端口；
- 连接目标；
- Runtime Config映射；
- 参数scale；
- 禁止打开的功能；
- 宽度合同；
- 某些关键值是否仍Golden。

## 4.2 不要只检查“有这个名字”

必须检查：

```text
块存在
+ 唯一
+ 类型正确
+ 来源/去向正确
+ 值/比例正确
```

## 4.3 表/Cell预分配必须和字段数量同步

历史E4 MAT R1：

```text
Coverage新增第11字段
但预分配仍1×10
→ 左侧1×10，右侧1×11
```

正确写法：

```matlab
names = {...};         % 单一事实源
N = numel(names);
rows = cell(nCase,N);  % 不手写10/11
```

不要：

```matlab
rows = cell(nCase,10);
...
% 后面又加了第11字段
```

# 5. C类：RT-LAB Configuration连接脚本

## 5.1 什么时候用

只在：

- OpInput/OpOutput数量变化；
- 新点表加入；
- Configuration连接丢失；
- Build结构变化导致endpoint要重建；

时使用。

## 5.2 本项目正确端点

Board→Model OpInput：

```text
<model>/SM_Master/<OpInput>/In1/Value
```

Model→Board OpOutput：

```text
<model>/SM_Master/.../<OpOutput>/OpOutput/port1
```

历史错误：

```text
OpInput/port1
```

不是正确连接端点。

## 5.3 168点正确恢复路径

冻结成功经验：

```text
new140：
BOARD15_RTLAB_AUTO_CONNECT_R3.py

old28：
BOARD15_RTLAB_CONNECT_OLD28_R8.py

总计168
```

不要再运行历史：

```text
BOARD15_RTLAB_AUTO_CONNECT_ALL168_R4.py
```

除非重新确认其逻辑。

# 6. D类：Target Tunability Verify脚本

## 6.1 什么时候用

Build以后，必须证明：

```text
Simulink里有参数
≠
Target真正有唯一可调binding
```

## 6.2 正确流程

每个参数：

```text
1. exact path查找
2. 必须唯一
3. 读原值
4. 写一个安全probe
5. 读回
6. 恢复原值
7. 再读回确认恢复
```

必须有`finally`恢复。

Python模板：

```python
old = read(path)
try:
    probe = safe_probe(old)
    write(path, probe)
    got = read(path)
    assert close(got, probe)
finally:
    write(path, old)
    restored = read(path)
    assert close(restored, old)
```

## 6.3 绝不能用“near candidate自动选”

错误：

```text
exact找不到
→ 找一个名字差不多的参数
→ 自动写
```

这在Target上非常危险。

正确：

```text
exact != 1
→ 收集错误
→ 不写
→ 报告人工确认
```

# 7. E类：Python动态Runner

这是本项目最重要、也最容易返工的脚本类型。

## 7.1 Runner职责

正式Runner只负责：

```text
打开工程
→ 检查Load/Paused
→ 取得SYSTEM/PARAMETER control
→ 执行时间轴
→ 原子配置
→ 快照
→ 安全退出
→ 保存events/snapshots/manifest
→ final Reset
```

不负责：

- 重新Build；
- 自动重建168点；
- 自动改Simulink；
- 自动决定策略性能“够不够漂亮”。

## 7.2 Runner硬门只保留链路/安全类

应该hard fail：

```text
Board heartbeat=0
通信必需位缺失
Config未应用
source2不真实
route invalid
Final invalid
fallback active
safe exit失败
```

不应该因为以下原因中途Abort整轮：

```text
PCC没有刚好贴目标
S9过调
S12进口偏大
S13最终很激进
```

这些是“性能/结果”，不是Runner安全故障。

## 7.3 Pause敏感策略必须批量读取

E1-R2教训：

```text
逐信号Target读取
+ 关键Pause时间过长
→ source2 validity丢失
→ S6历史状态被破坏
```

正确：

```python
keys = list(SIGNAL)
vals = RtlabApi.GetSignalsByName(tuple(SIGNAL[k] for k in keys))
row = dict(zip(keys, vals))
```

而不是：

```python
for each signal:
    GetSignalByName(...)
```

## 7.4 原子配置：CONFIG_SEQ最后写

正确：

```python
for name,value in changes.items():
    write(name,value)

seq = next_seq()
write("CONFIG_SEQ", seq)   # LAST
```

不要：

```text
一边写字段
一边读回
一边慢慢打印
最后再过很久写CONFIG_SEQ
```

关键阶段配置要短。

## 7.5 source0先配置，source2再接管

正确：

```text
source0
→ 配好策略/参数
→ 等Board applied
→ source2
→ 再验route
```

这样避免Board刚接管就吃到半套配置。

## 7.6 安全退出顺序

成功E1/E2/E3统一为：

```text
先 source2 → source0
→ 再 Board master/mask off
→ 保持2~3 s
→ 最后Reset
```

不要反过来：

```text
先关Board
→ source2仍选Board
```

可能引起无效路由。

# 8. Reset错误和MAT落盘：必须分层判断

## 8.1 error17不等于策略失败

如果final Reset返回：

```text
error17
model did not reset correctly
cleanup performed
```

而策略时序和safe exit已经完成：

```text
记录 RESET_CLEANUP_WARNING
不要盲目第二次Reset
```

因为旧逻辑曾导致：

```text
第一次error17已经cleanup
→ 第二次Reset
→ error22 model not loaded
```

## 8.2 Runner完成不等于MAT健康

E2 82 s案例：

```text
所有策略完成
safe exit完成
但：
G27 49×0
G29 47×0
G30 129×0
```

因此post-run需要独立检查MAT。

## 8.3 大MAT不要为了“图更长”无限延时

E2 82 s：

```text
5组高频MAT > 500 MB
```

最终写盘风险明显增加。

用户决定：

```text
不拆Run
但压缩到65 s
```

E2-R4成功。

原则：

> 报告图窗口够看清即可，不要为了视觉冗余制造超大OpWrite文件。

# 9. G类：MAT健康检查 / 提取脚本

## 9.1 先用历史已成功的schema，不重新猜

冻结5组家族：

```text
G26 rootdiag_ev12_data      dataWidth=96 → MAT维97
G27 rootdiag_ess2_data      dataWidth=48 → MAT维49
G28 rootdiag_pv12_data      dataWidth=96 → MAT维97
G29 d1_gfm_superpack_data   dataWidth=46 → MAT维47
G30 freqdiag_ess1_data      dataWidth=128 → MAT维129
```

历史成功loader：

```text
whos('-file',path)
→ exact var优先
→ 一维必须=dataWidth+1
→ 第一行/列Target Time
→ finite
→ diff(t)>0
```

## 9.2 不要为坏MAT放松规则

E2 R5出现：

```text
d1_gfm_superpack_data
size [47 0]
load失败
```

这时正确结论：

```text
原始MAT损坏/未完成写盘
```

而不是：

```text
继续写R6/R7解析器
```

## 9.3 如果单个MAT内部Target Time重置

绝对不要：

```matlab
[t,idx] = sort(t);
X = X(idx,:);
```

因为会把多个epoch混成一条假时间轴。

正确：

```text
找到 diff(t)<=0 的边界
→ 分割成多个monotonic epoch
→ 分别验证
→ 选择唯一覆盖本Run时间的epoch
```

# 10. H类：负责人出图脚本

## 10.1 出图脚本不是数据修复脚本

它只负责：

```text
读取冻结数据
→ 验schema
→ 计算展示量
→ 画图
```

原始数据有问题时必须停止。

## 10.2 必须“全量预检后再画第一张”

E3 R4历史：

```text
图01成功
图02成功
图03字段名写错
→ 报错
→ 只留下两张半套结果
```

正式R5吸取教训：

```text
先检查7/7 CSV + required columns
→ 全通过
→ 才开始figure
```

同理E2/E3最终报告版：

```text
五组MAT全部读取并检查coverage
→ 才创建任何figure
```

## 10.3 事务式输出

正确：

```matlab
tmpDir = ...
finalDir = ...

try
    生成全部图到tmpDir
    assert(PNG数量==N)
    assert(PDF数量==N)
    movefile(tmpDir,finalDir)
catch
    rmdir(tmpDir,'s')
    rethrow
end
```

这样不会留下：

```text
只有2张图
用户误以为脚本成功一半
```

## 10.4 不要拼`dir()`原始struct到手写窄struct

E2 R3/R4踩坑：

```matlab
allRuns = struct('folder',{},'name',{},'datenum',{});
z = dir(...);

allRuns = [allRuns; z(:)];
```

MATLAB `dir()` struct还有：

```text
date
bytes
isdir
datenum
...
```

字段数不同，`vertcat`报错。

正确：

```matlab
rows = cell(0,3);
for k=1:numel(z)
    rows(end+1,:) = {z(k).folder,z(k).name,z(k).datenum};
end
```

或者table projection。

## 10.5 报告图必须简单

当前冻结：

```text
总体图：PCC + 阶段
核心图上：PCC + 必要边界
核心图下：PV/ESS/EV实际有功合计
```

不要加十几条内部线。

# 11. Board CSV脚本与正文抽样

## 11.1 初版摘录脚本为什么错

曾用：

```text
strategy mask只要包含S7 bit
```

然后取全局开始/中间/结束。

导致S7“中段”选到了后面的：


```text
exact mask
+ state=ENABLED
+ 连续段分割

```

例如：

```python

        and int(r["strategy_mask"])==exact_mask
    ]

    # Board约0.1 s周期，超过0.5 s认为断段
```

## 11.3 现在正文不要求每轮都写extractor

新规则：

```text
完整Board CSV直接归档
→ 正文时用Python/Pandas临时选代表点
→ 形成小表
```

这样减少人为“先生成摘录，再改摘录，再合正文”的工作量。

# 12. 表格/CSV和Word文档的经验

## 12.1 Markdown表格复制Word会自动扩宽

已经采取：

- 表头缩短；
- 单元格两侧少空格；
- PV/ESS/EV三个数合并为一列。

但Word仍可能自动适应列宽。

如果最终Word手工排版，允许用户自行微调，不需要为此重做数据。

## 12.2 闭环箭头不要竖向逐行

用户明确：

```text
不要：
A
↓
B
↓
C

要：
A → B → C
```

因为Word复制时竖向箭头会制造大量回车。

# 16. 遇到报错时的判断顺序

不要第一反应“重跑”。

固定顺序：

```text
1. 这是语法错误？
2. 这是路径/文件筛选错误？
3. 这是schema/字段错误？
4. 这是绘图脚本错误？
5. 这是MAT原始数据错误？
6. 这是Runner时序错误？
7. 这是Board通信/route错误？
8. 最后才考虑模型/算法错误
```

例：

### `vertcat结构体字段数不匹配`

```text
= MATLAB脚本容器错误
≠ E2策略失败
```

### `d1_gfm_superpack_data [47 0]`

```text
= MAT数据损坏/未完成写盘
≠ 画图脚本识别问题
```

### `source2 valid=0`发生在S6长Pause后

```text
= Runner Pause方式破坏状态连续性
≠ S6算法方向错误
```

# 17. 正确的“修复范围”原则

这是防返工最重要的规则。

```text
脚本语法错
→ 只修脚本

Plot字段错
→ 只修Plot

MAT坏
→ 判断是否可从其他健康源完成证据
```

# 20. 最终原则

如果只保留十条：

1. `.m/.py`入口和函数名ASCII。
2. Patch和Verifier分离。
3. Build后必须Target Verify。
4. Target exact unique binding，不猜near candidate。
5. Runtime config所有字段先写，CONFIG_SEQ最后写。
6. Pause敏感策略用batch read，关键阶段不做慢Target遍历。
7. safe exit先source0，再关Board。
8. final Reset error17 cleanup后不二次Reset。
9. Plot先全量preflight，再事务式生成全部图。
10. 脚本错误只修脚本层；不要无脑重跑已PASS的前置阶段。
