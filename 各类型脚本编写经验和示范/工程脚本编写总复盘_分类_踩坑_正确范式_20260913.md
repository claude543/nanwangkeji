# 工程脚本编写总复盘
## MATLAB改模、只读审计、Verifier、RT-LAB Python Runner、DirectMAT计算、出图与封装的可复用经验

> 本文把本项目截至 2026-09-12/13 实际踩过的坑、已经证明有效的工程写法和后续固定流程重新分类。  
> 重点不是记录某一行代码怎么修，而是回答：
>
> **以后遇到同类任务，应该先写哪一类脚本、每类脚本能做什么、不能做什么、怎样一次性把问题收齐，以及怎样避免同一种返工再次发生。**

---

# 0. 先冻结最高原则

以后写任何工程脚本前，固定执行：

```text
先明确脚本类型
↓
先搜索仓库成熟实现 / helper / 成功脚本
↓
复用已经证明成功的识别和连接模式
↓
再写本轮最小新增逻辑
↓
生成后全文件静态扫描同类错误
↓
在不会破坏正式对象的层级先验证
↓
最后才碰正式模型 / Target
```

今天最明显的两次返工：

```text
R1审计：
重新使用 whole-SLX raw SHA 作为硬门
→ 仓库早已总结这是错误经验

R2审计：
重新发明 OpWrite 识别规则
→ 仓库早已有成功的 localFindAllOpWrites 模式
```

两次问题本质相同：

> **不是没有经验，而是生成脚本前没有真正把已有经验落实为代码约束。**

以后“先查仓库成熟 helper”必须是正式前置步骤，不再是可选项。

# 1. 本项目脚本必须按职责分类

不能把所有 `.m` / `.py` 都叫“测试脚本”。

| 类别 | 典型语言 | 主要职责 | 是否改模型/Target |
|---|---|---|---|
| A. 只读结构审计 | MATLAB | 回答“当前模型真实是什么” | 否 |
| B. 模型 Patch | MATLAB | 真正修改 Simulink 结构/源码/连线/参数暴露 | 是，改 SLX |
| C. 独立 Verifier | MATLAB | Patch 后重新只读验证 | 否 |
| D. 隔离 Harness / 自测 | MATLAB | 在临时普通模型验证生成源码/维度/构造方法 | 只改临时模型 |
| E. RT-LAB Target 探针 | Python | 证明当前 Build 参数/信号真实可写可读 | 可逆写 Target |
| F. 动态 Runner | Python | 按目标机时间轴执行正式工况并保留证据 | 会执行 Target |
| G. Archive-only / 后处理助手 | Python | 只归档既有 MAT，不重新跑物理试验 | 否 |
| H. DirectMAT / 原始 MAT 计算 | MATLAB | 从 OpWrite MAT 做最终工程分析 | 否 |
| I. 绘图/报告 | MATLAB/Python | 数据冻结后生成图、CSV、报告 | 否 |
| J. 封装/版本索引 | Python/MATLAB | SHA、manifest、正确/废止版本清单 | 否 |

最常见的返工，就是让一种脚本承担另一种脚本的职责。

例如：

```text
Patch PASS
≠
RT-LAB Build PASS

Build PASS
≠
Target参数可调

Runner结束
≠
电气性能PASS

MAT analyzer报数据问题
≠
物理试验必须重跑

Verifier语法错误
≠
Patch必须重新执行
```

# 2. A类：只读结构审计脚本

## 2.1 它只回答事实，不提前设计答案

正确任务：

```text
某个信号真正从哪里来？
某个端口真正连到哪里？
某个MATLAB Function当前源码是什么？
某个物理节点有哪些成员？
某个OpWrite到底是哪一组、什么宽度？
```

错误任务：

```text
先假定我要加一个控制器
→ 再让审计去证明它应该加
```

审计必须做到：

```text
事实
≠
设计决策
```

例如 C2：

```text
事实：
C2 Measurements=None
EV1_inv不在breaker-inner节点
EV1_LV_Meas在breaker另一侧

设计决策：
最终是否必须增加breaker-inner Vabc直接观测
```

前者是审计，后者是设计。

---

## 2.2 whole-SLX raw SHA 只能记录，不能等同语义身份

今天再次踩坑：

```text
Observed SHA != Historical SHA
→ 审计直接停止
```

但 `.slx` 是 ZIP 容器：

```text
布局整理
重新保存
metadata
打包顺序
```

都可能改变 raw SHA。

永久规则：

```text
raw SLX SHA
→ provenance / 来源记录

真正硬门
→ 模型名
→ 关键块存在
→ 关键MATLAB Function正文
→ 关键参数
→ 真实source/destination
→ 端口数/接口
→ 必要时Build后的compiled合同
```

---

## 2.3 Connectivity first，Name second

普通信号合同：

```text
source block / outport
→ destination block / inport
```

不要只写：

```text
“叫From28的那个块”
```

物理网络合同：

```text
LConn / RConn
+
节点成员集合
```

不要用普通信号线的：

```text
SrcBlockHandle / DstBlockHandle
```

去解释 SPS / Simscape conserving branch。

---

## 2.4 Goto/From 不能停在 From

今天 R3 审计曾只得到：

```text
IdIq_meas ← From28
IdIq_ref  ← From24
RawVdq    ← From26
```

这不叫“最终源头已审清”。

正确审计：

```text
From
↓
GotoTag
↓
唯一Goto
↓
Goto input真实Source
↓
Switch / Mux / Subsystem
↓
最终Measurement / Power Loop / 设备输入
```

如果 Goto 不是唯一：

```text
UNKNOWN / AMBIGUOUS
```

不能自动取第一个。

---

## 2.5 父子系统接口优先按 Port，而不是显示名称

今天 R3 用：

```matlab
find_system(...,'BlockType','Inport','Name','Vabc')
```

结果十个顶层输入全部 `NOT_UNIQUE / 0`。

大型模型里名字、历史复制、内部包装都可能变化。

更稳：

```text
ESS2_Control parent input1
← 实际Source

input2
← 实际Source
...
```

也就是：

```text
端口号 + SrcBlock + SrcPort
```

显示名称只做解释，不做唯一硬合同。

---

## 2.6 RT-LAB OpWrite 不要重新猜 BlockType

今天 R2 审计错误：

```matlab
find_system(...,'BlockType','Reference')
```

结果：

```text
OpWrite count = 0
```

仓库成熟实现已经证明正确方式：

```matlab
blocks = find_system(mdl, ...
    'LookUnderMasks','all', ...
    'FollowLinks','on', ...
    'Type','Block');

for each block:
    ref   = ReferenceBlock
    src   = SourceBlock
    mtype = MaskType

    txt = lower([ref ' ' src ' ' mtype]);

    if contains(txt,'opwritefile')
        → OpWrite
```

随后：

```text
读Acq_Group
→ 唯一映射G26~G30
```

这类 RT-LAB masked block 以后必须优先复用仓库 helper。

---

## 2.7 UNKNOWN 永远不能伪装成空

危险：

```matlab
try
    value = ...
catch
    value = [];
end
```

然后：

```text
[] → 无连接 → 安全
```

正确：

```text
read success
→ KNOWN

read fail / ambiguity
→ UNKNOWN
→ 不能做破坏性决定
```

---

## 2.8 一轮审计要一次收齐 blocker

旧式：

```text
A找不到
→ error
→ 修A
→ 下一次才发现B
```

正确：

```text
扫描全部合同
↓
收集 missing / duplicate / ambiguous
↓
输出统一 blocker 文件
↓
最后一次 raise
```

即使自动判据不能唯一，也应同时输出：

```text
所有候选路径
源码
连接trace
参数
```

后续人工就能用同一个 ZIP 封板，不要再拆第5、第6个微审计。

# 3. B类：MATLAB模型 Patch 脚本

## 3.1 Patch不是“能执行完”就算成功

Patch至少要满足：

```text
语义preflight
↓
scratch完整演练
↓
formal backup
↓
formal edit
↓
postassert
↓
save exactly once
↓
close/reload
↓
persistence postassert
```

真正平台可编译：

```text
RT-LAB Rebuild
```

仍是最后裁判。

---

## 3.2 推荐固定事务模板

```text
0. pure helper / numeric selftest
1. 当前模型语义preflight
2. byte-identical scratch copy
3. scratch apply
4. scratch postassert
5. scratch save once
6. scratch close/reload
7. scratch persistence verify
8. formal whole-file backup
9. formal re-preflight
10. formal in-memory edit
11. formal postassert
12. save_system exactly once
13. close/reload
14. persistence verify
15. result + SHA + report
```

异常分类：

### 正式保存前失败

```text
磁盘正式模型没有被该Patch保存
→ 不需要rollback
```

### 正式保存后失败

```text
whole-file backup覆盖回去
→ SHA确认byte-for-byte恢复
```

---

## 3.3 Scratch必须和正式构造“等价”

Final Build Closure R1 的教训：

Harness验证的是：

```text
Constant
→ Demux56
→ Mux56
```

正式Patch却是：

```text
创建Subsystem模板
→ 内部再建Demux/Mux
```

两者不等价。

结果默认 `In1 / Out1` 没在 Harness 里出现。

永久规则：

> **Harness要复用和正式Patch相同的builder函数。**

不是“逻辑差不多”就算等价。

---

## 3.4 新建 Subsystem 后必须先清空模板默认内容

错误：

```matlab
add_block('simulink/Ports & Subsystems/Subsystem',sub,...)
add In56
add Out56
```

库 Subsystem 已自带：

```text
In1
Out1
```

于是最终：

```text
2 inputs
2 outputs
```

正确：

```matlab
add_block(...)
Simulink.SubSystem.deleteContents(sub)

assert:
  direct children = EMPTY
  input count = 0
  output count = 0

再创建自己的：
In56 / Demux56 / Mux56 / Out56
```

这是以后所有“自动生成子系统”的固定模板。

---

## 3.5 MATLAB Function 的列向量不能只看 width

今天返回链/G27反复证明：

```matlab
y=zeros(12,1)
y=zeros(56,1)
```

虽然元素数是 12 / 56，但跨：

```text
task boundary
OpComm
OpWrite
```

时可能传播成 column matrix 维度语义，而不是普通 Simulink 1-D vector。

稳妥模式：

```text
MATLAB Function Nx1
↓
Demux N scalar
↓
classic Mux N
↓
标准N元素vector
↓
跨任务/OpWrite
```

所以：

```text
width=N
≠
orientation/dimensionality一定正确
```

---

## 3.6 拼接层级必须查“真正最后一层”

返回链第一次 Build 失败的根因：

R3 把 restore 12维追加到了：

```text
SS_Slave2/Mux
```

但真正最终返回拼接层其实是：

```text
AA15_V48_RETURN_APPEND_MUX [30 3]
→ Memory
```

因此：

```text
前级Mux改了
≠
最终packet真的改了
```

以后任何“扩向量/追加字段”前，必须从最终消费者反向追：

```text
Memory input
← final append
← legacy pack
← sources
```

不能按名字猜“这个Mux应该就是最后一个”。

---

## 3.7 空 endpoint 集合比较必须先规范化

Return Path Fix R1：

```text
Actual = empty
Expected = empty
```

却 mismatch。

原因：

```text
0×0 cell
1×0 cell
0×1 cell
```

在集合语义上都等价，但 `isequal` 比较容器形状。

正确：

```text
normalizeEndpointList
↓
统一1×N row-cell
↓
去空字符串
↓
排序
↓
比较元素数量
↓
逐项strcmp
```

所有“consumer set / endpoint set”以后都用集合语义，不比较 MATLAB cell 形状。

---

## 3.8 用Python生成MATLAB源码时要做整文件语法扫描

踩坑：

```matlab
readyBasic=...&&
    (...);
```

MATLAB Function Coder 报物理行语法错误。

以及历史自动生成：

```matlab
fprintf('
hello
');
```

字符向量未终止。

永久规则：

生成 `.m` 后扫描：

```text
fprintf(' / error(' / sprintf(' 跨物理行
bare && / ||
函数名与文件名
括号/引号
关键表项总数
重复token
```

发现一种 pattern：

```text
全文件扫描所有同类
```

不能只修 MATLAB 报出来的第一行。

---

## 3.9 不要把普通 host update 当 RT-LAB 最终裁判

当前 ARTEMiS / RT-LAB 模型含特殊 Selector、masked library、task interface。

普通：

```matlab
set_param(mdl,'SimulationCommand','update')
```

可能因为与本轮改动无关的历史结构失败。

所以：

```text
Patch / Verifier
→ 静态结构合同 + 隔离Harness

最终平台合同
→ RT-LAB Rebuild All
```

isolated ordinary-Simulink harness 可以 `update`，因为它只验证：

```text
生成MATLAB Function是否能解析
Demux/Mux构造是否可编译
```

不要用它冒充整个RT-LAB模型的Build。

# 4. C类：Independent Verifier

## 4.1 Verifier必须和Patch分离

Patch：

```text
负责写
```

Verifier：

```text
重新打开已保存模型
→ 只读检查
```

原因：

> 不能让“写错模型的代码”同时用同一套错误假设证明自己正确。

---

## 4.2 Verifier本身也要 pure selftest

Return Path Verifier R2 在访问模型前先测试：

```text
empty endpoint set normalization
排序
单元素
不同元素
不同数量
```

这是好模板。

以后任何自定义 helper：

```text
endpoint normalize
path normalize
schema decode
time merge
```

都应先纯函数自测，再碰模型。

---

## 4.3 Verifier解析错误时不要重跑已成功Patch

如果：

```text
Patch PASS / SAVED ONCE
```

然后 Verifier 因脚本语法错误根本没执行：

```text
模型没有因此变坏
```

正确：

```text
修Verifier
→ 继续验证
```

不要：

```text
重跑Patch
恢复PRE
再改一遍
```

# 5. D类：隔离Harness / 编译前自测

适合验证：

```text
MATLAB Function候选源码
Demux/Mux向量正规化
builder真实构造
```

不适合证明：

```text
RT-LAB最终task width
ARTEMiS完整编译
真实Target信号暴露
```

关键经验：

```text
Harness必须和production builder共享同一函数
```

否则会出现：

```text
Harness PASS
正式Patch仍因为构造差异失败
```

# 6. E类：Python Target Tunability / 信号探针

## 6.1 当前Build重新发现，不继承旧数字ID

不能把上一Build的：

```text
Parameter ID
Signal ID
```

硬编码到新 Build。

正确：

```text
GetParametersDescription
GetSignalsDescription
↓
当前Build重新发现
```

---

## 6.2 exact唯一命中才允许写

错误：

```text
exact没找到
→ 找名字差不多的near candidate
→ 自动写
```

正确：

```text
exact hits == 1
→ 才可写

0或>1
→ 只输出候选
→ 不动作
```

---

## 6.3 每次写参数必须 readback

```text
before
→ write
→ readback
→ compare
```

对于可逆 probe：

```python
old = read(path)
written = False
try:
    write(path, probe)
    written = True
    assert read(path) == probe
finally:
    if written:
        write(path, old)
        assert read(path) == old
```

避免：

```text
probe写成功
↓
第一次read报错
↓
restore没执行
```

---

## 6.4 信号描述重复行要按“真实PATH”去重

今天 ESS2 E2E 信号发现经验：

同一个信号可能在描述表出现多行。

不能直接：

```text
hits > 1
→ ambiguous
```

应该：

```text
normalize PATH
↓
collapse duplicate description rows
↓
剩余distinct path >1
→ 才叫ambiguous
```

然后每个接受路径都要：

```text
GetSignalsByName
```

真实可读。

# 7. F类：Python动态Runner

## 7.1 连接策略必须用仓库成熟模式

已证明的 yanshou_V7 连接：

```text
GetCurrentModel
↓
如果没有selected model：
GetActiveProjects
↓
只接受canonical yanshou_V7.llp
↓
验证项目里唯一目标模型
↓
OpenProject
↓
poll exact model
```

`GetCurrentModel: No selected model`

可能只是：

```text
API session binding
```

不等于：

```text
Target坏了
→ Reset
```

---

## 7.2 Runner起点要明确

正式运行：

```text
人工 Reset
→ Load once
→ MODEL_PAUSED @ t=0
→ 不手动Execute
→ Runner接管
```

Runner自己不偷偷：

```text
Reset
Load
```

这样 provenance 最清楚。

---

## 7.3 时间轴必须用 Target clock，不用 host sleep

正确：

```text
SetPauseTime
Execute
等待Target pause
读取Target clock
```

Host `sleep()` 只能用于轮询等待，不应作为物理仿真时间定义。

---

## 7.4 第一次Execute后不要自动Reset

Evidence-first：

```text
Execute以后
→ 出现普通V/f/I异常
→ Pause
→ 保存证据
→ DirectMAT分析
```

不要：

```text
看到波形差
→ 自动Reset
```

否则最关键的失稳 onset MAT 被清掉。

---

## 7.5 Hard Safety 和 Electrical Quality 必须分开

Runner硬停只针对：

```text
拓扑/控制合同无效
breaker未按命令
alpha提前非零
failCode
NaN/Inf
灾难性数值
```

普通：

```text
V暂低
f偏移
电流大
PostOK=false
```

应该首先是：

```text
物理证据
```

而不是立即把整轮判死。

ESS2 R3 → R4 的关键教训就是：

```text
50 ms PostOK=false
≠
永久不能恢复
```

R4改成长期零功率观察后，才真正证明：

```text
14 s仍不能进入state5
```

这才是模型/物理结论。

---

## 7.6 “内部资格去抖”不等于“外部长稳定证明”

例如：

```text
POST_DWELL = 0.2 s
```

只说明：

```text
连续0.2 s满足内部postOK
```

它不能代替：

```text
数秒长期稳定
```

状态机资格、Runner长期观察、最终物理判决必须分层。

---

## 7.7 同步判据要使用物理真实参考

ESS2早期 Runner 曾用：

```text
abs(PLL - legacy MasterF)
```

结果：

```text
PLL ≈ actual bus ≈ 50.233 Hz
legacy MasterF ≈ 49 Hz
```

误判不同步。

正确：

```text
物理并回同步
→ ESS2 PLL vs actual energized bus / PCC frequency
```

legacy MasterF：

```text
保留诊断
```

不能自动当物理真值。

---

## 7.8 Python只负责动作，不负责最终电气宣判

Runner输出：

```text
CAPTURE_COMPLETE_NO_ELECTRICAL_VERDICT
```

是好模式。

最终：

```text
MAT / engineering analysis
```

再判。

# 8. G类：Archive-only / 不重新跑物理试验

一条非常重要的规则：

> **后处理错误不能触发物理重跑。**

如果：

```text
正式试验已经完成
MAT只是晚落盘
archive脚本字段错误
plot脚本错误
```

应该：

```text
重新归档 / 重新分析
```

不能：

```text
重新Execute相同物理工况
```

除非原始运行证据本身不完整且不可恢复。

因此 Archive-only helper 要明确：

```text
NO Load
NO Reset
NO Execute
NO parameter write
```

# 9. H类：MATLAB DirectMAT / 原始MAT计算

## 9.1 Target Time 是唯一时间真值

不要用：

```text

主机读取时刻
```

代替仿真时间。

正式规则：

```text
MAT row1 = Target Time
```

---

## 9.2 每个family必须 exact schema

例如本轮：

```text
G27:
Target Time + 56 device channels = 57 rows

G29:
Target Time + 46 = 47 rows
```

不能：

```text
“列数差不多就读”
```

---

流程：

```text
列出本轮changed MAT
↓
验证stem / variable / row count
↓
按Target Time排序
↓
合并所有合法segment
```

---

## 9.4 相同Target Time内容不同 = HARD FAIL

如果两个 segment：

```text
Target Time相同
但内容不同
```

说明：

```text
可能混轮
```

不能“选最新”。

应：

```text
HARD FAIL
```

---

## 9.5 Missing ≠ 0

MAT缺失：

```text
unknown
```

不是：

```text
0
```

绝不能为了画图方便补零。

---

## 9.6 Schema改变后不要沿用历史语义

本次 G27 Repack 后：

```text
ch37 = PowerReleaseAllowed
```

不再是旧的：

```text
MasterF
```

如果 Analyzer 沿用旧 schema：

```text
数值能读
语义全错
```

所以：

> schema必须和当前 Build 同版本冻结。

---

## 9.7 有限窗FFT峰值不能冒充系统特征值

可以说：

```text
该时间窗主要能量峰位于某频段
```

不能直接说：

```text

```

除非做了真正线性化/模态识别。

# 18. 哪些规则应永久写进我们的项目习惯

最终压缩成 15 条：

1. **先分脚本类型，再写。**
2. **写前先搜仓库成熟 helper。**
3. **raw SLX SHA只作记录，语义合同才是硬门。**
4. **Connectivity first，Name second。**
5. **From不是最终源头，必须追Goto/selector/source。**
6. **SPS物理网络按电气节点，不按普通信号线。**
7. **UNKNOWN永远不是empty/PASS。**
8. **Patch必须scratch-first、事务式、save exactly once。**
9. **Subsystem模板创建后先deleteContents。**
10. **Nx1 MATLAB Function输出跨task/OpWrite前关注orientation，不只看width。**
11. **Patch和Verifier分离；Verifier失败不等于Patch要重跑。**
12. **Build之后Target参数必须真实写/readback/restore验证。**
13. **Runner使用Target clock，第一次Execute后不自动Reset。**
14. **后处理错误绝不自动触发物理重跑。**
15. **一次发现一种脚本pattern错误，全文件扫同类并一次修完。**
