# 关键论文全文碰撞框架

用于真正会影响研究决策的关键论文。

目标不是写一篇长摘要，而是回答：

> 它到底与我们的当前研究问题撞到哪一层？

# 1. 证据边界

对关键判断明确写：
- 已由全文确认
- 摘要支持
- 仅有基本信息
- 分析推断
- 现有材料无法判断

“没有做某事”优先使用全文确认。

# 2. 先按通用八维分析

每篇核心论文检查：

1. 研究对象
2. 研究目标
3. 问题层级与时间尺度
4. 状态/信息/数据
5. 核心机制
6. 约束与假设
7. 扰动/不确定性/运行条件
8. 验证与证据

# 3. 为什么这篇重要

必须说明：

> 它对应本轮哪个研究决策问题？

如果不能回答，通常不应成为核心全文。

# 4. 它真正做到了什么

只写有证据支持的能力。

不要把作者愿景、未来工作或泛化描述当成已验证能力。

# 5. 它没有覆盖什么

分成三类：

## 作者明确声明未做
作者自己写出的限制或未来工作。

## 全文结构可以确认未覆盖
从模型、算法、实验结构中能够确认。

## 当前无法判断
材料不够，不猜。

# 6. 哪些成熟机制可以直接借鉴

例如：
- 已经成熟的控制模块；
- 估计器；
- 优化框架；
- 稳定性判据；
- 保护逻辑；
- 实验设计；
- HIL验证方法；
- 建模方法。

“可以借”不等于“不能用于我们的论文”。

# 7. 哪些内容不能再当主要创新

明确写成自然中文：

- 已不能作为主要创新；
- 原因是什么；
- 哪篇文献已经覆盖到什么程度。

不要只给英文状态码。

# 8. 当前核心还剩什么

写清：

> 在考虑这篇论文以后，我们真正仍值得研究的问题是什么？

不要直接写“全球首次”。

# 9. 当前还存在什么风险

例如：
- 相邻领域可能已有同类机制；
- 只有摘要没有全文；
- 相同机制在不同对象中已有；
- 某项差异可能只是应用名称不同。

# 10. 研究方向影响

只给中文判断：

- 保持当前方向；
- 进一步收窄方向；
- 需要实质修改方向；
- 建议放弃当前方向。

后两者需要用户确认。

# 11. 按研究视角追加检查

根据当前主要/辅助视角，从
[electrical-engineering-profile.md](electrical-engineering-profile.md)
选择真正会影响当前决策的附加维度。

不要把所有视角的清单全部机械检查。

# 12. 通信/信息物理控制的条件检查

只有当当前问题触发相应层级时才检查。

## 性能/稳定性层
时延、丢包、带宽、新鲜度、通信拓扑、稳定性边界。

## 命令执行不确定层
是否需要区分：
- 控制器算出的命令；
- 最后成功提交的命令；
- 设备实际采用的设定；
- 设备真实输出。

## 恢复/重新接管层
检查：
- 保持；
- 防积分饱和/冻结；
- 备用控制；
- 复位；
- 恢复/重新启用；
- 平滑切换；
- 状态重新初始化；
- 设备真实执行反馈；
- 显式状态校正/重构；
- 受控重新接管。

特别区分：

> 重新收到新测量并继续计算

与

> 明确发现控制器内部状态已经失真，并用设备真实状态进行校正/重构

不是同一件事。
