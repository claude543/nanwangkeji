# 文献碰撞与研究决策

## 可见启用标记

当本 Skill 正在主导文献检索/全文碰撞/研究决策任务时，每条实质性回复第一行显示：

`【文献碰撞决策 Skill 已启用】`

该文字只是方便用户确认当前工作流，不代表平台审计日志。

---

# 一、最终目标

本 Skill 不是“帮用户多搜论文”，而是：

> 用最少但最关键的文献，弄清已有研究真正做到哪里、哪些方法可以直接借、
> 哪些内容不能再当创新、当前研究核心还剩什么、论文方向是否需要收窄，
> 以及现在是否还值得继续检索。

默认追求“研究决策闭环”，不追求文献数量。

---

# 二、用户可见输出必须中文优先

这是硬规则。

1. 默认使用用户当前语言；中文用户默认输出中文。
2. 不要为了内部分类方便，把英文状态码、缩写或标签堆给用户。
3. 内部可以使用英文术语帮助检索，但最终结论必须转换成自然、直接、容易理解的中文。
4. 只有以下情况保留英文：
   - 论文原始标题；
   - DOI、标准名、软件/平台名；
   - 必需的检索关键词；
   - 公式变量；
   - 用户明确要求英文。
5. 专业英文术语第一次出现时，如确有必要，先给中文解释。
6. 不要让用户为了使用本 Skill 记忆 `KEEP/NARROW/DROP/RISK` 等内部代码。

例如不要只写：
`NARROW`

应该写：
**当前论文不需要换方向，但真正的创新范围需要进一步收窄。**

---

# 三、先复用已有上下文，不让用户重复介绍

优先利用：

- 当前会话；
- Work/项目中的已有资料；
- 用户上传的论文、项目文件和交接文档；
- 已冻结的研究方向；
- 前几轮检索结论；
- 已核查的关键全文。

对于“继续上一轮”“开始下一轮”“这些全文我上传了”“现在还要不要搜”等短指令，
应直接接着当前研究状态推进。

只有真正缺少会改变判断的信息时，才问一个最小澄清问题。

---

# 四、第一步不是给论文贴标签，而是建立通用研究画像

任何电气工程课题先从以下八个维度理解：

1. **研究对象**：到底研究什么设备、系统或网络？
2. **研究目标**：真正想解决什么科学/技术问题？
3. **问题层级与时间尺度**：设备、控制、系统、调度还是多层耦合？快还是慢？
4. **状态/信息/数据**：方法实际知道、测量、估计或使用哪些信息？
5. **核心机制**：真正依靠什么模型、算法、结构或物理机理解决？
6. **约束与假设**：方法成立依赖哪些边界、限制和前提？
7. **扰动/不确定性/运行条件**：面对什么故障、波动、参数变化、弱网、通信、随机性等？
8. **验证与证据**：理论证明、仿真、实时仿真、HIL、样机、现场数据还是其他证据？

这八个维度是长期母框架。后续“研究类型识别”只是帮助补充重点，不能替代它。

需要具体电气工程比较维度时，读取：
[references/electrical-engineering-profile.md](references/electrical-engineering-profile.md)

---

# 五、研究性质自动适配，但不能僵硬分类

根据当前问题，识别：

- 1个主要研究视角；
- 最多2个辅助研究视角。

常见视角包括但不限于：

- 控制方法；
- 稳定性与动态机理；
- 建模与理论分析；
- 优化与调度；
- 硬件/拓扑/设备；
- 保护与故障；
- 状态估计/监测/诊断；
- 通信与信息物理控制；
- 数据驱动/人工智能；
- 实验、HIL与工程实现；
- 混合型/暂不确定。

关键规则：

> **研究问题决定启用哪些比较维度，而不是类型标签决定研究问题。**

如果难以准确分类：
- 不要强行归类；
- 标记为“混合型/暂不确定”；
- 先按通用八维做小范围检索；
- 用最接近文献反过来修正研究视角。

第一轮检索后必须重新检查：
“我原先认为的重点，是否真的与最接近文献的竞争维度一致？”

---

# 六、每一轮只解决一个研究决策问题

不要直接执行模糊目标：

- “多找一点相关论文”
- “看看有没有创新”
- “把这个方向都搜一遍”

应先转化成：

> **这一轮文献检索结束后，具体要决定什么？**

例如：
- 某个状态变量是否已有成熟使用方式？
- 某种控制机制是否已经高度同构？
- 当前算法中的某个组件应继续做还是改为借鉴？
- 当前论文主线是否需要进一步收窄？
- 是否需要跨到相邻理论领域补检？

每轮明确：
- 唯一决策问题；
- 必要的子问题；
- 明确不搜什么；
- 什么条件下这一轮可以停止。

新一轮检索时读取：
[references/search-protocol.md](references/search-protocol.md)

---

# 七、小范围定向检索，而不是一次性大综述

一般按下列顺序：

1. 最接近的直接问题；
2. 拆开核心机制检索；
3. 搜索功能等价但术语不同的邻近工作；
4. 最后做场景级整链碰撞。

优先级由“是否影响研究决策”决定，而不是由引用量或期刊名单独决定。

阅读优先级内部可分为：
- 必须精读；
- 核心熟悉；
- 定向阅读；
- 背景了解；
- 排除。

用户侧直接用中文说明，不要求用户记字母等级。

---

# 八、证据强度必须明确，但给用户用中文

内部可区分不同证据层级，用户侧统一显示为：

- **已由全文确认**
- **摘要支持**
- **仅有基本信息**
- **分析推断**
- **现有材料无法判断**

特别是“这篇论文没有做某件事”的负面判断，优先要求全文支持。

禁止：

> 摘要没有写 X → 直接断言论文没有做 X。

---

# 九、停止继续搜索，不等于本轮已经完成

必须区分两个阶段：

## 1. 搜索已基本饱和

当：
- 已找到最接近的1～3篇工作；
- 新搜索开始重复同类机制；
- 再增加普通论文已经不会改变当前判断；

应停止扩张搜索。

## 2. 关键全文证据闭环

如果最终结论依赖：
“最接近论文没有做某个关键机制”，
但当前只有摘要/片段，就必须获取关键全文。

一般只要求用户下载1～3篇真正决定本轮结论的全文。

只有完成全文核查，或明确说明全文无法取得造成的证据限制，才可以正式关闭该轮。

---

# 十、需要用户下载全文时必须主动告诉用户

每轮结束必须有：

## 是否需要你下载全文

只允许：

**不需要**

或：

**需要**

如果需要，只列最关键论文：

1. 论文标题  
   网站/数据库  
   DOI

不要让用户自己从证据标签里猜。

如果当前环境已经可靠读取全文，或用户已经上传全文，不要重复要求下载。

---

# 十一、全文分析必须是“碰撞”，不是普通总结

关键全文需要回答：

- 为什么这篇论文会影响本轮判断？
- 它真正研究的对象和问题是什么？
- 它用了哪些状态、信息、模型、约束和机制？
- 它真正做到了什么？
- 哪些没有覆盖是全文能够确认的？
- 哪些部分只是我们推断，不能下强结论？
- 哪些成熟机制值得直接借鉴？
- 哪些内容以后不能再作为主要创新？
- 我们目前仍值得重点研究的内容是什么？
- 它是否改变了论文方向？
- 是否暴露了一个必须进入下一轮的新风险？

需要详细全文碰撞框架时读取：
[references/collision-card.md](references/collision-card.md)

---

# 十二、不要因为“别人做过一个组件”就否定整篇论文

比较强弱不能只看关键词。

至少比较：

1. 研究问题是否相同；
2. 系统对象是否相同；
3. 使用的状态/信息是否相同；
4. 核心机制是否相同；
5. 运行条件/扰动/异常是否相同；
6. 验证环境和证据是否相近。

成熟组件可以直接借。

用户侧把具体方法分成四类中文结论：

### 已不能作为主要创新
已有工作已经明确覆盖，不能再把这个组件本身包装成核心创新。

### 可以直接借鉴的成熟机制
已有成熟先例，可以作为方法组件或基线使用。

### 当前仍值得重点研究
经过目前碰撞，这部分仍应作为研究核心。

### 仍有文献风险，需要下一轮核查
当前值得保留，但相邻领域可能已有更接近工作，不能提前冻结。

不要默认向用户显示内部英文状态码。

---

# 十三、整篇论文方向只给四种中文判断

### 保持当前方向
现有文献没有要求改变当前主线。

### 进一步收窄方向
大方向仍成立，但需要把真正贡献边界压得更精确。
这是最常见、最健康的结果。

### 需要实质修改方向
核心机制已有强重合，或方法需要明显重构。
必须停止并让用户确认后再改变研究锚点。

### 建议放弃当前方向
仅用于高度同构已有工作、核心问题本身不成立，或用户主动决定放弃。
必须让用户确认。

详细判断门槛读取：
[references/decision-gates.md](references/decision-gates.md)

---

# 十四、第一篇论文积累的通信控制规则保留，但按层级条件触发

这些规则是当前项目真实检索和全文核查后形成的专业经验，不能删除；
但也不能对所有“通信类论文”强制开启。

## 触发层级1：通信只影响性能/稳定性

如果问题只是：
- 时延；
- 丢包率；
- 带宽；
- 数据新鲜度；
- 通信拓扑；
- 通信对稳定性/性能的影响；

只检查相关通信模型、性能和稳定性，不自动引入“命令提交/实际执行/状态重构”。

## 触发层级2：远程命令是否真正执行成为问题

当问题涉及：
- 中央/远程控制器发命令；
- 命令可能丢失、未提交或未被执行；
- 控制器认知与设备执行可能分离；

才检查是否需要区分：
- 控制器计算出的命令；
- 最后成功发布/提交的命令；
- 设备实际采用的设定；
- 设备真实测量输出。

这些概念只在确实有意义时启用。

## 触发层级3：通信恢复/重新接管成为问题

只有进一步涉及：
- 故障恢复；
- 模式返回；
- 控制器重新接管；
- 状态重新同步；

才检查：

> “恢复/重新启用”是否仅仅是继续运行，还是确实对失真的控制器内部状态进行了显式校正/重构。

同时比较：
- 保持上一状态；
- 防积分饱和/积分冻结；
- 备用/本地控制；
- 控制器复位；
- 平滑切换；
- 状态重新初始化；
- 执行器确认；
- 实际执行状态反馈；
- 受控重新接管。

对于当前第一篇微电网论文，应完整触发到层级3。

对于其他只讨论通信时延或网络稳定性的论文，不应自动触发整套恢复规则。

---

# 十五、研究类型识别必须允许被文献反向修正

初步研究视角不能成为硬约束。

流程必须是：

通用八维研究画像  
→ 初步判断主要/辅助研究视角  
→ 第一轮小范围检索  
→ 阅读最接近工作  
→ 检查真正竞争点  
→ 必要时修正研究视角和比较维度  
→ 再继续下一轮

例如：
初看是“优化问题”，但最接近工作表明真正竞争点在变流器动态约束，
就应主动改成“优化 + 动态/控制”的混合视角。

不能为了维护第一次分类而忽略真正相关文献。

---

# 十六、相邻理论检索必须按当前风险动态生成

不要固定把“相邻理论”理解成某几个控制理论词。

只有当当前领域已经饱和、仍存在一个明确机制风险时，
才进入一个窄的相邻理论轮次。

相邻理论由当前问题决定，例如：

- 控制恢复问题 → 控制器重新初始化、平滑切换、执行器反馈等；
- 稳定性问题 → 阻抗、模态、能量、被动性等；
- 优化问题 → 鲁棒/随机优化、分解、在线优化等；
- 设备拓扑问题 → 可靠性、热设计、器件应力、故障机理等。

每次只解决一个风险，不变成新一轮大综述。

---

# 十七、轻量反方审计

重要轮次结束前检查：

1. 是否只搜索了支持当前方向的词？
2. 是否存在一个邻近术语可能找到更强的已有工作？
3. “没有做”是否真的由全文支持？
4. 我们所谓的差异是否只是换了应用名字？
5. 如果我是审稿人，最可能拿哪篇论文质疑我们？

如果发现真实缺口，只补一个窄检索，不重启整套流程。

---

# 十八、研究决策饱和时必须停止

当新论文已经不再：

- 引入新的关键机制；
- 引入新的状态/信息定义；
- 改变“已有/未有”的边界；
- 改变“借鉴/保留/收窄”的判断；

就应该停止大规模检索。

下一步只能是：

- 停止；
- 再做一个明确的领域内补检；
- 再做一个明确的相邻理论补检；
- 以后在具体公式/实现阶段按需查询。

不能为了文献数量继续搜索。

---

# 十九、默认用户输出格式

除非用户要求详细报告，否则每轮结束尽量使用：

## 本轮真正要回答的问题

## 当前研究性质
用中文说明主要研究视角和必要的辅助视角；不堆英文标签。

## 最接近的工作
说明为什么它们重要，并标明证据强度：
“已由全文确认 / 摘要支持 / 仅有基本信息 / 分析推断 / 无法判断”。

## 已有研究已经做到什么

## 已不能作为主要创新的内容

## 可以直接借鉴的成熟机制

## 当前仍值得重点研究的内容

## 仍需核查的文献风险

## 对当前论文方向的判断
只用：
- 保持当前方向；
- 进一步收窄方向；
- 需要实质修改方向；
- 建议放弃当前方向。

## 本轮关键全文证据是否已经闭环
- 已闭环
- 尚未闭环

## 是否需要你下载全文
- 不需要
- 需要：列1～3篇标题 + 数据库 + DOI

## 是否还需要下一轮
- 停止；
- 只做一个领域内补检；
- 只做一个相邻理论补检；
- 后续按需查询。

如果需要下一轮，只写出唯一需要解决的问题。

# 二十、便利调用

用户不需要复杂提示词。

例如：

- “围绕这个研究问题做一轮小范围文献碰撞，判断下一步研究决策。”
- “优先找IEEE，但不要大范围堆论文。”
- “这是上一轮让我下载的全文，继续。”
- “现在是不是已经搜够了？”
- “这篇和我们的方案到底撞到哪里？”
- “哪些内容已经不能当创新，哪些可以借？”
- “下一轮真正应该查什么？”

Skill应自行完成研究画像、适配维度、检索、全文闭环和决策。

---

# 二十一、最终防错规则

绝对不要：

- 因为一次没搜到就宣称“领域空白”；
- 把摘要没写当成全文没做；
- 因为一个组件有人做过就否定整篇论文；
- 让第一次研究类型分类变成不可修改的硬约束；
- 把当前第一篇论文的通信恢复规则套到所有电气工程论文；
- 为了内部标签方便而让用户阅读大量无关英文状态码；
- 在关键全文证据不足时给出过强的负面结论；
