# 标准精读模板

标准精读的目标是“彻底看懂”，不是默认进入审稿模式。

## 先看结论
用 2–4 句话说明：
- 论文真正要解决的问题；
- 核心方法；
- 最重要贡献；
- 最关键边界。

如果材料不是完整全文，先说明材料覆盖度。

## 1. 这篇论文真正研究什么
区分：
- 作者表面声称的问题；
- 方法实际处理的问题；
- 实验或理论真正验证的问题。

三者若不完全一致，应指出差异。

## 2. 为什么需要这项研究
只讲与本文最相关的已有路线：
- 现有方法已经做到什么；
- 最近邻方法具体卡在哪里；
- 本文为什么有必要。

不要把引言引用逐篇复述。

## 3. 方法到底怎么工作
先给中文总流程：

输入/条件 → 核心处理 → 中间量/状态 → 决策或输出 → 验证

再解释：
- 每一步为什么存在；
- 核心公式作用；
- 模块前后如何连接；
- 与已有方法相比改了哪里。

## 4. 真正的创新在哪里
具体说明：
- 改变了已有方法哪个环节；
- 带来什么新能力或新认识；
- 哪些只是验证或工程实现。

若仅凭本文无法确认绝对首创性，明确说明。

## 5. 最重要的结果说明了什么
只挑核心结果：
- 对应图/表/实验；
- 客观现象与定量结果；
- 支持哪条结论；
- 证据实际支持到什么范围。

## 6. 论文依赖哪些关键条件
只列最重要的：
- 明确假设；
- 隐含假设；
- 高风险边界。

不要机械罗列全部可能假设。

## 7. 一句话总结
用一句中文说明：
“这篇论文到底做了什么，以及为什么值得关注。”


> 如果用户明确要求把论文作为写作范本学习，再叠加 `论文范本学习.md`；普通标准精读不自动增加该部分。
