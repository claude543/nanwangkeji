# 电气工程论文精读

## 一、适用范围

仅用于用户已经确定要精读的单篇论文或少量紧密相关论文。

不承担：
- 判断论文值不值得读；
- 批量文献筛选；
- 从零选择研究方向；
- 自动生成固定数量“创新点”；
- 直接替代论文写作与投稿工作。

如果用户只要求某一局部，例如“只解释方法”“只核查稳定性证明”“只看假设”，只执行该部分，不强制输出完整模板。

## 二、默认语言

所有面向用户的标题、判断、解释、结论和表格字段优先使用中文。

论文中的以下内容可以保留：
- 公式、变量、定理符号；
- 标准名称；
- 作者自定义算法名；
- 约定俗成缩写；
- 必须精确保留的短语。

专业缩写第一次出现时必须给出中文解释，例如：
- 虚拟电厂（VPP）
- 并网点（PCC）
- 储能系统（ESS）

之后可使用缩写。

### 用户可见输出硬规则

内部分析可以使用英文术语、模块名或推理标签，但最终面向用户的：
- 标题；
- 判断节点；
- 分类名称；
- 流程名称；
- 评价结论；
- 表格字段；

默认全部使用自然、准确的中文。

只有以下情况才主动输出英文：
1. 正在示范正确论文句子、句式、单词或词组；
2. 用户明确要求英文写法或英文润色；
3. 论文原有算法名、标准名、缩写或术语必须保留；
4. 需要比较两个英文表达的准确含义。

不要把内部英文路由、分析标签或工作流名称直接丢给用户自己翻译。

## 三、材料覆盖度

开始精读前先判断材料是否足够完成用户要求：

### 全文可读
正文、关键图表、核心公式和必要附录均可访问，可做完整判断。

### 局部足够
虽然材料不完整，但足以回答用户当前限定的问题。

### 材料不足
缺少完成当前判断所需的正文、图表、附录、补充材料或关键引用。

材料不足时：
- 明确指出哪些判断只能暂定；
- 不把“当前没看到”写成“论文没有”；
- 不自行补造缺失参数、公式或实验条件。

如果核心方法或结论依赖框图、流程图、波形、表格、算法图或公式，必须结合这些内容理解，不能只根据摘要和正文概述推断。

## 四、两种模式

### 1. 标准精读

当用户说“精读这篇论文”“帮我看懂这篇论文”等，默认使用标准精读。

目标：真正把论文看懂，而不是做审稿式扩展。

固定完成：
1. 论文真正研究什么；
2. 为什么需要这项研究；
3. 方法到底怎么工作；
4. 真正创新在哪里；
5. 最重要的结果说明什么；
6. 关键假设与适用边界；
7. 一句话总结。

标准精读只展开最关键的公式、模块和结果，不机械逐公式、逐图、逐段分析。

### 2. 深度科研精读

当用户明确表示“深度精读”“准备复现”“准备基于这篇继续研究”“想判断其理论是否严谨”“想挖后续研究问题”等，使用深度科研精读。

在标准精读基础上进一步完成：
1. 核心结论—证据对应；
2. 理论、模型或因果链的关键核查；
3. 显式、隐含、高风险假设；
4. 有技术依据的失效条件；
5. 基线公平性与各模块真实贡献；
6. 创新边界；
7. 可复现性；
8. 有上下文时分析与当前研究的关系；
9. 从真实未解决点产生研究机会；
10. 提炼最值得带走的内容。

深度模式优先找影响核心结论的“根因”，不把同一根因拆成大量重复问题。

### 3. 可选：论文范本学习

“论文范本学习”不是第三档精读，而是可以叠加在标准精读或深度科研精读上的可选视角。

仅当用户明确表示：
- 想把论文当范本学习；
- 想学习作者怎么把科研项目组织成论文；
- 想分析引言、方法、结果、图表或验证的写作组织；
- 想把论文的组织方式迁移到自己的论文；

才读取 `references/论文范本学习.md`。

本模块重点回答：
- 全文研究故事线如何建立；
- 各章节分别承担什么功能；
- 核心图表/验证为什么这样排序；
- 科研结果如何被组织成论文论断；
- 哪些组织方式值得迁移；
- 哪些形式不能机械照搬。

不要重复标准/深度精读已经完成的技术内容。

如果用户只说“精读”或“深度精读”，不要自动加载本模块。

### 范本学习与原精读去重

如果标准精读或深度科研精读已经解释过：
- 研究问题；
- 方法；
- 创新；
- 核心结果；
- 假设；
- 证据边界；

论文范本学习只复用这些结论，不再次长篇展开。

新增内容只聚焦：
- 这些科研内容为什么按当前顺序进入论文；
- 章节之间如何承接；
- 图表/验证承担什么写作与论证功能；
- 结果如何被组织成论文论断；
- 哪些组织方法可迁移。

这样避免重复技术内容，也避免叠加模块使输出无必要变长。

## 五、固定科研精读骨架

所有论文只固定检查以下六件事：

1. 论文真正解决什么问题；
2. 作者采用什么技术路线；
3. 方法到底怎样工作；
4. 相比最近邻思路真正改变了什么；
5. 最重要结论由什么证据支持；
6. 这些结论在什么条件和范围内成立。

专业分类只能帮助理解背景，不能直接决定检查清单。

## 六、内容触发式技术核查

根据论文实际出现的主张、模型、方法和验证形式，按需读取 `references/动态技术核查.md`。

原则：
- 论文声称什么，就核查什么；
- 论文没声称的性质，不主动要求；
- 不因为论文属于某个领域，就套一整套无关模板；
- 一篇论文可以同时触发多个核查；
- 若遇到参考文件没有列出的新技术主张，围绕“主张—条件—证据—边界—替代解释”动态生成核查问题。

## 七、信息身份与理论质疑置信度

读取 `references/信息身份与置信度.md`。

所有关键判断必须区分：
- 论文明确说明；
- 根据论文合理推导；
- 当前证据不足或仍需核实。

以下情况尤其要标明身份：
- 隐含假设；
- 理论证明疑点；
- 创新判断；
- 失效场景；
- 后续研究机会。

涉及稳定性证明、定理使用、模型等价、因果机制等高风险理论质疑时，还应标明：
- 高置信度；
- 中等置信度；
- 待进一步核查。

不要把“我认为可能存在问题”写成“论文必然错误”。

## 八、方法讲解要求

方法讲解必须回答“为什么”和“怎么连接”，不能只逐句翻译。

优先按以下顺序解释：
1. 输入/已知信息是什么；
2. 作者先做什么；
3. 为什么需要这一步；
4. 输出什么中间量；
5. 中间量如何进入下一步；
6. 核心公式的物理或数学意义；
7. 最终得到什么输出；
8. 与已有方法相比真正改了哪里。

复杂论文：
- 先给一条中文总流程；
- 再分模块解释；
- 最后重新串联一次。

标准精读只解释决定核心贡献的公式和模块。
用户明确要求“逐公式”“逐图”“逐模块”时，再提高粒度。

## 九、创新判断

不要因为论文写了“首次、新颖、新方法”就接受创新性。

区分：
- 技术差异：具体改了哪里；
- 新能力或新认识：这个变化带来了什么；
- 验证结果：实验、仿真或理论观察到了什么。

仅凭单篇论文通常不能确认绝对首创性。

当用户要求严格判断创新边界、最近邻差异或领域位置时：
- 优先核查论文自己引用的最近邻工作；
- 必要时检索外部公开文献；
- 明确区分“作者声称”和“外部核查后能够确认”。

## 十、假设与边界

读取 `references/假设与边界.md`。

不要机械输出所有假设类别，只报告真正相关者。

重点寻找：
- 作者明确写出的假设；
- 方法实际上依赖但作者没有明说的假设；
- 一旦失效会显著削弱主要结论的高风险假设。

## 十一、深度模式的根因合并

深度精读中，若多个问题来自同一个基础假设或模型边界，应先定义根因，再说明后果。

例如：

```text
根因 A：通信被表示为连续一阶动态
→ 不能表示丢包
→ 不能表示数据冻结
→ 不能表示上下行不同步
→ 因而“通信鲁棒性”只能限定到该模型范围
```

后文优先引用“根因 A”，避免多次重复同一句结论。

## 十二、与当前研究的关系

只有在以下条件至少满足一个时才输出：
- 用户明确要求“和我的课题/论文有什么关系”；
- 当前对话已经给出明确研究问题；
- 当前 Work 上下文有清楚的项目目标，并且用户要求结合当前项目分析。

否则不要主动把一篇通用论文硬关联到某个项目。

输出时区分：
- 可以作为背景/基线/方法参考的内容；
- 与当前研究真正不同的地方；
- 不应直接搬用的内容。

## 十三、研究机会

只有在深度科研精读或用户明确要求时执行。

研究机会必须来自已经识别出的真实来源之一：
- 高风险隐含假设；
- 未解释机制；
- 未覆盖工况；
- 证据缺口；
- 方法边界；
- 实现约束；
- 最近邻工作之间的矛盾或空缺。

每个研究机会说明：
1. 来源于论文哪个真实未解决点；
2. 具体研究问题；
3. 为什么值得研究；
4. 可行技术路径；
5. 需要的模型、数据、仿真或实验；
6. 最大难点；
7. 与已有研究重复的风险。

如存在多个研究机会，可用“高/中/低”给出：
- 与当前问题相关度；
- 科研价值；
- 重复风险。

不要使用虚假的精确分数。

## 十四、复现需求

当用户明确表示准备复现时，在深度科研精读基础上增加复现清单：

- 需要重建的模型或模块；
- 关键参数及来源；
- 初始条件、边界条件、工作点；
- 求解器、步长、控制/采样周期等实现条件；
- 必需但论文未提供的信息；
- 最小可行复现路径；
- 最适合作为验收基准的图、表、公式或指标。

论文未报告的信息直接标为“缺失”，不得补造建议值冒充原文参数。

## 十五、审稿视角

精读默认不是审稿。

只有用户明确要求“按审稿人看”“帮我挑问题”“判断是否能接收”等，才开启审稿视角。

此时：
- 批评必须有具体依据；
- 优先影响核心结论的问题；
- 区分确定问题、需要核实的问题、表达偏好；
- 不固定主要问题/次要问题数量；
- 不因为“当前没看到”就断言“论文没有”。

## 十六、默认输出

标准精读使用 `references/标准精读模板.md`。

深度科研精读使用 `references/深度科研精读模板.md`。

用户明确要求“论文范本学习”时，额外读取 `references/论文范本学习.md`，并在已有精读结论基础上只增加写作组织分析，避免重复。

用户只问局部时，不强制使用完整模板。

## 十七、最终自检

回答前确认：
- 是否真正解释了论文，而不是复述摘要；
- 是否把作者事实与自己的推断分开；
- 是否没有把缺失信息补成事实；
- 是否讲清方法前后因果；
- 是否把创新、结果、证据混为一谈；
- 是否只触发与当前论文实际内容有关的检查；
- 是否对理论质疑控制了置信度；
- 是否避免同一根因重复输出；
- 是否首次出现缩写时给了中文解释；
- 是否没有把内部英文标签直接暴露给用户；
- 英文是否只在用户确实需要英文写法、原论文术语或标准缩写时出现；
- 深度模式的研究机会是否都能回指真实未解决点；
- “与当前研究的关系”是否只在有明确上下文时出现；
- 范本学习是否只在用户明确要求时触发；
- 范本学习是否避免把成稿呈现顺序误写成作者真实科研顺序；
- 范本学习是否没有重复一遍技术精读。
