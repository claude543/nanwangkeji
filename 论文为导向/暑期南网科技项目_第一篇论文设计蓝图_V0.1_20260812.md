# 5. Baseline严格定义

Baseline就是当前冻结的基础AGC。

核心：

```text
dP = Ptarget - Ppcc
```

资源顺序：

```text
dP > 0：
PV增加 → ESS放电 → EV减少充电

dP < 0：
EV增加充电 → ESS充电 → PV降低
```

主要依据：

```text
PCC总功率反馈
PVmax
SOC硬边界
理论功率上下限
AGC内部历史命令
固定资源优先级
```

最终正式实验中的Baseline应优先使用：

> **V5验证通过的真实板端基础C AGC闭环。**

这样Baseline与Proposed使用同一控制板、同一Modbus、同一OP5700对象，比较才公平。

```text
执行侧实际采用的设定状态

正常设备动态下应该出现的响应

```

核心问题：

```text
controller perceived state
≠

```

# 7. 已观察到的Baseline失效现象

## 正常长期运行

```text
PCC仍能维持目标附近
但
PV越来越正
EV越来越负
```

说明PCC目标正确，不等于内部资源状态合理。

## 下行异常

```text
控制器继续产生/积累命令
↓
设备仍执行旧命令
↓
内部状态与现实分叉
↓
恢复后命令突跳
↓
PCC超调和反向修正
```

## 上行异常

```text
控制器使用陈旧PCC/Pmeas
↓
真实系统已经变化
↓
控制器继续错误调节
↓
恢复后反馈突变
↓
反向修正和超调
```

# 9. 当前研究缺口

蓝图V0.1暂定的真正缺口：

> 已有研究可以处理通信失效、HOLD、恢复重新启用，也可以利用逐DER实际功率和可用能力进行集中协调；但本项目关注的是中央控制器所认知的“已执行资源状态”在异常过程中与真实设备执行状态持续分叉后，恢复时如何显式重构控制器内部资源状态，并以受控方式重新进入PCC协调。

RECONSTRUCTION不能等价于：

```text
恢复通信
→ 收到最新Pmeas
→ 直接再算下一条命令
```

必须回答：

1. 哪个controller-side state失真；
2. 为什么失真；
3. 哪个device-side量作为权威现实；
4. 怎样重建控制器状态；
5. 怎样避免恢复第一拍突跳；
6. 怎样回到NORMAL。

# 12. 策略7：功能定义

原策略7本质上仍然只是 `Pt-P`。

Proposed策略7拟升级为：

> **联络线有功协调 + 异常/恢复状态管理。**

暂定四状态：

```text
NORMAL
↓
HOLD
↓
RECONSTRUCTION
↓
RECOVERY
↓
NORMAL
```

## NORMAL

正常形成有效总调节需求。

## HOLD

停止错误推进，保留必要的已确认状态。

HOLD本身不是创新，只是必要组件。

## RECONSTRUCTION

通信/反馈恢复后，利用：

```text
最新PCC
六路Pmeas
最后成功u_commit
提交状态
```

重新建立controller-side资源状态。

需要进一步明确究竟重构：

```text
六路内部历史命令？
积分器？
资源当前基准状态？
有效能力？
分配状态？
还是组合状态？
```

## RECOVERY

重构后不能直接全量接管，而要受控恢复：

```text
限制第一拍
限制变化率
渐进释放调节需求
↓
稳定后回NORMAL
```

具体形式暂不冻结。

# 13. 策略7为什么输出“有效总调节需求”

正常：

```text
Ptarget = -100 kW
Ppcc = -120 kW
裸误差 = +20 kW
```

但策略7以后不应永远把20 kW原样送给AGC。

不同状态下：

```text
NORMAL：
正常释放调节需求

HOLD：
不再继续错误释放新需求

RECONSTRUCTION：
先重建状态

RECOVERY：
按受控方式逐步释放需求
```

因此策略7的输出是：

> **经过状态管理后的有效总调节需求。**

# 15. SOC的位置

SOC不是第四套算法，也不是主创新。

当前定位：

```text
SOC
↓
ESS当前调节可持续性/偏好
↓
作为改进AGC内部辅助约束或权重
```

因此SOC不均衡更适合作为：

```text
辅助案例
消融
资源分配合理性验证
```

而不是与上下行中断恢复同等级的核心贡献工况。

> **这篇论文不是研究通信丢包本身，而是研究通信异常和设备动态造成控制器认知状态与真实执行状态分叉以后，如何利用逐设备真实执行信息重构控制器资源状态，再受控恢复PCC联络线协调，并把真实有效调节任务重新分配给2PV、2ESS和2EV；最终在同一外部控制板—Modbus—OP5700平台上，以V5基础C AGC为Baseline完成真实CHIL对比。**
