# 0. 新窗口首先要知道的结论

今天的多轮检索不是“为了找一个没人做过的创新点”，而是为了回答：

1. 我们已经初步确定的论文方向是否有充分的已有研究基础；
2. 现有研究具体已经把哪些问题做到什么程度；
3. 哪些技术不能再被我们简单包装成主要贡献；
4. 哪些成熟方法可以直接借鉴；
5. 现有研究明确没有覆盖哪些状态、场景和方法环节；
6. 第一篇论文的主体到底应该落在策略2、策略7、AGC还是通信/SOC；
7. 后续算法设计、V5硬件在环试验应该重点验证什么。

经过多轮检索，**论文整体方向没有被推翻，也没有改成通信论文或SOC论文，反而进一步收敛、变得更准确。**

当前第一篇论文主线应继续冻结为：

```text
策略2
PCC/AGC跟踪状态
+
逐设备真实执行状态/一致性评估
        ↓
策略7
PCC/联络线有功协调
+
NORMAL / HOLD / RECONSTRUCTION / RECOVERY
异常与恢复状态管理
        ↓
改进AGC
根据资源当前真实有效调节能力
在 2PV + 2ESS + 2EV 之间动态重分配任务
        ↓
外部控制板
↕ Modbus TCP
OP5700六逆变器实时对象
        ↓
最终CHIL验证
```

通信的定位：

> **通信不是独立研究对象，而是导致“控制器认知状态—成功提交状态—设备真实执行状态”分离的工程条件。**

SOC的定位：

> **SOC是辅助状态/约束/权重，不是第一篇论文主创新。**

# 1. 检索前的论文初步方向

## 1.1 项目对象

- 并网光储充微电网；
- 2×PV、2×ESS、2×EV，共六台功率单元；
- PCC / 联络线有功功率作为主要协调目标；
- 外部控制板运行AGC/协调算法；
- Modbus TCP双向通信；
- OPAL-RT OP5700实时电气对象；
- 最终采用Controller Hardware-in-the-Loop（CHIL）闭环验证。

## 1.2 原始基础AGC的主要不足

基础AGC主要依据：

- PCC功率误差；
- 固定资源优先级；
- 理论功率上限/下限；
- 理论剩余可调裕度；
- SOC硬边界。

但存在：

```text
控制器算出的命令
≠
真正成功下发的命令
≠
设备实际采用的状态
≠
设备最终真实Pmeas
```

通信异常期间尤其容易出现：

- 上行反馈陈旧；
- 下行命令未真正执行；
- AGC内部状态仍继续累计；
- 控制器认为设备已经变化，设备实际上保持旧状态；
- 通信恢复后累计命令突跳；
- PCC超调、反向修正；
- 不同资源之间发生无意义对冲。

## 1.3 15策略中第一篇重点对象

第一篇论文不研究全部15种策略。

当前重点：

- **策略2：PCC/AGC跟踪状态评估**
- **策略7：联络线有功协调**

策略4防逆流、策略6光伏平滑暂时仅保留为后续扩展候选。

# 2. 本次大规模检索的总体原则

## 2.1 不为了“证明没人做过”而检索

每轮检索都必须回答：

```text
已有文献具体做了什么？
↓
具体没有做什么？
↓
我们能够直接借鉴什么？
↓
哪些表述以后不能再作为主要贡献？
↓
对我们的策略2/策略7/AGC具体有什么影响？
↓
下一轮为什么还有必要继续查？
```

## 2.2 不无限扩大检索主题

明确避免把论文带向：

- 一般网络控制系统；
- 普通MPC；
- 事件触发控制；
- AoI；
- 5G；
- DoS/网络攻击；
- 一般虚拟电厂市场优化；
- 普通SOC均衡；
- 普通CHIL平台。

只有当这些主题能够直接帮助回答当前算法问题时才检索。

## 2.3 “已有机制”不等于“我们不能用”

这是本轮检索形成的非常重要的认识：

> 某一个技术零件已有研究，不代表我们在自己的场景里不能使用。

例如：anti-windup、bumpless transfer、packet-loss hold、SOC连续权重、performance-aware allocation、CHIL都已有研究，我们仍然可以采用这些成熟思想。

真正需要避免的是：

> 把成熟组件本身包装成唯一主要创新。

我们的价值必须落在：问题定义、多状态关系、策略2/7和AGC的重新组织、状态重构方法、异构资源重分配逻辑、双向通信中断与恢复过程、真实外部板CHIL综合验证。

# 3. 第一轮：网络控制中的执行端隐状态、packet loss、buffer state

## 3.1 检索目的

最初我们考虑“控制器命令≠设备实际执行”，因此必须先查清：网络控制领域是否已经研究发送命令与执行器实际输入不一致、执行器buffer状态估计、packet-loss状态估计，以及“判断命令有没有到”能否成为主要技术。

## 3.2 Quevedo et al., 2015

**A Stochastic Model Predictive Controller for Systems with Unreliable Communications**  
IFAC-PapersOnLine, 2015  
DOI: `10.1016/j.ifacol.2015.11.262`

### 做了什么

- 随机packet dropout；
- 预测输入序列；
- 执行器端buffer；
- 丢包后使用buffer预测输入；
- MPC显式考虑不可靠通信。

### 没有做什么

- 不是微电网PCC控制；
- 没有PV/ESS/EV异构资源；
- “实际输入”仍是执行器输入，不是设备真实Pmeas；
- 没有AGC资源状态和恢复重同步。

### 对我们的影响

不能再声称“首次考虑丢包导致命令不执行”“首次使用hold/buffer”。

## 3.3 Vargas, Cid, Maass, 2023

**Plant and Buffer State Estimation for Networked Predictive Control Over Multiple Erasure Channels**  
ISA Transactions, 2023  
DOI: `10.1016/j.isatra.2023.01.022`

### 做了什么

- MIMO网络化控制；
- 多个上/下行erasure channels；
- 估计plant state与actuator buffer state；
- 预测序列补偿下行丢失；
- 缺失测量估计；
- ACK辅助buffer状态重构；
- 明确区分设计输入与执行器实际施加输入。

### 没有做什么

- 没有微电网PCC控制；
- 没有资源功率分配；
- 没有PV/ESS/EV真实物理Pmeas；
- 没有AGC恢复重构。

### 对我们的影响

这是第一轮最重要的边界文献之一。它说明“controller command vs actuator applied input”已经是成熟问题。我们的“执行状态”必须继续向物理层推进：

```text
u_commit
↓
设备正常动态
↓
Pexpected
↕
Pmeas
```

## 3.4 Mohammadzadeh & Tavassoli, 2024

**Optimal Linear Filter Design for Process State and Packet Loss Estimation in Networked Control Systems**  
ISA Transactions, 2024  
DOI: `10.1016/j.isatra.2024.01.030`

### 做了什么

- packet-loss occurrence作为状态；
- Markov模型；
- plant state + 输入通道packet loss联合估计；
- zero/hold策略；
- 无可靠ACK也可根据对象行为推测actuation packet loss。

### 没有做什么

- 不涉及DER/PCC/AGC资源分配；
- 不处理六设备执行状态；
- 不处理长通信中断后的AGC重构。

### 对我们的影响

不能把论文做成“根据Pmeas判断包到底丢没丢”。

## 3.5 补充：System Identification in Presence of Undetectable Packet Losses in the Actuation Path

DOI: `10.1177/01423312231202667`

进一步证明actuation packet loss可从输入输出行为估计，甚至可同时辨识对象参数和通信模式，因此“识别哪一拍丢包”不应成为我们的主要任务。

## 3.6 第一轮最终结论

正式放弃把论文做成packet-loss detector、actuator buffer estimator或ACK-based execution detector。论文收敛到**设备真实物理执行状态**。

# 4. 第二轮：实时可调裕度、tracking error、response-aware allocation

## 4.1 Wang et al., Applied Energy, 2023

**A Hierarchical Dispatch Strategy of Hybrid Energy Storage System in Internet Data Center With Model Predictive Control**  
DOI: `10.1016/j.apenergy.2022.120414`

### 做了什么

- BESS+HFC混合储能；
- 动态available energy；
- 下层MPC根据系统dispatch tracking error和BESS SOC重新分配。

### 没有做什么

其tracking error是聚合调度误差，不是逐设备command-vs-actual response；没有单设备响应差后在线降权，也没有通信commit state。

### 对我们的影响

“SOC + 总体tracking error→重新分配”已经有人做，不能简单作为主技术。

## 4.2 Chen et al., EPSR, 2023

**Scheduled Power Tracking Control of the Virtual Power Plant for Its Internal Contingency Considering the Communication Delay and the Unit Capacity Limitation**  
DOI: `10.1016/j.epsr.2023.109402`

### 做了什么

- scheduled power tracking；
- VPP内部机组退出/负荷变化；
- 容量限制；
- communication delay；
- limiter；
- back-calculation anti-windup；
- reset过程。

### 没有做什么

- “实际可施加值”主要仍是限幅后的理论值；
- 不是设备真实Pmeas；
- 没有u_calc/u_commit/Pmeas三层状态；
- 没有双向长中断与恢复重构。

### 对我们的影响

策略7的anti-windup、back-calculation、reset设计的重要参考。

## 4.3 Chong et al., Applied Energy, 2025

**Coordination Optimization Within Large-Scale Virtual Power Plant for Frequency Stability Improvement Under Internal Power and External Frequency Fluctuations**  
DOI: `10.1016/j.apenergy.2025.125416`

### 做了什么

- real-time available headroom；
- droop rate；
- 动态资源参与比例；
- 内部功率偏差和外部频率偏差协调。

### 没有做什么

没有形成“last successful command→normal response→actual Pmeas→execution-quality correction”。

### 对我们的影响

“实时剩余裕度动态改参与比例”不是空白。

## 4.4 第二轮最终结论

已有研究已覆盖real-time headroom、SOC、aggregate tracking error、capacity saturation、anti-windup、动态参与比例。我们的AGC必须进一步关注**具体设备当前是否真实兑现调节任务**。

# 5. 第三轮：策略2/策略7与异构资源参考跟踪结构

## 5.1 Oshnoei et al., Applied Energy, 2022

**Coordinated Control Scheme for Provision of Frequency Regulation Service by Virtual Power Plants**  
DOI: `10.1016/j.apenergy.2022.119734`

### 做了什么

- BESS+HPWH VPP；
- 多区域LFC；
- ACE包含tie-line deviation和frequency；
- BESS快，优先承担；
- 能力不足时剩余任务转给HPWH；
- 考虑available regulation capacity、成本、通信延时；
- BEL协调；
- OPAL-RT OP5600实时验证。

### 没有做什么

- 主要基于预设响应速度/容量；
- 不基于当前具体设备真实执行质量重新分配；
- 无u_commit和长中断恢复。

### 对我们的影响

“总调节任务→异构资源分解”有充分研究基础；“快资源优先、剩余给慢资源”不能再作为新点。

## 5.2 Chang et al., IEEE Access, 2020

**Improved Feeder Flow Control Method for a Virtual Power Plant With Various Resources to Reduce Communication Dependency**  
DOI: `10.1109/ACCESS.2020.3035867`

### 做了什么

- feeder flow / 接口功率控制；
- ESS快速瞬态、MTG较慢稳态；
- 多类型资源；
- 降低通信依赖。

### 没有做什么

- 主要按已知动态分工；
- 无逐设备执行状态；
- 无中断恢复重同步。

### 对我们的影响

与策略7高度相关，但说明“按资源动态特性预先分工”已成熟。

## 5.3 Espinosa et al., IEEE TCST, 2021

**Reference-Tracking Control Policies for Packetized Coordination of Heterogeneous DER Populations**  
DOI: `10.1109/TCST.2020.3039492`

### 做了什么

- heterogeneous DER populations；
- reference tracking；
- QoS；
- 不同额定功率；
- 资源不可用时其他群体接替；
- 跟踪误差分析。

### 没有做什么

- 大规模packetized群体，不是六台连续功率逆变器；
- 无单设备u_commit→Pexpected→Pmeas；
- 无AGC恢复重构。

## 5.4 第三轮最终结论

策略2/7仍然适合第一篇，但要升级：

- 策略2：**PCC跟踪状态 + 逐设备执行一致性评估**；
- 策略7：**联络线有功协调 + 异常/恢复状态管理**。

# 6. 第四轮：实时AGC disaggregation与异构资源动态特性

## 6.1 Xiang et al., IEEE TPWRS, 2023

**Hierarchical AGC Dispatch With Detailed Modeling of Energy Storage System Behaviors**  
DOI: `10.1109/TPWRS.2022.3178432`

### 做了什么

- proactive + real-time AGC；
- ESS详细行为；
- SOC recovery；
- ramping；
- deadband；
- forced SOC recovery；
- 按available regulation reserve分配；
- ESS退化。

### 没有做什么

- 无通信诱发u_calc/u_commit/Pmeas失配；
- 无通信恢复重构。

## 6.2 Chen et al., Applied Energy, 2024

**Real-Time Operation Strategy of Virtual Power Plants With Optimal Power Disaggregation Among Heterogeneous Resources**  
DOI: `10.1016/j.apenergy.2024.122876`

### 做了什么

- 总调节信号实时拆分；
- heterogeneous resources；
- 时间耦合；
- 低成本优先；
- 毫秒级在线算法。

### 没有做什么

没有重点处理“设备实际没做到上一条命令→下一周期降低该具体设备真实执行能力”。

## 6.3 Zheng et al., Applied Energy, 2025

**A De-Aggregation Strategy Based Optimal Co-Scheduling of Heterogeneous Flexible Resources in Virtual Power Plant**  
DOI: `10.1016/j.apenergy.2025.125404`

### 做了什么

使用capacity、response rate、response time、regulation potential、cost等特征做feature matching和动态响应排序。

### 没有做什么

这些主要是模型/预定义特征，不是当前这一拍的真实执行结果。

### 对我们的影响

“考虑响应速度/响应时间动态调优先级”不能单独作为核心贡献。

## 6.4 Guo et al., Cyber-Physical Energy Systems, 2025

**Coordinated Power Control of Virtual Power Plant for Frequency Regulation Considering Cyber-Physical Uncertainties**  
DOI: `10.1016/j.cpes.2025.06.002`

### 做了什么

非常接近我们的整体架构：

```text
上层：RMPC + robust optimization做异构DER协调分配
下层：H∞-LQR做逆变器动态功率跟踪
同时：RES不确定性 + network delay
```

### 没有做什么

- 主要连续network delay；
- 无长时间packet interruption；
- 无u_calc/u_commit；
- 无恢复后的AGC state reconstruction；
- 无六路Pmeas执行状态重构；
- 主要仿真验证。

### 对我们的影响

“异构DER协调 + 逆变器动态 + 网络延时”已经能完整串联；我们的进一步价值必须落在**多状态失配与恢复重构**。

# 7. 第五轮：实际调节绩效是否已经进入AGC资源分配

## 7.1 Tan et al., IJEPES, 2025

**Capacity Scheduling Optimization and Regulation Power Allocation for Improving AGC Performance Considering Asymmetric Characteristics of New Regulation Resources**  
DOI: `10.1016/j.ijepes.2025.111265`

### 做了什么

- RES/ESS/DRR；
- asymmetric capability；
- response uncertainty；
- penalty cost；
- real-time adaptive AGC allocation；
- 响应不可靠资源少承担，更可靠资源多承担。

### 没有做什么

response uncertainty主要来源于统计/概率/历史参数，不是当前这一拍`u_commit→Pexpected→Pmeas`得到的实时执行状态。

### 对我们的影响

不能说“首次根据响应可靠性改变AGC分配”。真正值得做的是**当前实时执行状态重构**。

## 7.2 Doenges et al., IEEE TPWRS, 2020

**Improving AGC Performance in Power Systems With Regulation Response Accuracy Margins Using Battery Energy Storage System (BESS)**  
DOI: `10.1109/TPWRS.2019.2960450`

### 做了什么

定义slowest/fastest permitted response，即AGC正常动态响应允许区间；BESS在系统响应接近/超过允许边界时补偿。

### 对我们的最大启发

以后策略2不能粗暴判断：

```text
Pcommand != Pmeas
→ 执行异常
```

应该允许正常设备动态：

```text
u_commit
↓
normal response model / tolerance band
↓
Pexpected
↕
Pmeas
```

### 没有做什么

- 主要是系统级响应；
- 无六台逐设备执行状态；
- 无通信恢复。

## 7.3 Huang et al., IEEE TSG, 2025

**Performance-Integrated Virtual Power Plant Management in the Frequency Regulation Market**  
DOI: `10.1109/TSG.2025.3605202`

### 做了什么

- accuracy/correlation/delay形成调频performance；
- performance映射到DER reserve portfolio；
- 参与aggregation/disaggregation。

### 没有做什么

主要是市场/小时级reserve portfolio和数据驱动performance mapping，不是当前具体设备实时物理执行状态。

## 7.4 第五轮最终结论

不能把`w_exec`简单做成响应速度、历史准确率、统计不确定性或裸`command-Pmeas`误差。更有技术意义的是：

```text
last successful u_commit
↓
normal expected response / tolerance band
↓
current Pmeas
↓
current execution-consistency state
↓
AGC resource-state correction
↓
task reallocation
```

# 8. 第六轮：通信异常期间状态保持、恢复与bumpless / anti-windup

## 8.1 Guo et al., IEEE TSG, 2025

**Multiagent System-Based VPPs Cooperative Power Control for Frequency Regulation Considering Diverse Communication Issues**  
DOI: `10.1109/TSG.2025.3557436`

### 做了什么

- 上行packet loss：保持上一状态；
- 下行packet loss：保持上一控制输入；
- inverter层IMPC；
- 同时涉及cyberattack/privacy/event-triggered。

### 没有做什么

没有长时间中断后AGC内部状态重构，没有u_calc/u_commit/Pmeas多状态，重点仍是packet loss存在时继续稳定跟踪。

## 8.2 Guo et al., IEEE TPWRS, 2025

**Cyber-Physical Integration Design for Frequency Regulation in Virtual Power Plants Facing Diverse Communication Issues**  
DOI: `10.1109/TPWRS.2025.3585511`

### 做了什么

- VPP dispatch；
- packet loss；
- communication resource allocation；
- cyber attack；
- 尽量通过通信资源优化降低packet loss影响。

### 对我们的影响

我们的路线不同：异常已经真实发生以后，算法如何避免状态失真、恢复后如何重新同步。

## 8.3 Das et al., IEEE TSG, 2018

**Linear Quadratic Regulator-Based Bumpless Transfer in Microgrids**  
DOI: `10.1109/TSG.2016.2580159`

### 做了什么

并网/孤岛控制器切换时，先减小两个控制器输出差，避免硬切换冲击。

### 可借鉴核心

不一定采用LQR，真正有用的是：

> **先让即将接管的控制器状态/输出贴近当前真实运行状态，再完成接管。**

### 对策略7的启发

```text
状态重构
→ 状态/输出对齐
→ 渐进接管
```

而不是“通信恢复→旧AGC直接继续”。

# 9. 第七轮：整篇论文场景级碰撞与CHIL

## 9.1 Callegari et al., IEEE OJIES, 2025

**Centralized Strategies for Grid-Connected Microgrids Integrating Multicontrol Actions to Enhance the Dynamic Response**  
DOI: `10.1109/OJIES.2025.3541880`

### 为什么极其重要

- grid-connected microgrid；
- PCC P/Q dispatchability；
- centralized controller；
- feedback/feedforward/disturbance decoupling；
- bidirectional communication；
- 实验室原型。

### 通信故障机制

```text
通信暂时中断
→ DER继续使用last received data

CC收不到数据
→ reset feedback controller
→ reset communication registers
→ retransmit previous power coefficient

通信恢复
→ anti-windup积分项逐渐重新接入
```

### 这意味着

“通信异常防windup”“last command保持”“恢复后积分渐进投入”均不能单独作为我们的核心新点。

### 它没有做什么

- 无u_calc/u_commit显式区分；
- 无六设备逐个Pmeas执行状态；
- 无Pexpected；
- 无2PV+2ESS+2EV异构再分配；
- 无上/下行故障分别构造状态；
- 无基于真实资源状态重构AGC。

## 9.2 Chaves et al., IEEE Access, 2025

**Impact of Latency and Packet Error on Communication in Centralized Microgrid Control: Modeling and Guidelines**  
DOI: `10.1109/ACCESS.2025.3567911`

### 做了什么

- centralized microgrid；
- PCC power control；
- six DERs；
- bidirectional communication；
- latency、packet error、packet loss、communication failure；
- Raspberry Pi中央控制器；
- Typhoon HIL/CHIL。

### 研究重点

通信参数和控制参数应配置到什么范围，才能确保PCC集中控制稳定与满足性能。failure时退回primary autonomous mode，保持稳定但失去PCC power-flow controllability。

### 没有做什么

- 不在failure后维持上层AGC协调；
- 无真实执行状态重构；
- 无AGC内部状态重同步；
- packet loss/failure主要作为latency/stability问题处理。

## 9.3 Valibeygi et al., IEEE ISGT, 2018

**Microgrid Control Using Remote Controller Hardware-in-the-Loop Over the Internet**  
DOI: `10.1109/ISGT.2018.8403345`

### 做了什么

```text
外部真实controller
↕ Internet
RTDS real-time microgrid

PMU → controller：C37.118
controller ↔ inverter：Modbus TCP/IP
```

控制PCC P/Q和BESS SOC。

### 极有价值的一点

通过阶跃试验辨识：

```text
inverter power input
→ PCC power response
```

得到离散动态模型。

### 对我们的启发

支持后续做更贴近本项目的：

```text
Pref_i / u_commit_i
→ Pmeas_i
```

正常动态辨识。

### 场景级轮次结论

没有发现一篇论文把以下整条链全部做完：

```text
2PV + 2ESS + 2EV
+ PCC/tie-line active power control
+ 集中式AGC资源分配
+ Ppcc_real/Ppcc_rx
+ u_calc/u_commit
+ Pexpected/Pmeas
+ 逐设备当前执行状态
+ 上/下行/双向连续中断
+ AGC资源状态重构
+ 平滑重新接管
+ 外部板Modbus TCP OP5700 CHIL
```

但其中许多单独技术已有成熟工作，所以我们的论文不能写成“已有机制堆叠”，而必须形成统一问题与统一方法。

# 12. 检索后对论文方向的最终修正

## 12.1 没有改变的主体

```text
对象：2PV + 2ESS + 2EV并网光储充微电网
任务：PCC / 联络线有功协调
核心：策略2 + 策略7 + 改进AGC
验证：外部控制板 + Modbus TCP + OP5700 CHIL
```

## 12.2 SOC进一步弱化

检索前概念性考虑过：

```text
R_eff = R_phys × w_SOC × w_exec
```

检索后必须强调：这只是概念结构，不能提前冻结成唯一最终公式。SOC可表现为连续权重、充放电方向权重、剩余能力修正、硬约束或轻微优先级修正，但不占主体。

## 12.3 策略2进一步强化

从普通“AGC tracking KPI”升级为：

> **PCC跟踪与逐设备资源执行状态评估。**

未来可能：

```text
u_commit,i
↓
normal expected response
↓
Pexpected,i
↕
Pmeas,i
↓
execution residual / consistency / confidence
```

具体公式仍未冻结。

## 12.4 策略7进一步强化

从简单`dP=Ptarget-Ppcc`升级为：

```text
NORMAL
↓
HOLD
↓
RECONSTRUCTION
↓
RECOVERY
↓
NORMAL
```

上行异常：PCC/Pmeas stale，不应继续用陈旧误差推进AGC。  
下行异常：candidate未成功commit，不能把它当成设备已执行。  
恢复：latest PCC + six Pmeas + last u_commit → reconstruct resource state → resynchronize AGC → align first recovery output → gradual takeover。

# 13. 后续论文需要明确区分的状态

```text
Ppcc_real  真实PCC
Ppcc_rx    控制器收到的PCC
u_calc     当前内部计算命令
u_commit   最后成功提交命令
u_act      执行侧实际采用输入
Pexpected  正常设备动态下预期物理功率
Pmeas      设备真实有功功率
x_AGC      AGC内部资源/历史状态
```

真正的问题是：

```text
Ppcc_rx ≠ Ppcc_real
u_calc ≠ u_commit
u_commit → Pexpected
Pexpected ≠ Pmeas
最终 x_AGC ≠ 当前真实资源状态
```
