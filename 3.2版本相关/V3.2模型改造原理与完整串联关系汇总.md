# V3.2 模型改造原理与完整串联关系汇总

## 一、整体结论：这次改造究竟做了什么

V3.1 已经解决：

```text
寄存器地址是否正确
数据类型是否正确
缩放是否正确
正负数和补码是否正确
板子能否读、能否写
```

V3.2 在此基础上增加的是一层**通信状态、数据新鲜度和外部命令安全管理机制**。

它要解决的问题不是"功率命令是多少"，而是：

```text
RT-LAB现在是否正常运行？
测量数据是否仍在刷新？
板子程序是否仍在运行？
板子是否明确声明命令有效？
通信断开后旧的使能值会不会被继续使用？
最终是否允许采用板子命令？
```

因此，V3.2 形成了两条双向状态链路和一条 RT-LAB 本地安全判断链路：

```text
RT-LAB → 板子：
40115 MODEL_STATUS
40116 RTLAB_HEARTBEAT

板子 → RT-LAB：
40010 EXT_AGC_ENABLE
40011 CMD_SEQ
40012 BOARD_HEARTBEAT

RT-LAB本地判断：
EXT_AGC_ENABLE
AND
BOARD_HEARTBEAT有效
→ EXTERNAL_COMMAND_VALID
```

板子接入后的总体架构本质是：基础有功 AGC 最终迁移到板子，电气对象、测量和设备本地控制仍留在 RT-LAB。

## 二、Model、I/O Interfaces、Configuration 和 SC 显示的职责

这四部分必须严格区分。

### 1. Simulink Model

负责模型内部怎样计算、状态怎样生成、心跳怎样判断、最终有效信号怎样形成。

例如：

```text
RTLAB_HEARTBEAT如何每秒增加
BOARD_HB_OK如何根据超时时间判断
EXTERNAL_COMMAND_VALID如何由两个条件相与得到
```

### 2. I/O Interfaces

负责定义 OP5700 向外提供哪些 Modbus 寄存器，包括：

```text
寄存器名称
offset
数据类型
初始值
由Master控制还是Model控制
```

当前：

```text
40010～40012：Control from = Master
40115～40116：Control from = Model
```

### 3. Configuration

负责把外部寄存器和模型内部的 OpInput、OpOutput 接起来。没有 Configuration 时，寄存器存在，模型信号也存在，但两者互不相通。

Configuration 相当于"内部接线表"。

### 4. sc_display 和 OpComm

只负责把 `sm_circuit` 中的运行状态送到上位机显示。它不负责 Modbus 通信，也不负责安全判断。

```text
sm_circuit计算状态
→ Mux打包
→ Outport
→ sc_display Inport
→ OpComm
→ Demux拆分
→ Display显示
```

## 三、40010～40012 为什么新增为三个 OpInput

新增的三个信号是：

| 地址   | 名称                    | 方向        |
| ------ | ----------------------- | ----------- |
| 40010  | `EXT_AGC_ENABLE_raw`    | 板子→RT-LAB |
| 40011  | `CMD_SEQ_raw`           | 板子→RT-LAB |
| 40012  | `BOARD_HEARTBEAT_raw`   | 板子→RT-LAB |

因为数据从外部板子进入模型，所以使用 `OpInput`。

完整路径是：

```text
板子FC16写40010～40012
→ OP5700 Modbus Slave寄存器
→ Configuration
→ sm_circuit中的三个OpInput
```

### 1. EXT_AGC_ENABLE_raw

表示板子认为当前外部命令是否有效。

取值：

```text
0：不得采用板子命令
1：板子认为通信、状态和测量条件满足
```

但 RT-LAB 不能只相信这个值，因为断线后它可能停留在旧值 1。

### 2. CMD_SEQ_raw

表示控制命令的批次号。每成功发布一组新命令，`CMD_SEQ` 增加 1。

即使功率值没有变化，成功发布新一轮命令后也应增加。

它用于区分这是新的命令批次，还是以前遗留的旧命令。

当前 V3.2 中主要用于显示和验收，尚未作为 RT-LAB 本地有效性的强制条件。

### 3. BOARD_HEARTBEAT_raw

表示板子主通信程序是否仍在运行。

板子每个通信周期使其增加：`0 → 1 → 2 → … → 65535 → 0`。

RT-LAB 判断的不是具体数值，而是它是否持续变化。

---

## 四、为什么 40010～40012 单独使用一个 3 路 Mux

原 40001～40009 继续组成 `modbus_raw_vec_to_sc`，新增 40010～40012 组成 `modbus_management_raw_vec`。

这样分开的原因是：

### 1. 不破坏 V3.1

原 9 路仍然独立保留，用于检查功率命令、AGC_STATUS、dP、remain、补码和缩放。

### 2. 区分业务命令和管理量

```text
40001～40009：功率命令和AGC结果
40010～40012：使能、序号、心跳
```

语义不同，不应混在同一组显示中。

### 3. 方便 SC 分区显示

最终可以分别观察 V3.1 命令区和 V3.2 管理区。

Mux 只是打包 `[EXT_AGC_ENABLE, CMD_SEQ, BOARD_HEARTBEAT]`，没有相加，也没有计算。

## 五、40115 MODEL_STATUS 的完整原理

### 1. MODEL_STATUS_MODE

这是一个模式选择 Constant。

当前：

```text
0：正常状态
1：未准备状态
2：模型故障状态
```

它不是最终发送给板子的状态值，而是告诉 Multiport Switch 选择哪一路。

### 2. 三个 Constant：7、1、23

**7：正常状态**

```text
7 = bit0 + bit1 + bit2
```

表示：

```text
MODEL_RUNNING = 1
MEAS_VALID = 1
EXT_INTERFACE_READY = 1
MODEL_FAULT = 0
```

**1：未准备状态**

表示模型运行，但测量或外部接口未准备。

**23：模型故障**

```text
23 = 1 + 2 + 4 + 16
```

即运行、测量、接口就绪，但 `MODEL_FAULT=1`。故障位优先，因此板子仍必须判定不可用。

### 3. Multiport Switch

其作用是：

```text
MODEL_STATUS_MODE=0 → 选择7
MODEL_STATUS_MODE=1 → 选择1
MODEL_STATUS_MODE=2 → 选择23
```

输出 `MODEL_STATUS_raw`。

### 4. MODEL_STATUS_raw 和 OpOutput

`raw` 表示它是直接写入 Modbus 寄存器的原始状态字，不需要缩放。

路径为：

```text
Multiport Switch
→ MODEL_STATUS_raw
→ OpOutput
→ Configuration
→ 40115
→ 板子FC03读取
```

## 六、40116 RTLAB_HEARTBEAT 的完整原理

### 1. Simulation_Time

Clock 模块输出当前仿真时间。

例如：`0, 0.00005, 0.00010, ..., 1.00000`。

使用仿真时间，是为了避免按照几十微秒仿真步长高速计数。

### 2. RTLAB_HB_FREEZE

测试开关：

```text
0：心跳正常变化
1：冻结在当前值
```

它的目的只是制造故障测试条件。

### 3. RTLAB_Heartbeat_Generator

MATLAB Function 完成：

```text
仿真时间
→ floor(time_s)
→ 每秒增加1
→ mod 65536
→ uint16输出
```

结果是：

```text
0～1秒：0
1～2秒：1
2～3秒：2
……
65535后回0
```

冻结时，它锁存当前值并持续输出。

### 4. 完整路径

```text
Simulation_Time
+ RTLAB_HB_FREEZE
→ RTLAB_Heartbeat_Generator
→ RTLAB_HEARTBEAT_raw
→ OpOutput
→ Configuration
→ 40116
→ 板子读取
```

40116 证明的是 **RT-LAB 模型和数据仍在持续刷新**。

## 七、为什么必须设置双向心跳

只有一个方向的心跳不够。

### 1. RTLAB_HEARTBEAT

RT-LAB → 板子，板子用它判断 RT-LAB 是否仍在运行。

### 2. BOARD_HEARTBEAT

板子 → RT-LAB，RT-LAB 用它判断板子是否仍在运行。

这样双方都能独立发现对方停止更新。

---

## 八、Board_Heartbeat_Monitor 的完整原理

输入：

```text
time_s
board_hb_raw
timeout_s
```

输出：

```text
hb_ok
hb_age_s
```

### 1. Board_HB_Time

Clock 模块，提供当前仿真时间，用于计算当前时间与板子心跳最后变化时间之差。

### 2. board_hb_raw

来自 40012 的 OpInput。

路径：

```text
板子写40012
→ Modbus Slave
→ Configuration
→ BOARD_HEARTBEAT_raw OpInput
→ Board_Heartbeat_Monitor
```

### 3. BOARD_HB_TIMEOUT_S = 3.5

允许板子心跳最多 3.5 秒不变化。

因为板子通信周期是 1 秒，3.5 秒可以容忍少量抖动，但能及时识别真正中断。

### 4. last_hb

内部保存上一次心跳值。

```text
上次100，本次101 → 说明心跳更新
```

### 5. last_change_t

保存最后一次观察到心跳变化的时间。

### 6. change_seen

第一次读取只保存初值，不能立即判定心跳正常。原因是寄存器初始值 0 并不能证明板子程序已经运行。必须至少观察到一次变化。

### 7. hb_age_s

含义：距板子心跳最后一次变化已经过去多少秒。

### 8. hb_ok

判据：

```text
至少观察到过一次变化
AND
hb_age_s ≤ 3.5
```

因此：

```text
板子正常更新 → hb_ok=1
板子尚未运行 → hb_ok=0
板子停止超过3.5秒 → hb_ok=0
```

---

## 九、Check_EXT_AGC_ENABLE 模块

这是一个 `Compare To Constant` 模块，设置为 `== 1`。

输入：`EXT_AGC_ENABLE_raw`。

输出：

```text
true：40010等于1
false：40010不等于1
```

它把 UINT16 寄存器值转换为逻辑判断结果。

它回答的是：**板子是否明确声明当前命令有效？**

---

## 十、External_Command_Valid_Logic 模块

这是一个 AND 模块。

输入：

```text
EXT_AGC_ENABLE_raw == 1
BOARD_HB_OK == 1
```

输出：`EXTERNAL_COMMAND_VALID`。

关系为：

```text
EXTERNAL_COMMAND_VALID
=
EXT_AGC_ENABLE有效
AND
板子心跳有效
```

### 为什么必须相与

假设 40010 已经被写成 1，随后通信断开。由于板子无法继续写寄存器，40010 可能一直保持旧值 1。

如果 RT-LAB 只看 40010，就可能继续使用失效命令。

加入板子心跳判断以后：

```text
40010旧值仍为1
但40012停止变化
→ hb_ok=0
→ EXTERNAL_COMMAND_VALID=0
```

这就是 RT-LAB 侧的独立安全保护。

## 十一、Data Type Conversion 模块

五路信号原始类型不同：

| 信号                     | 原类型     |
| ------------------------ | ---------- |
| MODEL_STATUS             | UINT16     |
| RTLAB_HEARTBEAT          | UINT16     |
| BOARD_HB_OK              | Boolean    |
| BOARD_HB_AGE_S           | double     |
| EXTERNAL_COMMAND_VALID   | Boolean    |

进入 Mux 和 OpComm 前统一转换为 `double`。

例如：

```text
uint16(7) → double(7)
true → double(1)
false → double(0)
```

它只改变存储类型，不改变信号含义。

需要注意：写 Modbus 寄存器时保持 UINT16，送 SC 显示时转换为 double。

---

## 十二、Goto 和 From 标签的作用

40115 和 40116 生成区域与状态 Mux 区域距离较远。

为了避免长距离交叉连线，使用：

```text
Goto：发送内部标签
From：在另一个位置取出同一信号
```

例如 `MODEL_STATUS_raw` → Goto 标签 → From 标签 → 状态 Mux。

Goto/From 只属于 Simulink 内部信号路由，不是 Modbus 通信。

## 十三、为什么把五路状态合并后送出

五路分别是：

| #   | 信号                    |
| --- | ----------------------- |
| 1   | MODEL_STATUS            |
| 2   | RTLAB_HEARTBEAT         |
| 3   | BOARD_HB_OK             |
| 4   | BOARD_HB_AGE_S          |
| 5   | EXTERNAL_COMMAND_VALID  |

它们共同组成 V3.2 安全状态的完整仪表盘。

### 1. MODEL_STATUS

回答：RT-LAB 模型是否准备好？

### 2. RTLAB_HEARTBEAT

回答：RT-LAB 是否仍在持续运行和刷新数据？

### 3. BOARD_HB_OK

回答：RT-LAB 是否认为板子程序仍在运行？

### 4. BOARD_HB_AGE_S

回答：板子心跳多久没有变化？是否正在接近 3.5 秒超时？

### 5. EXTERNAL_COMMAND_VALID

回答：当前板子命令最终是否具备安全使用资格？

## 十四、为什么使用 Mux，而不是五根线分别送出

如果不使用 Mux，需要：

```text
5个sm_circuit Outport
5个sc_display Inport
多组顶层连线
可能需要更多OpComm
```

使用 Mux 后：

```text
5路标量
→ 一个5维向量
→ 一个Outport
→ 一个Inport
→ 一个OpComm
→ Demux恢复成5路
```

优点：

- 端口更少
- 连线更清晰
- 采集组更少
- 五个状态同步刷新
- 不容易接错

Mux 没有把数值相加。例如 `[7, 105, 1, 0.4, 1]` 仍然是五个独立元素。

```text
v32：V3.2版本
rtlab_status：RT-LAB侧状态
vec：vector，向量
```

它表示 **V3.2 RT-LAB 安全状态向量**。

```text
五路状态
→ Data Type Conversion
```

它只送到 SC 显示，不发送给板子。

包含：

```text
EXT_AGC_ENABLE
```

来源：RT-LAB 自身状态 + RT-LAB 本地判断结果。

## 十七、完整运行场景

### 场景一：板子程序未运行

```text
MODEL_STATUS = 7
RTLAB_HEARTBEAT持续增加
BOARD_HEARTBEAT不变化
BOARD_HB_OK = 0
EXTERNAL_COMMAND_VALID = 0
```

说明：RT-LAB 正常，但没有检测到板子。

### 场景二：板子运行，但仍处于 WAIT_VALID

```text
BOARD_HEARTBEAT持续变化
BOARD_HB_OK = 1
EXT_AGC_ENABLE = 0
EXTERNAL_COMMAND_VALID = 0
```

说明：板子活着，但尚未确认命令有效。

### 场景三：正常进入 ENABLED

```text
EXT_AGC_ENABLE = 1
BOARD_HB_OK = 1
EXTERNAL_COMMAND_VALID = 1
```

说明：板子声明有效，RT-LAB 也确认板子存活，外部命令具备使用资格。

### 场景四：板子断线

```text
EXT_AGC_ENABLE可能仍保持旧值1
BOARD_HEARTBEAT停止变化
BOARD_HB_AGE_S持续增加
超过3.5秒后BOARD_HB_OK=0
EXTERNAL_COMMAND_VALID=0
```

这就是 V3.2 最重要的安全作用。

## 十八、最终统一理解

整个新增模块可以压缩为以下逻辑：

```text
RT-LAB通过40115和40116告诉板子：
"我的模型准备好了，而且我的数据还在更新。"

板子通过40010、40011、40012告诉RT-LAB：
"我的程序还活着，而且我认为命令有效。"

RT-LAB不能只相信40010，
还要独立检查40012是否持续变化。

最终：
EXT_AGC_ENABLE=1
AND
BOARD_HB_OK=1
→ EXTERNAL_COMMAND_VALID=1
```

五路状态合并送到 SC，是为了让操作人员同时看到：

```text
RT-LAB是否正常
板子是否正常
心跳是否接近超时
最终命令是否有效
```

它们组成了 V3.2 通信安全机制的完整监视面板。
