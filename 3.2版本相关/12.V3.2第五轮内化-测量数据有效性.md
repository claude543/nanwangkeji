# V3.2 第五轮内化：测量数据有效性、核心点分级，以及为什么输入越界不能限幅后继续使用

> 课题：AGC算法内化理解 · 2026暑期项目南网科技
> 整理日期：2026-07-20
> 本轮主题：第三层判断 —— 测量数据有效性 + 核心/辅助点分级机制

---

## 前情提要（三层判断体系）

前几轮已经建立了三层判断：

| 层级 | 关注点 |
|------|--------|
| 第一层 | Modbus是否连接、读写是否成功 |
| 第二层 | RT-LAB模型状态和心跳是否正常 |
| **第三层（本轮）** | 读取到的具体测量数值是否合理 |

**核心问题**：即使FC03读取成功、40115状态正常、40116心跳持续变化，40101～40114中的测量值仍可能错误，板子不能直接使用。

因此，V3.2增加了 `read_points` 测量有效性检查，并将测量点分成"**核心点**"和"**辅助点**"。**任一强制检查的核心点越界，都要立即撤销 40010、清零 `valid_count`，但保持通信程序继续运行。**

---

## 一、为什么"通信读取成功"不等于"测量数据正确"

假设板子发出 FC03，OP5700 正常返回 16 个寄存器。

**从通信层看：**
- TCP连接正常
- 功能码正常
- 返回数量正常
- 报文结构正常

**但返回的数据可能是：**
- `ESS1_SOC = 1.20`
- `PV1_P_MAX = 500 kW`
- `PCC_P = -2500 kW`

这些数值虽然成功传输了，但**不符合当前系统的物理范围**。

**核心结论：**
> 报文完整 ≠ 数据语义合理

### 故事类比

现场向调度员发送了一份完整报表。报表没有缺页，字迹也清楚：
- 储能 SOC：120%
- 光伏最大功率：500 kW

**"报表完整"只能证明通信正常**。调度员不能因为表格格式正确，就相信电池真的有120%电量，或100 kW光伏真的能发500 kW。

所以在报表进入控制算法之前，还要进行一次**合理性审核**。这就是 V3.2 的测量有效性检查。

---

## 二、V3.1 输出限幅与 V3.2 输入判断必须严格区分

> ⚠️ **本轮最重要的概念**

### 1. V3.1 处理的是板子准备发出的控制命令

例如板子产生：`PV1命令 = 1.20 p.u.`

PV 允许范围：`0～1 p.u.`

程序可以将其限制成：`1.00 p.u.`，然后继续发送。

这叫：**输出限幅 `write_points.min/max`**

### 2. V3.2 处理的是板子从 RT-LAB 读取的测量数据

例如板子读取：`ESS1_SOC = 1.20`

**不能**把它修改成 `ESS1_SOC = 1.00` 再交给算法使用。

因为板子不知道 1.20 是怎么产生的，可能原因包括：
- 寄存器地址映射错误
- UINT16/INT16 类型设置错误
- 缩放比例错误
- 模型信号接错
- 模型尚未初始化
- 数据损坏

**如果强行限幅为 1.00，等于把一个异常数据"伪装成正常数据"。**

正确处理是：
```
measurements_valid = false
40010 = 0
valid_count = 0
状态进入或保持 WAIT_VALID
```

## 三、为什么输出可以限幅，输入却不能修正

可以用"**命令**"和"**报告**"的区别理解。

### 控制命令

板子说：**"请让光伏输出 1.2 p.u."**

设备最大只能输出 1.0 p.u.，因此板子可以把自己的要求改成 1.0 p.u.。这是对自身控制意图进行**安全修正**。

### 测量报告

RT-LAB 说：**"当前电池 SOC 为 1.20。"**

板子不能擅自解释成"你大概想表达 1.00，我替你改一下"。

因为测量值是对实际状态的描述。**测量异常时，正确做法是停止使用并查找原因，而不是修改报告。**

> ✅ **核心原则：命令越界时可以安全约束；测量越界时必须判为不可信。**

---

## 四、测量有效性检查在通信周期中的位置

每个 1000 ms 通信周期，正确顺序应当是：

```
FC03 读取 40101～40116
        ↓
检查响应格式和寄存器数量
        ↓
按照 INT16/UINT16 解释原始值
        ↓
乘以 scale 恢复工程量
        ↓
对 range_check=true 的点检查范围
        ↓
汇总 measurements_valid
        ↓
结合 MODEL_STATUS、心跳等条件更新状态机
        ↓
准备 40010～40012
        ↓
FC16 写 40001～40012
```

> ⚠️ **范围检查必须发生在"完成类型解释和缩放之后"**，因为 `valid_min` 和 `valid_max` 是**工程量范围**，不是原始寄存器范围。

### 例子：ESS1_SOC 解码与判断

| 步骤 | 值 |
|------|-----|
| 原始寄存器 | 12000 |
| 类型 | UINT16 |
| 缩放 | 0.0001 |
| 解码 | 12000 × 0.0001 = **1.20** |
| 允许范围 | 0～1 |
| 实际值 | 1.20 |
| 结果 | **越界，measurements_valid = false** |

**不能直接拿原始值 12000 和 0～1 比较。**

## 五、点级开关与全局开关

### 点级配置

每个读取点支持：
```json
{
  "range_check": true,
  "valid_min": 0.0,
  "valid_max": 1.0
}
```

### 全局开关

```json
"range_check_enable": true
```

可以理解为**两层开关**：

| 开关层级 | 配置 | 含义 |
|---------|------|------|
| 全局开关 | `range_check_enable = true` | 启用整个输入有效性检查机制 |
| 点级开关 | `range_check = true` | 这个具体测量点参与有效性汇总 |

**通常需要同时满足：全局检查开启 且 本点 `range_check = true`，才真正执行强制范围判断。**

### 为什么要有全局开关？

主要用于：
- 初始调试
- 临时定位问题
- 判断异常是否由范围检查触发

但**正式 V3.2 联调和验收时应保持 `range_check_enable = true`**，否则五个核心点即使出现错误，也可能无法阻止 40010 投入，**失去 V3.2 数据安全管理的意义**。

---

## 六、为什么使用 valid_min/valid_max，而不继续使用 min/max

这是为了**避免混淆两种完全不同的处理**。

| 字段 | 含义 | 越界后处理 |
|------|------|-----------|
| `write_points.min/max` | 板子输出命令的允许边界 | 限幅并继续发送 |
| `read_points.valid_min/valid_max` | 输入测量的可信范围 | 判为无效，不继续作为有效数据使用 |

**命名不同，就是提醒工程师：一个用于修正命令，一个用于否定测量，处理结果完全不同。**

---

## 七、为什么只把五个点设为核心输入

V3.2 第一阶段默认强制检查：

| 寄存器 | 名称 | 作用 |
|--------|------|------|
| 40101 | PCC_P | 计算功率偏差 |
| 40105 | PV1_P_MAX | 限制光伏可调上限 |
| 40106 | PV2_P_MAX | 限制光伏可调上限 |
| 40107 | ESS1_SOC | 判断储能充放电方向 |
| 40108 | ESS2_SOC | 判断储能充放电方向 |

**基础控制关系**：
```
PCC_P        → 计算功率偏差
PV1/2_P_MAX  → 限制光伏可调上限
ESS1/2_SOC   → 判断储能充放电方向是否允许
```

其中**任意一点错误**，都可能直接造成控制方向、控制量或资源能力判断错误。所以默认 `range_check: true`。

---

## 八、五个核心点逐项为什么必须检查

### 1. 40101 PCC_P

**暂定有效范围：-1000～1000 kW**

如果读取 `PCC_P = 2500 kW`，可能表示：
- 缩放错误
- 类型错误
- 模型信号异常
- 测点接错

而基础 AGC 使用它计算：
$$dP = P_{target} - P_{PCC}$$

一旦 PCC_P 错误，AGC 可能立即产生方向和幅值都错误的指令。**所以必须撤销外部控制资格。**

### 2. 40105、40106 PV 最大可用出力

**暂定有效范围：0～100 kW**

需要注意：
- `PV_P_MAX = 0 kW` ✅ **是合法的**（可能代表夜间或光照完全不足）
- `PV_P_MAX = -10 kW` ❌ 不合理
- `PV_P_MAX = 500 kW` ❌ 不合理

### 3. 40107、40108 储能 SOC

**有效范围：0～1 p.u.**

边界值：
- `SOC = 0` ✅ 有效
- `SOC = 1` ✅ 有效

## 九、SOC 测量有效范围与 AGC 运行范围不是一回事

假设 AGC 设置：
- `SOC_min = 0.2`
- `SOC_max = 0.9`

现在读取 `SOC = 0.10`。V3.2 应该怎样处理？

**答案是：测量有效**。因为 0.10 仍在物理范围 0～1 内。

随后 AGC 根据 SOC 下限判断：**禁止继续放电**。

因此：

| 范围 | 作用 |
|------|------|
| **0～1** | 判断数据是否**物理可信** |
| **0.2～0.9** | 判断储能**允许怎样运行** |

**不能把两者混合。**

如果把有效范围直接设成 0.2～0.9，那么储能真实下降到 0.15 时，系统会**误认为通信数据损坏**，而不是正常执行低 SOC 保护。

---

## 十、为什么辅助点暂时不参与 40010 判断

V3.2 第一阶段辅助点包括：
- 40102 PCC_Q
- 40103 PCC_V
- 40104 PCC_F
- 40109～40114 六台设备实际功率

这些点仍然：
- ✅ 正常读取
- ✅ 正常解码
- ✅ 可以打印和记录
- ✅ 保留 valid_min/valid_max 配置

**但默认** `range_check: false`，因此：
- ❌ 不参与 `measurements_valid`
- ❌ 不影响 40010

### 原因一：当前基础 AGC 不直接使用它们

当前有功 AGC 不使用 PCC_Q、PCC_V、PCC_F、六台设备实际功率。即使其中某个辅助量暂时没有正确接入，也不应阻止当前基础 AGC 的通信接口验证。

### 原因二：部分语义还需要确认

例如 40103 PCC_V 仍需要确认：
- 线电压还是相电压
- 有效值还是其他计算值
- 测量位置
- 模型启动阶段是否短时为 0

如果语义尚未完全冻结，却立即设置为强制检查，可能出现：
- 电压信号实际正常
- 但由于单位理解错误而持续判越界

最终导致 40010 永远无法投入。

### 原因三：便于分阶段排错

如果 14 个测量点同时作为强制条件，只要一个辅助点未接好，整个状态机就无法进入 ENABLED。你将很难判断问题来自：
- 核心 AGC 输入
- 辅助显示量
- 符号定义
- 缩放配置
- 真实模型接线

**因此 V3.2 采用分级方式：先保证当前控制真正需要的五个核心点可靠，再逐步纳入其他测量点。**

## 十一、range_check=false 不等于"不读取"

> ⚠️ **必须记住的细节**

假设 `40104 PCC_F = 60 Hz`，`range_check = false`。

板子仍然应该：
- ✅ 读取 40104
- ✅ 按 UINT16 解释
- ✅ 乘 0.01 恢复为 60 Hz
- ✅ 在需要时打印或记录

只是：
- ❌ 不会令 `PCC_F = 60 Hz` 导致 `measurements_valid = false`
- ❌ 不会导致 40010 置 0

所以 `range_check = false` 的准确含义是：

> **当前不把这个点作为外部控制投入的强制条件。**

而不是：
- ❌ 不读这个点
- ❌ 不解码这个点
- ❌ 删除这个点

---

## 十二、为什么辅助点仍要保留有效范围

例如 PCC_F 配置：
```json
{
  "range_check": false,
  "valid_min": 45.0,
  "valid_max": 55.0
}
```

虽然当前不强制判断，但**范围配置仍有意义**。

以后完成：
- 信号确认
- 单位确认
- 正常运行验证

只需要把 `"range_check": false` 改成 `"range_check": true`，**即可纳入强制检查，无需重新设计点表**。

这是一种**逐步启用的接口设计**。

---

## 十三、五个核心点的汇总判断

板子内部的 `measurements_valid` **不是某一个寄存器**，而是五个强制点检查结果的逻辑汇总。

可以理解为：
```
measurements_valid
    = PCC_P_valid
    AND PV1_P_MAX_valid
    AND PV2_P_MAX_valid
    AND ESS1_SOC_valid
    AND ESS2_SOC_valid
```

| 情况 | 结果 |
|------|------|
| 全部为真 | `measurements_valid = true` |
| **任一点为假** | `measurements_valid = false` |

**示例**：
- PCC_P 正常
- PV1_P_MAX 正常
- PV2_P_MAX 正常
- **ESS1_SOC = 1.20** ❌
- ESS2_SOC 正常

最终仍然是 `measurements_valid = false`。

> ⚠️ **不能因为"四个正常、一个异常"而继续使能。**

---

## 十四、MODEL_STATUS 中的 MEAS_VALID 与板子的 measurements_valid 不同

> 这里有两个名字非常相似的量，必须区分。

| 量 | 来源 | 含义 |
|----|------|------|
| 40115 bit1 **MEAS_VALID** | RT-LAB 侧生成 | RT-LAB 模型认为自己的测量系统已经准备好、数据可用 |
| 板子内部 **measurements_valid** | 板子完成解码和范围检查后生成 | 板子根据当前读取结果，认为五个核心工程量都处于允许范围 |

**两者必须同时成立。**

完整逻辑是：
```
RT-LAB 自己声明测量有效
+
板子独立检查工程值合理
```

这相当于**双重确认**。

### 为什么不能只相信 bit1

假设 40115 中 `MEAS_VALID = 1`，但由于 JSON 缩放写错，板子把 SOC 解码成 1.20。

RT-LAB 模型本身可能认为信号正常，但**板子侧接口配置已经产生错误**。所以板子仍要独立检查。

## 十五、核心测量越界时完整发生什么

假设板子已经处于：
- `state = ENABLED`
- `40010 = 1`
- `valid_count = 3`

下一周期读取：`ESS1_SOC = 1.20`

完整处理过程应为：
```
FC03 成功
        ↓
UINT16 和 scale 解码成功
        ↓
发现 ESS1_SOC 超出 [0,1]
        ↓
measurements_valid = false
        ↓
ext_agc_enable_local = 0
        ↓
valid_count = 0
        ↓
ENABLED → WAIT_VALID
        ↓
本周期尝试通过 FC16 写 40010 = 0
```

**日志至少应包含**：
```
INVALID point=ESS1_SOC value=1.20 range=[0,1]
STATE ENABLED -> WAIT_VALID reason=MEASUREMENT_INVALID
```

## 十六、为什么测量越界不应该断开 Modbus 连接

ESS1_SOC 越界说明：**数据内容存在问题**。

不说明：**TCP 连接已经损坏**。

因此**不应**因为一个测量值异常就：
- ❌ 退出程序
- ❌ 关闭 socket
- ❌ 停止读取

正确行为是：
- ✅ 继续保持通信
- ✅ 继续读取全部测量点
- ✅ 继续写 40010 = 0
- ✅ 继续更新 BOARD_HEARTBEAT
- ✅ 等待数据恢复

**这样板子才能知道异常何时消失。**

如果一发现越界就退出程序，就无法自动观察和恢复。

> 📄 文档也明确要求：**单个测量越界时通信保持运行，程序不退出。**

---

## 十七、测量恢复后完整发生什么

假设下一周期 ESS1_SOC 恢复为 `0.75`。

**不能立即** `40010 = 1`，而应重新开始连续有效计数：

| 周期 | 操作 | 状态 |
|------|------|------|
| 恢复第 1 周期 | `valid_count = 1` | `40010 = 0` |
| 恢复第 2 周期 | `valid_count = 2` | `40010 = 0` |
| 恢复第 3 周期 | `valid_count = 3` | 进入 ENABLED，`40010 = 1` |

> ⚠️ **测量恢复 ≠ 外部命令立即恢复**
> 仍然遵循：**慢投入，快退出**。

---

## 十八、辅助点越界时怎样处理

假设 `PCC_F = 60 Hz`，`range_check = false`。

程序应当：
- ✅ 继续读取和解码
- ✅ 保持当前 `measurements_valid` 汇总不受影响
- ❌ **不**因为 PCC_F 退出 ENABLED

但这并不表示 60 Hz 是合理运行状态。它只表示：

> V3.2 第一阶段**暂不使用**这个辅助点决定外部命令资格。

以后如果论文或控制策略使用频率（例如低频减载），就必须重新评估：
- PCC_F 信号来源
- 缩放
- 范围
- 异常处理

并将其设置为 `"range_check": true`。

---

## 十九、当前范围是接口有效范围，不一定是最终保护定值

文档中的范围暂定为：

| 点 | 范围 |
|----|------|
| PCC_P | -1000～1000 kW |
| PV 最大出力 | 0～100 kW |
| SOC | 0～1 |

这些值主要用于发现**明显错误**，例如：
- 类型错误
- 缩放错误
- 信号接错
- 超出物理可能值

它们**不一定等于最终系统运行保护定值**。

例如 `PCC_P = 800 kW`，在当前接口范围内可能被认为"数据格式可信"，但不表示系统运行一定安全。

是否允许 800 kW 交换功率，应由：
- 设备容量
- 微网运行策略
- 保护定值
- 控制目标

**另行决定**。

> 📌 **需要区分三个概念：**
> - **数据可信范围**（接口层）
> - **控制允许运行范围**（策略层）
> - **设备保护范围**（设备层）
>
> 三者**不是同一个概念**。

---

## 二十、非有限数检查怎样理解

V3.2 文档还要求检查**非有限数**（NaN、Inf、-Inf）。

一个 16 位整数本身不会直接携带 NaN，但在以下情况下，工程量处理仍可能产生异常：
- 计算过程中除以错误的缩放值
- 配置读取异常
- 后续公式计算异常
- 数据结构未正确初始化

因此，**进行有限性检查属于防御性设计**。

**正常顺序是：**
```
先确认工程量为有限数
再判断 valid_min ≤ value ≤ valid_max
```

---

## 二十一、范围边界如何判断

"超出 valid_min/valid_max" 通常意味着**边界本身有效**。

### SOC 边界判断

| 值 | 判定 |
|----|------|
| 0.00 | ✅ 有效 |
| 1.00 | ✅ 有效 |
| -0.01 | ❌ 无效 |

## 二十五、本轮论文注意点

### 1. 通信正常与数据可信应分别评价

论文中不能只用 `TCP connected` 证明控制输入可靠。至少应区分：
- 传输可达性
- 数据新鲜度
- 数据内容合理性
- 模型运行状态

### 2. 分级有效性判断具有工程价值

不是所有数据都具有相同的重要程度。当前设计按照：
- 控制必需核心量
- 辅助监测量
- 模型与通信管理量

进行分级，可避免非关键测点异常导致整个控制系统不必要退出。

### 3. 不能通过限幅掩盖传感器或接口错误

"错误测量限幅后继续控制"可能让系统看起来稳定，却隐藏真实故障。论文实验中应明确区分：
- **命令饱和**（允许）
- **测量异常**（必须停用）

二者对应不同处理策略。

### 4. 阈值设置存在误判与漏判权衡

| 范围设置 | 后果 |
|---------|------|
| 范围过窄 | 正常波动可能被判异常 |
| 范围过宽 | 明显错误可能无法及时发现 |

后续真实模型运行后，需要根据数据记录**校核当前暂定范围**。

### 5. 设备实际功率以后可能升级为核心点

当前 40109～40114 不参与基础 AGC。但若论文采用：
- 基于设备实测功率的裕度重估
- 命令—实际偏差补偿
- 设备跟踪异常检测

那么这些点将从**辅助监测量升级为算法核心输入**，也应相应启用有效性检查。
