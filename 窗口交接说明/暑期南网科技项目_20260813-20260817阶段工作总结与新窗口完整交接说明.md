# 6. 8月13日遇到的第一个关键问题：Strategy 7 ↔ AGC 形成代数环

第一次主动整合时出现：

```text
algebraic loop（代数环）
```

真正原因不是状态机理论错误，而是遗漏了一条反馈路径：

```text
AGC命令
↓
Strategy 2（策略2）
↓
Pexpected + residual
↓
Pexec（执行功率估计）
↓
AGC
```

即：

```text
AGC
→ Strategy 2
→ AGC
```

Strategy 2（策略2）和AGC都包含内部状态，因此不能处于同一步直接代数反馈。

解决：

```text
六路 Pexec（执行功率估计）
↓
各插入一个 100 μs Unit Delay（单位延迟）
↓
再进入AGC
```

于是：

```text
Strategy2 Pexec(k-1)
→ AGC(k)
```

代数环消除。

这个问题后来对 LOCAL15（本地15策略闭环）的 S13（阶段13）也产生了直接经验价值：

> **系统级状态反馈必须显式建立时间因果，不要依赖MATLAB Function内部状态“自动解决”。**

# 8. 8月13日第三类问题：RECONSTRUCTION（状态对齐阶段）太短，正式MAT采不到

第一次真实握手时：

```text
RECONSTRUCTION（状态对齐）
→ AGC done（AGC完成）
→ RECOVERY（恢复）
```

只持续几个100 μs步长。

而正式OpWrite（目标机数据记录）的采样约：

```text
100 Hz
≈ 10 ms一个记录点
```

因此MAT中可能直接看到：

```text
NORMAL
→ HOLD
→ RECOVERY
```

但看不到短暂的：

```text
RECONSTRUCTION
```

并不是算法没执行，而是：

```text
状态驻留时间
<
日志分辨率
```

解决：

```text
T_RECON_MIN（状态对齐最小驻留时间）
= 0.05 s
```

这样100 Hz日志至少能看到约5个点。

此后四状态：

```text
NORMAL
→ HOLD
→ RECONSTRUCTION
→ RECOVERY
→ NORMAL
```

正式可观测。

# 18. V5-A中一个非常关键的工程问题：Modbus负数补码不能直接当正数

40001～40006 表达正负功率。

但寄存器原始读数可能表现为：

```text
0～65535
```

例如板端想发：

```text
-6000
```

模型侧可能读到：

```text
59536
```

因为：

```text
65536 - 6000 = 59536
```

因此V5-A增加：

```text
如果 raw < 32768
→ signed = raw

如果 raw >= 32768
→ signed = raw - 65536
```

然后：

```text
signed × 1e-4
→ pu（标幺有功指令）
```

例如：

```text
6500
→ +0.6500 pu

59536
→ -6000
→ -0.6000 pu
```

这使EV（电动汽车）充电负功率等命令能够被正确恢复。
