当前已经不再是：

```text
→ ESS1出现几十安培电流冲击
→ PCC出现约-450 kW大暂态
```

F21（电流 PI 状态复位）加入后：

```text

↓

而V9约45.6 A

↓

PCC不再出现约-450 kW冲击
只剩几kW级变化
```

因此可以正式冻结：

> **“ESS1 GFL→GFM（跟网→构网）大瞬态”的主根因已经完成主动干预验证并被 F21 解决。**

但是 V11（第11轮验证）第一次在这个修复基础上执行真正：

```text
ESS1已经稳定GFM
+
F21已经关闭
+
PCC P/Q已经重新连续接近0
+
```

> **F21 已经消除了模式切换首瞬冲击，但完整“ESS1 GFM（构网型控制）+ 另外5台GFL（跟网型控制）”在真正失去强网电压支撑以后，仍存在一个约 0.2～0.6 s 时间尺度的电压稳定性/电压接管问题。**

这个问题**不是旧的 GFL→GFM 状态切换问题**，必须作为第二层根因独立排查。

# 4. V7 / V7.1：为什么“先切GFM再开J1”第一次被重新审视

## 4.1 目的

当时想把：

```text
GFL→GFM
```

和：

```text
J1 CLOSED→OPEN
```

分开。

所以使用当前模型已有：

```text
CFG15_DIAG_MODE_BREAKER_DECOUPLE
```

让：

```text
模式执行允许
PCC断路器执行禁止
```

从而：

```text
ESS1先进入GFM
J1继续闭合
```

## 4.2 V7.1现象

GFL状态下 PCC 预平衡成功：

```text
t=3.1 s

Ppcc ≈ -1.515 kW
Qpcc ≈ -0.011 kvar
f ≈ 50 Hz
```

随后只切 ESS1 GFM，J1仍闭合。

但马上出现：

```text
3.105 s：
P ≈ -99.38 kW
Q ≈ +43.98 kvar

3.205 s：
P ≈ -543.30 kW
Q ≈ -59.90 kvar
```

随后长期有数百 kW / 上百 kvar 交换。

当时 F20 仍保持：

```text
F20_IOUT_RELEASE_TIME_S = 9999
```

也就是一直动态跟踪。

Group29（第29高速采集组）看到 F20 项在切换后亚毫秒内从正常小量迅速放大到约 ±1 pu，故当时形成强候选：

```text
F20动态跟踪可能把强网并联环流反向写入GFM电流参考
```

这个判断后来被 V8 修正为：

```text
F20确实会严重放大问题
但不是第一触发根因
```

# 5. V8：F20提前冻结，为什么仍然失败

## 5.1 唯一改变

V8：

```text
PCC预平衡
→ ESS1仍GFL
→ F20在3.11 s捕获
→ F20保持固定偏置
→ 再切ESS1 GFM
→ J1始终闭合
```

F20实际冻结值：

```text
d ≈ -0.0247813964 pu
q ≈ +0.1019562582 pu
```

Group29中冻结后标准差约：

```text
10^-14 ~ 10^-13
```

即数值意义上的严格常数。

## 5.2 结果

即使 F20 已经完全固定：

```text
3.320 s：
P ≈ -192 kW

3.325 s：
P ≈ -307 kW

3.330 s：
P ≈ -418 kW

3.335 s：
P ≈ -448 kW
```

所以：

> **F20持续动态跟踪不是第一根因。**

但与 V7.1相比，V8后面能恢复到几十/几 kW量级，说明：

> **F20动态跟踪会把原本的模式切换冲击放大并维持，因此未来正式架构仍应采用“工作点捕获后保持”，不能让强网并联状态下的输出电流无限动态回灌。**

## 6.1 唯一改变

V9相对V8：


GFL阶段实际 F2 本来就被逻辑压成模式0，因此：


V9切GFM以后：

```text

≈ -449 kW
```

与V8：

```text
≈ -448 kW
```

几乎一致。

# 7. 真正锁定的第一根因：Current PI旧积分状态没有无扰转移

## 7.1 V8/V9最关键证据

GFM切入第一拍：

新的 GFM 电流参考与新的反馈已经非常接近。

典型值：

```text
GFM Id_ref ≈ -0.07418 pu
GFM Iq_ref ≈ +0.10007 pu

selected Id ≈ -0.07672 pu
selected Iq ≈ +0.10482 pu
```

误差向量只有约：

```text
0.005~0.013 pu
```

按：

```text
Current PI Kp = 0.3
```

比例项应该只有千分之几 pu。

但当时 Current PI 输出仍接近：

```text
[+1.03, -0.95] pu
```

说明巨大输出不来自新误差，而来自：

```text
GFL阶段留下的积分状态
```

## 7.2 为什么会出现旧状态语义不一致

当前 ESS1 切换并不只是一个标签变化。

`ConnectMode（连接模式）` / `GridOn（跟网/构网选择）` 会使：

```text
GFL电流参考
→ GFM电流参考

GFL电流反馈语义
→ GFM电流反馈语义

部分d/q坐标和测量路径
→ GFM坐标
```

发生改变。

但同一个 Current PI 内部的离散积分状态：

```text
没有reset（复位）
没有preload（预置）
没有tracking（跟踪）
没有state transform（状态变换）
```

直接保留。

于是产生：

```text
新坐标/新工作点
+
旧积分器状态
```

的结构性不匹配。

# 8. F21 模型修改：到底改了什么

## 8.1 用户截图中的位置

用户上传截图所示：

```text
SS_Slave2
→ ESS1_Control
→ Current Regulator
→ PI regulator with anti-windup
→ Discrete-Time Integrator
```

就是修改核心。

不是改：

```text
Kp
Ki
饱和上限
抗饱和逻辑
```

而是给现有离散积分器增加一次性外部复位能力。

## 8.2 F21结构

新增：

```text
F21_CURRENT_PI_RESET_ENABLE
默认 Value = 0
```

逻辑：

```text
reset_request
=
F21_ENABLE
AND
NOT(GRIDON)
```

其中：

```text
GridOn=1
→ GFL

GridOn=0
→ GFM
```

积分器：

```text
ExternalReset = rising
```

即只对：

```text
0 → 1
```

上升沿复位一次。

## 8.3 为什么默认不会破坏原模型

保存默认：

```text
F21 = 0
```

因此：

```text
六GFL强网
Gate A黑启动
正常原模型
```

全部不触发 F21。

只有计划切岛脚本在：

```text
PCC预平衡
+
F20冻结
+
ESS1仍GFL
```

后：

```text
F21 0→1
```

此时：

```text
GridOn=1
```

所以 reset_request 仍为0。

然后 ESS1：

```text
GridOn 1→0
```

才使：

```text
reset_request 0→1
```

Current PI积分器只复位一次。

进入 GFM 后立即：

```text
F21 1→0
```

后面的 J1 开断和孤岛阶段 F21 完全退出。

# 34. 下午阶段形成的最终工程认识

3. **控制器切换不仅要参考连续，还要内部状态连续。**
4. **强网下看起来稳定，可能只是强网在替控制器承受状态迁移。**
5. **把一个大问题拆成正交单变量试验，比同时改参数高效得多。**
6. **F20动态前馈在Formation有价值，但不应在强网GFM阶段无限动态跟踪。**
7. **F2本地快反馈对健康GFM仍重要，不能因为切换失败就永久关闭。**
8. **Current PI状态管理是本项目真实的必要结构，不是调参。**
9. **F21 reset-to-zero对当前计划切岛已被数据证明有效。**
10. **真离网后当前主要问题已经变成电压稳定性，而不是首瞬电流爆炸。**
11. **后期频率跌落是电压/波形失稳后的结果，不应先调Droop。**
12. **在没有证明五台GFL是否为必要条件前，不应直接重调Voltage PI。**
13. **任何热接设备试验都应谨慎；优先从仿真初始时刻冻结拓扑。**
14. **OpWrite记录完整性不能凌驾于电气安全。**
15. **脚本框架一旦实机PASS，应复制而不是重写连接层。**

当前不能再只写成：

> F8 IOUT（输出电流前馈）“参与”了 3.4 Hz。

更准确的工程根因是：

> **成岛完成以后，把实际网络 IOUT（输出电流）作为连续动态 feedforward（前馈）100%重新送入 Id/Iq_ref（dq 轴电流参考），等价于把一个本身受母线电压和被动网络影响的量重新闭合进电压控制回路。该结构会抵消或相位扭曲被动网络的 incremental admittance（增量导纳）及其阻尼。RAW（原始）动态通道在约 3.4 Hz 形成负阻尼；改成 0.5 Hz LPF（低通滤波器）并没有消除这条反馈，只是增加相位滞后并把主要不稳定时间尺度移到约 0.3～0.5 Hz。**

- F8 测量方向一定错误；
- `F8_IOUT_GAIN=-1` 一定错误；
- Voltage PI（电压比例积分调节器）参数单独错误；
- Current PI（电流比例积分调节器）错误；
- 527 Hz LC（电感电容）问题复发；
- `fc=0.5 Hz` 单纯选得不够小。

根因是 **continuous measured IOUT feedforward（连续实测输出电流前馈）的闭环使用方式**。

### 0.3 当前问题已经有结构性解决方案

最终方向不是继续找 `fc`（截止频率）或 `beta`（快速分量混合系数），而是把 IOUT 的职责重新定义：

```text

raw IOUT（原始输出电流前馈）
→ 用于快速建立正确工作点

成岛完成以后
捕获当时 IOUT operating-point bias（输出电流工作点偏置）
→ 后续保持为常数
→ 不再让 ΔIOUT（输出电流动态变化）持续进入 Id/Iq_ref

后续真实网络变化
→ 由 Voltage PI（电压比例积分调节器）处理
→ CAP（电容同步补偿）继续正常工作
```

这就是 MODE1 已经实际验证的结构。

> **MODE1 不再只看作诊断模式。它已经是当前有直接因果证据支持的最终 Gate A 控制候选。**

# 4. 根本机制为什么能解释 MODE0 / MODE1 / MODE2 三组结果

下面用最简化的小信号关系说明，不把 dq 交叉补偿和已冻结的 CAP 项重复展开。

局部电容电压动态可简化为：

```math
C s V = I_L - I_{out}
```

Current Loop（电流环）近似写成：

```math
I_L = G_i(s)\left[G_v(s)(V_{ref}-V)+F(s)I_{out}\right]
```

被动网络输出电流：

```math
I_{out}=Y_n(s)V
```

合并后，闭环特征项中会出现：

```math
D(s)=Cs+G_i(s)G_v(s)+\left[1-G_i(s)F(s)\right]Y_n(s)
```

其中：

- `G_i(s)`：Current Loop（电流环）动态；
- `G_v(s)`：Voltage Loop（电压环）动态；
- `Y_n(s)`：Transformer/Stubline/passive network（变压器/短线/被动网络）的增量导纳；
- `F(s)`：IOUT dynamic feedforward（输出电流动态前馈）的传递关系。

## MODE1

成岛后：

```text
ΔF = 0
```

也就是固定 bias 不随 `ΔIout` 变化。

此时：

```math
[1-G_iF]Y_n \approx Y_n
```

被动网络的增量导纳和阻尼保留下来。

实验结果：稳定。

## MODE0

RAW（原始）动态前馈：

```text
F(s) ≈ 1
```

在几 Hz 低频范围 Current Loop（电流环）又接近 1，因此：

```math
1-G_iF \approx 0
```

也就是说，被动网络原本提供的增量电流响应被 IOUT feedforward（输出电流前馈）大量抵消。

这并不意味着网络消失，而是控制器把网络的动态电流变化重新补回 Current Reference（电流参考），使系统看到的有效增量阻尼显著改变。

结合实际离散延时、Current Loop（电流环）和 Voltage Loop（电压环）动态，就出现了约 3.4 Hz 负阻尼增长。

## MODE2

```text
F(s)=0.5 Hz 一阶 LPF
```

它并没有让 `F(s)=0`，所以动态反馈仍存在。

而且 LPF（低通滤波器）必然带相位滞后。

在 3.4 Hz：

- 幅值已经被强烈压低，所以旧 3.4 Hz 被消除；
- 但在约 0.3～0.5 Hz，LPF 仍有较大增益，同时已经产生明显相位滞后；
- 于是 `[1-G_iF]Y_n` 在更慢频段形成新的不利阻尼。

实验正好表现为：

```text
原 3.4 Hz 消失
+
新的几秒周期大摆动出现
```

所以 MODE2 不是“截止频率还不够低”，而是暴露了连续动态 IOUT 反馈本身的结构问题。

## 为什么第一台选 ESS2

这不是经验猜测。

现有 S14 Black Start（策略14黑启动）的冻结恢复顺序本来就是：

2. Stage2：先恢复 non-master ESS（非主储能），即 ESS2；
3. Stage3：再恢复 PV（光伏）；
4. Stage4：最后恢复 EV（电动汽车）。

同时 Device Mode Router（设备模式路由器）在 Black Start 模式下保持 ESS1 为唯一 GFM，其余设备均为 GFL。

因此先 ESS2 与模型原本设计一致。

## 第一轮 ESS2 恢复试验真正要回答什么

不是验证 3.4 Hz 根因。

3.4 Hz 问题已经通过 MODE0/MODE1/MODE2 因果链关闭到“成岛后不得持续动态反馈 IOUT”这一结构结论。

第一轮绝不同时加入有功功率阶跃。

这样若失败，可以把问题限制在：

- GFL 同步；
- 接入瞬态；
- 多变流器电气耦合；
- ESS1 对小工作点变化的承受能力。

不会把“功率命令变化”也混进来。

# 8. 但“PLL 已看见母线”为什么还不够

这是这轮设计中真正遗漏的地方。

ESS2 当前是 GFL。

GFL Current Regulator（电流调节器）使用：

```text
prim_ESS2 Vd/Vq
```

作为电压前馈，

使用：

```text
prim_ESS2 Id/Iq
```

作为电流反馈。

当低压诊断断路器 OPEN 时：

```text
prim_ESS2 current ≈ 0
```

而零功率测试又令：

```text
Id/Iq reference ≈ 0
```

所以电流 PI 可以看起来完全健康。

但是：

> **这个电流环没有直接闭环调节“ESS2 本地 L2/C2/Converter 侧断路器端电压必须等于母线侧断路器端电压”。**

换句话说：

```text
PLL锁住母线角度
```

不等于：

```text
断路器两端瞬时电压已经相等
```

而：

```text
Pref = 0
Qref = 0
```

更不等于：

```text
ΔVbreaker = 0
```

---

# 9. 为什么零功率仍然可以产生大冲击

真正的交流并联条件应接近：

```text
电压幅值匹配
频率匹配
相位匹配
波形状态匹配
```

如果断路器两端存在明显电压差：

```text
Δv = v_ESS2_local - v_bus
```

闭合瞬间：

```text
Δv
↓
L2 / transformer leakage / network impedance
↓
很大的瞬时均衡电流
```

它与：

```text
Pref = 0
```

没有矛盾。

`Pref=0/Qref=0` 只说明控制器不想持续交换有功/无功。

它不能消除两个交流电压源/电容节点并联时的瞬时压差。

---

# 10. 还有一个非常重要的已知结构风险：ESS2 没有做 F14

当前模型实际块参数显示：

ESS2：

```text
ESS2_PWM
= PWM Generator (2-Level)

ESS2_Converter
= Switching devices
```

而已经修正后的 ESS1：

```text
ESS1_PWM
= PWM Generator (Pulse Averaging)

ESS1_Converter
= Switching Function
```

项目实时步长：

```text
Ts = 100 μs
```

载波：

```text
Fsw = 4 kHz
Tsw = 250 μs
```

即一个 PWM 周期只有：

```text
2.5 个实时步
```

此前 F14 已经用直接实验明确证明：

> **ESS1 在孤立/构网条件下，原 `PWM Generator (2-Level) + Switching devices` 不能稳定、连续地把控制器的低频电压命令落实成真实物理输出。**

因此当前 ESS2 在断路器 OPEN 时：

```text
GFL控制器虽然根据prim_ESS2母线电压生成电压前馈命令
```

但它自己的隔离侧实际交流端电压能否精确匹配母线：

> **不能仅凭控制命令假定。**

这一点现在是与合闸失败高度一致的强候选机制。

但没有直接测到 ESS2 本地隔离侧电压以前，不能直接宣布：

```text
ESS2旧PWM就是唯一根因
```

必须做最后一次直接测量。

# 1. 最终系统的GFM/GFL模式到底应该怎样

当前项目最合理、也与现有LOCAL15策略一致的最终架构仍然是：

```text
PCC = CLOSED

ESS1 = GFL
ESS2 = GFL
PV1  = GFL
PV2  = GFL
EV1  = GFL
EV2  = GFL

上级电网负责定义：
V / f / θ
```

离网以后：

```text
PCC = OPEN

ESS1 = GFM master
负责定义：
V / f / θ

ESS2 = GFL
PV1  = GFL
PV2  = GFL
EV1  = GFL
EV2  = GFL

五台GFL跟随ESS1形成的本地母线，
按照Pref/Qref出力。
```

重新并网以后：

```text
PCC同步完成并闭合
↓
短时保持ESS1 GFM
↓
ESS1 GFM -> GFL
↓
六台全部回GFL
```

这与当前 `Device Mode Router（设备模式路由器）` 的设计一致：

```text
GridOn = 1 -> GFL
GridOn = 0 -> GFM
```

并且在：

```text
ISLANDING
ISLANDED
BLACK_START
RESYNCHRONIZATION
```

模式下只选择一个ESS作为GFM master。

# 2. 一台一台“接回来”究竟是不是最终效果

要区分两种完全不同的“接回来”。

## 2.1 S14原本的逐阶段恢复：是最终策略的一部分

S14原设计：

```text
Stage1
全部Pref = 0
ESS1 = GFM
PCC OPEN
↓
建立母线

Stage2
允许非主ESS（ESS2）的Pref恢复

Stage3
允许PV1/PV2的Pref恢复

Stage4
允许EV1/EV2的Pref恢复
```

这属于：

这个思路是正确的。

它避免ESS1刚建立母线时：

```text
所有设备同时带正常功率工作点
```

而是逐步增加岛内主动设备和负荷。

## 2.2 Gate A的“物理断路器逐台闭合”：不是S14原本的最终逻辑

Gate A为了回答：

> ESS1本体到底能不能构网？

我们后来增加：

```text
CFG_DIAG_AC_CONNECT_PV1
CFG_DIAG_AC_CONNECT_PV2
CFG_DIAG_AC_CONNECT_ESS2
CFG_DIAG_AC_CONNECT_EV1
CFG_DIAG_AC_CONNECT_EV2
```

五个诊断物理隔离断路器。

目的：

```text
把其它5台active converter完全从岛网断开
```

从而把问题压缩成：

```text
ESS1
+
真实被动Transformer/Stubline网络
```

这是一种 **诊断拓扑**。

它不是原S14正式策略中的：

```text
DeviceEnable / Contactor Sequencing
```

因为原S14文档明确写了：

```text
当前模型没有独立DeviceEnable。
```

所以：

> **当前没有依据要求最终黑启动必须按“ESS2物理合闸→PV物理合闸→EV物理合闸”来实现。**

刚才的ESS2合闸失败，不能判成：

```text
S14重启动本身不可实现。
```

更准确地说：

> 我们测试了一个原S14并没有定义过的“隔离GFL物理并联”动作，并发现这个动作缺少同步准备。

# 3. 那最终Black Start（黑启动）正确过程应该是什么

按照当前已有策略，不新增设备接触器语义时，应该回归原S14定义：

## State A：死母线准备

```text
PCC OPEN

ESS1 -> GFM

ESS2/PV/EV:
保持GFL控制逻辑
但Pref/Qref暂时为0
```

关键不是：

```text
把另外5台物理切出去以后再硬合回来
```

而是：

> 让它们在零功率/不主动承担功率的状态下存在于最终网络结构中。

---

## State B：ESS1 Formation

```text
ESS1 Vref从0缓升到10 kV
↓
ESS1建立V/f/θ
```

此时五台GFL的PLL逐渐看到并锁定：

```text
ESS1形成的本地母线。
```

由于：

```text
Pref=0
Qref=0
```

理想状态下它们不应与ESS1争夺V/f，只保持同步准备。

---

## State C：母线健康确认

不能只看时间。

至少需要：

```text
V在额定附近
f有界
ESS1无饱和
五台GFL电流无异常
GFL PLL/模式健康
```

---

## State D：S14 Stage2~4释放功率

```text
Stage2
ESS2 Pref允许恢复

Stage3
PV Pref允许恢复

Stage4
EV Pref允许恢复
```

这是S14真正设计的“重启动/恢复”。

也就是说：

> **最终S14更接近“先建立电网，再依次让设备开始承担功率”，而不是“先把所有设备物理隔离，再依次做交流并联”。**

---

# 4. 如果真实工程硬件确实有各设备AC接触器怎么办

这是另一层问题。

如果最终真实系统要求：

```text
设备AC接触器初始OPEN
↓
黑启动后逐台CLOSE
```

那么现有S14确实不完整。

因为此时“设备恢复”不再只是：

```text
Pref Gate
```

还需要新增：

```text
Device Connection Qualification
（设备并联资格判断）
```

每台设备在合闸前至少要确认：

```text
Bus valid
Converter ready
PLL lock
ΔV sufficiently small
Δf sufficiently small
Δθ sufficiently small
Pref/Qref = 0或安全值
```

然后：

```text
close device contactor
↓
short hold
↓
ramp/release Pref/Qref
```

这属于“设备级并联同步”。

但：

> **当前项目的原S14没有这个物理接触器层，因此不能把Gate-A诊断断路器自动当成最终设备接触器。**

我们是否需要正式增加这一层，应由项目最终验收对象/真实硬件接口决定，而不是因为一次诊断失败就自动扩展策略。

# 5. Grid-Connected -> Island（并网转孤岛）正确方式又不同

这不是Black Start。

正常并网时：

```text
六台设备都已经物理连接在同一母线上。
```

所以最终并→离网时根本不应该：

```text
打开其它5台设备
↓
ESS1建孤岛
↓
再一台台把5台合回来
```

正确过程应该是：

```text
GRID_CONNECTED
↓
PREPARE_ISLAND
↓
ESS1进入GFM-ready
↓
PCC处P/Q/I尽量预平衡
↓
慢控制HOLD
↓
OPEN PCC
↓
ISLANDED
```

其中：

```text
ESS1：GFL -> GFM
其它5台：始终保持GFL
```

其他五台不需要经历物理断开/重合。

因为它们在PCC打开前后都连接在同一微电网母线上。

它们的PLL只发生：

```text
原来跟随强网形成的母线
↓
PCC打开
↓
继续跟随ESS1形成的母线
```

如果切换足够无扰，这本身就是连续过程。

# 6. 并网转孤岛到底还缺什么

现有LOCAL15模式链已经有：

```text
S5/S14/S15
↓
Mode Manager
↓
S13
↓
Device Mode Router
↓
PCC Breaker
```

但从目前真实电气排错经验看，如果目标是高质量的无扰切岛，最终应明确四个步骤：

## 6.1 ESS1 GFM-ready

在PCC仍闭合时：

```text
ESS1准备好GFM状态
```

而不是：

```text
PCC打开
+
ESS1 GFL->GFM
```

两个动作完全同时发生而没有状态准备。

需要保证切换前后：

```text
V / f / θ
控制器内部积分状态
dq坐标
```

尽可能连续。

F3/F4过去处理的正是这一类问题的一部分。

---

## 6.2 PCC P/Q/I预平衡

计划性切岛时，开PCC前最好让：

```text
P_tie ≈ 0
Q_tie ≈ 0
I_tie 尽量小
```

这样PCC打开以后：

```text
ESS1不需要瞬间接管很大的功率缺口。
```

这一步应由现有：

```text
AGC
+
2PV+2ESS+2EV
```

共同完成，而不是只靠ESS1。

---

## 6.3 HOLD

切换窗口：

```text
冻结/限制上层慢控制器继续积分
```

避免：

```text
拓扑切换
+
慢控制目标变化
+
设备模式变化
```

三件事同时发生。

---

## 6.4 OPEN PCC

此时：

```text
ESS1 = GFM
其它5台 = GFL
```

直接形成完整六设备孤岛。

这才是最终Seamless Transfer（无扰并网转孤岛）路径。

```text
Δθ
↓

↓
三个同步条件连续满足0.50 s
↓
PCC CLOSE
```

# 10. PWM到底为什么换

F14时我们改变：

```text

→

Switching devices
```

最初它是在ESS1 Formation问题中被发现。

但它的根本原因不是：

```text
“GFM必须用Pulse Averaging，GFL不用。”
```

而是当前实时仿真条件：

```text
Ts = 100 μs
Fsw = 4 kHz
Tsw = 250 μs
```

所以：

```text
一个PWM周期只有2.5个实时计算step。
```

详细0/1开关边沿无法被100 μs网格充分表示。

Pulse Averaging解决的是：

> **RT-LAB当前步长下开关占空比如何被数值上正确执行。**

它是 **实时Plant执行表示问题**。

ESS1只是在脱离强网、需要自己连续形成电压时，最容易暴露这个问题。

# 2026-08-28｜六设备并网—离网—孤岛—黑启动验证路线重新冻结

## 0. 结论

当前不能直接执行：

```text
六台正常并网
→ ESS1直接切GFM
→ 等一段时间
→ PCC断开
→ 五台GFL全部正常带功率继续运行
```

这个目标形态在方向上接近最终系统，但中间缺少两个尚未真正验证的环节：

1. **ESS1 的 GFL→GFM 无扰接管；**
2. **F20 MODE1 的“固定 IOUT bias”从 Gate A 的定时诊断逻辑转成真正的状态触发逻辑，并验证其面对主动 GFL 工作点变化仍有足够裕度。**

因此不能把“五台一起恢复”作为下一轮。

正确方法是：

```text
先把公共实时执行层处理清楚
↓
正常六机并网回归
↓
五台GFL保持物理连接但先P/Q=0
↓
只验证ESS1 GFL→GFM + PCC OPEN的接管
↓
成功后逐阶段释放ESS2/PV/EV功率
↓
最后再验证真实全功率并网→孤岛
```

这里的“逐阶段”是 **功率/控制参与度逐步增加**，不是 Gate A 诊断断路器逐台热合闸。

# 4. 另外五台换PWM会不会也暴露一模一样的问题

## 不会自动重复ESS1的整条F15~F20路线

因为 ESS1 当前承担 GFM。

它具有：

```text
Voltage Loop
→ Current Reference
→ Current Loop
```

而普通 GFL 的主要结构是：

```text
P/Q控制
→ Current Reference
→ Current Loop
```

因此 ESS1 后来遇到的：

```text
F8 IOUT
F9 Voltage PI dq mapping
CAP compensation
F20 IOUT bias
```

主要属于 GFM Voltage Loop。

普通 GFL 并没有同样的主动电压外环，所以不能机械复制。

---

## 但可能暴露“公共内环/执行层”问题

例如：

```text
PWM/Converter实时表示
Current Regulator
电压前馈
本地电流反馈
```

这些是多台设备共享的结构层。

所以其它设备在换 PWM 后可能发现新的 GFL 问题，但不能提前假定它们会重复 ESS1。

# 5. 为什么仍然值得考虑统一六台PWM执行表示

当前：

```text
Ts = 100 μs
Fsw = 4 kHz
```

一个开关周期：

```text
250 μs
```

只有：

```text
2.5个实时计算步
```

这个数值事实对六台设备完全相同。

ESS1 已经直接证明：

```text
PWM Generator (2-Level)
+
Switching devices
```

在需要自主形成电压时存在严重执行问题。

因此其余五台继续长期采用另一种数值表示，会产生：

```text
ESS1：Pulse Averaging + Switching Function
其它5台：2-Level PWM + Switching devices
```

的混合实时Plant。

这样未来多机孤岛如果出现问题，很难区分：

```text
控制器差异
vs
实时开关表示差异
```

所以“统一执行层”仍然是合理方向。

但正确做法不是：

```text

```

只统一：

```text
PWM representation
Converter representation
```

# 7. IOUT问题现在到底解决到哪一层

IOUT 是：

> ESS1 本地滤波器向后面的变压器/线路/微网网络送出的输出电流。

它位于：

```text
ESS1_Control
→ F8 Voltage Loop Feedforward
→ F20 IOUT Dynamic Conditioner
```

原作用：

```text
提前告诉Voltage Loop：
网络本来需要多少电流
```

帮助 ESS1 快速建立正确工作点。

已经证明：

```text
持续RAW动态IOUT反馈
→ 3.4 Hz负阻尼

持续0.5 Hz slow IOUT反馈
→ 更慢低频失稳

捕获成固定bias
→ Gate A稳定
```

所以：

> **“持续动态 IOUT 不应该进入GFM电压环”这个根因已经处理清楚。**

但是：

> **当前 MODE1 不是最终策略实现。**

因为当前它按：

```text
t = 6.2 s
```

固定时间捕获。

这是 Gate A 专用试验逻辑。

最终应改成：

```text
状态触发 capture
```

# 8. 最终IOUT bias应该什么时候捕获

```text

↓

↓

↓
capture IOUT operating-point bias
```

不是永远6.2 s。

更合理的是：

```text

↓

↓
在GFM接管/PCC打开的切换窗口
capture当前ESS1 IOUT作为bias
↓
孤岛后Voltage PI承担增量变化
```

这样 bias 对应的是：

> **切岛瞬间ESS1真实运行工作点。**

不是 Gate A 的死母线建压工作点。

但不是OpWrite坏了，也不是Reset把已有完整MAT删掉了。

- 基本步长 `Ts = 100 μs`
- Group26 / Group28：
  - `Decimation = 100`
  - `Nb_Samples = 1000`

因此：

`100 μs × 100 = 0.01 s / recorded sample`

1000个记录点需要约：

`0.01 × 1000 = 10 s`

V4在：

`t = 8.0 s`

- F3/F4/F20
- S12/S13
- handover逻辑
- PCC/GFM执行顺序

也就是说：

> 不会因为要补日志而把“8秒没READY”偷偷改成“10秒以后也可以READY”。

# 2026-08-28｜PB2-EXT V6：READY模式语义修正与下一轮正式切岛

## 1. 最新完整MAT已经证明什么

最新一轮V5不是“预平衡失败”。

完整Group26/28/29显示：

- PCC始终CLOSED；
- executed mode始终NORMAL；
- ESS1 GridOn始终为1，即ESS1仍是GFL；
- ESS1 Pref约0.2 pu量级，调节余量充分；
- PCC有功约5.37~7.44 s连续约2 s保持在±5 kW内；
- 同一阶段PCC无功接近0；
- 因此物理PREPARE条件实际上已经满足。

## 2. 为什么V5没有READY

V5还附加了：

`ESS1 final Droop < 0.5`

作为“ESS1仍是GFL”的条件。

这是不正确的模式语义。

当前设备接口真正决定GFL/GFM的是：

- `GridOn = 1` -> GFL
- `GridOn = 0` -> GFM

Droop在GFL状态下可以保留legacy值1，并不意味着设备已经进入GFM。

最新MAT恰好证明：

`GridOn=1, Droop=1`

可以同时存在，而：

- J1仍闭合；
- executed mode仍NORMAL；
- ESS1仍然是GFL运行。

因此：

> PREPARE阶段不能再要求Droop=0。

## 3. V6唯一控制语义修改

### NORMAL / PREPARE

判定ESS1仍GFL只检查：

`ESS1 GridOn = 1`

Droop只记录，不参与READY。

READY继续要求：

- `|Ppcc| <= 5 kW`
- `|Qpcc| <= 5 kvar`
- `|ESS1 Pref| <= 0.75 pu`
- J1 CLOSED
- final breaker command CLOSED
- executed_mode = NORMAL
- ESS1 GridOn = 1
- PCC频率正常
- 若Vab在线量有效，则PCC电压正常
- 连续0.5 s

### HANDOVER之后

仍然严格要求：

- executed_mode = ISLANDED
- J1 OPEN
- final breaker command OPEN
- ESS1 GridOn = 0
- ESS1 Droop = 1

也就是说：

> Droop没有被删除，只是从“切岛前GFL判据”移动回它真正有意义的“切岛后GFM执行确认”。

## 4. V6额外改进

每个PREPARE采样点都会直接打印：

- P
- Q
- ESS1 Pref
- GridOn
- Droop
- executed mode
- J1

若NOT READY，会直接打印原因，例如：

`|P|>5`
`|Q|>5`
`ESS1_not_GFL`
`mode_not_NORMAL`

以后不需要再靠MAT倒推哪条条件卡住。

## 5. 其它全部冻结

V6不修改：

- GFM底层结构
- Voltage/Current PI
- F2/F3/F4
- F8/F9/F10
- PWM/Converter
- S7+AGC
- F20逻辑
