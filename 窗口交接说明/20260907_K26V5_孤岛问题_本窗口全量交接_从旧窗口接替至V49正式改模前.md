# 5. Frame / MasterF：为什么以前要加，为什么现在不直接推翻

历史强化：

```text
AA15_PLL_EXEC_FRAME_HOLD
AA15_MASTER_FREQ_FRAME_CORE
MasterF broadcast
```

目的：

> 孤岛后五台 GFL 不再各自被脆弱的局部 PLL 动态拖走，执行角由主机频率形成共同参考，减少坐标漂移和中频耦合。

这确实改善了：

```text
初期电压
ESS1 频率
中频峰值
```

因此当时评价：

```text
必要强化
≠
最终稳定器
```

后来全量 V4.8 数据又揭示了更细的事实：

> **公共频率执行坐标可以存在，但“共同频率”不等于该坐标 d 轴永远对准实际母线电压矢量。**

这就是后面 V4.9 为什么不是简单“恢复五套 PLL”，而是：

```text
保留公共执行坐标
+
功率分量按实际电压方向解释
```


# 8. V4.5 / V4.6 后为什么锁到 Q PI

五台真实 Q 外环：

```text
Qerror = Qmeas - QrefEff
    ↓
PI regulator with anti-windup D1
Kp = 0.06
Ki = 2
limit = ±1
    ↓
raw q / base q current
    ↓
AA15_ISLAND_GFL_SUPPORT_MANAGER
```

电流内环历史基线：

```text
Kp_I = 0.30
Ki_I = 20
```

0.25 Hz 处 Q PI 理论接近积分器。

从正式数据反解：

```text
PV1   BaseIq/Qerror ≈ 1.518  phase ≈ -73.88°
PV2                       ≈ -73.88°
ESS2   ≈ 1.589             ≈ -76.91°
EV1    ≈ 1.429             ≈ -73.84°
EV2    ≈ 1.429             ≈ -73.83°
R² ≈ 0.998
```

这不是“Q 侧看起来可疑”，而是：

> **Q PI 的实际动态和理论 PI 在主模态附近高度一致，而且幅值远大于外围 support。**

同时早期该模态建立时：

```text
CurrentLimit = 0
ModIndex 尚未到 0.98
```

所以当时正确因果链是：

```text
live Q PI / aggregate Q-port slow mode
↓
电压摆幅逐渐扩大
↓
后期才进入 ModIndex 饱和
↓
跟踪进一步恶化
```

在孤岛阶段主要按：

## 19.2 功率公式已用数据验证

当前项目符号近似：

\[

\]

\[

\]

当 `v_q` 很大时：

```text
原本“有功 d 电流”
会通过 v_q * i_d
```

## 39.4 完整执行残差


-

-

\]

残差：

```text

-
requested PI
```

上一拍成对保存后进入下一拍。

## 39.5 为什么用上一拍 residual

当前积分是：

```text
discrete trapezoidal
```

当拍 residual 直接闭环可能形成：

```text
algebraic loop
```

所以：

```text
上一拍 command / FF / residual
```

成对保存。

不是：

```text
上一拍 applied
-
当前拍 FF
```

避免时序混用。

其旧输出 destinations：

```text

```

即：

```text

```

但还保留其 shadow 输出作为：

```text
first-sample/state matching reference
```

这是为了无冲击接管，不是让两套 PI 同时抢控制权。
