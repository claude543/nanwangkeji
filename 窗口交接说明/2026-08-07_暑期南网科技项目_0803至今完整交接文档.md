# 13. 通过旧模型对比发现的物理问题

## 13.1 PCC测量边界

8月3日早期J1阶段曾经按另一种理解放置Load1/Load2。

8月6日重新以老师标准模型为最高基准后，最终确认：

```text
六设备网络
→ PCC V-I Measurement
→ Load1 / Load2 + PCC breaker + Grid
```

因此当前标准模型口径下：

> **PCC P主要反映六设备总交换功率，不把Load1/Load2计入当前这一路设备总功率口径。**

这个最终结论覆盖8月3日早期的临时拓扑理解。

# 20. AGC为什么先PV动、后面EV也动？

基础算法只有总PCC反馈。

15 s投入时：

```text
Ptarget = -100
Ppcc ≈ -120
dP = +20 kW左右
```

因此：

```text
dP > 0
→ 先增加PV
```

PV有：

```text
65 + 65 = 130 kW
```

的可用上限，所以不是PV能力不足。

但实际物理系统有：

- 控制器动态；
- Droop；
- Supervisor；
- PCC纹波；
- 1 s离散更新。

后续PCC会在目标附近穿越。

一旦：

```text
dP < 0
```

算法就按负向顺序：

```text
EV增加充电
→ ESS充电
→ PV降低
```

因此看起来会出现：

```text
PV已经上升
同时后续EV又变得更负
```

这是不同AGC周期先后发生的结果，不是同一周期同时错误分配。

# 35. FC16失败为什么不能推进AGC状态？

AGC有历史状态。

如果：

```text
算法先把历史状态推进
↓
FC16写板失败
```

那么现实中：

```text
命令没有成功发布
```

但算法内部却以为：

```text
命令已经执行过
```

这会造成控制状态失配。

所以必须：

```text
正式state
→ 复制candidate_state
→ candidate上算AGC
→ 生成候选报文
→ FC16成功
→ 才提交candidate_state
```

FC16重试：

```text
重复同一候选报文
重复同一candidate_cmd_seq
```

不得：

```text
再次算AGC
再次加CMD_SEQ
```

这一规则以后V4必须保持。
