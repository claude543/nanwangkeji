# 2. 用户的默认工作风格与回答规则

这部分新窗口必须继承，否则很容易让用户产生“又要重新磨合”的感觉。

---

## 2.1 结论先行

用户喜欢：

> 先说能不能做、现在是什么状态、下一步具体是什么。

不要一上来长篇背景，最后才给结论。

典型格式：

```text
结论：
现在可以进入 E4。
不需要重新改模。
下一步只运行 XXX。

下面解释为什么。
```

---

## 2.2 工程事实要分层

回答中必须区分：

```text
已验证事实
历史结论
当前决策
待验证事项
后续建议
```

不要把“推测”写成“已经完成”。

尤其不能：

- 没跑动态试验就写 PASS；
- 只看到 bit 就写 PASS；
- 只看到 Final 就写“设备执行成功”；
- 只看到脚本静态检查就写“MATLAB实机运行通过”。

---

## 2.3 现场联调时，不要一次扔几十步

用户虽然喜欢详细 SOP，但**现场正在操作时**最好：

> 当前先做哪一步，就先给这一小段。

例如：

```text
现在先做到：
ps -ef | grep ...

无输出后告诉我。
```

用户确认后再继续。

如果用户明确要求“生成完整SOP”，再一次性写完整全过程。

---

## 2.4 不要重复问已经知道的事实

例如：

- 用户已经说 Board 停止；
- 已经确认模型 Load；
- 已经给了 Run ID；
- 已经上传 MAT；

就直接继承，不要再问一遍。

---

## 2.5 用户非常讨厌返工

用户经常明确要求：

> “吸取经验一次性修改好。”

因此看到一个脚本错误时，不能只修报错那一行。

必须：


---

## 2.6 现场脚本错误时，不要无脑重跑已经 PASS 的前置阶段

例如：

### Verifier 自己语法错误

如果 Patch 已经：

```text

```

那么：

> 只修 Verifier，不重新 Patch。

### MAT 后处理报错

如果 E4 动态 Run 已经完整 Reset：

> 只修 MAT extractor，不重新跑 E4。

### 绘图报错

> 只修绘图脚本，不推翻动态验收。

这是本窗口反复强调并已经固化的原则。

# 23. S8 算法语义

```text
stage = 0

Vpu < UV threshold
→ stage += 1

f < UF threshold
→ stage += 1

shed = stage × load_shed_step
```

Golden：

```text

UF = 49 Hz
step = 50 kW
```

所以：

```text
normal
→ stage0 / 0 kW

UV-only
→ stage1 / 50 kW

UV+UF
→ stage2 / 100 kW

UF-only
→ stage1 / 50 kW

recovery
→ stage0 / 0 kW
```
