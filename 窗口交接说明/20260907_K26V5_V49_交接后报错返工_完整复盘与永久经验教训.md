# 1. 先给最终结论：这段时间实际发生了三类不同的问题

不要把所有 Build 失败混成一个问题。

## 1.1 第一类：V4.9 原始工程集成缺陷——真实存在

纯 V4.9 第一次 RT-LAB Build 的明确错误是：

```text
K26_V5/SM_Master/OpComm3
Signal of port #2 is a matrix.
Only [1 x 1] and [1 x n] signal dimensions are supported.
```

后来将正式 V4.8 与用户上传的“纯 V4.9”逐 XML / Stateflow 对比后，锁定到：

```text
AA15_V49_CURRENT_EXECUTION_ADAPTER/CORE

y = nan(27,1)
      ↓
明确 27×1 column matrix

UNPACK = [2 2 23]
      ↓
2×1 / 2×1 / 23×1 grouped outputs
```

ESS1 的 adapter output1/output2 又进入：

```text
ESS1_Control/AA15_D1_FAST_DIAG_MUX18
input7 / input6
      ↓
ESS1_Control output3
      ↓
SS_Slave2/Mux input5（26维）
      ↓
legacy width30
      ↓
AA15_V48_RETURN_APPEND_MUX [30 3]
      ↓
width33
      ↓
Memory
      ↓
SM_Master/ESS_Pmeas_vec2_from_SS
      ↓
OpComm3 input2
```

这是真实的 V4.9 工程集成缺陷。

它不是 q-bias、功率方向修复或完整执行残差控制方程错误，而是：

> **MATLAB Function 列矩阵输出经 grouped Demux 后，保留了 matrix dimensionality；旧 Verifier 只查 width，没有查 vector-vs-matrix dimensionality。**

> **彻底放弃 21 个 Reshape workaround，回到纯 V4.9，修第一污染点。**

# 3. 第一步错误：Formal Patch R1 把整个 SLX raw SHA 当成硬门

## 3.1 R1 做了什么

正式 V4.9 Patch R1 要求：

```text
expected raw SLX SHA =
cbe0bdaca52d860b7c528840785c86bd05ff47d8bd808287a6bd30f296f6d4ce
```

用户实际运行：

```text
actual =
5ab4ecf7ce444f74c459cef6a90a9be0498dd219b749d6779bf657d63399cb61
```

于是：

```text
PATCH ABORT
```

发生在任何正式编辑之前。

## 3.2 这里什么是对的

事务行为是对的：

```text
身份不符
→ 编辑前退出
→ 没有留下半改模型
```

因此 R1 没有破坏正式模型。

## 3.3 这里什么是错的

错误在于把：

```text
整个 .slx 文件容器 raw SHA
```

等同于：

```text
控制语义身份
```

`.slx` 本质是 ZIP 容器。

重新保存、内部 metadata、打包顺序变化都可能改变 raw SHA。

因此：

```text
raw SHA 不同
≠
控制图一定不同
```

## 3.4 永久经验

以后：

### raw SHA

用于：

```text
记录
提示
快速识别
```

### 真正 hard identity

必须使用：

```text
关键 MATLAB Function 正文 hash
关键 block 存在
关键参数
关键 source/destination
关键 compiled width/dimension
关键状态/接口
```

即：

> **文件容器身份和控制语义身份必须分开。**

# 4. Formal R2：正确修了 raw SHA，但身份硬门仍然不够完整

R2 把 raw SHA 降为提示，改为：

```text
q-bias function fingerprint
5 × manager fingerprint
5 × finalizer fingerprint
V4.9 adapter absent
critical module exists
strict compile
G26~G30 width
```

这比 R1 合理。

但后来复盘仍发现两个问题：

1. `assertV48CriticalConnectivity` 主要检查“block 存在”，不是完整逐端口 source/destination；
2. 某些 `assertScalarMaskValue` 如果 `get_param` 取不到参数会 `return`，不是 hard fail。

因此 R2 的“semantic hard gate”比 raw SHA 好，但仍没有完全达到项目自己规定的：

```text
先 connectivity
再名字
```

永久结论：

> **名字存在不是拓扑合同。以后正式 Patch/Verifier 必须同时冻结关键 source、destination、port number 和允许的唯一旁路。**

---

# 5. Verifier Dirty=on：我们没有在一开始把“磁盘模型”和“内存模型”彻底分开

用户运行 R2 Verifier：

```text
Verifier requires Dirty off.
```

这句话本身没有错。

Verifier 应验证：

```text
已经保存到磁盘的正式模型
```

而不是：

```text
内存里还有未保存变化的模型
```

但问题是前后工作流没有把以下身份一次写清：

```text
RT-LAB 当前模型条目
MATLAB 当前目录
当前 loaded block diagram
get_param(Model,'FileName')
磁盘 SLX
backup SLX
```

后来这直接发展成更严重的“用户在 RT-LAB 点的是 PRE 模型，但 Patch 实际改主 K26_V5”问题。

永久经验：

> **任何模型写脚本必须把绝对文件路径作为一等公民。**

最低要求：

```matlab
targetFile = canonical absolute path
loadedFile = get_param(MODEL,'FileName')
assert(canonical(targetFile) == canonical(loadedFile))
```

而不是只写：

```matlab
MODEL='K26_V5'
```

# 7. 最大的草率点：没有先找“第一污染点”，直接给 21 个位置加 Reshape

## 7.1 当时的思路

看到：

```text
OpComm3 port2 matrix
```

就想：

```text
把所有可能的 vector output 都 reshape
```

于是：

```text
6 current adapters × 3 outputs
+
3 OpComm boundary
=
21 Reshape
```

## 7.2 为什么这个思路不合格

因为它没有回答：

```text
PV 为什么没先报？
EV 为什么没先报？
为什么只有 ESS port2？
哪一条新信号刚好进入 ESS legacy return？
```

真正根因定位应该利用错误的“非对称性”。

只有 ESS port2 先报，说明最强搜索方向是：

```text
ESS1-specific path
```

而不是：

```text
所有六台输出
```

## 7.3 永久经验

面对跨分区/通信错误：

```text
终点错误
→ 反向 trace
→ 找第一个与已知成功版不同的位置
→ 只修第一差异
```

不能：

```text
终点错误
→ 大面积加兼容块
```

# 12. 正确的源头修复：不再 Reshape，而是 scalar Demux + classic Mux

最终确定：

```text
CORE y 27×1
↓
UNPACK 27 scalar
↓
scalar1,2 → Mux(2)
scalar3,4 → Mux(2)
scalar5..27 → Mux(23)
```

为什么这样做：

1. CORE 数值算法不变；
2. 27 项顺序不变；
3. classic Mux 输出是历史模型长期使用的一维 Simulink vector 语义；
4. 不在通信边界叠转换；
5. 六台统一从源头消除 matrix leakage；
6. ESS1 fastdiag 不再被 matrix dimensionality 污染。

这次的设计思想是正确的：

> **修第一污染点，不修最后报错点。**

# 18. 这段返工中最应该承担的错误

以下几项属于明显可避免错误：

## 18.1 交接文档生成后没有立即维护“版本废止表”

上一份交接还写：

```text
R1 final
```

随后 R2 已经替代 R1。

新窗口因此自然会认为：

```text
交接文档和当前包冲突
```

以后每次正式脚本 revision 必须同步写：

| 版本 | 状态 | 原因 |
|---|---|---|
| R1 | OBSOLETE | raw SHA hard gate 过严 |
| R2 | HISTORICAL FORMAL PATCH | 取代 R1 |
| Dimension Fix R1/R2 | OBSOLETE | 症状级 Reshape workaround |
| ARTEMIS Vector Fix | OBSOLETE | workaround 参数切换仍失败 |
| Portable R3 | CURRENT ENGINEERING FIX | 从源头恢复 1-D Mux |

---

## 18.2 过早承诺“一次性修改好”

没有 RT-LAB Build 前，任何说：

```text
这次已经一次性修完
```

都过度。

正确口径：

```text
当前已知错误已按证据修复
+
模块级验证通过
+
仍需 RT-LAB Build 做 integration verification
```

“一次性”应该表示：

```text
在修改前尽可能扫清可预见接口问题
```

不是：

```text
保证不存在任何运行环境/第三方工具限制
```

---

## 18.3 错误地把所有 vector outputs 都当嫌疑

真实错误只报：

```text
OpComm3 port2
```

应该先利用：

```text
ESS 特异性
```

而不是全六台、全边界一起动。

---

## 18.4 验证器只查 width，没有查 dimension type

以后任何 RT-LAB communication boundary：

```text
width
```

和：

```text
dimensionality
```

都要区分。

例如：

```text
width = 33
```

可以是：

```text
1-D length33
33×1 matrix
1×33 matrix
```

对 Simulink width 都是 33，但对 RT-LAB 不同。

---

## 18.5 普通 Simulink compile 和 RT-LAB Build 的职责混淆

普通 compile 能验证：

```text
Simulink graph
MATLAB Function compile
width
datatype
algebraic loop
```

不代表：

```text
RT-LAB separation
OpComm restrictions
ARTEMIS separation
target code generation
```

都成立。

以后四层验证明确：

```text
纯数值
↓
scratch Simulink
↓
正式 Simulink semantic/graph verification
↓
RT-LAB Rebuild
```

不能把第三层伪装成第四层。

```text

```

脚本文件可 `addpath`。

先：

```text
successful baseline
vs
failed candidate
```

做：

```text
minimum-delta diff
```

找到：

```text
first semantic divergence
```

才编辑。

## 19.5 每个跨边界向量都写 shape contract

例如：

```text
name
element order
width
dimension semantics
datatype
sample time
producer
consumer
```

不能只写：

```text
width=33
```

尤其：

```matlab
nan(N,1)
zeros(N,1)
```

会声明 column matrix。

如果外部合同要求 classic Simulink vector：

优先：

```text
scalar ports
→ Mux
```

而不是在远端补 Reshape。

```text

Memory
```

进入 RT-LAB task boundary 时，必须基于已成功结构增量修改。


对于老 Windows/老工具链：

```text
优先短根目录

```

```text
长说明性版本号
```

直接用作 RT-LAB active model basename。

版本信息放：

```text
manifest
TXT/JSON
Git
```

不放模型文件名里无限增长。
