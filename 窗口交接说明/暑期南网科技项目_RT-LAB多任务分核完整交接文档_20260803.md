# **1. 项目目标、环境与原始瓶颈**

项目最终目标不是单纯让模型通过Build，而是建立完整的硬件在环闭环：

> RT-LAB / OP5700：  
> 2 PV + 2 ESS + 2 EV 六逆变器电气模型  
> \+ 六套本地变流器控制器与PWM  
> \+ PCC/Grid测量

> Build → Load → Execute → 100 μs实时性 → 电气等效  
> → Modbus闭环 → 延时/丢包/中断恢复 → 论文方法试验

## **1.3 为什么必须做任务级分核**

早期尝试在单个SM内部使用SSN多核，三逆变器模型无论Cores=1还是Cores=4均约700 μs；六逆变器约970–981 μs，远大于100 μs。说明“一个实时任务内部SSN分组”没有得到有效加速。

因此改为真正的RT-LAB任务级分核：主网和PCC留在SM，不同资源设备放入独立SS，普通信号通过OpComm跨任务，物理电气连接通过ARTEMiS差分Stubline解耦。

## **1.4 曾经走过但被否定的物理拆分路径**

- 普通三相变压器 + 普通三相Stubline：离线等效基本可用，但Stubline自动电容引入约2.04 Mvar额外无功；RT-LAB仍判为串行任务。

- 把变压器漏抗迁移到线路、增加Memory/Unit Delay、删除普通通信、改变OpComm参数、清缓存等，均未解决原S3的serial依赖。

- 最终改用官方artemis_Transfo_StublineRT母版：每台设备使用三台单相两绕组变压器 + 三条差分Stubline，才形成RT-LAB可识别的任务级电气边界。

# **2. 原S3失败模型与重建策略**

## **2.1 原S3结构**

原完整迁移模型（通常称S3或EV2_OfficialBase_S3）已形成：

- SM_Master：主电网、PCC、负荷、六套高压侧变压器/PMIO、AGC、策略、通信；

- ss_ev、ss_ess、ss_pv：每个SS各两台设备；

- SC_Console；

- 顶层18条差分Stubline；

- Ctrl+D能够显示1个主网3开关网络和6个独立6开关逆变器网络。

但RT-LAB Build在任务通信优先级校验阶段失败，典型表现是SS等待SM当前步数据，形成serial依赖。删除三组普通24维通信、把SS内OpComm改为零输入、加入Memory/Unit Delay后错误仍然存在，因此无法继续把原S3当作修补母版。

## **2.2 关键决策：不再修S3，改为从已成功单EV母版逐步恢复**

> **重建原则：** 每轮只增加一个可解释的结构变量；成功后冻结并作为下一轮母版；失败后立即停止，只比较本轮增量。这样每次Build都能排除一类原因。

新的路线是：官方母版 → 完整单EV → 逐步增加SS和设备 → 恢复控制链 → 恢复24维通信 → 恢复正式公共电网 → 恢复正式测量 → 再恢复上层控制与Modbus。

# **3. 物理边界、普通通信与测量标签的统一规则**

## **3.1 每台设备的差分Stubline边界**

每台设备三相各用一条差分Stubline，共3条。每相对应一对PMIO端口：

> A相：奇数端口（上端） + 偶数端口（下端）  
> B相：下一对奇/偶端口  
> C相：下一对奇/偶端口  
>   
> 示例（第6台设备）：  
> SM 31/32 → A相Stubline → SS_Slave3 7/8  
> SM 33/34 → B相Stubline → SS_Slave3 9/10  
> SM 35/36 → C相Stubline → SS_Slave3 11/12

画布位置没有电气意义，端口编号、奇偶方向和实际连线才有意义。物理拓扑不再用一键脚本自动复制，因为Simulink物理端口分支和跨子系统复制容易失败；采用手动复制已连好的完整支路，脚本只做名称、端口号和检查。

## **3.2 单设备12维控制向量**

> device_io12 = \[  
> Vabc(3);  
> Iabc(3);  
> Fref;  
> Vref;  
> Droop_On;  
> Pref;  
> Qref;  
> GridOn  
> \]

两个同类设备在SM中先各自形成12维向量，再按“设备1、设备2”的顺序合成24维。

## **3.3 每组24维通信结构**

> SM_Master：  
> device1_IO_Mux12 ─┐  
> ├→ Group_Mux24 → Memory(zeros(24,1)) → Outport  
> device2_IO_Mux12 ─┘  
>   
> 顶层：  
> SM Outport → 对应SS Inport  
>   
> SS：  
> Inport → OpComm(nbport=1, st=Ts, subsys_rate=Ts)  
> → Group_Demux \[12 12\]  
> → 两个 Device_Demux \[3 3 1 1 1 1 1 1\]  
> → 两套本地控制器

Memory放在SM组输出前，用于跨任务时序解耦；三组通信分别进入三个SS，每个SS只有一条24维普通输入。

## **3.4 当前三组通信顺序**

| **组** | **24维顺序**             | **目标SS** |
|--------|--------------------------|------------|
| EV     | \[EV1_IO12; EV2_IO12\]   | SS_Slave   |
| ESS    | \[ESS1_IO12; ESS2_IO12\] | SS_Slave2  |
| PV     | \[PV1_IO12; PV2_IO12\]   | SS_Slave3  |

## **3.5 测量标签统一规则**

- 所有复制出来的Three-Phase V-I Measurement外层Mask，凡不再依赖隐藏标签者，SetLabelV=off、SetLabelI=off。

- 不要进入Mask内部修改Goto/From；只修改外层Mask参数。

- 当前J2成功模型中，SM侧8个重点测量块均已确认off/off：J2_Grid_VI、PCC的Three-Phase V-I Measurement3、六个prim\_\*。

- J2中Grid/PCC显式输出实际单位V/A，因此Vpu=off、Ipu=off；用普通Vabc/Iabc连线接测量子系统。

- SS_Slave2和SS_Slave3中复制的低压测量块和inv测量块均应off/off。SS_Slave中的原成功母版测量块保持已验证设置，不无故改变。

## **3.6 命令与操作习惯**

> mdl = bdroot(gcs);

- 任何脚本前先点击当前目标模型画布；不得写死旧模型名。

- Build前固定执行：静态检查 → Ctrl+D/update → save_system → RT-LAB Rebuild All。

- 每次成功版本保存独立SLX和完整Build文件夹；失败版本也保留日志和分离模型用于比较。

- 用户要求每轮说明：本次改了什么、为什么改、Build成功/失败说明什么、下一步是什么。

# **11. AGC MATLAB Function / Stateflow异常的逐步排查**

## **11.1 为什么错误与MATLAB Function有关**

MATLAB Function在Simulink内部由Stateflow EMChart对象管理。RT-LAB在模型分离时会“修复/恢复”Stateflow对象。日志中的乱码“###恢复的 Stateflow 图###”就是该临时修复容器。

## **11.2 已完成的对照试验**

| **试验**            | **做法**                                                          | **结果**             | **排除内容**                                         |
|---------------------|-------------------------------------------------------------------|----------------------|------------------------------------------------------|
| J3_BASIC_CONTROL    | 从供体复制AGC和Supervisory，正式连接测量和设备指令                | Signals Database失败 | 不是简单维度问题（修正后仍失败）                     |
| J3_BASIC_CONTROL_R1 | 新模型名、全新目录、关闭重开后Rebuild                             | 同样失败             | 不是Build缓存或旧分离目录污染                        |
| T1B fresh Function  | 从J2新建MATLAB Function，仅写入AGC代码，15入9出，输出全Terminator | 同样失败             | 不是原AGC块旧Chart ID、不是Supervisory、不是设备扇出 |
| 手动新建Function    | 手动拖块、手动粘贴代码、手动接Constant/Clock/Ppcc/Terminator      | 同样失败             | 不是自动脚本创建EMChart造成                          |
| AGC Wrapper         | 把AGC放入普通Subsystem，形成15入9出接口，外部终止                 | 同样失败             | 不是AGC直接位于SM第一层或缺少封装造成                |

## **11.3 日志中的决定性证据**

在生成SS_Slave和SS_Slave3分离模型代码时，日志出现类似路径：

> ...\_ss_slave3/  
> \###恢复的 Stateflow 图###/  
> SM_Master_Subsystem_T1C_AGC_Manual_repaired_1

并连续警告该“修复后的AGC”15个输入和9个输出均未连接。该AGC本应只属于SM，却被RT-LAB修复流程放入多个SS分离模型。随后Signals Database查找恢复容器时失败。

## **11.4 当前最准确的故障链**

> 完整多任务模型中，AGC MATLAB Function位于SM_Master  
> → RT-LAB分离SM/SS/SC  
> → 识别MATLAB Function为Stateflow EMChart  
> → 尝试修复/恢复Chart  
> → 修复副本错误或冗余进入多个SS分离模型  
> → 副本15入9出悬空  
> → 所有C代码仍能生成  
> → 参数数据库成功  
> → Signals Database扫描恢复对象  
> → 找不到“恢复的Stateflow图”临时子系统  
> → Build失败

## **11.5 非致命警告**

- PV1_Control内部块路径含“abc -\>dq0”“pi//2 delay”等特殊字符：随后C代码成功，当前不是根因。

- 分离模型中From找不到Goto：需要后续清理，但J2成功且本轮C代码继续生成，不是当前停止点。

- prim_EV1或部分V-I输出未连接：只是显式输出未被使用的警告。

- 最终“Error generating C code for ss_slave3”是汇总性表述，不能据此判断SS3/PV1失败。

## **11.6 当前不能下的过度结论**

> **重要：** 尚不能说“RT-LAB分核完全不支持MATLAB Function”。J2成功模型中的设备控制器已经包含代码模块并能Build。当前只确认：新增到SM的完整AGC Function会可重复触发恢复/Signals Database异常。

# **13. 当前问题是否能解决、有哪些技术路线**

## **13.1 项目整体可以继续**

当前问题是上层AGC在RT-LAB分离工具链中的承载形式异常，不是六逆变器分核路线失败。J2成功母版已经覆盖项目最困难的电气实时化、控制链和通信骨架。项目有多条可行绕行路线。

## **13.2 路线A：AGC放到外部控制板（与最终目标最一致）**

> RT-LAB：六逆变器 + PCC测量 + 六路状态上送 + 六路Pref接收  
> 外部板：AGC + 状态重建 + 策略 + 通信异常管理

优点：避免SM中的MATLAB Function分离问题，减少SM计算负担，并与最终HIL闭环架构一致。缺点：板端程序与Modbus接口必须同步完善。

## **13.3 路线B：AGC改为纯C封装**

保留AGC算法但不使用MATLAB Function/EMChart，采用C S-Function、Legacy Code Tool或RT-LAB支持的C/C++接口。适合保留RT-LAB内部闭环基线，也便于与板端AGC对照。

## **13.4 路线C：简单模块改用标准Simulink块**

- PVmax：Clock + 1-D Lookup Table + Gain/Saturation；

- SOC：Pess + Gain + Discrete-Time Integrator + Saturation；

- 简单状态/限幅/选择逻辑：Switch、Unit Delay、Saturation等。

15种策略和复杂Modbus状态机不宜盲目全部重画，可在T0判定后决定逐个Function测试、转纯C或转板端。

## **13.5 是否需要科梁/OPAL-RT协助**

若目标是保留现有MATLAB Function形式并让RT-LAB 2024.1.1.38在1SM+3SS分离模型中正常Build，建议由科梁/OPAL-RT确认已知缺陷、补丁、版本建议或关闭/修复Signals Database恢复扫描的方法。
