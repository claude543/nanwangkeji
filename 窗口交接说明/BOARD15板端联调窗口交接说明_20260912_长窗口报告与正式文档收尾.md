## 1.2 系统拓扑

```text
2 PV + 2 ESS + 2 EV
= 六台变流器
```

- ESS1为唯一GFM；
- 其余PV1/PV2/ESS2/EV1/EV2为GFL；
- 非孤岛BOARD15验收期间PCC保持并网闭合。

## 1.3 PCC方向

这是所有解释的硬约束：

```text
PCC P > 0
= 微电网向上级电网送电

PCC P < 0
= 微电网从上级电网进口
```

EV：

```text
EV = Electric Vehicle（电动汽车充电负荷/资源）
P_EV < 0 = 充电
越负 = 充电功率越大
```

- 需要更明确的“控制前基线 → 策略投入 → 资源响应”。

## 5.3 E2-R2/R3的Reset和MAT问题

长窗口约82 s，5组高频MAT总体量超过约500 MB。

一次运行在所有策略、安全退出都完成后，final Reset出现error17：

```text
RT-LAB detected that model did not reset correctly
cleanup of processes left running was performed
```

旧异常处理又盲目第二次Reset，导致：

```text
error22 model not loaded
```

结论：

```text
策略运行完成
≠
最后Reset清理阶段完全正常
```

后续规则冻结为：

- final cleanup Reset错误与“策略运行失败”分开；
- error17若明确说cleanup already performed：
  - 记录 `RESET_CLEANUP_WARNING`
  - 不再第二次Reset；
- 未知Reset错误仍失败。

## 5.4 原始MAT真正损坏

E2-R3 Run：


```text

但只到约78.27 s

G27 = 49×0
G29 = 47×0
G30 = 129×0
```

文件甚至有几十MB体积，但精确变量是0列 / load失败。

这一步非常关键：

> 不能再修“MAT识别脚本”去强行读取坏文件。

最合理推断是：

```text

→ 部分OpWrite最终flush/close失败
```

这个因果高度吻合，但不是100%单独证明。

## 5.8 S4为什么这次主要是ESS动作

本轮S4投入前：

```text
EV1/EV2已经约 -1 pu/台
→ 基本满充，无法继续增加充电

PV约0.65 pu/台
ESS约+0.845 pu/台放电
```

负向dP资源优先逻辑：

```text
EV增加充电
→ ESS向充电方向/少放电
→ PV降低
```

EV已无裕度，因此跳过EV；ESS从大放电降到小放电就已经提供足够负向调节，所以不需要继续削PV。

这不是“S4规定只用ESS”，而是本轮工作点下的资源裕度结果。

## 5.9 S10周期计划的准确含义

```text
当前计划点 → cmd10滚动PCC目标
```

执行前转换：

```text
dP = S10 target - current PCC
```

本次报告只验证：

```text
单个计划时段的板端真实闭环
```

不能写成：

