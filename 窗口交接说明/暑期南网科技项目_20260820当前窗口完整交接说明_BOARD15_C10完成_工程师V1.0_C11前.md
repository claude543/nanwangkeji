# 十一、C08：S15 Resynchronization（重同步恢复）迁移

## 11.1 FINAL S15状态

```text
0 IDLE（空闲）
1 RESYNCHRONIZATION（重同步）
2 RECLOSE_HOLD（重合闸保持）
3 CLEAR_ISLAND_LATCH_WAIT（等待清孤岛锁存）
```

默认：

```text
ΔV ≤ 0.10 pu
|Δf| ≤ 0.20 Hz
|Δθ| ≤ 10 deg
sync stable = 0.50 s
reclose hold = 0.20 s
Ktheta = 0.005 Hz/deg
Kdf = 0.50
Fref trim max = ±0.20 Hz
```

源公式：

```text
Δf = grid_f - pcc_f

ΔV_pu =
abs(pcc_v-grid_v)/max(abs(grid_v),1)

Δθ =
wrap180(grid_phase-pcc_phase)

Fref trim =
clamp(Ktheta*Δθ + Kdf*Δf)
```

```text
requested（请求）

```

特别：

```text
PCC close request
↓
FC16成功
↓
等待40122确认Breaker Closed
↓
才开始0.20 s reclose hold
```

新发现并关闭：

### 问题1：40029主表仍残留旧DOMAIN四位说明

虽然V0.5 Bitfields页已经改对，但 `Command_Frame（命令帧）` 页40029仍写旧：

```text

bit1=Q
bit2=MODE

```

### 问题2：未来字段容易误认为当前要实现

V0.6在主表直接注明：

```text
当前BASELINE写0/默认
不要求当前实现execution-aware（执行状态感知）算法
```

### 问题3：100 ms不能补跑

正式：

```text
通信阻塞导致某周期>100 ms
→ CYCLE_OVERRUN
→ 当前周期完成后继续下一周期
→ 不并发第二个周期
→ 不恢复后快速补跑历史周期
```

### 问题4：snapshot_fresh ≠ heartbeat本次必须变化

`snapshot_fresh=1`：

```text
本次成功取得一份新的完整40101～40124读取结果
```

`RTLAB_HEARTBEAT`：

```text
用于判断RT-LAB数据源是否持续活跃
```

两者不是同一个概念。

### 问题5：signal_valid字段有效 ≠ 布尔量值必须=1

例如：

```text
PHASE_VALID字段正确读取到0
```

可以是：

```text
SIG_VALID_PHASE_FLAG=1
phase_valid=0
```

表示：

```text
字段读取有效，但当前相角不能用于同步
```

### 问题6：RETRY_PENDING的“相同”约束控制候选，不冻结工程字段

重试时必须相同：

```text
pending ControllerOutput
candidate CMD_SEQ
candidate state
```

但：

```text
BOARD_HEARTBEAT
COMM_STATUS
```

仍按当前工程循环更新。

### 问题7：当前帧LAST_FC16_OK只能代表上一已完成FC16

当前帧尚未发送，不能预知当前发送结果。

### 问题8：FC16失败不能立刻abort pending

真正：

```text
FC16失败
→ 不commit
→ pending保留

同一Snapshot
→ 可以retry

新Snapshot
→ Adapter作废旧pending并重算

measurement break
→ notify函数清pending
```

本地编码/帧形成失败才主动 `controller_abort_pending`。

### 问题9：初始化前必须先取得完整Runtime Config

启动：

```text
40101～40124 measurement
+
40124/402xx完整合法配置
```

都准备好后才：

```text
controller_init
```

### 问题10：所有UINT16序号允许自然回绕

包括：

```text
CMD_SEQ
CONFIG_SEQ
CONTROLLER_RESET_SEQ
RTLAB_HEARTBEAT
BOARD_HEARTBEAT
```

不能用：

```text
new > old
```

作为唯一“变化”判断。
