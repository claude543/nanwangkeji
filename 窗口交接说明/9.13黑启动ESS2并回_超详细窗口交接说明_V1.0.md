# 2. 为什么从完整孤岛问题转向黑启动

此前完整六机孤岛运行一直不能长期稳定。

我们没有直接继续“在六机同时在线状态里盲调”，而是转向黑启动，目的不是逃避原问题，而是：

```text
把复杂多机状态拆开
↓
先验证ESS1自己能不能形成孤岛
↓
再逐台恢复GFL
↓
观察到底是哪一步第一次失效
```

这是一个因果分解策略。

最终恢复目标本来就是：

```text
J1 OPEN
↓
五台非主GFL支路 OPEN
↓
ESS1 only GFM
↓
dead bus 0 → 10 kV / 50 Hz
↓
确认母线健康
↓
ESS2
PV1
PV2
EV1
EV2
逐台恢复
↓
每台先零功率接入
↓
稳定后再功率释放
```

关键原则：

> **请求阶段 ≠ 物理已经执行的阶段。**

每个设备恢复都应有：

```text
零功率
→ 准备资格
→ breaker close
→ 闭合后稳定
→ power release
```

不能：

```text
close + full power
```

同一拍盲接。

# 5. 改模前 ESS2 存在什么问题

在 ESS2 断路器打开时，旧 GFL 控制仍在运行。

以前 Stage1 数据已经发现：

```text
PrefEff = 0
QrefEff = 0
LegacyQref = 0
Vsupport = 0
```

但：

```text
ESS2 FinalIref ≈ 0.47~0.49 pu
并继续上升
actual current仅约0.03 pu
current tracking error约0.5 pu
q current controller output≈1.25
RawModDemand≈1.034
ModIndex≈1
headroom≈0
```

物理原因：

```text
breaker OPEN
↓
控制器仍在追某个它实际无法通过支路实现的状态
↓
控制误差持续存在
```

因此需要一个明确的：

```text
断开待并状态
```

让 ESS2 在断路器打开时：

```text
不积累无意义的电流误差
不把错误状态带到未来接回
```

这就是后面 `RestoreHold` 最初设计的合理来源。

# 6. ESS2 物理支路必须这样理解

当前真实储能2支路：

```text
ESS2_Converter
↓
EV1_inv
↓
L2
↓
C2 所在断路器内侧节点
↓
AA15_DIAG_AC_BREAKER_ESS2
↓
EV1_LV_Meas
↓
变压器 / 岛网
```

这里历史名称极其误导：

## `EV1_inv`

在 `SS_Slave2` 中实际上属于 ESS2。

它是：

```text
变流器端 / L2 之前的三相 V-I Measurement
```

不是 EV1。

## `EV1_LV_Meas`

同样是历史名称。

它位于：

```text
ESS2 breaker 母线侧
```

不是 EV1。

## 6.1 C2 节点为什么重要

真正 breaker 合闸时接在一起的是：

```text
C2 / L2后 / breaker内侧节点
```

与：

```text
breaker外侧 / 岛网母线侧节点
```

因此物理合闸电流本质取决于：

\[
i \sim \frac{v_{\mathrm{inner}}-v_{\mathrm{bus}}}{Z_{\mathrm{branch}}}
\]

即使：

```text
P*=0
Q*=0
Iref=0
```

也不能保证：

```text
实际电流=0
```

只要两侧瞬时电压不一致，就会有接入电流。

---

## 6.2 当前两组 G27 代理电压并不是 breaker 两端

G27：

```text
ch49:51 = Vinner proxy = EV1_inv
ch52:54 = Vbus proxy = EV1_LV_Meas
```

问题：

```text
EV1_inv 在L2之前
```

不等于：

```text
C2 / breaker-inner
```

而 C2：

```text
Measurements = None
```

所以当前没有真正：

```text
breaker-inner Vabc
```

直接测量。

---

## 6.3 之前“390 vs 0.008”不是巨大幅值错位

两组测量单位不同：

```text
EV1_inv：
Vpu=off
→ 直接伏值

EV1_LV_Meas：
Vpu=on
Vbase=60e3
→ 标幺瞬时相电压
```

单位还原后，11~12 s 基波拟合约：

```text
converter proxy：
391.6 V peak

bus proxy：
392.3 V peak

phase difference：
约2.7°
```

因此：

```text
5×10^4 幅值差
```

主要是单位误读。

但：

```text
代理点幅值接近
≠
C2 breaker-inner真实节点已匹配
```

这条以后不能再混。

## 16.1 “匹配模式”是什么

不是新控制器。

# 17. 当前已经确认的核心设计缺陷

问题不是：

```text

```

```text

```


```text

↓
Current PI
↓
```


共同支持的设计缺陷。
