# 3. 一个必须补充的新风险：PLL看得到母线 ≠ breaker两侧电压已经同步

新窗口已经确认：

> ESS2在支路断开时，其PLL测量链结构上仍能看到变压器一次侧/岛网电压。

这很好，但必须避免从它推出：

```text
PLL locked
→ 可以直接合breaker
```

这是不成立的。

原因：

```text
PLL测到bus phase
```

只证明控制器知道：

```text
岛网相角/频率
```

不自动证明：

```text
breaker converter-side实际三相电压
```

已经与：

```text
breaker bus-side实际三相电压
```

一致。

历史hot reconnect失败恰恰提醒我们：

```text
converter/filter capacitor节点
```

可能在断开期间独立演化。

## 3.1 因此 ESS2 Canary 前新增一个必做的只读“Reconnect Readiness Audit”

在真正写 ESS2 hot reconnect Runner 前，下一窗口必须先确认：

1. `AA15_DIAG_AC_BREAKER_ESS2` 的确切电气位置；
2. breaker 左右两侧各是什么节点；
3. ESS2 `Vd/Vq`、PLL Vabc、converter/filter capacitor Vabc 分别取自哪一侧；
4. 当前 G27 / 在线 signal 是否能同时得到：
   - bus-side voltage；
   - converter-side voltage；
   - 或至少能构造 breaker 两侧电压差；
5. breaker OPEN 时，ESS2 PWM/Current Loop/Voltage Feedforward 实际在做什么；
6. `P/Q=0` 时 `FinalIref` 是否真的接近0；
7. converter-side电压是否自然跟随bus，还是悬浮。

### 冻结规则

```text
若不能证明breaker两侧接近可并条件
→ 不允许直接跑0→1热接回Canary。
```

因此本文虽然冻结 ESS2 Canary 的时间结构，但：

> **真正写 Runner 以前仍要完成这个“breaker两侧电压/控制状态”定向审计。**

这不是重新全面审计模型，只审 ESS2 这一条接回链。

# 4. ESS2 第一次接回时如何保证 P/Q 保持零？

## 4.1 旧窗口此前没有冻结唯一方案

旧交接只写：

```text
P/Q=0
→ breaker close
→ observe
→ next run release
```

没有明确：

```text
仅依赖S14 Stage1
还是
仅依赖<20s结束
还是
使用D2
```

所以这里必须补齐。

## 4.2 本文件现在冻结唯一方案：**D2硬压零 + 全程<20s**

第一轮 ESS2 hot reconnect Canary 必须采用双保险：

### 第一层：S14仍停留 Stage1

原 `Advanced_Strategy_Core`：

```matlab
elseif t > 20.0 && black_state < 2.0
    black_state = 2.0;
```

所以整个 Canary：

```text
必须在 t < 20 s 内结束
```

不允许进入原始 S14 Stage2 的 Pref 自动恢复。

### 第二层：D2从第一次 Execute 之前就启用

第一次 Execute 前：

```text
CFG_DIAG_ISLAND_PQ_OVERRIDE_ENABLE = 1
```

并至少：

```text
CFG_DIAG_P_SCALE_ESS2 = 0
CFG_DIAG_Q_SCALE_ESS2 = 0
```

为了防止其它物理断开设备内部出现任何非零P/Q控制，第一版建议干脆冻结：

```text
PV1 P/Q scale  = 0
PV2 P/Q scale  = 0
ESS2 P/Q scale = 0
EV1 P/Q scale  = 0
EV2 P/Q scale  = 0
```

其它四台本来就仍然物理OPEN，所以这不会改变Plant物理功率，只是形成第二道命令安全门。

### 这一层不能在 t=12 s 才打开

必须：

```text
PAUSED @ t=0
↓
D2 enable=1
五台P/Q scale=0
readback全部通过
↓
first Execute
```

这样即使：

- S14状态异常；
- Runner时间拖延；
- 其它Pref来源有残留；

ESS2在物理接回时仍然被 D2 限制为零P/Q命令。

## 4.3 Canary中 Python 不得直接写 ESS2 Pref/Qref

第一轮 Runner 唯一主动运行时动作：

```text
CFG_DIAG_AC_CONNECT_ESS2 : 0 → 1
```

不得同一轮再：

```text
改Pref
改Qref
改P/Q scale到非零
```

因此第一轮问的只有：

> **零功率GFL物理接回本身能否成立？**

# 5. ESS2 Hot-Reconnect Canary 的准确时间轴

旧窗口此前没有冻结绝对 `t_connect`。

本文件现在为了避免新窗口自行猜，冻结如下**第一版试验时间结构**。

> 注意：这不是“历史PASS参数”，而是从当前 Stage1 0→10kV 时间轴、S14 t>20边界和高频logger能力出发，新冻结的 Canary 试验合同。

## 5.1 前置条件

只有满足以下条件才允许写 ESS2 Canary Runner：

```text
A. 当前Stage1 R2 Runner已正常跑完
B. Stage1 DirectMAT已人工确认：
   ESS1确实形成并保持岛网
C. Overrun=0
D. ESS2 Reconnect Readiness Audit完成
E. 下一节所说的数值准入阈值已经由新窗口正式冻结
```

如果 A~E 任一项没有完成：

```text
不写/不跑ESS2 hot reconnect。
```

## 5.2 每轮都从 Reset / Load / t=0 重新开始

不要接着 Stage1 上一轮的11.4 s继续跑。

正式 Canary：

```text
Reset
↓
Load
↓
MODEL_PAUSED @ t=0
↓
所有初值写完+readback
↓
first Execute
```

原因：

```text
每轮实验必须有完整、可复现的初始状态。
```

## 5.3 冻结时间轴

### t = 0 ~ 0.5 s

```text
J1 OPEN
五台非主breaker OPEN
ESS1唯一GFM
GateA Vref=0
D2 enable=1
五台P/Q scale=0
```

dead-bus controller settling。

### t = 0.5 ~ 5.5 s

```text
GateA Vref：
0 → 10 kV
2000 V/s
```

### t = 5.5 ~ 10.5 s

```text
ESS1 10 kV自主hold
五台breaker继续OPEN
D2继续全零
```

### t = 10.5 ~ 12.0 s

专门的：

# `ESS2 PRE-CONNECT QUALIFICATION WINDOW`

持续1.5 s。

这里只观察，不做参数变化。

必须确认下一节冻结的 pre-connect gate。

### t = 12.000 s

模型应 PAUSED。

只有 pre-connect gate PASS 才执行：

```text
CFG_DIAG_AC_CONNECT_ESS2 : 0 → 1
```

然后：

```text
readback == 1
```

其余参数保持不变。

特别是：

```text
D2 enable = 1
ESS2 P scale = 0
ESS2 Q scale = 0
```

不能改变。

### 接回后的运行检查点

建议固定：

```text
12.005 s   +5 ms
12.020 s   +20 ms
12.100 s   +100 ms
12.500 s   +500 ms
13.000 s   +1.0 s
15.000 s   +3.0 s
```

每个点只读/记录：

```text
不调参
不释放功率
不接回其它设备
```

### t = 15.000 s

```text
PAUSED
不Reset
不把ESS2再OPEN
不接PV/EV
不释放P/Q
```

先跑 DirectMAT。

## 5.4 为什么选择 12 s / 15 s

不是物理定律。

只是当前第一版 Canary 的实验设计：

```text
5.5s建压完成
→ 5.5~10.5s继承Stage1标准hold
→ 再额外1.5s pre-connect资格观察
→ 12s合闸
→ 3s零功率观察
→ 15s结束
```

同时：

```text
15s < 原始S14 Stage2阈值20s
```

所以不会触发原始Pref恢复。

# 11. 五个物理断路器没有contact feedback，怎样定义“实际已闭合”？

## 11.1 当前事实

当前 SPS `AA15_DIAG_AC_BREAKER_*`：

```text
Measurements = None
```

没有独立：

```text
aux contact / contact feedback
```

因此：

```text
CFG_DIAG_AC_CONNECT_ESS2 = 1
```

严格只能证明：

```text
breaker control command/readback = CLOSE
```

不能称为：

```text
独立测得的机械触点闭合反馈
```

## 11.2 第一个 ESS2 Canary 不因此改模

第一次Canary采用两层证据：

### Command layer

```text
CFG_DIAG_AC_CONNECT_ESS2
0 → 1
SetParametersByName成功
readback=1
target event time记录
```

### Electrical continuity layer

合闸后看：

```text
ESS2 breaker两侧电压关系
ESS2 measured Id/Iq
Pmeas/Qmeas
PLL
Current PI
Vconv
ModIndex
母线响应
```

从电气连续性证明：

```text
设备已经实际被并入网络
```

因此第一轮准确措辞应为：

> **breaker command applied + electrical connection established**

不要写：

> **contact feedback confirmed**

## 11.3 Final integrated strategy是否需要新增status？

这里旧窗口此前没有冻结。

本文件现在冻结原则：

### 近期Canary

```text
不为了contact feedback单独Rebuild
```

### Final Physical S14 / BOARD15

至少要增加：

```text
final branch command / physical executor applied-state
```

作为正式状态反馈。

但注意：

```text
命令echo
```

仍然不是：

```text
mechanical contact measurement
```

如果甲方未来明确要求“触点真实反馈”，就必须：

- 检查 Three-Phase Breaker 是否可安全启用内部 measurement；
- 或另加可验证的电气状态判据；

**当前没有冻结要改 breaker Measurements。**
