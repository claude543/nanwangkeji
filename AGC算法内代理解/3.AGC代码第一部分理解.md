# AGC 代码第一部分理解——资源分配前

> 第三轮内化：基础 AGC 的总体结构、输入输出与运行节奏

这一轮先不急着钻进"光伏—储能—充电桩怎样分配"。先把整个 AGC 看成一个完整系统，理解：

```text
AGC处在什么位置
它接收什么
它保存什么
什么时候计算
什么时候不计算
计算结果怎样保持
最后输出什么
```

下一轮再分别进入 dP > 0 时的增功率分配、dP < 0 时的减功率分配、同类设备按裕度比例分配、remain 和 status 的变化。

---

## 一、AGC 究竟是什么

AGC 全称 **Automatic Generation Control（自动发电控制）**。

在传统大电网中，AGC 主要调节发电机有功功率，使联络线功率或频率满足目标。

在当前光储充微电网中，它更准确地承担：

> 根据 PCC 目标功率与 PCC 实际功率之间的偏差，把需要调节的总有功功率分配给光伏、储能和可控充电负荷。

它不是电流内环，也不是 PWM 控制器。

**完整控制层级**：

```text
上层给出PCC目标功率
        ↓
AGC计算总功率偏差
        ↓
AGC分配成6路设备功率指令
        ↓
设备本地控制器跟踪各自功率指令
        ↓
电气模型产生新的PCC功率
        ↓
重新反馈给AGC
```

AGC 就像一个"调度员"。

---

## 二、用一个调度故事理解 AGC

假设一个园区需要向外送电 200 kW，但当前实际只送了 150 kW。

那么还差：

```text
200 - 150 = 50 kW
```

调度员需要想办法增加 50 kW 净输出。

他有三类资源：

```text
光伏：如果还有剩余光照资源，可以多发电
储能：如果 SOC 足够，可以增加放电
充电桩：如果正在充电，可以暂时降低用电
```

调度员按既定优先级依次询问：

```text
先问光伏：你们还能增加多少？
不够，再问储能：你们还能放多少？
还不够，再降低充电桩负荷
```

AGC 代码就是把这个调度过程变成确定的数学步骤。

## 三、函数开头逐词理解

```matlab
function [Ppv1_pu, Ppv2_pu, Pess1_pu, Pess2_pu, ...
          Pev1_pu, Pev2_pu, agc_status, dP, remain] ...
    = AGC_Controller( ...
          t, P_target_kW, P_pcc_kW, ...
          Ppvmax1_kW, Ppvmax2_kW, ...
          SOC1, SOC2, enable, ...
          P_unit_kW, P_dead_kW, ...
          SOC_min, SOC_max, Ts_agc, ...
          PV_init_kW, EV_init_kW)
```

**AGC_Controller** = Automatic Generation Control Controller，自动发电控制器。

## 四、九个输出

### 1. Ppv1_pu、Ppv2_pu

| 缩写 | 全称 | 含义 |
|---|---|---|
| P | Power | 功率 |
| pv | Photovoltaic | 光伏 |
| pu | per unit | 标幺值 |

光伏 1、光伏 2 的有功功率指令标幺值。

示例：`Ppv1_pu = 0.6`, P_UNIT = 100 kW → 光伏 1 功率指令为 60 kW。

---

### 2. Pess1_pu、Pess2_pu

| 缩写 | 含义 |
|---|---|
| ess | Energy Storage System，储能系统 |

两台储能的有功功率指令标幺值。

**符号约定**：

```text
Pess > 0：放电
Pess < 0：充电
```

示例：`Pess1_pu = 0.4` → 储能 1 放电 40 kW；`Pess1_pu = -0.3` → 储能 1 充电 30 kW。

---

### 3. Pev1_pu、Pev2_pu

| 缩写 | 含义 |
|---|---|
| ev | Electric Vehicle，电动汽车/充电负荷 |

代码内部使用 `Pev` 保存正的充电功率，但最终输出时执行：

```matlab
Pev1_pu = -Pev(1) / P_UNIT;
Pev2_pu = -Pev(2) / P_UNIT;
```

**内部**：`Pev = 60 kW`（充电桩吸收 60 kW）

**外部**：`Pev_pu = -0.6`（系统接口约定"发电为正、负荷为负"）

---

### 4. agc_status

AGC 当前调节状态：

| 值 | 含义 |
|---|---|
| 0 | 无调节或偏差处于死区 |
| 1 | 正向调节（增加净输出），正常 |
| -1 | 反向调节（降低净输出），正常 |
| 2 | 需要增加净输出，但全部资源仍不足 |
| -2 | 需要降低净输出，但全部资源仍不足 |

正负号表示调节方向，绝对值 1 表示正常，绝对值 2 表示资源不足。

---

### 5. dP

```text
dP = P_target - P_pcc
```

单位：kW，有正负方向。

---

### 6. remain

剩余未完成的调节需求，始终取非负值：

```matlab
last_remain = max(rem, 0.0);
```

方向需结合 dP 或 agc_status 判断。

示例：

```text
dP = +80 kW, remain = 20 kW
→ 需要增加80，只完成60，还差20

dP = -80 kW, remain = 20 kW
→ 需要降低80，只完成60，还差20
```

|---|---|---|

### 关于 P_pcc 的符号

```text
P_pcc > 0：微电网向上级电网送电
P_pcc < 0：微电网从上级电网购电
```

## 六、代码总体结构

整个 AGC 函数可以分成六个阶段：

```text
阶段1：整理和保护输入参数
阶段2：第一次运行时初始化内部状态
阶段3：根据最新资源边界修正已有命令
阶段4：判断是否到了AGC更新周期
阶段5：计算偏差并进行资源分配
阶段6：把kW指令转换成标幺值输出
```

---

## 七、阶段1：参数整理和保护

```matlab
P_UNIT = max(abs(P_unit_kW), 1e-6);
P_DEAD = max(P_dead_kW, 0.0);
SOC_LOW = min(SOC_min, SOC_max);
SOC_HIGH = max(SOC_min, SOC_max);
T_UPDATE = max(Ts_agc, 1e-6);
```

### P_UNIT

```matlab
P_UNIT = max(abs(P_unit_kW), 1e-6);
```

两层保护：

1. `abs`：`P_unit_kW = -100` → 100
2. `max(..., 1e-6)`：防止功率基准为 0，后续除以 0

**P_UNIT 一定大于 0**。

### P_DEAD

```matlab
P_DEAD = max(P_dead_kW, 0.0);
```

防止死区为负数。"负死区"没有合理物理意义。

### SOC_LOW / SOC_HIGH

防填反保护：不管用户怎么传，`SOC_LOW ≤ SOC_HIGH` 总成立。

### T_UPDATE

```matlab
T_UPDATE = max(Ts_agc, 1e-6);
```

防止控制周期为 0 或负数。但工程上应给出合理 AGC 周期，不能依赖 1e-6 保护。

---

## 八、阶段2：为什么 AGC 需要 persistent

```matlab
persistent Ppv Pess Pev last_t status last_dP last_remain
```

| 变量 | 含义 |
|---|---|
| Ppv | 两台光伏上一次的功率指令 [PV1, PV2] |
| Pess | 两台储能上一次的功率指令 [ESS1, ESS2] |
| Pev | 两台充电桩上一次的内部充电功率 [EV1, EV2] |
| last_t | AGC 上一次真正更新的时间 |
| status | 上一次 AGC 状态 |
| last_dP | 上一次实际计算的偏差 |
| last_remain | 上一次剩余未分配量 |

**为什么不能每次重新计算完就忘记？**

假设第一个周期 PV1 = 30 kW，AGC 增加 10 kW 变成 40 kW。下一个周期应当从 40 kW 继续判断还能增加多少。如果没有 persistent，下一次又从 30 kW 开始，之前调节的结果就丢失了。

这像调度员必须保存上一轮下发的设备指令，否则每次开会都失忆。

## 九、第一次运行初始化

```matlab
if isempty(Ppv)
    pvInit = clamp(PV_init_kW, 0.0, P_UNIT);
    evInit = clamp(EV_init_kW, 0.0, P_UNIT);
```

光伏和充电桩初值都被限制在 0～P_UNIT。

```matlab
    Ppv = [
        min(max(Ppvmax1_kW, 0.0), pvInit),
        min(max(Ppvmax2_kW, 0.0), pvInit)
    ];
```

光伏初值**同时被 PV_init 和当前 Ppvmax 限制**：

```text
0 ≤ Ppv初值 ≤ min(PV_init, Ppvmax)
```

示例：PV_init = 80 kW, Ppvmax1 = 50 kW → Ppv1 = 50 kW
示例：PV_init = 40 kW, Ppvmax1 = 80 kW → Ppv1 = 40 kW

储能初始化为不充不放：

```matlab
    Pess = [0.0, 0.0];
```

充电桩初始化为：

```matlab
    Pev = [evInit, evInit];
```

时间与状态：

```matlab
    last_t = -1.0;     % 特殊标志：AGC从未更新过
    status = 0.0;
    last_dP = 0.0;
    last_remain = 0.0;
```

---

## 十、阶段3：为什么每次都重新检查光伏边界

初始化结束后，每次调用都会执行：

```matlab
pvmax = [
    clamp(Ppvmax1_kW, 0.0, P_UNIT),
    clamp(Ppvmax2_kW, 0.0, P_UNIT)
];
Ppv = min(max(Ppv, 0.0), pvmax);
```

**为什么这一步非常重要？**

假设上一秒 PV1 最大可用出力 = 80 kW，指令 = 70 kW。突然云层遮挡，当前最大可用出力下降到 40 kW，原指令 70 kW 已经无法实现。

代码立即将 Ppv1 = min(70, 40) = 40 kW。

> 自然资源上限下降了，旧光伏指令必须先服从新上限。

---

## 十一、充电桩重新限幅

```matlab
Pev = min(max(Pev, 0.0), P_UNIT);
```

保证内部充电功率始终在 0～P_UNIT 之间。注意这是内部正数，最终输出才加负号。

---

## 十二、仿真时间倒退的处理

```matlab
if t < last_t
    last_t = -1.0;
end
```

模型 Reset 后 t 从 100 → 0，代码把 last_t 设为 -1，使 AGC 在下一步获得立即更新资格。

但注意：**当前代码只重置了 last_t，没有重新初始化 Ppv、Pess、Pev**。这与 SOC 代码不同（SOC 在时间倒退时会恢复初始值）。这是后续 V4 工程化需要确认的边界问题。

---

## 十三、阶段4：AGC 什么时候真正重新计算

```matlab
if enable > 0.5 && ...
   (last_t < 0.0 || (t - last_t) >= T_UPDATE)
```

**条件一**：`enable > 0.5`——AGC 已使能

**条件二**（满足任一项）：
- `last_t < 0.0`——从未更新过，立即执行第一次
- `t - last_t >= T_UPDATE`——距离上次更新已达到 AGC 控制周期

两个大条件必须**同时**满足。

---

## 十四、为什么 AGC 不在每一个仿真步运行

RT-LAB 电气模型仿真步长可能为 50 μs，每秒计算 20000 次。

但 AGC 是上层协调控制，只需每 1 秒（或几百 ms）更新一次。

在 20000 个实时步中，AGC 输出保持上一次值——这叫 **sample and hold（采样并保持）**。

---

## 十五、没有到更新时间时

如果 `enable = 1` 但 `t - last_t < T_UPDATE`，代码不进入 AGC 计算区：

```text
Ppv保持上一次值
Pess保持上一次值
Pev保持上一次值
status保持上一次值
dP保持上一次值
remain保持上一次值
```

显示出来的 dP 是上一个 AGC 控制周期计算出的偏差，不一定是此刻每个电磁仿真步的瞬时偏差。

---

## 十六、enable 关闭时的真实行为

当前代码没有写：

```matlab
if enable <= 0.5
    Ppv = 0;  Pess = 0;  Pev = 0;
end
```

所以 `enable = 0` 只是**停止更新**，不会自动清零已有命令。

但注意：在 enable 判断之前，光伏边界修正（阶段3）仍然执行。所以即使 enable=0，如果 Ppvmax 下降，光伏指令仍会被压下来。

> 当前 enable 含义是"允许或禁止 AGC 重新计算"，不是"0 代表所有设备立即停机"。

这是 V4 接口设计时必须明确的内容。

---

## 十七、进入更新周期后第一件事

```matlab
last_t = t;        % 记录本次AGC更新时间
dPnow = P_target_kW - P_pcc_kW;
```

---

## 十八、dP 的方向理解

### dP > 0

```text
P_target = 200 kW, P_pcc = 150 kW
dP = +50 kW
```

实际送电低于目标，需要提高微电网净输出：增加光伏、增加储能放电、减少充电负荷。

### dP < 0

```text
P_target = 100 kW, P_pcc = 150 kW
dP = -50 kW
```

当前送电过多，需要降低微电网净输出：增加充电桩用电、增加储能充电、降低光伏。

---

## 十九、为什么 rem = abs(dPnow)

```matlab
rem = abs(dPnow);
```

rem（remaining requirement）只表示"需要调节多少"，方向由 dPnow 决定：

```text
dP的符号：告诉调度员向哪个方向调
rem的大小：告诉调度员一共要调多少
```

---

## 二十、为什么先把 status 设为 0

```matlab
status = 0.0;
```

每个新 AGC 周期开始时，先假设无需调节。后面如果偏差超过死区，再将状态改为 1、-1、2 或 -2。

---

## 二十一、死区判断

```matlab
if abs(dPnow) > P_DEAD
```

只有偏差绝对值**严格大于**死区，AGC 才开始分配。

| dP | 死区 | 是否动作 |
|---|---|---|
| +3 kW | 5 kW | 否（|3| ≤ 5） |
| -4 kW | 5 kW | 否（|4| ≤ 5） |
| +8 kW | 5 kW | 是（|8| > 5）→ 正向调节 |
| -8 kW | 5 kW | 是（|8| > 5）→ 反向调节 |

注意使用 `>`，所以 `|dP| = P_DEAD` 时也不动作。

---

## 二十二、本轮完整流程（截至资源分配前）

```text
整理参数（P_UNIT, P_DEAD, SOC_LOW, SOC_HIGH, T_UPDATE）
↓
初始化或读取上一周期设备指令（persistent）
↓
根据最新光伏上限修正旧光伏指令
↓
判断AGC是否使能（enable > 0.5）
    并判断是否到达控制周期
↓
计算 dP = P_target - P_pcc
↓
计算 rem = |dP|
↓
判断是否超过死区（|dP| > P_DEAD）
↓
决定进入正向或反向资源分配
```

---

## 二十三、与前两轮的串联

```text
光伏曲线模块
→ 给出 Ppvmax1, Ppvmax2 → 限制光伏最大指令

SOC计算模块
→ 给出 SOC1, SOC2 → 限制储能充放电能力

PCC测量和目标
→ 形成 dP

AGC
→ 综合 Ppvmax、SOC 和 dP
→ 生成6路设备功率指令
```

---

## 二十四、核心结论

1. **AGC 不是每个实时仿真步都更新**，而是按 Ts_agc 周期更新，其他时间保持上一周期指令
2. **persistent** 保存上一次设备指令、状态、偏差和剩余量，使控制过程连续
3. **enable=0** 表示停止更新，不表示自动清零已有命令
4. **dP = P_target - P_pcc**，正值需增加净输出，负值需降低净输出
5. **rem = abs(dP)** 只保存大小，方向由 dP 决定
6. 只有 **|dP| > P_DEAD** 时才进入资源分配
7. 光伏最大可用出力下降时，**旧光伏指令先被强制压到新上限内**
8. 时间倒退后，当前代码**只重置更新时间，没有重新初始化全部设备指令**
9. 充电桩内部用正的耗电功率，最终输出时取负号

## 附录：全部参考解答

### 第1题：为什么 AGC 需要保存 persistent？

因为这套 AGC 采用**在上一周期指令基础上继续调整**的增量式调度方式。

```matlab
persistent Ppv Pess Pev last_t status last_dP last_remain
```

如果没有 persistent：

- 前一周期调节结果丢失
- 设备指令不能连续变化
- 无法正确计算设备剩余调节裕度（裕度 = Ppvmax - 当前 Ppv）

> 需要保存的不是"历史记录供查看"，而是下一次功率分配必须使用的当前指令状态。

---

### 第2题：enable=0 是否会清零？

**不会自动清零。**

`enable > 0.5` 是进入新偏差计算的条件。当 enable=0，代码跳过更新过程，通常继续输出上一周期保存的指令。

但阶段3（光伏边界修正）在 enable 判断前仍然执行，所以：

- 光伏旧指令仍受最新 Ppvmax 限制
- 充电桩仍被限制在 0～P_UNIT
- 储能 Pess 不会自动清零

> enable=0 会停止新的偏差分配，但不会把六路命令统一清零，部分基本边界保护仍继续执行。

---

### 第3题：为什么用 Ts_agc？

电气主回路（50 μs 步长）和 AGC 属于不同时间尺度：

1. **避免设备指令高速抖动**——PCC 有小幅波动，每 50 μs 重新分配会导致指令不停跳动
2. **不同控制层有不同职责**——AGC 是协调层，不应追逐每个高频瞬时波动
3. **降低实时计算负担**——避免 OP5700 超时或 Overrun
4. **形成 sample and hold**——更新时刻采集计算，非更新时刻保持输出

### 第4题：P_target=200, P_pcc=150, P_dead=5

```text
dP = 200 - 150 = +50 kW
rem = |+50| = 50 kW
|dP| = 50 > 5 → 需要调节
dP > 0 → 增加净输出
顺序：增加光伏 → 增加储能放电 → 降低充电桩充电
```

---

### 第5题：P_target=100, P_pcc=160, P_dead=5

```text
dP = 100 - 160 = -60 kW
rem = 60 kW
|dP| = 60 > 5 → 需要调节
dP < 0 → 降低净输出
顺序：增加充电桩充电 → 增加储能充电 → 降低光伏
```

### 第6题：为什么 EV 输出负值

**内部**方便计算，Pev 在 0～P_UNIT 范围表示充电功率大小。

**外部**输出时翻转符号，适配系统"发电为正、负荷为负"的接口约定：

```matlab
Pev1_pu = -Pev(1) / P_UNIT;
```

50 kW 充电 → 内部 Pev=50 → 外部 Pev_pu=-0.5。说的是同一个物理状态。

### 第7题：Ppvmax 从 70 降到 40

在进入新 AGC 分配之前，代码执行：

```matlab
Ppv = min(max(Ppv, 0.0), pvmax);
```

```text
Ppv1 = min(max(70, 0), 40) = 40 kW
```

70 kW 在光照下降后已不是可实现命令，必须先服从当前自然资源上限。这属于资源物理上限修正，发生在正式偏差分配之前。

### 七题压缩

| 问题 | 核心答案 |
|---|---|
| 为什么保存 Ppv/Pess/Pev | AGC 从上一周期指令继续增减，必须保存当前调度状态 |
| enable=0 是否清零 | 不清零，停止新分配，通常保持旧值，基础限幅仍执行 |
| 为什么用 Ts_agc | AGC 是慢速协调层，不应跟随每个电磁仿真步高速动作 |
| 200-150 | dP=+50, rem=50，增加 PV、ESS 放电、降低 EV 充电 |
| 100-160 | dP=-60, rem=60，增加 EV 充电、ESS 充电、降低 PV |
| 为什么 EV 输出为负 | 内部存充电功率大小为正，外部接口按"发电正、负荷负"输出 |
| PV 上限由 70 降至 40 | 指令在正式分配前直接压到 40 kW |
