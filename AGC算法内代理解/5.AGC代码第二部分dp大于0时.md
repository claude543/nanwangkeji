# AGC 代码第二部分——dP > 0 时的分层资源分配

> 第四轮内化：当 dP > 0 时，AGC 怎样依次调用光伏、储能和充电桩

这一轮专门研究基础 AGC 中最重要的一条分配路径：

```text
dP > 0
→ 当前PCC功率低于目标
→ 需要增加微电网净输出
→ 先增加光伏
→ 再增加储能放电
→ 最后减少充电桩用电
```

对应的核心代码：

```matlab
if dPnow > 0.0
    status = 1.0;

    [Ppv, used] = alloc_up(Ppv, pvmax, rem);
    rem = rem - used;

    essUpper = [P_UNIT, P_UNIT];

    if SOC1 <= SOC_LOW
        essUpper(1) = 0.0;
    end

    if SOC2 <= SOC_LOW
        essUpper(2) = 0.0;
    end

    [Pess, used] = alloc_up(Pess, essUpper, rem);
    rem = rem - used;

    [Pev, used] = alloc_down(Pev, [0.0, 0.0], rem);
    rem = rem - used;
end
```

---

## 一、为什么 dP > 0 代表要增加净输出

```matlab
dPnow = P_target_kW - P_pcc_kW;
```

示例：P_target = 300 kW, P_pcc = 200 kW → dP = +100 kW

当前 PCC 送出的功率比目标少 100 kW，需要采取能提高净输出的动作：

| 动作 | 效果 |
|---|---|
| 光伏多发电 | ↑ 净输出 |
| 储能多放电 | ↑ 净输出 |
| 充电桩少用电 | ↑ 净输出 |

---

## 二、园区能源调度故事

假设一个工业园区承诺向电网送出 500 kW，但现在只送出了 200 kW，还差 300 kW。

**第一组——光伏组**：当前还有没有未利用的阳光？能不能多发一些？（受 Ppvmax 限制）

**第二组——储能组**：如果光伏不够，电池还有没有电？能不能增加放电？（受 SOC 下限限制）

**第三组——充电桩组**：如果前两组都不够，当前正在充电的车辆能不能少充一点？（减少充电负荷 ≡ 提高净输出）

---

## 三、为什么先设置 status = 1

```matlab
status = 1.0;
```

| 值 | 含义 |
|---|---|
| 1 | 正在执行正向调节（增加净输出），资源充足 |
| -1 | 正在执行反向调节（降低净输出），资源充足 |
| 2 | 正向调节，但资源不足 |
| -2 | 反向调节，但资源不足 |

---

## 四、第一层：为什么优先增加光伏

```matlab
[Ppv, used] = alloc_up(Ppv, pvmax, rem);
rem = rem - used;
```

| 变量 | 含义 |
|---|---|
| alloc_up | allocate up，向上分配 |
| Ppv | 两台光伏当前功率指令 |
| pvmax | 两台光伏当前最大可用出力 |
| rem | 当前剩余调节需求 |
| used | 本层资源实际承担的调节量 |

### 光伏的向上裕度

对每台光伏：**向上裕度 = Ppvmax - 当前指令**

示例：PV1 当前 40 kW, Ppvmax = 80 kW → 裕度 40 kW；PV2 当前 60 kW, Ppvmax = 70 kW → 裕度 10 kW。光伏组总共还能增加 50 kW。

---

## 五、深入理解 alloc_up

```matlab
function [x, used] = alloc_up(x, upper, req)

    head = max(upper - x, 0.0);
    total = head(1) + head(2);
    used = 0.0;

    if req > 0.0 && total > 0.0
        used = min(req, total);

        x(1) = x(1) + used * head(1) / total;
        x(2) = x(2) + used * head(2) / total;
    end
end
```

### 参数

| 参数 | 含义 |
|---|---|
| x | 当前两台设备功率指令（调用时传入 Ppv 或 Pess） |
| upper | 两台设备允许达到的最大功率 |
| req | 当前剩余功率调节需求 |

### head——剩余裕度

```matlab
head = max(upper - x, 0.0);
```

示例：x = [40, 60], upper = [80, 70] → head = [40, 10]

`max(..., 0)` 防止出现负裕度。

### total——同类总裕度

```matlab
total = head(1) + head(2);
```

示例：total = 40 + 10 = 50 kW

### used——实际承担量

```matlab
used = min(req, total);
```

| 情况 | req | total | used |
|---|---|---|---|
| 需求 < 总裕度 | 30 | 50 | 30（光伏承担全部） |
| 需求 > 总裕度 | 100 | 50 | 50（光伏已达极限） |

### 按裕度比例分配

```matlab
x(1) = x(1) + used * head(1) / total;
x(2) = x(2) + used * head(2) / total;
```

示例：head = [40, 10], total = 50, used = 30

| 设备 | 分配比例 | 实际增加 | 最终 |
|---|---|---|---|
| PV1 | 40/50 = 0.8 | 30 × 0.8 = 24 kW | 40 → 64 kW |
| PV2 | 10/50 = 0.2 | 30 × 0.2 = 6 kW | 60 → 66 kW |

两台设备按各自剩余能力承担，不是简单平分。

## 六、为什么每层后都要更新 rem

```matlab
rem = rem - used;
```

rem 像一张任务单：

```text
最开始写着"还需要300 kW"
光伏完成50 kW → 任务单改为250 kW
储能完成200 kW → 任务单改为50 kW
充电桩完成50 kW → 任务单改为0
```

---

## 七、第二层：储能根据 SOC 建立功率上限

### 初始上限

```matlab
essUpper = [P_UNIT, P_UNIT];
```

正常情况下两台储能的放电上限都是 +P_UNIT。

### SOC 限制

```matlab
if SOC1 <= SOC_LOW
    essUpper(1) = 0.0;
end
if SOC2 <= SOC_LOW
    essUpper(2) = 0.0;
end
```

| SOC 状态 | essUpper | 含义 |
|---|---|---|
| > SOC_LOW | +P_UNIT | 允许增加放电 |
| ≤ SOC_LOW | 0 | 禁止向正方向增加 |

### 一个重要细节

把 essUpper 设为 0 并不总是意味着储能指令立即变成 0。

**情况一：储能原来正在充电（Pess = -30 kW）**

裕度 = 0 - (-30) = 30 kW，alloc_up 可以把储能从 -30 kW 逐渐提高到 0 kW。减少充电也可以提高净输出。

**情况二：储能原来已经在放电（Pess = +30 kW）**

裕度 = max(0 - 30, 0) = 0，AGC 不会再增加放电，但不会主动把已有的 +30 kW 降到 0。

> SOC 到达下限后，代码禁止继续增加放电，但未必立即撤销已有放电命令。

---

## 八、第三层：为什么充电桩用 alloc_down

```matlab
[Pev, used] = alloc_down(Pev, [0.0, 0.0], rem);
rem = rem - used;
```

内部 Pev 保存的是充电桩吸收功率的正数大小（如 Pev = 80 kW 表示消耗 80 kW）。

把充电功率从 80 kW 降到 30 kW，少消耗 50 kW，这部分功率可以送往 PCC，等效于净输出增加 50 kW。

> 增加净输出 → 减少充电负荷 → Pev 向下调整 → 使用 alloc_down

---

## 九、深入理解 alloc_down

```matlab
function [x, used] = alloc_down(x, lower, req)

    head = max(x - lower, 0.0);
    total = head(1) + head(2);
    used = 0.0;

    if req > 0.0 && total > 0.0
        used = min(req, total);

        x(1) = x(1) - used * head(1) / total;
        x(2) = x(2) - used * head(2) / total;
    end
end
```

### 参数

| 参数 | 含义 |
|---|---|
| lower | 下限（充电桩调用时为 [0, 0]） |
| head | 向下裕度 = x - lower（还能减少多少） |

示例：Pev = [30, 70], lower = [0, 0] → head = [30, 70], total = 100

如果还需增加 50 kW 净输出：

| 设备 | 比例 | 减少量 | 最终 |
|---|---|---|---|
| EV1 | 30/100 | 15 kW | 30 → 15 kW |
| EV2 | 70/100 | 35 kW | 70 → 35 kW |

总负荷减少 50 kW → 净输出增加 50 kW。

## 十、完整数字案例

### 初始条件

```text
dP = +300 kW,  rem_初始 = 300 kW,  P_UNIT = 100 kW

Ppv   = [40, 60] kW      Ppvmax = [80, 70] kW
Pess  = [0, 0] kW        SOC均正常
Pev   = [30, 70] kW
```

### 第一层：光伏

| 设备 | 裕度 |
|---|---|
| PV1 | 80 - 40 = 40 kW |
| PV2 | 70 - 60 = 10 kW |
| **合计** | **50 kW** |

```text
used = min(300, 50) = 50 kW
Ppv = [80, 70] kW
rem = 300 - 50 = 250 kW
```

### 第二层：储能

```text
essUpper = [100, 100] kW
裕度 = [100, 100],  total = 200 kW

used = min(250, 200) = 200 kW
Pess = [100, 100] kW
rem = 250 - 200 = 50 kW
```

### 第三层：充电桩

```text
Pev = [30, 70] kW
向下裕度 = [30, 70],  total = 100 kW

used = min(50, 100) = 50 kW
EV1减少: 50 × 30/100 = 15 kW → 15 kW
EV2减少: 50 × 70/100 = 35 kW → 35 kW
Pev = [15, 35] kW
rem = 50 - 50 = 0
```

### 最终效果

| 资源 | 变化 | 净输出效果 |
|---|---|---|
| 光伏增加 | +50 kW | ↑ 50 kW |
| 储能放电增加 | +200 kW | ↑ 200 kW |
| 充电桩负荷减少 | -50 kW | ↑ 50 kW |
| **合计** | | **↑ 300 kW** ✅ |

```text
rem = 0,  status = 1
```

## 十一、资源不够时的处理

```matlab
if rem > P_DEAD
    status = 2.0 * sign(dPnow);
end
```

对于 dP > 0：sign(dPnow) = +1，所以 status = 2。

示例：初始需求 400 kW

| 资源 | 最大能力 |
|---|---|
| 光伏 | +50 kW |
| 储能 | +200 kW |
| 充电桩 | -100 kW |
| **合计** | **350 kW** |

```text
remain = 400 - 350 = 50 kW
50 > P_DEAD(5) → status = 2
```

如果最终 remain = 3 kW ≤ P_DEAD(5)，则 status 保持为 1（剩余误差在允许死区内，视为基本完成）。

## 十二、论文关注点

### 1. 固定优先级

当前顺序始终为光伏 → 储能 → 充电桩，没有根据 SOC、效率、寿命、用户需求、经济成本动态变化。

### 2. 同类资源只按功率裕度比例分配

没有考虑 SOC 差异、SOH 差异、效率差异、寿命损耗差异。

### 3. 没有爬坡率限制

储能可能在一个 AGC 周期内从 -50 kW 充电直接切换到 +100 kW 放电（变化 150 kW），代码只检查功率上下限，不检查每周期最大允许变化量。

### 4. SOC 约束是开关式的

高于下限允许满功率放电，达到下限才禁止。没有接近下限时逐步降额的连续约束。

### 5. 使用内部命令计算裕度

Ppv/Pess/Pev 是上一周期命令，不一定等于设备实际功率，裕度计算可能失真。

---

## 十三、核心结论

```text
dP > 0：         需要增加微电网净输出

第一层 光伏：    增加发电，受 Ppvmax 限制

第二层 储能：    增加正功率（放电），受 SOC 下限和 P_UNIT 限制

第三层 充电桩：  减少内部充电功率（减少负荷），增加净输出

每层完成后：     rem = rem - used

同类两台设备：   按各自剩余可调裕度比例分配

全部资源不足：   remain 保留，status 变为 2
```

下一轮将进入相反的路径：dP < 0 → 增加充电桩负荷 → 增加储能充电 → 降低光伏出力。
