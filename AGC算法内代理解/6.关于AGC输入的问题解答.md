# 关于 AGC 输入的问题解答

## 结论

这里要区分两类"实际功率"：

```text
P_pcc_kW：
是整个微电网在PCC处测得的实际有功功率，属于真实反馈量。

Ppv、Pess、Pev：
是AGC内部保存的六台设备上一周期功率指令，不是六台设备各自的实际功率反馈。
```

所以当前 AGC 并不是完全没有实际功率输入，而是：

> **有一个系统级实际功率反馈 P_pcc_kW，但没有六台设备各自的实际功率反馈。**

同时，t、enable、P_target_kW 和 Ts_agc 的性质不同：

```text
t、P_pcc_kW：
运行过程中不断变化的动态输入。

enable、P_target_kW：
由上层控制或操作人员下达的运行指令。

Ts_agc：
控制器设计参数，通常配置后固定，不应随意变化。
```

---

## 一、仿真时间 t 的作用

函数输入中第一个量是 `t`，表示当前仿真时间（秒）。代码主要在两个地方使用它。

### 1. 判断是否到了 AGC 更新周期

```matlab
if enable > 0.5 && ...
   (last_t < 0.0 || (t - last_t) >= T_UPDATE)
```

| 变量 | 含义 |
|---|---|
| t | 当前时间 |
| last_t | 上一次 AGC 真正更新的时间 |
| t - last_t | 距离上一次 AGC 更新经过了多久 |
| T_UPDATE | 规定的 AGC 更新周期 |

**示例**：Ts_agc = 1 s, last_t = 5 s

| 当前时间 | t - last_t | 是否更新 |
|---|---|---|
| 5.4 s | 0.4 s < 1 s | ❌ 保持上一周期命令 |
| 6.0 s | 1.0 s ≥ 1 s | ✅ 重新分配 |

t 像 AGC 调度员的时钟，告诉调度员现在是否到了下一次开调度会议的时间。

---

### 2. 判断模型是否重新开始

```matlab
if t < last_t
    last_t = -1.0;
end
```

正常时间递增：0 → 1 → 2 → 3。模型 Reset 后可能出现 100 → 0，此时 t < last_t，代码让 AGC 重新获得立即更新资格。

### 3. t 参与功率分配吗？

**不直接参与。** 它决定"什么时候更新一次 AGC"和"是否发生仿真重新启动"，不决定光伏/储能/充电桩各分多少。

### 4. AGC 上板后还需要仿真时间吗？

需要"时间功能"，但不一定必须使用 RT-LAB 的仿真时间。

| 环境 | 时间来源 |
|---|---|
| Simulink 参考算法 | Clock 模块或仿真时间 |
| 板子 C 程序 | 板子系统时钟 / 定时器 / 主循环累计时间 / 固定周期任务调度器 |

V4 需要明确：RT-LAB 参考算法使用仿真时间 t 进行周期判断；板子 C 算法使用板子本地定时器控制执行周期。

---

## 二、P_pcc_kW 是不是实际功率？

**是。** P_pcc_kW 是公共连接点 PCC 测得的实际有功功率，是基础 AGC 最核心的系统反馈量。

AGC 通过 `dPnow = P_target_kW - P_pcc_kW` 计算目标与实际之间的误差。

示例：目标 PCC 功率 = 200 kW，实际 = 150 kW → dP = +50 kW，AGC 知道还需增加 50 kW 净输出。

如果没有 P_pcc_kW，AGC 就不知道前一轮命令执行后系统实际发生了什么，无法形成 PCC 功率闭环。

---

## 三、为什么之前又说"AGC 没有输入实际功率"？

准确说法是：

> **当前 AGC 没有输入六台具体设备各自的实际功率。**

它没有这些输入：

```text
PV1实际功率     PV2实际功率
ESS1实际功率    ESS2实际功率
EV1实际功率     EV2实际功率
```

但它有 P_pcc_kW——整个微电网在公共连接点的实际总功率反馈。

**当前结构**：系统级反馈 ✅ 有 / 设备级反馈 ❌ 没有

---

## 四、系统级反馈 vs 设备级反馈

### P_pcc_kW（系统级反馈）

回答：整个微电网最终向外送了多少功率？目标是否实现？总体还差多少？

### 六台设备实际功率（设备级反馈）

回答：PV1 是否真的执行了 60 kW 命令？ESS1 是否因为本地限幅只输出了 20 kW？某个充电桩是否离线？每台设备还剩多少真实调节能力？

当前 AGC 不知道这些设备级执行细节，它只保存 `persistent Ppv Pess Pev`——自己上次下发的指令。

---

## 五、一个例子说明二者的差别

假设 AGC 上一周期下发 PV1 指令 = 80 kW，内部记住 Ppv1 = 80 kW。但因云层遮挡，PV1 实际只发出 50 kW。

当前 AGC 没有 PV1 实际功率输入，仍认为 PV1 当前指令是 80 kW。

但 PCC 实际功率会反映总体少发的 30 kW：P_pcc 低于目标 → 下一周期 dP 仍为正 → AGC 继续尝试分配。

**系统级闭环仍然可以纠偏，但 AGC 不清楚偏差究竟来自哪一台设备没有执行到位，导致裕度计算不准确。**

---

## 六、当前 AGC 是什么类型的反馈结构？

```text
外层：利用PCC实际功率形成系统总功率闭环
内层：根据上一周期设备指令估计各资源当前状态和裕度
```

完整闭环：

```text
六路指令 → 设备本地控制 → 电气系统响应 → PCC实际功率
→ AGC重新计算总偏差 → 再次调整六路指令
```

它不是开环算法，但设备级分配部分使用的是"命令状态"而非"每台设备实际反馈"。这是后续论文或算法提升中已记录的重要方向。

---

## 七、enable 是随便设置的吗？

不是随便设置，但在不同阶段可以由不同来源给出。

### 在模型调试阶段

使用 Constant、Switch 或面板按钮，例如 `0 = 停止 AGC 更新，1 = 允许 AGC 更新`。

### 在正式系统中

应由安全与运行条件共同决定：

```text
人工允许AGC
AND 模型测量有效
AND 通信正常
AND 设备接口准备完成
AND 没有严重故障
```

后续板载 AGC 中可以关联到 EXT_AGC_ENABLE、EXTERNAL_COMMAND_VALID、板子状态机，不能简单永久写成 1。

### 当前 enable=0 的含义

只是"停止重新计算"，不会自动把六路命令清零。V4 必须明确：AGC 失能后保持旧命令？切换至内部命令？切换至安全值？平滑降到预设功率？

---

## 八、P_target_kW 是随便设置的吗？

也不是。P_target_kW 是希望 PCC 达到的有功功率目标，是 AGC 控制任务的来源。

### 在模型测试阶段

为制造不同工况，可人为设置不同值（如 200 kW、100 kW、-50 kW）。

### 在正式运行中

目标值应来自明确来源：

```text
上级调度指令 / 微电网能量管理系统
日前计划 / 联络线计划
防逆流策略 / 削峰填谷策略
新能源消纳策略 / 本地操作员设定
```

**基础 AGC 的任务**：接收目标，然后通过六类设备资源使 PCC 实际功率跟踪该目标。

---

## 九、P_target_kW 和 15 种策略的关系

这正是基础 AGC 和 15 种策略的重要连接点。未来某些高级策略可以修改或生成 PCC 目标功率：

| 策略 | 可能的目标 |
|---|---|
| 防逆流 | P_target = 0，或降低净输出的修正量 |
| 削峰填谷 | 降低购电功率目标 |
| 联络线控制 | P_target = P_tie_reference |
| 周期计划 | 按一天中的时段给出不同目标 |

```text
高级策略：决定"PCC应该达到什么目标"
基础 AGC：决定"怎样让六台设备共同实现这个目标"
```

## 十、Ts_agc 是随便设置的吗？

不是。Ts_agc 是 AGC 更新周期，属于控制器设计参数，需要综合考虑：

1. **被控对象响应速度**——设备本地功率环需要时间响应，更新过快则上一条命令尚未执行完新命令又来了
2. **通信周期**——板子与 RT-LAB 若每 1 秒交换一次数据，AGC 不宜要求每 10 ms 更新
3. **测量刷新速度**——测量量每 1 秒刷新，AGC 却每 0.1 秒计算，会反复使用相同旧数据
4. **算法计算时间**——板子需要足够时间完成读取→解码→有效性检查→AGC 计算→编码→写回
5. **控制性能**——周期太长则响应慢、跟踪滞后；周期太短则容易追逐噪声、命令频繁变化

---

## 十一、当前项目中如何初步确定更新周期

结合当前板子与 RT-LAB 通信框架，通信主周期约为 1 秒：

```text
第1秒：板子读取40101~40116
→ 验证状态、心跳和测量值
→ 执行AGC
→ 写40001~40012

第2秒：再次读取并更新
```

后续如果通信周期、设备响应和论文场景改变，Ts_agc 也可以重新设计。尤其是研究通信延时、丢包、自适应控制周期时，Ts_agc 可能本身就是研究变量。

---

## 十二、四个输入的性质对照

| 输入 | 是否动态变化 | 来源 | 能否随便设置 |
|---|---|---|---|
| t | 持续变化 | 仿真时钟或板子时钟 | 不能随意，必须真实反映时间 |
| P_pcc_kW | 持续变化 | PCC 实际功率测量 | 不能随意，测试时可人为注入 |
| enable | 0/1 变化 | 人工与安全逻辑 | 调试时可设，正式运行要有明确逻辑 |
| P_target_kW | 可变化 | 上层调度或高级策略 | 测试时可设，正式运行由控制目标决定 |
| Ts_agc | 通常固定 | 控制器设计参数 | 不能随意，需要按系统时间尺度设计 |

---

## 十三、完整串联关系

```text
上层调度或策略 → 给出P_target_kW
PCC测量 → 给出P_pcc_kW
两者相减 → dP = P_target - P_pcc

板子或模型时钟 → 给出t → 判断是否到Ts_agc更新时刻
安全与人工逻辑 → 给出enable

当enable有效且更新时间到达
→ AGC根据dP、Ppvmax、SOC等
→ 生成6路功率指令
```

## 最后压缩理解

```text
t：            控制AGC"什么时候算"
P_pcc_kW：     告诉AGC"系统现在实际做到多少"
P_target_kW：  告诉AGC"系统希望做到多少"
enable：       告诉AGC"当前是否允许计算和更新"
Ts_agc：       规定AGC"多久算一次"
```

之前所说的"没有实际功率输入"，特指**没有六台设备各自的实际功率反馈**，不是没有 PCC 实际功率反馈。

当前算法是：

```text
PCC总功率闭环
+ 设备指令状态式资源分配
```

而不是：

```text
六台设备实际功率全部反馈的精细闭环分配
```
