# AGC理解：`dP < 0` 时情况

## 第五轮内化：当 `dP < 0` 时，AGC怎样降低微电网净输出

这一轮研究与上一轮相反的调节路径：

```text
dP < 0
→ 当前PCC功率高于目标
→ 微电网向外送出的功率过多
→ 需要降低净输出
→ 先增加充电桩用电
→ 再让储能增加充电
→ 最后降低光伏出力
```

对应核心代码为：

```matlab
else
    status = -1.0;

    [Pev, used] = alloc_up(Pev, [P_UNIT, P_UNIT], rem);
    rem = rem - used;

    essLower = [-P_UNIT, -P_UNIT];

    if SOC1 >= SOC_HIGH
        essLower(1) = 0.0;
    end

    if SOC2 >= SOC_HIGH
        essLower(2) = 0.0;
    end

    [Pess, used] = alloc_down(Pess, essLower, rem);
    rem = rem - used;

    [Ppv, used] = alloc_down(Ppv, [0.0, 0.0], rem);
    rem = rem - used;
end
```

这段代码实现了"可控负荷吸收—储能充电—光伏限发"的三级调节。

---

## 一、为什么 `dP < 0` 表示需要降低净输出

AGC的偏差定义是：

```matlab
dPnow = P_target_kW - P_pcc_kW;
```

例如：

```text
P_target = 200 kW
P_pcc    = 300 kW
```

则：

```text
dP = 200 - 300 = -100 kW
```

按照当前基础AGC的功率方向：

```text
PCC功率为正：
微电网向上级电网送电
```

现在实际送出了300 kW，但目标只要求200 kW，所以多送了：

```text
300 - 200 = 100 kW
```

因此需要让微电网净输出减少100 kW。

可以采用三种动作：

```text
充电桩增加用电
储能增加充电
光伏减少发电
```

三种动作的共同效果都是：**减少最终送到PCC的功率。**

---

## 二、用"园区电力过剩"的故事理解

假设一个工业园区原本只计划向电网送出200 kW，但因为阳光增强，现在实际送出了550 kW。

多出来：

```text
550 - 200 = 350 kW
```

园区调度员按顺序处理。

第一步问充电桩：

> 现在有没有车辆可以多充一些电，把多余功率就地消耗掉？

第二步问储能：

> 充电桩吸收不完，电池能不能充电，把多余能量存起来？

第三步才通知光伏：

> 如果内部负荷和储能都吸收不完，只能降低光伏发电。

这个顺序体现了当前代码的基本思想：

```text
优先增加内部消纳
→ 其次储存能量
→ 最后才弃光
```

但这是当前代码预设的固定策略，并不代表任何场景下都一定最优。

## 三、为什么先设置 `status = -1`

代码：

```matlab
status = -1.0;
```

含义是：

```text
AGC正在执行降低微电网净输出的反向调节
```

这里的负号表示调节方向，不表示故障。

当前状态含义可以理解为：

| status | 含义                   |
| ------ | ---------------------- |
| 0      | 死区内，无需调节       |
| 1      | 增加净输出，资源正常调节 |
| -1     | 降低净输出，资源正常调节 |
| 2      | 需要增加净输出，但资源不足 |
| -2     | 需要降低净输出，但资源不足 |

## 四、第一层：为什么充电桩调用 `alloc_up`

代码：

```matlab
[Pev, used] = alloc_up(Pev, [P_UNIT, P_UNIT], rem);
rem = rem - used;
```

容易产生疑问：

> 现在需要降低微电网输出，为什么却调用"向上增加"函数？

因为AGC内部的 `Pev` 不是整个系统中的带符号功率，而是：

```text
充电桩正在吸收的功率大小
```

例如：

```text
内部Pev = 30 kW
```

表示充电桩正在消耗30 kW。

如果把它增加到：

```text
内部Pev = 80 kW
```

充电桩就多消耗了50 kW，因此PCC向外送出的功率减少50 kW。

所以：

```text
降低PCC净输出
→ 增加充电负荷
→ 内部Pev增大
→ 使用alloc_up
```

## 五、充电桩的向上裕度怎样计算

调用：

```matlab
alloc_up(Pev, [P_UNIT,P_UNIT], rem)
```

其中：

```text
x = Pev
upper = [P_UNIT,P_UNIT]
req = rem
```

`alloc_up` 内部计算：

```matlab
head = max(upper - x, 0.0);
```

对充电桩而言：

```text
向上裕度 = 最大允许充电功率 - 当前充电功率
```

例如：

```text
P_UNIT = 100 kW

EV1当前充电功率 = 30 kW
EV2当前充电功率 = 70 kW
```

则：

```text
EV1还能增加：100 - 30 = 70 kW
EV2还能增加：100 - 70 = 30 kW
```

总共还能多消耗：

```text
70 + 30 = 100 kW
```

如果当前需要降低净输出60 kW，则按裕度比例：

```text
EV1增加 = 60 × 70/100 = 42 kW
EV2增加 = 60 × 30/100 = 18 kW
```

最终：

```text
EV1：30 → 72 kW
EV2：70 → 88 kW
```

两台充电桩总用电增加60 kW，PCC净输出相应减少60 kW。

## 六、为什么最终输出的EV功率反而更负

内部保存的是：

```text
Pev = 正的充电功率大小
```

但最终输出时执行：

```matlab
Pev1_pu = -Pev(1)/P_UNIT;
Pev2_pu = -Pev(2)/P_UNIT;
```

例如内部：

```text
Pev1 = 72 kW
P_UNIT = 100 kW
```

最终输出：

```text
Pev1_pu = -72/100 = -0.72
```

因为系统统一采用：

```text
向微电网注入功率为正
从微电网吸收功率为负
```

所以：

```text
内部Pev越大 → 最终输出越负 → 充电桩消耗功率越大 → PCC净输出越小
```

## 七、第二层：储能为什么使用 `alloc_down`

充电桩吸收后，如果仍有剩余需求，代码处理储能：

```matlab
essLower = [-P_UNIT, -P_UNIT];
```

`essLower` 表示：

```text
Energy Storage System Lower Limit
储能功率下限
```

由于当前约定：

```text
Pess > 0：放电
Pess < 0：充电
```

所以 `-P_UNIT` 表示最大允许充电功率。

例如：

```text
P_UNIT = 100 kW
```

则储能功率范围是：

```text
-100 kW ～ +100 kW
```

其中：

```text
-100 kW：满功率充电
  0 kW：不充不放
+100 kW：满功率放电
```

要让储能增加充电，就要使 `Pess` 向更负的方向降低，因此调用：

```matlab
alloc_down
```

## 八、SOC上限怎样限制储能充电

代码：

```matlab
if SOC1 >= SOC_HIGH
    essLower(1) = 0.0;
end
```

如果储能1达到或超过SOC上限：

```text
SOC1 ≥ SOC_HIGH
```

原本允许的功率下限 `-P_UNIT` 被改为 `0`。

含义是：

> 储能1不能再向负功率方向调节，不能继续增加充电。

储能2处理方式相同。

### 三种SOC情况

假设 `SOC_HIGH = 0.90`：

| SOC  | essLower | 能否继续充电 |
| ---- | -------- | ------------ |
| 0.60 | -100 kW  | 可以           |
| 0.90 | 0 kW     | 禁止进一步增加充电 |
| 0.95 | 0 kW     | 禁止进一步增加充电 |

## 九、一个关键细节：`essLower=0` 不一定让已有充电立即停止

这与上一轮SOC下限问题对称。

### 情况一：储能原来正在放电

例如：

```text
当前Pess = +40 kW
SOC已经达到上限
essLower = 0
```

向下裕度为：

```text
x - lower = 40 - 0 = 40 kW
```

`alloc_down` 可以把储能从 `+40 kW` 放电降低到 `0 kW`，这相当于取消放电，也会降低微电网净输出。这是合理的。

### 情况二：储能原来已经在充电

例如：

```text
当前Pess = -30 kW
SOC已经达到上限
essLower = 0
```

计算：

```text
x - lower = -30 - 0 = -30
```

经过 `max(-30, 0) = 0`，该储能没有进一步向下调节裕度。

但是 `Pess` 仍然保持 `-30 kW`。也就是说：

> 当前代码不再增加充电，但也没有主动将已有的充电命令恢复到0。

这可能造成：SOC已经达到上限，但储能旧充电命令仍然存在。虽然SOC计算模块会把SOC数值限制在上限，但物理命令层面并不完整。

### 论文/算法关注点记录

后续应关注：

```text
SOC达到上限 → 已有充电命令应撤销或平滑退到0
SOC接近上限 → 允许充电功率逐步降额
```

这属于当前算法一个明确的工程完善点。

## 十、`alloc_down` 究竟怎样工作

函数为：

```matlab
function [x, used] = alloc_down(x, lower, req)

    head = max(x - lower, 0.0);
    total = head(1) + head(2);
    used = 0.0;

    if req > 0.0 && total > 0.0
        used = min(req,total);

        x(1) = x(1) - used*head(1)/total;
        x(2) = x(2) - used*head(2)/total;
    end
end
```

英文含义：

```text
alloc = allocate，分配
down = 向下
lower = 下限
req = requirement，请求量
head = 向下可调裕度
total = 总裕度
used = 实际承担量
```

### 向下裕度

```matlab
head = max(x-lower,0);
```

例如：

```text
当前Pess = [+20,-20] kW
功率下限 = [-100,-100] kW
```

则：

```text
ESS1向下裕度 = 20 - (-100) = 120 kW
ESS2向下裕度 = -20 - (-100) = 80 kW
```

总向下裕度：`120 + 80 = 200 kW`

这里为什么ESS1有120 kW裕度？因为它可以从 `+20 kW` 放电一路降低到 `0`，再继续降低到 `-100 kW` 充电，总变化量就是 `20 - (-100) = 120 kW`。

## 十一、储能可以在一个周期内从放电跨过零变成充电

假设：

```text
ESS1当前Pess = +20 kW
下限 = -100 kW
```

如果调节需求足够大，`alloc_down` 可能直接将其调整为 `-100 kW`。也就是说，`+20 kW` 放电 → 0 → `-100 kW` 充电，在一个AGC更新周期内完成。

当前代码没有设置：

- 功率变化率限制
- 充放电模式切换等待时间
- 零功率停留时间
- PCS切换约束

### 论文/算法关注点记录

这一点适合后续研究：

```text
储能充放电无扰切换
功率爬坡率约束
模式切换死区
减少频繁充放电反转
```

## 十二、第三层：为什么最后才降低光伏

如果充电桩和储能仍不能吸收全部多余功率，代码执行：

```matlab
[Ppv, used] = alloc_down(Ppv, [0.0, 0.0], rem);
rem = rem - used;
```

光伏功率下限是 `0 kW`，所以光伏可以从当前指令向下调整到0。

例如：

```text
当前Ppv = [80,60] kW
lower = [0,0]
```

向下裕度：

```text
PV1：80 - 0 = 80 kW
PV2：60 - 0 = 60 kW
```

总共最多可以减少 `140 kW`。两台光伏仍按各自当前可减少裕度比例降低。

### 为什么光伏最后才调

按照当前算法思路：

```text
先增加负荷吸收 → 再将能量存入储能 → 最后才降低光伏
```

这样可以尽量避免弃光，提高新能源利用率。

但这一顺序没有考虑：

```text
电价
储能寿命
车辆用户充电需求
储能充电效率
光伏限发成本
设备响应速度
```

所以这是基础固定优先级，不是最终最优策略。

## 十三、完整数字案例：三层资源全部参与

设定：

```text
P_target = 200 kW
P_pcc = 550 kW

dP = 200 - 550 = -350 kW
rem初始 = 350 kW

P_UNIT = 100 kW
```

当前资源状态：

```text
Pev内部 = [30,70] kW

Pess = [+20,-20] kW
SOC1、SOC2均在正常范围

Ppv = [80,60] kW
```

### 第一层：增加充电桩负荷

最大值：

```text
upper = [100,100]
```

向上裕度：

```text
EV1：100-30=70 kW
EV2：100-70=30 kW
```

总裕度 `100 kW`。需求350 kW大于充电桩能力，所以 `used = 100 kW`。

最终：

```text
Pev = [100,100] kW
rem = 350-100=250 kW
```

最终输出对应：

```text
Pev1_pu = -1
Pev2_pu = -1
```

### 第二层：储能增加充电

两台SOC正常：

```text
essLower = [-100,-100] kW
```

当前 `Pess=[+20,-20]`。

向下裕度：

```text
ESS1：20-(-100)=120 kW
ESS2：-20-(-100)=80 kW
```

总裕度 `200 kW`。剩余需求250 kW大于储能能力，因此 `used=200 kW`。

两台储能都达到下限：

```text
Pess=[-100,-100] kW
rem=250-200=50 kW
```

储能总功率从 `+20 + (-20) = 0 kW` 变为 `-100 + (-100) = -200 kW`，因此微电网净输出降低了200 kW。

### 第三层：降低光伏

当前 `Ppv=[80,60] kW`，总可减少量 `80+60=140 kW`。只剩50 kW需求，按比例降低。

PV1承担：`50 × 80/140 ≈ 28.57 kW`
PV2承担：`50 × 60/140 ≈ 21.43 kW`

最终：

```text
PV1 ≈ 51.43 kW
PV2 ≈ 38.57 kW
rem = 50-50 = 0
```

| **合计** | **350 kW** | 恰好补偿 dP = -350 kW |

status = -1

Ppv1_pu ≈ 0.5143

## 十五、如果所有资源仍然不够

分配完成后，统一检查：

```matlab
if rem > P_DEAD
    status = 2.0*sign(dPnow);
end
```

当 `dPnow < 0`，则 `sign(dPnow) = -1`。所以如果仍有较大剩余需求：`status = 2 × (-1) = -2`。

含义：系统需要降低净输出，但所有充电桩、储能和光伏调节能力仍然不足。

例如：需要降低500 kW，全部资源最多只能降低440 kW，则 `remain=60 kW`。如果死区为5 kW，`60 > 5`，最终 `status = -2`，`remain = 60`。

## 十六、正向和反向路径对比

| 内容        | `dP > 0`           | `dP < 0`            |
| ----------- | ------------------ | ------------------- |
| 系统目标    | 增加净输出           | 降低净输出            |
| 第一层      | 增加光伏             | 增加充电桩用电         |
| 第二层      | 增加储能放电         | 增加储能充电          |
| 第三层      | 减少充电桩用电        | 降低光伏              |
| 储能SOC限制 | SOC低时禁放电        | SOC高时禁充电         |
| 状态正常    | `status = 1`       | `status = -1`       |
| 资源不足    | `status = 2`       | `status = -2`       |

可以记成：

```text
净输出不够：多发电、多放电、少用电
净输出过多：多用电、多充电、少发电
```

## 十七、本轮论文关注点简要记录

### 1. 固定反向调节优先级

当前始终：充电桩 → 储能 → 光伏。没有考虑车辆用户需求、储能寿命、电价和通信质量。可研究动态优先级或多目标优化。

### 2. 高SOC下已有充电命令未必退出

当前只禁止继续增加充电，并不一定撤销旧充电命令。可研究SOC边界主动退出和连续降额。

### 3. 储能可在一个周期内充放电直接反转

缺少爬坡率和模式切换约束。可研究无扰切换、斜率限制和切换死区。

### 4. 光伏最后限发体现新能源消纳目标

但当前没有量化比较弃光成本、储能寿命损耗、车辆充电满意度、购售电经济性。可发展为多目标权重调度。

### 5. 仍使用上一周期命令而非实际功率反馈

设备执行不到位时，裕度计算可能失真。可研究基于实际反馈的动态裕度重估。

## 十八、本轮必须掌握的核心结论

```text
dP<0表示PCC实际功率高于目标，需要降低微电网净输出。

第一层：
增加充电桩内部Pev，增加负荷消耗。

第二层：
降低Pess，使储能减少放电或转为充电。

第三层：
降低光伏Ppv，减少发电。

SOC达到上限：
储能不允许继续向负功率方向增加充电。

每层完成后：
rem = rem-used。

所有资源仍不足：
status=-2，remain保留。
```

下一轮应进入基础AGC最核心的数学机制总结：`alloc_up`、`alloc_down` 为什么能保证总分配量守恒、同类设备为什么按实时可调裕度比例分配，以及这种分配方法的优点、局限和完整手算验证。
