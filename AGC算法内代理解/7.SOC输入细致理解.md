# SOC输入细致理解

## 结论

**根据目前代码和现有模型说明，不能说 `SOC_Calculation` 已经使用了两台储能设备返回的真实功率。**

更准确的判断是：

> 当前简化模型中的 `Pess1_pu`、`Pess2_pu` 很可能来自AGC生成的储能功率指令，或者通信解码后的执行指令，而不是储能逆变器测量模块返回的实际有功功率。

原因是：

- AGC输出正好叫 `Pess1_pu`、`Pess2_pu`；
- SOC函数输入也叫 `Pess1_pu`、`Pess2_pu`；
- 当前AGC和SOC接口说明中没有单独定义 `Pess1_meas`、`Pess2_meas`；
- 虽然每台储能逆变器内部确实存在 `P_meas` 实际功率测量，但现有资料只明确说明它用于设备本地功率闭环，没有明确说明它被送回SOC计算模块。

---

## 一、SOC函数本身无法判断输入是不是真实功率

SOC代码只有：

```matlab
function [SOC1,SOC2] = SOC_Calculation( ...
    Pess1_pu,Pess2_pu,time_s,...)
```

以及：

```matlab
soc1 = soc1 - Pess1_pu * P_unit_kW * dt / den;
soc2 = soc2 - Pess2_pu * P_unit_kW * dt / den;
```

对这个函数而言，`Pess1_pu` 只是一个输入数值。

它不知道这个数值来自：

- AGC功率指令
- 通信解码后的设备指令
- 逆变器实际功率测量
- 人工 Constant

真正决定信号性质的是 Simulink 中接到这个端口上的那根线。

---

## 二、当前模型里确实存在储能实际功率测量

两台储能逆变器内部有 `Measurements` 测量模块，通过电压和电流计算：

```
P_meas
Q_meas
```

这些真实测量值进入本地功率控制环：

```
Pref − P_meas → PI功率控制器 → 电流参考 → 电流环 → PWM → IGBT
```

所以储能设备内部确实有真实有功反馈。

但这只能证明：

> 储能本地控制器使用了真实功率反馈

不能自动证明：

> SOC_Calculation 也使用了该真实功率反馈

这是两个不同的信号路径。

---

## 三、当前更可能的SOC计算链路

当前资料显示AGC输出：

```
Pess1_pu
Pess2_pu
```

作为储能功率指令，经通信和本地控制最终作用到设备。

因此当前SOC模块很可能采用：

```
AGC储能功率指令 → Pess1_pu、Pess2_pu → SOC_Calculation积分 → SOC1、SOC2 → 返回AGC作为约束
```

或者稍好一些，是：

```
AGC指令 → 通信链路解码 → 设备最终收到的Pref → SOC_Calculation积分
```

但两种情况都仍然是 **"按指令估算SOC"**，而不是 **"按储能实际输出功率估算SOC"**。

---

## 四、指令功率和实际功率可能不相等

假设AGC下发：

```
ESS1指令 = +80 kW 放电
```

但由于：

- 本地功率环暂态
- PCS限流
- 直流电压限制
- 通信延时
- 设备故障

储能实际可能只放出：

```
ESS1实际功率 = +50 kW
```

### 如果SOC按指令计算

会按照 `80 kW` 扣减电量，SOC下降得过快。

### 如果SOC按实测功率计算

会按照 `50 kW` 扣减电量，这才与实际能量交换一致。

所以更真实的SOC路径应为：

```
储能端电压、电流 → 计算实际有功Pess_meas → 功率积分 → SOC
```

---

## 五、怎样在Simulink中最终确认

打开 `ESS_SOC_Calculation` 模块，沿着 `Pess1_pu`、`Pess2_pu` 两根输入线向左追踪，重点看来源。

### 如果来源是

- `AGC_Controller` 的 `Pess1_pu`/`Pess2_pu`
- 或通信解码后的 `ESS1_Pref`/`ESS2_Pref`

结论就是：

> SOC按功率指令估算

### 如果来源是

- `ESS1 Measurements` 中的 `P_meas`
- `ESS2 Measurements` 中的 `P_meas`

并且经过实际功率标幺化，结论才是：

> SOC按真实设备功率估算

当前文档没有列出 `ESS1_P_meas → SOC_Calculation` 这条明确连线，因此现阶段不能宣称它采用了实际功率。

---

## 六、当前基线和后续改进应怎样处理

### 当前内化和V4基线

先按现有代码的简化逻辑理解：

> SOC根据Pess输入进行能量积分

但在算法说明中应明确写成：

> 当前SOC模块使用输入的储能功率标幺量进行估算；该输入究竟为命令功率还是实测功率，需要根据模型连线最终确认。

不能直接写"储能真实功率"。

### 后续工程完善

建议形成明确的实际反馈接口：

```
ESS1_P_ACTUAL
ESS2_P_ACTUAL
```

并采用：

```
储能实际功率 → SOC积分 → SOC反馈给AGC
```

如果以后使用真实电池或BMS，则更合理的是：

```
BMS直接提供SOC → 板子读取SOC → AGC使用SOC
```

而不必由AGC板子自行估算完整SOC。

## 八、SOC闭环的完整理解

SOC闭环可以概括为：

```
AGC输出两台储能功率指令 Pess1、Pess2
→ SOC模块按照功率指令和时间进行能量积分
→ 得到新的SOC1、SOC2
→ SOC反馈给AGC
→ AGC根据SOC上下限限制下一周期储能充放电方向
→ 再输出新的Pess指令
```

具体来说：

```
Pess > 0 → 按指令认为储能在放电 → SOC下降
Pess < 0 → 按指令认为储能在充电 → SOC上升
```

AGC使用SOC的方法是：

```
SOC ≤ SOC_min   → 禁止继续增加放电
SOC ≥ SOC_max   → 禁止继续增加充电
SOC_min < SOC < SOC_max → 允许储能在额定功率范围内充放电
```

因此当前SOC闭环属于：

> **基于储能功率指令估算SOC，再用估算SOC约束后续功率指令的指令闭环。**

它不是基于储能实际功率测量的真实能量闭环。更准确的结构是：

```
储能功率指令 → SOC估算 → SOC边界判断 → 下一周期储能功率指令
```

而整个系统同时还有PCC总功率反馈闭环：

```
六路设备指令 → 电气模型响应 → PCC实际功率 → AGC计算dP → 重新分配六路指令
```

所以目前模型是**两层闭环**：

```
外层：PCC实际功率反馈闭环
内部约束层：基于Pess指令估算的SOC反馈闭环
```

---

## 九、SOC闭环的四个作用

这个SOC闭环的作用，是让储能不再被当作"可以无限充放电的理想功率源"，而是让AGC知道这台储能现在还剩多少电，下一周期还能不能继续充电或放电。

### 1. 反映储能能量状态随时间变化

AGC给储能下发功率指令后，SOC模块根据功率和持续时间更新SOC：

```
持续放电 → SOC逐渐下降
持续充电 → SOC逐渐上升
```

这样储能状态会随运行过程积累变化，而不是永远停留在初始SOC。

例如：

```
初始SOC = 0.60
AGC持续要求储能放电 → SOC逐步变为0.58、0.55、0.50……
```

### 2. 防止储能被无限调用

没有SOC反馈时，AGC可能一直要求储能放电或充电。

加入SOC闭环后：

```
SOC下降到SOC_min → AGC不再允许继续增加放电
SOC上升到SOC_max → AGC不再允许继续增加充电
```

因此它为储能增加了**能量边界保护**。

光伏受 `Ppvmax` 限制，是因为光伏当前"最多能发多少功率"。储能受SOC限制，是因为储能当前"还剩多少能量、还能不能继续朝该方向运行"。

### 3. 让下一周期AGC分配随储能状态变化

SOC不是只用于显示，而是重新进入AGC。

完整循环是：

```
AGC生成Pess指令 → SOC模块更新SOC → 新SOC返回AGC → AGC重新判断储能是否可用 → 调整下一周期Pess指令
```

例如储能1已经到SOC下限，而储能2仍有电：

```
ESS1：禁止继续增加放电
ESS2：仍允许放电
```

下一周期AGC会把更多调节任务交给ESS2，或继续传给充电桩，而不是继续增加ESS1放电。

### 4. 形成储能的"能量约束层"

PCC反馈回答的是：

> 整个微电网的总功率是否跟踪目标。

SOC反馈回答的是：

> 储能是否还有能力长期执行当前功率指令。

所以两者作用不同：

```
PCC闭环：控制系统总体功率目标
SOC闭环：保护和约束储能的能量状态
```

最终整个系统可以理解为：

```
PCC实际功率 → 决定系统还需要调多少功率
SOC1、SOC2  → 决定储能是否可以承担这部分调节任务
```

---

> **需要注意**：当前SOC是根据储能**功率指令**估算的，所以它反映的是"按照指令假定执行后的SOC"，并不一定等于设备真实SOC。它适合当前仿真基线，但后续可以改进为使用实际功率或BMS返回SOC。
