# 储能荷电状态算法内化

> 第二轮内化：储能 SOC 计算算法

**学习对象**：

```matlab
SOC_Calculation(2).m
```

---

## 一、模块在系统中的位置

```text
储能实际充放电功率
+ 时间
+ 储能容量
→ 计算SOC变化       ← 本模块
→ 把SOC送给AGC
→ AGC判断储能还能不能继续充电或放电
```

**它不负责决定储能应该充电还是放电**——这个决定由 AGC 作出。

它只负责回答：

> 储能按照当前功率运行了一段时间后，还剩多少电量？

当前代码通过功率对时间积分，分别计算两台储能的 SOC。

---

## 二、用"水箱故事"理解 SOC

把储能想象成一个水箱：

| 储能概念 | 水箱类比 |
|---|---|
| 储能额定能量 E_ess_kWh | 水箱总容量 |
| SOC（荷电状态） | 水箱当前水位比例 |
| 储能放电（Pess > 0） | 水从水箱流出去 |
| 储能充电（Pess < 0） | 水流进水箱 |

假设水箱最大能装 200 升水，当前装了 120 升：

```text
水位比例 = 120 ÷ 200 = 0.60 → SOC = 0.60 = 60%
```

**符号关系**（当前代码约定）：

```text
Pess > 0：储能放电，SOC 下降
Pess < 0：储能充电，SOC 上升
```

## 三、函数名称和输入输出

```matlab
function [SOC1, SOC2] = SOC_Calculation( ...
    Pess1_pu, Pess2_pu, time_s, P_unit_kW, E_ess_kWh, ...
    SOC0_ess1, SOC0_ess2, SOC_min, SOC_max)
```

### 输出

| 输出 | 含义 |
|---|---|
| **SOC1** | 储能 1 当前荷电状态 |
| **SOC2** | 储能 2 当前荷电状态 |

通常采用 0～1 小数表示：`0.20 = 20%`，`0.60 = 60%`，`0.90 = 90%`。

### 输入

| 参数 | 分解 | 含义 |
|---|---|---|
| **Pess1_pu** / **Pess2_pu** | P=Power, ess=储能系统, pu=标幺值 | 储能 1/2 有功功率标幺值 |
| **time_s** | time=时间, s=秒 | 当前仿真时间（s） |
| **P_unit_kW** | P=功率, unit=基准值, kW=千瓦 | 功率基准值，把标幺值转实际功率 |
| **E_ess_kWh** | E=Energy, ess=储能, kWh=千瓦时 | 单台储能额定能量容量 |
| **SOC0_ess1** / **SOC0_ess2** | SOC0=初始 SOC | 储能 1/2 初始荷电状态 |
| **SOC_min** / **SOC_max** | min=最小值, max=最大值 | SOC 允许范围 |

## 四、核心物理公式

```
                Pess × Δt
SOC_new = SOC_old - ───────────
                E_ess × 3600
```

| 符号 | 含义 |
|---|---|
| SOC_old | 上一次 SOC |
| SOC_new | 本次更新后的 SOC |
| Pess | 储能实际功率（kW） |
| Δt | 两次计算之间的时间差（s） |
| E_ess | 储能额定能量（kWh） |

**为什么是减号？** 当前符号约定：Pess > 0 代表放电，放电时能量减少，SOC 下降。Pess < 0 代表充电，减去负数等于加，SOC 上升。

---

## 五、为什么要乘以 3600

功率单位是 kW，储能容量单位是 kWh，但时间 dt 的单位是秒。

```text
1 小时 = 3600 秒
```

所以 `E_ess_kWh × 3600` 相当于把容量转换为 kW·s，单位才能相消：

```text
  kW × s
─────────── → 无量纲（SOC 变化量）
kWh × 3600
```

## 六、主函数逐行讲解

### 6.1 定义持久变量

```matlab
persistent soc1 soc2 last_t
```

**为什么需要 persistent？** 普通变量在函数调用结束后消失，但 SOC 计算必须记住上一时刻的值。persistent 就像储能管理员手中的账本——每次先翻开账本，再继续计算。

| 变量 | 含义 |
|---|---|
| soc1, soc2 | 两台储能上一次保存的 SOC |
| last_t | 上一次记录的时间 |

---

### 6.2 确定 SOC 上下限

```matlab
lo = min(SOC_min, SOC_max);
hi = max(SOC_min, SOC_max);
```

**参数防错**：如果用户把 SOC_min 和 SOC_max 填反了（如 min=0.90, max=0.20），代码通过 min/max 仍能得到正确区间 lo=0.20, hi=0.90。

---

### 6.3 复位标志

```matlab
resetState = false;
```

后面如果发现第一次运行或仿真时间倒退，就把它设为 true。

---

### 6.4 第一次运行初始化

```matlab
if isempty(soc1)
    soc1 = 0.0;
    soc2 = 0.0;
    last_t = time_s;
    resetState = true;
end
```

先赋值 0 只是创建变量，然后通过 `resetState = true` 让后面的初始化部分用 `SOC0_ess1/2` 设置真实初值。

---

### 6.5 时间倒退检测

```matlab
if time_s < last_t
    resetState = true;
end
```

正常仿真时间：0→1→2→3。如果模型 Reset，可能出现 100→0。此时 `time_s < last_t`，说明仿真重新开始，需要恢复初始 SOC，避免把上一轮结束时的 SOC 带到新一轮。

---

### 6.6 真正执行初始化

```matlab
if resetState
    soc1 = clamp(SOC0_ess1, lo, hi);
    soc2 = clamp(SOC0_ess2, lo, hi);
    last_t = time_s;
end
```

`clamp` 保证初始 SOC 位于 lo～hi 之间。同时 `last_t = time_s` 保证初始化后第一次时间差为 0，不会在启动瞬间产生 SOC 跳变。

---

### 6.7 计算时间间隔 dt

```matlab
dt = max(time_s - last_t, 0.0);
```

dt = delta time，即两次计算之间经过的秒数。`max(..., 0.0)` 为防止时间差意外为负数。

---

### 6.8 计算分母 den

```matlab
den = max(E_ess_kWh, 1e-6) * 3600.0;
```

`max(E_ess_kWh, 1e-6)` 防止储能容量错误设为 0 时出现除以零。`1e-6 = 0.000001` 是保护值，真实模型必须保证 `E_ess_kWh > 0`。

---

### 6.9 SOC1 更新公式

```matlab
soc1 = clamp( ...
    soc1 - Pess1_pu * P_unit_kW * dt / den, ...
    lo, hi);
```

拆解为五步：

| 步骤 | 计算 | 示例 |
|---|---|---|
| ① 标幺值转实际功率 | `Pess1_pu × P_unit_kW` | 0.5 × 100 = 50 kW |
| ② 本周期能量变化 | `功率 × dt` | 50 kW × 60 s |
| ③ 除以储能总容量 | `(功率×时间) / (容量×3600)` | SOC 变化比例 |
| ④ 从原 SOC 中减去 | `SOC_旧 - SOC变化量` | 放电 → SOC 下降 |
| ⑤ clamp 限幅 | 确保在 lo～hi 之间 | 不越界 |

储能 2 完全相同：

```matlab
soc2 = clamp( ...
    soc2 - Pess2_pu * P_unit_kW * dt / den, ...
    lo, hi);
```

---

### 6.10 更新上一次时间

```matlab
last_t = time_s;
```

记录"本次已经计算到这个时刻"，下次从这继续。

---

### 6.11 输出最终 SOC

```matlab
SOC1 = soc1;
SOC2 = soc2;
```

左边大写（SOC1, SOC2）是对外输出，右边小写（soc1, soc2）是内部持久状态。

---

## 七、辅助函数 clamp

```matlab
function y = clamp(x, lo, hi)
    y = min(max(x, lo), hi);
end
```

**执行顺序**：

1. `max(x, lo)` — 不低于下限
2. `min(..., hi)` — 不高于上限

| 情况 | x | lo | hi | 结果 |
|---|---|---|---|---|
| x 过低 | 0.10 | 0.20 | 0.90 | 0.20 |
| x 正常 | 0.60 | 0.20 | 0.90 | 0.60 |
| x 过高 | 1.10 | 0.20 | 0.90 | 0.90 |

## 八、手算示例

### 8.1 放电

**给定**：

```text
初始 SOC = 0.60
Pess1_pu = 0.5
P_unit_kW = 100 kW
E_ess_kWh = 200 kWh
运行时间 = 60 s
```

**步骤**：

```
① 实际放电功率 = 0.5 × 100 = 50 kW

② ΔSOC = (50 × 60) / (200 × 3600) = 0.0041667 = 0.41667%

③ SOC_new = 0.60 - 0.0041667 = 0.5958333
```

结果：60% → 约 59.58%。200 kWh 储能以 50 kW 放电 1 分钟，消耗了较小一部分电量。

---

### 8.2 充电

**给定**：

```text
初始 SOC = 0.60
Pess1_pu = -0.4
P_unit_kW = 100 kW
E_ess_kWh = 200 kWh
运行时间 = 60 s
```

**步骤**：

```
① 实际功率 = -0.4 × 100 = -40 kW

② ΔSOC = (-40 × 60) / (200 × 3600) = -0.0033333

③ SOC_new = 0.60 - (-0.0033333) = 0.6033333
```

结果：60% → 约 60.33%。储能充电后 SOC 上升。

## 九、当前代码的理想化假设

当前代码没有考虑：

| 缺失因素 | 说明 |
|---|---|
| **充电效率 ηch** | 外部输入 100 kWh，内部可能只增加 95 kWh |
| **放电效率 ηdis** | 内部释放 100 kWh，外部可能只得到 90 kWh |
| **自放电** | 长时间不充不放时，SOC 自然下降 |
| **温度影响** | 低温下可用容量减少 |
| **容量衰减** | 电池老化后实际容量低于额定值 |

当前假设效率为 100%，属于**理想储能模型**。这些可以作为后续模型精细化研究的点，记录但不修改。

## 十一、SOC 达到上下限的行为

假设 SOC_max = 0.90，当前 SOC = 0.899，继续充电：

```
原始计算 → 0.902
clamp 后 → 0.90（不再增加）
```

这只是 SOC 模型的物理边界保护。真正的 AGC 应提前判断：

```text
SOC ≤ SOC_min → 禁止继续放电
SOC ≥ SOC_max → 禁止继续充电
```

不能长期依赖 clamp 硬卡。

---

## 十二、clamp 与 V3.2 输入越界不是同一件事

| 场景 | 本质 | 处理方式 |
|---|---|---|
| 内部 SOC 模型 clamp | 模型自己计算的内部状态，保证不超出物理边界 | clamp 到边界 |
| 板子读到 SOC=1.20 | 外部通信输入异常 | 判定无效 → AGC 禁止使能 → 40010 置 0 |

**内部状态边界保护 ≠ 外部异常数据修正**，不可混为一谈。

## 十三、SOC 模块如何进入 AGC

```text
储能功率 → SOC随时间变化 → SOC约束AGC → AGC改变下一步储能功率 → SOC继续变化
```

**闭环关系**：

- 系统需要增加净输出（储能放电）：SOC ≤ SOC_LOW → 禁止该储能放电
- 系统需要降低净输出（储能充电）：SOC ≥ SOC_HIGH → 禁止该储能充电

---

## 十四、Ppvmax 与 SOC 的根本区别

这是理解 AGC 资源边界的关键：**Ppvmax 和 SOC 虽然都限制设备，但限制的维度不同。**

### Ppvmax：直接的功率上限

Ppvmax 来自光伏曲线模块，单位是 kW。

它直接回答：

> 光伏当前时刻最多能发多少功率？

AGC 使用它的方式是：

```text
Ppv 指令 ≤ Ppvmax
```

如果 Ppvmax = 40 kW，光伏指令绝不允许超过 40 kW。这是**硬性功率上限**。

### SOC：决定调节方向是否允许的能量状态条件

SOC 来自 SOC 计算模块，单位是 %（无量纲比例）。

它不直接回答"储能当前最多能充/放多少 kW"——那是后续裕度计算的事。

它回答的是更基础的问题：

> 储能当前是否处于允许放电或允许充电的能量状态？

### AGC 使用 SOC 的方法

```text
SOC ≤ SOC_min：
  储能已达到放电下限
  → 禁止继续放电
  → 本周期该储能不参与增功率分配

SOC ≥ SOC_max：
  储能已达到充电上限
  → 禁止继续充电
  → 本周期该储能不参与降功率分配

SOC_min < SOC < SOC_max：
  储能处于正常工作区
  → 允许在额定功率范围内充放电
```

### 一句话区分

| | Ppvmax | SOC |
|---|---|---|
| **维度** | 功率上限（kW） | 能量状态条件（无量纲） |
| **作用方式** | 直接限制指令数值 | 决定调节方向是否被允许 |
| **类比** | 水管的最大流速 | 水箱还有多少水 |

Ppvmax 说"不能超过这个数"，SOC 说"这个方向不允许操作"。

### 为什么这个区分很重要

在 AGC 分配代码中：

- Ppvmax 直接出现在 `alloc_up` 的 `pvmax` 参数中，限制光伏指令的上限
- SOC 则通过 `SOC_LOW` / `SOC_HIGH` 影响储能上下界的构造，决定储能能否参与增/减调节

两者共同决定了资源的可用范围，但机制完全不同。

## 十五、SOC_min / SOC_max 的完整角色

### 角色一：SOC 计算模块的 clamp 边界

在 `SOC_Calculation` 内部：

```matlab
lo = min(SOC_min, SOC_max);
hi = max(SOC_min, SOC_max);

soc1 = clamp(soc1 - Pess1_pu * P_unit_kW * dt / den, lo, hi);
```

这里 SOC_min 和 SOC_max 用于把计算结果限制在物理范围内，防止积分累积导致 SOC 越界。

### 角色二：AGC 中储能充放电方向判断依据

在 `AGC_Controller` 中，SOC 与 SOC_LOW / SOC_HIGH 比较后构造储能的可调边界：

```text
SOC 状态       → 储能向上调节能力     → 储能向下调节能力
─────────────────────────────────────────────────────
SOC ≤ SOC_LOW     无（禁止放电）        有（可充电）
SOC ≥ SOC_HIGH    有（可放电）          无（禁止充电）
中间区             有                    有
```

### 角色三：储能裕度计算的输入

储能放电裕度（向上调节量）不仅取决于当前 Pess 离 P_UNIT 还有多远，还要考虑 SOC 是否允许放电。

储能充电裕度（向下调节量）受 SOC 是否允许充电的制约。

所以 SOC_min 和 SOC_max 是三重角色：

```text
SOC模块内部：计算结果的clamp边界
AGC边界构造：充放电方向使能条件
裕度计算：限制储能可调范围
```

## 十六、SOC 模块在整体模型中的作用总结

```
储能实际充放电功率（Pess1_pu, Pess2_pu）
             +
        时间（time_s）
             +
        储能容量（E_ess_kWh）
             ↓
    SOC_Calculation（能量积分）
             ↓
        SOC1, SOC2
             ↓
        送给 AGC
             ↓
    AGC 用 SOC 判断：
      SOC ≤ SOC_LOW  → 禁止放电
      SOC ≥ SOC_HIGH → 禁止充电
      中间区          → 允许充放电
             ↓
    AGC 构造储能上下界 → 分配功率 → 改变 Pess
             ↓
    SOC 继续变化（闭环）
```

## 十七、核心结论

1. **SOC 是比例**：当前剩余能量占额定容量的比例，不是绝对能量值
2. **符号约定**：Pess > 0 放电（SOC↓），Pess < 0 充电（SOC↑）
3. **persistent 必要性**：保存上一周期 SOC，否则每次调用丢失历史
4. **dt 的含义**：两次调用之间的时间差，SOC 本质是功率对时间的积分
5. **×3600 的原因**：时间用秒，容量用 kWh，需要单位统一
6. **时间倒退**：仿真重新开始时 SOC 需恢复初始值
7. **clamp 的定位**：SOC 边界保护，不能替代 AGC 充放电判断
8. **理想化模型**：当前没有考虑充放电效率

## 十九、附录：三个理解的深化

### 19A. 代码没有直接写"放电"二字，如何知道 Pess > 0 是放电？

从 SOC 更新公式中的符号推导：

```matlab
soc1 = soc1 - Pess1_pu * P_unit_kW * dt / den;
```

- **Pess > 0**：新 SOC = 旧 SOC − 正数 → SOC 下降 → 放电
- **Pess < 0**：新 SOC = 旧 SOC − 负数 = 旧 SOC + 正数 → SOC 上升 → 充电

AGC 代码可反向验证：`dPnow > 0`（需增加净输出）→ `alloc_up` 使 Pess 增大（趋向正值）→ 储能放电。

这是人为规定的功率正方向。换一套模型也可规定"充电为正"，但 SOC 公式、AGC 分配、设备接口必须全部同步改变。

---

### 19B. `function y = clamp(...)` 不多余

文件中的 `clamp(...)` 是**调用**函数，末尾的 `function y = clamp(...)` 是**定义**函数。

| 位置 | 角色 |
|---|---|
| `soc1 = clamp(SOC0_ess1, lo, hi);` | 调用——让"保安"检查数值 |
| `function y = clamp(...)` | 定义——规定"保安"怎样检查 |

若删除定义，MATLAB 会报"未定义函数或变量 'clamp'"。也可以把 `y` 改名：

```matlab
function result = clamp(x, lo, hi)
    result = min(max(x, lo), hi);
end
```

功能完全相同。辅助函数的好处：减少重复代码、提高可读性、保证处理方式一致。

---

### 19C. SOC 是一种比例，公式不是随意编造的

SOC = 当前可用储能量 ÷ 额定总容量，无量纲比例。

更新公式来自基本能量关系：

```
ΔE = P × Δt           （能量变化 = 功率 × 时间）
ΔSOC = ΔE / E_rated   （SOC 变化 = 能量变化 ÷ 额定容量）
```

代入得：

```
ΔSOC = (P × Δt) / (E_rated × 3600)   （加上单位换算）
```

**物理基础**：能量守恒
**人为选择**：功率正方向
**程序实现**：把连续能量积分离散成每个仿真周期更新一次

> SOC 的定义是物理概念，SOC 计算模型可以有不同复杂程度。当前代码选择了最基础的能量积分模型，没有考虑效率、温度、老化等因素。
