# ESS2 下一步到底怎么从“小功率、小权限”平滑放开到正常运行

日期：2026-09-18

## 一、先给结论

当前主方向没有变：

```text
小功率恢复
→ 小权限接管
→ 小权限一次协调
→ 正常基础任务逐步放开
→ 一次协调权限逐步放开
→ 正常ESS2运行
→ 再恢复下一台GFL资源
```

我前面提到的 `Mode4 / 正常基础任务更新` **不是另一条路线**，而是上述“逐步放开”过程中必须确认的一条功能通道。

---

# 二、为什么已经到 -0.006 pu，还要验证“基础任务更新”？

当前已经实测：

```text
基础任务 Pbase = -0.005 pu
Primary 权限   = ±0.001 pu
```

本轮频率偏高，所以一次调频修正把最终命令推到：

```text
Pfinal ≈ -0.006 pu
```

这证明的是：

> Coordinator（正常协调器）可以围绕固定基准 `-0.005 pu`，利用 Primary（一次有功-频率协调）临时调整功率。

它还没有证明：

> 正常调度可以把 ESS2 的基础任务本身从 `-0.005 pu` 改成新的目标。

两者完全不同。

概念上：

```text
Pfinal
=
Pbase
+
ΔPprimary
+
ΔPsecondary
```

当前已经证明：

```text
Pbase固定 = -0.005
ΔPprimary可以变化
```

还没有证明：

```text
Pbase可以由正常调度更新
```

如果只扩大 Primary authority，而 Pbase 永远锁在 `-0.005`，那 ESS2 仍然只是“围绕500 W工作点调频”，不是正常接受新的充放电任务。

---

# 三、什么才叫“逐步平滑放开到正常”？

这里至少有三件事情要逐步放开。

## 1. 基础任务范围

当前：

```text
Pbase = -0.005 pu
```

以后正常运行应该能够：

```text
上层正常功率管理
↓
给出新的ESS2目标
↓
Coordinator平滑更新Pbase
```

例如未来可能：

```text
-0.005
→ -0.010
→ ...
```

具体范围不能现在凭空指定，应依据 ESS1/ESS2实际余量确定。

## 2. 调节权限 authority

当前：

```text
Primary authority = ±0.001 pu
```

也就是只允许在基础任务周围约±100 W动作。

以后可以逐渐扩大。

但：

```text
authority
```

只表示“允许偏离基础任务多少”，不是正常基础任务本身。

## 3. 可用资源数量

当前孤岛协调基本只有：

```text
ESS1 = GFM
ESS2 = 已恢复GFL
```

以后才是：

```text
PV1
PV2
EV1
EV2
```

逐个恢复。

所以“正常放开”不是一个开关，而是：

```text
正常任务范围
+
调节权限
+
资源数量
```

逐步扩展。

---

# 四、Mode4 到底是什么？

不要把 Mode4 理解成一个额外的正式运行阶段。

它的作用只是：

> 把“改变基础任务”与“Primary调频修正”分离开来验证。

当前 Mode5 已经证明：

```text
Coordinator接管
+
Primary小权限
```

Mode4可以让我们做：

```text
Coordinator已经接管
+
Primary不参与
+
只改变ESS2正常基础任务
```

所以它是一个调试工具，用来回答：

> 当上层正常任务改变时，Coordinator能不能平滑地把ESS2从旧Pbase移到新Pbase？

不是让系统以后一直运行在Mode4。

---

# 五、下一轮为什么先用 -0.005 → -0.006？

不是因为我们认为正常运行只需要600 W。

而是因为：

```text
-0.006 pu
```

本轮已经由 Primary 真正执行并稳定保持了十几秒。

因此：

```text
-0.005 → -0.006
```

不会引入新的“更大功率稳定性”问题。

它只验证：

```text
Normal task input
→ baseline update
→ rate limiter
→ final command
```

这条软件/控制通道。

如果直接下一轮同时做：

```text
新baseline通道
+
大功率
+
大authority
```

一旦出问题，又无法区分：

```text
是正常任务入口写错
还是功率放太大
还是ESS1余量不够
还是斜坡太快
```

---

# 六、但不需要为 -0.006 单独浪费一个完整大周期

这一点很重要。

不建议再做：

```text
Build
→ 60秒
→ 只验证 -0.005→-0.006
→ 再Build
```

更高效的做法是：

## 同一版模型、同一轮正式扩展试验

先：

```text
Phase A
已验证链条快速进入：
Restore
→ Handover
```

然后：

```text
Phase B
Primary OFF
Pbase:
-0.005 → -0.006
```

确认正常任务入口工作。

如果这一小段满足：

```text
命令来源正确
baseline更新正确
限速正确
无跳变
ESS1/ESS2健康
```

则在**同一轮试验**继续：

```text
Phase C
平滑扩大到下一档经过批准的正常任务
```

这个“下一档”不应现在随便写死，应先依据：

```text
ESS1 P/Q/current/modulation余量
ESS2 current/modulation余量
母线V/f
```

确定。

这样才能真正做到：

> 从小功率平滑向正常功率扩展，而不是每100 W单独跑一轮。

---

# 七、我们还需要验证什么？

从现在到“ESS2正常运行”，剩下的核心不是很多。

## 已经不用再重复验证

已经有真实动态证据：

```text
ESS1构网
ESS2真实并回
ESS2小功率执行
Restore-state7
S14→Coordinator无扰接管
Beta 0→1
小权限Primary
```

这些不应该反复重做为独立课题。

以后只作为每次正式序列的前置过程。

---

## 还需要验证1：正常基础任务入口

必须确认：

```text
normal target
↓
baseline
↓
rate limit
↓
final P command
```

能真正工作。

这是当前最直接的下一步。

---

## 还需要验证2：更大功率时的ESS1/ESS2余量

现在不能简单说：

```text
ESS2额定100 kW
所以直接放到几十kW
```

孤岛里 ESS1 是唯一 GFM。

ESS2功率改变后：

```text
ESS1必须承担岛内功率平衡变化
```

所以扩大ESS2任务前至少要看：

```text
ESS1 P
ESS1 Q
ESS1 current
ESS1 modulation
母线V/f

ESS2 current
ESS2 modulation
```

不是为了增加新的复杂算法，而是避免把ESS1顶到边界。

---

## 还需要验证3：正常任务扩大时的平滑限速

即：

```text
Pbase old
→ Pbase new
```

应该通过可控斜坡，而不是阶跃。

我们需要证明：

```text
任务变化率受限
最终任务能到
没有持续振荡
没有限流
```

---

## 还需要验证4：扩大后重新允许Primary

基础任务范围扩大以后：

```text
Pfinal = 新Pbase + Primary
```

再确认一次Primary仍能围绕新工作点正确动作。

这一项通常不需要重新从零设计，因为小权限Primary已经通过。

---

# 八、ESS2真正“正常放开”的路线

建议现在把路线冻结成：

```text
当前里程碑
Pbase=-0.005
Primary authority=±0.001
Coordinator ownership=100%
        ↓

A. 正常基础任务入口
先用已证明的 -0.006 验证baseline更新
        ↓

B. 加入ESS1/ESS2余量边界
确定下一档可批准功率范围
        ↓

C. ESS2正常基础任务逐步扩大
不是每100 W一档，而是按可解释的工程区间平滑扩大
        ↓

D. Primary在新baseline上重新开放
        ↓

E. 扩大Primary authority
        ↓

F. ESS2达到本阶段“正常孤岛运行”
        ↓

G. 恢复下一台GFL
PV / EV逐台进入相同流程
```

---

# 九、“正常放开”不等于“取消所有限制”

最终正常运行也仍然应该有：

```text
P上下限
Q上下限
电流限制
调制限制
SOC/能量限制
变化率限制
ESS1共享余量
```

所以我们最终追求的是：

> 从调试小权限，逐步扩大到设备和系统实际允许的正常运行范围。

不是：

> 最后把所有限制全部设成无限大。

---

# 十、当前下一步一句话

**下一步仍然是你理解的“从小功率小权限继续平滑向正常放开”。**

只是具体第一件事应该是：

> 让 Coordinator 不再永远围绕固定 `-0.005 pu` 工作，而是能够接收并平滑执行新的正常基础功率目标。

`-0.005 → -0.006` 只是这条通道的低风险起始验证点，不是新的最终目标，也不需要为它单独浪费一整轮长期试验。

之后马上就进入：

```text
根据ESS1/ESS2真实余量
→ 扩大Pbase范围
→ 扩大authority
→ 正常ESS2运行
```
