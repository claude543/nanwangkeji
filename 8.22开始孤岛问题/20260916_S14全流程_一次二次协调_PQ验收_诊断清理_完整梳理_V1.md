# 1. 下一轮先做P+Q小功率验收：这个思路正确

## 1.1 为什么先开Q外环

当前稳定小功率试验一直使用：

```text
P loop = ON
Q loop = OFF
```

所以我们已经证明：

> Q外环不是原P环低频负阻尼出现的必要因素。

但这并不等于：

> Q外环已经证明可以安全投入。

因此，在进入S14正式无扰接管之前，先做一轮：

```text
P loop = ON
Q loop = ON
```

是合理而且必要的。

---

# 2. 这一轮Q应该怎么验

最干净的第一轮不是马上给一个非零Q目标。

建议：

```text
P target = -0.005 pu
Qref = 0
```

P参数：

```text
Kp_P = 0.06
Ki_P = 0.5
```

Q参数暂时保持模型原值：

```text
Kp_Q = 0.06
Ki_Q = 2
```

其它继续保持诊断基线：

```text
support实际执行 = 0
Coordinator handover = OFF
Primary = OFF
Secondary = OFF
Direct dq branch = OFF
```

与上一轮P-only相比，只新增：

```text
Q loop OFF
→
Q loop ON
```

所以如果系统动态明显改变，因果解释非常干净。

---

# 3. PQ小功率PASS究竟能证明什么

如果：

```text
P=-0.005
Qref=0
Q loop ON
```

仍然：

- Vpu / PLL / Pmeas / Qmeas / Imeas不出现增长；
- P保持良好跟踪；
- Q保持在合理零附近；
- QIntegral没有异常放大；
- CurrentLimit=0；
- 调制裕量健康；

那么可以说：

> **Q外环以零Q参考闭环投入，不会重新引入当前已知的弱岛低频不稳定。**

但不能过度表述为：

> “Q外环任何工况都完全没问题。”

因为还没有测试：

```text
非零Qref
```

如果后续正常运行确实需要明确非零无功跟踪，则在更后面还应补：

```text
Q-only / small-Q
```

或者正常电压/无功协调工况。

# 4. PQ通过以后，为什么应该清理诊断改造

当前模型里为了定位根因，故意加入了很多“只为实验而存在”的结构。

它们完成任务后继续长期保留，会导致：

- 模型路径变复杂；
- 最终S14流程和BASETEST流程并存；
- 以后很容易再混淆“正式功能”和“诊断功能”；
- 交付/维护困难。

所以PQ通过以后，应进入：

```text
诊断结构清理
+
正式结构重新审计
```

而不是继续在诊断模型上一路堆状态。

# 11. S14Substate 20：ESS2_GFL_PREPARE

ESS2仍未正式功率承担。

# 12. S14Substate 25：ISLAND_STABILIZE PRE-CLOSE HOLD

这是后来专门保留下来的重要状态。

```text

```

但 Restore Executor仍被限制在：


```text
4 s
```

为什么存在：

> 历史R6.1证明GFL工程Stage2先稳定一段时间，再允许真实breaker动作更可靠。

因此它是：

```text
“控制器先准备好”
和
“真的物理合闸”
```

之间的隔离层。

# 16. beta到底是什么

最终功率命令概念上：

```text
Pfinal
=
(1-beta) * P_S14
+
beta * P_Coordinator
```

state40：

```text
beta ≈ 0
```

所以：

```text
S14拥有功率
```

state50：

```text
beta: 0 → 1
```

约2秒。

beta=1：

```text
Coordinator拥有功率命令
```

所以beta回答的是：

> **控制权归谁？**

不是：

> “ESS2能调多少？”

# 17. 为什么handover期间功率目标基本不变

在ESS2还没有Available的时候，Coordinator内部：

```text
Pbase_ESS2
```

一直跟踪：

```text
Pmeas_ESS2
```

所以在state40：

```text
Pmeas ≈ -0.005
```

时，Coordinator内部基线也应该：

```text
≈ -0.005
```

于是state50：

```text
S14 target       ≈ -0.005
Coordinator base ≈ -0.005
```

beta从0到1时：

```text
数值目标几乎不变
```

只是：

```text
所有者换了
```

这叫：


# 18. 为什么beta=1之后还要state60

这是第二个最容易误解的地方。

如果beta=1只表示：

```text
Coordinator已经拿到方向盘
```

那么state60做的是：

```text
允许它开始真的“打方向”
```

state50：

```text
Coordinator只接住当前工作点
```

state60：

```text
Coordinator开始根据频率偏差进行一次协调
```

所以这两步必须分开。

否则：

```text
beta刚到1
+
一次频率修正同时全强度出现
```

又会造成新的功率阶跃。

# 19. Primary（一次协调）到底是什么

它来自原有的：

```text
Normal Island Coordinator（正常孤岛协调器）
```

不是S14临时发明的。

核心公式概念上：

```text
频率误差：
ef = 50 Hz - master_f

经过：
滤波
+
deadband（死区）

得到：
ef_db

Primary P correction：
dp_primary
=
Kpf * ef_db
```

当前S14 V2还在外面乘：

```text
CorrectionGain
```

实际：

```text
dp_primary
=
CorrectionGain * Kpf * ef_db
```

Primary特点：

```text
快
不积累长期历史误差
频率偏了就立即按比例给功率帮助
```

类似传统电力系统里的：

```text
一次调频 / droop-like response
```

它主要负责：

> 频率刚偏时快速帮ESS1分担功率失配。

state50只验证：


如果state50同时：

然后：

而且不是瞬间满强度。


参数：

```text
Rising = 0.25 /s
```

所以：

```text
CorrectionGain 0 → 1
```

约4秒。

又增加了一层平滑。

# 21. authority（保守权限）到底是什么

进入Coordinator以后，ESS2理论设备容量很大。

但：

> 设备额定容量不是“当前黑启动孤岛允许它安全调多少功率”的同义词。

因此当前S14 V2给ESS2定义：

```text
ESS2CoordAuthority
```

默认：

```text
0.01 pu
```

Core内部硬上限：

```text
0.02 pu
```

意思：

> Coordinator即使算出一个很大的频率修正，也只能让ESS2在“当前捕获稳定基线”附近小范围移动。

例如稳定基线：

```text
Pbase ≈ -0.005
```

authority=0.01时：

```text
ESS2正常协调只允许在大约：

-0.015 ~ +0.005 pu

这个局部范围内承担修正
```

具体还受ESS2本身充放电能力边界限制。

---

# 22. authority是不是多余

不是。

它和beta解决完全不同的问题。

可以类比：

```text
beta
=
把方向盘从教练手里交给驾驶员

authority
=
方向盘暂时只允许小角度转动
```

beta回答：

```text
谁控制？
```

authority回答：

```text
新的控制者最多能改多少？
```

所以：

```text
beta=1
```

并不意味着：

```text
Coordinator可以立即给ESS2 ±1 pu
```

---

# 23. 为什么当前必须保守限制authority

因为当前：

```text
ESS1 = 唯一GFM
```

而目前模型**没有真正的动态ESS1 GFM reserve监督算法**。

当前没有显式根据：

- ESS1电流；
- ESS1 modulation headroom；
- ESS1 P/Q剩余能力；

动态算出：

```text
“ESS1现在还能安全托住多少额外失配”
```

所以当前不能自信地说：

```text
ESS2有1 pu设备能力
→ 黑启动时就可以随便调1 pu
```

当前方案故意使用：

```text
0.01默认
0.02硬上限
```

作为安全诊断边界。

这是保守但合理的工程做法。

后续扩大到：

```text
更大ESS2正常调节
+
PV/EV逐台恢复
```

时，应增加真正：

```text
ESS1 GFM reserve supervision
```

而不是永远依靠0.02硬上限。

# 24. Secondary（二次协调）到底是什么

Secondary同样来自已有的正常孤岛Coordinator。

Primary快速响应以后，典型结果是：

```text
频率偏差变小
但不一定精确回50 Hz
```

Secondary的任务：

> 把长期剩余频率偏差继续积分掉，让频率恢复到标称值附近。

当前Coordinator中已有：

```text
secondary frequency-restoration integrator
```

概念：

```text
p_sec
←
p_sec + Ki_sec * frequency_error * Ts
```

并且带：

- entry delay；
- slew limit；
- capability clamp。

因此：

```text
Primary = 快速按频差比例帮忙
Secondary = 更慢地累计剩余频差，把频率真正恢复
```

此外Coordinator还有：

```text
slow voltage restoration
```

同样只在Secondary权限打开后才参与。

# 27. S14 coarse stage又是什么

S14还保留了粗粒度：

```text
0 = 非黑启动
1 = ESS1形成 / ESS2准备
2 = ESS2恢复 / 承担 / 交接
3 = PV层（未来）
4 = EV层（未来）
-1 = fail
```

这是为了兼容原15策略外层接口。

真正的细步骤：

```text
10/20/25/30/40/50/60...
```

放在：

```text
S14Substate
```

里。

所以：

```text
coarse stage=2
```

并不意味着只对应一个动作，它内部包含：

```text
ESS2 zero reconnect
pickup
handover
primary
```

多个细阶段。

# 28. 为什么我们一定要把这些环节拆得这么细

因为黑启动里同时存在三种完全不同的问题：

## 物理接入问题

```text
breaker
同步
V/f
电流
```

## 本地设备功率控制问题

```text
P/Q PI
Current Adapter
Current Regulator
```

## 系统级协调问题

```text
谁拥有命令
频率一次修正
二次恢复
多资源调度
```

如果全部一次打开：

```text
失败
```

以后没有办法定位。

分层状态的真正意义就是：

> 每跨一个状态，只增加一种新的控制责任。

# 37. 本轮讨论形成的最终认知

## beta不是调功率大小的参数



决定：


只有接管已经完成以后才打开。

```text
Secondary = slow integral restoration
```

负责消除Primary后的长期频率偏差。
