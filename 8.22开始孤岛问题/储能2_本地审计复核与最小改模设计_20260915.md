## 三、本地数值确认后，哪些疑问已经结束

### 3.1 功率环参数不是未解析的符号了

共同父路径：

`K26_K50_CLEAN_P1/SS_Slave2/ESS2_Control`（当前模型／第二从任务／储能2控制器）。

| 位置与参数 | 已求值结果 |
|---|---:|
| `Power Control Loop`（功率控制环）内有功、无功比例增益 | 0.06 |
| 同上，积分增益 | 2 |
| 两个功率积分器初值 | 0 |
| 采样时间 | 0.0001秒，即100微秒 |
| 有功基础电流输出上下限 | −1.25、+1.25标幺 |
| 无功基础电流输出上下限 | −1、+1标幺 |
| 两个功率积分器的外部复位方式 | 无外部复位 |
| 功率基准 | 100000瓦 |
| 储能2电流环前馈电阻、电感参数 | 0.004、0.21标幺 |

因此，当前负0.005标幺的有功任务对应−500瓦；按本项目正负约定，它表示储能2从交流侧吸收约500瓦。这里依据的是当前模型功率基准，不能把它当作所有设备或其他工程的通用换算。[R4]

电流环使用的0.3和20，与这里功率环的0.06和2不是同一组增益。本轮两组都不调整。

### 3.2 恢复放行系数为零，不等于积分器清零

`RestoreAlpha`（恢复放行系数）先把功率误差乘零，功率环因此暂不根据新误差继续调节；但这不是将已有积分输出重新设为零。离散积分的状态复位需要明确的复位机制，不能把零输入当作复位。[R4][R5][W2]

**现在为什么有风险：**若曾经运行过功率任务后失败，同一轮内直接再次放行，可能把上次留下的基础电流一起恢复。

**本轮正确处理：**只验证一次新初始化后的首次恢复；失败后保持失败，不自动重试。初值为零与前序误差门控为零必须在本次运行中对应起来。后续确实需要自动重试时，再单独定义积分状态匹配。

### 3.3 旧监督电压控制确实具有启动条件

本地读取确认 `K1B_Ctrl_On_Step`（旧监督使能阶跃）为：5秒、从0变1。旧电压调节器初值为10000伏，输出范围为9600～10400伏。[R4]

这确认了旧电压参考路径有实际启用条件，但不是已经测到旧调节器在失败时从9600变到10400伏。其运行轨迹仍需下一次记录。

**现在不正确的说法：**关闭新协调器的二次电压功能，就等于储能2收到的电压参考固定。

**正确的说法：**新二次偏移关闭了，但新协调器仍可能跟踪旧电压基准。必须检查最终生效的参考从哪里来，不能只看一个使能位。

## 四、这一次为什么没有证明储能2带不了小功率

上一轮失败前，计划的小功率目标刚开始变化；与此同时，恢复放行系数从0直接变成1，允许选中的完整电流请求进入电流调节。那个完整请求还含有附加支撑，不只是功率环基础请求。[R5][P1]

我们希望检验的是：

“储能2只增加一点充电功率时，系统能否稳定？”

实际同时改变的是：

“增加一点功率任务，并允许一组已经计算出来的附加电流参与执行。”

所以试验没有把两个作用分开。故障又发生在尚未到达−0.005标幺之前，不能由此判定−500瓦稳态无法存在。

此外，本次失败记录在功率开放前就有电压波动。**隔离附加请求能够使下一次试验更明确，不保证它会自动消除此前全部波动。**如果修改后在开放基础功率之前已经恶化，应停在该阶段研究，而不是继续把失败归给小功率任务。

### 6.2 为什么不在最终输出后减掉支撑

原有限流是在基础电流和支撑电流共同存在时算的。它们有时相互抵消。限幅后再减掉其中一项，可能使剩余电流超过总限值，也可能留下先前分配对基础电流的压缩。

**正确方式是先决定本次允许哪些请求参与，再对这些请求一起限幅。**这样真实电流、基础电流允许比例、支撑诊断及下一拍反馈来自同一次计算。

在储能2角色、附加请求全零的分支中，现有公式退化为：

$$
\boldsymbol B=\boldsymbol u i_P+\boldsymbol n i_R,
\qquad
\boldsymbol F=\lambda\boldsymbol B,
\qquad
\lambda=\min\left(1,\frac{I_{\max}}{\|\boldsymbol B\|}\right).
$$

零向量单独按比例1处理。这里 $\boldsymbol u$ 为真实电压单位方向，$\boldsymbol n$ 为其正交方向，$i_P,i_R$ 为功率环基础标量，$I_{\max}$ 为总电流上限。该分支同时应输出零附加支撑，基础限幅仍如实反馈。

此前保存源码代数检查支持这个退化关系，但它不证明整个电气闭环稳定。[P2]

### 6.3 内部尚未执行的请求怎样处理

本轮不要求全部31个滤波、延时和历史状态都为零。

- 必要电压前馈及坐标状态继续更新。
- 附加请求可以继续作为诊断计算，但不能进入实际电流、共同能力分配或功率权限修正。
- 支撑活动统计应看到“已允许分配的附加支撑为零”，而非把未允许的请求算作已执行。
- 新初始化的一轮中，相关活动状态应从已有零初值开始。若从非零历史状态进入诊断，本轮不自动允许；那属于另一个切换工况。

通俗地说：**不需要所有后台算法停止计算，只需要它们在本轮没有被允许时，不能通过其他通道继续改变本次基础功率任务。**

**零电流参考与零有功目标不是完全同一个工况。**开放基础功率环以后，即使目标仍为0，实际偏差也可能产生纠偏电流。因此中间的零目标观察不是重复旧合闸研究，而是检查这个新的控制开放事件。

二值恢复系数本身不必禁止。如果开放前基础请求与当前实际采用请求接近，就不需要再给它套另一条恢复斜坡。本轮先核对它所开放的内容，不把“多加一个渐变”当作必然正确。

### 8.3 不在本轮新增连续健康门控

功率目标不随母线电压反复升降，也不新增一套自动寻找稳定功率的控制器。已有功率斜坡保持确定目标和确定速度。

但严重异常保护保留。取消连续目标门控，不等于取消过流、严重欠压或无效数据时的停止条件。

## 九、拟采用的状态和时间安排

本节为**设计建议及首轮诊断参数建议**，不是设备规范或已经完成的试验。

上层位置：

`K26_K50_CLEAN_P1/SM_Master/Advanced_Microgrid_15_Strategies/Advanced_Strategy_Core`  
（主任务／15策略计算容器／现有上层策略核心）。

保留现有上层状态机，不新建第三套状态机。仅在诊断分支中增加一个基础电流开放观察子状态；非诊断分支保持当前行为。

| 拟采用阶段 | 上层编号建议 | 本地跟网阶段 | 恢复阶段 | 本轮功率任务与退出条件 |
|---|---:|---:|---:|---|
| 既有建压、准备、合闸 | 原10、20、25、30 | 沿用原顺序 | 沿用原顺序 | 不重新设计同期和真实合闸 |
| 基础电流开放，零目标观察 | 新35，明确为拟新增编号 | 2 | 3 | 目标仍0；先确认本地真正进入恢复状态6，再累计观察时间 |
| 小功率斜坡及固定平台 | 原40的诊断分支 | 2 | 3 | 沿用目标−0.005及每秒−0.0025的下降斜率；本机资格成立后仍不进入50 |
| 结束或失败 | 诊断完成标记／原90 | 保持明确安全语义 | 依当前退出方式 | 正常结束暂停取证；失败不自动重试、不回到强网控制 |

首轮可先给基础电流开放后的零目标观察5秒，固定小功率达到后观察30秒；这是为了分离两个事件并覆盖既有较晚异常时间尺度的**起始建议**，不是“等满时间自动稳定”。

时间计数应从真实本地反馈确认的事件开始：不能上层一发恢复阶段3，就把尚未收到指令的从任务当成已经开放。目标平台计时从本地实际收到最终功率指令并达到目标附近开始，不从总试验零时刻开始。

原固定小功率阶段12秒超时必须相应改成覆盖斜坡、资格及平台的有界诊断超时；本轮建议从本阶段开始最长60秒，不成功就作为超时诊断停止。零目标开放状态另设有界超时。总试验最长时长应统一约束，例如不超过120秒，记录容量按总长计算。

若零目标观察时已经持续恶化，不为完成后续计划而强行加功率。若采用分段暂停人工判断，也必须使用目标机时间，不能把电脑等待时间当成电气稳定时间。这只是诊断操作选择，不新增连续功率控制环。

## 十、完成判据怎样改，才既明确又不苛求零波动

### 10.1 本机任务资格与长期稳定结论分开

当前恢复执行器已收到原48维工程诊断；其中第24项为实际进入本地控制的有功指令，第16项为实测有功，第26项才是内部处理参考。**这里是恢复执行器收到的原诊断，不是被重打包覆盖后的记录通道。**[R5][P2]

本轮拟改为：

1. 本地收到的有功指令已经接近本次固定目标；
2. 实测有功与最终任务方向一致，且误差在明确诊断容许范围内；
3. 电压、频率、电流及执行余量满足既有资格；
4. 资格持续满足后，只宣布本机达到任务，不据此宣布长期稳定。

可以继续把已有0.002标幺功率误差界限作为首轮诊断起点，同时另外检查任务是否真的到达−0.005附近；0.002对应200瓦，是当前诊断的较宽范围，不是正式产品精度标准。不用一个很小的相对百分比去限制接近零的量。

没有必要先新增三层自动收敛控制模块。对连续窗口的均值、波动幅值及变化趋势做离线分析即可。非发散和数学意义上的渐近收敛不是同一个结论；报告中按实际证据命名。

### 10.2 为什么不能只看均值

平均电压接近额定，但若波动接近安全上下限，系统已经没有足够余量承受下一步变化；实测功率波动若远大于500瓦，也难以判断500瓦任务的跟踪是否真实。

所以本轮不要求完全无波动，但需要回答：均值是否漂移，幅值是否增长，是否反复接近保护边界，是否还能区分本次功率任务。没有充分依据时不先指定1%或2%的波动标准。

## 十一、旧电压参考本轮如何处理

**本轮先不删除旧电压调节器，也不改储能1电压目标。**

根据已导出的储能2状态核心，旧电压参考变化进入本地慢电压支撑目标；必要电压前馈另由本地测量和已捕获锚点计算。功率环内的电压比较支路终止，不进入功率比例积分器。[R5][P2]

因此在四类附加请求于共同分配前被隔离、本地阶段2保持、中央无功偏置为零的诊断条件下，旧参考可继续作为后台量被记录，但不应再通过这些支撑请求改变本轮执行电流或功率权限。

这是一项**需要用修改后单元试验验证的路径隔离要求**，不是已经运行证明。测试时固定其他输入，只改变旧电压参考，基础电流执行输出和基础功率允许比例应不随之改变；后台支撑计算值可以改变。若不成立，先修正漏掉的消费者，不急于删除全局旧调节器。

## 十二、异常退出不能再留语义空白

本次正常设计只讨论首次恢复，不加自动重试；同时必须保证新增长观察期的保护覆盖完整。

| 情况 | 本轮设计要求 |
|---|---|
| 普通小幅波动或暂时跟踪不足 | 记录，不用连续反馈反复改功率目标 |
| 严重欠压、过流、数据无效或明确执行失效 | 进入现有失败处理，禁止自动推进、禁止自动重新放行 |
| 断路器保持闭合的退出 | 保持真实电流反馈；取消任务与参考放行，不把测量置零 |
| 配置允许物理开断 | 用已有断路器路径退出，并记录指令及实际可观测电气响应；不能把发出开断指令直接写成物理触点已断 |
| 试验脚本停止 | 优先暂停和保留状态，不因普通坏波形立即复位清除证据 |

恢复状态5当前没有与状态6同样完整的严重异常分支。本轮若延长该阶段，应把这段保护缺口一并处理；否则“等待更久”可能只延长无明确退出的异常运行。处理应复用已有严重异常判断和退出路径，不增加一套正常功率恢复门控。[R5]

## 十三、记录设计必须与控制修改一起完成

### 13.1 已查明的事实

本地再次确认第27、29、30组使用实时记录方式，且记录块的两个文件状态输出都没有消费者。此前原始文件存在分包边界时间缺口，储能1记录没有覆盖真正功率故障尾段。现有文件远小于容量上限；旧尾段缺失不是这次写满文件。[R7][P2]

官方说明明确区分记录分包、完整缓冲提交、文件关闭和回传。暂停模型不能被我们自行解释成所有尾段已经提交；实时方式允许包间缺口，强行改为无丢样仿真记录可能不再保持实时性。[W3]

### 13.2 下一版最低取证要求

| 需要看到的量 | 取值原则 |
|---|---|
| 本地真正收到的有功任务、内部有效参考、实测有功 | 三者同时记录，不互相替代 |
| 恢复阶段、本地阶段、恢复保持、恢复系数、最终连接模式 | 在接收任务中取得，不能只记录发送端 |
| 功率环基础输出与积分状态 | 直接从已有输出／状态取值；不把基础有功标量再次当执行坐标投影 |
| 被允许进入分配的四路附加请求及共同分配支撑输出 | 证明本轮确实没有间接参与，而非只写了一个禁用参数 |
| 真正送进适配器计算的电流参考与电流反馈 | 优先在同一次函数计算中增加只读诊断输出，不用旁路重算冒充内部探针 |
| 实际限幅、调制需求与余量 | 区分共同电流分配限制与适配器电压／调制限制，不能只依赖一个旧标志 |
| 储能1的电压、电流、功率及调制状态 | 必须覆盖基础电流开放、小功率开始、故障或平台结束 |
| 上游旧电压参考与储能2接收电压参考 | 解释此前参考变化，不再用已被覆盖通道读取 |
| 文件限制标志、文件开闭状态 | 接出记录块真实输出，核对保存与回传过程 |

现有第27组1～62通道、第29组1～68通道及第30组原通道含义不再覆盖。新增量采用尾部追加或单独明确的诊断输出；正式脚本生成新的通道表及宽度核验。不能为了少改维度，再覆盖一个看似暂时没用的旧通道。

若为适配器增加诊断输出，只在外层把已经实际使用的参考、反馈等值直接输出；其两个既有计算输出和内部电流调节辅助函数数值算法保持不变，并通过前后等价测试确认。不能借取证之名顺手更改电流环。

### 13.3 文件结束与尾段覆盖的边界

本轮开始设计可以不再向你要文件；但**下一次正式电气试验前，必须验证记录结束流程，而不是继续只扫描电脑目录是否有文件。**

优先在本地已安装版本的记录块机制内设计：正常安全运行结束时明确关闭当前记录段并取得完成状态；需要采用动态文件编号时，利用官方支持的编号改变关闭旧段，但这本身不保证未满的数据包也会全部保存。严重异常时优先暂停，不为填满缓冲区继续异常运行。[W3]

文件取得方式、暂停后允许的操作与最终回传步骤，放进下一版运行脚本的专门验证；不在这里虚构一个已验证可用的刷新命令。若旧方式确实无法保留故障前最后的关键值，可增加事件瞬间的只读锁存诊断；它只能补事件值，不能冒充缺失的连续波形。

容量按“启动全过程＋零目标观察＋功率斜坡＋固定平台＋正常结束余量”的总时长，以及最终新增通道数计算。不能仅按平台30秒计算，也不能以扩大容量代替尾段完成验证。

## 十四、模块形式怎样选

| 功能 | 本轮推荐 | 选择理由 |
|---|---|---|
| 四个附加请求取原值或零 | 普通 `Switch`（选择块） | 明确、少状态，容易逐端口检查，不改既有限幅数学 |
| 目标功率缓变 | 复用 `PickupRateLimiter`（小功率变化率限制器） | 已有实例已成功构建；不新增第二条斜坡 |
| 本轮顺序、超时、失败锁定 | 修改已有策略核心及恢复执行器的诊断分支 | 不新增相互独立的第三套状态机 |
| 实际方向转换和总电流几何约束 | 保留现有 `MATLAB Function`（MATLAB函数模块） | 这是复杂而边界清楚的计算，不因形式偏好拆成大量基本块 |
| 稳定判断 | 先在原始数据中作离线分析 | 当前不需要自动调整目标的收敛控制器 |
| 新增诊断 | 固定维度、明确采样；尾部追加并核验 | 兼顾记录可信度与既有实时接口 |

MathWorks（数学计算软件公司）官方支持函数模块参与代码生成，但具体代码必须满足代码生成限制；变化率限制块也支持代码生成，且在离散运行方式下有明确初始条件处理。**官方支持不等于当前实时构建必然通过**；仍以本地2023b环境、现有平台配置与重新构建结果为准。[W4][W5]

因此不作“普通块永远更好”或“函数越少越可靠”的判断。此次选择的依据是最少改变状态语义、复用成功实例、易于验证、保留实时兼容环境。

## 十七、边界和当前判断

可以确定：现有小功率恢复试验把附加请求放行与有功任务变化混在一起；阶段和部分证据的语义也有遗漏。现在可以设计并实施一个更可解释的基础功率试验。

尚不能确定：去除这些遗漏后储能2一定稳定；所有附加支撑算法都错误；旧电压调节器就是全部故障根因；储能1构网能力不足；必须增加第二台构网设备。

**本轮设计的价值，是让下一次成功或失败能够明确对应到实际改变的部分，而不是继续用一次混合变化的试验判断储能2是否天生无法稳定。**
