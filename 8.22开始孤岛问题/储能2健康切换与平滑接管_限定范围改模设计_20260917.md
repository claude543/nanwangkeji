# 储能2健康切换与平滑接管：本次限定范围改模设计

日期：2026年9月17日。

**本次范围由用户确定：先只修改储能2；第一轮验证健康条件真正参与恢复，以及同一小功率任务的平滑接管。其他设备不在本次实施范围内。**

本文是基于已上传原生审计源码形成的改模设计，不是已修改模型、已完成构建或已通过电气试验的声明。当前源模型保持不变。

## 1．先回答四个问题

### 1.1 原来的孤岛协调器，现在是不是为黑启动补功能？

是，但不应理解为两个完全不同的控制器。当前黑启动完成储能1建网、储能2接入后，系统仍然在孤岛中运行。

现有协调器已经能够保存运行基准、根据频率偏差产生修正，并按能力分配。现在主要补两个衔接：

1. 储能2从恢复流程交给正常协调器时，怎样接住已经确认的任务，而不是不断把实测值改成新任务。
2. 接管完成后，怎样平滑接受储能2自己的新功率目标，而不再只围绕原捕获点修正。

这些能力也可以服务于长期孤岛运行，不是黑启动才有意义的功能。首轮只执行第一个衔接；本次设计为第二个衔接准备储能2专用入口，默认不生效。[A1]

### 1.2 正常目标是不是像原自动有功调节一样，设一个−100千瓦？

**设置目标、检查跟踪的思路相似，但必须先说明目标对应哪个测量点。**

| 任务 | 控制对象 | 当前是否采用 |
|---|---|---|
| 公共连接点／联络线有功跟踪 | 整个微电网与上级电网之间的交换功率 | 当前公共连接点断开，不能把原非零联络线交换目标搬过来 |
| 储能2本机有功跟踪 | 储能2自身充放电功率 | 本轮采用，目标仍为−0.005标幺，即约吸收500瓦 |
| 未来正常岛内功率分配 | 按岛内供需和设备能力形成各设备任务 | 当前不新写完整调度算法，只为储能2准备有效任务入口 |

按本次源模型的100千瓦功率基准，储能2本机−100千瓦对应−1标幺，是当前−0.005标幺任务幅值的200倍。**它不是下一轮建议，也不能因模型额定基准为100千瓦就直接运行。**[A2]

首轮接管前、接管中、接管后都维持−0.005标幺。后续新的本机目标，在能力和稳定范围校核后，由运行前配置的测试目标模拟正常管理输入。运行脚本不逐拍替代控制器。

### 1.3 先只改储能2，是否合理？

合理。本版不把其他四台设备的恢复管理一并重写，不增加五套恢复程序，不重新设计全微电网能量管理。

仍然保留另外四台设备不可调度的当前边界。只改协调器中储能2这一项的捕获、保持、任务更新和允许调节逻辑；不顺带重置其他设备状态。

以后可以复用已验证的方法、脚本工具和接口定义，但光伏和电动汽车的能力、方向限制及接入条件仍需分别核对。储能2成功不等于其他设备自动通过。

### 1.4 本次主要改代码，还是加新模块？

**主要修改三个既有函数核心，完善一个已有命令混合子系统，再补少量必要的参数、保持／延时、比较、限幅及记录连线。**

不计划新增完整的黑启动状态机、第二个孤岛协调器或新的储能2底层控制器。简单运算不另写自定义函数。为整理布局而增加普通子系统容器可以，但它只收纳现有标准块，不代表新增一层控制。

## 2．本次修改的确定边界

### 2.1 首轮必须实际验证

储能1建网及储能2同期接入保持原结构；合闸后和零任务阶段按健康条件推进；恢复放行后保留原零任务观察；按原斜坡到−0.005标幺；正确确认任务和健康；协调器准备相同命令；平滑交接；接管后继续保持同一个任务。

首轮不改变无功控制方式，不恢复四路附加支撑，不投入一次和二次修正，不扩大充放电范围，也不恢复下一台设备。

### 2.2 同一版中准备、但首轮不放行

储能2接管后的受限测试目标入口、正常任务平滑更新，以及既有一次协调的独立验收选择。它们应只作用于储能2，并通过同一最终能力和变化率限制。

这意味着后续在已经实现的范围内，可以换运行前配置做不同试验，而不必反复改模型。

### 2.3 本版不声称完成

其他四台设备恢复、完整能量优化调度、全部功率范围的稳定性、无功功率外环恢复、独立电压二次恢复，以及新的步骤70。后续确实需要新控制功能时仍需改模；不能承诺以后任何试验只改运行脚本就够。

## 4．首轮恢复和接管具体怎样运行

### 4.1 原有接入过程保持

储能1建网、储能2准备、同期和真实合闸结构不重新设计。保留当前真实电流反馈、限幅和已验证的底层参数。[A2]

合闸后观察和零任务资格恢复为健康条件连续满足才计时。条件不满足时，不因时间到了就强行推进；严重异常按已有可执行保护路径处理。这里是“有条件地继续”，不是为观察稳定而先要求任何波动都为零。

### 4.2 保留放行后零任务观察，再执行原小功率

成功诊断中，电流执行放行后还有约5秒零任务观察，再由模型内部斜坡执行−0.005标幺。本轮优先保留这一已验证进入方式，避免把删掉观察、改初态和健康切换同时混在一起。[A1]

这5秒与合闸后的零参考资格驻留不是同一段时间。程序分别记录，不复用一个计时器含混表示。

### 4.3 本地确认任务完成

检查三类条件：

1. 本地收到的任务已经到达本次资格目标，不是仍在斜坡中，也不是上游尚未实际施加的目标。
2. 实测功率与已收到任务的偏差及波动处于批准范围。
3. 数据、母线、储能2执行和储能1运行健康，并持续满足要求。

当前源代码把本地诊断向量第24项读为 `prefApplied`（本地实际收到的外部有功任务），第26项读为 `prefEff`（内部有效有功参考）。任务完成不能只拿后者与实测值比较。[A1]

本地状态7在新流程中的含义是“首个任务已合格，继续监督运行”，不是一进入7就永远合格。

### 4.4 协调器准备同一任务

接管前，策略14仍保持本地已确认的−0.005标幺任务。协调器储能2基准接住这项任务，而不是继续逐拍跟着实测功率波动。

首轮只有一个固定任务，可以优先利用已有目标、状态和回传；若本地确认的命令回显尚未到主任务，只追加必要的明确标量。不先为五台设备建立新的通用命令事务系统。

基准初始化不重置储能2有功比例积分状态，不把其他四台设备重新初始化。匹配检查应基于实际两路最终候选命令，而不是只看基准变量相同。

### 4.5 匹配后平滑混合

现有混合形式继续使用：

$$P_{\mathrm{最终}}=(1-\beta)P_{\mathrm{策略14}}+\beta P_{\mathrm{协调器}}.$$

其中，$\beta$表示命令来源混合比例。两路命令都保持同一个已确认值时，混合比例变化不会改变功率目标。这是代数性质，不是对实际电气稳定的保证。[W1]

本轮用10001个混合比例对“两路均为−0.005标幺”的代数式做数值校核，最大舍入偏差约为$8.7\times10^{-19}$标幺。**只校核了命令混合的数学关系，没有运行模型或电气仿真。**

当前已有混合上升速率对应约2秒完整交接，可作为首轮沿用候选；最终仍检查实际记录，不以计时结束代替成功。[A1]

### 4.6 接管后保持

混合比例达到1以后，协调器继续给相同任务。本轮一次修正、二次修正和新任务更新仍关闭，其他设备仍不可分配。

可让策略14仍停留在现有步骤50的“混合完成后观察”分支。这个分支使用单独事件和计时含义，不需要增加一套顶层状态机。

本轮验收的是“模型按健康条件推进，且命令来源已经实际交接后继续稳定”，不是“已经通过完整正常调度”。

## 5．哪些标准模块可复用，哪些可能需要增加

### 5.1 已经存在，优先原样复用

原生审计已经列出下列混合子系统内的块：[A1]

- `PickupTargetSaturation`（小功率目标限幅）；
- `PickupRateLimiter`（小功率任务变化率限制）；
- `BetaRateLimiter`（混合比例变化率限制）；
- `CoordWeighted`（协调器命令加权）；
- `S14Weighted`（策略14命令加权）；
- `MixedP`（混合命令求和）。

因此不另建新的功率斜坡和接管控制器。

### 5.2 必要新增或调整的标准块

按最终接线需要，增加少量：命令差值比较、与／或逻辑、选择器、单位延时或保持、参数常数、状态／事件记录出口。

正常目标平滑更新优先在已有协调器基准状态上实现；接管阶段使用事件捕获，后续任务阶段使用有界更新，不平行维护两个互相不一致的功率基准。

源代码修改可能改变函数输入或内部状态数量，必须同步更新其父子系统端口和发送／接收打包。**“主要改代码”不等于只复制三段函数正文就完成。**

### 5.3 明确不加

新的储能2电流控制器、新的构网控制器、第二个正常协调器、五设备通用恢复状态机、为每个健康条件单独增加的自定义函数，以及本轮不执行的二次调频状态。

## 6．后续只改运行脚本，能够做什么、不能做什么

### 6.1 同一版模型内可由运行前配置选择

本地健康合格后保持；完成接管后保持；接管后接受一个批准范围内的新本机目标；在批准范围内单独投入既有一次协调。

首轮选“完成接管后保持”。后续配置全部在首次执行前写入并回读，实际转移由模型依照健康和事件自动触发，不由主机固定绝对秒数临时抢写命令。

新的本机目标和一次修正虽然可用同一版实现，但首次试验仍分开，避免无法判断变化来源。

### 6.2 不能靠运行脚本替代的工作

恢复尚未设计完整的无功控制、开启独立电压二次、扩展新设备真实接入、修改控制结构，以及超出已验证范围的参数与能力设计，仍可能需要后续改模。

“可以配置后续试验”不等于“任何权限一开就已具备正式安全运行能力”。没有批准范围或能力证据的后续入口默认不放行。

## 7．后续储能2正常目标入口：只实现本机，不扩展五台

正常管理未来给出的是储能2的基础任务；协调器可以在其上叠加允许的一次频率修正。本版二次修正维持零。

建议逻辑为：

**接管完成并允许接新任务 → 校验本机目标与能力 → 基准平滑更新 → 加一次修正 → 总功率／变化率限制 → 本地实际执行。**

正常目标初值等于捕获基准。首轮禁止更新，即使测试目标参数提前写成其他值，也不能提前取得执行权。

本地状态7接入新任务后，对新任务作过渡和持续健康判断，不因任务不再等于原−0.005标幺就立刻跌回零任务状态。运行目标尚在斜坡时，不要求瞬时完成最终任务。

“调节范围”仍是边界，不是目标本身。边界不能每拍围绕新基准平移后无限累积扩大；后续模式须同时有明确的绝对设备范围和储能1可承受边界。

首轮不扩大范围，不重写动态能力算法。后续任务／一次模式在能力未校核前保持禁用。

## 8．本次操作参数保持少量

### 8.1 主要操作面

建议只新增或集中为两个主要入口：本轮验收终点；接管后的下一测试任务。第一轮终点为接管后保持，下一任务初值与当前任务相同且不允许投入。

复用已有小功率目标、储能2有功增益和必要的调节限额。不要新增多个表达相同作用的主从手工开关。

### 8.2 内部配置不等于都要在线暴露

健康误差、连续时间、匹配容差、返回边界和斜坡等在配置中必须明确，但不一定全部成为用户手动调的在线参数。只有确实需反复验收调整的量才暴露。

本地健康、接入事实、测量新鲜度和能力不是可由用户写成“正常”的常数。

### 8.3 健康与支撑隔离必须在逻辑上分开

当前总诊断位同时影响健康推进、支撑隔离和部分本地阶段。新模式需要分清这些用途，但可以由一个验收选择在内部产生允许条件，不要求用户操作许多额外开关。

首次运行前，主从任务中相关配置、目标和版本必须一致；不一致就阻止试验开始。

## 9．60秒试验与记录安排

用户确定单轮不超过60秒，本次遵守。健康不合格时，不为赶时间缩短资格、强行接管或忽略故障。

本地健康和接管较早完成时，余下时间全部用于同功率点保持。如果接管太晚、没有足够的后段观察，只能报告接管动作已观察或证据不足，不能宣布慢动态验收完成。

### 9.1 优先保留现有三组

| 组号 | 现有用途 | 首轮必须能读到的证据 |
|---|---|---|
| 27 | 储能2本地控制与恢复 | 本地真实任务、内部有效参考、实测功率、资格和失败原因、状态6／7、真实电流和限幅、无功及支撑实际量 |
| 29 | 上层策略与协调 | 上层步骤、确认和捕获事件、两路候选命令、命令差值、混合比例、最终命令、协调器基准、一次二次实际关闭、资源可用性 |
| 30 | 储能1构网响应 | 实际有功无功、母线电压频率、真实电流、真实调制／裁剪指标与有效性 |

已有字段不重复追加。确认为重复或过时的旧诊断通道可以替换，但必须在改模时给出新的唯一数据字典，并同步改分析脚本。**不能只保持矩阵宽度不变，就继续使用旧行号解释。**

### 9.2 容量不是本次主要瓶颈

当前119、74、144个信号，另有时间行；名义记录间隔分别0.4、0.4、1毫秒。按厂商经验预算公式，60秒分别约216、135、104.4兆字节，低于各500兆字节的现有限额。[A2、W2]

改完字段以后重新算一次，不盲目扩容。仍检查实际文件时间行、包间缺口、结束时刻和实时超步长。厂商说明记录器自动加时间行、动态编号可关闭当前文件，但完整写入和回传仍需按已验证流程检查。[W2]

关键事件记录保持的时间或事件编号，不只记录可能被抽取漏掉的100微秒单拍脉冲。60秒运行预算需包含必要的数据收尾；不把实际运行继续到60秒以后却仍称为60秒试验。

## 10．储能1本次做到什么程度

首轮任务前后不改变，但不能只看储能2而忽视供电源。已有储能1记录必须参与试验评价，相关有效健康信息参与继续推进许可。

优先复用已有测量，增加必要比较与许可，不修改储能1电压环、电流环，也不先设计完整动态能量优化。

若某个量只是“允许比例”，就不能当作“还剩多少物理调制余量”。原生审计已经说明部分名为余量的量其实是0到1的放行比例。[A1]

首轮只有同功率点接管，复杂的动态余量分配可以暂不实施。后续增加新任务和一次调节前，必须校核双向能力并施加相应限制；能力信息不足的后续运行模式保持不放行。

## 11．异常与兼容性必须一起设计

| 情况 | 必须有的处理 |
|---|---|
| 数据无效、配置不一致 | 不累计健康时间，不捕获任务，不继续交权；记录具体原因 |
| 普通误差暂时越界但未到保护条件 | 清除或暂停对应合格计时，保持当前仍可安全执行的任务；不伪造健康 |
| 本地资格丢失但混合尚未开始 | 不接管；按既定恢复状态重新判断 |
| 本地已经合格，用户选择等待 | 不继续累计“任务尚未完成”的超时，不因正常验收等待进入故障 |
| 接管中发生软异常 | 停止继续混合；只向已匹配、当前可行的命令来源返回，不直接跳变 |
| 严重电气故障或反馈无效 | 由明确可执行的保护／停止路径处理；不能将真实电流反馈替换为零来掩盖问题 |
| 后续任务已改变后要求返回 | 先匹配当前已施加命令；不能突然回到旧500瓦任务，也不能无条件清零 |
| 全流程重新复位 | 捕获有效性、事件、计时和混合比例按定义复位，禁止残留上次合格状态 |
| 退出黑启动请求 | 不能拿关闭黑启动总位当正常恢复完成动作，避免解除另外四台设备隔离 |
| 其他策略运行 | 本次新增逻辑仅限授权储能2恢复路径，不改A窗口已验收母版和外部15策略合同 |

任何时候都不承诺“平滑与所有突然收紧的硬限制永远同时满足”。发生冲突时，安全限制优先并记录原因。

## 12．代码前需要固定的数值与接口

已经有依据：−0.005标幺首任务；储能2有功0.06／0.5候选；100微秒基本步长；现有任务约2秒斜坡；当前混合约2秒候选；单轮60秒上限。

还需对原成功数据或明确设计容差校核：任务完成误差与波动条件、连续合格时间是否足够且可达到、两路命令匹配容差、接管后观察覆盖，以及后续目标范围和速度。

保存的0.002标幺功率误差门槛为200瓦，是500瓦任务的40%，不能原封不动当精确完成判据。旧成功记录末段±5%误差带的表现可支持25瓦级候选的校核，但不能只用一个末段平均误差就宣布全部启动期间满足。

不要求用户再次确认版本。执行前的脚本仍自动检查对应修改位置、原函数指纹、端口和默认配置；这属于防误改，不是重新索取用户已经给出的事实。

## 13．改模与验收的交付要求

本轮先形成此设计；没有执行修改。实际联合改模脚本应完成：

1. 在副本上核对修改前条件并修改，保留正式源文件备份。
2. 对同任务交接、不匹配拒绝、旧诊断不误进入接管、正常等待不误超时、返回匹配等运行逻辑做离线检查。
3. 验证修改仅落在批准位置；旧诊断模式、非黑启动分支和其他设备保持既定行为。
4. 同步更新函数端口、状态尺寸、主从打包、参数和记录映射；不按普通信号处理电力系统物理端口。
5. 独立只读验证，不用有风险的普通整模型更新替代实时平台构建。
6. 重新构建后重新发现参数和信号；首次执行前写入、回读并记录本轮配置。
7. 使用60秒首轮脚本验证健康推进与平滑接管，最后分析原始记录而非只看流程状态。

只要同一版已经实现的接口与范围不变，后续可以通过运行前配置验证新任务和一次协调。控制结构、设备角色或二次功能发生变化时，再进行对应的定点改模。

**防止返工的做法是先固定这些边界并逐项验证，不是提前承诺任何错误都不可能发生。**
