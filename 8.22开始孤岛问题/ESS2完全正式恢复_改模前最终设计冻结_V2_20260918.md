# ESS2 完全正式恢复：改模前最终设计冻结 V2

日期：2026-09-18

---

# 1. 这次最终目标

下一次改模不再只解决一个局部小功能，而是一次把 ESS2 黑启动后“完全正式恢复”需要的基础设施准备完整：

```text
ESS1建网
→ ESS2物理恢复
→ 小功率资格
→ 无扰交权
→ 一次有功协调
→ 二次频率慢恢复
→ 电压/q-bias慢恢复
→ ESS1负担/余量约束下的正常有功责任释放
→ ESS2 NORMAL RESTORED
```

运行时仍然一层一层自动投入，不允许一次全部打开。

---

# 2. V4.8 q-bias当初为什么出现

它不是为了“多加一个Q控制器”。

当时旧孤岛电压二次路径是：

```text
PCC电压误差
→ 旧Voltage Secondary
→ dVSecondary
→ 五台VsupportRef
→ slow-q
```

正式数据已经出现：

```text
dVSecondary已经打到限制
但母线电压仍明显偏高
```

所以问题不是“旧二次完全没动作”，而是：

> 旧的“改VsupportRef再经过slow-q”的执行方式和权限不足以建立需要的稳态无功工作点。

因此V4.8改成：

```text
PCC慢速电压误差
→ 中央q-bias
→ 直接建立可保持的q轴电流偏置
→ 各GFL本地Finalizer执行
```

它的本质是：

> 给孤岛建立一个能够长期保持的稳态无功/电压工作点。

所以它很适合黑启动后正常孤岛阶段复用。

---

# 3. V4.8能不能原样用于黑启动

核心算法与执行链可以复用，但入口必须适配。

## 保留

```text
central q-bias controller
Router
transport
Decoder
Finalizer
current/modulation capability
```

## 黑启动必须改

### 3.1 电压目标

计划孤岛可以捕获“切岛前PCC电压”。

黑启动没有有效的切岛前正常母线，因此应改为：

```text
Vtarget_BS
=
ESS1正常建网电压目标
≈ 1.0 pu
```

或者直接使用ESS1 GFM当前正式电压参考。

不能依赖旧逻辑“捕获失败后fallback到1.0”作为正式黑启动设计。

### 3.2 初始q-bias

```text
ESS2恢复/接管阶段
q-bias = 0
```

正常P控制稳定以后，再：

```text
q-bias 0 → 正常需要值
```

### 3.3 资源资格

第一台只恢复ESS2时：

```text
ESS2 available for q-bias = 1
PV1/PV2/EV1/EV2 = 0
```

以后每台资源恢复成功后才进入Q能力池。

### 3.4 独立使能

必须分开：

```text
Frequency Secondary Enable
Voltage q-bias Enable
```

不能再只靠一个Coordinator Stage同时打开。

# 4. 正常孤岛到底需要几个“调控”

不要把“控制目标”误认为“又要增加几个控制器”。

最终只保留四个职责实体：

## A. ESS1本地GFM控制器

已有，不新增。

负责：

```text
瞬时建压
瞬时建频
最快速承担P/Q不平衡
```

## B. Normal Island Coordinator

已有，不新增第二套。

内部承担三个有功层次：

```text
Primary P-f
Frequency Secondary
ESS1负担/余量恢复
```

这三个是同一个正常Coordinator的三个时间尺度职责，不是三个新控制器。

## C. V4.8 q-bias电压慢恢复

已有。

负责：

```text
慢速V-Q恢复
```

## D. S14黑启动监督器

已有。

只负责：

```text
恢复顺序
资格
使能
交权
何时进入70/75/80/88
```

S14不做长期正常调度。

因此：

> 不需要继续叠加新的MATLAB Function控制器。

---

# 5. ESS1负担恢复有没有涉及电压

有，但不是把“电压误差”直接塞进P控制公式。

正确分工：

## 有功需求方向

主要由：

```text
ESS1当前P负担
+
频率状态
```

决定ESS2是否需要多分担/少分担P。

## 安全许可

同时检查：

```text
母线V
ESS1 Q
ESS1 current
ESS1 modulation
ESS2 current
ESS2 modulation
```

原因：

```text
P和Q共享逆变器电流/kVA/调制能力
```

例如ESS1 P负担很高，本来希望ESS2多承担P，但如果：

```text
母线电压异常
ESS1 Q已经很大
ESS2需要保留较多Iq做电压支撑
```

就不能继续无脑扩大ESS2 P责任。

所以完整逻辑是：

```text
“需要多少P分担”
×
“P/Q联合能力还允许多少”
```

电压不是缺席，而是作为能力约束参与。

# 6. ESS1、ESS2的正确主从关系

冻结：

```text
外部扰动 / 负荷变化
↓
ESS1 GFM第一时间承担
↓
V/f保持
↓
Normal Coordinator观察ESS1负担
↓
ESS1仍在舒适区
    → ESS2不因微小波动追踪ESS1
ESS1长期偏离舒适区
    → ESS2缓慢分担
↓
ESS1回到保有备用的工作区
```

ESS2不是主动把ESS1拖着走。

---

# 7. ESS1负担恢复应该怎样设计

定义：

```text
ESS1正常负担区
[P1_low, P1_high]
```

具体数值不能现在拍脑袋，需根据额定参数和现有真实数据冻结。

逻辑：

```text
P1_low <= P_ESS1 <= P1_high
→ 不产生新的慢速P基准修正

P_ESS1 > P1_high
→ ESS2逐渐增加供电/减少充电

P_ESS1 < P1_low
→ ESS2逐渐减少供电/增加充电
```

必须带：

```text
低通
死区
迟滞
变化率限制
```

避免ESS2追逐ESS1的小纹波。

这属于Coordinator内部正常负担分配，不新增第二套协调器。

# 8. 小功率、小权限怎样真正过渡到正式运行

当前：

```text
恢复资格目标 ≈ -0.005 pu
调试允许调节范围 ≈ ±0.001 pu
```

这只是进入正常系统前的安全过渡。

最终不再使用固定小范围。

正式恢复后：

```text
ESS2正常可调范围
=
ESS2自身能力
∩
ESS1当前可释放能力
∩
P/Q电流与调制能力
∩
V/f健康约束
```

注意：

> “正常放开”不是无限放开。

而是从固定调试限制切换到实时能力允许的正常范围。

---

# 9. 不新增Function，怎样实现正常权限释放

建议使用：

```text
现有Coordinator Core
+
普通Simulink标准块
```

例如：

```text
Min/Max
Saturation
Rate Limiter
Switch
Unit Delay / Memory
```

构成一个普通子系统：

```text
ESS1_CAPABILITY_AND_RELEASE
```

它不是新的控制器，只是：

> 把现有测量转换为Coordinator允许使用的正常P/Q能力边界。

输入：

```text
ESS1 P/Q
ESS1 current
ESS1 ModHeadroom
Vpu/f
ESS2 current/ModHeadroom
```

输出：

```text
ESS2_P_UP_ALLOWED
ESS2_P_DOWN_ALLOWED
NORMAL_RELEASE_HEALTHY
```

然后喂给现有Coordinator。

如果当前Coordinator为了最小改动只能先接一个对称范围，可先取：

```text
Allowed = min(UpAllowed, DownAllowed)
```

但记录中必须保留两个方向原始值，为后续非对称升级准备。

# 10. q-bias与正常P释放的顺序需要调整

既然最终确定ESS2也要承担电压辅助，就不能先把P能力大幅放开，再最后才考虑Q。

因为：

```text
P越大
→ 剩余可用于Iq/Q的电流容量越少
```

因此最终顺序应改为：

```text
60  Primary @ commissioning范围
↓
70  Frequency Secondary @ commissioning范围
↓
75  Voltage q-bias @ commissioning范围
↓
80  P/Q联合能力约束下 Normal Responsibility Release
↓
88  ESS2 Normal Restored
```

这样在扩大ESS2正常P责任以前，Q/V辅助已经在线且能力约束已准备好。


# 13. 普通波动和严重异常

延续当前成熟原则。

## 普通波动

```text
短时V/f误差
短时功率误差
普通小振荡
```

处理：

```text
暂停继续扩大责任
冻结当前允许范围
继续记录
```

不退回恢复流程，不立即停止试验。

## 严重异常

例如：

```text
持续CurrentLimit
严重调制饱和
非有限值
明显V/f失效
ESS1/ESS2严重能力越界
```

才：

```text
收缩正常责任
必要时退回安全阶段/保护
```

# 14. 下一次改模前必须先做的准备

不能直接开始写Patch。

先对当前Build对应SLX做一次定向审计，确认：

1. ESS1 P/Q/current/modulation真实信号路径；
2. ESS2 current/modulation真实信号路径；
3. 当前Coordinator所有P能力输入与输出；
4. q-bias输入/输出/Stage/availability；
5. S14当前40/50/60状态源码；
6. G29/G30现有记录是否已经包含足够信号；
7. 是否可以不增加OpComm维度完成ESS1余量输入；
8. Stage3若开启会连带打开哪些旧功能。

然后冻结具体接口与数值，再写Patch。

# 16. 最终系统只保留一个正常P协调器

最终不要出现：

```text
Primary Controller
+
Secondary Controller
+
ESS1 Burden Controller
+
Authority Controller
+
另一个Normal Coordinator
```

这种堆叠。

正确结构：

```text
Normal Island Coordinator
├─ Primary
├─ Frequency Secondary
└─ Slow burden/reserve allocation

V4.8 q-bias
└─ Voltage/Q slow restoration

S14
└─ sequencing / enable / handover

ESS1/ESS2 local controllers
└─ fast electrical execution
```

这就是最终架构边界。
