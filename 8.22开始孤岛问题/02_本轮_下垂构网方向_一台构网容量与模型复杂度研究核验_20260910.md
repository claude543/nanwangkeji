# 本轮研究核验：下垂构网方向、一台构网容量与孤岛模型复杂度

**结论：下垂式构网与一台构网机协调多台跟网机，是有研究和实验依据的技术方向；但现有审计没有证明我们添加的每个模块都必不可少，也没有证明当前储能1的容量与动态裕度已经足够。当前应保留下垂方式作为默认研究基线，同时重新证明功能必要性、功率能力和联合稳定性，而不是因投入很多就保留所有历史实现。**

本文件专门回答本轮关于“路线、数量、复杂度和是否被现有方案锁定”的问题。上一轮的缺陷、候选原因和改善次序已单独整理，不在这里把它们伪装成新试验结论。

## 1. 先逐项回答最关心的问题

| 问题 | 本轮判断 |
|---|---|
| 主任务和从任务新增的所有模块都一定必要吗？ | **不是。**有些功能必要，有些只对当前切换实现必要，有些是条件性增强，有些是参数、记录或包装。每个具体块是否不可替代，尚未证明。 |
| 别人的模型也有这么多块吗？ | 真实模型也有多层控制、状态、限幅和接口，但公开论文通常未给出可直接比较的同口径模块数。不能用论文中几个框与我们的展开块数比较。 |
| 当前复杂度已经在合理范围内吗？ | 控制层级有合理来源；**具体实现的最小性、无重复性与整体稳定性没有得到证明。**已有历史累积和坐标残留，不能给全体模块背书。 |
| 下垂构网本身可以实现稳定孤岛吗？ | **可以。**存在仿真、控制器硬件在环和功率硬件实验依据；这不保证当前参数、限幅及切换实现自然正确。 |
| 一台构网带五台跟网够不够？ | 原理上可以形成一个连通孤岛，但“够不够”由有功、无功、暂态电流、调制、能量、网络和稳定裕度决定，不能只数台数。 |
| 已经做了很多，所以不能换构网方式了吗？ | **仍然可以改变。**但目前没有充分证据要求更换。应比较从现在开始的收益、风险和验证成本，而不是用过去投入证明方案正确。 |
| 整体方向有没有偏差？ | 一构网、多跟网、分层协调的总体方向有依据；偏差风险主要在逐个问题追加支路后，未在最终对象上统一证明控制权、能力和稳定性。 |
| 下一步仍然只能改坐标那一处吗？ | 不是。先修两处相关坐标遗漏，同时开展容量、工作点和联合动态分析；再决定哪些增强支路保留、整定、合并或替代。 |

文献对总体路线的支持见第2节；项目当前证据等级见第3节和脚注。[^R6][^R7][^R8][^P1]

## 2. 本轮深度检索实际找到什么

### 2.1 有直接采用“一台下垂构网、其他跟网”的独立微电网研究

2022年《全球能源互联网》英文刊的一台构网协调研究，采用一台带有功—频率、无功—电压下垂的主逆变器，另两台使用有功、无功控制。上层协调根据主机承担的功率调整跟网机出力，避免主机超过能力。验证是仿真。[^R6]

**它证明一台构网协调多台跟网并不是方向错误；它不证明当前使用100千瓦功率基准的主机、五个跟网端口和本项目控制器已经具备足够能力。**

### 2.2 下垂方式有真实硬件依据，不是仅在理想仿真中成立

2024年IEEE工业电子汇刊的关键设施切换研究，使用持续构网、统一模式相关下垂控制，并报告控制器硬件在环以及两台480伏、125千伏安构网逆变器的硬件实验。[^R7]

本轮对这篇的核验范围是正式摘要与元数据，不是已经复现其全部控制器。它足以支持“下垂方式具备实际可行性”，不能支持“本项目全部模块都是必要的”。较早的微电网试验平台也有下垂与孤岛运行工程验证。[^R12]

### 2.3 同一实时仿真平台已有相似分层结构

OPAL-RT（实时仿真设备与软件供应商）的官方混合构网／跟网算例，为三台构网、一台跟网，使用平均值变流器。构网控制分为测量处理、二次控制、一次下垂、内层控制和参考生成，跟网侧也有测量与支撑、参考形成和执行。[^R8]

因此，我们出现测量、下垂、电压电流环、限幅、慢恢复和接口，并不反常。**但该官方例子不是一构网五跟网，也没有证明本项目每一条历史阻尼或交接支路必须存在。**当前用户安装版本是否含同一算例、参数是否可复用，尚未确认。

### 2.4 近期研究仍在处理混合控制和功率分担，不存在一套可直接照搬的普适小模型

2022年IEEE智能电网汇刊研究构网、跟网共同参与频压恢复和功率共享；2026年IET电力电子研究进一步关注暂态功率分担约束，并采用两构网、两跟网的控制器硬件在环验证。[^R2][^R11]

这些工作支持继续研究混合系统动态，而不是只要求跟网机机械跟随固定命令。但它们的分布式算法不是本项目必须增加的新层。

### 2.5 公开研究不能给出一个“正常应有多少块”的数字

本轮没有找到与本项目在六台设备、求解器、实时分区、切换范围、诊断和展开深度都一致的模块数量基准。因此无法据文献给出“九千块正常”或“必须删到多少块”的判断。

可靠的比较口径是：同一功能需要多少独立动态状态、谁控制哪个变量、多少次控制权切换、如何限幅和反馈、接口是否一致，以及是否有同工况验证。块数只能说明实现规模，不能直接说明必要性或稳定性。

## 3. 今天的完整审计，究竟证明了哪些“必要性”

### 3.1 功能存在、实际连通、必要、最小，是四个不同判断

以一个仍被消费的输出为例：能查到消费者，证明它参与当前模型。并不证明删除或替代它后，不能构成另一套更简单而稳定的控制器。

同理，某个历史补丁曾改善波形，证明它对当时模型有作用；最终执行对象、坐标和上层控制改变后，它的增益与结构是否仍是最佳选择，要重新评价。

目前源审计明确保留了“未证明唯一根因、未证明动态贡献排名”的边界。[^P3]

### 3.2 必须区分三种复杂度

**显示和实现复杂度。**多路复用、解复用、常数、端口、延迟、标签、实时通信、记录等会产生很多模块。一个数学运算可以用一个函数或很多基础块实现。

**控制动态复杂度。**真正需要审视的是独立积分器、滤波器、状态机、保持和复位、并联支撑路径及多级限制。它们决定闭环动态，不随界面变整齐而消失。

**运行与验证复杂度。**并网、计划切岛、持续孤岛、低压支撑、黑启动、重同步、板端接管具有不同初始条件和控制权，验证难度不能由策略编号数量衡量。

把长线改成 `Goto/From`（标签发送／读取）减少的是可见连线，并没有减少信号依赖或动态状态。把块装进子系统也不自动完成控制架构简化。

### 3.3 当前的真实判断

本项目存在正常的工程实现复杂度，也存在逐轮修补形成的历史复杂度。**前者不能用来合理化后者。**当前还不能宣布最小实现，但也不能因画面复杂就认定所有后加支路无用。

## 4. 哪些功能必须有，哪些具体模块未必必须保留

下表中的“必要”均带有条件，不是批准现在直接删除任何功能块。路径按已知整理容器定位，正式修改仍须核对当前文件。

| 功能与模型位置 | 必要性判断 | 当前应怎样处理 |
|---|---|---|
| `SS_Slave2/ESS1_Control/Droop Control`（储能1／下垂控制） | 当前架构必须有形成电压相角和幅值的控制功能；下垂是已选择方式 | 默认保留，但参数与参考相容性要证明 |
| 同层 `Voltage Regulators`（电压调节器）、电流执行及 `Vref Generation`（电压参考生成） | 需要把电压目标变成实际变流器输出；双环是当前实现，不是所有构网方法唯一实现 | 保留真实执行与保护，核对对象、相移、基准和限幅 |
| 主任务内阶段、J1断路器许可及准备顺序 | 涉及切换就需要确定的状态和动作条件 | 保留功能；不等于必须多套阶段机并行 |
| `AA15_PLAN_P_COMMIT_HOLD`、`AA15_PLAN_Q_COMMIT_HOLD`（有功、无功提交保持） | 对当前以捕获工作点准备切岛的流程有明确作用 | 当前保留；更统一架构中可以改变实现形式 |
| 储能1交接容器中的F21、F22（电流、电压比例积分状态交接） | 对当前跟网转构网时的状态管理必要 | 不把F编号当普适构网必需模块；未来可统一状态管理 |
| F24参考交接 | 当前切换过程需要参考预对齐和边沿一致 | 功能保留；不等于独立大模块是唯一做法 |
| F8内F23、F25（工作点估计、输出电流责任交接） | 解决当前前馈与交接实现的真实问题 | 暂不拆；不宣称所有下垂孤岛都需要同款快速责任转移 |
| 六台版本4.9电流执行适配器 | 真实限幅与控制状态一致性是必要设计原则；另建适配器是当前改造选择 | 将来可与正式内环集成；没有验证前不删除旧状态匹配依赖 |
| 五台 `AA15_PLL_EXEC_FRAME_HOLD`（锁相环执行坐标保持） | 电流指令必须有可信相角；“保持并由主机频率推进”是本项目选择 | 不能说所有跟网机都必须用这一形式，也不能忽略历史快速失稳对照 |
| 五台版本4.7无功基础保持、误差归零、权限混合 | 是针对本项目旧无功环交互形成的设计 | 不是“跟网机在任何孤岛都禁止无功比例积分”的通用定律 |
| 五台中频阻尼、低频无功阻尼和慢无功支撑 | 条件性稳定增强，不是启动孤岛的统一必备三件套 | 按最终对象评价各自增量价值；不能无证据全部叠加或全部删除 |
| 主任务中央有功二次恢复、版本4.8无功偏置 | 为频压恢复、稳态分担服务，未必是维持带电的最低条件 | 是否需要及由谁实现，取决于允许静差、分担与裕度目标 |
| `AA15_*`（后加策略前缀）的包装、常数、标签与记录 | 许多是组织和证据，不是独立控制器 | 可做等价精简；不能仅凭前缀决定删除 |

项目历史证明F21、F22等解决过具体状态问题，也否定过永久原始输出电流反馈方案；这提供保留现行交接功能的理由，不能推出所有独立包装永远不能改变。[^P3]

## 5. 为什么“只是实现一项策略”仍会牵涉很多环节

正常并网时，上级电网提供强电压与频率参考；断路器打开后，本地变流器需要承担这项责任，功率不平衡、控制初值、测量可信度和保护行为也改变。这种策略触及物理边界条件，不等同于调整一次功率设定值。切换研究因此会同时讨论运行点、相角、功率与参考一致性。[^R13]

但是，任务本身复杂不等于任何追加模块都合理。当前至少应分别说明：

1. **维持带电孤岛**所需的一次控制与能力条件；
2. **平滑切岛**所需的参考、积分状态和开断管理；
3. **恢复到目标频压及分担**所需的慢协调；
4. **保护和重并网**所需的额外条件。

不能把“重同步未来可能用到”作为现在某条持续振荡支路必须在线的理由。各阶段有独立准入条件。

## 6. 下垂构网到底能不能最终实现

### 6.1 技术路线层面：可以

文献与官方算例已经显示，下垂控制不是仅适用于刚性大电网，也能够用于孤岛电压源控制。一次下垂允许负载变化时出现频压偏移，再由合适的慢协调处理需要消除的偏差。[^R6][^R7][^R9]

### 6.2 当前实现层面：必须有条件地判断

一种常见有功—频率与无功—电压下垂写法是：

$$
f^*=f_0-m_p(P-P^*),\qquad
V^*=V_0-n_q(Q-Q^*).
$$

这里 $f_0,V_0$ 为参考中心，$P^*,Q^*$ 为功率工作点，$m_p,n_q$ 为下垂系数。该表达式只用于解释常见关系，**不是对本项目实际函数符号、交叉轴映射和单位的替换**。[^R6]

要判断当前下垂能否稳定，还要检查：电压电流环动态、滤波与数字延迟、线路阻抗与变压器相移、端口测点、实际限幅、跟网机响应和运行点。

储能1目前的电压环增益0.02、0.14曾用于抑制较高频问题；这既不是永远正确的证明，也不是因与其他机组不同就应该放大100倍的理由。[^P3]

### 6.3 不能对一个构网机同时独立强制四个不相容目标

孤岛构网机通过输出电压和频率承担网络功率平衡。其实际有功、无功由网络、负荷和其他设备输出共同决定，不是任意四个目标都能独立满足。

因此不能未经协调同时要求：储能1严格保持某个固定有功、某个固定无功，且母线频率、电压均绝对固定。可以通过参考和功率分担寻找相容工作点，但不能让多个控制器在同一执行自由度上各自追不同目标。此处是控制设计判断，不是新证实的接线错误。

## 7. 一台构网真的够吗：应当计算什么

**一台能够提供电压相位基准，与一台能够覆盖整个工况的能量和动态需求，是两个问题。**2022年单构网研究使用上层协调控制主机负担，本身就说明“有主机”之后仍须解决能力分配。[^R6]

### 7.1 稳态有功与无功平衡

先将各台功率统一到“向微电网交流母线注入为正”的物理口径。若五台跟网机中电动汽车充电，其有功为负。设其功率为 $P_j,Q_j$，被动岛内负荷为 $P_L,Q_L$，连接网络吸收量为 $P_N,Q_N$，则稳态有：

$$
P_1=P_L+P_N-\sum_{j\in\mathcal G_5}P_j,
\qquad
Q_1=Q_L+Q_N-\sum_{j\in\mathcal G_5}Q_j.
$$

其中 $\mathcal G_5$ 表示五台跟网设备集合；电动汽车已经包含在集合内时，不得又把其充电功率重复加到 $P_L$。网络无功可以带符号，不能一律当电阻损耗。

这些是功率守恒核算式，不是给当前储能1填入一组未经核实的数字。实际应使用六台同一时间、同一测点折算口径的数据。

### 7.2 电流和视在功率能力

在平衡正弦、同一交流端口的近似下：

$$
S_1=\sqrt{P_1^2+Q_1^2},\qquad
I_1\approx\frac{S_1}{\sqrt{3}\,V_{LL,1}}.
$$

$V_{LL,1}$ 是该端口线电压有效值。低电压下，相同视在功率需要更大电流。还必须区别滤波器前后的电流：电容、滤波支路和暂态分量会使桥臂电流约束比端口基波估计更严。

所以即使有功只占额定的一小部分，也不能直接判定构网机裕度足够。还要看无功、电压需求、调制限制、峰值和短时能力。限流会改变构网机的等效动态，不能当成不影响稳定性的最后一道裁剪。[^R5]

### 7.3 暂态不平衡和功率恢复速度

需要核对断路器打开、跟网机暂时退让、充电恢复或负荷变化时，储能1实际承担的瞬态增量。中央协调有通信和更新周期，不应假设五台在同一拍完全补足缺口。

用实际时序回答：最大功率增量多大、持续多久、电流何时限幅、调制何时受限、其他设备何时响应。不能只看切岛前公共连接点有功接近零；无功、内部电流、参考和储能元件初态同样有关。[^R13]

### 7.4 直流侧与储能能量

当前六个直流源是理想1000伏源。它适合分析指定边界下的交流控制动态，但不能证明真实电池功率能力、直流母线恢复或持续能量充足。[^P1]

功率基准值不自动等于额定视在功率、短时过载电流或真实电池功率。实际持续时长还取决于储能荷电状态、可用能量、变换效率和直流功率限制。应将能量问题与当前30秒交流振荡问题区分：理想直流源下出现振荡，并不能解释为真实电池电量耗尽；反过来也不能因理想源不掉压，就认定硬件储能足够。

### 7.5 网络与动态稳定能力

一台构网机通过滤波器、变压器和线路支撑五个受控端口。其输出阻抗与五台聚合动态相互作用。某机容量够，并不自动保证它在所有相关频率和工作点对网络提供足够阻尼。

至少保留各端口进行分析，不能只按总容量比判断。离散端口建模方法能帮助分辨哪台、哪个状态参与最多；该方法在本项目上仍需建立和验证。[^R1]

### 7.6 可靠性要求是独立问题

一台构网机可满足某个正常工况的控制需求，不代表主机退出后仍能维持孤岛。若项目要求单一设备故障后继续供电，就需要备用构网能力、其他电压源或明确负荷切除方案。是否有此要求应以项目任务书为准，不能自动给本项目增加可靠性指标。

### 7.7 不存在从台数直接推导的充足性比例

六台额定容量相同，一台构网在设备额定总容量中约占六分之一；但这不是“必须够”或“必然不够”的判据。构网占比硬件研究也显示，不同配置的负荷扰动、同步切换和电压恢复表现并不由一个百分比统一解释。[^R10]

**当前结论：一台构网尚未被否定，但“一台已经足够”仍需要上述计算与动态验证。**

## 8. 是否必须增加第二台构网机

现在不建议直接把储能2改成构网机作为默认修复。两台构网可以分担有功、无功和动态支撑，但同时引入下垂匹配、相位同步、线路压降、环流、限流后的重新分配等新关系。多台构网的硬件可行性有研究依据，不代表比当前架构无条件更简单。[^R7][^R10]

下列证据出现时，增加构网能力才更值得进入正式比较：

- 正确坐标、合理控制下，储能1仍持续承担超过可用电流或调制能力的任务；
- 调度、负荷限制和现有五台支撑都不能满足规定扰动；
- 网络位置使唯一主机无法覆盖所需电压动态，且分析证明第二处构网明显改善；
- 项目明确要求主机退出后的继续供电。

若主要原因是已有方向错误、控制目标不相容或积分状态追逐不可执行命令，第二台构网也可能只是暂时掩盖问题。应先辨别限制来源。

## 9. 走到现在，还能不能改构网方式

### 9.1 可以改变，但不应把“能改变”理解为“现在必须改变”

过去投入不是方案正确的证据，也不是禁止替代的理由。真正需要比较的是：当前哪种方案更可能满足目标、需要改变多少已验证接口、验证工作量和新增风险多大。

目前下垂路线本身有充分依据，项目已有真实成岛和有效历史修复，因此默认继续保留是合理的。其理由是现有证据与前向成本，不是无法回头。

### 9.2 不换下垂方式，也可以大幅调整实现

可以在下垂框架内研究：统一控制权、合并重复方向限制、减少无效并行状态、把独立适配器与正式内环集成、让一次和二次参考相容，以及根据动态能力分配目标。这些不必更换为另一类构网算法。

### 9.3 持续构网是一种值得熟读的中期架构选择

当前储能1经历跟网到构网的交接，因此需要处理两类控制器之间的参考和内部状态匹配。持续构网研究保持构网控制，由模式相关参考和下垂调整满足并网功率目标与离网运行，提供了减少某些切换负担的可能性。[^R7]

**这不是说F21—F25现在都可删。**改变到持续构网需要重新设计并网运行点、同步、功率控制、保护和限制，也不能自动消除已经进入孤岛后才出现的低频问题。它是完整架构方案比较，不是当前坐标补丁的附带小改。

### 9.4 换成其他构网方法不是稳定性的保证

虚拟同步控制、振荡器类控制等也需要处理网络耦合、功率分配、限流和运行模式。当前发现的能力与坐标问题不会因为算法名称更换就自动消失。此处不对某一新算法作优劣排名，现有资料不足以给本项目选定替代方案。

## 10. 与文献比较后，当前复杂度最值得质疑的地方

### 10.1 多个实现是否在承担同一个限制或恢复任务

角色限制的旧直轴预裁剪与新物理方向裁剪，是已经发现的不一致实例。其余并联支撑不能因此全部定罪，但应逐项确认：谁形成基础量、谁形成增量、谁最后限幅、反馈给哪个状态。[^P1]

### 10.2 新执行对象是否仍使用旧对象下形成的增强支路

版本4.9改变了功率方向和执行残差处理，原低频阻尼与慢无功支撑的参数不应只因历史有效就永久冻结。应该评价在新对象中的增量收益。没有证据前既不全部删除，也不继续附加一层来弥补未知相互作用。[^P2][^P3]

### 10.3 参考恢复是否使支撑退出，反而重新增加主机负担

本轮官方算例提供了一个有用提醒：当构网机恢复频压至名义值，按偏差提供支撑的跟网机可能因进入死区而退出支撑。[^R8]

对本项目而言，应核对：本地慢无功支撑随着误差减小而下降时，中央是否把所需稳态分担保留下来；电动汽车充电恢复时，储能1负担和中央有功分配是否同步更新。**这不是已经确认的本项目故障，而是有文献机制支持的检查方向。**

版本4.8中央非零偏置的功能之一，正可以是保留需要的稳态支撑。因此不能因为它增加复杂度，就认为它一定多余。

### 10.4 主频推进、实际电压方向与控制参考系是否各司其职

公共频率推进提供相位演化的一部分，不保证本机电压正交轴分量为零。版本4.9已有方向修正，两处残留说明迁移尚未彻底一致。需要统一物理意义，而不是再叠加一个相角控制器。[^P1]

### 10.5 对照和诊断是否还被误认为正式控制核心

旧电流调节器可能仍提供状态匹配参考；名称含“影子”或“诊断”的模块可能保留正式消费者。相反，某些已删除日志并不提供闭环反馈。不能凭名称决定。审计应服务于明确实际权限，随后才做有证据的精简。[^P3]

## 11. 怎样评价一个后加控制支路是否值得保留

不采用“接着线所以必要”，也不采用“论文没有同名块所以应该删”。对每条拟保留或简化的增强支路，回答五件事：

| 评价问题 | 应提供的证据 |
|---|---|
| 它解决什么具体问题？ | 相应物理现象、控制目标或保护需求，不只是旧试验编号 |
| 它何时有控制权？ | 阶段、使能、状态初值、退出条件以及最终消费者 |
| 它改变什么物理量？ | 参考、前馈、阻尼、限幅或执行量，单位、符号与坐标明确 |
| 它对最终模型有何增量价值？ | 相同或可解释工作点下的响应比较、模型预测和保护边界 |
| 有没有更少状态或更一致的实现？ | 合并、统一或替代的设计，以及同等功能验证 |

这里的比较不要求粗暴关闭每个模块。可以使用等价重构、相容工作点下的有界扰动、保持已施加量的对照，或离线状态与参数灵敏度。若保持状态会影响其他分支，也必须一并建模说明。

## 12. 接下来怎样执行，避免继续复杂化

### 12.1 板端验收优先级保持不变

继续完成暂不依赖孤岛长期稳定的板端策略验收。接替时核对中央与板端的控制权、模式映射和真实在线参数。该阶段不擅自把孤岛未验证范围扩大为已完成。

### 12.2 先确定一份可信、可比较的实际模型

冻结当前工作文件和参数，核对整理引入的名称、父层和标签变动是否保持有效源到目标关系。之后做集中正常构建回归，不重复危险的整模只读编译尝试。布局脚本的通过不作为控制等价证明。

### 12.3 先修明确错误，同时开展“是否够用”的计算

首轮功能改动仍以两处坐标一致性为限。与之并行准备储能1的有功、无功、电流、调制和动态余量核算，明确理想直流源的证明边界。不是坐标补丁失败以后才开始考虑容量。

### 12.4 建立用于比较方案的六端口动态模型

从当前实际控制代码提取低频相关状态，与网络、必要快环及数字延迟连接。平均化是分析工具，不是删掉正式电磁暂态模型。对非平衡轨迹，先找相容工作点或使用局部轨迹分析，不能把电压平缓的某一秒直接当稳态。[^R1]

原作者公开的构网／跟网状态空间脚本可以作为推导交叉检查材料，但不能直接代替本项目的特殊前馈、交接和限制。[^R14]

### 12.5 按结果选择，而不是提前承诺全保留或全推倒

| 观察与分析结果 | 下一步方向 |
|---|---|
| 坐标修正后明显改善，主机能力充足 | 保留下垂一构网五跟网，继续验证完整慢动态与扰动 |
| 波动与电动汽车恢复或本地退让强相关，且定向对照支持 | 修复恢复过程、动态能力和中央分配的一致性 |
| 相容工作点附近一次控制自身衰减不足 | 在联合模型支持下整定必要支路，考虑合并或替代重复增强，而不是继续叠加 |
| 二次恢复改变工作点后才明显恶化 | 核对恢复目标、渐入、分担和状态跟踪；不能简单清零积分器 |
| 正确控制下仍存在实质能力不足 | 调度、负荷、容量与额外构网资源进入正式方案比较 |
| 主要复杂度持续来自控制器切换、并网与离网权限反复交接 | 将持续构网下垂方案作为独立中期方案比较，而不是临时打补丁 |

### 12.6 最终目标是减少不必要控制，而不只是减少画面上的线

希望最终保留下来的每一条动态支路，都有明确职责和验证；允许以更统一的实现替换历史补丁。不能因当前模型能够短时运行就永久冻结所有结构，也不能因未稳定就否定已验证的全部功能。

## 13. 文献阅读优先级及要提取的内容

### 13.1 本轮新增的三个优先对照

**第一：2022年一台构网、多台跟网协调研究。**用于对照一台主机的功率负担与跟网分配，需要提取主机下垂、功率上限、上层反馈和工况条件。它最直接回答我们的台数架构问题。[^R6]

**第二：2024年持续下垂构网切换研究。**用于比较当前跟网转构网交接与持续构网的复杂度来源。先看为什么其并网和离网共用控制，哪些状态与参考仍要管理。它不是当前立刻替换的指令。[^R7]

**第三：2025年中文离散端口建模研究。**用于实际建立六机联合分析方法。重点是公共坐标、连接网络、状态和参数灵敏度；不要复制虚拟同步算例参数。[^R1]

上一轮的有源负荷论文、混合二次协调论文和饱和反馈论文仍保留，分别支撑电动汽车恢复、功率分担与执行能力问题。[^R2][^R3][^R5]

### 13.2 同口径比较表

| 来源 | 对象及验证层级 | 对本项目可借鉴什么 | 不能外推什么 |
|---|---|---|---|
| 2022一台构网协调研究 | 一下垂构网、两跟网；仿真 | 单主机功率负担与跟网协调 | 一带五的容量和所有暂态已证明 |
| 2024持续构网研究 | 两台构网；控制器硬件在环和功率硬件实验 | 不换下垂也能改变切换架构 | 本项目应立即删掉全部交接模块 |
| 官方实时平台混合算例 | 三构网、一跟网；平均值实时模型说明 | 测量、一次、二次、内环、参考分层 | 同样平台即参数和结构可以照搬 |
| 2022混合协调论文 | 混合构网跟网、协调控制分析与仿真 | 恢复与功率共享一起设计 | 必须改成分布式通信拓扑 |
| 2025中文离散模型 | 一虚拟同步构网、三跟网的四机并网算例 | 保留端口、网络和离散动态 | 构网形式和频段与本项目相同 |
| 2025构网占比硬件研究 | 多种容量与同步源配置、不同事件 | 容量和事件类型必须共同看 | 某个占比是通用最低标准 |
| 2026混合动态协调论文 | 两构网、两跟网；控制器硬件在环 | 暂态功率共享也应纳入目标 | 其证明覆盖当前全部限制与保护 |

### 13.3 阅读结束后怎样判断真正有用

每篇至少形成：研究对象与假设、验证层级、相关方程、与当前模型差异、具体对应模块、预期能解释的现象，以及仍需本项目验证的部分。没有这些映射，下载再多论文也不会自动形成下一版控制器。

本轮已完成公开正文、作者稿和官方记录的定向核验，但没有逐式复现所有论文，也没有得到用户当前模型的稳定域或最优参数。各来源的具体阅读范围在脚注中明示。

## 14. 应当撤回或避免延续的结论

“所有新增块都必要”“审计完整所以其余环节全部正确”“一台主机一定足够”“无法更换构网方式”“频带重叠就一定错误”“某一项同工况试验能一次证明唯一根因”“又增加一层阻尼就会稳定”，这些说法均缺少当前证据。

同时也不应反向认定：“复杂就一定错”“必须双构网”“下垂已经走不通”“所有历史补丁应该推倒”。本轮检索同样不支持这些结论。

## 15. 最终判断

**总体控制方向可以继续，当前实现需要更严格的必要性与能力论证。**

保留下垂与一构网五跟网作为默认基线，不是因为已经投入太多，而是因为它有研究依据，项目已经实现真实成岛，当前还有可定位、可验证的实现和动态问题。

允许精简、合并或替代历史支路，也允许在明确容量或架构证据下改变构网配置；但每一次改变都应指向具体限制，不能因为疲于排错而无依据换算法。真正的下一步是：**修正明确错误，核算主机能力，建立相容工作点与六机联合动态证据，再决定哪些复杂度确有价值。**
