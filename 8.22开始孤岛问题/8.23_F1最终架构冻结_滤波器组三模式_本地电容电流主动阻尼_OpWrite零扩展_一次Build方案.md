# 8.23｜F1最终架构冻结：滤波器组三模式 + 本地电容电流主动阻尼 + OpWrite零扩展 + 一次Build方案

> 本文件是正式F1 Patch编写前的**结构冻结文件**。  
> 当前不再扩大根因诊断范围；目标是把已经找到的约0.53 kHz低阻尼模态，用一次F1 Build构造成可比较、可回退、可调的修复平台。  
>
> 最重要的新决策：
>
> ```text
> 1. Group29 OpWrite完全不扩展，31行/5 kHz保持D1原样；
> 2. Vdq/Idq只局部增加500/800/1000 Hz并行滤波器组；
> 3. 主动阻尼使用SS本地LC电容电流候选，而不是再走SM→SS反馈；
> 4. 主动阻尼插在Current Regulator的Add2与原final Saturation之间；
> 5. AD_ENABLE=0、K_AD=0、FILTER_MODE=0时必须严格退回当前D1基线；
> 6. 不在F1第一版复制多套PI，不同时改SM/SS反馈架构；
> 7. 下一次结构修改目标仍然只有1次Rebuild。
> ```

---

# 1. F1为什么现在可以冻结

最新F1只读审计已经确认：

```text
Vdq:
Selector2
→ 原500 Hz Second-Order Filter
→ VdVq_meas

Idq:
Selector1
→ 原500 Hz Second-Order Filter1
→ IdIq_meas
```

并且原500 Hz V/I Filter的输出都**只去对应的正式Outport**，没有隐藏正式分支。

因此滤波器组三模式可以局部插入，而不碰：

```text
P_meas
Q_meas
PLL相关Filter
```

当前Current Regulator也已经锁定：

```text
IdIq error
→ Current PI
→ PIdq

VdVq_meas + R/L feedforward
→ feedforward dq

PIdq + feedforward
→ Add2
→ 原final Saturation
→ VdVq_conv
```

VdVq_conv之后：

```text
Vref Generation
→ Unit Delay
→ Vpwm
→ PWM
```

所以修复位置已经足够清楚。

# 5. 为什么三个Filter必须始终并行运行

不能采用：

```text
mode切换以后才启动对应Filter
```

而是三路从仿真开始就同时接raw信号。

这样：

```text
500
800
1000
```

内部状态一直都是“热的”。

以后即使切换：

```text
FILTER_MODE
```

也不会因为新Filter从零状态突然投入而制造额外大瞬态。

正式测试仍优先：

> **在Execute之前或GFM接管之前确定FILTER_MODE，不要在已经孤岛振荡时频繁切Filter。**

# 6. 为什么不用Multiport Switch

为了降低脚本和代码生成风险，F1采用两个普通 `Switch` 串联。

例如Vdq：

```text
SW800：
mode >= 0.5
→ 800
否则
→ 500

SW1000：
mode >= 1.5
→ 1000
否则
→ SW800
```

因此：

```text
mode=0 →500
mode=1 →800
mode=2 →1000
```

Idq相同。

普通Switch是当前模型已经大量使用并成功Build过的基础块。

# 7. 500/800/1000在当前484 Hz模态上的含义

当前D1实测500 Hz接近：

```text
|H| ≈0.516
phase ≈-88°
```

连续域ζ=1比较：

| Fo | 484 Hz幅值 | 484 Hz相位 |
|---:|---:|---:|
|500 Hz|0.516|-88.1°|
|800 Hz|0.732|-62.4°|
|1000 Hz|0.810|-51.7°|

所以：

```text
500 → 800
约减少26°相位损失

500 → 1000
约减少36.5°相位损失
```

这两项不是“最终最佳值已确定”，而是一次Build内最有信息量的第一组修复候选。

# 8. F1第二修复层：本地电容电流主动阻尼

当前SS低压链：

```text
ESS1_Converter
↓
inv
↓
L1
↓
LC节点
├── C1
└── Stubline
```

用户截图已经确认：

```text
inv：
左 A/B/C = Converter侧
右 a/b/c = L1侧

Measurement6：
左 A/B/C = Stubline侧
右 a/b/c = LC节点侧
```

Three-Phase V-I Measurement的正电流方向按：

```text
A/B/C → a/b/c
```

所以：

```text
i_inv 正方向：
Converter → LC节点

i_M6 正方向：
Stubline → LC节点
```

如果定义：

```text
i_out：
LC节点 → Stubline

i_C：
LC节点 → C1
```

那么：

```text
i_out = -i_M6
```

KCL得到：

```text
i_C
= i_inv - i_out
= i_inv + i_M6
```

因此**现有两个测量输出的物理组合符号已经冻结为“加”**。

---

# 9. 一个必须纠正的量纲细节：控制pu采用峰值电流基准

此前只读审计先按RMS基值计算了：

```text
ESS RMS base ≈ 120.281306081 A
Measurement6 RMS base ≈ 4330.127018922 A
```

这个比例确实是：

```text
36
```

但当前GFM正式电流标幺Gain已经明确为：

```text
Vnom_prim*sqrt(3)/Pnom/sqrt(2)
```

也就是：

> **瞬时三相电流按“峰值相电流基值”进入控制pu。**

因此F1构造本地电流时，不能把 `inv_I_A` 除以120.28 A。

正确的ESS低压峰值电流基准：

```text
Ibase_ESS_peak
= sqrt(2) × Pnom/(sqrt(3)×Vnom_sec)
= 170.103454360 A
```

Measurement6对应峰值基准：

```text
Ibase_M6_peak
= sqrt(2) × 450e6/(sqrt(3)×60e3)
= 6123.724356958 A
```

两者比例仍然严格：

```text
36
```

因为sqrt(2)在比例中抵消。

---

# 10. 因此F1电流统一公式冻结为

## inv

`inv` 当前：

```text
Ipu = off
```

输出是实际瞬时A。

转换到ESS控制pu：

```text
i_inv_pu
=
i_inv_A / 170.103454360

=
i_inv_A
× Vnom_sec*sqrt(3)/(Pnom*sqrt(2))
```

当前数值Gain约：

```text
0.005878775383
```

---

## Measurement6

Measurement6：

```text
Ipu = on
Pbase = 450e6
Vbase = 60e3
```

由于其pu基准与ESS控制pu的峰值电流基准比例仍为36：

```text
i_M6_on_ESS_pu
=
36 × i_M6_pu
```

所以最终：

```text
i_C_abc_pu
=
i_inv_A × Vnom_sec*sqrt(3)/(Pnom*sqrt(2))
+
36 × i_M6_pu
```

---

# 11. F1正式Patch必须对Measurement6的pu约定做“编辑前断言”

虽然上面的比例与现有GFM控制的峰值pu定义一致，而且MathWorks的pu文档也采用峰值电流作为瞬时current pu基准，但为了避免将一个通用约定硬套给具体SPS块：

> **F1 Patch在任何结构修改前，必须尝试读取Measurement6 Mask Workspace中的 `Ki`，或者它内部 `Kv` 的实际解析增益。**

必须验证：

```text
Ki_expected
=
Vbase*sqrt(3)/(Pbase*sqrt(2))
```

如果解析出的实际 `Ki` 与该式不一致：

```text
脚本立即停止
Build=0
模型不改
```

届时才让用户执行一个极小的手动读数。

也就是说：

> **这一个最后的数值约定不通过猜测解决，而是作为F1 Patch的pre-flight硬断言。**

# 12. 为什么主动阻尼不使用prim_ESS1电流

GFM正式反馈：

```text
prim_ESS1
↓
SM
↓
ESS_IO_Memory24
↓
SM→SS
↓
ESS1_Control
```

已经确认它跨任务/Memory。

而主动阻尼目标频率：

```text
约530 Hz
周期≈1.89 ms
```

所以主动阻尼更适合使用：

```text
SS本地inv / LCout
```

直接形成电容电流。

这样主动阻尼不再额外承受：

```text
SM→SS反馈时序
```

这是F1的一个关键优势。

# 13. 电容电流如何进入dq

在 `ESS1_Control` 中新增一个：

```text
F1_AD_ABC_TO_DQ
```

不手工重新写Park变换。

直接复制当前已经使用的：

```text
Measurements/abc to dq0
```

因此保持：

```text
Alignment = 90 degrees behind phase A axis
```

输入：

```text
abc = i_C_abc_pu
wt  = GFM Droop theta_out
```

输出：

```text
[d q 0]
```

再复制现有Selector取：

```text
i_C_d
i_C_q
```

这可以确保主动阻尼dq坐标和当前GFM Vdq/Idq坐标定义一致。

# 14. 为什么用Droop theta_out而不是PLL角

主动阻尼只在：

```text
GridOn=0
```

即ESS1实际GFM时投入。

GFM正式电压/电流测量本来就是使用Droop自生角进行dq变换。

所以主动阻尼必须使用同一个：

```text
Droop theta_out
```

不使用PLL角。



# 16. AD_SIGN为什么仍然保留

物理电流组合的加号已经通过截图冻结：

```text
iC = i_inv + i_M6
```

但是：

```text
电流反馈到VdVq命令
```

的最终控制符号还涉及：

```text
dq定义
Current Regulator的正方向
Vref Generation电压指令方向
```

标准电容电流反馈通常以负反馈形式工作，所以F1默认：

```text
F1_AD_SIGN = -1
```

但必须保留：

```text
+1 / -1
```

可调。

这样即使运行敏感性证据表明符号需要翻转：

```text
无需再次Build
```

这不是“靠试错代替物理判断”，而是额外的反向保险。

# 18. F1_K_AD固定语义

单位：

```text
pu voltage / pu current
```

可理解成：

```text
pu虚拟阻尼/虚拟电阻系数
```

默认：

```text
0
```

正式Patch阶段**不硬编码一个“最佳K”**。

```text

```

再决定是否开启AD。

如果需要AD：

```text
K=0
→ 小值
→ 逐渐增大
```

不允许第一次直接给大K。

# 20. 为什么这个位置最合适

原结构：

```text
PIdq
+
R/L feedforward
↓
Add2
↓
Saturation
↓
VdVq_conv
```

F1：

```text
PIdq
+
R/L feedforward
↓
Add2
+
V_AD_dq
↓
F1_VAD_SUM
↓
原Saturation
↓
VdVq_conv
```

优点：

```text
不改Current PI内部
不改anti-windup内部
不改R/L feedforward
不新增第二个最终电压限幅
不改Vref Generation
不改PWM
```

而且：

```text
AD=0
```

时：

```text
F1_VAD_SUM = 原Add2
```

所以原final Saturation收到的输入完全相同。

这比“在Current Regulator输出后再加第二个Saturation”更干净。

# 21. 为什么F1第一版不复制多套PI

最新审计确认：

```text
DefaultParameterBehavior = Tunable
InlineParams = off
```

但并没有证明RT-LAB Execute期间所有Linked PI Mask参数都能可靠实时改。

如果为了“可能要调PI”一次性复制：

```text
多套Voltage Regulator
多套Current Regulator
```

会显著增加：

```text
状态量
anti-windup状态
切换瞬态
Build复杂度
```

而D1最强的直接证据首先指向：

```text
500 Hz feedback phase loss
+
缺少本地快速阻尼
```

因此F1第一Build只做：

```text
Filter Mode
+
Active Damping
```

PI原值保持：

```text
Kp_Vreg = 2
Ki_Vreg = 14

Kp_Ireg = 0.3
Ki_Ireg = 20
```

如果F1仍然不足，再决定PI是否进入下一层优化。

# 22. F1控制参数放在哪里

为了避免扩展SM→SS 24维控制向量：

> **F1参数全部作为ESS1_Control内部显式Constant块。**

建议：

```text
F1_FILTER_MODE
Value=0

F1_AD_ENABLE
Value=0

F1_K_AD
Value=0

F1_AD_SIGN
Value=-1
```

这些都是普通Simulink `Constant`。

当前模型：

```text
DefaultParameterBehavior=Tunable
```

所以它们应作为独立调试参数被代码生成保留。

F1 Build以后先在RT-LAB Variables Table中确认可写，再由后续测试脚本自动化。

不为了这4个参数修改：

```text
SM→SS
OpComm
device_io12
group_io24
BOARD15
```

# 40. 当前最重要的工程判断

> **我们现在不应该为了“功能齐全”把所有可能修复都塞入F1。最有可能一次Build解决问题的做法，是只安装D1证据直接支持的两把杠杆：局部V/I滤波相位改善，以及SS本地电容电流主动阻尼。两者都可关闭，Filter Mode=0与AD OFF能够回到当前基线；PI、Plant、SM→SS架构全部不动。这样如果800/1000 Hz单独已经解决问题，我们直接停止；只有阻尼仍不足才打开AD。**
