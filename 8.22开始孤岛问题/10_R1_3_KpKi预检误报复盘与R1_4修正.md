# R1.3 Kp/Ki预检误报复盘与R1.4修正
## K26_K50_CLEAN_P1｜2026-09-20

# 1. 用户遇到的报错

R1.3只读PRECHECK报：

```text
PV1 P Kp baseline drift.
```

报错代码使用：

```matlab
str2double(get_param([ppi '/Kp4'],'Gain'))
```

# 2. 模型真实情况

已上传模型的PV1 P PI实际保存形式是：

```text
Kp4.Gain = Kp
Kp5.Gain = Ki
```

不是直接写成：

```text
0.06
2.0
```

因此：

```text
str2double('Kp') = NaN
```

R1.3把“表达式参数”误报成“模型漂移”。

# 3. 为什么这是脚本错误，而不是模型错误

ESS2已经成功过的：

```text
PATCH_K26_K50_ESS2_P_PI_RUNTIME_GAINS_R1
```

明确采用：

```matlab
raw=get_param(block,param);
got=slResolve(raw,block);
```

在模块上下文中解析`Kp/Ki`的实际数值。

只有解析后的真实数学值不是：

```text
Kp = 0.06
Ki = 2.0
```

才属于真正baseline drift（基线漂移）。

# 4. R1.4怎样改

PRECHECK、APPLY的改前门、postassert（改后断言）、VERIFY（只读验证）统一采用同一个成功范式：

```text
表达式
→ slResolve
→ 实际数值
```

同时保护Q PI：

```text
Q Kp resolved = 0.06
Q Ki resolved = 2.0
```

Q PI本轮不修改。

# 5. P Kp/Ki在线暴露怎样复用ESS2

PV1 R1.4正式采用：

```text
原Kp4 / Kp5 Gain → 1
显式Constant → CFG_PV1_DIAG_P_KP_RT / KI_RT
Constant × unity Gain output
→ 原比例/积分后级
```

Patch默认：

```text
Kp_RT = 0.06
Ki_RT = 2.0
```

所以Patch前后默认数学完全一致。

Build以后才通过Target Verify证明：

```text
GetParametersDescription
→ exact unique binding（精确唯一绑定）
→ write
→ readback
→ restore
→ readback
```

正式Run A再在第一次Execute前写：

```text
Kp = 0.06
Ki = 0.5
```

# 6. 用户是否需要手工操作

不需要手工改：

```text
Kp4
Kp5
Constant
Product
PI内部连线
```

这些都属于普通Simulink结构，按ESS2已经成功的事务式Patch自动完成更可靠。

如果R1.4 PRECHECK仍无法用`slResolve`解析当前模型的Kp/Ki，才停止，并要求用户上传当前SLX或提供以下MATLAB输出：

```matlab
ppi = ['K26_K50_CLEAN_P1/SS_Slave3/PV1_Control/Power Control Loop/' sprintf('PI regulator\nwith anti-windup D')];
get_param([ppi '/Kp4'],'Gain')
slResolve(get_param([ppi '/Kp4'],'Gain'),[ppi '/Kp4'])
get_param([ppi '/Kp5'],'Gain')
slResolve(get_param([ppi '/Kp5'],'Gain'),[ppi '/Kp5'])
```

在这之前不需要重新上传模型。
