# K26_V5｜V4.7 五台跟网设备孤岛 Q 控制权重构｜最终设计冻结 V2

> 日期：2026-09-04  
> 当前基线：V4.6（版本4.6）  
> 当前磁盘模型 SHA256：`7f076e193b2582493cd0b8723fed53cac1cc68afbed8323bd36f2752fa409092`  
> 本版状态：**设计冻结，可进入事务式 Patch（改模补丁）与独立 Verifier（独立校验）**  
> 本版相较 V1 的关键修正：**不再使用一个同时处理基础 q 轴电流和 QrefEff（有效无功参考）的单一 MATLAB Function。改为三个职责分离的核心模块，主动避免重演 V4.4 的 block-level direct-feedthrough（块级直接馈通）代数环问题。**

# 0. 最终判断

现在已经有足够证据把“下一次应该改哪里”冻结。

当前最大的剩余结构问题不是：

- ESS1 不会构网；
- J1 没有真实断开；
- 执行坐标不对；
- 5~20 Hz 主动阻尼没有工作；
- Current PI（电流内环比例积分器）参数本身错误；
- 电流圆首先触发；
- ModIndex（调制度）首先饱和；
- V4.6 低频支路符号写反。

当前最大的剩余结构问题是：

> **在 ESS1 已经作为唯一 GFM（Grid-Forming，构网型）承担孤岛电压/频率形成以后，PV1、PV2、ESS2、EV1、EV2 五台仍为 GFL（Grid-Following，跟网型）的设备，仍继续让原“强网固定 Q 跟踪比例积分器”实时决定基础 q 轴电流。**

这使五台 GFL 的无功外环与唯一 GFM 的有限 Q-V（无功-电压）输出阻抗，在公共母线上形成低频聚合闭环。

# 1. 为什么现在可以把 Q 外环提升到“本次主修改对象”

## 1.1 真实结构已经锁死

五台均为：

```text
Power Control Loop
（功率控制环）

Qmeas - QrefEff
        ↓
PI regulator with anti-windup D1
（无功外环比例积分器）
        ↓
Power Control Loop 输出第二分量
        ↓
raw q current
（原始 q 轴基础电流）
        ↓
AA15_ISLAND_GFL_SUPPORT_MANAGER
（跟网设备孤岛支撑管理器）
```

无功 PI 参数：

```text
Kp = 0.06
Ki = 2
Upper = +1
Lower = -1
```

内部为：

```text
离散梯形积分器
内部条件式抗积分饱和
无外部 reset
无外部 state-set
```

因此这次不进入封装 PI 内部修改。

---

## 1.2 raw/base q 已经被直接反解，不再拿 FinalIref_q 冒充 PI 输出

V4.5/V4.6 Limit Core（最终电流限流核心）的真实合同是：

\[
I_{final,q}
=
I_{support,q}
+
g_Q I_{base,q}
\]

因此：

\[
I_{base,q}
=
\frac{I_{final,q}-I_{support,q}}{g_Q}
\]

本轮 0.25 Hz 分析窗口：

```text
J1 + 0.20 s
~
J1 + 3.30 s
```

五台：

```text
gQ = 1
CurrentLimit = 0
```

所以这里的 BaseIq（基础 q 轴电流）实际上就是没有被 current-circle（电流圆）污染的 Q PI 原始基础电流。

---

## 1.3 五台 BaseIq / Qerror 与实际 Q PI 理论动态一致

Q PI：

```text
Kp = 0.06
Ki = 2
```

在 0.25 Hz：

```text
理论幅值 ≈ 1.27465
理论相位 ≈ -87.30°
```

实测反解：

```text
PV1   BaseIq/Qerror ≈ 1.518   phase ≈ -73.88°
PV2                   1.518           -73.88°
ESS2                   1.589           -76.91°
EV1                    1.429           -73.84°
EV2                    1.429           -73.83°
```

五台全部通过理论一致性筛选。

同时 BaseIq 的 0.25 Hz 拟合：

```text
R² ≈ 0.998
```

说明不是偶然小成分。

## 1.4 BaseIq 明显大于外围支撑

```text
PV1   BaseIq / SupportQ ≈ 13.51
PV2                      ≈ 13.51
ESS2                      ≈ 3.72
EV1                       ≈ 15.05
EV2                       ≈ 15.06
```

中位数：

```text

```


这解释了为什么 V4.6 再增加一个 0.18~0.35 Hz q 轴支路仍不足以稳定系统。

# 2. 为什么分析器曾给 StrongQPIBaseQEvidenceScreen=0，但不能据此否定根因

原分析器把：

```text
五台 BaseIq 两两相关必须为正
```

作为强证据条件。

这是错误的“符号统一”假设。

实际：

```text
PV1 ↔ PV2   correlation ≈ +1.000
EV1 ↔ EV2   correlation ≈ +1.000

PV ↔ EV     correlation ≈ -0.996
ESS2 ↔ EV   correlation ≈ -0.981
```

同时相位差集中在：

```text
0°
或
接近 180°
```

原因是发电资源和充电负荷的功率方向/局部 dq 符号不同。

如果判断：

```text
abs(correlation)
```

则五台之间最低仍约：

```text
0.981
```

中位数约：

```text
0.996
```

这代表高度相干的同一个公共慢模态，而不是无关运动。

因此：

> `StrongQPIBaseQEvidenceScreen=0` 是分析器 signed correlation（带符号相关）判据的假阴性，不是 Q PI 证据失败。

# 3. 真实调制饱和是不是根因

不是本次首发根因。

在同一个 0.25 Hz 因果分析窗口：

```text
PV1/PV2  Max ModIndex ≈ 0.877
ESS2                  ≈ 0.837
EV1/EV2               ≈ 0.813
```

五台：

```text
CurrentLimit = 0
```

第一次 ModIndex ≥ 0.98：

```text
PV1/PV2 ≈ J1 + 3.55 s
ESS2    ≈ J1 + 5.91 s
EV1/EV2 ≈ J1 + 5.93 s
```

而 0.25 Hz BaseIq/Qerror 动态在此前已经清晰存在。

所以正确因果顺序是：

```text

        ↓
电压摆幅逐渐扩大
        ↓
要求的 converter voltage（变流器输出电压）扩大
        ↓

        ↓
电流跟踪继续恶化
        ↓
系统进入强非线性
```

# 4. 真实调制裕度仍然存在什么缺陷

真实链：

```text
Current PI
（电流比例积分器）
+
VFF
（电压前馈）
+
R/L 解耦
        ↓
Current Regulator 最终 VdVq_conv
（最终 dq 轴变流器电压命令）
        ↓
Goto / From 信号路由
        ↓
Vref Generation
（调制参考生成模块）
        ↓
ModIndex 0~1 最终限制
```

Current PI 的内部抗积分饱和知道的是它自己的限制。

但真正下游：

```text
ModIndex <= 1
```

没有反馈回：

```text
Current Regulator
或
AA15_ISLAND_GFL_SUPPORT_MANAGER
```

所以“真实调制裕度反馈缺口”确实存在。

但第一版 V4.7 不同时修改这个问题。

原因：

> 本次首先消除已经被直接证据锁定的首发反馈机制；如果 Q 控制权修复以后 ModIndex 自然不再撞限，那么继续增加调制反馈反而是不必要复杂化。

## 5.5 V4.6 LFQ 为什么没有解决 Primary

V4.6 的思路是：

```text

        ↓

        ↓

```

这个设计：

- 频带合理；
- 符号合理；
- 零直流增益；
- 显式 UnitDelay 因果；
- 不是“写反”。

真正问题是：

> **它仍然是“加在原 Q PI 后面的外围支撑”，没有改变谁拥有孤岛基础 q 轴电流控制权。**

实际 0.25 Hz：

```text

```

也就是说：

```text

```

而新支路只是在外围增加一个小修正。

所以它是在：

```text
外围支撑
vs
内部更强的 Q 积分器
```

之间拔河。

## 5.6 GammaQ 为什么也没有根治

GammaQ（无功跟踪释放系数）的逻辑是：

```text
support 活跃
→ 适当减弱 Q tracking
```

但它的目标是：

> 防止 Q PI 过快抵消 support。

它不是：

> 让 Q PI 退出孤岛主控制权。

而且 V4.6 的实际外围 support 幅值很小，GammaQ 的软释放无法等价于：

```text
Qerror = 0
```

所以它只能缓解竞争，不能消除结构性竞争。

# 8. V2 设计为什么必须拆成三个核心模块

V1 曾倾向于设计一个：

```text
AA15_Q_AUTHORITY_CORE_V47
```

同时输入：

- raw q；
- Qmeas；
- legacy QrefEff；
- Stage；
- 状态；

同时输出：

- applied qbase；
- selected QrefEff。

现在正式放弃这种单块做法。

原因：

> MATLAB Function 在 Simulink block level（块级）会被按 direct-feedthrough（直接馈通）参与代数环判断，而不会只依据某个 if 分支当前是否使用某个输入。

如果同一个块既有：

```text
raw q 输入
```

又有：

```text
QrefEff 输出
```

就可能重新形成：

```text
QrefEff
→ Q PI
→ raw q
→ Q authority block
→ QrefEff
```

的代数环。

这与 V4.4 Frame 错误属于同一类工程风险。

因此 V4.7 V2 强制拆成三个独立核心。

# 16. 为什么“保持 qbase”和“Qerror=0”必须同时做

只保持 qbase、不处理 Qerror：

```text
物理上虽然暂时不用 live Q PI
但 Q PI 内部仍继续积分
```

重新并网时会有 hidden bump（隐藏冲击）。

只让 Qerror=0、不保持 qbase：

```text
Q PI 输出会立刻失去原来的 Kp*error 分量
```

可能在 J1 边沿出现 q 电流工作点跳变。

因此必须同时：

```text
applied base q = pre-island hold
+
background Q PI error = 0
```

# 20. 为什么恢复要同时混合两条路径

如果只混合 qbase：

```text
Q PI 仍然 error=0
```

恢复时 live PI 不会提前适应原 Qref。

如果只恢复 Qref：

```text
Q PI 开始变化
但 applied base 仍完全 hold
```

直到突然接权，仍可能产生冲击。

同步恢复：

```text
Qref authority
+
current authority
```

才是完整 bumpless transfer（无冲击控制权交接）。

# 24. 为什么 V4.6 LFQ 第一版仍保留

不是因为它被证明“必要”。

而是为了保持 V4.6→V4.7 因果干净：

```text
V4.6：
live Q PI + LFQ
FAIL

V4.7：
held base-q + Qerror zero + 同一个 LFQ
?
```

如果 V4.7 稳定，最主要变化就是 Q authority（Q 控制权）。

如果这次顺便把 LFQ 关闭，就同时改变两个变量。

因此 V4.7 第一版不动 LFQ。

调小 Ki 仍然意味着：

> 五台设备孤岛后继续把固定 Q 当主要动态目标。

```text

```

的模式切换，而不是参数微调。

- 频率通道明显健康；
- P/f 需要 P 外环继续执行；
- 同时改 P/Q 无法判断根因；
- 当前没有证据把 P 外环提升为首发源。

所以 V4.7 只改 Q。

---

# 28. 为什么这个方案不会把五台变成 GFM

五台仍然使用：

```text
Current Regulator
```

控制电流。

没有让它们：

- 自己积分频率角度；
- 独立形成母线电压；
- 改成电压源。

只是把：

```text
fixed-Q current-controlled GFL
```

变成：

```text
island voltage-supporting current-controlled GFL
```

ESS1 仍是唯一 GFM。


不增加 OpWrite 宽度。
