## 二、先用普通语言理解我们的系统

### 1. 断开上级电网后，谁真正建立电压？

在当前配置中，储能1承担构网任务。它给孤岛建立交流电压和频率。其余五台是跟网设备：它们按已有交流电压和相角控制自己的电流，提供有功和无功支撑。

因此，要判断孤岛为什么出问题，至少要同时看两条实际执行链：

```text
储能1：
电压/频率参考
→ 电压调节器计算需要的电流
→ 电流参考交接及限幅
→ 电流调节器计算需要的变流器电压
→ 调制与电气对象
→ 实际母线电压和电流

其余五台：
有功任务 + 电压辅助支撑 + 二次q轴偏置
→ 最终电流参考
→ 电流调节器
→ 调制与电气对象
→ 实际电流和功率
```

只看中央命令已经发出，无法证明设备实际做到了。只看五台跟网设备，也不能排除构网储能1在其中的作用。

### 2. q轴偏置究竟是什么？

它是加在五台设备q轴电流参考上的一部分慢修正量。它的用途是：在切换后的快速过程结束以后，逐渐调整辅助支撑，把母线电压向目标范围恢复。

它不是必须回到零的临时扰动。**系统在额定附近运行时，仍可能需要一个非零偏置来维持新的平衡。**

因此，正确的控制器应允许这个非零偏置稍微增大或稍微减小，而不是只要调整方向与已有偏置相反，就认为已有偏置应当全部撤掉。

### 3. 有功工作点为什么暂时不改？

离网前留下的有功工作点是切换初始条件，不一定是所有后续工况下的最佳调度。但是，“不是最优”不等于“必然不稳定”，更不等于“当前异常已经证明由它引起”。

当前模型还存在频率相关的一次、二次有功修正，不能把基准保存理解成所有实际有功指令在孤岛里永久不变。光伏向电动汽车供电也是正常供用电关系，不能仅因为发电和充电功率较大，就把它称为已经证明有害的功率环流。

**有功侧保留为待检查因素，先不因此新增一套调度算法。** 后面若实际数据证明既定工作点下某个执行约束长期无法满足，再讨论减载或重调度。

## 五、目前真正确认的问题是什么

### 1. 代码中存在不合适的积分回调规则

实际模型位置：

```text
K26_V5/SM_Master/AA15_V48_ISLAND_QBIAS_COORDINATOR/AA15_V48_QBIAS_COORD_CORE
```

路径含义：模型 → 主计算分区 → 岛内二次q轴偏置协调器 → 二次偏置计算核心。

当前实际代码包含：

```matlab
elseif qz*dqdes<0.0 && abs(qz)>1e-12
    qstaten=releaseZero(qz,abs(rev_slew)*TsS);
```

`qz（当前偏置状态）`表示已有的控制作用；`dqdes（期望变化率）`表示现在希望它增加还是减少；`releaseZero（按固定速度向零释放）`不按小误差大小进行调整。

举一个只用于解释代码的例子：

- 系统当前需要约正0.20的偏置；
- 滤波后的误差为正0.011；
- 死区为0.01，积分系数为0.30。

正常积分给出的变化率是：

\[
-0.30\,(0.011-0.010)=-0.0003.
\]

意思是稍微减小已有偏置。

但当前特殊分支给出的速度为负0.15，是前者的500倍。它把普通的小幅回调变成了较强的向零释放。

**这项问题已经在最终上传模型内确认，不是只存在于之前的建议文本。** 但500倍是这个例子的单步算法计算，不是说整个电压振荡被放大了500倍，也不是说已经证明全部异常都由此产生。

### 2. 慢滤波误差在电压翻转时存在旧状态滞留

当前误差低通截止频率是0.10赫兹，对应时间常数约1.59秒。

已上传记录显示：

| 离网后时间 | 实际母线电压 | 中央慢误差的含义 | 已有偏置 |
|---|---|---|---|
| 5.48秒 | 约1.0674，已经偏高 | 仍表示电压偏低 | 约−0.0347 |
| 5.68秒 | 约1.1840，明显偏高 | 仍表示电压偏低 | 约−0.0356 |
| 13.20秒 | 约0.7042，明显偏低 | 仍表示电压偏高 | 约+0.2409 |

这是升压、降压两个方向都观察到的现象。[来源3]

**不能把它简单改成电压一反号就清零偏置。** 因为系统可能仍然需要一部分已有偏置。正确问题应是：当前新增的调整是否不利，已有状态应如何平滑回调，以及下游实际来得及执行多少。

### 3. 目前反馈的已施加偏置不是实际物理电流

五台本地核心中的实质操作是：

```matlab
fd=id0;
fq=iq0+qsec_used;
```

`qsec_used（本次施加的二次q轴偏置）`被加到了 `fq（最终q轴电流参考）`。

因此，`IqSecApplied（施加到电流参考的二次q轴偏置）`与中央之和一致，可以证明命令分配和参考计算一致；**不能证明逆变器已经输出同样大小的实际q轴电流。**

这次提取将补充“最终参考—实际电流”的误差，而不是重复验证“中央命令—局部参考”的一致性。

### 4. 本轮新确认：所谓原始调制需求之前还存在一次分量限幅

当前实际链路并不是：

```text
完全不受限制的电压需求 → 唯一调制幅值限幅
```

而是包含：

```text
电流调节器内部计算
→ d、q电压分量限制到±1.25
→ 电压归一化
→ 计算矢量幅值
→ 将调制度限制到0～1
```

所以 `RawModDemand（幅值限幅前的调制需求）`只是**幅值限幅前**，不是**所有上游限制之前**。

本模型的归一化使用480伏交流额定值和1000伏直流常数。该直流输入在这里是额定常数，不是此处额外接入的实时直流测量。

按实际模型计算：

\[
M=\frac{2\times480\sqrt{2/3}}{1000}\sqrt{V_d^2+V_q^2}.
\]

若两个分量同时处在±1.25，幅值恰好是：

\[
M_{\max}\approx1.385640646.
\]

这与现有日志反复出现的约1.386一致。因此，不能再把该值解释为“真正无限幅请求恰好需要1.386”。它可能已经受到更前面的限制。[来源1、3；公式为本轮计算]

**这不是又宣布一个新根因，而是把执行链中的限幅位置认清楚。** 后续要检查何时开始分量贴限、实际电流何时开始跟不上，以及这些事件是在母线电压变化之前还是之后。

## 六、哪些问题现在还不能锁定

“根因锁定”至少应能解释：异常怎样开始、哪一级先偏离正常执行、为什么之后放大、针对修改是否得到预期的物理改善。

目前已锁定的是具体的控制规则与观察事实，尚不能锁定全系统唯一原因：

| 问题 | 目前证据状态 |
|---|---|
| 中央存在强制向零的非对称回调 | 最终模型源码已确认 |
| 慢误差在真实电压反向后仍保留旧方向 | 已有时序已确认 |
| 五台施加偏置等于真实物理电流 | 不成立；它是参考量 |
| 第一次高压上升由光伏调制饱和先触发 | 现有光伏1时序不支持；上升先于它的幅值饱和 |
| 储能1是否更早出现电压环或电流执行异常 | 缺少第30组详细时序，尚不能排除 |
| 有功工作点就是唯一原因 | 未证明 |
| 只改中央规则就一定稳定 | 未证明，需要完整闭环验证 |

**现在不再把每个可疑现象升级成必须增加一个新模块的理由。** 先用同次试验的数据区分：参考先变化、控制器先贴限、实际电流先偏离，还是母线先变化。

## 十、提取结果分别用来回答什么

### 1. 异常到底先发生在哪一级

看第29组中央电压、偏置状态、第30组储能1参考和实际执行、五台设备的参考和电流。

重点不是比较哪条曲线看起来更大，而是对齐这些事件：

```text
电压参考变化
→ 电压调节器输出变化
→ 电流参考被裁剪或快速变化
→ 实际电流跟踪偏差出现
→ 电压分量贴限
→ 调制幅值贴限
→ 母线电压上升或跌落
```

实际顺序可能不同。只有根据记录判断，不能在分析前预设箭头一定如此。

### 2. 中央偏置到底在哪些时候用了特殊分支

脚本按记录时刻重算正常积分、异号释放、能力回退等分支的可见条件，同时给出相邻记录之间实际偏置变化率。

这不是重放了内部每个100微秒周期。第26～29组正式记录大约每400微秒一次，第30组大约每1毫秒一次；脚本会重新测量实际间隔。记录之间遗漏的内部细节不能编造出来。

### 3. 真正的物理电流是否跟随参考

每台计算d、q电流误差的均方根、矢量误差95%分位值，以及参考、实际电流最大幅值。

储能1还比较F8限幅前后参考。这样可以区分：中央要求错、本地裁剪、参考限速，以及参考正确但电流实际跟不上。

### 4. 原来的频谱结论如何纠正

本次使用两个等长4秒窗口：离网后1～5秒、11～15秒。

实际计算0.25～2赫兹和5～30赫兹的频带能量；使用原始记录，去趋势并进行窗函数能量校正。时间不连续或采样不适用时，明确返回无法计算的原因。

0.25赫兹在4秒里也只有约一个周期，只适合描述。**不再声称辨识了0.05赫兹；不把一次跌落产生的谱峰直接叫作系统固有振荡模态。**

## 十一、下一次实际改模怎么决定

不额外并联电压积分器，不恢复五台原固定无功控制权，不因这次修改顺手提高电流极限或增加有功调度。
