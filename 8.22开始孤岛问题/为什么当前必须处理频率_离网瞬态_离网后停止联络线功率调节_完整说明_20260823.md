# 暑期南网科技项目｜为什么当前必须处理三个模型尾项
## 频率、离网瞬态、离网后停止联络线功率调节

> **日期**：2026-08-23  
> **当前背景**：PCC/J1/Load边界已经修复，正常并网和AGC回归已经通过；真实J1打开后，孤岛已经能够重新建立约10 kV电压。  
> **当前真正剩余的三个模型侧问题**：
>
> 1. 离网以后频率到底发生了什么；
> 2. 离网瞬间为什么还有较大的电压冲击；
> 3. 离网以后为什么必须停止继续做“PCC联络线功率调节”。

---

# 0. 先给结论：为什么这三个问题现在必须处理？

因为我们现在已经不再处于：

```text
模型到底能不能运行？
J1到底有没有真的打开？
孤岛到底会不会永久塌压？
```

这种“大故障排查阶段”。

这些大问题已经基本解决。

现在已经进入：

> **“这个模型是否已经具备一个逻辑正确、物理合理、可以让BOARD15真正接入的并离网Plant”**

这个阶段。

因此剩下的三个问题分别卡住三个不同层面：

```text
频率问题
→ 卡住“孤岛是否真的由GFM正确建立频率”
→ 直接影响S14黑启动、S15重同步和重新并网

离网瞬态问题
→ 卡住“从并网切到孤岛这一瞬间是否合理、安全”
→ 决定并离网切换质量是否能被接受

离网后仍继续PCC功率调节
→ 卡住“控制逻辑是否符合物理场景”
→ 离网后已经没有联络线，继续追PCC功率目标在概念上就是错的
```

这三个问题并不是“为了把模型调得更漂亮”。

而是分别对应：

```text
稳态基准正确
+
切换动态正确
+
运行逻辑正确
```

只有这三项基本成立，我们才有资格说：

> 当前Plant可以继续作为BOARD15和最终CHIL的正式被控对象。

---

# 1. 第一个问题：为什么必须把“离网后的频率”查清楚？

---

# 1.1 并网时，频率是谁决定的？

并网状态下：

```text
上级电网
↓
提供一个非常强的50 Hz电压源
↓
整个微电网跟着这个频率运行
```

此时六台逆变器中的跟网型设备主要做：

```text
测电网频率和相位
↓
PLL锁定
↓
跟着主网运行
```

所以并网时：

> 即使本地控制器本身有一些小问题，强电网也可能把系统频率“压”在50 Hz附近。

---

# 1.2 J1断开以后，情况发生了根本变化

真实J1打开以后：

```text
上级电网
×
与微电网电气断开
```

这时上级电网已经不能再给孤岛提供：

```text
50 Hz参考
```

此时必须有人自己建立：

```text
电压
+
频率
+
相角
```

当前项目选的是：

```text
ESS1
→ GFM
→ Grid-Forming
→ 构网型
```

所以离网以后，ESS1不再只是“跟着别人走”。

它变成：

> **孤岛内部的电压和频率基准源。**

---

# 1.3 因此，离网后的频率是判断GFM是否真正工作的核心证据

假设J1打开以后：

```text
电压恢复到10 kV
```

但频率：

```text
跑到55 Hz
```

那不能说：

> “GFM已经完全正常。”

因为一个合格的孤岛至少应该做到：

```text
电压建立
+
频率建立
```

不能只看电压。

所以当前：

```text
“电压回到10 kV”
```

只证明：

> 长期电压塌陷的主根因已经解决。

它还没有证明：

> 孤岛运行质量已经完全正常。

---

# 1.4 当前55 Hz现象为什么必须继续查？

当前MAT里可以看到：

```text
PCC frequency
→ 离网后逐渐升高
→ 最后停在55 Hz附近
```

但当前模型里的PCC测频链本身存在：

```text
Saturation
Lower = 45 Hz
Upper = 55 Hz
```

所以现在只知道：

```text
测量输出 = 55 Hz
```

却不知道真实情况是哪一种。

---

# 1.5 第一种可能：真实孤岛频率真的在往55 Hz甚至更高跑

如果是真的，那么说明：

```text
ESS1 GFM
↓
Droop / Fref / frequency loop
↓
建立出来的孤岛频率不正确
```

这属于真正的GFM控制问题。

如果不处理，会发生三个严重后果。

---

## 后果1：孤岛本身运行不正确

项目额定频率：

```text
50 Hz
```

如果孤岛长期：

```text
55 Hz
```

已经偏差：

\[
\frac{55-50}{50}=10\%
\]

这不是普通的小波动。

所以即使电压10 kV，也不能把这个孤岛称为正常运行状态。

---

## 后果2：S15不可能完成正常重同步

当前S15重同步要求：

```text
Δf ≤ 0.20 Hz
```

而主网仍然：

```text
≈50 Hz
```

如果孤岛真实：

```text
≈55 Hz
```

则：

\[
\Delta f\approx5\text{ Hz}
\]

远大于：

```text
0.20 Hz
```

因此：

```text
sync_ok
永远不会成立
```

最终：

```text
J1不能安全重合
```

所以不解决真实频率，就无法完成：

```text
ISLANDED
↓
RESYNCHRONIZATION
↓
RECLOSE
↓
GRID_CONNECTED_NORMAL
```

这条完整S15链。

---

## 后果3：S14黑启动也不能真正验收

黑启动最终也要求储能自己：

```text
建立电压
+
建立频率
```

如果GFM的频率源本身有问题，那么：

```text
S14虽然状态机能跑
```

也不能说：

> “真实黑启动功能已经完成。”

---

# 1.6 第二种可能：真实频率其实正常，但PCC测量链出了问题

还有另一种可能：

```text
ESS1真实Fout ≈ 50 Hz

但：
PCC PLL / frequency measurement
↓
发生异常或失锁
↓
最后撞到55 Hz Saturation上限
```

这种情况同样必须处理。

为什么？

因为BOARD15和S15以后读的不是“上帝视角真实频率”。

它们读的是：

```text
测量值
```

如果测量错：

```text
真实系统正常
但控制器以为频率55 Hz
```

那么S15仍然会判断：

```text
Δf很大
→ 不允许重合闸
```

也就是说：

> **真实物理正确，但控制器认知错误，系统仍然不能工作。**

这正好和我们第一篇论文研究的基本思想一致：

```text
Physical State
真实状态

≠

Controller Perceived State
控制器认知状态
```

所以无论55 Hz是真频率还是假测量，都不能直接跳过。

---

# 1.7 所以当前频率问题真正要查的不是“为什么是55这个数字”

而是区分下面三条信号：

```text
1. ESS1 GFM内部生成的频率
   Droop Fout / internal frequency

2. ESS1端实际三相电压的真实电气周期
   由Vabc周期反推

3. PCC PLL测出来的Freq_pcc
```

然后看：

### 情况A

```text
1 ≈55
2 ≈55
3 =55
```

说明：

> GFM真实频率跑偏。

---

### 情况B

```text
1 ≈50
2 ≈50
3 =55
```

说明：

> PCC PLL/测量链错。

---

### 情况C

```text
1 ≈50
2明显异常
3=55
```

说明还要继续查：

```text
GFM输出到Plant之间
或
PLL失锁
```

---

# 1.8 处理到什么程度就够了？

当前不要求立刻把GFM做到论文级高性能。

最低要求是：

```text
J1打开
↓
孤岛稳定以后
↓
真实频率能够维持在50 Hz附近
```

并且：

```text
PCC测频
≈
真实电气频率
≈
GFM内部Fout
```

三者不能明显互相矛盾。

达到这一步，频率尾项就可以基本关闭。

---

# 2. 第二个问题：为什么长期电压已经恢复10 kV，还必须看离网瞬态？

---

# 2.1 先解释“瞬态”到底是什么

“瞬态”不是另一个神秘算法。

它只是：

> **系统从一种运行状态切换到另一种运行状态时，短时间内发生的快速变化。**

当前项目：

```text
J1 CLOSED
并网
↓
60 s
J1 OPEN
↓
孤岛
```

60 s附近这一小段过程就是：

```text
离网瞬态
```

---

# 2.2 当前真正的好消息是什么？

边界修复以后：

```text
J1打开
↓
孤岛电压不再永久掉到低电压
↓
最终能够重新建立到约10 kV
```

这说明：

> 原来长期塌压的900 kW边界问题已经解决。

这是最重要的主结论。

---

# 2.3 但是当前切换瞬间仍然出现过很大的电压摆动

当前MAT记录里出现过大约：

```text
最低 ≈ 4.3 kV
最高 ≈ 14.7 kV
```

而额定：

```text
10 kV
```

也就是瞬间可能经历：

```text
0.43 pu
↓
1.47 pu
```

这样的范围。

所以当前现象不是：

```text
10 kV
→ 9.8 kV
→ 10 kV
```

这种很小的过渡。

而是明显的大幅度切换冲击。

---

# 2.4 为什么不能只看“最后又回到10 kV”？

因为工程系统不只关心最终值。

例如：

```text
一个人从10楼跳下来
最后又站起来
```

不能只看最后：

```text
“他站着”
```

还必须看中间过程有没有发生巨大冲击。

对电力系统也是一样。

---

# 2.5 瞬态过大会影响设备和保护

如果真实电压瞬间：

```text
4.3 kV
```

那是严重欠压。

如果瞬间：

```text
14.7 kV
```

那是明显过压。

真实设备可能存在：

- 欠压保护；
- 过压保护；
- 逆变器过流；
- 直流侧冲击；
- 变压器磁通过渡；
- 控制器饱和；
- PWM调制饱和。

所以：

```text
最终恢复正常
```

不代表：

```text
中间过程一定可接受
```

---

# 2.6 它还会误触发我们自己的高级策略

项目里本身就有：

```text
S5 孤岛判断
S8 低压/低频减载
S3 AVC
S15 重同步
```

如果离网瞬间电压从：

```text
0.43 pu
```

冲到：

```text
1.47 pu
```

这些策略都会看到非常激烈的异常测量。

于是有可能：

```text
一个正常的“计划离网”
```

被其他策略当成：

```text
新的故障
```

形成策略相互打架。

---

# 2.7 为什么现在不是立刻调PI，而是先量化瞬态？

这是非常重要的工程顺序。

现在我们还不知道：

```text
4.3~14.7 kV
```

到底持续：

```text
100 μs？
1 ms？
20 ms？
200 ms？
1 s？
```

这些情况意义完全不同。

---

## 如果只是极少数100 μs采样点

可能是：

- 切换瞬间数值离散效应；
- Stubline/Breaker一步延时；
- 测量算法短暂失真。

这种未必值得大改GFM。

---

## 如果持续几十毫秒

就可能是：

- GFL→GFM无扰切换不足；
- Droop相角状态没对齐；
- Voltage Regulator积分状态没对齐；
- 电流参考突变；
- 调制饱和。

这就值得优化。

---

## 如果持续几百毫秒甚至更久

那就不能再称为“小瞬态”。

而是：

> 实际并离网动态性能明显不合格。

---

# 2.8 为什么之前的GFL→GFM审计仍然有价值？

此前审计发现：

```text
Droop phase integrator
没有明显PLL状态跟踪

Voltage Regulator
没有明显GFL IdIq reference状态跟踪
```

这意味着当前模型存在一种结构风险：

```text
并网时：
GFL控制器在工作

离网时：
突然切到另一套GFM内部状态
```

如果两套控制器的：

- 相角；
- 电流参考；
- PI积分器状态

没有提前对齐，

就可能发生：

```text
切换一瞬间
控制器内部状态跳变
↓
电压/电流冲击
```

因此：

> 900 kW负荷解释的是“为什么以前长期塌压”。

而：

> GFL/GFM状态不对齐仍可能解释“为什么现在离网瞬间冲击很大”。

这两个结论不冲突。

---

# 2.9 为什么这个问题可以比频率稍微晚一点解决？

因为当前已经证明：

```text
孤岛最终能重新建压
```

所以它不是一个：

```text
“系统完全不能运行”
```

的问题。

它更接近：

```text
“运行质量够不够好”
```

因此当前优先级可以是：

```text
先查频率真实性
+
先修正离网后的错误PCC调节逻辑
↓
再定量看瞬态
↓
如果持续时间不可接受
再做无扰切换优化
```

而不是现在直接乱调PI。

---

# 2.10 瞬态问题最低处理标准是什么？

不一定要求：

```text
完全没有任何尖峰
```

最低应该做到：

```text
1. 知道最低电压
2. 知道最高电压
3. 知道异常持续时间
4. 知道发生在J1打开前还是后
5. 知道是不是测量假象
6. 判断是否会触发保护/策略
```

如果证明确实不可接受，再进入：

```text
GFL→GFM bumpless transfer
无扰切换
```

优化。

---

# 3. 第三个问题：不要再叫“P控制HOLD”

以后建议统一叫：

# **“离网后停止联络线功率调节”**

这样最容易理解。

---

# 3.1 先说什么叫“联络线功率调节”

我们现在正常并网时的AGC/S7做的是：

```text
给一个PCC目标

例如：
Ptarget = -100 kW
```

然后测：

```text
Ppcc
```

计算：

\[
dP=P_{\mathrm{target}}-P_{\mathrm{PCC}}
\]

再让：

```text
PV
ESS
EV
```

共同调整。

它的目的：

> **让整个微电网与上级电网之间的交换功率满足计划。**

所以本质名字应该叫：

```text
并网联络线功率控制
```

---

# 3.2 为什么并网时这个控制非常合理？

因为此时：

```text
微网
↕
PCC/J1
↕
上级电网
```

电气上真的连着。

例如：

```text
Ptarget = -100 kW
```

意思：

> 希望微电网从主网购100 kW。

这是一个真实存在的物理交换量。

---

# 3.3 J1一打开以后，这条“联络线”发生了什么？

答案：

```text
断了
```

也就是：

```text
微电网     ×     上级电网
```

两边已经没有有功功率交换通道。

理论上：

```text
PCC跨断路器真实有功交换
≈ 0
```

此时你再说：

```text
我要让PCC跟踪 -100 kW
```

已经没有物理意义。

因为：

> 没有那条线了，怎么从主网买100 kW？

---

# 3.4 所以为什么离网以后必须停止普通PCC AGC？

假设离网以后仍然保留：

```text
Ptarget = -100 kW
```

而实际：

```text
Ppcc ≈ 0
```

那么AGC会算：

\[
dP=-100-0=-100\text{ kW}
\]

然后它会认为：

> “系统还有100 kW误差，我要继续调PV/ESS/EV。”

但这个所谓“误差”根本不是控制误差。

它只是因为：

> **PCC已经断开。**

---

# 3.5 这就像什么？

可以把并网AGC理解成：

> 开车时用导航控制“我离前车保持100米”。

当前车还在前面时，这个目标合理。

但如果前车已经转弯离开，两个车根本不在同一条路上，

你还继续根据：

```text
“前车距离误差”
```

猛踩油门或刹车，

控制目标本身就已经失效。

孤岛以后继续做PCC联络线AGC就是类似问题。

---

# 3.6 离网以后系统真正应该控制什么？

并网时核心目标：

```text
PCC交换功率
```

离网以后核心目标应该切换为：

```text
岛内功率平衡
+
电压
+
频率
+
SOC/设备约束
```

也就是说控制目标发生了变化。

---

## 并网模式

```text
强网提供V/f
↓
我们主要控制P/Q交换
↓
PCC AGC有效
```

---

## 孤岛模式

```text
没有强网
↓
GFM负责建立V/f
↓
其他资源配合岛内功率平衡
↓
PCC目标不再有效
```

这就是为什么：

> 并网和孤岛不能共用完全相同的系统级P控制目标。

---

# 3.7 当前模型其实已经“知道”这个道理，但还没真正执行到底

当前LOCAL15 Mode Manager已经输出：

```text
AA15_MODE_ALLOW_NORMAL_P
```

它的含义就是：

```text
当前是否允许普通有功协调继续工作
```

并网时：

```text
=1
```

进入孤岛以后：

```text
=0
```

所以逻辑判断层已经明确说：

> **现在不要再运行普通PCC有功调节了。**

---

# 3.8 但当前真正的问题是什么？

这个：

```text
MODE_ALLOW_NORMAL_P = 0
```

目前主要被：

```text
记录
诊断
```

并没有真正接到：

```text
P Objective
↓
AGC
```

执行入口。

所以现在存在：

```text
模式层：
“应该停止普通P控制”

但P控制层：
“我没收到这个停止命令”
```

---

# 3.9 MAT已经证明离网前后AGC确实仍然继续调整

当前MAT里：

```text
55 s左右
ESS1进入GFM
```

以后，

AGC Candidate仍继续变化。

例如ESS1候选Pref继续发生：

```text
0.264
→ 0.230
→ 0.218
→ 0.246
→ 0.205
```

说明：

> 当前模式已经进入孤岛方向，但普通PCC有功协调器仍在运行。

所以这个不是理论猜测。

而是当前模型真实存在的执行语义缺口。

---

# 3.10 为什么这会影响孤岛频率和电压？

GFM建立孤岛以后，需要通过：

```text
有功平衡
↔
频率
```

自己维持系统。

这时如果旁边还有一个并网AGC不断根据：

```text
PCC目标误差
```

修改：

```text
ESS Pref
PV Pref
EV Pref
```

就可能和GFM自身的功率/频率动态发生冲突。

于是你看到频率异常时，很难判断：

```text
到底是GFM本身错
还是并网AGC还在乱调
```

所以为了正确排频率问题，也必须先明确：

> 孤岛期间普通联络线AGC到底是否退出。

---

# 3.11 为什么这对BOARD15尤其重要？

以后BOARD15在板端如果仍然：

```text
J1 OPEN
↓
PCC≈0
↓
Ptarget=-100
↓
AGC继续计算
↓
不停调整六资源
```

这不是一个“小Bug”。

而是：

> **运行模式定义错误。**

因为板端控制器没有理解：

```text
PCC已经不存在为一条有功交换通道
```

这种错误即使通信100%正常、C程序完全无bug，也会产生错误控制。

所以必须在BOARD15真正接板之前，把这个模式语义冻结清楚。

---

# 3.12 “停止联络线功率调节”是不是等于把六台设备Pref全部清零？

绝对不是。

这是最重要的区别之一。

离网以后：

```text
停止PCC AGC
```

不是：

```text
PV=0
ESS=0
EV=0
```

正确含义是：

> **停止继续根据PCC目标误差产生新的调节动作。**

已有设备仍然需要运行。

---

# 3.13 那离网瞬间Pref应该怎么办？

当前最保守、最容易理解的方法是：

```text
J1打开前
最后一组合法设备命令
↓
暂时保持
```

然后由孤岛运行逻辑逐步接管。

也就是：

```text
不要因为PCC突然变0
就让并网AGC立刻重新算一大堆资源命令
```

这才是之前“hold”这个英文真正想表达的意思。

翻成最直白中文：

> **“先别再根据PCC误差继续改设备功率。”**

---

# 3.14 为什么不能直接叫“冻结所有控制”？

因为不准确。

孤岛以后仍然要运行：

```text
GFM电压/频率控制
Droop
S8紧急减载
S14黑启动
S15恢复逻辑
必要的设备保护
```

停止的只是：

```text
普通并网PCC有功目标跟踪
```

不是整个控制系统。

所以以后我们统一叫：

# **离网后停止联络线功率调节**

比：

```text
P Control HOLD
```

清楚得多。

# 3.15 正确的模式切换应该是什么样？

## 并网

```text
↓

↓

↓
```


这才是完整逻辑。

# 4. 为什么三个问题之间其实是串联的，而不是独立三个Bug？

它们真实关系是：

```text
               J1打开
                  │
       ┌──────────┴──────────┐
       │                     │
       ▼                     ▼
控制模式改变             电气状态突然改变
       │                     │
       ▼                     ▼
PCC AGC应该退出          GFL → GFM
       │                     │
若没退出                 │
       │                     ▼
       └──────────────→ 功率/状态冲击
                             │
                    ┌────────┴────────┐
                    ▼                 ▼
                 电压瞬态          频率变化
```

所以三个问题不是毫无关系。

---

# 4.1 为什么“停止联络线功率调节”应该较早确认？

因为如果它没退出：

```text
你看到的频率异常
```

可能部分来自错误的资源功率继续变化。

你看到的：

```text
电压瞬态
```

也可能被额外P命令变化放大。

所以要先把控制语义搞正确。

---

# 4.2 为什么频率优先级也很高？

因为频率决定：

```text
GFM是否真正建立孤岛
+
S15能不能重同步
+
S14能不能黑启动
```

它是功能闭环必须项。

---

# 4.3 为什么瞬态可以最后定量处理？

因为：

```text
长期建压已经成功
```

所以我们已经知道：

> 系统不是完全构不起网。

剩下的问题是：

```text
切换质量有多差
需不需要进一步优化
```

因此合理顺序是：

```text
第一：
确认离网后普通PCC AGC真正退出

第二：
查清真实频率与测量频率

第三：
在上述逻辑正确以后重新量一次离网瞬态

第四：
如果冲击仍明显且持续时间不可接受
再做GFL→GFM无扰切换优化
```

而不是三个方向同时乱改。

---

# 5. 为什么这三个问题应该在BOARD15全面接板之前至少“定义清楚”？

因为BOARD15最终并不是只做一个：

```text
-100 kW AGC
```

它还要真正输出：

```text
Pref
Qref
GridOn
Droop
Breaker
Fref
Mode
```

也就是说：

> 板端以后会直接控制当前这套并离网Plant。

如果Plant和模式逻辑里还有：

```text
离网频率真假不明
+
切换冲击量级不明
+
离网以后并网AGC仍继续运行
```

那么接Board后出现异常，我们就无法分辨：

```text
是Board程序错
还是Plant本来就错
```

这会重新把故障边界扩大。

所以现在处理这三个尾项的真正价值是：

> **先把模型本身变成一个可信的BOARD15测试对象。**

# 7. 三个问题分别“不处理”的最终后果

| 问题 | 不处理会怎样 |
|---|---|
| 离网频率 | 无法证明GFM真正稳定；S14不能完整验收；S15 Δf无法可信；重合闸可能永远不允许或错误允许 |
| 离网瞬态 | 不知道并离网切换是否会产生严重欠压/过压、过流、保护误动；无法判断切换质量 |
| 离网后继续PCC功率调节 | 控制目标本身失去物理意义；AGC会把“J1断开造成PCC=0”误当成有功误差继续改六资源，可能干扰孤岛V/f |

# 8. 最通俗的三句话

如果以后老师或面试官问：

> 为什么现在还要修这三个？

可以直接说：

### 频率

> **因为离网后主网已经不提供50 Hz，ESS构网以后必须自己把频率建立正确；现在看到的55 Hz还分不清是真实频率跑偏还是测量链失真，而这直接决定黑启动和重新并网能不能成立。**

### 瞬态

> **因为现在解决的是“长期不再塌压”，不代表切换瞬间已经正常。J1打开时电压还出现过很大的上下冲击，所以必须先知道它持续多久、是不是实际电气冲击，再决定要不要做GFL到GFM的无扰切换优化。**

### 离网后停止联络线功率调节

> **因为J1打开以后微网已经和主网断开，原来的PCC购电/送电目标就不存在了。此时如果AGC还拿Ptarget−Ppcc继续调六台设备，相当于在追一个已经没有物理意义的目标，所以离网后必须暂停普通PCC功率调节，等重新并网后再恢复。**

# 9. 最终建议的处理顺序

当前不要同时修改很多东西。

最稳的顺序：

```text
Step 1
先确认并实现：
J1打开/进入孤岛
→ 普通PCC联络线AGC停止继续更新

Step 2
只读观察：
ESS1 Droop Fout
PCC原始PLL频率
PCC三相电压真实周期
→ 判断55 Hz到底是谁的问题

Step 3
重新跑一次相同离网工况
→ 定量截取J1打开前后约100~500 ms
→ 看V、f、Pref、Pmeas、GridOn

Step 4
如果大电压瞬态仍持续几十毫秒以上
→ 再做GFL→GFM状态对齐/无扰切换

Step 5
重新验：
真实孤岛
→ S15重同步
→ J1重合
→ GFM→GFL
→ NORMAL

Step 6
最后重新做S14黑启动
```

这样每一步只有一个主要变量，不会重新陷入“大范围猜根因”。
