# 1. 现在究竟是什么情况？

当前问题已经不像之前那么模糊了。

我们现在已经知道下面这条链是真实存在的：

```text
J1打开
↓
强网退出
↓
孤岛自身约527 Hz电气自然模态被激发
↓
abc三相真实振荡逐渐发展到约530～535 Hz
↓
进入50 Hz同步dq后表现为约480～485 Hz
↓
正式500 Hz二阶测量滤波
在这个模态上实测：
幅值约0.516
相位约-88°
↓
Voltage / Current快速控制闭环
↓
10～20 ms内迅速进入限幅/饱和
↓
ModIndex / Vpwm也携带同一快速模态
↓
Converter继续把这个快速控制动作施加到Plant
↓
LC/网络模态继续得到反馈
↓
六台变流器共同参与公共模态
↓
最终形成持续0.53 kHz振荡
```

---

# 2. 所以根因不是“500 Hz滤波器坏了”

这一点必须准确。

500 Hz滤波器本身：

```text
没有实现错误
```

它是按设计正常工作的。

问题在于：

```text
系统真正需要控制的异常dq模态
≈ 480～485 Hz
```

而：

```text
滤波器Fo
= 500 Hz
```

所以它正好处于该滤波器相位变化最大的区域。

D1已经直接测到：

```text
约-88°相位滞后
```

这等于：

> 控制器看到这个快速电气模态时，反馈已经“晚了接近四分之一个周期”。

再叠加：

```text
离散控制
任务交互
PI动态
PWM
```

就非常容易导致：

```text
相位裕度不足
↓
阻尼不足
```

---

# 3. 为什么Voltage Regulator饱和也很关键？

D1证明：

```text
J1开以后约10～18 ms
```

就开始出现：

```text
Iq_ref限幅
Vd_conv限幅
Id_ref限幅
ModIndex=1
Vq_conv限幅
```

而后期：

```text
Id_ref约94%时间处于限幅附近
```

这说明：

> **原本可能是一个“低阻尼快速模态”，很快被推入了非线性限幅区。**

一旦进入这里：

```text
控制器不能再线性地小幅修正
```

而是在：

```text
不断打满
不断反向
```

于是振荡更难自己衰减。

---

# 4. PWM是不是根因？

现在优先级已经明显下降。

因为D1直接证明：

```text
PWM之前的Vpwm_ab
```

本身已经含有强约533 Hz分量。

所以不是：

```text
控制参考健康
↓
PWM自己凭空造出530 Hz
```

而是：

```text
控制器输出已经带着快速模态
↓
PWM只是执行
```

PWM和100 μs离散实现仍可能影响最终相位，但不再是第一主因。

---

# 5. Droop是不是根因？

基本可以排除快速源。

D1后期：

```text
Fout ≈49.22 Hz
其484 Hz分量极小

Vout ≈0.959 pu
其484 Hz分量也极小
```

所以：

```text
Droop没有在命令530 Hz
```

问题主要发生在：

```text
Droop之后
↓
Measurement
↓
Voltage Loop
↓
Current Loop
↓
PWM
↓
Plant
```

# 6. 六台设备都参与意味着什么？

D1显示六台支路：

```text
PV1
PV2
ESS1
ESS2
EV1
EV2
```

在约530 Hz都具有：

```text
很高相干度
≈0.997～0.999
```

并形成两组近反相模态电流：

```text
PV1 / PV2 / ESS2
        ↔
ESS1 / EV1 / EV2
```

这说明：

# **现在是整个孤岛内部的系统模态。**

不是：

```text
ESS1某个测点局部振
```

但ESS1仍然是修复的首要控制对象，因为：

```text
它是唯一GFM
它负责建立孤岛电压
它的Voltage/Current Loop决定孤岛快速电压控制
```

# 7. 所以我们到底能不能妥善解决？

### **大概率可以。**

原因不是“我觉得能调好”，而是现在已经具备三个很重要条件。

---

## 7.1 模态已经稳定识别出来

不是随机故障。

我们已经知道：

```text
理论 ≈527 Hz
实测abc ≈530～535 Hz
dq ≈480～485 Hz
```

它有非常清楚的频率结构。

---

## 7.2 主要相位损失已经测出来

500 Hz正式反馈链：

```text
约0.516增益
约-88°相位
```

这是一个非常具体、可以工程处理的问题。

---

## 7.3 控制器可修改的位置已经确定

可以动的高价值杠杆：

```text
V/I measurement filter
Voltage-loop bandwidth
Current-loop bandwidth
Active damping
反馈时序
```

都位于我们可以明确修改的位置。

所以现在不是：

```text
不知道该改哪里
```

而是：

```text
知道需要恢复这个模态的相位裕度和正阻尼
```

# 8. “一次性解决”到底能做到什么程度？

要分两种“一次”。

## 一次Build

### **这个目标很现实。**

我们完全可以把下一份F1设计成：

# **一个可切换、可调的修复实验平台。**

一次Rebuild以后，通过不同Mode和Gain，在同一个模型里测试多种修复方案。

---

## 一组参数第一次就完美

### **不能承诺。**

因为最终最优参数仍然需要通过：

```text
模态衰减速度
50 Hz动态
电流峰值
ModIndex裕度
多机稳定性
```

综合选择。

所以我们的目标应该是：

> **一次Build把“修复手段”全部装进模型，然后通过多轮无需Build的运行把参数找到。**

这才是真正高效率。

---

# 9. F1不应该只做一个简单“加阻尼块”

为了最大概率一次Build解决，建议F1同时预留三层修复能力。

---

# 10. F1第一层：测量滤波器修复

D1最直接的证据就是：

```text
500 Hz V/I filter
在480～485 Hz处
≈ -88°
```

所以F1必须允许测试：

```text
原500 Hz
+
较高截止频率候选
```

但不要直接删除低通。

---

# 11. 为什么不能简单取消500 Hz低通？

因为它还负责抑制：

```text
高频开关纹波
测量噪声
```

如果直接旁路：

```text
4 kHz相关成分
```

可能大量进入Voltage/Current Loop。

所以正确方向是：

# **把控制模态和滤波器动态区域拉开，而不是彻底取消滤波。**

---

# 12. F1建议一次Build内准备多个固定滤波候选

最稳妥的方法不是依赖：

```text
运行时直接修改库块Fo
```

因为目前还没有证明RT-LAB Execute阶段这个Mask参数一定可调。

更稳的是一次Build就准备：

```text
FILTER_MODE = 0
原500 Hz

FILTER_MODE = 1
约800 Hz

FILTER_MODE = 2
约1000 Hz
```

然后用：

```text
Multiport Switch / Switch
```

在线选择。

这样：

```text
不需要每换一个滤波频率就Build
```

---

# 13. 为什么优先800 / 1000 Hz量级？

不是说这两个就是最终答案。

是因为对约484 Hz dq模态：

```text
500 Hz滤波：
相位约-88°
```

把Fo提高以后：

```text
800 Hz
相位滞后会明显减小

1000 Hz
会进一步减小
```

与此同时又没有直接把截止频率提到：

```text
接近4 kHz PWM
```

所以它们适合作为第一轮工程敏感性候选。

最终参数仍由实测决定。

---

# 14. F1第二层：Voltage Loop / Current Loop参数可调

D1显示：

```text
Voltage Regulator输出很快撞限
```

所以F1还应该保留：

```text
Kp_Vreg
Ki_Vreg

Kp_Ireg
Ki_Ireg
```

的可调能力。

如果现有变量可以运行时修改：

```text
直接使用Variables Table
```

如果不能：

```text
F1中准备少量固定参数组
+
模式选择
```

也可以做到一次Build。

---

# 15. 为什么Voltage Loop比Droop更值得优先调？

因为D1显示：

```text
Vout基本没有快速模态
```

但是：

```text
Id_ref很快大量限幅
```

所以真正快速增益问题发生在：

```text
Vout/Vdq
↓
Voltage Regulator
↓
IdIq_ref
```

这一层。

---

# 16. F1第三层：主动阻尼

即使把滤波相位改善，

LC/网络仍然存在：

```text
约527 Hz自然模态
```

因此为了提高最终鲁棒性，F1最好同时预留：

```text
AD_ENABLE
K_AD
```

即：

```text
主动阻尼开关
主动阻尼增益
```

---

# 17. 为什么主动阻尼仍值得放进同一个F1？

因为有两种可能。

## 情况A

只改变滤波：

```text
530 Hz已经快速衰减
```

那么：

```text
AD_ENABLE = 0
```

最终可以不用主动阻尼。

---

## 情况B

改滤波后：

```text
模态明显改善
但仍然衰减太慢
```

那么直接：

```text
AD_ENABLE = 1
```

继续调K_AD。

不需要第二次Build。

---

# 18. 主动阻尼具体加在哪里不能现在随便接

这是F1前唯一还需要认真设计的地方。

一个高质量主动阻尼不能只是：

```text
随便拿一个530 Hz信号乘Gain
```

必须：

```text
有明确物理含义
单位正确
符号正确
插入点正确
```

最经典候选之一是：

```text
电容电流反馈
```

形成虚拟阻尼。

---

# 19. 为什么现在还没有直接给K_AD？

因为当前：

```text
inv Iabc
Ipu = off

LCout Iabc
Ipu = on
```

它们量纲不一致。

所以不能直接：

```text
iC = inv_I - LCout_I
```

否则主动阻尼信号就是错的。

---

# 20. F1前只需要做一个“零Build静态校准”

不是新的动态诊断Build。

只需要精确锁定：

```text
inv电流单位
LCout电流pu基准
方向

变压器/Stubline接口对应比例

如何把二者统一成同一个pu基准
```

然后才能构造：

```text
iC
```

这一步：

```text
只读模型/参数
Build = 0
```

---

# 21. 如果电容电流主动阻尼实现太复杂怎么办？

F1不必被它卡住。

可以先把F1主体设计成：

```text
Filter Mode
+
Voltage/Current gain tuning
+
AD接口预留
```

如果电流量纲校准能够确定：

```text
把capacitor-current AD一起装进去
```

如果当前模型量纲路径存在不确定：

```text
先用滤波/环路修复
```

也完全可能已经解决主要问题。

---

# 22. F1最重要的是必须“可退回原模型”

所有修复都应该带：

```text

```

使模型数学上退化回当前D1前控制行为。

例如：

```text

→ 500 Hz原始滤波

AD_ENABLE = 0
→ 无主动阻尼

PI_MODE = 0
→ 原始PI参数
```

这样一次Build就可以：

```text

和

```

在同一模型中公平比较。

# 29. 但必须诚实保留一个不确定性

```text

```

所以可能出现：

```text

```

```text

```

这时才需要进一步针对GFL。

不过：

> **D1已经证明六台没有“一台绝对独占”模态，因此优先从ESS1 GFM公共电压形成环修复，是合理且信息增益最高的第一步。**

# 36. 最终一句话

> **另一个Group28 MAT现在不需要上传。当前问题已经足够明确：J1打开后约527 Hz电气模态被激发，500 Hz正式V/I测量滤波在对应约484 Hz dq模态上实测产生约−88°相位滞后，GFM Voltage/Current Loop随即进入强限幅并把同一模态送到PWM前，同时六台变流器共同参与公共模态。我们大概率能够妥善解决；最合理的方式不是赌一个阻尼参数，而是先用零Build审计把F1插入点和主动阻尼量纲锁死，然后只做一个F1修复Build，把原500 Hz、800/1000 Hz候选滤波、PI参数模式和可开关主动阻尼一起装进模型，通过无需Build的多轮短工况找到最终稳定组合。这样“一个Build解决整个修复阶段”的目标是现实的，但不能承诺第一组参数就一定是最终最优值。**
