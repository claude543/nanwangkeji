# 储能2真实任务、健康判断、状态编号与本次联合审计

日期：2026年9月17日。

**原来的−0.005标幺任务本来就是真实任务，本次不换目标，也不提高功率。健康判断与接管可以放在同一轮设计、同一份受控改模中完成；验证时仍分为本地合格、同功率交接、有限调节，避免一处失败后无法区分原因。现在交付的是覆盖这些环节的只读审计，不是已经修改后的模型。**

## 1. 之前的小功率是否是真正的外部任务？

是。这里“外部”只是相对于储能2本地控制器而言：策略14在本地功率控制器之外给出任务，经现有命令路径进入本地控制器。它不意味着这轮必须换成外部控制板、另一个控制器或新的功率值。

本次仍然是：

$$P_{\mathrm{task}}=-0.005\text{ 标幺。}$$

按当前使用的100千瓦基准，对应吸收约500瓦。已有积分增益0.5的小功率结果就是对这项任务的真实试验。补充交接记录给出的结果文件编号为564047446，固定平台约33.54秒，末10秒平均实测有功约−0.004982659标幺。[R1]

此前我说“要核对真正收到的外部任务”，指的是**程序拿哪个量来判断成功**，不是质疑旧试验任务不真实。

当前要区分三个量：

| 量 | 意思 |
|---|---|
| `PrefApplied`（本地实际收到的有功任务） | 上层最终要求储能2完成多少功率。 |
| `PrefEff`（本地内部有效有功参考） | 本地根据执行能力等处理后交给功率控制器的参考。 |
| `Pmeas`（实测有功） | 设备实际吸收或发出的功率。 |

自动判定任务完成，必须确认实际收到的任务已经达到本次目标，并且实测功率与这项任务足够接近。不能只检查实测功率与内部有效参考接近。[R2]

**说明性例子，不是本次试验数据：**上层要求吸收500瓦，本地由于限额只允许100瓦，实际也只有100瓦。设备跟上了内部100瓦参考，但没有完成上层500瓦任务。旧判据如果只看内部参考，就可能把两件事混为一谈。

因此，本次任务不变；需要改进的是完成判断。

## 2. 这是不是之前说的健康门控？既然成功了，为什么还要验证？

是，就是健康门控加任务完成判断，没有新的神秘概念。

需要区别：

**波形已经显示设备能够完成任务。**

**模型里的自动判断程序是否能正确识别成功，并在未成功、数据无效或超时时不错误放行。**

前者已经有证据。后者不能只从成功波形推出，原因在当前源码中已经可见：诊断分支按时间推进，状态6中把功率资格和严重异常留作记录，不要求资格成立后进入状态7；原自动分支的功率资格又主要比较内部有效参考。[R2]

因此不需要再重复证明旧控制器能不能吸收500瓦，但需要验证改后的自动状态逻辑。主要检查成功、未完成、资格反复失效、超时、数据失效和交接中失去资格这些分支。能用已保存数据或独立控制逻辑测试回答的，不重复运行电气试验。

### 本次范围调整

按用户本轮要求，**不把设计和改模机械限制在接管之前**。本次审计将健康判断、接管和接管后涉及的模块一起读取，为联合改模准备证据。

建议之后的一份受控改模可同时实现：

1. 正确的本地任务完成和健康判断；
2. 本地合格后可保持，也可按预先配置继续接管；
3. 接管前两路命令匹配、交接平滑、接管后观察；
4. 一次协调与二次恢复不因为接管完成而自动同时投入；
5. 明确的失败、保持与返回路径。

**一次设计/修改不等于一次试验全部开放。**正式运行前确定本轮要观察到哪一步，运行后不靠临时改参改变对照条件。这样不必为每个停点重新改模和构建。

上述是待审计结果支撑的设计安排，不表示本包已经实现这些功能。

## 3. 储能1和储能2现在的有功、无功责任

可以简单理解为：**储能1建立并维持母线电压、频率，承担当前系统供电及无功支撑责任；储能2目前已经验证按要求执行小有功任务，暂不额外恢复其旧无功功率外环。**[R1、R2]

但不要把它理解成储能1刚刚同时打开了与储能2相同的两个功率跟踪外环。储能1当前采用构网控制：它形成电压和频率，实际有功、无功随系统负荷、控制和网络状态变化。

储能2旧无功外环暂不重新取得控制权，也不等于它没有真实无功或电流控制。当前还有基础无功电流保持，真实电流反馈仍然存在。[R2]

本轮保持已经成功的控制条件，同时审计电压、无功、电流和储能1余量的测量与记录位置。是否增加储能2电压/无功分担，在对应功能投入前单独核定，不能从500瓦小有功试验推断全部无功能力已经通过。

## 4. 状态6、7和步骤40、50、60、70到底是什么？

**有两套编号，不是同一个状态机从6一直数到70。**

| 所属程序 | 编号 | 普通含义 | 目前证据边界 |
|---|---|---|---|
| 储能2本地恢复执行器 | 6 | 电流执行已放行，正在承担功率或接受诊断观察；还不能只凭编号宣布任务合格。 | 诊断试验主要停留在这里观察波形。 |
| 储能2本地恢复执行器 | 7 | 本地程序判定恢复任务和健康条件已持续满足。 | 自动分支有这一步，但其判断需要本次审计与完善。 |
| 策略14上层流程 | 40 | 给储能2小功率任务，等待本地恢复资格。 | 与诊断同号步骤的具体行为不能混用。 |
| 策略14上层流程 | 50 | 将有功命令来源从策略14平滑交给正常协调器。 | 结构已存在，新参数下完整交接尚未实测。 |
| 策略14上层流程 | 60 | 正常协调器已接手，开始允许受限的一次有功协调。 | 不是完整功率范围已经恢复。 |
| 策略14上层流程 | 70 | 之前规划的后续慢速频率/电压恢复步骤。 | 当前正式状态链尚未实现，不能当成现成步骤。 |

对应关系是：

**上层40要求设备完成小功率 → 本地6执行 → 本地7报告合格 → 上层50交接命令来源 → 上层60允许有限调节。**

上层是否进入70，是更后面的实现与验证，不是这轮打开现有参数就自动完成。[R2、R3]

所谓“少量调节”就是原来的“小权限一次协调”。接管只换命令来源，有限调节才允许新命令来源改变功率；两者不是同一件事。

## 5. 本次审计为什么覆盖接管之后？

因为即使本轮先验证接管，也必须知道接管后哪些功能会自动投入、哪些旧命令会恢复、哪些设备会被判为可用。只看混合系数那一块不够。

本次脚本读取健康门控、上层状态、命令混合、协调器、独立电压恢复、储能1测量、无功控制权、诊断总开关和记录器之间的连接。具体要回答：

| 问题 | 审计后的设计用途 |
|---|---|
| 真正任务与内部参考在哪里？ | 避免错误判断恢复完成。 |
| 合格、失效、超时怎么推进？ | 防止未完成就接管，也防止合格保持时误超时。 |
| 总诊断开关同时控制什么？ | 防止关闭诊断时同时恢复支撑、改变本地阶段和投入一次协调。 |
| 协调器如何获得并保持当前功率基准？ | 使接管前后的任务匹配。 |
| 混合系数如何变化和返回？ | 使交接、暂停、失败退出可解释。 |
| 一次有功与独立电压恢复由什么使能？ | 防止只关一个二次开关却放开另一条慢控制。 |
| 未接入资源是否被排除？ | 防止把任务分给仍断开的设备。 |
| 正常调度目标如何进入？ | 避免以为仅扩大权限就恢复了正常任务。 |
| 储能1能力数据在哪里？ | 约束之后允许的调节幅度，而不是仅按额定功率猜。 |
| 记录器能看到哪些判断和命令？ | 确保下一轮失败时仍有原因、状态和执行证据。 |

读到不确定、歧义、库内部不可见或未取得维度的地方，脚本会明确列出。**不承诺一次静态审计能证明所有动态条件都没有遗漏。**

## 6. 脚本使用与本轮交付边界

本轮提供的是：

- `AUDIT_K26_K50_ESS2_RESTORE_HANDOVER_R1.m`（健康判断与接管全关联只读审计脚本）；
- `ESS2_RESTORE_HANDOVER_SCOPE_R1.json`（配套范围和静态结构核对表）；
- 使用说明和静态检查记录。

完整解压后，在已打开并保存的源模型环境运行：

```matlab
result = AUDIT_K26_K50_ESS2_RESTORE_HANDOVER_R1;
```

`result`（审计结果）中包含输出路径。脚本自动生成结果压缩包，默认放在系统临时目录的独立审计文件夹。只需上传该结果压缩包。

它不会重新选择版本、不会改动功率目标、不会新增控制开关、不会运行电气试验、不会修改或保存模型。源模型哈希仅记录出处。

成功经验依据为用户脚本包中的四份审计，特别是后期本地补充第三版的：已加载模型读取、原生标签解析、保持未知项、输出完整证据及只读检查。原始函数和标量参数以本地实际读取为准，不沿用旧的模块顺序猜测。

当前环境无 MATLAB（矩阵计算与仿真软件），本脚本未在该软件中执行。已经完成的只是文件配套、静态关键路径和连线端点、禁止写模型调用、局部函数名及分隔符检查，不能代替本地运行验证。
