# 13. 新窗口脚本编写永久规则

1. 每个gate必须写清“这个信号在这个状态是否有定义”。
2. 不再为“保险”随手加一个新gate；新增gate必须来自模型状态机合同。
3. `stable`必须至少包含：
   - command frozen，或
   - command derivative明确接近0。
4. `capture point`和`steady state`必须分词。
5. J1边沿永远：
   ```text
   last physical CLOSED
   vs
   first physical OPEN
   ```
6. Host低速值不定义dq工作点。
7. 新Build先解析参数/signal contract，再Execute。
8. Build-specific ID不能沿用旧Build想当然。
9. 任何Python PASS文案必须由实际readback生成，不要留下硬编码旧描述。
   - V25A5日志里曾出现F23参数已0、但旧PASS文字仍写“ENABLE/ARM=1”的文案残留；
   - 这是日志文字缺陷，不是模型状态，但以后必须消除。
10. FAIL首先判断：
    ```text
    脚本合同失败？
    模型控制失败？
    物理失稳？
    ```
11. 不因为想拿MAT而无条件拖着非有限状态运行。
12. 但普通低电压/有限振荡可以继续到logger完整block，像V25A5一样保留全过程。
13. Overrun必须=0才冻结物理结论。
14. 不在一个脚本同时改变：
    - GFL拓扑；
    - F20；
    - PI；
    - F24；
    - P/Q策略。
15. 任何“以前做过”的实验若要重做，必须在脚本/方案开头写：
    ```text
    旧试验为什么不具当前判别力
    当前相比旧试验新增了哪些已关闭干扰
    ```

## 9.1 V12B.1单主动ESS1测试：Host PASS后来不能作为物理PASS

五台active GFL物理隔离，ESS1独立带被动岛网。

早期Host状态曾显示：

```text
P/Q≈0
f≈50Hz
J1 OPEN
```

并打印过：

```text
V12B.1 ESS1单主动自然带电切岛 PASS
```

**这个Host PASS后来不能继续当作物理PASS。**

原因：

- 当时Host判据偏重mode / J1 / PLL frequency；
- 真正决定10 kV岛网是否建立的Group29物理电压没有被同等优先使用；
- 后续重新看Group29后，单主动ESS1的带电live-transfer也出现过明显的真实电压跌落，甚至可到约1.1~1.3 kV量级；
- 因而不能用V12B.1证明“只要去掉五GFL，带电切岛就天然稳定”。

这里必须与Gate A严格区分：

```text
Gate A:
J1从第一步OPEN
dead bus自主建压
Supervisor F/V旁路
→ 已证明ESS1具备自主构网能力

V12B.1:
强网带电状态 → J1 OPEN
→ 属于live handover
→ Host旧PASS不能代表真实物理PASS
```

最新含义：

> 五GFL不是“ESS1自主构网能力”的必要条件；但Reference/State handover问题可以在没有五GFL主动功率交互时仍出现。完整六机下五GFL又会成为可能的持续/放大机制。

这也是为什么V20D后根因排序变成：

```text
第一层：Reference Handover trigger
第二层：five-GFL aggregate dynamic amplification
```



```text

Release后失稳
```

才有资格说：
