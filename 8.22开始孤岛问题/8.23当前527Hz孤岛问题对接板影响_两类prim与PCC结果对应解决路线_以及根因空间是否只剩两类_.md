# 暑期南网科技项目｜当前527 Hz孤岛问题对后续接板的影响、两类 `prim_ESS1 Vabc / PCC Vabc` 结果对应解决路线，以及根因空间是否只剩两类

> 日期：2026-08-23  
> 当前阶段：**继续分析和规划，不立即修改模型、不立即跑新试验。**  
> 当前最高可信事实：
>
> - 正常并网阶段，PCC三相电压和50 Hz基波基本健康；
> - J1真实打开以后，PCC原始三相电压出现持续快速振荡；
> - 当前理论电气模态约527.4 Hz，与上一轮PCC原始Vabc中约531 Hz的表观主快速分量高度接近；
> - 当前ESS1 GFM测量反馈、数字时序、LC/Transformer/Stubline和五台GFL均仍属于可能参与该模态阻尼的环节；
> - `PCC raw Vabc` 与 `prim_ESS1 Vabc` 是两个独立物理测点，当前还没有完成两者同工况比较。
>
> 本文把“接板会不会受影响”“如果prim坏怎么办”“如果prim健康怎么办”“是不是只剩两个原因”一次回答清楚。

# 0. 先给四个问题的结论

## 问题1：这个问题对后续接板有没有重大影响？

### 结论

> **对“正常并网BOARD15通信/AGC接管”不是立即阻塞项；但对“真实离网、孤岛、黑启动、重同步、最终CHIL”是重大阻塞项，而且如果不解决，会在每一次真实J1打开后重复出现。**

原因很简单：

```text
BOARD15
只是把：
GridOn / Fref / Pref / Qref / Breaker / mode
等命令送给Plant

它不会自动改变：
L1
C1
Transformer
Stubline
Measurement filter
Current/Voltage regulator
Plant网络阻抗
```

所以如果当前527 Hz级模态是Plant/GFM闭环固有稳定性问题：

```text
LOCAL15触发真实孤岛
→ 会出现

以后BOARD15触发同样真实孤岛
→ 仍然会出现
```

控制源换成Board并不会自动把这个问题消失。

---

## 问题2：如果 `prim_ESS1 Vabc` 本身也有强527~531 Hz，怎么解决？

结论：

> **这会把问题优先收敛到“ESS1源端相关链”，但仍不能直接说某一个PI有bug。解决路线应继续把ESS1源端拆成：控制指令 → 内环 → PWM → L1/C1 → Stubline/Transformer反馈时序，找出谁在给约527 Hz模态提供负阻尼或不足阻尼。**

可能的最终修复类型包括：

```text
主动阻尼 / 虚拟阻抗
测量滤波重新设计
缩短GFM快速反馈路径
Current/Voltage loop重新整定
Lff与实际Plant参数统一
GFL→GFM状态对齐
限幅/调制裕度处理
```

但必须由下一层证据选择，不能全部一起改。

---

## 问题3：如果 `prim_ESS1` 很健康、PCC才出现强531 Hz，怎么解决？

结论：

> **这会明显降低“ESS1单机内部失稳”的优先级，重点转向公共网络和其余五台GFL的多变流器交互。**

解决路线变成：

```text
ESS1源端保持不动
↓
逐组隔离/恢复其它GFL资源
↓
找到哪一组接入以后527 Hz模态阻尼明显恶化
↓
再审计该组PLL / Current Loop / Network impedance
↓
做弱网适配、虚拟阻抗、PLL/电流环整定等
```

---

## 问题4：现在是不是只剩这两个原因？

### 不是。

`prim_ESS1是否也振荡` 是一个：

# **诊断分水岭**

而不是两个最终根因。

真正根因至少还有四大类：

```text
A. ESS1控制/功率级内部
B. SS↔SM分核快速反馈时序
C. ESS1与其它5台GFL/公共网络交互
D. 参数/离散实现不匹配
```

并且还可能出现第三种结果：

```text
prim_ESS1有小振荡
PCC把它显著放大
```

这代表：

```text
ESS1提供初始激励
+
公共网络/其它GFL继续放大
```

是典型的“混合根因”。

# 15. 第一个内部判别：Droop是否只是“慢变量”

当前静态审计已经确认：

```text
Frequency_Droop = 1%
Fnom = 50 Hz
```

正常Pmeas范围下理论Fout只是：

```text
约49.6~50.8 Hz
```

所以如果prim有527 Hz：

```text
普通Droop本身
```

很难合理地作为527 Hz命令源。

因此Droop更可能是：

```text
被电气振荡污染
```

而不是：

```text
主动生成527 Hz
```

除非以后数据发现Fout/theta本身异常。

# 19. 如果最终确认“527 Hz LC模态 + 阻尼不足”，怎么修？

这时典型修复不是：

```text
加一个PCC低通滤波器
```

而是直接增加该模态的：

# **positive damping（正阻尼）**

可能的技术方案：

```text
Active Damping
主动阻尼

Capacitor-current feedback
电容电流反馈

Virtual Resistance
虚拟电阻

Virtual Impedance
虚拟阻抗
```

本质：

```text
看到LC开始振
↓
控制器产生一个反向阻尼作用
↓
让振荡能量逐周期消耗
```

# 20. 如果根因是500 Hz测量滤波带来的相位问题，怎么修？

当前真正敏感的是：

```text
fn_Filter = 500 Hz
```

而理论模态：

```text
≈527 Hz
```

两者靠得太近。

修复方向可能是：

```text
重新设计测量滤波频率
重新设计滤波阶数/阻尼
重新匹配Current/Voltage Loop带宽
```

但不是简单：

```text

```

因为：

```text

相位更小
但PWM纹波进入更多

降低滤波频率：
滤波更强
但相位更差
```

所以必须连同：

```text
Fsw
Ts
Current bandwidth
Voltage bandwidth
LC resonance
```

统一重整定。

```text

```

即：

# **快速内环本地闭合，慢速监督量允许跨任务。**

这是合理的实时控制架构优化。

```text
网络接口参数修正
```

如果是多台共同作用，

可能需要：

```text

```

而不是改单台ESS。

# 43. 当前最重要的认识

这个问题不能被理解成：

```text
“我们现在先不管，
接上板以后Board可能会控制得更好。”
```

因为：

```text
Board控制周期
≈监督/协调层

527 Hz
≈2 ms周期量级的快速电气模态
```

这是两个完全不同时间尺度。

Board不适合、更不可能用100 ms级协调周期直接去“压527 Hz”。

真正负责压制这种模态的应该是：

```text
本地逆变器快速控制
+
Plant物理阻尼
```

---

# 44. 为什么Board不能解决527 Hz？

527 Hz周期约：

\[
T \approx \frac1{527}
\approx 1.90\ ms
\]

而Board未来协调周期大致：

```text
约100 ms
```

100 ms里：

```text
527 Hz模态已经振了约52~53个周期
```

所以BOARD15应该做：

```text
模式
资源协调
慢速恢复
```

而不是：

```text
电力电子快速阻尼
```

这是控制层级分工决定的。

Board最多做：

而不是负责消除这个模态。
