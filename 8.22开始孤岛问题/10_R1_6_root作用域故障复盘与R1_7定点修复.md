# R1.6 `root` 作用域故障复盘与 R1.7 定点修复
## 2026-09-20

## 1. R1.6为什么在Scratch阶段失败

R1.6执行到：

```matlab
addPV1ControlRestore(PV1,GFL,PWR,M);
```

进入本地函数：

```matlab
function addPV1ControlRestore(PV1,GFL,PWR,M)
```

以后，又调用：

```matlab
upgradePV1CurrentAdapter(adapter,root);
```

但是`root`既不是该本地函数的输入参数，也没有在该函数内部定义。

MATLAB的同文件local function（本地函数）不会自动继承主函数工作区变量，因此报：

```text
函数或变量 'root' 无法识别
```

这次失败发生在byte-identical scratch（字节一致副本）阶段，正式模型尚未写入，因此用户正式SLX保持不变。

## 2. 为什么这违反了已有成功经验

ESS2成功脚本的明确范式是：

> helper（辅助函数）需要packageDir/root（包目录）时，必须显式作为参数传入；不能依赖调用者工作区。

例如成功脚本`PATCH_E2_HEALTH_HANDOVER_R2_2.m`中，`packageDir`由正式入口得到，并显式传给需要读取payload（控制源码）的辅助函数。

R1.6在这个点偏离了成功范式。

## 3. R1.7怎么修

R1.7只做最小、确定的作用域修复：

```matlab
% R1.6
addPV1ControlRestore(PV1,GFL,PWR,M);

function addPV1ControlRestore(PV1,GFL,PWR,M)
    ...
    upgradePV1CurrentAdapter(adapter,root);
end
```

改为：

```matlab
% R1.7
addPV1ControlRestore(PV1,GFL,PWR,root);

function addPV1ControlRestore(PV1,GFL,PWR,root)
    ...
    upgradePV1CurrentAdapter(adapter,root);
end
```

同时删除该helper中未使用的`M`形参。

控制逻辑、通信宽度、Recorder（记录器）布局、Primary公式、Kp/Ki在线暴露结构、GlobalHardOpen（全局硬故障强制断开）等均不因这次修复改变。

## 4. R1.7交付前新增的检查不是新的运行硬门

为了避免再出现这种纯脚本作用域错误，交付前离线检查增加：

1. local function（本地函数）调用参数个数与定义一致；
2. 读取`root/packageDir`的helper必须显式接收该参数或在本函数内定义；
3. `fileread(fullfile(root,...))`的每个使用点都检查作用域闭合；
4. MATLAB脚本/控制payload的字符串、括号、函数签名继续检查；
5. 执行依赖哈希重新计算。

这些只用于交付前自检，不增加用户新的`CHECK_BEFORE`步骤。

## 5. 用户执行方式

R1.7继续保持ESS2成功范式：

```text
一个正式PATCH入口
→ 内部结构preflight（修改前检查）
→ SELFTEST（自测）
→ byte-identical scratch
→ scratch改模
→ Update Diagram（更新模型图）
→ native compile（原生编译）
→ save/reopen
→ formal backup
→ promote compile-passed scratch
→ formal reopen/compile/postassert
```

用户不需要手工修改任何模型内容来修复本问题。
