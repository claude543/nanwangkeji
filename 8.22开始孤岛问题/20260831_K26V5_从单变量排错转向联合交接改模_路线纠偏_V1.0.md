# 1. `+5/+10 ms`到底是不是当前还应该使用的F20方案？

不是。

必须把历史分开。

## 1.1 `+5/+10 ms`是什么

它是历史V15～V20D期间：

```text
Python Host
检测到J1 OPEN
↓
约+5 ms
pulse F20 V2 capture
↓
约+10 ms
再pulse一次
↓
hold
```

本质：

> 根据V13A高速波形选出的“有界诊断事件时刻”。

它的价值是：

```text
证明J1后早期Iout工作点更新是否有作用
```

不是：

```text
最终自适应控制算法
```

---

## 1.2 为什么后来还专门改了F23

因为F20 V2本体被代码审计证明：

```text
est_d/q = raw_d/q
capture = 当前100us raw sample
```

所以：

```text
F20 V2
```

仍然存在“抓到哪个瞬时相位样本”的问题。

因此后来新增F23：

```text
本地100 us
↓
2×10 ms
↓
20 ms mean/std/drift
↓
candidate latch
↓
2 ms ramp
↓
permanent hold
```

而且：

```text
上游F20 bias变化
→ F23重新开始完整20ms窗口
```

这本来就是为了让：

```text
+5/+10 ms瞬时capture
```

不再定义最终工作点。

因此：

> **已经做了模型侧改进，就不应该再把+5/+10 ms当成“最新版F20”。**

---

# 2. 但F23也不是“最终F20动态解决方案”

这里必须避免另一个混淆。

F23后来被降为Observe-Only，不是因为它代码失败。

而是V20D证明：

```text
早期F20 V2两次更新以后
held bias
vs
后续20ms准稳态mean

只差约0.002~0.003 pu
```

所以原先：

```text
J1后还有0.025~0.04 pu大DC工作点迁移
```

这个假设被否决。

因此：

> F23“再大幅提交一个新的最终DC工作点”不是Primary解决方案。

但是这和：

```text
J1最初0~20/50 ms是否需要快速瞬态电流接管
```

是两个不同问题。

# 3. F20后来真正得到直接因果支持的模式是什么？

这里是此前回答最容易遗漏的一点。

## 3.1 MODE0

```text
成岛以后继续raw IOUT动态反馈
```

结果：

```text
约3.4 Hz指数增长
```

因此否决。

---

## 3.2 MODE1

```text
Formation阶段：
raw IOUT用于建立工作点

↓ release

Established island：
冻结Iout operating-point bias
ΔIout动态不再持续进入Id/Iq_ref
```

结果：

```text
3.4 Hz增长几乎消失
系统有界收敛
```

所以旧窗口已经明确：

> **MODE1不是单纯诊断模式，而是有直接因果证据支持的最终Gate A控制候选。**

---

## 3.3 MODE2

目的原本是：

```text
既不永久hold
又保留很慢的DC/慢变化跟踪
```

实现：

```text
release以后
0.5 Hz unity-DC slow IOUT
```

结果不是更好。

历史重新审判已经得到：

```text
原3.4 Hz虽然被抑制
但出现新的约0.3~0.5 Hz秒级不稳定
```

所以：

> **“只要成岛以后继续让实测IOUT以连续动态方式进入Id/Iq_ref，就可能重新改变系统阻尼。”**

因此当前正确原则仍是：

```text
建立工作点
→ 断开持续动态IOUT闭环
→ hold
```

而不是长期slow tracking。

# 4. 所以当前A1使用Legacy F20 MODE1是不是“落后版本”？

不能这样说。

A1使用的：

```text
Legacy F20 MODE1 HOLD
```

本身继承的是：

> **Gate A阶段已经由MODE0/MODE1/MODE2正交试验证明最合理的核心原则。**

也就是：

```text
不允许Established island持续dynamic IOUT tracking
```

这部分并没有过时。

A1真正和成功Gate A不同的是：

## Gate A MODE1

```text
J1从第一拍已经OPEN

ESS1在孤岛Formation过程中
F20仍track Iout

岛网已经建立以后
才freeze/hold
```

## A1 live-transfer

```text
ESS1仍GFL、J1仍CLOSED
就先freeze Legacy F20

随后：
GFL→GFM
F24
J1 OPEN

J1后：
F20继续保持原pre-island bias
```

所以当前真正的问题不是：

```text
A1用了旧F20
```

而是：

> **MODE1“建立工作点以后再hold”的原则，在dead-bus Formation里定义清楚了；但在live-transfer里，“J1突变附近什么时候、怎样完成从并网工作点到孤岛工作点的过渡”还没有形成正式的模型内语义。**

# 11. 所以当前真正的“未闭合问题”是什么？

现在剩下的核心不是：

```text
ESS1控制器整体是否稳定
```

也不是：

```text
五台GFL是否把它拖垮
```

而是：

> **同一个已经证明可以稳定工作的ESS1孤岛控制结构，为什么从dead-bus慢Formation可以进入稳定吸引域，而从强网带电状态经J1瞬间移除却进入严重低压轨迹？**

这个问题落在：

```text
live-transfer transition architecture
```

上。

主要涉及：

1. F22清除并网Voltage PI历史状态；
2. F24在J1边沿保持正确F/V reference；
3. F20/F8需要怎样把“并网输出电流工作点”迁移成“孤岛输出电流工作点”；
4. J1切换时C/L/Transformer已有能量状态；
5. 这些动作必须在同一个100 μs本地事件下协调。

# 12. 现在是否仍然应该追求“一次只动一个块”？

不应机械化。

单因果原则应该理解成：

> **一次只验证一个“功能假设”。**

如果一个功能本身天然由多个动作构成，例如：

```text
J1事件下的完整Current-Reference Handover
```

它就可能必须同时包括：

```text
edge detection
fast transition
candidate estimation
smooth hold
F22 coordination
```

这几个子动作不能为了追求形式上的“单变量”被拆成五轮Host定时试验。

正确做法是：

```text
把整个handover功能作为一个新功能变量

同时给它完整state/ack/diagnostics
```

然后用：

```text
ENABLE=0 exact bypass
vs
ENABLE=1 integrated handover
```

做真正干净的A/B。

这比：

```text
今天+5ms
明天+10ms
后天F23 commit
```

更适合当前阶段。

# 16. TRANSIENT_TRANSFER怎么设计？

这里现在不能凭空把算法写死。

但约束已经非常明确：

## 必须满足

1. 真实J1 local falling edge触发；
2. 100 μs本地执行；
3. 不依赖Host固定+5/+10 ms；
4. 不长期continuous raw IOUT；
5. J1最初几十ms必须具有足够快的工作点迁移能力；
6. 必须限幅；
7. 必须限制slew；
8. 必须有maximum-duration fail-safe；
9. 必须和F22 reset同步，避免：
   ```text
   VPI刚清零
   但IOUT新支撑还没进入
   ```
10. 最终必须转入HOLD。

# 17. 最合理的两时间尺度结构

历史证据已经自然指向：

```text
FAST PATH
J1后最初0~几十ms
负责“不让电压先塌”
```

同时：

```text
SLOW / QUASI-STEADY PATH
F23-style 20ms local estimator
负责判断最终应该hold在哪里
```

然后：

```text
candidate valid
↓
从当前effective feedforward
平滑过渡到candidate
↓
permanent hold
```

注意：

> V20D已经否决“大DC shift”，所以新的candidate逻辑不能继续要求`delta >= 0.02 pu`这类旧假设门。

阈值必须根据A1、V13A、Gate A数据重新设计。

# 18. 为什么这比+5/+10 ms更正确

旧：

```text
J1
↓
Host +5ms
capture
↓
Host +10ms
capture
```

依赖：

- Host timing；
- 固定绝对延时；
- 瞬时raw sample；
- 工况变化以后时间点可能失效。

新：

```text
J1 local edge
↓
local transition state
↓
local data-driven candidate
↓
condition-driven hold
```

这是控制器真正应有的工程语义。
