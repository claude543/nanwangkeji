# 储能2健康恢复与平滑接管：原生改模包第一版

日期：2026年9月17日。

**本版首轮只验证：健康条件参与恢复 → 执行原来的−0.005标幺任务 → 同任务接管 → 接管后保持。**不改变原有储能1建网、储能2同期与合闸物理结构，不恢复旧无功外环和四路附加支撑，不在首轮增加功率。

这里的并回指储能2接入储能1建立的孤岛母线，不是公共连接点重新接上级电网。

## 一、怎样使用

把整个目录解压到模型目录以外的短英文路径，例如 `D:\E2PATCH\HR1`（改模工具目录）。不要只复制两个主脚本，`payload`（修改后的控制源码）、`reference`（原审计源码）及辅助函数需要一起保留。

在 MATLAB（矩阵计算与仿真软件）中打开当前 `K26_K50_CLEAN_P1`（储能2黑启动研究模型），保持源模型停止并已保存。将工作目录切换到工具目录，运行：

```matlab
result = PATCH_E2_HEALTH_HANDOVER_R1;
```

其中 `result`（修改结果）包含备份和日志位置。

脚本会先做源文件和三个函数的核对，然后在副本中修改、验证、保存并重新打开验证。通过后才把这个原生保存的副本写回正式源文件。执行过程中不进行普通整模型更新、编译或电气运行。

看到 `PATCH_SAVED_AND_PERSISTENCE_VERIFIED`（修改已保存且重新打开核对一致）以后，再单独运行：

```matlab
verification = VERIFY_E2_HEALTH_HANDOVER_R1;
```

其中 `verification`（独立结构核对结果）应为 `READ_ONLY_STRUCTURE_PASS`（只读结构核对通过）。这个结果不等于实时构建或电气试验通过。

随后再在 RT-LAB（实时仿真平台）执行全部重新构建。构建后必须重新发现目标机参数、信号及记录宽度。

**不要直接套用旧有功诊断运行脚本，也不要执行先前暂停的零无功试验脚本。**旧运行脚本会把诊断模式写回1，且可能要求保存积分默认值为2；旧分析脚本也不认识新的第29组宽度。需使用与本包配置和记录定义一致的首轮运行／分析脚本。

## 二、本版修改了什么

### 1. 三个已有控制核心

- `AA15_ESS2_RESTORE_EXECUTOR/CORE`（储能2恢复执行器／核心）：将诊断定时分支与健康推进分开；新模式使用实际收到的外部任务判断；连续健康才完成资格。旧模式1仍保留原有诊断行为。
- `Advanced_Strategy_Core`（策略核心）：保留放行后的零任务观察；健康合格后允许接管；先匹配两路命令再混合；首轮在接管后保持，不自动投入一次修正。
- `AA15_FINAL_COORD_CORE`（正常孤岛协调核心）：储能2可用状态上升时接住上一拍实际施加的命令；接管期间保持，不继续逐拍追随实测波动。其他四台资源仍不可分配。

### 2. 标准模块和连线

复用原有任务斜坡、混合比例斜坡和加权求和。增加必要的一拍延时、子系统标量端口和记录连线。新增反馈均用一拍延时打断直接环路；新连线限定在主任务内部，不直接跨接主从任务。

没有新增一套黑启动状态机，没有新增储能2电流控制器，没有复制五套设备控制函数。

### 3. 首个功率目标不变

仍然是−0.005标幺，按100千瓦基准为吸收500瓦。储能2有功参数保存为比例0.06、积分0.5。旧无功环与直接电流诊断支路保存为关闭。

本版首任务资格采用25瓦级误差候选，即0.00025标幺；这是依据已报告末段±5%表现选择的验收候选，**并未声称已用本地原始全时域数据完成新门控重放**。实际条件不满足就等待或按异常规则退出，不为赶60秒放宽条件。

## 三、如何区分运行模式

复用现有基础试验模式常数，不增加一排新的主从手工开关。主从同类常数必须一致，由新运行脚本在首次执行前统一写入和回读。

| 数值 | 含义 |
|---:|---|
| 1 | 保留旧定时诊断观察，不接管 |
| 2 | 健康资格成立后保持，不接管 |
| **3** | **健康恢复、同任务接管、接管后保持；本版保存默认与首轮使用值** |
| 4 | 接管后保持合格，再接受受限的下一本机任务 |
| 5 | 接管后保持合格，再允许受限的一次协调；不同时改变基础任务 |

模式4、5虽然准备了控制入口，但默认工程允许区间只有原来的−0.005标幺一点。因此仅把模式改成4或5，并不会自行放开新的功率范围。

`CFG_E2HH_NEXT_TARGET_PU`（下一本机功率目标）默认−0.005。

`CFG_E2HH_APPROVED_LIMITS`（已批准试验范围）默认：

```text
[-0.005; -0.005; 0.0025; 0.0025]
```

四项依次是绝对下限、绝对上限、增大速度、减小速度幅值。功率单位为标幺，速度为标幺每秒。它们是明确的工程试验边界，**不是已实现的储能1动态余量计算器**。

扩大这些范围之前，必须基于储能1和储能2的实际电流、功率、无功及调制证据确定可承受范围。当前没有依据允许直接设成额定全功率。

## 四、平滑接管具体做法

本地先确认当前500瓦任务完成。策略14仍给出同一任务，协调器捕获实际施加命令。两路延时命令相差不超过0.000001标幺，即按当前基准0.1瓦，并保持20毫秒，才允许混合。

该匹配容差针对两条数字命令，不是要求实测功率精确到0.1瓦；实测跟踪采用前面的25瓦级候选。

已有混合上升速度对应约2秒完整交接。模式3完成后继续停在策略14步骤50，任务不变，一次和二次修正为零。模式4、5须在混合后另保持约3秒才进入后续步骤60。

两路相同命令的混合在数学上保持同一个值，但真正电流、电压与功率是否稳定，仍要看原始记录。

## 五、健康与异常处理边界

- 合闸后、零参考阶段恢复健康条件计时。
- 电流执行放行后仍保留原5秒零任务观察，并要求对应零任务健康许可。
- 在固定任务模式中，本地状态7若失去普通任务资格，返回状态6重新判断，但不通过把真实测量电流改成零来掩盖问题。
- 原有严重异常处理优先，不把源模型已有保护条件删除。
- 本地合格但选择等待，不继续累计任务尚未完成的超时。
- 主任务增加构网频率参考有效性的一拍回授，参与接管许可。它不是储能1完整物理余量，也不是电流保护的替代品。
- 接管后的受限模式中，普通健康许可丢失时，停止增加任务并保持当前命令，不跳回旧500瓦任务。
- 请求撤回在新模式下保留失败／保持上下文，不能以结束启动为由直接恢复原全资源可用假设。它不替代操作平台的停止／复位流程，也不支持运行中任意修改总控制配置。

本版不宣称已完成所有真实硬件保护、断路器独立触点反馈、通信新鲜度或储能1双向动态余量估计。现有严重故障链仍必须在相应工况下验证。

## 六、记录安排

第27组和第30组宽度与原行号保持不变。第29组原前74个数据通道不变，末尾追加12个字段，总计86个数据通道加1行时间，**新矩阵应为87行**。

追加内容包括运行模式、两路延时命令、上一拍实际命令、上一拍可用状态、匹配误差、下一任务、绝对边界和速度、上层步骤回显。完整含义见 `RECORD_LAYOUT.json`（记录定义）。

60秒名义文件预算：第27组216兆字节，第29组156.6兆字节，第30组104.4兆字节，均低于现有每组500兆字节上限。这个预算不证明目标机无丢点，仍需检查实际时间行、末尾覆盖和实时超步长。

记录追加只改变第29组原有末级多路拼接输入，不删除原通道。脚本找不到唯一的组29记录块或透明数据拼接路径时，会停止副本修改，不猜测相似模块。

## 七、结果含义和失败时怎么办

| 输出状态 | 含义 |
|---|---|
| `PATCH_SAVED_AND_PERSISTENCE_VERIFIED`（修改保存且持久化核对通过） | 已用本地软件保存、重新打开核对；不是实时构建通过 |
| `READ_ONLY_STRUCTURE_PASS`（只读结构通过） | 已修改源码、端口与原有连线等静态检查通过；不是电气通过 |
| `BLOCKED_BEFORE_FORMAL_WRITE`（写正式文件之前阻断） | 副本检查未通过，正式源文件未写回 |
| `FORMAL_SAVED_NEEDS_READ_ONLY_REVIEW`（正式文件已保存，需只读复核） | 不要机械重跑补丁；先看独立验证和日志 |

每次执行单独建立 `APPLY_时间`（本次修改输出）目录，内有原始备份、副本、修改记录、结果和独立验证结果。

本包源码转换、约束示例和离线命令交接检查结果在 `OFFLINE_CHECKS.json`（离线检查）中。独立逻辑核对不包含电气被控对象，也不等价于执行了三个原生状态函数或实时模型。

**本环境没有运行 MATLAB、RT-LAB 或目标机。**最终还需要本地副本核对、独立验证、实时重新构建以及首轮原始数据验收。

## 八、固定小功率之后是不是放开到全部功率？

可以从首个合格的小功率点平滑走向正常任务，但正常任务不一定是额定功率，更不是取消限制。

正确关系是：先完成小功率资格和交权，再由正常管理给出所需任务，在已经批准且设备承受得住的范围内平滑执行。经过充分验证后，最终运行不必在每个小幅值上长期停留；但电流、功率、能量和稳定范围限制始终保留。

本版首轮始终保持原500瓦任务，先把交接事实验证清楚。尚未取得依据的更大功率不会由本补丁自行放开。
