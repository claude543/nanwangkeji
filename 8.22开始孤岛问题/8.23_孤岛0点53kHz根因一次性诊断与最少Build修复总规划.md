# 8.23｜孤岛0.53 kHz根因一次性诊断与最少Build修复总规划

## 0. 本轮规划的核心目标

后续不再采用：

```text
怀疑一个点
↓
改一次模型
↓
Rebuild
↓
跑一次
↓
再怀疑下一个点
↓
再Rebuild
```

这种低效率方式。

从当前证据看，我们已经把问题压缩到：

```text
ESS1 GFM快速控制
↕
Current/Voltage Loop
↕
PWM / Converter
↕
LC约0.53 kHz自然模态
↕
其余5台GFL / 孤岛网络
```

因此现在最合理的路线是：

# **0次Build完成“超级测点审计”**
# **1次Build建立“一次性根因诊断平台 D1”**
# **同一个D1模型连续跑多个工况，不再Build**
# **分析后只做1次“正式修复Build F1”**
# **F1中让阻尼增益/使能可调，尽量不再Build地完成调参**
# **最后需要交付时才做1次可选的清理/冻结Build**

如果D1一次成功，后续理想Build数量为：

```text
D1：1次
F1：1次
最终清理版：0～1次
```

也就是说：

> **从现在开始，正常情况下不应该再出现五六次甚至十几次Rebuild去“猜原因”。**

# 1. 我们到目前为止有没有漏掉大方向？

有一些**还没有动态测到的关键机制**，但现在已经可以一次性补齐。

已经解决或大幅降级的方向：

```text
PCC 55 Hz是实际孤岛频率
→ 否，55 Hz是异常波形下PLL/限幅症状

PCC测量自己制造0.53 kHz
→ 否

2 kHz日志混叠出假531 Hz
→ 否，10 kHz已经确认真实0.53 kHz

Line_ESS1把健康prim放大成异常PCC
→ 否

Stubline/Transformer之后才开始振
→ 大幅降级，LCout在Stubline前已经振

L1/C1之后才从无到有
→ 否，inv在L1前已经有强同频分量

Fref把系统命令到530 Hz
→ 否，开J1时Fref仍约50 Hz
```

因此这些以后不应再反复重新查。

# 3. 当前一个非常重要、以前还没有一次性利用起来的东西：`meas` 14维总线

```text

```

14维诊断总线。

现有模型资料已经明确：

```text

6  PId
```

这意味着：


# 5. 当前最大遗漏之一：必须同时测“500 Hz滤波前”和“500 Hz滤波后”

这是下一次D1最关键的新证据之一。

现有静态审计已经确认正式GFM测量路径使用：

```text
Second-Order Lowpass
Fo = fn_Filter = 500 Hz
ζ = 1
Ts = 100 μs
```

而真实故障模态：

```text
abc侧约530 Hz
```

对于50 Hz同步旋转dq坐标，一个正序530 Hz分量在dq中通常表现为约：

```text
530 - 50
≈ 480 Hz
```

所以以后看到：

```text
dq里约480 Hz
```

不要误认为和abc的530 Hz“不一致”。

恰恰相反：

```text
abc：约530 Hz
↓
50 Hz同步旋转坐标
↓
dq：约480 Hz
```

是同一个正序模态的正常表现。

# 6. 为什么一定要测滤波前后？

如果我们只测滤波后的：

```text
Vd/Vq
Id/Iq
```

只能知道：

```text
控制器收到了振荡
```

但不知道500 Hz滤波器在这个频率上：

```text
衰减了多少
滞后了多少
```

D1必须增加：

```text
Vdq_raw_before_500Hz
Idq_raw_before_500Hz
```

再和：

```text
Vd/Vq_after_500Hz
Id/Iq_after_500Hz
```

比较。

这样可以直接计算：

```text
幅值比
相位差
等效延时
```

如果在约480 Hz：

```text
滤波后明显滞后
+
Current/Voltage Loop输出同步变大
```

那么“500 Hz滤波 + 数字延时侵蚀阻尼”就会从猜测升级成直接证据。

# 7. 当前另一个遗漏：饱和状态必须一次性查清

当前已经知道：

```text
Voltage PI限幅约 ±1.25
Current PI限幅约 ±1.25
Current最终VdVq_conv约 ±1.25
ModIndex限幅 0～1
```

但我们还没有动态确认：

```text
孤岛失稳时有没有撞限幅
```

D1不一定需要额外记录十几个“饱和Flag”。

利用已有量即可判断大部分：

```text
Id_ref / Iq_ref
→ 是否长期贴±1.25

PId / PIq
→ 是否长期贴±1.25

Vd_conv / Vq_conv
→ 是否长期贴±1.25

ModIndex
→ 是否长期贴1
```

如果这些量出现平顶/削顶：

```text
系统已经进入非线性饱和/极限环
```

那么最终修复就不能只谈“小信号阻尼”。

# 10. 六路支路电流能告诉我们什么？

对530 Hz主模态做频域分析：

```text
PCC模态电压
vs
每台设备模态电流
```

看相位关系。

通俗理解：

```text
某台设备的530 Hz电流
如果在这个模态上不断“推着电压振”
→ 它在给振荡供能
→ 等效负阻尼

如果它的电流作用方向相反
→ 它在吸收振荡能量
→ 等效正阻尼
```

这不是完整正式阻抗扫描，

但足以在一次运行里形成：

```text
六设备模态参与度排序
```

从而决定：

```text
有没有必要再做GFL逐台隔离
```

```text

互相关
cross-correlation

以及已知Ts
```

估计相位/等效延时。

因此5 kHz仍然可以识别：



# 16. D1要怎样回传，才能不增加很多额外延时？

原则：

# **所有SS内部新增诊断量统一进入现有那一个SS→SM向量，并且统一经过现有唯一Memory。**

当前：

```text
Pmeas1
Pmeas2
inv_Vab
LCout_Vab
↓
Mux
↓
一个Memory
↓
SS→SM
```

D1扩成：

```text
原4路
+
12路meas
+
7路内部fast diag
↓
同一个Mux
↓
还是同一个Memory
↓
SS→SM
```

不要：

```text
每组信号单独加Memory
单独加Outport
单独加OpComm
```

这样：

```text
ESS1内部诊断量之间
```

全部共享同一个回传时序。

因此它们之间的相对先后/相位最可信。

# 17. SM本地量和SS回传量之间的延时怎么办？

例如：

```text
SS内部Vd/Iq/Vpwm
```

经过：

```text
原Memory
→ SS→SM
```

而：

```text
PCC_V
prim电流
```

本来就在SM。

因此两组之间存在一个共同的回传时序偏移。

这个不要通过再加Memory“人为对齐”。

正确做法是：

```text
保持真实原模型
↓
离线估计共同延时
↓
统一补偿
```

否则人为给SM量再加Memory反而会改变诊断。



# 24. 为什么早期窗口非常重要？

65 s以后系统已经严重振荡，

可能：

```text
PI饱和
ModIndex饱和
PLL失锁
进入非线性极限环
```

这时候：

```text
“谁先导致谁”
```

已经不容易判断。

真正根因最有价值的是：

```text
J1刚打开后的最初几百毫秒到1～2 s
```

谁先增长。

所以D1必须同时分析：

```text
早期线性/弱非线性阶段
+
后期持续振荡阶段
```

# 25. 第二层：直接测500 Hz滤波器的相位作用

# 26. 第三层：看控制器到底在哪一层“加能量”

## 若 `Id_ref/Iq_ref`先有强480 Hz

说明：

```text
Voltage Regulator
```

已经把振荡写进：

```text
电流目标
```

重点：

```text
电压反馈
500 Hz滤波
Voltage PI
```

---

## 若 `Id_ref/Iq_ref`相对干净，但`Id/Iq`先振

说明：

```text
Plant/LC/网络
```

先驱动真实电流振荡。

随后看：

```text
PIdq
VdVq_conv
```

控制器是在：

```text
压制
还是放大
```

---

## 若 `PId/PIq`迅速大幅振荡

说明：

```text
Current PI
```

正在强烈参与。

---

## 若 `VdVq_conv`撞±1.25

说明：

```text
Current Regulator最终电压命令已经饱和
```

---

## 若 `ModIndex≈1`

说明：

```text
PWM线性调制能力已经用尽
```

这时后期波形属于：

```text
能力限制 + 原始振荡
```

共同形成。

---

## 若 `Vpwm_ab`本身有明显快速模态

说明：

```text
PWM之前控制参考已经含该模态
```

那么不能再优先怪：

```text
PWM Generator凭空制造530 Hz
```

# 28. D1一次数据最终应该把根因收敛成哪四类？

理想情况下只剩以下之一或组合。

## A. 500 Hz测量滤波/数字延时主导

特征：

```text
raw dq
↓
500 Hz filter
出现显著相位滞后
↓
Voltage/Current Loop输出进一步放大
```

修复：

```text
重新设计测量滤波
+
重新匹配环路带宽
+
必要时减少快速反馈延时
```

---

## B. Voltage/Current PI与LC模态耦合

特征：

```text
Id_ref/PIdq/VdVq_conv
在480 Hz附近显著放大

或者
饱和/限幅成为持续振荡的重要部分
```

修复：

```text
重新整定Voltage/Current Loop
+
主动阻尼/虚拟阻抗
```

---

## C. 多GFL负阻尼交互

特征：

```text
某些GFL支路530 Hz电流明显向系统注入模态能量
```

修复：

```text
GFL PLL带宽
Current Loop
虚拟阻抗
弱网适配
```

而不是只改ESS1。

---

## D. PWM/Converter离散功率级异常

特征：

```text
Vpwm控制参考相对正常
但inv电气端已经强异常
```

这时才重点查：

```text
PWM
2.5 step / switching period
Converter switching implementation
DC侧
```

当前它属于低于A/B/C的候选。

# 29. GFL→GFM无扰切换有没有遗漏？

没有完全排除，但优先级已经下降。

以前审计发现：

```text
Droop相角没有明显PLL状态初始化
Voltage PI没有明显GFL电流状态跟踪
```

确实存在：

```text
hard switch
```

风险。

但是当前实际工况：

```text
55 s ESS1已经切GFM
J1仍闭合

一直到60 s
才真正开J1
```

也就是说：

```text
有5 s的GFM + 强网预运行
```

而持续0.53 kHz失稳主要在：

```text
60 s J1打开以后
```

才暴露。

所以无扰切换可能：

```text
提供初始扰动
```

但不像：

```text
持续530 Hz模态唯一根因
```

D1保留模式/Freq/P/Q等信息即可，不需要把它重新提升为第一排查方向。


```text
或

```

一旦系统变好，

我们仍然不知道是：

```text

还是模态阻尼
```

所以：

```text

↓
再做单变量敏感性
```

更高效。

# 33. 如果D1证明“LC模态 + 控制负阻尼”主导

优先考虑：

# **Active Damping / Virtual Resistance**

即：

```text
主动阻尼 / 虚拟电阻
```

目标不是改掉LC自然频率，

而是：

```text
振荡一出现
↓
控制器产生与振荡方向相反的作用
↓
把模态能量耗掉
↓
振荡快速衰减
```

# 34. 当前模型其实已经有构造“电容电流主动阻尼”候选的物理测点

SS中：

```text
inv Iabc
≈ L1输入/电感电流候选

LCout Iabc
≈ 向Stubline/Transformer输出电流候选
```

理论上在方向/量纲统一后：

```text
i_C
≈
i_L - i_out
```

就可以得到：

```text
电容支路电流
```

而电容电流反馈是LC主动阻尼的经典候选信号之一。

但当前 `Three-Phase V-I Measurement6` 有自己的：

```text
Ipu
Pbase
Vbase
```

设置，

所以在F1之前必须先确认：

```text
两个Iabc是否同单位
参考方向是否一致
比例如何换算
```

不能直接相减。

这个也放进D0静态审计。

# 35. F1要怎样避免“每换一个阻尼系数就Rebuild”？

F1设计时一开始就加入：

```text
AD_ENABLE
K_AD
```

例如：

```text
AD_ENABLE = 0
→ 完全退化为原模型

AD_ENABLE = 1
→ 主动阻尼投入

K_AD
→ 阻尼增益
```

并尽量让：

```text
K_AD
```

作为RT-LAB运行时可调参数。

这样：

```text
K_AD = 0
K_AD = K1
K_AD = K2
K_AD = K3
...
```

可以：

```text
Load一次
多轮运行
```

而不是每个K重新Build。

# 36. F1不能只看“波形看起来平了”

每个阻尼参数都要自动计算：

```text
主模态频率
衰减率
settling time
PCC 50 Hz基波恢复
电压RMS
Current/Voltage PI裕度
ModIndex裕度
Overrun
```

最佳K不是：

```text
越大越好
```

而是：

```text
530 Hz足够快衰减
+
不明显损害50 Hz动态
+
不引入新的高频模态
+
不让控制器饱和
```

# 37. 如果D1证明500 Hz滤波器是主要问题

F1就不应先硬加大主动阻尼。

优先：

```text
重新设计fn_Filter
+
Voltage/Current loop带宽
```

核心原则：

```text
测量滤波带宽
控制环带宽
LC自然模态
PWM频率
采样频率
```

必须分层。

不能简单：

```text
500 → 1000
```

就认为一定更好。

# 38. 如果D1证明SM/SS快速反馈时延是关键

则更合理的根治是：

```text
快速Current/Voltage Loop
尽量用SS本地低压V/I闭合

继续用于：
P/Q
监督
保护
Board状态
```

# **fast loop local, slow supervisory remote**

而不是用更大的PI去硬顶跨任务延时。

# 43. 现在真正应该立刻做什么？

下一步先做：

# **D0：一次只读“SUPERPACK测点审计”**

不修改模型。

不Build。

目标一次锁死：

```text
1. ESS1 meas bus 14个字段的实际名称/来源
2. 当前GFM正式Vd/Vq、Id/Iq反馈
3. 500 Hz滤波器前的raw dq点
4. VdVq_conv
5. Vpwm
6. ModIndex / PIdq / IdIq_ref
7. Voltage/Current/Vref所有关键限幅点
8. 六台prim Iabc输出
9. 当前SS2→SM回传Mux/Memory
10. 当前Group29 OpWrite
11. 可能的runtime tunable参数
12. inv/LCout电流量纲和方向线索
```

只有这个D0 TXT确认以后，

才生成唯一D1 patch。

# 45. 最终结论

> **我们目前没有漏掉一个“明显的大块根因”，但仍缺四类决定性动态证据：500 Hz滤波前后、Voltage/Current loop内部、PWM前调制参考，以及其它5台GFL的530 Hz模态电流参与度。最有效率的做法不是继续一层一Build，而是先零Build做一次SUPERPACK测点审计，然后只用1次D1 Rebuild把这些关键点统一送到现有SS→SM诊断向量，并复用现有SM Group29 OpWrite，以约5 kHz一次性记录约30个高价值标量。D1后同一Build先跑66 s正式参考，再验证一个约16 s短工况；一旦短工况等价，后续所有敏感性测试和阻尼调节都用短工况，不再Build。分析上同时看raw/filtered dq、IdIq_ref/meas、PIdq、VdVq_conv、ModIndex、Vpwm和六台支路模态电流，就可以把根因收敛到‘测量滤波/延时、GFM电压/电流环、GFL多机负阻尼、或少数PWM/功率级问题’之一。之后只做1次F1修复Build，并把AD_ENABLE/K_AD等阻尼参数设计成运行时可调，尽量在同一Build内完成阻尼扫参。正常情况下，从现在到根因+修复只需要2次关键Rebuild，最多再加1次最终清理Build。**
