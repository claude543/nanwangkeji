# 8.24｜现在问题到底在哪里、还剩几种完整解决路径、为什么F2是当前主线

## 0. 最先把一句话讲明白

现在我们已经不是：

```text
“不知道系统为什么孤岛失败”
```

而是：

```text
已经知道这是一个约527 Hz电气自然模态
在失去强网以后得不到足够正阻尼的问题；
真正剩下的是：
为什么现有GFM快环没有给它足够阻尼，
以及用哪一种工程方式把正阻尼补回来。
```

当前最高置信度的结构性原因已经收敛到：

# **现有GFM“快环”实际上用的是远端 `prim_ESS1` 高压侧V/I，且反馈要经过SM Memory、跨任务接口再回到SS；它没有直接用LC本地的电容电压 `vC` 和L1电感电流 `iL` 来闭合毫秒级Voltage/Current Loop。500 Hz低通又进一步增加了相位滞后。强网一断，约527 Hz LC模态失去钳位，控制器来不及正确“刹车”，随后进入限幅，多机一起参与，最终形成持续快速振荡。**

这就是现在最通俗、最完整的核心判断。

# 1. 最容易听懂的类比

把ESS1的LC网络想象成：

```text
一根天然在527 Hz附近容易振的弹簧
```

并网时：

```text
强网
=
一堵很硬的墙
```

它把弹簧压得很稳。

J1打开：

```text
墙突然没了
```

这时GFM控制器应该像：

```text
减震器
```

在弹簧刚开始振的时候立刻施加反向力，让它：

```text
振几下
↓
迅速停下来
```

但我们现在的“减震器传感器”并不直接装在弹簧上。

它实际是：

```text
LC
↓
Stubline
↓
Transformer
↓
prim_ESS1高压侧测量
↓
SM Memory
↓
跨任务通信
↓
SS控制器
↓
500 Hz Filter
↓
Voltage/Current Loop
```

所以控制器得到的是：

```text
离弹簧比较远
+
已经晚了一些
+
又被500 Hz滤波进一步拖相位
```

的反馈。

结果就是：

```text
弹簧已经开始振
↓
减震器才反应
↓
反应时机又不理想
↓
不能提供足够正阻尼
↓
最后控制器自己也打满
↓
振荡越来越大
```

这就是现在问题最通俗的本质。

# 2. 为什么现在不再认为“500 Hz滤波器就是根因”

因为我们已经真正跑了：

```text
500 Hz
800 Hz
1000 Hz
```

三组Filter-only实验。

结果：

```text
500 Hz：
相位滞后最大
失稳

800 Hz：
相位明显改善
快速模态最弱
但仍然失稳

1000 Hz：
相位进一步减小
但快速模态重新增强
仍然失稳
```

所以：

> **500 Hz Filter是重要参与因素，但不是唯一决定因素。**

如果它是唯一根因，那么：

```text
500 → 800 → 1000
```

至少应该存在一个明显进入稳定区的点。

实际没有。

所以继续扫：

```text
700
900
1200
```

大概率只是在不断移动不稳定模态，而不是根治。

---

# 3. 为什么主动阻尼正负号都没有解决，也很重要

我们又验证：

```text
800 Hz + AD OFF

800 Hz + K=0.005, SIGN=-1

800 Hz + K=0.005, SIGN=+1
```

结果两个SIGN都没有恢复健康50 Hz孤岛，而且都比AD OFF更容易重新形成强约0.5 kHz模态。

这说明：

```text
“直接把本地电容电流乘一个K加到电压命令”
```

这种裸比例主动阻尼，并不适合当前完整闭环。

所以现在也不能继续：

```text
K=0.01
K=0.02
不断翻SIGN
```

碰运气。

# 4. 经过这些实验以后，真正的根因如何进一步收敛

当前证据链已经变成：

```text
约527 Hz LC/network自然模态
       │
       ▼
J1打开，强网钳位消失
       │
       ▼
现有快环没有直接控制本地LC状态
       │
       ├── Voltage feedback不是直接本地vC
       ├── Current feedback不是直接本地iL
       └── 而是远端prim V/I
       │
       ▼
prim反馈还经过：
SM Memory + 跨任务/OpComm
       │
       ▼
500 Hz Filter再增加大相位滞后
       │
       ▼
Voltage/Current Loop对527 Hz模态反应不够及时
       │
       ▼
Id_ref / VdVq / ModIndex迅速限幅
       │
       ▼
Vpwm自己也开始带同一快速模态
       │
       ▼
其它5台GFL通过动态阻抗共同参与
       │
       ▼
模态不衰减，形成持续振荡
```

所以现在真正剩下的主问题是：

# **GFM快环的测量位置、控制对象和数字延时与LC模态不匹配。**

而不是：

```text
一个单独的500 Hz数字
```

---

# 7. 第一层，也是当前最高优先级：GFM快环本地化

这是现在最重要、最可能真正解决的主方法。

把：

```text
GFM快速Voltage/Current Loop
```

从当前远端：

```text
prim_ESS1 V/I
↓
SM Memory
↓
SM→SS
```

改成SS本地：

```text
vC = C1/LC节点电压
iL = L1电感电流
```

即：

```text
Converter
↓
L1
↓
iL
↓
C1
↓
vC
```

然后：

```text
Voltage Loop用vC
Current Loop用iL
```

这才是LC内部状态最直接的快速闭环。

---

# 8. 为什么这被认为是最根本的修复

Current Loop最自然控制：

```text
L1中的电感电流 iL
```

Voltage Loop最自然控制：

```text
C1两端电压 vC
```

因为物理能量链就是：

```text
Converter voltage
↓
L1电流iL
↓
给C1充放电
↓
形成vC
```

所以：

```text
Current Loop → iL
Voltage Loop → vC
```

是一个非常直接的控制对象对应关系。

现在的remote prim反馈相当于：

```text
隔着LC、Stubline、Transformer
去控制一个毫秒级LC模态
```

天然更困难。

---

# 9. F2本地化以后，慢环并不需要全部搬回来

这是很重要的。

F2不是：

```text
把整个控制器推翻重写
```

而是：

```text
【快环】
SS本地vC / iL
→ Voltage/Current Loop

【慢环】
prim_ESS1
→ P/Q
→ Droop
→ 策略
→ BOARD15
```

也就是：

# **fast loop local, slow supervisory remote**

所以：

```text
S5/S14/S15
AGC
BOARD15
P/Q Droop
```

都不用推倒。

# 10. 第二层：本地快环的Plant参数/前馈匹配

如果Current Loop从remote电流切到真正的：

```text
iL
```

那么Current Regulator看到的Plant主要就是：

```text
L1
```

当前：

```text
Rff = 0.004
Lff = 0.21
```

是按更远端的等效串联阻抗设计的。

L1本身折算：

```text
R_L1 ≈0.0015 pu
X_L1 @50Hz ≈0.125 pu
```

因此F2本地Current Loop要同时匹配：

```text
Rff_local ≈0.0015
Lff_local ≈0.125
```

不能只换测量而不换Plant模型。

---

# 11. 第三层：本地快环的Filter/PI带宽协调

如果本地vC/iL以后：

```text
延时显著减少
控制对象更直接
```

仍然需要确保：

```text
Current Loop
比
Voltage Loop
快

Filter
不在目标模态上造成过大相位损失
```

这时再调整：

```text
Filter
Kp_Ireg / Ki_Ireg
Kp_Vreg / Ki_Vreg
```

才是正确顺序。

而不是像现在一样在远端反馈架构里盲调PI。

---

# 12. 第四层：经过动态整形的主动阻尼/虚拟阻抗

如果F2本地快环已经基本稳定，但：

```text
527 Hz模态衰减还不够快
```

再增加：

```text
Active Damping
Virtual Resistance
Virtual Impedance
```

这时主动阻尼要基于：

```text
本地状态
+
目标频带
+
数字延时
```

设计。

可能需要：

```text
高通
带通
Lead补偿
```

而不是当前已经证伪的：

```text
±K × raw iC
```

裸比例反馈。

# 21. 最简单的一句话怎么讲现在的问题

你可以这样记：

> **现在的GFM像是在用一个“远处、延迟、经过滤波的传感器”控制一个本地527 Hz的LC弹簧。并网时电网帮它压着，所以看不出；一孤岛，电网这堵墙没了，控制器来不及正确刹车，LC就振起来。500/800/1000 Hz只是改变这个远端传感器的响应速度，所以能改变振荡，却不能根治。现在真正该做的是把毫秒级快环的传感器搬回LC旁边：电压环直接看电容电压vC，电流环直接看L1电流iL；远端prim只继续负责P/Q、Droop和上层监督。**

这就是现在最需要听懂的一句话。

# 25. 最终结论

> **现在不再是“还有很多原因不知道”。经过前面的排除，我们已经把问题压缩成一个很清楚的结构性矛盾：527 Hz LC自然模态需要一个真正快速、低延时、直接控制LC状态的GFM快环，而现有控制仍通过远端prim_ESS1高压侧V/I、SM Memory和跨任务接口来闭合快环。Filter只是在这个架构上改变相位，所以500/800/1000都不能根治；裸比例iC主动阻尼两种极性也都不能补救这个底层架构。剩余完整解决方法可以归纳为五层：①首先把GFM快环本地化到vC+iL；②匹配本地R/L、PI和Filter；③必要时加入经过动态整形的主动阻尼；④若仍有多机负阻尼再修GFL；⑤最后才考虑Ts/PWM离散实现。当前最应该做的是第①层，它既是最高优先级根因验证，也是最可能真正解决问题的修复。**
