# 0. 第一屏：这四个问题先直接回答

## 0.1 F20为什么改了很多遍，还没有完全“冻结关闭”？

因为F20承担的是一个**本身就存在矛盾的控制任务**：

```text
一方面：
Voltage Loop需要output-current feedforward
否则Voltage PI必须自己慢慢积分出全部负载/网络电流，
Gate A Formation会严重滞后。

另一方面：
如果把实际iout的动态变化毫无条件地持续闭回Current Reference，
测量延迟/相位/网络动态会改变GFM输出阻抗，
历史上已经实测造成约3.4 Hz低频负阻尼增长。
```

所以F20从来不是“一个简单滤波器”。

它真正要解决的是：

> **既保留输出电流的准稳态工作点前馈，又不能把危险的动态输出电流扰动持续闭回GFM电压环。**

而且它还有第二个维度：

> **这个准稳态工作点究竟在什么时候捕获？**

过去我们反复修F20，本质上一直在两个维度之间来回补洞：

```text
维度A：信号语义
raw瞬时值？
低通值？
20 ms mean？
candidate？

维度B：事件时机
GFL时冻结？
GFM并网时冻结？
J1前最终工作点冻结？
J1后估计？
```

此前没有一个版本同时把：

```text
“正确的工作点估计”
+
“正确的捕获时机”
+
“J1后绝不continuous tracking”
```

三个条件完全闭合。

因此F20没有完全冻结，不是因为我们“不知道它干什么”，而是因为：

> **我们直到V25A5以后才真正把其它handover干扰清理干净，才有资格单独判断F20最终工作点时机到底是不是剩余问题。**

## 0.3 五台GFL零P/Q是不是最终目标？

**绝对不是。**

最终工程目标仍然是：

```text
ESS1 = GFM
PV1 / PV2 / ESS2 / EV1 / EV2 = GFL
并且五台正常承担非零P/Q
```

V25A5就是当前正常有功工作点的A3基线。

五台零P/Q只是一种**诊断中间态A2**，目的不是运行系统，而是回答：

> **如果五台GFL仍然物理在线、PLL和Current Loop都还存在，但它们不承担有功/无功工作点，系统还会不会失稳？**

它用于把：

```text
“GFL支路动态存在”
```

与：

```text
“非零功率工作点/恒功率特性”
```

分离开。

## 0.4 五台物理隔离的意义是什么？

五台物理隔离A1回答：

> **五台非主GFL支路是不是V25A5失稳的必要参与条件。**

A1不是重新验证“ESS1会不会构网”。

Gate A已经证明ESS1可以从dead bus形成稳定孤岛。

A1验证的是：

```text
当前最终F21/F22/F24/PQ-COMMIT全部正确以后

ESS1 + passive network
是否能承受：

strong grid CLOSED
→
hard J1 OPEN
```

即**当前最终基线下的single-GFM live-transfer**。

而且当前模型已经能做到真正物理隔离：

```text
CFG_DIAG_AC_CONNECT_PV1
CFG_DIAG_AC_CONNECT_PV2
CFG_DIAG_AC_CONNECT_ESS2
CFG_DIAG_AC_CONNECT_EV1
CFG_DIAG_AC_CONNECT_EV2
```

这些参数控制各非主变流器：

```text
AA15_DIAG_AC_BREAKER_*
```

Gate A历史上已经从第一次Execute之前把它们断开并成功运行。

所以：

> **A1的物理隔离操作本身不是未知能力；真正要小心的是隔离以后PCC预平衡语义，因为当前AGC不知道设备已经被断开。**

# 1. F20到底是什么：从电容电压控制方程开始

## 1.1 F20不是独立的“外环控制器”

F20位于：

```text
SS_Slave2/ESS1_Control/
AA15_F8_VOLTAGE_LOOP_FEEDFORWARD/
F20_IOUT_DYNAMIC_CONDITIONER
```

后来又增加：

```text
AA15_F8_VOLTAGE_LOOP_FEEDFORWARD/
AA15_F20_V2_STATE_MANAGER

AA15_F20_V2_SELECT_ACTIVE

AA15_F8_VOLTAGE_LOOP_FEEDFORWARD/
AA15_F23_WORKPOINT_ESTIMATOR

AA15_F8_VOLTAGE_LOOP_FEEDFORWARD/
AA15_F23_COMMIT_MANAGER
```

所以必须先明确：

> **F20不是Voltage PI本身，也不是Current PI本身。**

它是在F8的：

```text
output-current feedforward
```

支路上管理“输出电流前馈工作点”的模块。

---

## 1.2 为什么Voltage Loop本来就需要Iout feedforward？

ESS1 local C1节点可以抽象为：

```text
inductor current iL
        │
        ▼
       C1
        │──────────→ network/output current iout
        ▼
       vC
```

电容电压变化由：

```text
iL - iout
```

决定。

如果负载/网络需要：

```text
iout = 0.1 pu
```

而Voltage PI不知道这个负载电流，那么Voltage PI必须自己不断积分：

```text
“电压有一点掉”
→ 增加Iref
→ 再看电压
→ 再增加
→ 最终慢慢积分出约0.1 pu
```

这就是为什么F17：

```text
F9 mapping
+
CAP compensation
+
IOUT=0
```

虽然稳定，却严重Formation lag。

F18把Iout feedforward补回来以后，Formation才真正跟上Ramp。

---

## 1.3 当前F18/F8完整current-reference结构

当前最终控制律的核心可以写成：

```text
Id_ref = -u2 + Iout_d - Bc·Vq
Iq_ref = +u1 + Iout_q + Bc·Vd
```

其中：

```text
u1/u2
= Voltage PI动态纠偏量

Iout_d/q
= 经过方向归一化、再经过F20处理后的output-current feedforward

[-Bc·Vq,+Bc·Vd]
= C1 dq同步旋转补偿
```

实现中Measurement6/output-current方向与控制器定义相反，因此F8使用：

```text
F8_IOUT_GAIN = -1
```

先把测量翻成控制器正方向。

所以F8的职责是：

> **让Current Loop看到的current reference，一开始就包含大部分稳态网络电流，只让Voltage PI负责“剩余动态电压误差”。**

# 2. 为什么“直接实时Iout feedforward”又会出问题？

## 2.1 理想数学里它很好

理想情况下：

```text
iL* = iout + capacitor-required-current
```

负载电流一变：

```text
iout变化
→ iL*立即跟
→ vC不需要明显跌落
```

这是理想负载电流前馈。

---

## 2.2 真实模型里iout不是一个静态常数

真实微电网中的iout包含：

```text
稳态负载/网络电流
+
50 Hz/谐波
+
GFL控制互动
+
PLL动态
+
LC/Transformer模态
+
测量噪声
+
控制延迟
+
拓扑切换瞬态
```

写成：

```text
iout = Iout_DC/quasi-steady + Δiout_dynamic
```

如果F8把全部：

```text
Δiout_dynamic
```

毫无约束地又加到Current Reference，就形成：

```text
bus/network动态
→ measured iout
→ current reference
→ converter voltage/current
→ bus/network动态
```

新的闭环。

这个闭环会直接改变GFM的等效输出阻抗。

---

## 2.3 历史数据已经证明continuous tracking有害

早期Gate A长Hold：

```text
F20 MODE0
持续RAW IOUT动态反馈
```

出现：

```text
约3.4 Hz指数增长
```

所以可以正式冻结：

> **J1后/Established island持续raw IOUT tracking不能恢复。**

这不是猜测，是历史主动因果结果。

# 3. F20为什么一直改不好：因为它其实有“两张二维表”要同时解决

## 3.1 维度一：工作点怎么估计？

候选有：

```text
A. instantaneous raw
B. filtered raw
C. Host rolling mean
D. SS2 local 20 ms mean
E. 40 ms quasi-steady candidate
```

过去错误包括：

### F20 V2

名义上像“工作点管理器”，但实际代码曾：

```text
est_d = raw_d
est_q = raw_q

capture:
bias_d = raw_d
bias_q = raw_q
```

所以：

> 名字叫estimator，实际还是瞬时raw capture。

### V19B

Host 1 ms rolling mean又受到采样相位影响。

曾误认为：

```text
J1后稳定DC shift ≈0.026 pu
```

后来SS2本地全样本20 ms窗口V20D证明实际：

```text
mean-bias≈0.002~0.003 pu
```

所以“大DC shift”旧解释被否决。

---

## 3.2 维度二：什么时候捕获？

候选有：

```text
A. ESS1仍GFL时
B. ESS1刚切GFM时
C. ESS1 GFM + J1 CLOSED强网准稳态
D. F24 READY + PCC近零最终pre-open
E. J1 OPEN后
```

不同工况需要的答案不一样。

Gate A：

```text
dead bus Formation
```

最自然：

```text
Formation期间track
→ established island后hold
```

而planned live-transfer：

```text
强网已经带电
→ ESS1先GFM
→ PCC prebalance
→ J1才开
```

这时最合理的held workpoint很可能应该来自：

```text
“ESS1已经成为GFM、J1仍闭合、最终pre-open准稳态”
```

而不是更早的GFL状态。

这正是当前仍未完全关闭的F20问题。

# 4. F20历次版本分别解决了什么、没解决什么？

| 版本/阶段 | 做法 | 解决了什么 | 剩余缺陷 |
|---|---|---|---|
| F8原始Iout FF | continuous Iout feedforward | F18 Formation能跟Ramp | Established后动态Iout重塑阻尼 |
| F20 MODE0 | 持续RAW | 保留快速负载前馈 | 实测3.4 Hz负阻尼，否决 |
| F20 MODE1 | Formation track，随后hold bias | Gate A长Hold稳定，3.4 Hz退出 | capture时刻依赖场景；live-transfer最终时机未闭合 |
| F20 MODE2 | slow/filtered dynamic Iout | 尝试折中 | 出现更慢0.3~0.5 Hz问题，不作为当前正式结构 |
| F20 V2 | explicit enable/capture/selected | 事件式控制更清楚 | capture仍是instantaneous raw |
| V19B Host workpoint | Host rolling mean | 试图找J1后workpoint | Host alias/相位导致假大shift |
| F23 | SS2 local 20 ms mean/std/drift + candidate + commit | 真正解决“工作点估计”语义 | 当前gate主要面向J1 OPEN + F22 ack，不是pre-open最终capture工具 |
| V25A5 | Legacy F20固定，F20V2/F23 OFF | 保证Reference-Handover实验单变量 | Legacy bias在ESS1仍GFL时冻结，最终capture时机仍可讨论 |

所以：

> **我们不是“每次推翻前一次F20”；实际上每次都修掉了一层不同错误。**

真正一直没有完全解决的是：

```text
pre-open最终quasi-steady workpoint
应该怎样本地估计、在什么事件捕获、怎样在J1后hold
```

# 5. 现在所谓“完美F20”必须满足什么？

以后不能再看到一个新现象就临时设计F20。

最终F20至少必须同时满足六条。

## 5.1 Source正确

输入是：

```text
ESS1真正local output-current state
```

方向经：

```text
F8_IOUT_GAIN=-1
```

统一到控制器正方向。

---

## 5.2 不能直接capture raw

必须有：

```text
local full-rate estimator
```

至少：

```text
20 ms mean
+
window drift
```

不能再用Host瞬时值。

---

## 5.3 candidate必须在“最终ownership状态”里形成

对planned live-transfer，候选更合理的状态是：

```text
ESS1已经GFM
J1仍CLOSED
F21已经完成
F24已经PREALIGN/READY
PCC已接近最终工作点
```

而不是：

```text
ESS1仍GFL
```

但这一点仍需因果验证，不能现在直接改模型宣布最终答案。

---

## 5.4 capture以后必须Hold

J1 OPEN以后：

```text
禁止raw continuous tracking
```

这是已冻结结论。

---

## 5.5 如果未来需要dynamic residual，必须单独设计

可能最终出现：

```text
quasi-steady Iout bias
+
受限/带阻尼的dynamic residual
```

但这个dynamic residual绝不能等同于：

```text
raw Iout
```

它必须有：

- 明确带宽；
- 相位裕度；
- 限幅；
- slew；
- 与GFM output impedance的阻尼解释。

在没有这些分析前，不添加。

---

## 5.6 F20最终关闭条件

只有当下面被验证，才能说“F20正式冻结关闭”：

```text
A. capture signal是quasi-steady，不是raw
B. capture timing在最终pre-open状态正确
C. J1边沿bias不跳
D. post-open不continuous track
E. A1/A3中不再出现由F20时机引起的明显差异
F. 不再需要F23/F20V2作为诊断补丁
```

目前：

```text
A、D基本知道怎么做
B仍未正式因果闭环
```

所以现在不能为了“想结束F20”而过早冻结。


> planned islanding前先让PCC交换功率接近0。

```text

```

## 7.2 P/Q COMMIT HOLD

位置：

```text
SM_Master/AA15_LOCAL_CONTROL_STACK/
AA15_PLAN_P_COMMIT_HOLD

SM_Master/AA15_LOCAL_CONTROL_STACK/
AA15_PLAN_Q_COMMIT_HOLD
```

```text
COMMIT_STATE_MANAGER
ROUTER_1 ... ROUTER_6
```

控制：

```text
CFG_PLAN_COMMIT_ENABLE
CFG_PLAN_COMMIT_HOLD_REQ
```

原来为什么不对？

因为：

```text
PCC穿过0以后
AGC仍继续调
```


```text

→ 立即COMMIT

```

这个结构现在是正确且应保留的。

# 32. 最终给下一窗口的一段话

> 当前不要把F20理解成“反复设计失败的一个模块”。它其实是在解决一个经典但困难的矛盾：Voltage Loop需要输出电流前馈承担稳态负载电流，但持续动态输出电流反馈又会改变GFM输出阻抗并造成负阻尼。历史MODE0证明continuous raw tracking错误；MODE1证明track→hold可以让Gate A稳定；V20D又否决了大DC工作点迁移；当前唯一未完全闭环的是planned live-transfer里最终held workpoint应该在什么状态以什么quasi-steady estimator捕获。V25A5故意保持Legacy F20不变，是为了先把Reference Handover单变量验证完。因此A1首先不改F20。若A1失败，也不要直接把raw F20 tracking延长到GFM强网阶段，因为V7历史已经证明这会严重放大强网交互。应先用当前高速数据做B0只读workpoint decomposition，再决定是否值得设计一个“GFM+J1 CLOSED+F24 READY下的local quasi-steady pre-open capture”。  
>
> 五台0PQ不是最终运行要求；它只是A2诊断条件。最终系统必须五台正常承担P/Q，当前A3=V25A5已经完成并失败。A1物理隔离用于判断五台branch是否是失稳必要条件，Gate A历史已经证明这些诊断breaker可以在first Execute前安全隔离，但A1的真正难点是AGC不感知availability，所以必须只用真实PCC做prebalance准入。A1 PASS再做A2；A1 FAIL先比较故障签名，并进入F20/Voltage Loop/hard-topology的只读分解，不机械重复旧试验。
