# 8.23｜F1正式Patch执行说明：一次Build、OpWrite不扩展、失败先回滚

## 1. 本轮正式脚本

只使用：

```text
PATCH_K26_V5_F1_GFM_DAMPING_PLATFORM_V1.m
```

它基于当前已经成功运行D1的 `K26_V5`。

---

## 2. 它会先做什么？

在修改任何模型结构之前，它先完整检查：

```text
D1诊断结构仍完整
Group29仍30输入
Group29仍5 kHz
Group29 file_size仍150 MB
Group28不变

Vdq原500 Hz Filter仍只→VdVq_meas
Idq原500 Hz Filter1仍只→IdIq_meas

Current Regulator：
Add2仍直接→原Saturation
原Saturation仍→VdVq_conv

inv仍：
Converter→inv→L1

Measurement6仍：
Stubline A/B/C → Measurement6 → a/b/c LC节点

Pnom=100 kVA
Vnom_sec=480 V
Measurement6 Pbase=450 MVA
Measurement6 Vbase=60 kV
```

最重要的是：

> **它会在任何编辑之前尝试读取Measurement6实际Mask Workspace中的 `Ki`，验证具体SPS块确实使用峰值瞬时电流pu公式。**

如果这一步无法解析：

```text
脚本直接停止
模型不改
Build=0
```

把完整输出发回来即可。

这比猜量纲后再返工安全。

---

## 3. 为什么此前120.28 A现在改成170.10 A？

120.28 A是：

```text
100 kVA / (sqrt(3)×480 V)
```

即RMS电流基值。

但当前GFM本身的电流标幺Gain已经明确：

```text
Vnom_prim*sqrt(3)/(Pnom*sqrt(2))
```

它对应的是：

```text
峰值瞬时电流基准
```

所以低压侧inv进入同一控制pu应该使用：

```text
Ibase_peak
≈170.103 A
```

Measurement6的自身pu基准也使用峰值后，两套基值的比例仍为：

```text
36
```

因此最终关系：

```text
iC_pu
=
inv_I_A / 170.103...
+
36 × M6_Ipu
```

但正式脚本仍会先验证M6实际 `Ki`，不会直接相信理论。

## 4. F1实际增加什么？

### 滤波器组三模式

```text
F1_FILTER_MODE=0 → 原500 Hz
F1_FILTER_MODE=1 → 800 Hz
F1_FILTER_MODE=2 → 1000 Hz
```

只作用于GFM正式：

```text
VdVq_meas
IdIq_meas
```

不全局修改 `fn_Filter`。

---

### 本地电容电流主动阻尼

```text
inv Iabc
+
Measurement6 Iabc
↓
统一到ESS控制pu
↓
iCabc
↓
GFM同一Droop角abc→dq
↓
iCdq
↓
K_AD / SIGN / ENABLE
↓
GridOn=0门控
↓
Current Regulator
```

最终插入：

```text
原Add2
+
V_AD_dq
↓
原final Saturation
↓
VdVq_conv
```

## 6. OpWrite本轮完全不改

这是正式决策。

仍然：

```text
Group29
30 signals + time
31 rows
5 kHz
file_size=150000000
d1_gfm_superpack_data.mat
```

不新增：

```text
Group30
Group31
第二个OpWrite
```

也不为了记录F1参数把30维Mux改成33维。

这样降低Build风险。

## 7. 文件大小

66 s：

```text
约80～90 MB
```

20 s：

```text
约25～30 MB
```

所以后续参数扫描会使用短工况。

```text

```

```text

→ 重命名/复制
→ 再开始下一轮
```

后续会做专用F1 runner自动完成。


## 10. 如果Pre-flight在Ki检查处停止

这是**安全停止**，不是模型修改失败。

因为这发生在：

```text

```

把完整输出发回来。

不要手动改模型。
