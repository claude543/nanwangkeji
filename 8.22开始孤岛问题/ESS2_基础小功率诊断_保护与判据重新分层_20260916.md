# ESS2 基础小功率正式检验：保护与诊断逻辑重新分层

日期：2026-09-16

## 1. 结论

当前阶段的目标不是让模型自己判断“稳不稳定”，而是让模型按固定、可重复的顺序完成一次基础小功率试验，再用 G27/G29/G30 的 MAT 数据判断系统响应。

因此，前一版把 V/f/I/P 的健康条件直接写进 Restore Executor，并让它们决定 state5/state6/state7 是否继续、是否 Fail，属于把“最终自治恢复控制器”与“当前诊断试验”混在了一起。

本轮应改成：

- 模型负责执行确定的实验时序；
- 物理限流、调制饱和、电流闭环等真实控制行为继续保留；
- 同期与真实合闸的必要前置条件继续保留；
- 小功率试验开始以后，不再因普通电压/频率/功率波动提前终止；
- V/f/I/P 健康量继续记录，但只作为事后分析证据；
- Python 只负责运行、目标机时间、计划暂停和保存证据，不给出电气 PASS/FAIL；
- 只有数值无效、RT-LAB 执行错误或控制合同失效等“试验本身已经不可信”的情况才提前停止。

## 2. 为什么之前的逻辑不适合本轮

当前恢复执行器：

`K26_K50_CLEAN_P1/SS_Slave2/AA15_ESS2_RESTORE_EXECUTOR/CORE`

曾同时承担两种职责：

1. 控制恢复顺序；
2. 根据 V/f/I/P 判定系统是否“足够健康”。

这对最终无人值守恢复控制器是合理方向，但对当前研究试验不合理。

例如本轮真正想研究：

> ESS2 在附加支撑已隔离的条件下，从 P=0 缓慢到 -0.005 pu 后，电压、频率、电流和功率会怎样变化？

如果模型要求：

> 电压先必须始终处在某个范围、功率误差先必须满足某个范围，否则不允许进入试验或直接 Fail，

那么模型已经在试验发生之前替我们下了结论，MAT 中最有价值的失稳过程反而被截断。

这形成了逻辑循环：

`要做稳定性试验 -> 先要求满足稳定性阈值 -> 才允许试验继续`

当前阶段不应这样设计。

## 3. 正确分层

### 3.1 仍然保留：真实控制和物理约束

这些不是“试验判据”，而是系统本体：

- ESS1 GFM 建压；
- ESS2 同期和真实断路器合闸；
- ESS2 电流闭环和真实电流反馈；
- 动态电压前馈和坐标处理；
- `AA15_FINAL_GFL_LIMIT_CORE` 中真实总电流限幅；
- 调制度限制、CurrentLimit 等控制器本身的饱和行为；
- 本轮已经完成的四路附加支撑隔离。

它们发生时应被记录，而不是因为发生就让实验脚本提前宣布失败。

### 3.2 改成只记录：普通电气健康量

以下量继续完整记录，但在本轮基础小功率诊断中不再直接决定试验中止：

- Vpu 是否越过 0.9/1.1 或 0.8/1.2；
- PLL/frequency 的普通偏移；
- Pmeas 与 Pref 的误差；
- Iref/Imeas 是否接近原恢复资格边界；
- CurrentLimit 是否短时动作；
- ModHeadroom 是否下降；
- `pickupOK`、`zeroStableOK` 等资格量。

它们应成为 MAT 分析变量，而不是“试验是否有资格发生”的门。

### 3.3 仍可提前停止：试验已经失去可解释性

只保留非常少的提前停止条件：

- NaN/Inf；
- RT-LAB 执行/通信错误；
- 状态机进入不可能状态或控制合同明显失效；
- 本轮明确禁止的控制权意外接管；
- 操作员主动停止。

这些表示“数据已经不可信或实验已经不是原计划”，不是对电气稳定性的评价。

## 4. 下一版正式诊断时序

### 阶段A：既有建压、同期、真实合闸

沿用已经验证的流程，不重新设计。

### 阶段B：合闸后固定等待

进入 connected-zero 后，只用固定目标机时间把“合闸瞬态”和“基础电流放行”分开。

这一等待只是实验时序，不表示稳定判定。

### 阶段C：基础控制开放，P=0

`RestoreAlpha = 1`，附加支撑仍被隔离，Pref 保持 0。

固定观察一段目标机时间，例如现有设计中的 5 s。

不因普通 V/f/P 波动提前 Fail。

### 阶段D：固定小功率

Pref 按已有 Rate Limiter：

`0 -> -0.005 pu`

名义约 2 s 到目标。

达到目标的判定使用“命令本身到达目标”，不使用 Pmeas 跟踪误差作为继续运行资格。

### 阶段E：固定平台

命令到达 -0.005 pu 后固定记录约 30 s。

无论波形是：

- 收敛；
- 有界振荡；
- 缓慢漂移；
- 明显发散；

只要数值仍有效、RT-LAB仍可运行，就让记录继续到计划结束。

最后由 MAT 判断结论。

## 5. state7 在本轮不应成为必要条件

`state7 = 本地恢复完成` 是面向未来自动交权给 Coordinator 的资格状态。

但本轮明确：

- 不交权；
- 不开一次协调；
- 不开二次恢复；
- 不恢复其他设备。

因此本轮没有必要要求 `state7` 才能完成基础小功率试验。

最干净的做法是：

- 本轮可一直保持 Restore state6（基础电流已开放）；
- S14 的 30 s 平台计时由外部 Pref 到达 -0.005 pu 后开始；
- state7/pickupOK 仍可计算并记录，但不控制本轮时序。

这避免“我们正在验证它是否能稳定跟踪 -0.005 pu，却先要求它通过 pickupOK 才允许继续记录”的循环。

## 6. Python 的正确职责

LEAN Runner 应恢复到此前成熟用法：

1. 从当前 Build 动态发现必要接口；
2. t=0 写入并回读本轮固定配置；
3. Execute；
4. 以目标机时间采样少量状态；
5. 不根据普通 V/f/P/I 波动提前中止；
6. 到计划结束时间 Pause；
7. 保留并分析 G27/G29/G30；
8. Python 明确写 `NO_ELECTRICAL_VERDICT`。

Python 不应成为另一个稳定性控制器。

## 7. 对现有 R1E 的处理

R1E 仍然沿用了“持续 severe -> Fail”的自治保护思路。

它比“一拍即 Fail”合理，但仍不符合当前基础小功率**诊断试验**的核心目的。

因此：

**在采用本文件的新原则后，不建议继续执行 R1E。**

下一版应直接做一个更小的“Diagnostic Observe Mode”定点修改：

- BASETEST 模式下，不让普通 V/f/I/P 健康判据驱动 state5/6/7 Fail；
- 不要求 state7 才能进入/完成 30 s 小功率平台；
- 保留所有健康量为诊断输出；
- 非 BASETEST 模式维持原自动恢复语义，不影响以后正常自治恢复设计。

## 8. 最终一句话

当前阶段正确的问题不是：

> “模型什么时候认为自己已经稳定？”

而是：

> “在固定控制结构、固定功率命令和固定观察时间下，系统真实响应是什么？”

先把完整响应记录下来，再由 MAT 数据回答稳定性。
