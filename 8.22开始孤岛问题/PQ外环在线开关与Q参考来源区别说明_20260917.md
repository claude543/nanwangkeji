# 为什么P外环开关有效，而Q外环“开了却可能不动作”

> 日期：2026-09-17  
> 工程：`yanshou_V7 / K26_K50_CLEAN_P1`

# 0. 结论

不是：

```text
P在线开关有效
Q在线开关无效
```

而是：

```text
P/Q在线开关都有效
```

但它们只控制：

> **这个PI外环是否允许响应当前误差。**

它们不负责决定：

> **误差里面的参考值到底是什么。**

真正差异来自 P 和 Q 的参考来源。

---

# 1. P外环为什么一打开就真的工作

P有功外环的核心误差：

```text
Perror
=
PrefEff - Pmeas
```

再乘：

```text
RestoreAlpha
×
P_LOOP_ENABLE
```

所以实际类似：

```text
Perror_applied
=
RestoreAlpha
× P_LOOP_ENABLE
× (PrefEff - Pmeas)
```

当前黑启动基础试验中：

```text
PrefApplied / PrefEff
```

来自 S14 的有功任务。

例如：

```text
先 0
之后 0 → -0.005 pu
```

这个参考值不是自动设置为：

```text
Pmeas
```

因此只要：

```text
Pmeas ≠ PrefEff
```

就会有真实 P 误差。

于是：

```text
P_LOOP_ENABLE = 1
```

以后：

```text
Perror
→ P PI
→ RawPowerCurrent_P
→ d轴电流参考
→ Current Adapter
→ Current Regulator
```

P外环就真正参与控制。

这就是为什么 P0 中虽然：

```text
Pref = 0
```

但只要：

```text
Pmeas ≠ 0
```

P PI 就会不断动作，最后我们才能观察到 Ki=2 导致的低频负阻尼。

---

# 2. Q外环现在为什么不同

Q无功外环的误差形式不是：

```text
0 - Qmeas
```

而是当前模型符号约定下的：

```text
Qerror
=
Qmeas - QrefEff
```

关键在：

```text
QrefEff
```

不是直接固定为我们口头说的：

```text
Qref = 0
```

它前面还有：

```text
Qref selector
（无功参考选择器）
```

和孤岛 Stage 逻辑。

当前 ESS2-GFL-Stage2 中，保存模型的无功参考选择逻辑会让：

```text
qsel = Qmeas
```

然后后一级形成：

```text
QrefEff
≈
Qmeas
```

因此：

```text
Qerror
=
Qmeas - QrefEff
≈
0
```

---

# 3. 所以Q在线开关打开以后发生什么

我们已有：

```text
CFG_E2_DIAG_Q_LOOP_ENABLE
```

它控制的是：

```text
Q effective alpha
=
RestoreAlpha
× Q_LOOP_ENABLE
```

所以：

```text
Q_LOOP_ENABLE = 0
```

确实是把 Q PI 的误差门控掉。

而：

```text
Q_LOOP_ENABLE = 1
```

也确实把门打开。

但是如果门后面的误差本来就是：

```text
Qmeas - QrefEff
≈
Qmeas - Qmeas
≈
0
```

那么：

```text
门虽然打开
↓
但是没有误差信号
↓
Q PI基本没有动作
```

所以问题不在：

```text
Q_LOOP_ENABLE失效
```

而在：

```text
Qref来源仍然是Stage2的“跟踪Qmeas”逻辑
```

---

# 4. 一个最简单的类比

把 PI 外环看成司机。

```text
P_LOOP_ENABLE / Q_LOOP_ENABLE
```

相当于：

> 是否允许司机踩油门/刹车。

但是：

```text
Pref / Qref
```

相当于：

> 导航告诉司机目标速度是多少。

P外环现在是：

```text
目标速度 = 0 或 -0.005
当前速度 = Pmeas
```

两者不一样：

```text
有误差
→ 司机会动作
```

Q外环当前 Stage2 却类似：

```text
目标速度 = 当前速度
```

即：

```text
QrefEff = Qmeas
```

于是：

```text
目标 - 当前 = 0
```

你即使把“允许司机控制”打开：

```text
Q_LOOP_ENABLE=1
```

司机也会认为：

> 已经到目标了，不需要调。

---

# 5. 为什么模型原来会这么设计Q

这是历史孤岛工程设计的一部分，不是Q开关的bug。

当时为了避免 GFL（跟网型）进入弱孤岛时，原有 Q PI、旧 Qref、无功偏置等突然产生新的 q轴电流冲击，Stage2/Stage3一度采用：

```text
QrefEff跟踪当前Qmeas
```

本质上是：

> **先把 Q 功率误差冻结到接近0，让无功外环不要在恢复初期突然抢控制。**

这个设计对：

```text
安全进入弱孤岛
```

是有目的的。

但现在我们已经到了新的问题：

> **要正式验证Q外环本身能不能承担一个零无功目标。**

这时继续：

```text
QrefEff = Qmeas
```

就不合适了，因为它把我们要测试的 Q 误差自动消掉了。

---

# 6. 为什么P没有同样的问题

P的 S14 V2 已经专门建立了：

```text
P_S14
→ Pickup Rate Limiter
→ Ownership Blend
→ Pfinal / PrefApplied
→ ESS2 Power Loop
```

所以 P 有一个独立、明确的外部功率任务：

```text
0
→ -0.005 pu
```

而不是：

```text
PrefEff = Pmeas
```

因此 P Loop 一开：

```text
PrefEff - Pmeas
```

真实存在。

Q目前还没有一条与之等价的：

```text
Q_S14 = 0
→ Qfinal
→ Qref selector override
→ QrefEff
```

正式诊断路径。

这就是两者结构上的本质差异。

---

# 7. 所以我们现在到底缺什么

不是再增加一个：

```text
Q_LOOP_ENABLE
```

因为这个已经有了。

缺的是：

> **在BASETEST / Q正式验收条件下，让Q参考明确来自我们希望测试的目标 `Qref=0`，而不是Stage2自动跟踪Qmeas。**

最小设计：

```text
原：
Stage Qref selector
→ qsel
→ Final GFL State
→ QrefEff

新增仅诊断选择：
              ┌─ 原 qsel
QREF_ZERO_SEL ┤
              └─ 0
                  ↓
           Final GFL State
                  ↓
              QrefEff
```

在线开关例如：

```text
CFG_E2_DIAG_QREF_ZERO_ENABLE
```

正常默认：

```text
0
```

Q验收：

```text
1
```

于是我们才真正得到：

```text
外部Q目标 = 0
Q Loop = ON
```

这个有物理意义的工况。

---

# 8. 为什么不能直接把QrefEff硬改成0

因为当前还有：

```text
GammaQ
BaseScaleQ
current capability
```

等正常限权机制。

我们应该改变的是：

```text
“原始目标来源”
```

而不是绕过整套有效参考算法。

因此正确做法是：

```text
qsel = 0
```

然后仍然让原来的：

```text
QrefEff算法
GammaQ
BaseScaleQ
```

继续工作。

这样真正的有效Q误差可能是：

```text
Qerror
≈
GammaQ × Qmeas
```

而不是简单粗暴：

```text
Qerror = Qmeas
```

这保留了当前系统的实际能力约束。

---

# 9. 当前一句话

> **P/Q在线外环开关本身都没有问题。P外环之所以一打开就真正工作，是因为P参考由S14独立给定，通常不等于Pmeas；Q外环虽然也能打开，但当前Stage2的Q参考选择器会让QrefEff跟踪Qmeas，于是Q误差接近0，Q PI没有真正的调节任务。因此我们现在缺的不是“Q开关”，而是一个最小的“Qref=0参考来源覆盖接口”，让Q外环在保持Stage2其它弱网控制不变的条件下真正看到零无功目标。**
