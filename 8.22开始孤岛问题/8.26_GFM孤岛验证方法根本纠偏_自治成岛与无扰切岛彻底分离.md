# 8.26｜GFM孤岛验证方法根本纠偏
## ——“ESS1能否形成孤岛”与“当前并→离网切换为什么失败”必须彻底分开

# 0. 结论

用户提出的三个质疑中，第1和第3点是对当前验证方法最关键的纠偏。

必须正式修正此前的表述：

# A0/B0/B1/B2从来没有真正证明“ESS1没有孤岛能力”。

它们证明的是：

# “ESS1在健康强网GFM工作点下，J1带着非零边界电流/复功率突然打开时，grid-to-island transfer失败。”

这是：

```text
并网→孤岛切换能力
```

不是：

```text
孤岛自治运行能力
```

两者不能再混为一谈。

这也是为什么过去几轮虽然不断获得有价值信息，却始终没能回答用户最关心的：

> “ESS1自己到底能不能把这个岛撑起来？”

因为此前的实验设计没有把这两个问题正交分开。

---

# 1. 用户问题1：如果连五台被动支路都带不起来，证明纯ESS1能孤岛有什么意义？

## 用户这个质疑是正确的

此前提出：

```text
静态切掉五台高压Transformer/Stubline
→ 做pure ESS1 autonomous C0
```

作为下一步主实验，不够合理。

原因有三点。

---

## 1.1 最终系统本来就包含这五条支路

最终微网不是：

```text
只有ESS1
```

而是：

```text
PV1
PV2
ESS1
ESS2
EV1
EV2
+
全部Transformer/Stubline/network
```

如果为了证明ESS1控制器本身稳定而把五条高压支路全部删掉，

最终只能证明：

```text
ESS1在一个更简单Plant上稳定
```

不能证明：

```text
真实微网能够稳定。
```

所以它只有“局部控制器诊断”价值，

不是最终工程验证。

---

## 1.2 直接静态断开高压Stubline支路还有实时分区风险

当前：

```text
1 SM + 3 SS
```

之所以能在100 us下实时运行，

与现有：

```text
Stubline
SSN
partition boundary
```

结构紧密相关。

为了做一个纯ESS1实验去重构五条Stubline电气边界，

会重新打开：

```text
SSN分组
物理网络拓扑
分核边界
Build稳定性
```

这些已经冻结的工程风险。

因此：

# 不应该为了根因定位破坏现有Stubline分核结构。

这一点用户判断是对的。

---

## 1.3 更关键：目前并没有证据表明ESS1“稳态带不起15 kvar”

B2在J1打开前五台被动Transformer残余约：

```text
S_5tr ≈ -2.77 + j15.43 kVA
```

ESS1额定：

```text
100 kVA
```

所以仅从容量看：

```text
15.4 kvar ≈ 0.154 pu
```

远没有超过ESS1能力。

当前失败是：

```text
J1瞬时开断
→ 原来由Grid承担的一部分电流/无功突然转给ESS1
```

而不是已经证明：

```text
ESS1在稳定孤岛中无法长期输出15 kvar。
```

这两个命题完全不同。

所以不能说：

```text
“带不起五台被动支路”
```

我们目前只知道：

```text
“不能在当前非零边界功率条件下无扰接管它们。”
```

---

# 2. 更准确理解五台被动支路

五台低压breaker打开以后：

```text
Converter
L/C
PLL
Current controller
PWM
```

已经从公共母线动态中移除。

但：

```text
Transformer
Stubline
high-side passive network
```

仍然保留。

因此A0/B1/B2不是：

```text
pure ESS1
```

准确名称应该改成：

# ESS1-dominant island-transfer test

即：

```text
ESS1作为唯一主动电源
+
真实五台被动高压残余网络
+
从强网突然切岛
```

这个工况本身很有工程价值，

但它测试的是：

```text
ESS1能否接管真实被动岛网
```

不是：

```text
ESS1空载自治小信号稳定性
```

# 3. 用户问题2：旧Supervisor是不是只有Vref真正进了IO_MUX？


所以：

# 4. 但Supervisor Fref并没有因此彻底失效

因为S15后来建立了新的Fref路由。

最新SLX实际链路是：

```text
Microgrid Supervisory Control
out1 = Fref
        ↓
AA15_S15_LEGACY_FREF_GOTO
tag = AA15_S15_LEGACY_FREF_SUP
        ↓
AA15_S15_Master_Fref_Router
        ↓
AA15_S15_FINAL_FREF_ESS1
        ↓
AA15_S15_FINAL_FREF_ESS1_TO_MUX
        ↓
ESS1_IO_Mux12 input3
        ↓
ESS_Group_Mux24
        ↓
SS_Slave2 ESS1_IO_Demux output3
        ↓
ESS1_Control input3
        ↓
Fref
```

而S15 Fref Router代码在：

```text
recovery_active <= 0.5
```

时默认：

```text
f1 = legacy_fref
f2 = legacy_fref
```

因此正常非恢复工况下：

# Supervisor Fref仍然通过S15新的Fref route进入ESS1。

```text
Vref肯定进入ESS1 Control
```

这一点没有争议。

此前把：

```text

```

写成一个新的“根因”，也过快。

正确定位应该是：

会改变：

```text

```

不能一边说：

```text

```

一边让它后台运行。

# 7. 用户问题3：现在是不是连一台ESS1都无法建立孤岛？

# 不是。

这是当前最重要的逻辑纠正。

我们到现在从未真正执行过：

# “J1已经打开，然后ESS1从无电压/低电压开始建立并维持一个岛网”

这样的实验。

A0/B0/B1/B2全部是：

```text
强网存在
↓
ESS1先并联GFM
↓
PCC约10 kV
↓
J1突然打开
```

所以它们测试的是：

# grid-to-island transition

不是：

# autonomous island formation

---

# 8. 这两个能力为什么完全不同

一个GFM可以：

```text
在J1已经打开时
慢慢把一个无电压岛网建立到10 kV / 50 Hz
```

但仍然可能：

```text
在J1带着非零P/Q/current时突然打开
→ 因电流状态不能瞬间改变
→ 切岛失败
```

反过来也可能：

```text
切换瞬间处理很好
```

但自治输出阻抗本身不稳定，

几百ms以后仍振荡。

所以必须分成两个独立命题：

---

## 命题A：ESS1 autonomous formation capability

```text
J1先OPEN
↓
没有强网钳位
↓
ESS1自己建立V/f
↓
能否稳定带当前真实被动岛网
```

---

## 命题B：seamless grid-to-island transfer capability

```text
J1 CLOSED
↓
ESS1与Grid并联
↓
P/Q/current预平衡
↓
打开J1
↓
是否无扰接管
```

过去我们一直主要在做命题B，

却不断用B的失败来推断A。

这是最近验证方法真正需要纠正的地方。

---

# 11. Level A：先证明自治成岛能力

## A-ISLAND-START

保持现有真实电气结构：

```text
五台Transformer/Stubline不删
SSN/Stubline分核不改
```

五台低压诊断breaker可以保持OPEN：

```text
五台active GFL controller暂时不参与
```

所以岛内仍有：

```text
五台真实被动Transformer/Stubline residual
```

约15 kvar。

这反而是一个合理、保守、与最终系统相关的被动岛网负担。

---

## 关键不同

不是：

```text
J1在10 kV强网下突然打开
```

而是：

```text
J1一开始就OPEN
```

然后：

```text
ESS1直接进入GFM
```

用受控Vref ramp：

```text
0 / 较低电压
→
逐步提升到10 kV
```

而不是一步10 kV。

这样：

```text
没有Grid→Island边界电流step
```

只回答：

# ESS1本体能不能把“现有真实被动岛网”建立起来并维持。

# 12. 为什么这个试验比“切掉五台Stubline”有意义得多


# 21. 对用户三个问题的直接回答

## Q1：切五台高压被动支路有什么意义？

作为最终验证意义很小，而且有Stubline/SSN风险。

# 所以撤回把它作为下一步主方案的建议。

下一步保留五台被动支路，不破坏Stubline。

---

## Q2：Fref是不是没进IO_MUX？

旧的：

```text
ESS1_Fref_From_Sup
```

确实没接。

但最新S15重构以后：

```text
Supervisor Fref
→ S15 legacy Fref router
→ FINAL_FREF_ESS1
→ ESS1_IO_Mux12 input3
```

仍然进入ESS1。

Vref则直接进入：

```text
ESS1_IO_Mux12 input4
```

所以要区分：

```text
旧直连Fref块失效
≠
Supervisor Fref彻底失效
```

---

## Q3：是不是已经证明ESS1自己无法建立孤岛？

# 没有。

我们一直证明的是：

```text
当前grid-to-island transfer失败。
```

真正：

```text
J1初始OPEN
→ ESS1软启动建立岛网
```

还没有做过。

这就是当前验证流程最需要纠正的地方。

# 22. 最终一句话

> **真正的方法论问题不是我们前面所有排错都错了，而是当F2/F3/F4/VPI等内部问题被关闭以后，我们仍继续用“J1从强网工作点突然打开”这一种实验同时判断两个不同命题：ESS1本体是否具有自治成岛能力，以及系统是否具备无扰并→离网切换能力。A0~B2失败只能证明后者失败，不能证明前者失败。用户提出“不应为了纯ESS1去破坏五台Stubline”是正确的；下一步应保留完整被动网络和分核结构，让J1从一开始就OPEN，旁路Supervisor，ESS1以GFM软启动/电压ramp方式建立现有约15-kvar被动岛网。这个Gate A若稳定，就证明ESS1本体有孤岛能力，后续只处理P/Q/I_tie预平衡与Supervisor HOLD/RELEASE；Gate A若仍不稳定，才真正进入ESS1 autonomous output-impedance/F6层。这样才是从现在开始不再盲试的正确验证顺序。**
