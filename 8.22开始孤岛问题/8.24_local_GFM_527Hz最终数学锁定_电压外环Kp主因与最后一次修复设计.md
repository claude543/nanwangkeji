当前最新SLX、完整Build日志、SS_Slave2目标运行日志以及此前的精确结构审计已经足够完成第一层定量分析。

```text

Real-time SingleTasking
```

因此本地ESS1快环已经不再涉及SM→SS的远端状态交换；当前真正需要分析的是SS_Slave2内部的离散闭环。

# 1. 本轮最关键的新发现

此前我们把剩余原因表述为：

```text
Voltage PI
Current PI
800 Hz filter
数字延时
LC
```

共同造成local GFM稳定裕度不足。

现在可以进一步缩窄：

# **主导根因已经高度锁定为：Voltage Regulator的比例增益 `Kp_Vreg=2` 对local C1电压Plant大约高了两个数量级，使“外电压环”实际被推到约470 Hz附近工作，而内电流环本身只有约118 Hz带宽。**

因此当前违反了级联控制最基本的带宽层级：

```text
应当：
Voltage loop << Current loop

当前实际：
Voltage loop试图比Current loop快很多
```

# 3. local电气Plant

ESS1 L1：

```text
Rpu ≈ 0.0015
Lpu ≈ 0.125
```

C1在额定条件：

```text
Qc = 0.05*Pnom
```

因此：

```text
Cpu ≈ 0.05 pu
```

本地电流Plant近似：

```text
Gi(s) = wb / (Lpu*s + Rpu*wb)
```

本地电容电压Plant：

```text
Gv(s) = wb / (Cpu*s)
```

其中：

```text
wb = 2*pi*50
```

# 5. Voltage Loop现在的带宽从物理上就是错误的

若先把Current Loop看成低频近似1，

```text
Kp_Vreg * |Gv| = 1
```

```text

```

当前：

```text
Kp_Vreg = 2
fb       = 50 Hz
Cpu      = 0.05
```

因此：

# **理想Voltage-loop带宽意图约2000 Hz。**

但Current Loop本身只有：

```text
≈118 Hz
```

即：

```text
“外环目标带宽”
约是
“内环实际带宽”
的17倍
```

这是级联控制层级完全反过来了。

# 6. 为什么真实系统最后恰好在470～520 Hz爆振

当把实际：

```text
Current PI
Current-loop 800 Hz反馈LPF
Voltage-loop 800 Hz反馈LPF
100 us Vref Unit Delay
L1
C1
```

一起纳入离散频域估算以后，

当前 `Kp_Vreg=2, Ki_Vreg=14` 的外电压闭环开环增益第一次重新降到1附近的位置约：

# **469.9 Hz（dq频率）**

此时展开相位已经约：

```text
-275.9 deg
```

也就是控制作用已经深入严重相位反转区。

而最终Phase=0实测：

```text
abc快速峰 ≈ 522 Hz
Fout       ≈ 49～50 Hz
```

对应dq：

```text
≈472 Hz
```

所以：

# **模型计算约470 Hz，与实测dq约470～473 Hz几乎重合。**

这不是“参数大概不合适”。

而是已经建立：

```text
Kp_Vreg过大
↓
Voltage outer loop被推到Current loop能力之外
↓
800 Hz测量相位 + 100 us数字延时开始变得关键
↓
外环交越落入L-C模态邻域
↓
形成负阻尼
↓
dq≈470 Hz
↓
abc≈520 Hz
```

完整因果链。

# 7. 为什么现在可以把Kp_Vreg定义为主导项

在470 Hz：

```text
Voltage比例项 = 2
Voltage积分项幅值 = 14/(2*pi*470)
                  ≈ 0.0047
```

积分项仅约为比例项的：

```text
0.24 %
```

因此500+ Hz快速模态不可能主要由 `Ki_Vreg=14` 决定。

它在该频带几乎完全是：

# **Kp_Vreg = 2**

在起作用。

Filter和100 us延时决定“这个过大的比例作用最后以多坏的相位进入Plant”，但把控制增益推到该频段的根本原因是Kp_Vreg本身。

# 8. 最自然的最终整定值不是猜出来的

要求Voltage Loop约20 Hz：

```text
fc_v_target = 20 Hz
```

根据：

```text
Kp_v ≈ fc_v_target * Cpu / fb
```

得到：

```text
Kp_V_local
≈ 20 * 0.05 / 50
≈ 0.02
```

为了保持当前PI零点位置不变：

```text
Ki/Kp = 14/2 = 7 rad/s
```

所以：

```text
Ki_V_local
= 0.02 * 7
= 0.14
```

因此当前最有依据的最终候选是：

# **Kp_V_local = 0.02**
# **Ki_V_local = 0.14**

不是随意把原参数“调小一点”，而是：

```text
2 / 14
↓ 同比例缩小100倍
0.02 / 0.14
```

保持PI零点不动，仅把整个Voltage Loop带宽移回正确层级。

# 10. 对527 Hz最关键的变化

在危险dq频率约：

```text
472 Hz
```

当前Voltage外环估算开环增益约：

```text
0.988
```

已经接近1。

换成：

```text
0.02 / 0.14
```

后变成：

```text
0.0099
```

也就是约降低：

# **100倍**

因此新的Voltage Loop在527 Hz电气模态附近基本“退出竞争”，不会再强行追踪这个LC快速振荡。

这正是级联GFM应该有的行为：

```text
Voltage outer loop：
管低频电压恢复

Current inner loop：
管快速电流

LC高频自然模态：
不允许Voltage PI在该频带用高增益追着打
```

# 12. 当前最终根因可以进一步升级为

此前：

```text
local GFM fast-loop稳定裕度不足
```

现在可以更具体冻结为：

> **F2完成local vC/local iL和local execution frame统一以后，ESS1的Current Loop本身约118 Hz且强网阶段能够正确跟踪；但原Voltage Regulator仍沿用了Kp_Vreg=2、Ki_Vreg=14。对C1=0.05 pu的本地电容Plant，该Kp对应约2 kHz的理想外环带宽意图，远高于118 Hz内电流环。实际受Current Loop、800 Hz测量LPF和100 us延时限制，Voltage Loop的unity交越被拖到约470 Hz dq频段，恰好与实测dq 470～473 Hz、abc约520～527 Hz模态重合，从而在LC模态附近形成负阻尼。**

这是目前最强、最具体的根因结论。

# 16. 当前边界

这套数学模型仍是“针对已锁定主模态的最小闭环模型”，没有把其它5台GFL的完整dq admittance全部写进状态矩阵。

因此：

```text
470 Hz计算值
```

不应解释成“完整六机特征值精确到0.1 Hz”。

但是它与：

```text
最终实测dq≈470～473 Hz
```

几乎重合，且数量级和控制因果完全一致。

其它GFL更可能负责：

```text
模态频率/阻尼的小幅偏移
```

而不是推翻：

```text
Voltage-loop带宽层级错误
```

这一主因。

# 17. 最终一句话

> **我们现在已经从“local fast-loop某处不稳定”进一步锁定到一个非常具体的控制设计错误：`Kp_Vreg=2` 对local C1=0.05 pu电压Plant大约高两个数量级。Current Loop实际只有约118 Hz，而原Voltage Kp按本地电容Plant对应约2 kHz的理想外环带宽，最终受800 Hz反馈滤波、100 us延时和Current Loop滚降作用，被迫在约470 Hz dq频段形成unity交越，几乎与实测dq≈470～473 Hz完全重合；因此它把527 Hz LC模态变成负阻尼。最有依据的最终候选不是继续试Filter/AD/30°，而是把local GFM Voltage PI按100倍同比缩放到 `Kp=0.02, Ki=0.14`，保持Current PI、800 Hz、local R/L、phase=0和AD OFF不变。**
