# 10. 功率恢复回路自身存在“弱网正反馈”特征

功率释放后：

```text

→ Power PI继续要求更大的有功电流
```

随着电压下降，实际有功越来越难跟上目标，误差长期存在。

数据：

```text
25.18 s：
P误差约 -0.103 pu
RawIdRef约 -0.024

25.65 s：
P误差约 -0.096 pu
RawIdRef约 -0.069

27.0 s：
P误差约 -0.191 pu
RawIdRef约 -0.407

30 s：

```

这高度符合：

> **弱网中近似恒功率GFL负载/功率调节造成的负增量阻抗式正反馈。**

机制可描述为：

```text

↓

↓

↓
对有限GFM/母线施加更强负担
↓

```

当前数据强烈支持这个机制，但如果要做严格小信号理论定性，还需要专门阻抗/线性化分析；现阶段不需要把它写成已数学证明的唯一模态。

# 16. 正确的黑启动应该长什么样

最终建议冻结为“全局监督 + 每台设备局部恢复状态机”。

## 16.1 Global Black-Start Supervisor（全局黑启动监督器）

### G0：ISOLATE

```text
J1 OPEN
五台非master GFL物理断开
选择ESS1为GFM master
```

### G1：GFM_FORMATION

```text
ESS1死母线建压
V/f达到稳定
持续健康驻留
```

达到：

```text
BUS_FORMED_ACK
```

才继续。

### G2：SELECT_NEXT_RESOURCE

依据：

```text
当前负荷/发电缺口
ESS1 GFM有功/无功/电流余量
资源类型
SOC/PV可用功率
当前V/f状态
```

决定下一台设备，而不是只靠固定20/40/60 s。

---

## 16.2 每台GFL独立Local Restore State Machine（局部恢复状态机）

### L0 ISOLATED

```text
breaker open
power execution off
```

### L1 PREPARE

复用现有：

```text
ISLAND_PREPARE
```

退出强网dynamic VFF。

### L2 SYNC_READY

必须真实检查breaker两侧：

```text
ΔV
Δf
Δθ
```

### L3 ZERO_CLOSE

```text
breaker close
IrefUsed=0
ImeasUsed=真实电流
Current PI主动压零电流
```

### L4 CONNECTED_ZERO

连续满足：

```text
V/f正常
Imeas小
CurrentLimit=0
ModHeadroom正常
```

完成zero-power dwell。

### L5 PICKUP_ARMED

冻结一个**black-start-specific pickup target**：

```text
Ptarget_pickup
Qtarget_pickup
```

不能让长期二次调频目标在拾取过程中自由漂移。

### L6 POWER_PICKUP

不是开环alpha计时器，而是：

```text
如果ReleaseHealthOK：
    alpha缓慢增加

如果质量变差：
    alpha HOLD

如果持续低压/限流：
    alpha下降
    或退回CONNECTED_ZERO

如果严重异常：
    breaker open
```

### L7 RESTORED

必须同时满足：

```text
alpha达到目标
P/Q跟踪正常
V/f持续正常
CurrentLimit=0
ModHeadroom足够
设备无故障
持续健康dwell
```

才能发：

```text
DEVICE_RESTORED_ACK
```

```text
刚并回设备的首次功率拾取
```

混在了一起。

正确结构应分成：

```text
Black-start Pickup Controller
（黑启动功率拾取控制）

↓

设备稳定RESTORED

↓

Normal Island Coordinator
（正常孤岛长期协调）
```

拾取阶段：

- 从0或极小功率开始；
- 按当前GFM headroom与系统功率缺口给目标；
- 有明确dP/dt限制；
- 低压时优先卸载/冻结，而不是继续追频率；
- disconnected资源不参与分配；
- 二次频率积分最好冻结，等DEVICE_RESTORED_ACK后再接管。

# 21. 最终冻结一句话

> **现在的黑启动已经解决了“设备怎么安全接进孤岛”，但还没有解决“接进来后怎么安全地承担功率”。真正正确的黑启动不是按时间把Alpha推到1，而是“形成母线 → 逐设备准备/同步/零功率并回 → 健康门控功率拾取 → 物理健康确认 → ACK → 下一资源”的闭环恢复系统。**
