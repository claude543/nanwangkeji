# K26_K50 物理黑启动｜ESS2 断开待并与第一次物理接回最小改造冻结说明 V1.0

日期：2026-09-12  
当前模型：`K26_K50_CLEAN_P1`  
改造对象：**仅 ESS2 样机**  
状态：**R3 审计完成，第一阶段改造设计冻结**

---

## 1. 为什么现在可以改模

R3 已闭合此前所有会阻碍第一阶段 ESS2 样机改造的关键不确定项：

1. 五台 GFL 的功率控制环结构、误差方向、参数完全一致：
   - 有功误差：`Pref - Pmeas`
   - 无功误差：`Qmeas - Qref`
   - `Kp = 0.06`
   - `Ki = 2`
   - 有功 PI 限幅：`±1.25`
   - 无功 PI 限幅：`±1`
2. 五台 `AA15_V49_CURRENT_EXECUTION_ADAPTER` 核心代码完全一致；
3. 现有 GFL 电流适配器正常调用中：
   - 误差为 `iref - imeas`
   - 积分使能固定为 1
   - GFL 情况无运行时复位；
4. Stage1 已经证明 ESS2 在：
   - `PrefEff = 0`
   - `QrefEff = 0`
   - support = 0
   的情况下，仍持续出现较大电流请求并长期调制度饱和；
5. ESS2 物理断开时，控制器使用的 V/I 来自母线/变压器侧，而不是自身断路器内侧；
6. 当前 C2 节点没有直接电压测量；
7. `LOCAL15 S14 stage_echo` 当前没有送入三个 SS 实时任务；
8. 三组 SM→SS 向量均为满 24 维，没有 spare；
9. OpWrite 已满 5 个，不能新增第 6 个。

因此，**现在足以做“ESS2本地待并样机”**；但还不应该同时改 S14/SM/其余四台。

---

## 2. 这次到底修什么

只解决一个问题：

> ESS2 支路已经物理断开，但它的外层功率控制和本地电流执行仍按“正常并网设备”工作，持续试图纠正一个自己已经无法控制的母线侧 P/Q 和电流误差。

本次改造把 ESS2 增加一个：

```text
断开待并状态
```

其控制效果：

```text
ESS2物理断开
↓
standby = 1
↓
P/Q误差送PI前归零
↓
外层功率PI不继续追不可控母线功率
↓
电流执行适配器进入待并
↓
有效电流请求=0
↓
内部执行PI总输出匹配到0
↓
仍保留母线电压前馈
↓
ESS2保持“跟着岛网电压、但不主动送电流”的待并状态
```

---

## 3. 为什么是两层处理，不能只把 Final Iref 置零

只把电流参考置零仍不够：

```text
iref = 0
但 imeas 来自母线侧且不等于0
↓
iref - imeas ≠ 0
↓
本地电流执行PI仍会继续积分
```

因此必须同时做：

### A. 功率控制层

位置：

```text
SS_Slave2
└─ ESS2_Control
   └─ Power Control Loop
```

在原：

```text
Pref - Pmeas → P PI
Qmeas - Qref → Q PI
```

和 PI 之间增加两个待并误差门。

正常：

```text
standby=0
→ 原误差原样通过
```

待并：

```text
standby=1
→ P误差=0
→ Q误差=0
```

**不改 Kp/Ki、不换 PI、不改限幅。**

### B. 电流执行层

位置：

```text
SS_Slave2
└─ ESS2_Control
   └─ AA15_GFL_ISLAND_SUPPORT
      └─ AA15_V49_CURRENT_EXECUTION_ADAPTER
         └─ CORE
```

现有 `CORE` 是 MATLAB Function。

只扩展最外层调用接口，底层已审计的 V4.9 辅助函数**不修改**。

待并时：

```text
iref_used  = [0;0]
imeas_used = [0;0]
PI目标输出 = [0;0]
```

所以：

```text
执行PI动态项 = 0
```

但已有：

```text
Vff
```

继续保留。

这比“整个逆变器关掉”更适合后续接回，因为 GFL 仍然可以利用已有 PLL 和电压前馈跟随岛网。

---

## 4. 为什么不改原来的 Current Regulator

R3/当前结构进一步确认：

- 真正送往最终 `VdVq_conv` 的路径已经来自 `AA15_GFL_ISLAND_SUPPORT` 的 `VdVq_ComponentLimited`；
- 旧 `Current Regulator` 的输出1已经不再作为最终执行路径；
- 它的 PI 输出仍作为 `OldPI` 给 V4.9 适配器做初始化匹配参考。

本次待并分支在 `CORE` 中明确把匹配目标改成 0，因此不会拿待并期间可能异常的 `OldPI` 作为执行目标。

所以第一版没有必要侵入旧 `Current Regulator` 内部。

---

## 5. 新增的唯一运行参数

位置：

```text
SS_Slave2/ESS2_Control/
CFG_ESS2_RECONNECT_STANDBY_ENABLE
```

保存默认：

```text
0
```

因此模型保存后：

```text
0 = 原行为
1 = ESS2断开待并
```

第一轮试验由 Python 在 `t=0 / first Execute之前` 写成 1。

这保证：

> 补丁落盘以后默认仍然是原模型行为，不会因为忘记测试配置而改变正常工况。

---

## 6. 为什么本轮不改 SM / S14

当前目的不是自动完成完整黑启动，而是证明一个最基础的物理动作：

```text
ESS1建立岛网
↓
ESS2能够以健康零电流状态等待
↓
ESS2能够零功率安全接入
```

因此本轮：

```text
不扩 24维组向量
不传 S14 stage
不增加中央恢复顺序门
不增加 SS→SM 恢复状态
```

这些只有在 ESS2 样机真正通过以后，才值得推广。

这样每轮只有一个主要控制变化。

## 7. G27 为什么要改，但不增加 OpWrite

平台最多 5 个 OpWrite，所以继续保持：

```text
G26 EV1/EV2
G27 ESS2
G28 PV1/PV2
G29 系统
G30 ESS1
```

本次仅在 G27 的现有 48 个设备通道中替换 7 个重复/低价值量：

| 设备通道 | 原记录 | 新记录 |
|---:|---|---|
| 20 | `Stage` | 变流器侧 Va |
| 31 | `Kslow` | 变流器侧 Vb |
| 32 | `Kfast` | 变流器侧 Vc |
| 33 | `gP` | 母线侧 Va |
| 34 | `gQ` | 母线侧 Vb |
| 37 | `MasterF_Hz` | 母线侧 Vc |
| 38 | `VrefCmd_V` | ESS2支路断路器命令 |

G27：

```text
仍然 Target Time + 48 通道
仍然 Acq Group 27
仍然 Decimation 4
仍然 rootdiag_ess2_data
```

不会改变 OpWrite 个数和宽度。

## 8. 两组三相电压分别是什么

现有物理测量：

### `EV1_inv`

尽管名字历史遗留，当前实际位于：

```text
ESS2 Converter
↓
EV1_inv
↓
L2
```

因此它记录：

> **变流器端、L2之前的三相电压。**

### `EV1_LV_Meas`

当前位于：

```text
母线/Stubline
↓
EV1_LV_Meas
↓
ESS2支路断路器
```

因此它记录：

> **断路器母线侧三相电压。**

### 重要边界

真正的：

```text
C2 / breaker-inner node
```

位于 L2 后、断路器内侧。

当前没有直接电压测量。

所以：

> `EV1_inv` 不能被写成“断路器内侧 C2 电压”。

本轮把它用于判断待并电压跟随趋势；如果待并阶段电流已经很小，且两组三相电压明显接近，才有继续零功率接回 Canary 的资格。

如果两侧仍明显冲突：

```text
禁止直接合闸
```

再决定是否需要补 C2 精确观测或额外预同步机制。

## 9. 本 Patch 明确不做什么

### 不改其它四台 GFL

```text
PV1
PV2
EV1
EV2
```

它们的代码必须保持 R3 原 SHA。

ESS2通过以后再将同一模板推广。

### 不改真实物理网络

不改：

```text
C2
L2
AA15_DIAG_AC_BREAKER_ESS2 的物理端子
Transformer / Stubline
```

新增的电压证据只从**已有三相测量块输出分支**获取。

### 不自动合 ESS2

这个 Patch 本身：

```text
不会增加自动 breaker state machine
不会在某个时刻自动合闸
```

第一次接回仍由既有：

```text
CFG_DIAG_AC_CONNECT_ESS2
```

作为唯一运行时物理动作。

这样失败原因最干净。


> **先证明“零电流设备物理接进岛网”本身安全。**

不和第一次合闸混在一轮。

## 13. 第一版样机的明确适用边界

本补丁的功率 PI 待并门是**误差归零/状态保持**，不是对原 PI 内部积分器增加新的任意时刻复位端口。

因此第一版样机的正式测试合同必须是：

```text
Reset
→ Load
→ MODEL_PAUSED @ t=0
→ standby=1 在 first Execute 前写入并 readback
→ 才第一次 Execute
```

因为现有两只功率 PI 的初值已经审计为 0，所以从 t=0 开始待并时：

```text
误差=0
→ 积分状态从0保持
```

这足以回答当前黑启动恢复问题。

本补丁**不宣称**已经解决“设备正常运行一段时间后，任意时刻突然断开再重新待并”的通用故障重连问题；如果未来需要该功能，再单独设计 PI 状态复位/匹配，不在本轮扩大范围。

## 14. C2 电压观测边界

R3 已确认：

```text
C2 Measurements = None
```

因此本轮 G27 新增的两组三相电压是：

```text
EV1_inv      → ESS2变流器端、L2之前
EV1_LV_Meas  → ESS2断路器母线侧
```

它们**不是**断路器两侧的两个精确节点电压。

所以第一轮待并试验可以利用它们判断“电压跟随趋势”，但不能把它们包装成严格的 C2 同期判据。

正式零功率合闸是否还需要增加 C2 精确观测，将由待并试验结果决定：

- 若 ESS2 待并后电流请求、调制度等仍不健康：先修控制，不讨论合闸；
- 若待并控制健康，但现有两组三相电压仍明显不一致：禁止合闸，进入 C2 精确观测设计；
- 只有待并控制健康且现有证据没有显示明显电压冲突，才进入第一次零功率接回 Canary 的最终准入审查。

因此本补丁**不会自动合闸，也不会因为加入两组电压日志就自动宣布“已具备合闸条件”。**
