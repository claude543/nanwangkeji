# 8.23｜后续是否以“补阻尼”为核心、D1到F1成功概率与Build风险控制

## 0. 先给结论

是，但要把“补阻尼”理解准确。

我们最终真正要达到的目标不是：

```text
把530 Hz这个频率“滤掉”
```

也不是：

```text
强行把某个参数调到看不到振荡
```

而是：

> **让当前约0.53 kHz的控制—电气模态重新获得足够的正阻尼，使J1打开以后即使该模态被扰动激发，也只能短暂振几下，然后迅速衰减，最终重新由健康50 Hz基波主导。**

因此从工程上说：

# **后续最终确实是在“补阻尼”。**

但“阻尼应该补在哪里、用什么方式补”还不能现在拍脑袋决定。

D1的任务就是找出：

```text
到底哪一层正在让阻尼变差
```

然后F1只在真正需要的位置做修复。

---

# 1. “补阻尼”不一定等于增加一个叫Damping的块

后续可能出现四种不同意义上的“补阻尼”。

## 情况A：LC模态本身需要主动阻尼

可能最终采用：

```text
Active Damping
Virtual Resistance
Virtual Impedance
Capacitor-current feedback
```

这是最直观意义上的“补阻尼”。

---

## 情况B：500 Hz测量滤波造成过大相位滞后

此时正确修复可能是：

```text
重新设计measurement filter
+
重新协调Voltage/Current Loop带宽
```

虽然没有增加一个独立“阻尼块”，但本质仍然是在：

```text
恢复相位裕度
→ 恢复模态正阻尼
```

---

## 情况C：SM/SS快速反馈时序导致相位裕度不足

正确修复可能是：

```text
把快速V/I内环尽量本地化
减少快速反馈路径延时
```

本质依然是：

```text
减少相位损失
→ 增加有效阻尼
```

---

## 情况D：某个GFL在弱网下提供负阻尼

此时阻尼应该补在：

```text
对应GFL PLL / Current Loop / Virtual Impedance
```

而不是硬改ESS1。

# 6. D1内部取点应该采用“直接旁路”，而不是重构控制器

建议直接从：

```text
Measurements/Selector2
→ Vdq_raw

Measurements/Selector1
→ Idq_raw

Measurements/VdVq_meas
→ filtered Vdq

Measurements/IdIq_meas
→ filtered Idq

Voltage Regulators/IdIq_ref

Current Regulator/PIdq

Current Regulator/VdVq_conv

Vref Generation/ModIndex

Droop Control/Fout

Measurements/P_meas
Measurements/Q_meas
```

分别做只读branch。

然后用：

```text
Mux
```

拼成一个固定顺序的：

```text
D1_FAST_DIAG_VECTOR
```

最后新增：

```text
ESS1_Control第3个诊断Outport
```

送到SS顶层。

这样完全不修改任何现有控制计算。

# 7. 为什么这种方式Build成功率更高？

因为只使用项目已经反复证明RT-LAB能够正常处理的基础块：

```text
Mux
Demux
Sum
Selector/branch
Outport
Gain（如必要）
```

不会新增：

```text
MATLAB Function
Stateflow
复杂自定义S-Function
新的控制算法
```

特别重要：

> **此前项目已经证明当前RT-LAB版本对新增MATLAB Function存在恢复/Stateflow相关问题，所以D1绝不能引入MATLAB Function。**

# 8. D1的SS→SM接口应该怎样设计最稳？

当前实际：

```text
SS Mux
Inputs = 4

1 ESS1_Pmeas
2 ESS2_Pmeas
3 inv_Vab
4 LCout_Vab
↓
原Memory
↓
SS→SM
```

D1不要为每个内部信号新增一个Outport。

最稳的是：

```text
1 ESS1_Pmeas
2 ESS2_Pmeas
3 inv_Vab
4 LCout_Vab
5 D1_FAST_DIAG_VECTOR
```

即：

```text
Mux input数
4 → 5
```

其中第5项本身是：

```text
一个固定宽度向量
```

继续统一经过：

```text
原来的唯一Memory
```

这样比：

```text
Mux从4直接扩成25个独立input
```

结构干净很多。

---

# 9. SM侧也不要拆成二三十个顶层线路

当前：

```text
Demux1 Outputs = 4
```

D1建议变成类似：

```text
Outputs = [1 1 1 1 N]
```

含义：

```text
out1 ESS1_Pmeas
out2 ESS2_Pmeas
out3 inv_Vab
out4 LCout_Vab
out5 D1_FAST_DIAG_VECTOR
```

然后：

```text
out5
↓
单独D1 Demux
↓
各内部诊断量
```

这样原来的前四路完全不碰。

# 11. D1 logger是否复用Group29？

目前建议：

# **继续复用已经验证成功的SM Group29 OpWrite。**

不新增第二个高频OpWrite。

Group28：

```text

继续记录策略状态
```

Group29：

```text

```

这样可以降低：

```text
IO负担
Acquisition group复杂度
RT-LAB配置风险
```

# 13. D1一个需要特别避免的频谱坑

因为：

```text
Fsw = 4 kHz
```

而：

```text
5 kHz Nyquist = 2.5 kHz
```

所以：

```text
L1前inv
```

的4 kHz开关成分在5 kHz采样下会混叠。

因此D1的5 kHz文件主要针对：

```text
dq控制量
LCout
prim
PCC
六支路高压电流
```

而不是再次靠5 kHz的inv波形证明PWM频谱。

# 30. 最终判断

> **是的，后续最终目标就是给当前约0.53 kHz模态恢复足够阻尼，但现在不是直接“找一个地方塞阻尼”，而是先用D1把负阻尼来源一次性定位清楚。当前规划已经覆盖了滤波、Voltage/Current Loop、数字时延、饱和、PWM/Converter、Lff/Plant不匹配以及1 GFM + 5 GFL多机交互等主要机制，没有明显的大类遗漏。模型实施上也已经吸收了此前RT-LAB经验：复用现有SS→SM回传、只用一个Memory、优先复用Group29、不用MATLAB Function、用标准Mux/Demux/Outport旁路诊断，并在Patch中加入备份和严格断言。由于前一轮2→4维回传和10 kHz高频记录已经真实Build/Execute成功，D1沿同一架构扩展，成功Build的概率较高，但不能承诺100%一次过；即使出现Build错误，大概率也属于接口/维度层面的局部工程问题，不会推翻诊断路线。理想情况下，从现在开始只需1次D1诊断Build和1次F1修复Build，就能完成根因定位与阻尼验证。**
