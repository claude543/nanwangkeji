# 暑期南网科技项目｜三个模型尾项查明以后怎么处理、是否必须修改，以及BOARD15应该承担什么

> **日期**：2026-08-23  
> **当前冻结事实**：
>
> - PCC/J1/Load边界已经修正；
> - 新拓扑 Rebuild All 成功；
> - 正常并网和AGC回归通过；
> - J1真实打开以后，孤岛已经能够重新建立约10 kV；
> - 当前仍看到PCC频率最终顶在55 Hz；
> - J1打开附近仍存在约4.3～14.7 kV的大幅电压瞬态；
> - 当前LOCAL15模型侧虽然产生了“孤岛后不允许普通P控制”的判断量，但它没有真正接入LOCAL15的有功协调执行链；

> 2. 离网冲击确认持续时间、确认是不是实际电气冲击以后，到底怎么处理？是否一定要解决？
> 3. 离网后停止联络线功率调节既然BOARD15已经考虑了，模型侧还要不要改？

# 0. 最终结论先给出来

三个问题的处理结论**并不一样**。

| 问题 | 现在必须做什么 | 是否一定要修改模型 | 最迟什么时候必须闭环 |
|---|---|---|---|
| 频率 | 必须先区分“真实频率跑偏”还是“测量链错误” | **看结果决定**。真实频率错→必须修GFM；测量错→必须修测量/输入路径；如果只是无关诊断量错误而控制输入可靠，则可不动Plant | S14/S15最终验收之前 |
| 离网瞬态 | 必须先量化峰值、持续时间和真实性 | **不一定**。若只是极短测量尖峰/可接受瞬态，可记录不改；若真实且持续、会触发保护或干扰控制，则必须优化 | 最终并离网/CHIL验收之前 |
| 离网后停止PCC功率调节 | BOARD15已经在C09里实际实现 | **当前不建议为了这个专门修改LOCAL15模型**。重点是要求工程师保留该语义并做实板验证 | BOARD15程序验收时 |

所以这三个问题不能统一理解成：

> “都必须马上改模型。”

真正应该是：

```text
频率
→ 先诊断
→ 根据根因修对应层

瞬态
→ 先定量
→ 根据严重程度决定是否优化

离网后停止PCC功率调节
→ BOARD15已有
→ 当前重点转为工程师集成不得破坏 + 后续实板验收
```

# 1. 频率：查明以后到底怎么办？

---

## 1.1 现在真正要区分的不是“55 Hz好不好”

55 Hz当然不是我们希望的正常孤岛频率。

但当前最关键的是：

> **MAT里看到的55 Hz究竟代表什么。**

目前至少有三层量：

```text
A. ESS1 GFM内部自己生成的频率
   Droop Fout / Fref相关量

B. ESS1真正输出到孤岛电压里的物理频率
   可以从实际Vabc周期判断

C. PCC测量模块/PLL输出的Freq_pcc
```

当前MAT看到的是：

```text
C
```

并且我们已经确认：

```text
PCC测频链后面有45～55 Hz Saturation
```

所以：

```text
Freq_pcc = 55 Hz
```

只证明：

> 这个测量输出已经撞到55 Hz上限。

并不能自动证明：

```text
真实电气频率 = 55.000 Hz
```

更不能证明：

```text
真实电气频率只到55，不会更高
```

---

# 2. 情况A：如果查出来“ESS1 GFM真实频率确实跑偏”

假设以后记录：

```text
Droop Fout ≈ 55 Hz
实际Vabc周期也≈55 Hz
PCC PLL≈55 Hz
```

那么结论就是：

> **真实构网频率本身有问题。**

这种情况：

# **必须处理。**

不是“有时间再优化”。

---

## 2.1 为什么真实频率跑偏必须处理？

因为当前ESS1在孤岛中承担的是：

```text
Grid-Forming
构网
```

它必须建立：

```text
V
+
f
+
phase
```

如果只做到：

```text
V≈10 kV
```

但：

```text
f≈55 Hz
```

那只能说明：

> 有电压，但构网基准不正确。

---

## 2.2 对S15的直接影响

当前S15同步条件：

```text
|Δf| ≤ 0.20 Hz
```

主网：

```text
≈50 Hz
```

如果孤岛：

```text
≈55 Hz
```

则：

```text
Δf≈5 Hz
```

远大于0.20 Hz。

所以：

```text
SYNC_OK
不可能正常成立
```

也就是说：

```text
RESYNCHRONIZATION
→ 无法完成
→ J1不能安全重合
```

---

## 2.3 对S14黑启动的影响

黑启动本身就是：

```text
没有主网
↓
储能自己建立电压和频率
```

因此真实GFM频率错误时：

> S14不能算最终通过。

---

# 3. 如果真实频率跑偏，具体怎么查、怎么修？

不能直接：

```text
“55 Hz了”
→ 随便调Droop PI
```

应该按因果链查。

---

## 第一步：先看Fref

当前正常孤岛不是S15重同步阶段时，ESS1参考频率本来应该围绕：

```text
50 Hz
```

所以先查：

```text
ESS1 final Fref
```

### 如果Fref本身已经≈55 Hz

说明问题在：

```text
上层Fref路由
S15 Fref trim
Supervisor
配置
```

不需要先碰低层GFM。

---

### 如果Fref≈50 Hz，但Droop Fout≈55 Hz

问题才进入：

```text
Droop频率生成逻辑
```

重点检查：

```text
P-f Droop的符号
Frequency_Droop参数
Pmeas反馈
Pref/P平衡
Enable逻辑
积分器
单位换算
```

---

### 如果Fref≈50、Fout≈50，但真实Vabc≈55 Hz

说明：

```text
频率命令正确
但真正生成三相电压的相角/调制链不一致
```

就要继续查：

```text
theta_out
→ wts
→ Vref Generation
→ PWM
```

---

## 3.1 所以真实频率问题的处理原则

不是：

> 发现55 Hz，就整体重写GFM。

而是：

```text
Fref错
→ 修上层路由

Fout错
→ 修Droop频率逻辑

Fout对、Vabc错
→ 修相角/PWM生成链
```

只修发生错误的那一层。

---

# 4. 情况B：如果真实频率其实正常，只有PCC测频链跑到55 Hz

假设最后发现：

```text
ESS1 Droop Fout ≈ 50 Hz
实际Vabc周期 ≈ 50 Hz

但：

PCC PLL输出 → 55 Hz
```

那么结论：

> **Plant/GFM本身可能是正常的，错误发生在测量层。**

这种情况也不能完全不管。

但处理对象完全不同。

---

# 5. 测量频率错误时，要不要处理？

答案分两层。

---

## 5.1 如果这一路测量只是显示/日志用

假设：

```text
Scope显示用
MAT记录用
```

但：

```text
S15不用它
BOARD15也不用它
保护也不用它
```

那么：

> **不一定需要为了一个显示量去改Plant。**

只需要：

- 标记该测量链不可靠；
- 不再用它作为控制判断依据；
- 后续论文不用它做关键结论。

---

## 5.2 但当前项目不是这个情况

当前LOCAL15 S15设计明确使用：

```text
J2_Grid_Measurements Freq
J2_PCC_Measurements Freq
```

去计算：

```text
Δf
```

也就是说：

```text
PCC测量频率
```

直接进入：

```text
重同步判据
```

因此如果它是错误的：

# **必须处理。**

但是处理的是：

```text
测量/输入路径
```

而不是：

```text
GFM控制器
```

---

# 6. 测量链错误时具体怎么处理？

最低风险方案应该是：

```text
先找到PLL原始未限幅频率
↓
判断PLL本身是否正确
```

---

## 情况B1：PLL原始输出正常，只是Saturation把它夹住

这种情况下：

```text
不需要改GFM
```

只需要重新定义：

```text
S15 / BOARD15应该读取哪个可信频率量
```

例如：

```text
使用正确的PLL频率输出
```

而不是一个会隐藏真实状态的诊断限幅量。

---

## 情况B2：PLL原始输出本身就失真

那么需要解决：

```text
为什么孤岛状态下PLL测频不可靠
```

可能进一步检查：

- 电压畸变；
- 低压阶段；
- PLL失锁；
- 初始化；
- 参数；
- 是否本来就不适合在强瞬态期间立即作为同步判据。

这时也不一定需要修改GFM。

---

# 7. 频率问题“一定要处理”的准确表述

不是：

> “55 Hz这个数字必须通过调参消失。”

而是：

# **在最终S14/S15验收以前，必须确保控制器使用的频率是可信的，并且真实孤岛频率能够回到合理的50 Hz附近。**

如果最后证明：

```text
真实频率正常
只是旧MAT记录通道有问题
```

那么：

```text
修测量/换信号
```

即可。

不需要为了这个去动逆变器Plant。

---

# 8. 频率问题会不会挡住BOARD15正常并网接板？

不会。

可以并行。

正常并网：

```text
J1 CLOSED
↓
强网提供50 Hz
↓
BOARD15先做正常PCC AGC
```

完全可以先做。

但：

```text
BOARD15孤岛
S14
S15
最终CHIL并离网
```

之前必须把频率闭环。

# 9. 第二个问题：瞬态查明以后到底怎么办？

当前看到：

```text
J1 OPEN附近
Vab RMS最低≈4.3 kV
最高≈14.7 kV
```

但这还不是“必须马上修GFM”的充分证据。

因为我们还缺两个信息：

```text
1. 持续多久？
2. 是真实电气电压，还是测量/计算瞬态？
```

---

# 10. 为什么先看持续时间？

下面三种现象完全不是一个严重程度。

---

## 类型A：只有极少数100 μs采样点

例如：

```text
1~3个100 μs点
```

也就是：

```text
0.1~0.3 ms
```

这种情况下可能更多属于：

- 离散切换瞬间；
- 测量RMS窗口短暂失真；
- Breaker/Z^-1边界切换；
- 数值求解瞬态。

这种情况：

# **未必需要修改控制器。**

---

## 类型B：持续几毫秒到几十毫秒

这时更像真实：

```text
GFL→GFM切换动态
```

就值得继续看：

```text
theta
IdIq_ref
Voltage Regulator状态
Current Regulator
modulation
```

---

## 类型C：持续几百毫秒甚至秒级

这就已经不是：

```text
“切换尖峰”
```

而是：

```text
明显的并离网动态性能问题
```

这种情况通常需要处理。

---

# 11. 确认“是不是真实电气冲击”之后怎么办？

还是分情况。

---

# 12. 情况A：只是测量算法在切换瞬间产生假尖峰

例如真正：

```text
Vabc实际幅值变化不大
```

但：

```text
RMS estimator
PLL
positive-sequence calculation
```

短时间算出4.3/14.7 kV。

那么：

# **不需要改逆变器Plant。**

应该改的是：

```text
测量/判据使用方式
```

例如：

- 切换后给PLL/RMS短时间settling window；
- 高级策略不在1~2个无效采样点上立即做硬动作；
- 使用quality flag；
- 论文取证时同时保存原始Vabc。

这里最忌讳：

```text
测量有尖峰
→ 去乱调GFM PI
```

---

# 13. 情况B：是真实电气冲击，但非常短，并且不会触发保护/失稳

这种情况下：

# **也不一定必须消灭。**

真实电力电子系统并离网：

```text
完全零扰动
```

不是默认要求。

真正要问的是：

```text
是否很快恢复？
是否造成过流？
是否造成保护动作？
是否让模式状态机误判？
是否破坏后续孤岛稳定？
```

如果这些都没有：

> 可以把它作为可接受的切换瞬态记录下来。

---

# 14. 当前项目没有给出一个明确的“允许瞬态必须≤多少kV/多少ms”的正式指标

这一点不能自己编。

目前已有项目资料中并没有冻结类似：

```text
离网过压必须<1.1 pu持续X ms
```

这样的验收阈值。

所以现在不能直接说：

```text
14.7 kV一定不合格
```

或者：

```text
只要20 ms以内就一定合格
```

都没有资料依据。

正确做法：

```text
先定量
↓
再根据
设备保护
控制稳定性
项目最终验收要求
决定是否必须优化
```

---

# 15. 情况C：真实冲击明显、持续，并且影响保护/控制

如果最后发现：

```text
真实Vabc确实掉到0.43 pu
又冲到1.47 pu
持续几十/几百ms
```

并且：

- S8被错误触发；
- S5持续异常；
- 逆变器电流饱和；
- modulation打满；
- 频率被拉乱；
- 后续S15无法进入正常状态；

那么：

# **必须优化。**

---

# 16. 如果瞬态必须优化，应该怎么处理？

不能直接先调PI。

先判断是哪一类。

---

## 16.1 如果主要是GFL→GFM状态不连续

我们已有审计发现：

```text
Droop phase integrator
没有明显PLL相角跟踪路径

Voltage Regulator
没有明显GFL电流参考状态跟踪路径
```

那么优先方向是：

# **Bumpless Transfer，无扰切换**

通俗说：

> 切换到GFM以前，先让GFM内部状态尽量靠近当前真实运行状态。

可能包括：

```text
Droop theta
← 当前PLL相角

Voltage Regulator内部积分状态
← 当前GFL运行点

GFM初始Id/Iq reference
← 当前实际电流/原GFL参考
```

而不是从一套毫无关系的初始状态突然切入。

---

## 16.2 如果主要是功率不平衡

就要做：

```text
离网前功率预平衡
```

也就是J1打开以前尽量让：

```text
岛内发电
≈
岛内负荷
```

减少切断瞬间的功率阶跃。

当前06试验已经做了：

```text
PCC target → 0
```

所以有功平均交换已经尽量减小。

---

## 16.3 如果主要是电流/调制限幅

那应该查：

```text
Id/Iq
IdIq_ref
Vd/Vq command
Modulation index
current limit
```

然后解决：

```text
电流参考突变
或
调制饱和
```

而不是调一个与根因无关的上层状态机。

---

# 17. 所以瞬态到底“一定要解决吗”？

准确答案：

# **一定要“查清楚和定量”，但不一定要把所有瞬态都消掉。**

只有以下情况才必须进一步修改：

```text
真实冲击
+
持续时间明显
+
影响设备/保护/控制
或
无法满足最终验收
```

如果最后证明：

```text
主要是测量瞬态
```

或者：

```text
真实但极短、系统立即恢复、无保护后果
```

那么可以：

```text
记录
+
说明
+
不继续大改Plant
```

```text
S14/S15
CHIL
```

之前必须作出最终处理决定。

# 19. 第三个问题：离网后停止联络线功率调节

这次可以给一个非常明确的新结论：

# **BOARD15 C01～C10实际源码已经实现了。**

# 20. BOARD15实际是怎么实现的？

我直接检查了正式：

```text
project15_core_BOARD15_C09_V0_2.c
```

里面有：

```c
effective_mode_permissions(...)
```

它先把：

```text
allow_p = 0
allow_q = 0
allow_s6 = 0
```

然后只有：

```text
SYS_GRID_CONNECTED_NORMAL
```

时允许：

```text
allow_p = 1
allow_q = 1
allow_s6 = 1
```

以及：

```text
SYS_GRID_CONNECTED_EMERGENCY
```

时允许：

```text
allow_p = 1
allow_q = 1
allow_s6 = 0
```

也就是说：

```text
ISLANDING
ISLANDED
BLACK_START
RESYNCHRONIZATION
```

都不会得到：

```text
allow_p = 1
```

---

# 21. BOARD15不只是“给了allow_p=0”

更关键的是C09后面真的使用了它。

代码逻辑是：

```text
如果：
MASTER ENABLE
+
AGC ENABLE
+
allow_p = 1

→ 调用 p_coord_baseline_step()
→ 正常更新有功协调内部状态
```

否则：

```text
不调用step
```

而是：

```text
p_coord_baseline_get_output()
```

即：

> **只拿出此前已有的有功协调输出，不再根据新的PCC误差更新。**

并且还专门记录：

```text
pcoord_held_by_mode = 1
```

# 22. 用通俗语言翻译BOARD15现在已经做了什么

并网时：

```text
Ptarget
-
Ppcc
↓
继续计算
↓
继续修改六路基础Pref
```

离网后：

```text
系统模式 = ISLANDED
↓
allow_p = 0
↓
不再执行新的PCC AGC更新
↓
保留上一组已有基础协调输出
```

这就是我们说的：

# **“离网以后停止继续按PCC误差改六台设备功率。”**

---

# 23. 这和“把六路Pref全部清零”完全不是一回事

BOARD15现在的逻辑是：

```text
不更新普通PCC AGC
```

而不是：

```text
六路Pref = 0
```

后面仍然可以有：

```text
S8
Black Start Pref Gate
Mode Control
```

# 39. 最关键的三个答案，压缩版

## 1. 频率查清以后一定要处理吗？

> 如果是真实GFM频率跑偏，必须修；如果真实频率正常而只是PCC测量错，则修测量/输入路径，不需要动GFM；如果错误量只是无关显示量且不被任何控制使用，则可以记录而不改。但当前S15会使用PCC频率，所以如果这一路测量不可信，最终S15前必须处理。

---

## 2. 瞬态查清以后一定要解决吗？

> 不一定。一定要先知道它是真实还是测量尖峰、持续多久。如果只是极短测量瞬态或真实但非常短且不会触发保护、不会破坏控制，可以记录而不继续改模型；如果是真实、持续、会引起过压欠压/过流/策略误触发或影响S14/S15，则必须优化。当前还不应该在没有定量以前直接调GFM PI。

---

## 3. 离网后停止PCC功率调节模型侧还要改吗？

> 对最终BOARD15路线，目前不建议专门修改LOCAL15。BOARD15 C09已经真实实现：只有并网正常/紧急模式允许P协调更新，进入ISLANDING、ISLANDED、BLACK_START、RESYNCHRONIZATION后不再调用P协调更新，而是保持已有输出，并记录`pcoord_held_by_mode`。现在重点是把这一语义写进工程师集成要求并在实板程序回来后专项验证，防止工程主程序绕过或破坏它。只有以后还要把LOCAL15本身重新作为最终孤岛控制器验收时，才有必要把同样门控补回模型侧。
