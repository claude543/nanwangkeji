# 光伏1合闸后电压退出：当前模型核对与验证安排

适用：运行编号912633781、用户本次上传的第23版正式模型。本文是分析与建议，不是已执行的保护修改。

## 1. 结论

现有约0.77秒的接入数据不能证明电压在不退出的条件下必然持续升高，也不能证明它会自行恢复。准确结论是：当前配置先观察到电压抬升，随后电压越带判据触发本地回退和全局退出，原来的接入运行条件被改变，未观察到原闭环的后续轨迹。

必须区分：恢复功能未完成、保护逻辑确实动作、未受保护切换影响的长期动态尚未验证。这三个结论不能合并成“电气控制已经证明发散”。

当前应重新审查电压幅值与持续时间的联合判据，以及局部故障到全局退出的升级关系。建议安排一次受限的合闸后零功率延长观察，而不是取消全部保护或重复原200秒运行。

## 3. 当前实际退出链

### 3.1 首先在储能2本地触发

位置：`SS_Slave2/AA15_ESS2_RESTORE_EXECUTOR/CORE（储能2从任务中的恢复执行核心）`。

已经完成首次恢复、处于正常模式及相应全局阶段时，严重条件是以下条件的逻辑或：

- 电压低于合闸后低限；
- 电压高于合闸后高限；
- 频率偏离额定值超过已有严重频差；
- 实测电流超过正常电流上限，并达到设定持续时间。

运行时上下限分别为0.8和1.2标幺。电流上限1.2标幺，过流持续时间0.05秒。

关键差异：**电流有单独持续计时，电压和这条严重频差没有单独持续计时。** 电压标幺量由已有测量/处理链提供，并非直接用正弦瞬时电压与1.2比较；但一旦这个量在一个控制步越带，严重条件就能成立。

本地状态7遇到严重条件后：

- 自动开断路器开关为1：转入状态9，并置失败码7。
- 自动开断路器开关为0：转入状态5、撤回电流释放，仍然置失败码7。

因此，已经设为0的 `CFG_ESS2_RESTORE_ABORT_OPEN_ENABLE（储能2异常自动断开使能）` 并没有取消本地回退和失败码。

### 3.2 随后升级为全局90

位置：`SM_Master/Advanced_Microgrid_15_Strategies/Advanced_Strategy_Core（主任务中的策略核心）`。

全局阶段处于30至90之前时，储能2恢复状态无效、失败码非零或本地状态达到9，均可直接将全局阶段设置为90。这里没有按照电压越带持续时间进行第二次分级。

因此本轮路径是：储能2电压越带 → 严重条件 → 储能2退回状态5并锁存失败码7 → 全局90。

不能只在全局层忽略失败码：到达全局之前，储能2已经改变了释放系数和本地状态。只屏蔽最后的全局退出，仍无法得到原来两个设备都按正常状态运行的后续响应。

### 3.3 全局退出改变了哪些运行条件

- 光伏中央监督器因为全局不再等于88，将其恢复阶段清为0。
- 最终断路器仲裁强制光伏1断开。
- 储能2退出正常资源池并撤回电流释放。
- 储能1的频率/电压参考二次恢复在全局90冻结当前偏置；不是继续按正常阶段更新，也不是把偏置立即归零。

因此，退出后的电压降低不能证明光伏保持接入时本来也会恢复；退出前的上升也不能证明它在不退出时必然发散。

## 4. Python（运行脚本）到底可以改什么

|内容|当前实现|判断|
|---|---|---|
|储能2电压上下限|两个显式常数参数，已在本轮运行清单中发现路径并回读|可以在首次执行前通过现有参数接口设置；不能称为全部硬编码不可调|
|正常实测过流持续时间|独立参数0.05秒|可以设置，但它只用于过流，不能给电压添加延时|
|电压连续越带计时、返回复归带的计时清除、分级故障|当前故障函数中没有相应状态和参数|单靠更换Python文件不能新增算法；需要局部改模及重新构建|
|局部失败码非零就进入全局90|中央策略函数逻辑|没有一个现成、独立的Python电压宽限开关|
|最终断路器命令与本地保持同步|当前缺少反馈衔接|改运行参数不能替代结构修正|

真实参数：

- `CFG_ESS2_RESTORE_POST_V_MIN_PU（储能2合闸后电压低限）`。
- `CFG_ESS2_RESTORE_POST_V_MAX_PU（储能2合闸后电压高限）`。
- `CFG_E2FR_RUN_OVER_I_PERSIST_S（储能2正常运行过流持续时间）`。

当前正式Python入口会在执行前重新写入0.8和1.2。因此，仅修改模型显示值而不调整运行配置，会被旧运行入口覆盖。后续必须让模型配置、运行前写入和清单保持一致。

只提高上限不是持续时间判据；这对上下限还被合闸后健康判断复用。不能将所有越限取消、设为无穷大或用巨大上限来伪装正常保护。

## 5. 0.77秒的数据仍然有用

现有数据已回答：

1. 光伏实际发出并施加了合闸命令，后进入本地状态5；第23版解除综合限幅误阻断有效。
2. 升压发生在零功率连接阶段，尚未释放500瓦有功任务、交权或无功分担。
3. 可以定位实际退出来源、故障传播和退出后的控制状态不一致。
4. 可以观察电流控制输出、电流反馈、无功和构网参考在退出之前的演变。

本轮新复算的约20毫秒紧凑样本中：

- 光伏q轴电流调节器输出在101.70秒约0.13713标幺；101.84秒约0.13148标幺，已有下降，不能说所有内部状态都始终增大。
- 储能1最终电压参考由101.0605秒约9983.39伏下降到101.8405秒约9973.78伏，已经朝降低母线电压的方向调节。
- 当前电压参考二次恢复的误差滤波时间常数为1秒，变化率限制为0.01标幺/秒。约0.77秒的扰动观察不能直接代表这一慢控制已完成响应。
- 以上都不能单独证明不退出时一定稳定，也不能用来直接决定应增加哪个增益。

必要的进一步离线计算仍使用本轮已有数据：将合闸前、合闸后但退出前、退出后三个区间分开；计算电压越带起点/持续时长、斜率和峰值，电流反馈误差、调节器输出与前馈、构网电压参考变化、限幅和功率变化。

当前紧凑数据可作趋势分析，但不能恢复丢失的原始采样点。若需要精确触发拍或毫秒级先后，应使用本轮原始G27/G29/G30（1毫秒）和G28（10毫秒）记录的约100至103秒窗口；不必为了取得旧窗口重跑试验。

## 6. 建议的电压判据修正原则

这是修正设计建议，不是已经完成的修改：

- 合闸前同步资格保留，不能为了观察而在明显不同步时强制合闸。
- 合闸后一般电压越带先记录幅值、持续时间和恢复趋势；必要时保持在零功率观察，不继续放大任务，但不立即锁存全局失败。
- 连续越带达到经验证的持续时间，才形成相应电压故障；计时仅反映该原因，不和过流计时共用。
- 更严重的电压、电流或数值异常要有独立退出边界。具体数值须结合仿真对象和硬件约束，不在当前证据下任意宣布某个高压值可安全维持数秒。
- 普通告警、阶段资格未完成、确实需要退出的故障分开输出；不能把告警编码为失败码7后仍沿旧全局路径处理。
- 退出后恢复执行器、最终断路器命令、电流保持和积分状态同步进入对应状态；按项目已有一拍监督反馈范式避免代数环。

现有0.8/1.2参数是本项目当前设置；不能据此宣称它们是所有微电网的通用瞬时退出标准。定限时保护是一种已有规范化实现方法，但保护延时的工程整定不能由一般文档自动决定。

## 7. 下一次试验应该怎样安排

建议先安排一次只观察合闸后零功率闭环的诊断试验，不立刻再要求完成所有阶段。

适用前提：电气功率对象仍在仿真器内，没有按此方法撤除真实设备保护。若接入真实功率硬件，须先依据该硬件额定值和保护要求确定可观察范围。

- 储能1/储能2按原已验证方式建立工作点；不同时改变电流控制增益、滤波参数和二次恢复增益。
- 光伏按原同步条件合闸。
- 用明确的零功率观察状态保持释放系数为0，不人为提高资格分数，也不强制进入小功率或正常资源池。
- 观察时长建议以实际合闸事件后3秒为第一观察点，必要时延至5秒。3至5秒是诊断记录目标，不是对所有越限持续时间的安全承诺；触及更严重退出条件时应提前结束。
- 原0.8/1.2越带持续记录。是否延后本地回退、延后多久，以及对应的更高一级退出界限，必须在试验前明确；不能运行后临时改变。
- 不在观察中由主机反复清失败码、强行写回88或再闭合断路器。
- 这一观察结束后再决定是否继续恢复试验。按历史合闸约101秒估算，总时长可能约106至110秒，但终点以本轮真实事件为准，不硬编码必须在101秒合闸。

无保护切换干扰时，若电压先增大后回落，可进一步评估峰值和调节时间；若形成非额定高压平台，应报告稳态偏差；若继续增大并伴随电流、调节器或调制持续饱和，应进一步做闭环定位。这几种结果都不能提前按成功或失败模板填写。
