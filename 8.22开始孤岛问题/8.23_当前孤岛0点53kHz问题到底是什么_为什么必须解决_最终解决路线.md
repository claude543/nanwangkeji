# 8.23｜当前孤岛0.53 kHz问题到底是什么、为什么必须解决、最终解决路线

## 0. 先用一句最容易理解的话说明现在发生了什么

现在不是“PCC频率变成了55 Hz”这么简单。

真正发生的是：

> **并网时，上级电网把整个微网牢牢稳定在50 Hz；J1打开以后，ESS1要自己当“电网”，但ESS1构网以后，整个电气系统没有稳定在50 Hz，而是激起了一个大约0.53 kHz（530 Hz）的快速振荡。这个振荡从逆变器交流出口就已经存在，经过LC滤波器后又被进一步增强，最后一路传到prim_ESS1和PCC。**

所以：

```text
PCC显示55 Hz
```

只是后果。

真正的病根是：

```text
孤岛以后
三相电压本身在快速振荡
```

---

# 1. 为什么并网的时候没事，一离网就出问题？

可以把上级电网理解成一个非常“硬”的50 Hz电压源。

并网时：

```text
Grid
= 强大的50 Hz电压参考
```

ESS1、PV、EV等设备都接在这个强网之上。

哪怕ESS1内部某个530 Hz附近的模态本身阻尼不够，强网也可能把它压住。

所以并网阶段看到：

```text
PCC约10 kV
50 Hz正常
```

并不证明ESS1单独构网一定稳定。

---

当J1打开以后：

```text
Grid退出
↓
ESS1 GFM接管
```

ESS1从：

```text
“跟着电网运行的设备”
```

变成：

```text
“自己建立电压和频率的电网源”
```

这时候原来被强网压住的动态问题暴露出来了。

---

# 2. 现在真实电气链已经查到什么程度？

目前已经沿着ESS1整条功率路径测了四个位置：

```text
ESS1_Control
↓
PWM
↓
ESS1_Converter

[测点1]
inv_Vab
= Converter交流出口
= L1之前

↓
L1

[测点2]
LCout_Vab
= L1之后
= C1并联节点
= Stubline之前

↓
Stubline
↓
Transformer

[测点3]
prim_ESS1_Vab

↓
Line_ESS1

[测点4]
PCC_Vab
```

---

# 3. 这四个位置测到了什么？

J1打开以后：

```text
inv
LCout
prim
PCC
```

四个位置全部出现同一个快速振荡。

而且主频不是瞬间固定530 Hz，而是逐渐变化：

```text
约130 Hz
→180 Hz
→300 Hz
→420 Hz
→470 Hz
→500 Hz
→520 Hz
→530 Hz附近
```

最后稳定到：

```text
约530~532 Hz
```

这说明它不是一个简单的测量错误。

而是：

# **真实的控制—电气系统失稳过程。**

---

# 4. 最关键的新发现是什么？

最重要的是：

```text
inv_Vab
```

也就是：

```text
ESS1_Converter刚输出
L1还没有经过
```

这里已经出现了很强的530 Hz分量。

这点极其重要。

因为它排除了一个过于简单的解释：

```text
Converter输出本来很正常
↓
只是L1/C1在后面自己振了
```

不是这样。

实际是：

```text
Converter输出端
已经参与530 Hz振荡
```

---

# 5. 那是不是已经证明ESS1_Control写错了？

还不能。

这是现在最容易误解的一点。

虽然Converter端已经振荡，但ESS1_Control本身是一个闭环控制器。

它不是自己闭着眼睛输出电压。

它一直在读取：

```text
Vabc
Iabc
P
Q
```

然后根据这些反馈重新计算PWM。

所以完全存在下面这种情况：

```text
LC/外部网络先有振荡趋势
↓
V/I反馈也开始振
↓
ESS1_Control看到了这个振荡
↓
控制器为了纠正它而不断动作
↓
结果相位不合适
↓
控制器反而继续给这个530 Hz模态“加能量”
↓
Converter端也出现同频振荡
```

因此：

```text
inv也振
```

说明控制器/Converter已经进入这个模态，

但还不能证明：

```text
控制器是最初唯一的发起者
```

---

# 6. 现在最可能是什么本质？

目前最合理的解释是：

# **ESS1 GFM快速控制闭环与约0.53 kHz的LC/网络自然模态发生了耦合，导致该模态阻尼不足甚至出现负阻尼。**

换成人话：

系统里面本来就存在一个大约527 Hz附近的“容易振的频率”。

这个频率本身存在并不奇怪。

就像：

```text
弹簧 + 质量
```

本来就有一个固有振动频率。

真正的问题不是：

```text
系统有527 Hz固有频率
```

而是：

```text
振起来以后为什么不衰减？
```

正常系统应该：

```text
扰动
↓
振几下
↓
越来越小
↓
回到50 Hz
```

现在却是：

```text
J1打开
↓
振荡被激发
↓
没有衰减
↓
反而越来越成为主导波形
```

这说明：

# **阻尼不够。**

甚至可能某些控制环节在这个频率附近表现成了“负阻尼”。

---

# 7. 为什么一直说527 Hz和530 Hz很关键？

根据现有L1、C1、Transformer漏抗、Stubline漏抗等参数，之前计算得到一个理想化自然模态：

```text
约527.4 Hz
```

而现在10 kHz实测：

```text
后期真实主振荡约530~532 Hz
```

两者非常接近。

所以现在已经有很强证据说明：

> **ESS1相关LC/网络的自然模态确实参与了当前失稳。**

但要注意：

```text
527 Hz
不是系统应该运行的频率
```

系统仍然应该运行在：

```text
50 Hz
```

527~532 Hz只是叠加在50 Hz电压上的一种快速振荡模态。

---

# 8. L1/C1有没有问题？

有参与，但不能简单说“L1/C1错了”。

实测显示：

```text
inv
↓
LCout
```

到了530 Hz附近，LCout相对inv大约又增强了20%~34%。

所以：

```text
L1/C1
```

确实在这个频率附近具有明显的频率选择性和放大作用。

这和：

```text
LC谐振
```

非常吻合。

但因为：

```text
L1之前的inv也已经振
```

所以不能说：

```text
只要换L1/C1就一定解决
```

更合理的是：

```text
LC提供了这个自然模态
+
控制闭环没有把它阻尼住
```

两者共同形成问题。

---

# 9. Stubline是不是主要问题？

目前优先级已经下降。

因为：

```text
LCout
```

在Stubline之前已经强烈振荡。

而：

```text
LCout
→ Stubline
→ Transformer
→ prim
```

这段并没有出现明显的额外巨大放大。

因此：

> **不能再把Stubline当作第一嫌疑。**

当然它仍可能通过：

```text
漏抗
数字分区
任务延时
```

影响整体阻尼，

但不是：

```text
“SS出来健康，过Stubline才坏”
```

这种简单问题。

---

# 10. PCC为什么显示55 Hz？

现在这个问题已经解释得很清楚。

PCC电压真实波形已经不是健康50 Hz正弦。

变成：

```text
50 Hz基波
+
很强的530 Hz快速振荡
```

PLL接收到这种严重畸变波形以后：

```text
不能正确跟踪真正的基波相位
```

于是输出频率一路偏移，

最后碰到了人为设置的：

```text
55 Hz上限
```

所以：

```text
PCC freq = 55 Hz
```

不是：

```text
这个孤岛真的稳定运行在55 Hz
```

而是：

# **PLL在异常电压下失锁后的表现。**

---

# 11. 为什么这个问题一定要解决？

因为它不是“曲线不好看”。

它直接破坏：

```text
孤岛电网本身
```

---

## 11.1 S5真实孤岛

S5真正成功应该是：

```text
J1打开
↓
ESS1接管
↓
建立稳定约10 kV
↓
稳定约50 Hz
```

现在只能做到：

```text
J1打开
ESS1切GFM
```

但后面电压严重振荡。

所以：

```text
S5逻辑执行成功
≠
S5真实孤岛成功
```

---

## 11.2 S14黑启动

黑启动的本质就是：

```text
没有Grid
↓
ESS自己建立健康电网
```

如果ESS一构网就530 Hz强振荡：

```text
BLACK_START状态机即使走完
```

也不能叫黑启动成功。

---

## 11.3 S15重同步

重同步需要：

```text
ΔV
Δf
Δθ
```

但现在：

```text
PCC Vabc不健康
↓
PCC频率不可信
↓
PCC相位不可信
```

所以根本无法正确做：

```text
岛内 vs Grid
```

同步判断。

---

## 11.4 BOARD15以后也解决不了这个问题

BOARD15属于：

```text
上层协调控制
```

而530 Hz周期只有：

\[
T=\frac{1}{530}
\approx1.89\text{ ms}
\]

这是非常快的电力电子动态。

Board以后即使100 ms做一次协调：

```text
100 ms里
530 Hz已经振了大约53次
```

所以Board没有能力直接去压这个振荡。

它必须由：

```text
逆变器本地快速控制
+
LC/网络阻尼
```

解决。

---

# 12. 那到底怎么解决？

现在不要“猜一个PI然后乱调”。

真正解决要分两步：

# **第一步：找到是谁在给530 Hz模态加能量。**

# **第二步：针对这个环节增加阻尼。**

---

# 13. 下一步最关键的是看PWM之前的控制输出

我们现在已经看完：

```text
inv
LCout
prim
PCC
```

继续测更多电气点意义已经不大。

下一步应该看：

```text
ESS1_Control Outport1
↓
ESS1_PWM input1
```

也就是：

# **PWM之前的调制参考。**

它能够直接告诉我们：

```text
530 Hz到底是控制器自己输出出来的
还是功率级/网络先振以后控制器才被带着振
```


# 15. 最可能的“最终修法”是什么？

根据现在所有证据，最有可能不是一个单独开关，而是以下几种中的一项或组合：

## 方案1：增加主动阻尼

让控制器看到LC振荡以后主动产生反向阻尼作用。

例如：

```text
虚拟电阻
虚拟阻抗
电容电流反馈
主动阻尼环
```

这是解决LC模态最典型的方法之一。

---

## 方案2：重新设计500 Hz附近测量滤波

目前：

```text
fn_Filter = 500 Hz
```

而真实模态：

```text
≈530 Hz
```

两者太接近。

如果滤波器在这个频率附近带来较大相位滞后，

控制器本来想“刹车”，

最后可能变成：

```text
晚了一拍
反而推了一把
```

这就是典型的阻尼恶化。

---

## 方案3：重新整定Current / Voltage Loop

如果环路带宽和530 Hz模态没有拉开，

就可能和LC模态发生耦合。

需要重新协调：

```text
Current loop
Voltage loop
LC resonance
Fsw
Ts
measurement filter
```

---

## 方案4：减少快速反馈延时

现在ESS1快速反馈路径涉及：

```text
SS功率级
↓
Stubline/SM
↓
prim V/I
↓
Memory / communication
↓
SS ESS1_Control
```

在530 Hz：

```text
100 μs延时
≈19°相位
```

几个100 μs叠加以后，对稳定裕度影响很大。

如果最终证明确实是延时主导，

最合理的架构会是：

```text
快速V/I内环尽量在SS本地闭合

prim高压侧量
保留给：
P/Q
监督
保护
策略
```

---

## 方案5：修正参数不一致

当前还有明确风险：

```text
L1物理表达式仍按60 Hz换算
当前系统是50 Hz

Lff = 0.21 pu
实际物理等效约0.18 pu
```

如果控制器认为的对象和真实Plant不一样，

也会影响阻尼。

---

## 方案6：如果最后证明是多GFL交互

那就需要调整：

```text
GFL PLL带宽
Current loop
虚拟阻抗
弱网适配
```

而不是只改ESS1。

---

# 16. 为什么现在不能一次把这六种全改掉？

因为如果全部一起改：

```text
最后系统好了
```

你也不知道：

```text
到底是谁造成的
```

以后：

```text
换参数
换板
换模型
换工况
```

很可能再次出问题。

所以现在必须遵循：

```text
诊断一层
↓
确认机制
↓
只改一个关键机制
↓
回归
```

# 18. 你现在应该怎样记住整个问题？

最简单记成下面这句话：

> **并网时强网把系统压在50 Hz；离网后ESS1自己构网时，一个约530 Hz的LC/控制耦合模态被激发，而且系统没有足够阻尼，所以振荡越来越强。530 Hz不是系统频率，而是叠加在50 Hz上的快速振荡。它已经从Converter出口一路存在到PCC，因此不能只怪PLL、PCC、Stubline或LC某一个块。下一步要查PWM前控制参考和Voltage/Current loop，找出是谁在给这个530 Hz模态“加能量”，然后通过主动阻尼、滤波/PI重新整定、反馈延时优化或多GFL弱网协调把它压下去。这个问题必须解决，因为S5真实孤岛、S14黑启动、S15重同步以及最终BOARD15/CHIL都建立在“ESS1能先建立稳定50 Hz孤岛电网”这个前提上。**
