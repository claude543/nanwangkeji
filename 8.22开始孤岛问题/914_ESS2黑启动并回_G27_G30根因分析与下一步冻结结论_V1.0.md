# 2026-09-14｜ESS2黑启动并回失败：G27+G30根因分析与下一步冻结结论

> 项目：K26_K50_CLEAN_P1  
> 场景：ESS1（储能1）唯一GFM（构网型变流器）黑启动建网，ESS2（储能2）作为第一台GFL（跟网型变流器）执行零功率物理并回  
> 数据：G27（ESS2高速诊断）+ G30（ESS1高频详细诊断）  
> 结论级别：**高置信度根因假设，已具备下一轮单变量因果实验条件；尚未完成最终因果闭环**

---

## 1. 本轮最重要结论

本轮ESS2并回失败，不是因为：

- Current PI（电流比例积分调节器）没有恢复真实电流反馈；
- 合闸前两侧严重不同步；
- RestoreAlpha（恢复系数）提前释放功率；
- CurrentLimit（电流限制）持续触发；
- PostOK（合闸后健康判据）阈值设置稍微偏严；
- ESS1（储能1）的Fout（构网输出频率参考）本身发生大幅猎振。

当前最强证据指向：

> **黑启动S14阶段已经推进，但五台GFL原有的孤岛工程控制阶段没有同步推进。ESS2在真实并入弱孤岛时仍停留在`GRID_NORMAL（电网正常）`控制状态，因此历史上已经证明在弱孤岛中有风险的`terminal Vdq direct feedforward（端电压dq直接前馈）`被完整保留。**

这意味着当前问题本质上是：

```text
S14 Black-Start Stage
（S14黑启动阶段）

与

GFL Engineering Stage
（跟网设备孤岛工程控制阶段）

之间缺少黑启动场景下的阶段协同/桥接。
```

因此当前实现已经真正形成：

```text
真实断路器闭合
↓
零电流参考
+
真实电流反馈
+
原Current PI主动纠偏
```

上一轮“合闸后真实电流反馈仍被屏蔽”的缺陷已关闭。

## 4. state4一直不能进入state5不是“门槛太严”

state4之后：

- CurrentLimit条件基本一直通过；
- 真正反复破坏PostOK的是电压和实际电流；
- PostOK最长连续满足时间远小于要求的0.2 s；
- 更严格的zero-stable（零功率稳定）状态也只零星出现毫秒级窗口，远小于2 s。

因此不能通过简单放宽：

```text
0.2 s → 0.1 s
2 s → 1 s
```

来“让状态机过关”。

状态机拒绝进入state5是正确反映了物理系统并未稳定。

## 5. 本轮最关键的G27数据证据

全程比较：

```text
RawVdq_d/q
（原始端电压dq）

与

FinalVFF_d/q
（最终电压前馈dq）
```

得到：

```text
FinalVFF_d - RawVdq_d = 0
FinalVFF_q - RawVdq_q = 0
```

即：

```text
FinalVFF ≡ RawVdq
```

这意味着整个黑启动并回试验中，ESS2的动态端电压直接前馈保持100%通过。

而现有GFL孤岛工程控制设计本来就是：

```text
Stage0 = GRID_NORMAL
Kslow = 1
Kfast = 1
Vff = Vraw

Stage1 = ISLAND_PREPARE
逐步退出动态端电压前馈

Stage2 = ISLAND_STABILIZE
抑制dynamic terminal-Vdq feedforward
保持弱孤岛兼容控制
```

因此本轮数据说明：

> **ESS2并没有进入为弱孤岛设计的GFL控制状态。**

## 6. 为什么会发生：两个“Stage”没有联动

### 6.1 S14 Black-Start Stage（S14黑启动阶段）

负责：

```text
Stage1：ESS1建网
Stage2：恢复非主储能ESS2
Stage3：恢复PV
Stage4：恢复EV
```

### 6.2 GFL Engineering Stage（跟网设备孤岛工程控制阶段）

负责：

```text
0 = GRID_NORMAL
1 = ISLAND_PREPARE
2 = ISLAND_STABILIZE
3 = ISLAND_POWER_RECOVERY
4 = GRID_RECONNECT_RECOVERY
```

这两套Stage不是同一个状态量。

本轮Runner保持：

```text
AA15_FINAL_SYSTEM_STAGE = 0
```

所以即使S14已经从Stage1推进到Stage2，GFL工程控制仍然认为：

```text
系统处于GRID_NORMAL
```

于是：

```text
Kslow = 1
Kfast = 1
↓
FinalVFF = RawVdq
```

这与G27观测完全一致。

## 7. 当前约26 Hz振荡的解释

本轮15–20 s附近出现明显约26 Hz共享模态。

ESS2侧：

```text
Iq
Vpu
VFF_d/q
CurrentPI
```

均出现约26 Hz主成分。

ESS1侧：

```text
Vq_meas
Vconv_q
Iq
PLL相关量
```

也出现同一频率成分。

ESS1与ESS2多个关键量在该频率附近具有很高相干性，因此这不是单设备记录噪声，而是：

```text
ESS1 GFM
+
ESS2 GFL
+
孤岛网络
```

共同参与的真实系统模态。

同时在该频带中：

```text
|VFF| >> |CurrentPI|
```

说明Current PI虽然确实在纠偏，但最终电压指令仍主要被动态端电压前馈主导。

因此目前最合理的机制链是：

```text
ESS2在错误Stage0并入弱孤岛
↓
100% dynamic terminal-Vdq feedforward仍开启
↓
ESS1有限GFM + ESS2 GFL + 网络形成低阻尼/不稳定闭环
↓
约26 Hz共享模态增长
↓
随后进入调制度饱和等非线性区
↓
出现谐波、振荡形态变化和暂时衰减
```

## 8. 与历史孤岛因果试验的关系

此前已经通过D/Q正交试验确认：

```text
dynamic terminal-Vdq direct feedforward
```

在弱孤岛中属于高风险结构路径。

历史结果：

```text
D ON / Q ON
→ 约17 Hz正增长

D OFF / Q OFF
→ 原快速失稳被打断

D ON / Q OFF
→ 原17 Hz消失，但转为d轴/电压崩溃

D OFF / Q ON
→ 约10.6 Hz强正增长
```

因此这次约26 Hz不能直接说成“完全相同的旧模态”，但可以说：

> **它与此前确认的动态端电压直接前馈风险机制高度一致；不同拓扑和工作点下，主频发生变化是合理的。**

## 9. 当前不能过度结论的部分

本轮尚不能证明：

```text
1 GFM + 1 GFL
```

这种结构本身不可稳定。

原因是这次ESS2并入时没有运行在正确的孤岛GFL控制状态，而是在GRID_NORMAL强网旁路状态。

因此当前不能把失败解释成：

```text
“一台GFM天生带不动GFL”
```

更不能外推成：

```text
“1 GFM + 5 GFL架构必然不可行”
```

## 10. 本轮发现的真正设计缺陷

当前设计缺口是：

```text
S14 Black-Start Stage
        ↓
缺少黑启动专用阶段桥接
        ↓
AA15_FINAL_SYSTEM_STAGE
        ↓
五台GFL孤岛支撑管理器
```

本质上不是GFL孤岛支撑控制本身“没做”，而是：

> **这套控制已经存在，但黑启动恢复流程没有把它正确调入工作状态。**
