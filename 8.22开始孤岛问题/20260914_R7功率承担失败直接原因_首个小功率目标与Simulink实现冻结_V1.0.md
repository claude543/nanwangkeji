# 2026-09-14｜R7功率承担失败的直接原因、首个小功率目标与Simulink实现方式冻结 V1.0

> 适用对象：K26_K50_CLEAN_P1 / S14黑启动 / ESS2首次功率承担  
> 数据依据：R7 G27+G30完整MAT  
> 设计原则：优先使用最合适的Simulink/Stateflow原生机制，不无脑增加MATLAB Function。

---

## 1. 当前最关键结论

R7并没有证明：

```text
ESS2根本不能承担任何功率
```

也没有证明：

```text
只要把2 s RestoreAlpha改慢就一定能解决
```

R7真正证明的是：

```text
ESS2零功率接入稳定
↓
Stage3正常孤岛功率协调器提前形成并持续移动的ESS2功率目标
↓
24.5 s MANUAL_RELEASE后RestoreAlpha开始增加
↓
“移动的正常调度目标”
+
“RestoreAlpha开放程度”
+
“Power PI积分状态”
三者同时变化
↓
母线电压进入持续下降
↓
电压下降后实际P更跟不上目标
↓
Power PI继续增加电流请求
↓
形成弱孤岛功率恢复正反馈
↓
CurrentLimit很晚才介入
```

因此直接问题首先是：

> **功率恢复结构本身没有把“首次功率拾取”与“正常孤岛长期功率调度”分开。**

---

## 2. 为什么不是“ESS2一承担一点功率就必然不稳定”

R7没有做任何一个：

```text
固定非零功率目标
+
长时间保持
```

的实验。

整个24.5~26.5 s期间：

```text
RestoreAlpha持续增加
PrefCmd持续变化
Power PI持续积分
```

所以不能从这一条动态斜坡直接推出：

```text
固定-0.005 pu也一定不稳定
```

或：

```text
固定-0.01 pu也一定不稳定
```

---

## 3. R7能给出的第一版“小功率”线索

### 3.1 Stage3先在Alpha=0时积累了非零目标

约：

```text
23.9 s：PrefCmd ≈ -0.0427 pu
24.0 s：PrefCmd ≈ -0.0427 pu
24.2 s：PrefCmd ≈ -0.0554 pu
24.4 s：PrefCmd ≈ -0.0681 pu
24.5 s：PrefCmd ≈ -0.0745 pu
```

而此时：

```text
RestoreAlpha = 0
实际P≈0
```

所以MANUAL_RELEASE开始时并不是“从零目标开始”。

而是：

> **打开一个已经积累到约-0.0745 pu、并且还在继续变化的正常调度目标。**

### 3.2 Release后前期

约：

```text
25.0 s：
Alpha≈0.25
Vpu≈0.993
IrefUsed≈0.0044 pu
Pmeas≈+0.0007 pu

25.18 s：
Alpha≈0.34
Vpu≈0.970
IrefUsed≈0.0098 pu
Pmeas≈-0.0010 pu

25.23~25.25 s：
100 ms平均Vpu跌破约0.95
IrefUsed≈0.012 pu量级
Pmeas≈-0.002 pu量级

25.40 s：
Vpu≈0.913
IrefUsed≈0.022 pu
Pmeas≈-0.0054 pu
```

因此R7最多只能给出：

> **一个“第一轮固定功率平台试验”的保守量级，而不能给出最终稳定能力。**

建议第一平台：

```text
P_pickup_test_1 ≈ -0.003 ~ -0.005 pu
```

含义：

- 这不是最终可承担功率；
- 只是明显低于R7持续下坠区的第一个因果测试点；
- 必须固定保持数秒，不能同时移动目标。

随后才可：

```text
-0.005
→ -0.01
→ -0.02 ...
```

逐档探索。

如果-0.003~-0.005 pu固定平台都无法稳定，则说明问题不再主要是“恢复太快”，而要进一步锁定：

```text
ESS2 Power Loop / Current Loop与ESS1 GFM的低频耦合
坐标/符号
功率环积分/anti-windup
GFM输出阻抗/电压环
```

## 4. R7真正的直接触发链

### 4.1 Stage3正常Coordinator先积累目标

Stage3进入后，ESS1 Fout仍约：

```text
50.23~50.24 Hz
```

高于50 Hz。

正常孤岛二次频率协调器因此继续产生负向ESS2功率命令：

```text
PrefCmd：
-0.043
→ -0.074
→ -0.107
→ -0.138
→ ...
```

### 4.2 24.5 s RestoreAlpha打开

此时：

```text
目标已经非零
而且仍在变化
```

### 4.3 Power PI开始持续积分

电压一旦下降：

```text
实际P更难跟上PrefEff
↓
Perror长期存在
↓
RawIdRef继续增大
↓
实际Iref增加
↓
ESS1有限GFM母线进一步受压
```

### 4.4 CurrentLimit不是初始触发

电压已经降至很低后，CurrentLimit才动作。

所以初始触发不是：

```text
限流
```

而是：

> **正常调度目标 + RestoreAlpha + Power PI同时动态变化，在有限GFM弱岛中形成不良闭环。**

---

## 5. “2 s太快”是不是根因

当前只能说：

```text
2 s开放环斜坡明显过于激进/不合理
```

但不能说：

```text
只要改成5 s或10 s就一定解决
```

因为：

- PrefCmd本身还在移动；
- Power PI还在积分；
- 没有固定功率平台；
- 没有观察“某一个功率值”是否有稳定平衡点。

因此下一步必须：

```text
先冻结功率目标
再单独测试不同功率平台
```

之后才能决定最终功率上升速度。

## 6. 如果第一个小功率平台也失败，接下来怎么办

不是只回退然后结束。

按因果诊断顺序：

### A. 小功率固定目标失败

检查：

```text
Power PI积分状态
实际Iref与目标Iref
Current PI误差
ESS1 Vref/Fout
ESS1电压环/电流环
ESS2 VFF / CurrentPI
```

如果目标固定、没有正常Coordinator漂移、没有Alpha变化，仍然电压持续下降：

> 问题被锁到“底层功率环/GFL-GFM耦合”。

### B. 小功率稳定，大一点失败

则证明：

> 存在实际的ESS1+ESS2稳定功率边界。

以后黑启动算法的任务就是：

```text
在这个边界内逐步承担功率
并根据在线余量调整
```

### C. 充电方向失败、放电方向稳定

则说明：

> 存在明显的功率方向相关性，黑启动低压时ESS2充电必须退让，而ESS2放电可能是支撑资源。

## 7. Simulink / Stateflow最合适的实现方式

### 7.1 高层状态机：优先Stateflow，而不是MATLAB Function

适用于：

```text
S14黑启动全局状态
ESS2恢复状态
失败回退
重试
超时
健康驻留
```

Stateflow本来就是为：

```text
supervisory control
state machine
fault management
hybrid systems
```

设计的。

其时间逻辑：

```text
after(...)
duration(...)
```

非常适合：

```text
健康持续200 ms
低压持续100 ms
恢复后保持2 s
```

而不需要手写计数器。

RT-LAB与MATLAB/Simulink/Stateflow有官方集成基础；但正式迁移前仍需要在当前RT-LAB 2024.1 + R2023b环境做最小Build验证。

### 7.2 功率目标斜率：Rate Limiter / Rate Limiter Dynamic

不要在Function里手写：

```text
P = P + step
```

Rate Limiter可直接限制变化率。

Rate Limiter Dynamic更适合：

```text
健康时：允许缓慢增加
临界时：上升速率=0
恶化时：允许快速回退
```

也就是动态改变上升/下降速率。

### 7.3 阈值滞回：Relay

例如：

```text
Vpu > 0.95 → HEALTHY
Vpu < 0.92 → NOT_HEALTHY
```

中间区域保持原状态。

避免电压在阈值附近抖动导致状态反复切换。

### 7.4 条件执行：Enabled / Resettable Subsystem

例如：

```text
只有POWER_PICKUP阶段
才允许临时功率目标积分/斜坡模块运行
```

退出该阶段后：

```text
Resettable Subsystem
```

可以明确复位内部状态。

### 7.5 多条件决策：Stateflow Truth Table

对于：

```text
V/f健康？
CurrentLimit？
ModHeadroom？
Perror扩大？
ESS1余量？
```

这些组合逻辑，如果条件较多，可使用Truth Table，而不是十几个If嵌套。

### 7.6 Power PI anti-windup：优先审计“实际执行量反馈”

当前Power PI后面还有：

```text
RestoreAlpha
Current Adapter
CurrentLimit
```

因此PI输出并不等于真正执行的Iref。

MathWorks PID支持：

```text
tracking mode
external anti-windup
```

用于“下游还有饱和/执行器动态”的情况。

我们当前自定义PI不一定要替换成PID Controller，但应检查是否需要：

```text
把真正IrefUsed反馈给Power PI anti-windup/tracking
```

避免外环在实际执行受限时继续积累。

## 8. 下一步最小因果实验应怎样设计

不要先加完整健康门。

先做：

```text
ESS1建网
↓
ESS2 Stage1/2
↓
ESS2零功率并回
↓
不进入正常Stage3二次调度
或冻结其ESS2输出
↓
给ESS2固定临时功率目标
例如 -0.003~-0.005 pu
↓
用Rate Limiter缓慢从0走到该值
↓
保持3~5 s
↓
看能否形成稳定非零功率工作点
```

必须记录：

```text
固定目标
Pmeas
Perror
Power PI内部积分/输出
IrefUsed
Id/Iq
Vpu
ESS1 Fout/Vref
ESS1电流
```

若第一平台稳定，再增加第二平台。

## 9. 当前最终判断

### 已经明确

```text
ESS2零功率接入可以稳定
旧26 Hz VFF问题已解决
Stage3授权但Alpha=0可以稳定
MANUAL_RELEASE以后才开始持续电压下坠
CurrentLimit不是初始触发
```

### 高置信度直接原因

```text
正常长期调度目标在Stage3持续移动
+
RestoreAlpha开放
+
Power PI积分
同时作用
```

导致ESS2首次功率承担不是一个干净的“固定小功率拾取”，而是一个多环同时运动的动态过程。

### 尚不能证明

```text
ESS2完全不能承担任何非零功率
```

也不能证明：

```text
只改慢RestoreAlpha就能解决
```

下一轮固定小功率平台试验就是为了区分这两种可能。
