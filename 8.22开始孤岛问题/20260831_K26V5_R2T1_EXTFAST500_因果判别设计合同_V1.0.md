# K26_V5｜R2-T1 F25 Extended-FAST500 因果判别设计合同 V1.0

## 核心结论

500 ms **不是强制FAST持续时间**，而只是 F25 的最大诊断上限。

F25 模型本地逻辑仍然是：

```text
state4 FAST
│
├─ post candidate一旦成熟
│  + F22 ack
│  + Vmag健康
│
│  → 立即state5 SMOOTH_COMMIT
│  → state6 HOLD
│
└─ 只有一直没有candidate
   且fast_count达到maxFast
   → timeout
   → state7 FALLBACK
```

所以如果六机在 130 ms、180 ms、240 ms 就稳定，F25 会直接提前退出FAST，不会为了“等满500 ms”继续动态跟踪。

---

## 为什么选500 ms，而不是不停试时间

不是做 120/150/200/300/500 ms 扫参。

当前 R2V1.4 的决定性时间是：

```text
旧F25 timeout      ≈ +100.2 ms
旧明显过压首样本   ≈ +155 ms
旧V<9 kV          ≈ +175 ms
旧V<5 kV          ≈ +180 ms
```

因此本轮只需要一个足够大的反事实窗口，明确跨过旧失稳区。

本轮解释分成：

```text
0~250 ms
Primary因果判别窗口

250~500 ms
secondary / slow-mode诊断窗口

500 ms
有限硬上限
```

最终算法如果确认100 ms过短，正确方向是状态驱动结束，不是把500 ms写死成最终值。

## 为什么500 ms不会造成“结果误导”

本轮提前写死四种分叉：

```text
A.
>100ms后candidate自然成熟
+ V/f健康
→ H1强确认：100ms cutoff过早

B.
<250ms内
F25仍state4 FAST
无timeout
无限幅饥饿
但V/f同型失稳
→ H1作为Primary被否决

C.
延长FAST过程中撞slew/mag authority
→ 单独进入authority分支
→ 禁止直接放大0.6pu

D.
旧155~180ms窗口被推迟
但250~500ms出现新的慢模态
→ long-FAST / low-frequency分支
→ 与历史continuous IOUT慢模态和五GFL共同模态比较
```

所以500 ms不是“越长越好”，只是让一个运行同时观察旧100 ms cutoff两侧。
