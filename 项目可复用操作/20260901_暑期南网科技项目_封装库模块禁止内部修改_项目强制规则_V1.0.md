# 暑期南网科技项目｜封装/库模块禁止内部修改——项目强制规则 V1.0

> 日期：2026-09-01  
> 适用范围：后续所有 K26_V5、RT-LAB、Simulink 控制器调试、因果 A/B、正式解决方案 Patch、模型交接与窗口交接文档。

## 一、永久规则

后续**不要进入带 Mask / Library Link / simulation callbacks 的封装或厂家库模块内部进行修改**。

尤其包括但不限于：

```text
MathWorks Specialized Power Systems 厂家模块
PLL (3ph)
Power (PLL-Driven, Positive-Sequence)
其它库链接、Mask、callback 驱动的专用模块
```

即使程序化方式理论上可能通过：

```text
LinkStatus = inactive
解除库链接
修改封装内部连接
复制厂家内部实现
```

也**不作为本项目优先或默认修改方法**。

## 二、原因

1. GUI 无法正常 Expand / 展开带 simulation callbacks 的模块，说明其内部结构依赖厂家封装、库链接或回调机制。
2. 修改内部实现会引入：
   - library link 状态变化；
   - callback 行为变化；
   - 厂家内部状态/初始化逻辑被破坏；
   - 模型更新、Build、代码生成与 RT-LAB 兼容性风险；
   - 后续模型维护困难。
3. 本项目此前稳定成功的修改方式主要发生在：
   - 用户可编辑普通 Subsystem；
   - Control wrapper；
   - Measurements wrapper；
   - 顶层模式选择；
   - F21/F22/F24/F25 等外围协调模块；
   - RootDiag / OpWrite 诊断层。
4. 当前 PLL 因果 B 试验已经证明可以在 `Measurements` 外层完成同等甚至更干净的干预，因此没有必要破坏厂家 PLL 内部。

## 三、默认替代策略

以后遇到需要改变厂家封装模块行为时，优先顺序固定为：

```text
第一优先：
在封装模块的输入/输出外层增加 wrapper / manager / selector / track-hold / state manager

第二优先：
利用模块已经暴露的正式参数、输入或模式接口

第三优先：
在上层统一替换参考值、状态、测量量或执行量，但必须保持坐标系/状态一致

最后才考虑：
内部封装修改
```

最后一种原则上默认禁止，除非：

```text
1. 外围方式已经被严格证明无法实现目标；
2. 有完整内部结构审计；
3. 明确确认库链接/回调/代码生成行为；
4. 用户明确批准；
5. 有独立备份和可逆 rollback。
```

## 四、PLL 相关当前具体冻结

当前 five-GFL PLL 因果 B 试验：

```text
不修改：
PLL (3ph) 内部
PLL mask
ParK
Par_Init
PID内部
spsPLL3phLib
library link
simulation callbacks
```

只允许修改：

```text
各 GFL 的 Measurements wrapper
+
父级 GFL Control 中执行 thetaF / FreqF 的连接
```

当前正式 B 方案：

```text
native PLL Freq / wt
↓
Measurements 外层 AA15_PLL_EXEC_FRAME_HOLD
↓
execution Freq / theta
↓
原 abc→dq / P/Q / Current Regulator / Vref Generation / PWM
```

同时：

```text
raw native PLL
继续通过原 RootDiag 记录
```

## 五、后续交接文档强制要求

以后所有窗口交接、阶段总结、Build 前冻结说明、根因报告中都必须明确记录：

> **本项目后续禁止优先进入 Mask / Library Link / simulation callbacks 厂家封装内部修改。默认采用 wrapper / 外围协调方式实现控制干预。当前 PLL B 因果试验已正式放弃内部 PLL Patch，改为 Measurements 外层一致 frame hold 方案。**

不得在新窗口中重新提出：

```text
解除 PLL library link
直接修改 PLL (3ph)/Model
直接修改厂商 PID 内部
```

除非出现新的直接证据证明外围方案无法完成目标，并重新经过用户批准。
