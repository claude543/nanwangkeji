# K26_V5 V4.9｜R5仍误报F25 BYPASS NaN的根因与R6修复

## 0. 结论

这次 R5（第5版）仍然报：

```text
F25 disabled BYPASS:
authoritative F25 signal(s) non-finite:
F25_applied_d, F25_applied_q
```

不是因为 V4.9（版本4.9）三条主改模已经被证明设计错误。

当前直接证明的是：

> **R5 仍然错误地假设：F25 在 disabled BYPASS（关闭旁路）阶段，Host（上位机）在线读取到的 `F25_applied_d/q` 必须是有限数，并且这两个 Host 在线量在该阶段拥有物理控制权。**

当前 Build（构建）真实运行已经直接证伪了这条假设：

```text
F25_ENABLE = 0
F25_state = 0 BYPASS

但：

F25_applied_d = NaN
F25_applied_q = NaN
```

因此不能再继续通过“把 NaN 放宽一点”这种方式逐个补丁。

正确修复是重新定义：

```text
不同 F25 state（状态）
→ 哪些 Host 在线信号当前真正拥有控制/安全语义
→ 哪些只是未激活 telemetry（遥测/诊断）
```

---

# 1. 为什么 R5 还是报错

R4（第4版）的问题是：

```text
F25 36个输出
→ 全部要求 finite（有限）
```

R5 已经把很多未激活诊断量降为 warning-only（仅警告）。

但是 R5 仍保留：

```text
BYPASS hard keys:
F25_applied_d
F25_applied_q
F25_state
```

也就是说 R5 仍然认为：

```text
F25_ENABLE=0
→ applied_d/q 仍然是当前物理施加路径
→ 所以它们必须 finite
```

当前真实运行结果：

```text
F25_applied_d/q = NaN
```

因此 R5 仍在 Stage0（阶段0）刚运行到约1 s就 Reset（复位）。

这说明：

> **R5 修复了“36个量全硬门”的大错误，但没有完全修掉“Host在线数值端口在所有状态都代表物理当前值”的更深层错误。**

---

# 2. 这次最重要的认识：Signal exposed ≠ Signal authoritative

RT-LAB（实时仿真平台）能够通过：

```text
GetSignalsByName
```

读到某个内部 port（端口），只说明：

```text
这个内部信号被Host暴露
```

不代表：

```text
它在每一个控制状态都已初始化
它在每一个控制状态都参与真实执行
它在每一个控制状态都适合作为hard gate
```

本项目永久证据层级应该继续遵守：

```text
模型内部真实state / physical execution
>
目标侧高分辨率 G30 MAT
>
Host异步在线读取
```

因此：

```text
Host F25_applied_d/q = NaN
```

不能直接等同：

```text
实际施加到ESS1的电流前馈 = NaN
```

尤其是在：

```text
F25_ENABLE=0
state=0 BYPASS
```

这种明确未激活状态。

# 3. 为什么现在还不能说是模型设计问题

当前脚本的执行顺序是：

```text
Stage0运行到1s
↓
read_snapshot
↓
assert_f25_disabled_sanity
↓
然后才检查：
six_gfl_normal
grid_electrical_healthy
```

R5 在 F25 Host 数值检查处提前退出。

所以我们甚至还没有让脚本完成：

```text
F25关闭且applied Host量为NaN
但是
PCC电压/频率/六机模式是否仍然完全健康
```

这一关键判别。

因此目前最严谨的结论：

```text
[已证明]
Host在线F25_applied_d/q在BYPASS为NaN

[尚未证明]
实际物理施加路径为NaN

[尚未证明]
F25模型内部有设计错误

[更没有证明]
V4.9方向映射 / Current Adapter / q-bias三条主修复设计错误
```

# 4. R6 的正确判别逻辑

R6（第6版）不再把 F25 的 Host 数值向量在所有阶段当硬门。

## 4.1 BYPASS（旁路）

当：

```text
F25_ENABLE = 0
```

硬检查只有：

```text
F25_state finite
F25_state = 0
```

然后实际安全性由本来就存在的：

```text
six_gfl_normal
grid_electrical_healthy
topology
PCC V/f
```

继续判决。

`F25_applied_d/q`、候选量、统计量若是 NaN：

```text
WARNING
继续
```

---

## 4.2 PREPARE_ESTIMATE（准备估计）

当 F25 真正 Enable（使能）后进入 state1：

硬检查：

```text
state
pre_ready
timeout
+
真实强网电气健康
```

Host 的：

```text
applied_d/q
candidate_d/q
```

若暂时 NaN，不立刻 Reset。

如果：

```text
pre_ready = 1
```

但 Host candidate（候选值）仍 NaN：

```text
记录 WARNING
继续按 state-machine（状态机）合同
```

数值候选最终由 G30（第30记录组）MAT 判决。

---

## 4.3 PREPARED_HOLD（准备完成保持）

真正关键的是：

```text
state = 2
pre_commit_ack = 1
edge_seen = 0
timeout = 0
```

这些是状态机是否成功接管的权威合同。

`pre_bias` / `applied_d/q`：

```text
如果Host能正常读取
→ 做一致性检查

如果Host仍NaN
→ 不让Host遥测缺口破坏正式运行
→ 交给G30/MAT判断
```

同时强网：

```text
P/Q/V/f
模式
P/Q COMMIT
F24 READY
```

仍必须正常。

如果真实物理路径真的被 NaN 污染，这一层的电气健康会首先失败，不会被“忽略”。

---

## 4.4 EDGE_ARMED / J1 OPEN

F25 的硬合同改为：

```text
state
ack
edge_armed
edge_seen
event_match
fast_active
timeout
```

这些决定：

```text
F25状态机有没有正确看到真实J1事件
有没有进入FAST_TRANSFER
```

Host applied numeric（施加数值）继续作为 best-effort（尽力读取）遥测。

---

## 4.5 J1打开以后

严格执行：

```text
Evidence-first（证据优先）
```

硬 NaN/Inf 门：

```text
PCC P/Q/V/f
F24有效参考
F25 state / edge / event / timeout
J1真实状态
```

F25 内部数值诊断：

```text
applied
candidate
post mean/std
ramp
limit
```

若 Host 读取 NaN：

```text
记录
不中断15 s数据
```

最终由：

```text
G26~G30
尤其G30 ESS1
```

判断目标侧真实数值。

# 5. 什么时候才说明模型/F25本身有问题

R6 把判别点明确分开。

## 情况 A

如果 R6 越过 Stage0：

```text
F25_ENABLE=0
F25_state=0
applied Host = NaN

但是：
六机模式正常
V/f正常
P/Q正常
```

则可以直接证明：

> BYPASS阶段的 `F25_applied_d/q=NaN` 是 Host/未激活遥测语义，不是实际物理 NaN。

---

## 情况 B

如果 F25 Enable 后：

```text
state不能从0进入1/2
pre_ready/ack不形成
timeout
```

这才进入：

```text
F25状态机 / 参数 / 接口问题
```

---

## 情况 C

如果 state/ack 正常，但 F25 Enable 或 Commit 后：

```text
PCC V/f立即NaN
模式异常
真实电气状态崩坏
```

这时才有资格怀疑：

```text
F25真实执行路径
或
F25与当前V4.9模型集成
```

---

## 情况 D

如果整轮运行正常，但 Host F25数值始终NaN，而 G30 中：

```text
applied_d/q
pre_bias
FAST target
```

是有限且正确的：

则根因锁定为：

```text
RT-LAB Host在线内部信号可观测性 / 映射语义
```

不是控制模型问题。

---

## 情况 E

如果 G30 目标侧同样显示：

```text
F25 applied / bias
在真正active状态仍NaN
```

才可以确认：

> **F25模型内部或集成设计存在真实问题。**

这时再改模型，而不是现在提前改。

# 10. R6的意义

这一版不是简单地：

```text
把NaN检查删掉
```

而是把监督原则改成：

```text
当前Phase真正拥有物理/状态机权威性的量
→ hard gate

未激活/Host不可靠的内部遥测
→ warning/evidence

真实P/Q/V/f
→ 始终保留硬安全意义

G30
→ F25数值执行最终判据
```

因此下一次若仍停止，错误位置将能真正区分：

```text
Python监督问题
vs
RT-LAB Host可观测问题
vs
F25模型/集成问题
vs
真实物理失败
```

而不是继续“一个NaN就Reset”。
