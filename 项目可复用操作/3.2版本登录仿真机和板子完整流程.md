# 3.2版本登录仿真机和板子完整流程

## 二、窗口1：登录RTServer并检查1502

在Windows新开PowerShell：

```bash
ssh -o KexAlgorithms=+diffie-hellman-group14-sha1 -o HostKeyAlgorithms=+ssh-rsa -o MACs=+hmac-sha1 root@192.168.10.87
```

输入RTServer密码。

登录后执行：

```bash
hostname
ip addr show eth1
ss -lntp | grep ':1502'
```

没有ss时执行：

```bash
netstat -lntp | grep ':1502'
```

必须看到类似：

```text
192.168.1.100:1502  LISTEN
```

或：

```text
0.0.0.0:1502  LISTEN
```

保留该窗口。

---

## 三、窗口2：建立板子SSH隧道

再开一个PowerShell：

```bash
ssh -N -o KexAlgorithms=+diffie-hellman-group14-sha1 -o HostKeyAlgorithms=+ssh-rsa -o MACs=+hmac-sha1 -o ExitOnForwardFailure=yes -L 127.0.0.1:10023:192.168.1.10:10022 root@192.168.10.87
```

输入RTServer密码。

随后窗口保持空白是正常的。不要关闭，也不要在其中继续输入命令。该隧道路径是：

```text
Windows 127.0.0.1:10023
→ RTServer 192.168.10.87
→ 板子192.168.1.10:10022
```

---

## 四、窗口3：确认隧道

再开第三个PowerShell：

```powershell
Test-NetConnection 127.0.0.1 -Port 10023
```

必须看到：

```text
TcpTestSucceeded : True
```

## 五、通过隧道上传V3.2程序和JSON

在窗口3完整执行：

```bash
scp -P 10023 "C:\Users\linjj\Desktop\PVenergy\modbus_ceshichengxu\modbus_tcp_master_test(9)" root@127.0.0.1:/tmp/modbus_tcp_master_test_v32
```

再上传配置：

```bash
scp -P 10023 "C:\Users\linjj\Desktop\PVenergy\modbus_ceshichengxu\modbus_tcp_master_test_config(5).json" root@127.0.0.1:/tmp/modbus_tcp_master_test_config_v32.json
```

然后重新上传。

## 六、登录板子

仍在窗口3执行：

```bash
ssh -p 10023 root@127.0.0.1
```

输入板子密码。

登录成功后检查：

```bash
hostname
uname -m
ip addr show eth1
```

应确认：

```text
uname -m = aarch64
eth1 = 192.168.1.10
```

上传的程序本身也是AArch64可执行文件，与板子架构一致。

---

板子中执行：

```bash

ls -lh /tmp/modbus_tcp_master_test_config_v32.json
```

```bash
chmod +x /tmp/modbus_tcp_master_test_v32
```

```text
1be13206bf41a3a35db501ec69293066b9a8db68b43b73bc93d5c72df795006b
```

## 八、确认板子到RT-LAB网络

执行：

```bash
ping -c 4 192.168.1.100
```

应能收到响应。即使目标禁止ICMP，只要RTServer已经确认1502监听，仍可继续用程序进行实际连接测试。

---

## 九、启动V3.2程序

明确指定配置文件运行：

```bash
/tmp/modbus_tcp_master_test_v32 --config /tmp/modbus_tcp_master_test_config_v32.json
```

当前配置的重要参数是：

```text
RT-LAB IP = 192.168.1.100
Port = 1502
Unit ID = 1
通信周期 = 1000 ms
RT-LAB心跳超时 = 3500 ms
连续有效周期 = 3
test_mode = true
agc_enable = false
external_enable_request = false
```

板端日志应出现类似：

```text
MODBUS_CONNECTED
FC03读取成功
FC16写入成功
```

## 链路恢复后的完整操作

现在链路已经恢复正常：

```text
192.168.1.10能够回应ARP
10022/tcp = open
22/tcp = closed
```

这正符合原登录方案：板子SSH端口是10022，不是22。

前后两次MAC地址不同，也说明之前的接线或端口确实有问题；当前这次连接才是正确链路。

### 1. 重新建立隧道

先把之前保持空白的旧隧道窗口按：

```text
Ctrl+C
```

然后重新执行：

```bash
ssh -N -o KexAlgorithms=+diffie-hellman-group14-sha1 -o HostKeyAlgorithms=+ssh-rsa -o MACs=+hmac-sha1 -o ExitOnForwardFailure=yes -L 127.0.0.1:10023:192.168.1.10:10022 root@192.168.10.87
```

输入RTServer密码后窗口保持空白，不要关闭。

### 2. 新窗口检查隧道

```powershell
Test-NetConnection 127.0.0.1 -Port 10023
```

必须显示：

```text
TcpTestSucceeded : True
```

### 3. 登录板子

```bash
ssh -p 10023 -o KexAlgorithms=+diffie-hellman-group14-sha1 -o HostKeyAlgorithms=+ssh-rsa -o MACs=+hmac-sha1 root@127.0.0.1
```

输入板子密码。登录后执行：

```bash
hostname
uname -m
ip addr show eth1
```

确认：

```text
uname -m = aarch64
eth1 = 192.168.1.10
```

确认能正常登录后先执行：

```bash
exit
```

### 4. 上传两个文件

程序：

```bash
scp -O -P 10023 -o KexAlgorithms=+diffie-hellman-group14-sha1 -o HostKeyAlgorithms=+ssh-rsa -o MACs=+hmac-sha1 "C:\Users\linjj\Desktop\PVenergy\modbus_ceshichengxu\modbus_tcp_master_test(9)" root@127.0.0.1:/tmp/modbus_tcp_master_test_v32
```

配置：

```bash
scp -O -P 10023 -o KexAlgorithms=+diffie-hellman-group14-sha1 -o HostKeyAlgorithms=+ssh-rsa -o MACs=+hmac-sha1 "C:\Users\linjj\Desktop\PVenergy\modbus_ceshichengxu\modbus_tcp_master_test_config(5).json" root@127.0.0.1:/tmp/modbus_tcp_master_test_config_v32.json
```

RT-LAB继续保持Execute，暂时不要Reset。上传成功后再登录板子检查文件并启动程序。保持RT-LAB继续 Execute，隧道窗口不要关闭。接下来这样做：

### 5. 在RTServer确认1502仍监听

```bash

```

没有 ss：



该程序确实支持 `--config PATH` 参数。当前JSON配置为连接 192.168.1.100:1502，通信周期1秒，并且 `external_enable_request=false`。
