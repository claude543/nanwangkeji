# RT-LAB 在线调参能力与跨项目复用手册
## ——基于 K26_V5 / LOCAL15 / OP5700 实际验证结果

**版本：V1.0**  
**日期：2026-08-29**  
**平台基线：RT-LAB 2024.1.1.38 + MATLAB R2023b + OP5700**  
**用途：后续本项目或其它 RT-LAB 项目判断“某个量能否不 Build、直接在线修改”的统一方法。**

---

# 0. 核心结论

RT-LAB 能不能在线修改一个量，不能只看它是不是 Constant、Gain、Step。真正的判断标准是：

```text
Simulink / 代码生成把该量保留为 Tunable Parameter
+
当前 Build 的 Target 参数表实际暴露该参数
+
SetParametersByName() 写入成功
+
GetParametersByName() readback 一致
+
必要时 MAT / 在线动态信号证明 Target 真实采用
```

因此以后禁止凭经验直接说“这个块一定能在线调”。统一流程：

```text
GetParametersDescription()
↓
唯一发现
↓
GetParametersByName()
↓
SetParametersByName()
↓
立即readback
↓
MAT/动态信号闭环验证
```

# 1. 当前已经实际验证的在线能力

## 1.1 Execute 状态下 Host Python 在线改 Target 参数：PASS

链路：

```text
Windows Host Python
→ RtlabApi
→ SetParametersByName()
→ OP5700 Target
→ 参数运行时采用
→ MAT / 动态信号反映变化
```

代表性验证：

```text
CFG15_ISLAND_MASTER
1 → 2 → 1
```

后续又实际完成过：

```text
CFG_AA_tie_target_kW
-100 → 0 kW

SM_Master/Step Time
15 → 0 s

F4_SYNC_OFFSET_RAD
旧保存值 → -2*pi/3

F20_IOUT_RELEASE_TIME_S
9999 → READY时刻+10 ms

CFG_AA_v_nom_V
10000 → 20000 → 10000
```

因此“在线改参”这一层已经可以冻结为 PASS。

# 2. 按 RT-LAB 仿真时间自动改参：PASS

正式时间调度：

```python
RtlabApi.SetPauseTime(abs_time)
RtlabApi.Execute(1.0)
等待 MODEL_PAUSED
```

然后：

```text
读取 / 改参数
→ 设置下一个PauseTime
→ 再Execute
```

不用 `time.sleep()` 作为实验时间轴。

原因：

```text
time.sleep() = Windows墙钟
SetPauseTime() = RT-LAB Simulation Time
```

后者已经实际验证，适合可重复实时实验。

# 3. 模型侧 Tunability 基础设置

LOCAL15 Stage00 冻结：

```matlab
set_param(mdl,'DefaultParameterBehavior','Tunable');
set_param(mdl,'ParameterTunabilityLossMsg','error');
```

## 3.1 DefaultParameterBehavior=Tunable

目标：

```text
尽可能让运行时参数在代码生成后仍保留为可调对象
```

## 3.2 ParameterTunabilityLossMsg=error

如果：

```text
设计上希望在线调
但代码生成把它内联/优化掉
```

则 Build 直接报错，而不是悄悄失去可调性。

跨项目建议默认采用这一保护。

# 4. 当前 K26_V5 已经可在线设置的主要参数类型

## 4.1 Enable / Mode / Strategy Permission

例如：

```text

```

最适合做成在线可调，因为它们可以实现：

```text
一次Build
→ 多运行模式
→ 多工况自动实验
```

---

## 4.2 控制目标 / 阈值 / 参考值

例如：

```text
CFG_AA_tie_target_kW
CFG_AA_v_nom_V
CFG_AA_enable
CFG_AA_switch_enable
CFG_AA_blackstart_enable
AA15_COMM_OK
```

PB1 已经证明：

```text

```

不仅能写入，而且真实进入：

```text

→ effective dP
→ AGC
→ 六设备

```

## 4.3 诊断覆盖 / Scale / 已预置Breaker控制

当前：

```text
CFG_DIAG_AC_CONNECT_PV1/PV2/ESS2/EV1/EV2
CFG_DIAG_ISLAND_PQ_OVERRIDE_ENABLE
CFG_DIAG_P_SCALE_*
CFG_DIAG_Q_SCALE_*
```

注意：


不是“在线修改模型拓扑”。

```text

```

所以跨项目要区分：

```text
运行时控制已有执行器
≠
运行时 add_block / delete_line
```

# 5. 参数发现的正确方法

正式入口：

```python
params = RtlabApi.GetParametersDescription()
```

## 5.1 不写死 Parameter ID

Rebuild、增删模块后 ID 会变化。

禁止长期：

```python
SetParameters(((1124,5.0),))
```

正式使用：

```python
SetParametersByName(...)
```

---

## 5.2 必须唯一发现

当前成熟规则：

```text
0 hits
→ 当前Build没暴露

1 hit
→ 可继续

>1 hits
→ 有歧义，STOP
```

不要默认取第一个。

---

## 5.3 两种实用发现方法

### 叶块名 + 参数属性

例如：

```text
F20_IOUT_RELEASE_TIME_S / Value
```

### 精确 path suffix + parameter

例如：

```text
SM_Master/Step / Time
```

---

# 6. 读写必须闭环

读取：

```python
RtlabApi.GetParametersByName((path,))
```

修改：

```python
RtlabApi.SetParametersByName((path,), (value,))
```

修改后必须：

```text
立即readback
→ 与wanted比较
→ 不一致立即STOP
```

只有 GUI 显示变化不够。

---

# 7. System Control 与 Parameter Control

分别：

```text
OP_FB_SYSTEM
OP_FB_PARAMETER
```

成熟脚本：

```python
TakeFunctionControl(
    OP_FB_SYSTEM,0,OP_CTRL_PRIO_MACRO
)

TakeFunctionControl(
    OP_FB_PARAMETER,0,OP_CTRL_PRIO_MACRO
)
```

结束一定：

```python
ReleaseFunctionControl(...)
```

放入 `finally`。

这样可避免旧GUI/Console占用导致：

```text
Parameter Control already been given
```

# 10. 在线“手”和在线“眼睛”必须分开理解

在线手：

```text
SetParametersByName
```

在线眼睛：

```text
GetSignalsDescription
GetSignalsByName
```

PB2审计已经证明当前 Build：

```text
4867 dynamic signals
```

且 `GetSignalsByName()` 实际读取 PASS。

因此可实现：

```text
改目标
→ 实时读P/Q
→ 条件满足
→ 再执行下一动作
```

即外置条件状态机。

# 13. 日志完整性必须提前算

本项目真实踩坑：

```text
Ts=100 us
Decimation=100
Nb_Samples=1000
```

所以：

```text
0.01 s/recorded sample
完整1000点约10 s
```

V4在8 s Reset：

```text
Group26/28 MAT约1 KB
```

因此脚本设计必须区分：

```text
CONTROL DEADLINE
LOGGER MINIMUM END
```

---

# 14. 安全失败优先于补日志

如果：

```text
PCC仍CLOSED
PREPARE只是超时
```

可以安全继续到 logger end。

但如果：

```text
已经孤岛
频率/电压/电流越界
```

必须立即 Reset。

V6 在：

```text
f=46.868 Hz < 47 Hz
```

立即 fail-safe Reset，所以 Group26/28 只有1 KB是合理结果。

# 15. 历史诊断参数要分级

PB2 V1 曾把：

```text
F7_VFF_GAIN
```

当 hard-required。

当前 Build 不暴露它就STOP。

后来重新定义：

```text
hard required
optional build-frozen
```

F7/F11/F12这类历史诊断参数如果本轮不需要在线动作，可以缺失并记录；但真正参与本轮控制的 F3/F4/F8/F9/F10/F20 必须存在。

# 16. 跨项目决策树

用户问：

> “这个参数能不能在线改？”

按下面做：

```text
1. 当前模型是否已经Build？
   否 → 先设计Tunability

2. GetParametersDescription有没有？
   无 → 不能按当前Build在线改

3. 是否唯一？
   否 → 先消除歧义

4. SetParametersByName能否写？
   否 → STOP

5. readback一致？
   否 → STOP

6. 是否需要证明Plant采用？
   是 → 动态信号/MAT确认

7. 它改变的是“已有执行器命令”还是“模型结构”？
   已有命令 → 可继续
   结构 → 应Build
```

# 18. 快速判断表

| 需求 | 默认判断 |
|---|---|
| Constant Value | 高概率可在线，必须查Target |
| Enable/Mode | 最适合在线化 |
| P/Q/V/f目标 | 最适合在线化 |
| Step Time | 当前项目已验证 |
| Gain/Kp/Ki | 可能，必须确认未内联 |
| 已存在Breaker命令 | 可设计成在线 |
| 新增Breaker | 结构修改 |
| Mux输入数 | 结构修改 |
| MATLAB Function代码 | 结构修改 |
| SSN/Stubline/Solver | 结构修改 |
| OpComm宽度 | 结构修改 |
| 在线读P/Q/状态 | 当前项目已验证 |
| 改动态Signal本身 | 应通过参数/执行器，不直接写Signal |

# 20. 最终原则

> **RT-LAB在线调参的本质，不是“运行时随便改Simulink”，而是在Build前把未来需要变化的自由度设计成Tunable Parameter；Build后Python只改变这些预留自由度，并通过readback、动态Signal和MAT形成可审计的闭环证据。**
