# 1. 先建立总知识框架：为什么示波器不能直接“看到MATLAB变量”

## 1.1 示波器真正测的是什么

示波器本质上观察的是：

> **Voltage versus Time（电压随时间的变化）。**

它并不知道：

```text
PCC = -100 kW
ESS1_Pmeas = 35 kW
Strategy7 = RECOVERY
```

这些都是软件/算法内部的“数字语义”。

因此必须把数字变量转换为真实物理电压：

```text
模型中的数字量
↓
FPGA
↓
DAC
↓
真实模拟电压
↓
示波器
```

---

## 1.2 DAC是什么

`DAC = Digital-to-Analog Converter，数模转换器。`

作用：

```text
数字量
3.2
↓
DAC
↓
真实电压
3.2 V
```

本项目中：

```text
OP5330-3
```

就是承担这一角色的模拟输出子卡。

---

## 1.3 ADC是什么

`ADC = Analog-to-Digital Converter，模数转换器。`

方向与DAC相反：

```text
外部真实电压
↓
ADC
↓
数字量
↓
RT-LAB模型
```

当前：

```text
Slot 1B = OP5340
```

就是Analog Input（模拟输入）卡。

记住：

```text
AO / DAC：模型 → 物理世界
AI / ADC：物理世界 → 模型
```

---

# 2. 当前项目中三个经常混淆的“输出”必须分清

## 2.1 模型里的OpOutput

`OpOutput`不是模拟电压输出卡。

它是RT-LAB模型中的一个：

> **模型数据连接点 / 对外数据端点。**

当前项目已经大量使用OpInput/OpOutput，例如：

```text
模型PCC / PVmax / SOC
↓
OpOutput
↓
Configuration
↓
Modbus Holding Register
↓
Board FC03读取
```

因此：

```text
OpOutput
≠
Analog Output
```

---

## 2.2 Modbus输出

当前正式项目原有路径：

```text
模型
↓
OpOutput
↓
Configuration
↓
Modbus Slave
↓
Ethernet
↓
外部控制板
```

它传的是：

> **网络数据。**

不是物理电压。

---

## 2.3 Analog Output

以后新增的示波器路径：

```text
模型
↓
OpOutput
↓
Configuration
↓
OPAL-RT Board
↓
Analog Out
↓
DAC
↓
真实电压
```

它才是示波器真正能够观察的物理信号。

## 4.2 Configuration是什么

这是理解RT-LAB最关键的概念之一：

> **Configuration = 外部I/O接口与模型内部数据点之间的“接线表”。**

整体：

```text
Model
↓
OpInput / OpOutput

        ↕ Configuration

I/O Interfaces
↓
Modbus / OPAL-RT Board / CAN / ...
```

---

## 4.3 页面三个区域

### Models

显示当前模型可连接的数据点。

包括：

```text
Aliases
OpInputs & OpOutputs
SC_Console
SM_Master
SS_Slave
SS_Slave2
SS_Slave3
```

### I/O Interfaces

显示当前工程已经创建的外部接口。

早期只有：

```text
Modbus Slave
```

后面新增：

```text
OPAL-RT Board
```

### Connections

显示某一个I/O点最终连接到了哪个Model数据点。

---

## 4.4 为什么当前大量OpInput/OpOutput不等于已经有物理AO

因为现有OpInput/OpOutput大量服务于：

```text
Modbus寄存器
```

例如：

```text
401xx ← Model OpOutput
400xx → Model OpInput
```

因此看到很多OpOutput只能证明：

> 模型有很多软件数据出口。

不能证明：

> 已经有实体模拟电压输出。

# 5. 截图03：Modbus Slave Configuration

![截图03](images/03_Modbus_Slave_Configuration.png)

## 5.1 Associated subsystem

当前类似：

```text
K14.../SM_Master
```

意思是：

> 这套Modbus接口属于哪个实时计算Subsystem。

本项目最终通信核心位于SM_Master侧，因此这个关联是合理的。

---

## 5.2 Mode = TCP

表示：

```text
Modbus TCP
```

而不是：

```text
Modbus RTU / RS485
```

---

## 5.3 NIC name = eth1

`NIC = Network Interface Card，网络接口卡。`

OP5700当前两张关键网：

```text
eth0 / 管理网：
192.168.10.87

eth1 / 板端通信网：
192.168.1.100
```

因此Modbus必须绑定：

```text
eth1
```

---

## 5.4 IP address = 192.168.1.100

这是：

> OP5700作为Modbus Slave/Server向板端提供服务的地址。

不是Board IP。

当前：

```text
OP5700 = 192.168.1.100
Board  = 192.168.1.10
```

---

## 5.5 TCP port = 1502

本项目约定：

```text
192.168.1.100:1502
```

而不是标准502。

只要双方一致即可。

---

## 5.6 Cycle output rate = 2000 ms

它表示模型控制的数据多久刷新到Modbus输出数据区。

它不等于：

```text
Board程序主循环周期
```

也不等于：

```text
TCP每2秒才能回应一次
```

这是项目早期配置，后续100 ms BOARD15正式通信会另外统一周期。

---

## 5.7 Byte ordering = ABCD

用于多字节/多寄存器数据的字节顺序。

当前大量16位寄存器：

```text
INT16 / UINT16
```

一个值只占一个寄存器时影响较小。

若以后使用：

```text
FLOAT32 / INT32 / UINT32
```

则双方必须严格一致。

---

## 5.8 Permit read/write requests with address gaps

允许地址区间存在空洞。

本项目早期：

```text
40001...
40101...
```

中间留了大段地址空间，方便方向区分和扩展。

# 7. 为什么没有优先使用Legacy Common Analog Out

OPAL-RT还有传统工作流：

```text
Simulink
↓
OpCtrl
↓
Common Analog Out
↓
FPGA
↓
OP533X
```

这条路本身是合法的。

但当前项目更适合：

```text
I/O Interfaces
→ OPAL-RT Board
```

因为：

1. 当前工程已经大量使用`I/O Interfaces + Configuration + OpInput/OpOutput`；
2. 将硬件配置集中在Project层比塞入SM_Master更清晰；
3. BOARD15最终模型已经复杂，不希望再引入更多Legacy硬件控制块；
4. 本轮实测证明OPAL-RT Board能够正确解析当前VC707配置并暴露AO通道；
5. 因此没有必要优先退回Legacy方案。

Legacy方案保留为：

> 如果OPAL-RT Board在后续真实Load阶段遇到不可解决兼容问题时的备用路径。

# 9. General参数逐项解释

## 9.1 Chassis type

告诉驱动：

> 当前物理硬件属于哪个OPAL-RT机箱/FPGA家族。

错误选择会导致：

```text
FPGA驱动类型错误
配置文件不兼容
I/O资源解析错误
```

---

## 9.2 Chassis ID

不是随便编号。

它是实际板卡/机箱在驱动中的识别ID。

界面默认：

```text
0
```

后来通过硬件命令确认真实为：

```text
8
```

所以正式应使用：

```text
Chassis ID = 8
```

---

## 9.3 Use external synchronization source

是否从外部同步源获取实时同步。

当前只有单台OP5700，没有建立多机同步，因此：

```text
不勾选
```

---

## 9.4 Type of generated synchronization signal

例如：

```text
Optical
```

表示生成同步信号时采用的同步输出形式。

由于当前没有启用External synchronization，这个参数不是本轮示波器AO主问题。

保持当前默认即可，不需要为了AO主动修改。

---

## 9.5 Bitstream configuration location

决定：

> FPGA配置描述文件从哪里找。

两个选项：

```text
File system
Standard repositories
```

详见后文。

---

## 9.6 Bitstream configuration file

这里选择的是：

```text
.opal
或
.opbin
```

类配置。

它告诉驱动：

```text
有哪些DataIN/DataOUT
哪些Slot是什么I/O
每个I/O对应哪里
应该匹配哪个.bin FPGA固件
```

---

## 9.7 Show advanced configuration

开启高级配置参数。

本轮一般不需要。

高级选项通常用于：

```text
time-step factor
FPGA register logger
更底层调试
```

---

## 9.8 Automatic bitstream reprogramming

非常重要。

开启：

```text
Load模型
↓
驱动尝试重新program/reload FPGA bitstream
```

关闭：

```text
不自动重新编程FPGA
```

本轮调查和后续第一阶段测试首选：

```text
OFF
```

原因：

> 当前FPGA已经存在与55/44相匹配的固件，没有理由为了示波器调查重新刷FPGA。

---

## 9.9 Bitstream name

只读字段。

显示根据`.opal/.opbin`找到的真实：

```text
.bin
```

文件名。

后面我们看到：

```text
...IOConfig1-55-44.bin
```

与目标机真实Minor/Revision吻合。

---

## 9.10 Force

作用：

> 即使驱动认为当前Bitstream相同，也强制重新program。

当前：

```text
OFF
```

没有理由使用。

---

## 9.11 Disable strict hardware mismatch validation

关闭严格硬件不匹配检查。

正常项目：

```text
不要勾
```

因为我们反而希望RT-LAB发现：

```text
配置描述
≠
实际I/O硬件
```

时及时报错。

只有明确理解Polymorphism（兼容硬件映射）等高级场景后才考虑。

---

## 9.12 Enable FPGA scope

`FPGA Scope = FPGA内部高速信号采集工具。`

它可以在FPGA内部以高于CPU仿真步长的速度采集FPGA信号，再给ScopeView等工具看。

它不是：

```text
外部RIGOL示波器
```

本项目论文最终需要的是：

```text
Physical AO → RIGOL
```

所以当前不需要Enable FPGA Scope。

---

## 9.13 Enable virtual mode

虚拟模式。

可以让没有真实硬件时做部分配置/仿真初始化。

当前我们必须连接真实OP5700，因此：

```text
OFF
```



# 49. Monitoring面板其他区域分别是什么

## 49.1 SFP

`SFP = Small Form-factor Pluggable，小型可插拔光模块接口。`

主要用于高速FPGA/多系统数据链路。

不是本次示波器路径。

---

## 49.2 SYNCHRO

`Synchronization，同步。`

可以看到：

```text
Fiber TX / RX
LVDS RX / TX
M/S
```

用于多实时系统时间同步。

### TX / RX

```text
TX = Transmit，发送
RX = Receive，接收
```

### LVDS

`Low-Voltage Differential Signaling，低电压差分信号。`

高速、抗干扰数字通信。

### M/S

`Master / Slave，主/从同步。`

当前单台OP5700示波器取证无需操作。

---

# 65. 最容易混淆的10个概念

## 65.1 OpOutput ≠ Analog Output

OpOutput是模型连接点。

Analog Output是实体电压输出。

## 65.2 I/O Interfaces ≠ Configuration

I/O Interfaces：

```text
定义接口/硬件
```

Configuration：

```text
连接接口和模型数据
```

## 65.3 `.opal` ≠ `.bin`

`.opal`：

```text
硬件/Bitstream配置描述
```

`.bin`：

```text
真正FPGA可编程二进制Bitstream
```

## 65.4 eHS名字 ≠ 当前一定使用eHS

当前只是复用包含IOConfig的固件。

## 65.5 Enable Channel ≠ 已经输出电压

Enable只是：

```text
允许Configuration连接
```

真正电压要等：

```text
Model连接
Build
Load
Execute
```

## 65.6 Monitoring口空闲 ≠ AO逻辑通道没被用

Monitoring是监听旁路。

## 65.7 AO ±16 V ≠ 论文一定用±16 V

可以人为只用±5/±10 V。

## 65.8 Monitoring ×0.1 ≠ 探头10X

两层不同缩放。

## 65.9 FPGA Scope ≠ 外部示波器

FPGA Scope是内部数字采集。

RIGOL是实体仪器。

## 65.10 48路AO ≠ 48路都可以随便改

要避免影响其他正式I/O用途。

# 72. 官方资料核验依据

本轮关键结论交叉核验了OPAL-RT官方文档，主要包括：

1. **OP5700 Connecting Monitoring Devices**  
   - Monitoring RJ45 → Monitoring Panel → mini-BNC；
   - 4通道A/B/C/D；
   - Monitoring Board Gain = 0.1；
   - 只能按规定连接Monitoring RJ45。

2. **OP5700 I/O Configuration**  
   - 4组Group；
   - 每组A/B两块Mezzanine；
   - Analog/Digital I/O基本组织。

3. **OP5700 General Pin Assignments**  
   - DB37与Channel基本针脚关系；
   - Single-ended output负端接地等原则；
   - 具体设备最终以System Description为准。

4. **RT-LAB OPAL-RT Board / Analog Out**  
   - OP5330 Analog Output通过FPGA DataIN接收模型数据；
   - Channel按8路一组Enable；
   - Standard Analog Out与Advanced Analog Out区别；
   - Voltage Range支持配置；
   - Configuration负责Signal Source连接。

5. **Common Analog Out**  
   - Legacy Simulink硬件块方案；
   - 通过OpCtrl/FPGA DataIn驱动OP533X；
   - 本项目保留为备用而非首选。
