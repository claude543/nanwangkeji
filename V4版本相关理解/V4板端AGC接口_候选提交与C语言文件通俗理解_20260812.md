# V4板端AGC接口、状态提交与 `.h/.c` 文件理解

> 本文整理自两轮问答，面向非程序员。重点解释 V4 中 `UPDATED/HELD/ERROR`、`reset/init/step`、candidate/commit，以及 `.h`、`.c`、`main.c` 的关系。

---

# 问题1：`AGC_STEP_UPDATED / AGC_STEP_HELD / AGC_STEP_ERROR` 是怎么来的？原来的 AGC 代码什么时候有这三个输出？

## 回答

先说结论：

**这三个不是原 MATLAB AGC 原来就有的三个输出，而是把 MATLAB AGC 封装成 C 模块以后，为方便板端主程序管理算法状态而增加的“本次调用结果”。**

原来的 MATLAB `AGC_Controller(...)` 主要输出：

```text
PV1命令
PV2命令
ESS1命令
ESS2命令
EV1命令
EV2命令
AGC_STATUS
dP
remain
```

它主要回答的是：

> 当前六台设备分别应该给什么功率命令？

C 版除了要算这些值，还必须告诉主程序：

> 这次调用到底有没有真正推进 AGC 内部状态？

因此 `agc_controller_step()` 会额外返回一个结果：

```text
UPDATED = 这一次真的生成了一版新的AGC状态
HELD    = 这一次不需要更新，继续保持上一版
ERROR   = 这一次计算有问题，结果不能用
```

## 1.1 UPDATED

如果到了新的 AGC 更新周期，而且输入正常：

```text
当前PCC/PVmax/SOC
↓
重新计算dP
↓
更新PV/ESS/EV内部历史命令
↓
生成新六路输出
```

这时返回：

```c
AGC_STEP_UPDATED
```

但要注意：

```text
UPDATED ≠ 已经成功发给RT-LAB
```

它只说明算法算出了新的候选结果，后面还要经过编码、FC16发送和成功提交。

## 1.2 HELD

如果当前这一拍不应该推进 AGC 状态，例如还没到下一个更新时间，那么保持上一版结果：

```text
AGC历史状态不推进
六路命令保持上一版
CMD_SEQ不增加
```

这时返回：

```c
AGC_STEP_HELD
```

HELD 不是错误。

## 1.3 ERROR

如果出现非法输入、NaN/Inf、参数异常等情况，则返回：

```c
AGC_STEP_ERROR
```

此时：

```text
本次结果无效
不提交candidate
CMD_SEQ不增加
40010撤销
```

# 问题2：`agc_controller_reset()`、`agc_controller_init()`、`agc_controller_step()` 是三个函数吗？分别干什么？

## 回答

是，**它们是同一个 `agc_controller` C 模块里的三个函数接口，不是三套算法。**

可以理解成一个有记忆的机器，它内部保存：

```text
当前PV内部命令
当前ESS内部命令
当前EV内部命令
last_t
status
last_dP
remain
……
```

这个机器的生命周期是：

```text
reset
↓
init
↓
step
```

也就是：

```text
复位
↓
初始化
↓
正常运行一步
```

## 2.1 reset

```c
agc_controller_reset(&agc_state);
```

作用：

> 把 AGC 恢复成“尚未初始化”的状态。

通常在板端程序真正启动时执行。

普通 Modbus 断线重连不应该 reset，因为 V4 要求保留 AGC 历史状态。

## 2.2 init

程序启动后不立即 init，而是先等第一批 FC03 成功并且核心测量合法。

原因是初始化需要真实数据，例如 PV 初始命令还要受当前 PVmax 限制。

因此：

```text
板端启动
↓
reset()
↓
FC03读取RT-LAB
↓
第一批数据合法
↓
init()
```

`init()` 用第一批真实数据建立初始状态，例如：

```text
PV内部初值 = min(PV_init, 当前PVmax)
ESS内部初值 = 0
EV内部初值 = EV_init
AGC_STATUS = 0
dP = 0
remain = 0
```

## 2.3 step

后续正常运行时周期调用：

```c
agc_controller_step(...)
```

它表示：

> 根据这一周期当前输入，让 AGC 向前运行一次。

它会读取当前时间、Ptarget、PCC、PVmax、SOC、enable 等，决定是否更新，并输出六路命令、status、dP、remain，同时返回 UPDATED / HELD / ERROR。

完整关系：

```text
程序启动
↓
reset()
↓
第一批FC03合法
↓
init()
↓
后续每周期
↓
step()
↓
UPDATED / HELD / ERROR
```

# 问题3：为什么 MATLAB 版本没有 reset / init / step？

## 回答

因为 MATLAB Function 里很多状态管理被 `persistent` 和 `isempty(...)` 隐藏了。

例如：

```matlab
persistent Ppv Pess Pev last_t
if isempty(Ppv)
    ...
end
```

它实际已经在做：

```text
第一次调用
→ 自动初始化
```

C 版只是把 MATLAB 里原本隐式的生命周期管理显式拆成：

```text
reset
init
step
```

所以不是多了三套新算法，而是把状态管理写清楚了。

# 问题4：V4 里的 candidate state / commit 那一大串代码到底是什么意思？

## 回答

它只解决一个核心问题：

> **AGC 算出新命令以后，如果 FC16 发送失败，AGC 内部能不能假装这条命令已经成功发布？**

答案：不能。

假设正式状态当前认为：

```text
PV1 = 30 kW
```

这一轮 AGC 算出：

```text
PV1 = 40 kW
```

如果直接在正式 `agc_state` 上更新成 40，然后 FC16 失败，那么：

```text
板端内部认为：40 kW
RT-LAB最后实际收到：30 kW
```

控制器认知和现实就分叉了。

因此先复制：

```text
正式状态 = 30
candidate = 30
```

只在 candidate 上执行 AGC：

```text
candidate：30 → 40
正式状态仍然：30
```

然后 FC16 发送 40。

如果 FC16 成功：

```text
candidate → commit
正式状态：30 → 40
CMD_SEQ + 1
```

如果 FC16 失败：

```text
candidate丢弃
正式状态仍然 = 30
CMD_SEQ不变
```

这就是 candidate/commit 的核心。

你真正需要记住五条规则：

1. 不要直接先推进正式 `agc_state`，先复制 candidate。
2. UPDATED 只表示有新的候选结果，不等于已提交。
3. 只有“UPDATED + 输出合法 + 编码成功 + FC16成功”才 commit，才 CMD_SEQ+1。
4. HELD 不推进 AGC 状态，CMD_SEQ 不增加。
5. ERROR 或 FC16 失败都不 commit，CMD_SEQ 不增加。

# 问题5：那段很长的示意代码，我是不是不需要逐行看懂？

## 回答

对。

工程师需要：

```text
能实现
能调试
能改程序
```

你需要：

```text
知道为什么这样设计
知道正确运行结果应该是什么
知道日志出现什么现象说明实现错了
```

例如：

```text
AGC_RESULT = UPDATED
FC16 = FAIL
CMD_SEQ：20 → 21
```

这是错误，因为 FC16 失败不能 commit，也不能增加 CMD_SEQ。

再例如：

```text
AGC_RESULT = HELD
CMD_SEQ：31 → 32
```

也是错误，因为 HELD 没有产生新状态。

所以你的目标不是从零手写 C 程序，而是能判断工程语义是否正确。

# 问题6：`.h` 和 `.c` 文件有什么区别？

## 回答

最简单的理解：

```text
.h = 说明书 / 接口表
.c = 真正的内部实现
```

或者：

```text
.h 告诉别人：“我有什么、你怎么调用我”
.c 真正实现：“我内部到底怎么算”
```

## 6.1 `agc_controller.h`

通常定义：

```text
有哪些数据类型
有哪些输入
有哪些输出
有哪些内部状态
有哪些函数
函数怎么调用
可能返回哪些状态
```

例如：

```c
typedef enum {
    AGC_STEP_ERROR = -1,
    AGC_STEP_HELD = 0,
    AGC_STEP_UPDATED = 1
} AgcStepResult;
```

这只是告诉其他程序：

> AGC 模块可能返回这三种结果。

又例如：

```c
void agc_controller_reset(...);
bool agc_controller_init(...);
AgcStepResult agc_controller_step(...);
```

这些只是函数声明，告诉别人这些函数存在、怎么调用。

## 6.2 `agc_controller.c`

`.c` 文件里才真正写：

```c
agc_controller_reset(...)
{
    ...
}
```

```c
agc_controller_init(...)
{
    ...
}
```

```c
agc_controller_step(...)
{
    ...
}
```

也就是说：

```text
.h：有一个step函数，你这样调用
.c：step内部真正执行dP计算、PV/ESS/EV分配、状态更新
```

## 6.3 UPDATED / HELD / ERROR 在两类文件里的关系

```text
.h：
定义“有哪些可能”

.c：
决定“什么时候返回哪一种”
```

# 问题7：`.h` 里的结构体是什么？

## 回答

结构体可以理解成：

> **把一组相关数据装在一个盒子里。**

例如：

```text
AgcParams
├─ Ptarget
├─ Punit
├─ deadband
├─ SOC_min
└─ SOC_max
```

表示一组参数。

```text
AgcInputs
├─ PCC
├─ PV1max
├─ PV2max
├─ SOC1
└─ SOC2
```

表示当前一周期的输入。

```text
AgcOutputs
├─ 六路命令
├─ status
├─ dP
└─ remain
```

表示输出。

最重要的是：

```text
AgcState
```

它保存 AGC 的历史记忆，例如：

```text
上一轮PV内部命令
上一轮ESS内部命令
上一轮EV内部命令
last_t
last_dP
remain
……
```

因为 AGC 下一轮不是从零开始算，而是在上一轮状态基础上继续调节。

# 问题8：`main.c`、`agc_controller.h`、`agc_controller.c` 是什么关系？

## 回答

可以直接记这张图：

```text
main.c
整个板端程序的总指挥
        │
        │ 调用
        ▼
agc_controller.h
告诉main：
AGC有哪些接口
数据怎么传
有哪些返回状态
        │
        │ 对应真正实现
        ▼
agc_controller.c
真正执行：
dP计算
PV/ESS/EV分配
状态更新
UPDATED/HELD/ERROR判断
```

`main.c` 负责的是整个板端程序的大流程：

```text
连接RT-LAB
↓
FC03读40101～40116
↓
解码
↓
V3.2安全状态机
↓
准备AgcInputs
↓
调用agc_controller_step()
↓
得到AgcOutputs
↓
candidate/commit
↓
FC16写40001～40012
↓
CSV
↓
重连
```

而：

```c
#include "agc_controller.h"
```

表示 `main.c` 要使用 AGC 模块公开出来的接口。

# 问题9：为什么不全部写进一个 `.c`？

## 回答

小程序可以。

但项目变大以后，如果把：

```text
Modbus通信
安全状态机
AGC算法
CSV
重连
寄存器编码
candidate/commit
```

全部塞进一个 `main.c`，会很难维护。

拆分以后：

```text

agc_controller.h
负责公开接口和数据结构

agc_controller.c
负责AGC内部实现
```

职责就清楚很多。

# 你最终真正需要掌握的10句话

1. 原 MATLAB AGC 没有 `UPDATED/HELD/ERROR`，它们是 C 版工程封装增加的调用结果。
2. UPDATED 表示生成了新的候选 AGC 状态。
3. HELD 表示本周期不更新，保持上一版。
4. ERROR 表示本次结果不能使用。
5. `reset/init/step` 是同一个 AGC C 模块的三个生命周期函数。
6. reset 回到未初始化，init 用第一批真实数据建立初始状态，step 正常运行一步。
7. candidate state 是正式状态的草稿副本。
8. 只有 FC16 成功 candidate 才能 commit；失败不能假装命令已经发布。
9. `.h` 是接口说明和数据结构定义，`.c` 是真正实现算法的代码。
10. 你不需要逐行会写 C，但必须能根据日志判断 UPDATED/HELD/ERROR、FC16、commit、CMD_SEQ 的行为是否正确。
