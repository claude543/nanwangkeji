# 修改AGC更新周期后改善与问题

## 结论

把AGC周期从`0.1 s`改为`1.0 s`后，闭环性能明显改善：

* PCC能够围绕`−40 kW`目标运行；
* `remain`基本维持在0附近；
* `agc_status`不再长期停留在`−2`；
* ESS始终未参与；
* PV没有再升到接近`1 pu`；
* EV也没有再降到接近`−1 pu`；
* AGC原始命令与设备最终命令重合，通信链路正常。

因此可以确认：

> **0.1 s更新周期相对于约1 s的设备响应速度过快，是此前命令过度累积和资源大幅对冲的重要原因之一。**

但`1 s`并没有完全消除资源对冲，不能直接称为最优周期。

---

# 一、各波形说明了什么

## 1. PCC跟踪

PCC实际功率最终围绕：

```
−40 kW
```

波动，说明目标跟踪已经基本实现。

与`0.1 s`时长期停留在约`−20 kW`相比，本次明显更合理。

---

## 2. PV动作

两台PV命令大致由：

```
0.30 → 0.55 pu
```

每台增加约25 kW，两台合计约增加：

```
50 kW
```

PV实测能够跟随命令。

---

## 3. EV动作

两台EV命令大致由：

```
−0.60 → −0.75 pu
```

每台增加约15 kW充电，两台合计增加约：

```
30 kW
```

因此最终净功率变化大致为：

```
+50 − 30 = +20 kW
```

正好对应PCC目标从`−60 kW`调整到`−40 kW`所需要的20 kW。

---

## 4. ESS没有动作

ESS始终为0，说明在本次较慢的更新周期下，PV和EV已经能够完成调节，不再需要继续调用储能充电。

这比`0.1 s`工况中PV、EV、ESS同时大幅动作明显合理。

---

## 5. AGC状态仍在切换

`agc_status`在：

```text
+1、0、−1
```

之间变化。

这说明PCC瞬时功率仍频繁越过目标：

* PCC低于目标时，AGC增加微网出力；
* PCC高于目标时，AGC增加充电负荷；
* 偏差较小时进入0状态。

所以虽然PCC平均值接近目标，但原始功率纹波和较小死区仍使控制器来回动作。

---

## 6. `dP`与`remain`

`dP`围绕0上下变化，而`remain`基本为0。

这意味着：

* 当前每轮偏差基本都能被资源分配掉；
* 已经不存在资源能力不足；
* 问题由"无法完成调节"转变为"正负调节交替累积"。

---

# 二、与0.1 s工况的对比

| 现象       | `Ts_agc=0.1 s` | `Ts_agc=1.0 s` |
| -------- | -------------: | -------------: |
| PCC最终跟踪  |    能跟踪，但资源严重对冲 |            能跟踪 |
| PV最终命令   |       接近1.0 pu |       约0.55 pu |
| EV最终命令   |      接近−1.0 pu |      约−0.75 pu |
| ESS最终命令  |       约−0.2 pu |              0 |
| `remain` |        有明显异常阶段 |           基本为0 |
| 状态       |        频繁且动作剧烈 |      仍切换，但明显缓和 |
| 资源对冲     |            很严重 |      明显减轻，但仍存在 |

所以这次单变量对照有效证明：

> 将更新周期由0.1 s调整为1 s，显著减少了设备尚未响应完成时AGC再次累计分配的次数。

---

# 三、为什么仍然存在PV和EV对冲

当前PCC实测存在明显纹波，而AGC死区只有：

```
P_dead = 2 kW
```

PCC波动幅度远大于2 kW，所以即使平均功率已经接近目标，AGC每次采样仍可能看到：

```text
本轮dP>0 → 增加PV
下一轮dP<0 → 增加EV充电
```

现有算法又是基于上一轮命令继续增量调整，不会自动把已经累积的PV和EV命令恢复到最小对冲状态，因此逐渐形成：

```text
PV多发约50 kW
EV多充约30 kW
净结果增加20 kW
```

PCC目标实现了，但内部调节效率还不理想。

---

# 四、当前能够得出的正式结论

可以记录为：

> 在完整AGC代码和理想通信条件下，将AGC控制周期由0.1 s调整至1.0 s后，PCC能够稳定运行在−40 kW目标附近，PV、EV和ESS之间的功率对冲明显减少，ESS不再参与调节，证明0.1 s高频更新与约1 s设备响应过程不匹配是原基线命令累积的重要原因。但由于PCC功率纹波明显大于2 kW死区，AGC状态仍在正、负调节之间切换，PV和EV仍存在约30 kW的对冲功率，说明控制周期并非唯一因素。

---

# 五、下一步应该做什么

下一项建议保持：

```text
Ts_agc = 1.0 s
```

只把：

```text
P_dead_kW = 2
```

改为：

```text
P_dead_kW = 10
```

其他参数全部不动。

## 为什么做

用于验证当前剩余的PV—EV对冲是否主要由：

```text
PCC纹波远大于2 kW死区
```

造成。

## 要观察什么

若死区改为10 kW后：

* PCC仍能保持在目标允许范围内；
* `agc_status`切换次数明显减少；
* PV停止继续累积；
* EV不再不断增加充电；
* ESS仍保持0；

则说明小死区是资源对冲的另一个主要原因。

若改善不明显，则下一步不应继续扩大死区，而应考虑对PCC反馈进行低通滤波或滑动平均。
