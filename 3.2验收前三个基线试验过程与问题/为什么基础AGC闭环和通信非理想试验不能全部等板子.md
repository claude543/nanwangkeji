# 为什么基础AGC闭环和通信非理想试验不能全部等板子

## 结论

**基础AGC闭环试验应当在板子接入前先做；通信非理想造成的性能退化试验则分两级：模型内先做小规模筛查，最终结论必须等板子闭环后再做HIL验证。**

也就是说，不是"现在全部做完"或"全部等板子"二选一，而是：

```text
现在：确认RT-LAB模型基线是否成立、找出值得研究的问题
后续：用板子—RT-LAB真实闭环给出最终工程和论文证据
```

---

# 一、为什么基础AGC闭环不能全部等板子

板子闭环出现异常时，可能来自多个环节：

```text
基础AGC算法
RT-LAB电气模型
功率符号
标幺和缩放
板端C代码移植
Modbus通信
外部命令切换
设备动态响应
```

如果没有先证明：

> 同一个RT-LAB模型，在内部参考AGC控制下能够正常闭环，

那么板子接入后PCC无法跟踪时，就无法判断是板子的问题，还是模型内部基线本来就存在问题。

因此，板子接入前至少需要一组**理想条件下的参考结果**：

```text
内部Simulink AGC
→ 六台设备
→ PCC反馈
→ 目标跟踪结果
```

以后板端闭环结果才能与它比较。

V4本来就计划采用相同输入，比较Simulink参考AGC与板端C版AGC的六路命令、`status`、`dP`和`remain`；V5才让板端命令实际接管设备。

所以内部AGC不是最终产品，但它是板端算法的**参考标准和故障隔离基线**。

---

# 二、老师已经跑出波形，为什么还要测试

老师已有波形证明的是特定范围内的功能和逻辑，不等于我们当前工程链路已经全部验证。

## 1. 15项策略波形主要验证策略层

15项策略输出的是：

```text
status
alarm
metric
cmd
```

其中不少`cmd`属于建议控制量，尚未全部接管六台设备。当前文档也明确说明，形成闭环实控还需要增加策略仲裁和设备功率分配。 

例如一张策略7波形可以证明：

```text
PCC存在偏差时，策略能够计算出修正需求
```

但它不一定证明：

```text
修正需求经过资源分配
→ 六台逆变器执行
→ PCC最终稳定跟踪
```

我们现在测的是后面这条物理执行链。

## 2. 当前模型已经不是老师最初运行的原始模型

现在的V3.2模型加入了：

* RT-LAB模型分区；
* OpComm传输；
* 外部Modbus寄存器；
* MODEL_STATUS；
* 双向心跳；
* 外部命令有效性；
* 测量和故障注入；
* 固定步长实时编译。

V3.2本身明确暂不接入正式AGC，重点是通信状态、数据有效性和安全管理。

因此老师以前的离线或原模型波形，不能完全替代当前实时模型版本的核对。

## 3. Simulink能运行不等于RT-LAB实时执行完全相同

RT-LAB引入了：

* 固定步长限制；
* 任务采样率限制；
* 子系统分区；
* OpComm采集时序；
* 实时超限风险；
* 控制台与计算节点传输。

我们刚刚遇到的采样时间和跨速率数据完整性报错，就是典型例子。原Simulink模型能运行，不代表实时模型无需重新验证。

所以测试不是质疑老师模型，而是进行：

> **模型迁移、实时化和外部控制器接入前的工程确认。**

# 三、通信非理想试验要不要等板子

## 最终结论必须等板子

如果论文最后声称：

> 在真实控制器硬件在环条件下，改进算法能够减小延时、丢包或恢复冲击，

那么最终数据必须来自：

```text
板端算法
+
真实Modbus TCP
+
RT-LAB实时模型
```

只在Simulink内部增加Delay或随机丢包，不能替代最终HIL证据。

## 但现在可以做小规模模型内筛查

模型内通信非理想试验现在的作用不是作为最终论文结果，而是：

* 判断延时是否真的显著影响控制；
* 判断丢包是否值得作为论文重点；
* 判断数据冻结是否比随机丢包更严重；
* 选择后续板端HIL要重点测试的场景；
* 避免工程师和板子到位后才发现研究方向不成立。

准确定位是：

```text
模型内试验：问题筛选与算法开发
板端HIL试验：最终验证与论文证据
```

因此，现在不需要开展完整的延时、丢包率大规模扫描。等基础AGC和代表性设备特性确认后，做少量筛查即可；正式矩阵留到V5。

# 四、测试三类设备到底有没有必要

有必要，但不需要把六台设备全部逐台做完整研究。

我们真正需要覆盖的是三种不同对象：

```text
PV：单向发电资源
ESS：双向充放电资源
EV：可控负荷
```

## PV1试验已经回答了什么

PV1最终能够准确跟踪命令，但10%～90%上升时间约为0.964 s。

这不是证明`Ts_agc=0.1 s`错误，而是获得一个设备动态基线：

```text
命令立刻变化
实际功率约1 s完成主要响应
```

## ESS为什么还必须测

储能与PV不同：

* 正值放电；
* 负值充电；
* 存在SOC约束；
* 充电和放电动态可能不同；
* 是AGC调节中的核心双向资源。

需要确认：

```text
+0.3 pu是否确实放电
-0.3 pu是否确实充电
实测功率和SOC方向是否正确
响应是否比PV更快或更慢
```

这将决定40111、40112的符号、范围和后续算法含义。

## EV为什么还必须测

EV是负荷，当前命令采用负值：

```text
-0.6 pu表示充电
0表示停止充电
```

需要确认设备内部`Pmeas`是否同样采用负号。如果EV实际功率信号采用相反方向，板端读取后就必须转换。

这直接关系到40113、40114，以及AGC中"增加充电"和"减少充电"的动作方向。

## 同类第二台设备怎么处理

PV2、ESS2、EV2只需要做一致性核对：

* 同样的符号；
* 同样的额定比例；
* 接线没有错误。

不需要再次完整计算全部动态指标。

# 五、这些试验能怎样推进工程

## 已经实际推进的事项

### 1. 找到了PCC点表的符号风险

模型实际采用：

```text
正值：向外送电
负值：从外部购电
```

我们发给工程师的点表采用：

```text
正值：购电
负值：送电
```

因此40101正式接入真实信号前，必须做符号转换或重新统一点表。

这是直接影响V4和V5的工程问题。

### 2. 建立了六路命令、六路实测和PCC的统一观测通道

以后V4和V5可直接观察：

```text
板端命令
→ RT-LAB实际Pref
→ 设备Pmeas
→ PCC响应
```

这套观测通道本身就是调试基础设施。

### 3. 开始确定40109～40114的真实来源和定义

完成ESS、EV代表性测试后，可以冻结：

* 信号来源；
* 正负方向；
* pu到kW转换；
* 有效范围；
* 是否参与未来AGC计算。

这直接推动V4输入接口设计。

# 六、这些试验能怎样推进论文

当前还没有锁定论文，只是在建立"问题是否真实"的证据链。

论文不能只写：

> AGC周期0.1 s，而设备响应约1 s，所以提出新算法。

这个论证不充分，因为快速控制器更新并不一定有问题。

真正需要证明的是：

```text
设备响应和通信非理想
        ↓
导致现有AGC产生可量化性能问题
        ↓
改进方法能够减轻该问题
```

例如后续若发现：

```text
基线AGC在理想条件正常
加1 s数据陈旧后出现明显超调
使用实测/新鲜度权重后超调下降
```

这才构成一条完整论文逻辑。

设备试验只提供第一层依据：

```text
命令和实测在动态期间确实存在差异
```

它不能单独成为论文结论，但决定后续是否值得继续研究这个方向。

# 七、现阶段还要做什么，做到哪里停止

当前不需要无限做模型内部试验。

建议的最小集合是：

## 现在完成

1. PCC符号试验——已完成；
2. PV1动态试验——已完成；
3. ESS1放电和充电代表性试验；
4. EV1增加和减少充电代表性试验；
5. 一组理想条件下基础AGC闭环阶跃。

完成第5项后，回答：

* 当前AGC基线是否稳定；
* 0.1 s周期是否真的产生问题；
* 命令—实测差异是否影响闭环；
* 现有AGC是否可以作为论文基线。

## 暂时不做大规模试验

以下内容可以等板子和V5：

* 完整延时扫描；
* 多档丢包率；
* 断网恢复矩阵；
* 基线与改进算法全部对比；
* 最终论文HIL结果。

## 工程师程序到位后立即并行

先完成V3.2状态机、心跳、测量有效性和断线恢复联合验收。老师的要求也是先理解算法所需测量和命令，完成基本链路，再针对延时、丢包和通信问题做改进。

---

## 最准确的阶段定位

我们现在既不是在重新开发老师的模型，也不是已经开始做最终论文算法。

我们在做：

> **把老师提供的模型，从"已有功能仿真模型"转化为"能够被外部板安全接管、能够定位问题、能够开展论文对比的实时实验平台"。**

板端闭环是最终目标；当前基线试验是让最终闭环可以被正确接入、解释和比较，而不是替代板端闭环。
