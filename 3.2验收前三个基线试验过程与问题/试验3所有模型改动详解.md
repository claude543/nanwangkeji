# 试验3所有模型改动详解

## 结论

刚刚的所有修改，目的是把模型从"单台设备开环响应测试状态"恢复为：

> **基础AGC自动分配六台设备功率、设备实际执行、PCC重新反馈的完整内部闭环测试状态。**

这一步不修改AGC算法和参数，而是先观察老师原始基线在当前RT-LAB实时模型中的实际表现。后续板端AGC将以这组结果作为参考。

---

# 一、另存为独立的AGC闭环试验模型

我们将模型另存为类似：

```text
V3.2_AGC_Ideal_ClosedLoop.slx
```

目的有两个：

* 不影响正式V3.2通信验收模型；
* 不覆盖已经完成的PV、ESS、EV单设备试验模型。

前面的单设备模型是"人为Step直接控制设备"，当前模型则是"AGC自动控制设备"，两者用途不同，必须分别保存。

---

# 二、撤销单设备测试Step对设备的接管

前面测试PV1、ESS1和EV1时，曾把设备原来的AGC命令断开，改成：

```text
测试Step → 设备Pref
```

这样可以单独测量设备响应，但不属于正常AGC闭环。

现在恢复为：

```text
AGC计算命令
→ 模型内部通信链路
→ From_SIG_*_PREF_PU
→ 六台设备Pref
```

具体而言，六台设备都重新使用正常命令：

```text
PV1、ESS1、EV1
PV2、ESS2、EV2
```

所有测试Step均断开或停用。

### 为什么必须恢复

若仍有一台设备由测试Step控制，AGC即使计算出新命令，该设备也不会执行，PCC闭环结果就不再代表基础AGC性能。

恢复后的完整链路是：

```text
PCC偏差
→ AGC_Controller
→ 六路功率命令
→ 六台设备
→ 六路实际功率
→ PCC变化
→ 再反馈给AGC
```

---

# 三、重新启用基础AGC

将：

```matlab
CFG_AGC_enable = 1
```

前面单设备试验时设置为0，是为了避免AGC同时调节其他设备。

现在设为1后，`AGC_Controller`开始按设定周期运行：

```
dP = P_target - P_PCC
```

并根据偏差方向自动分配资源。

保留：

```matlab
CFG_Ts_agc = 0.1
CFG_P_dead_kW = 2
```

### 为什么暂时不修改0.1 s周期

当前试验的目的正是观察老师原有参数下的基线结果。

若先把周期改成1 s或其他值，即使结果正常，也无法知道：

* 原始0.1 s是否有问题；
* 改变周期后改善了什么；
* 板端应复刻原算法还是修改算法。

所以第一次必须保持原参数，先测事实，再决定是否调整。

---

# 四、固定初始设备工况

保留大致如下设置：

```matlab
CFG_AGC_PV_init_kW = 30
CFG_AGC_EV_init_kW = 60
CFG_SOC0_ess1 = 0.60
CFG_SOC0_ess2 = 0.60
```

对应初始状态约为：

```text
PV1、PV2：各发电30 kW
ESS1、ESS2：初始0 kW
EV1、EV2：各充电60 kW
```

前面已经实测，在这个条件下PCC大约为：

```text
−60 kW
```

### 为什么沿用这一工况

因为该工况已经经过实验一和实验二验证：

* 设备符号明确；
* 功率缩放正确；
* PCC初始值已知；
* PV还有较大的向上调节裕度；
* SOC处于安全中间区间。

这样闭环试验出现变化时，容易判断是AGC动作，而不是初始条件不确定。

# 五、固定光伏最大可用功率

继续设置：

```matlab
CFG_PV_time_s = [0 1 2 4 6 8]
CFG_PV_profile_pu = [1 1 1 1 1 1]
```

此时：

```text
PV1最大可用功率 = 100 kW
PV2最大可用功率 = 100 kW
```

而初始命令仅为每台30 kW，所以两台PV共有约140 kW上调能力。

### 为什么固定光伏曲线

原光伏曲线会随时间变化。如果PCC同时受：

* AGC目标阶跃；
* 光伏最大可用功率变化；

两种因素影响，就无法判断PCC变化到底是谁造成的。

固定为1 pu后，本次唯一主要扰动就是PCC目标变化。

# 六、关闭通信非理想因素

设置为：

```matlab
CFG_RS485_delay_s = 0
CFG_RS485_packet_loss_enable = 0
CFG_RS485_packet_loss_rate = 0
CFG_RS485_force_crc_error = 0
```

同时保留内部命令通信链路使能。

### 为什么不是完全绕过通信模块

我们仍希望保留模型原来的命令路径：

```text
AGC
→ 模型内部Modbus/RS485链路
→ 设备
```

但先把延时、丢包和错误全部关掉。

这样测试的是：

> 基础AGC和设备动态本身是否正常。

若理想条件下都不能稳定，就没有必要先研究通信问题；若理想条件正常，后面加入延时和丢包后出现退化，才能归因于通信非理想。

---

# 七、将固定PCC目标改为阶跃目标

原来：

```text
CFG_P_target_kW Constant
→ AGC的P_target输入
```

改成：

```text
Step_PCC_Target
→ AGC的P_target输入
```

Step设置为：

```text
初值：−60 kW
终值：−40 kW
阶跃时刻：3 s
```

### 为什么选择−60到−40 kW

模型实际PCC符号已经确认：

```text
正值：向外送电
负值：从外部购电
```

因此：

```text
−60 kW → −40 kW
```

表示要求微电网从外部少购电20 kW，也就是要求微电网自身增加约20 kW出力。

阶跃后初始偏差为：

```
dP = -40 - (-60) = +20 kW
```

按照基础AGC逻辑，`dP>0`时优先增加光伏，所以预期：

```text
两台PV命令增加
→ PV实际功率逐渐增加
→ PCC由−60 kW向−40 kW移动
```

### 为什么只选20 kW小阶跃

两台PV有充足裕度，20 kW理论上可以完全由PV承担，不需要调用ESS或EV。

这样首次闭环试验能够先单独验证：

* AGC方向是否正确；
* PV优先级是否正确；
* 是否存在重复分配；
* PCC是否能进入目标附近。

若一开始使用很大的目标阶跃，PV、ESS、EV可能全部动作，问题更难定位。

# 八、保留六路命令、六路实测和PCC观测

实验二中已经建立了13路观测通道：

```text
六路设备命令
+
六路设备Pmeas
+
PCC实际功率
```

这13路继续保留。

### 作用

它允许同时观察：

```text
AGC给每台设备下了什么命令
设备实际执行到什么程度
PCC最后怎样变化
```

例如，如果PCC超调，可以判断：

* AGC是否连续增加PV命令；
* PV实际功率是否尚未跟上；
* ESS或EV是否错误参与；
* 是命令问题还是设备执行过程问题。

---

# 九、将观测通道由13路扩展到21路

新增了：

```text
14：P_target
15：dP
16：remain
17：agc_status
18：SOC1
19：SOC2
20：PV1_P_MAX
21：PV2_P_MAX
```

### 为什么增加这些信号

仅观察设备命令和PCC，能看到系统"发生了什么"，但不能完全知道AGC"为什么这样动作"。

增加这些信号后可以解释内部决策。

## `P_target`

用来和PCC实际功率直接比较，判断跟踪效果。

## `dP`

显示AGC认为当前还差多少功率：

```
dP = P_target - P_PCC
```

可以观察偏差是否逐渐趋近0，还是反复改变符号。

## `remain`

表示本轮经过PV、ESS、EV分配后仍未分完的调节量。

本次资源充足，正常预期：

```text
remain = 0
```

若仍大于0，说明分配逻辑或能力计算存在问题。

## `agc_status`

用于判断AGC当前状态：

```text
0：死区或不动作
+1：增出力方向
−1：减出力方向
+2/−2：资源能力不足，仍有剩余量
```

## `SOC1、SOC2`

本次预期ESS不动作，SOC应基本不变。

若SOC变化明显，说明储能参与了调节或信号连接存在问题。

## `PV1_P_MAX、PV2_P_MAX`

用于确认PV最大能力始终为100 kW，避免把PV停止增加误判成AGC问题。

# 十、在sc_display中增加相应Scope

## PCC跟踪Scope

同时观察：

```text
P_target
P_PCC
```

作用是直接看：

* 目标何时阶跃；
* PCC何时开始响应；
* 是否到达目标；
* 是否存在超调、振荡和稳态误差。

## AGC误差Scope

观察：

```text
dP
remain
```

作用是区分：

* PCC还有实际跟踪偏差；
* AGC本轮是否已经把偏差全部分配出去。

需要注意：

```text
remain=0
```

只表示本轮命令已经分配完，不表示PCC实际已经到达目标。

## AGC状态显示

观察控制器是在：

```text
增出力、减出力、死区、能力不足
```

哪一种状态。

## SOC Scope

确认储能是否被调用以及SOC是否符合功率方向。

## PV最大出力Scope

确认光伏上限在测试期间没有变化。

# 十一、为什么这些修改对后续板端有用

这次虽然使用的是内部Simulink AGC，但建立的是板端闭环的参考标准。

后续V4中：

```text
同一组输入
→ Simulink AGC
→ 板端C版AGC
```

需要比较：

* 六路命令；
* `dP`；
* `remain`；
* `agc_status`。

这些信号现在都已经加入观测通道。

后续V5中板端命令真正接管设备后，还可以比较：

```text
板端命令
→ 设备Pmeas
→ PCC响应
```

所以这次扩展的21路观测接口并非只服务一次试验，而是为V4、V5和论文对比搭建统一观测平台。

---

# 十二、本次修改没有做什么

我们没有：

* 修改AGC算法代码；
* 修改资源优先级；
* 修改`alloc_up/alloc_down`；
* 修改AGC周期；
* 引入实测功率参与AGC；
* 修改通信点表；
* 接入外部板；
* 加入延时和丢包。

因此，这次结果代表的是：

> **当前老师原始基础AGC，在当前RT-LAB实时模型、理想内部通信和已知设备动态条件下的原始基线表现。**

这正是下一步判断是否需要改算法、改周期或转向通信问题的依据。
