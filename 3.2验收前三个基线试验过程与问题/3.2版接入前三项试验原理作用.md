# 3.2版接入前三项试验原理作用

## 两项试验阶段总结

### 总体结论

我们目前完成的不是"重新验证老师的模型能不能运行"，而是给当前RT-LAB版本建立了两项外部板接入前必须掌握的基线：

1. **模型中的功率方向到底怎样定义；**
2. **六类功率命令下发后，设备实际功率怎样响应。**

目前得到的核心结果是：

> 当前模型中PCC正值表示微电网向外送电，负值表示从外部购电；PV、ESS和EV的命令符号及缩放均能正确作用于设备，三类设备稳态均能基本准确跟踪命令，但命令到实际功率的主要动态响应时间均约为1 s。

这为后续40101、40109～40114正式接入、V4板端算法影子运行、V5板端闭环控制和论文方向筛选提供了基础，但尚未证明现有AGC存在闭环性能问题，也没有证明`Ts_agc=0.1 s`一定不合理。

---

# 一、试验一：PCC功率方向确认

## 1. 为什么要做

我们发给工程师的V3.1/V3.2通信点表中人为规定：

```text
PCC_P > 0：从大电网购电
PCC_P < 0：向大电网送电
```

但这个规定是我们制定的通信接口约定，不代表老师搭建的Simulink模型中PCC测量模块天然就是这个方向。

如果模型实际方向与点表相反，未来将实际PCC信号直接写入40101，板端就会把购电理解成送电，AGC、防逆流、联络线控制等动作都可能反向。

所以该试验要回答：

> 增加微电网内部发电后，模型实际PCC功率是增大还是减小？

---

## 2. 做了什么

为了只改变光伏功率，排除其他因素，我们在专门的试验副本中：

* 关闭了AGC动态调节；
* 关闭通信附加延时、丢包和CRC错误；
* 将光伏最大可用出力固定为1 pu；
* 保持ESS和EV工况不变；
* 分两次运行改变两台PV初始指令。

光伏曲线输入要求固定为`1×6`，因此使用：

```matlab
PV_time_s = [0 1 2 4 6 8]
PV_profile_pu = [1 1 1 1 1 1]
```

两组工况为：

| 工况 |   PV1 |   PV2 |  光伏总指令 |
| -- | ----: | ----: | -----: |
| A  | 30 kW | 30 kW |  60 kW |
| B  | 50 kW | 50 kW | 100 kW |

通过`sc_display/vload1`观察实际电气模型的PCC有功功率，而不是观察当时仍为测试常量的40101。

---

## 3. 试验结果

工况A：

```
P_A = -59.89 kW
```

工况B：

```
P_B = -20.08 kW
```

PCC变化量：

```
ΔP_PCC = -20.08 - (-59.89) = +39.81 kW
```

两台光伏总出力增加40 kW，PCC增加39.81 kW，误差只有约0.19 kW。

---

## 4. 得出的结论

当前Simulink模型实际采用：

```text
PCC_P > 0：微电网向外送电
PCC_P < 0：微电网从外部购电
```

这与我们发给工程师的点表"正购负送"相反。

因此，后续如果仍保留点表的"正购负送"约定，40101正式接入时应当采用：

```
P_PCC_40101 = -P_PCC_model
```

也就是：

```text
模型实际PCC功率
→ Gain = -1
→ 缩放和INT16编码
→ 40101
```

## 5. 试验一推动了什么

它直接推动的是工程接口，而不是论文创新：

* 关闭了PCC符号不确定问题；
* 证明40101不能未经处理直接接入模型原始信号；
* 为板端AGC、策略2/4/7/11和论文公式确定统一方向；
* 避免V5闭环时出现控制方向整体相反。

---

# 二、试验二：设备命令—实际功率响应试验

## 1. 为什么要做

现有`AGC_Controller`内部使用persistent变量保存上一周期的PV、ESS和EV命令，并用这些命令作为下一周期计算可调裕度时的设备状态，没有使用六台设备实际有功功率。

它隐含的假设是：

```
P_i_meas(k) ≈ P_i_cmd(k-1)
```

但板端闭环以后，命令从板子写入RT-LAB，再经过逆变器功率环、电流环、电气对象和测量滤波，实际功率不可能严格瞬间等于命令。

因此，试验二要回答：

* 命令符号是否正确；
* 标幺值与实际功率比例是否正确；
* 设备能否最终跟踪命令；
* 命令与实测在动态过程中相差多大；
* 三类资源的动态速度是否显著不同；
* 40109～40114应该接什么信号、用什么符号；
* 后续是否值得研究命令—实测融合或动态裕度。

---

# 三、为试验二对Simulink模型做了哪些修改

## 1. 建立独立测试模型

没有污染正式V3.2验收模型，而是为各项试验保存独立副本，例如：

```text
PV1响应试验模型
ESS1放电试验模型
ESS1充电试验模型
EV1减少充电试验模型
```

这样每个结果都可以复查，也避免不同工况的参数互相污染。

---

## 2. 关闭上层AGC和通信非理想因素

公共设置为：

```text
CFG_AGC_enable = 0
通信附加延时 = 0
丢包 = 0
CRC错误 = 0
```

原因是我们要先测设备本身的正常动态，不能同时让AGC调整其他设备，也不能把通信延时和设备本地响应混在一起。

---

## 3. 在被测设备Pref前加入Step测试命令

每次只测试一台设备。

例如PV1：

```text
Step：0.30 → 0.50 pu
→ PV1 Pref
```

ESS1放电：

```text
Step：0 → +0.30 pu
→ ESS1 Pref
```

ESS1充电：

```text
Step：0 → -0.30 pu
→ ESS1 Pref
```

EV1减少充电：

```text
Step：-0.60 → -0.30 pu
→ EV1 Pref
```

Step采样时间使用当前RT-LAB模型固定步长：

```text
0.0001 s
```

每个Step输出同时分支到观测向量，确保记录的是设备实际收到的命令，而不是上游AGC的某个中间值。

---

## 4. 建立13路统一观测通道

为了避免每测试一种设备就重新Build，我们利用原来已经验证可用的`vload1` OpComm通道，把它改成13维观测向量。

实际固定顺序为：

| 序号 | 信号       |
| -: | -------- |
|  1 | PV1命令    |
|  2 | PV1实际功率  |
|  3 | ESS1命令   |
|  4 | ESS1实际功率 |
|  5 | EV1命令    |
|  6 | EV1实际功率  |
|  7 | PV2命令    |
|  8 | PV2实际功率  |
|  9 | ESS2命令   |
| 10 | ESS2实际功率 |
| 11 | EV2命令    |
| 12 | EV2实际功率  |
| 13 | PCC实际功率  |

信号路径为：

```text
六路设备命令
+
六路设备Control.Pmeas
+
实际PCC有功功率
        ↓
13输入Mux
        ↓
原vload1 OpComm通道
        ↓
sc_display
        ↓
13输出Demux
        ↓
PV / ESS / EV / PCC Scope
```

之所以这样改，是为了在RT-LAB Execute期间同时观察：

```text
设备收到什么命令
→ 设备实际功率是多少
→ PCC发生什么变化
```

这套通道以后还可直接用于V4、V5调试。

---

## 5. 删除了观测Zero-Order Hold

最初曾加入1 ms的Zero-Order Hold以降低显示数据量，但它与OpComm的`0.0001 s`采样任务产生跨速率数据完整性错误。

因此最终采用：

```text
13路Mux
→ 直接进入原OpComm
```

显示数据量通过Scope自身的显示和记录设置处理，而不改变实时目标模型的任务采样率。

这避免了修改模型全局调度和多任务设置。

---

# 四、试验二各项结果

## 1. PV1发电增加

工况：

```
0.30 → 0.50 pu
```

动态指标：

| 指标          |       结果 |
| ----------- | -------: |
| 响应延迟        | 约0.076 s |
| 10%～90%上升时间 | 约0.964 s |
| 从命令到90%     | 约1.040 s |

8～10 s稳态统计：

| 指标    |        结果 |
| ----- | --------: |
| 命令均值  | 0.5000 pu |
| 实测均值  | 0.5000 pu |
| 实测中位数 | 0.5017 pu |
| 实测最大值 | 0.5529 pu |
| 实测最小值 | 0.4241 pu |

结论：

* 正值表示发电；
* 0.5 pu稳态平均约对应50 kW；
* 没有明显长期稳态误差；
* 从命令变化到主要响应完成约需1 s；
* 实测存在明显瞬时纹波；
* PCC增加约20 kW，物理链路正确。

---

## 2. ESS1放电

工况：

```
0 → +0.30 pu
```

动态指标：

| 指标        |       结果 |
| --------- | -------: |
| 响应延迟      | 约0.052 s |
| 10%～90%时间 | 约1.022 s |
| 从命令到90%   | 约1.074 s |

稳态统计：

| 指标    |         结果 |
| ----- | ---------: |
| 命令    | +0.3000 pu |
| 实测均值  | +0.3001 pu |
| 实测中位数 | +0.3007 pu |
| 最大值   | +0.3676 pu |
| 最小值   | +0.2118 pu |

PCC约增加30 kW。

结论：

* ESS正值确实表示放电；
* 最终稳态平均能够准确达到30 kW；
* 没有明显长期误差；
* 放电主要响应过程约1 s。

---

## 3. ESS1充电

工况：

```
0 → -0.30 pu
```

动态指标：

| 指标        |       结果 |
| --------- | -------: |
| 响应延迟      | 约0.072 s |
| 10%～90%时间 | 约1.031 s |
| 从命令到90%   | 约1.103 s |

8～10 s均值约为：

```
-0.3000 pu
```

PCC由约`-60 kW`下降至约`-90 kW`，变化约`-30 kW`。

结论：

* ESS负值确实表示充电；
* 实际功率能够准确跟踪`-30 kW`；
* 充电和放电动态基本对称；
* 当前没有证据需要为充、放电分别设计不同补偿。

---

## 4. EV1减少充电

工况：

```
-0.60 → -0.30 pu
```

动态指标：

| 指标        |       结果 |
| --------- | -------: |
| 响应延迟      | 约0.043 s |
| 10%～90%时间 | 约0.925 s |
| 从命令到90%   | 约0.968 s |

8～10 s实测均值：

```
-0.2975 pu
```

与`-0.3000 pu`命令相比，误差为：

```
0.0025 pu = 0.25 kW
```

约为0.83%。

PCC向正方向增加约30 kW。

结论：

* EV命令与实测均采用负值表示充电；
* 充电功率从60 kW降低到30 kW后，实际功率能够正确跟踪；
* 40113、40114使用该`Pmeas`时不需要额外反号；
* 主要响应过程同样约1 s；
* 由于EV始终位于同一负功率充电区间，现阶段没有必要再耗时Build验证反向阶跃。

---

# 五、三类资源的总体比较

| 资源工况    |    响应延迟 | 10%～90%时间 | 达到90%总时间 |
| ------- | ------: | --------: | -------: |
| PV1发电增加 | 0.076 s |   0.964 s |  1.040 s |
| ESS1放电  | 0.052 s |   1.022 s |  1.074 s |
| ESS1充电  | 0.072 s |   1.031 s |  1.103 s |
| EV1减少充电 | 0.043 s |   0.925 s |  0.968 s |

总体规律非常一致：

> PV、ESS和EV的响应延迟约为40～80 ms，10%～90%主要响应时间约为0.93～1.03 s，稳态均能够基本准确跟踪命令。

所以当前没有发现三类资源之间特别显著的动态速度差异，也没有发现长期执行偏差或严重限幅。

# 六、试验二最终验证了什么

## 1. 验证了命令、符号和缩放

可以确认：

```text
PV：正值发电
ESS：正值放电、负值充电
EV：负值充电
```

单台设备1 pu对应约100 kW，命令与实际`Pmeas`的标幺关系基本正确。

这为40109～40114正式接入提供了依据：

| 地址    | 建议实际信号     | 方向      |
| ----- | ---------- | ------- |
| 40109 | PV1 Pmeas  | 正值发电    |
| 40110 | PV2 Pmeas  | 正值发电    |
| 40111 | ESS1 Pmeas | 正放电、负充电 |
| 40112 | ESS2 Pmeas | 正放电、负充电 |
| 40113 | EV1 Pmeas  | 负值充电    |
| 40114 | EV2 Pmeas  | 负值充电    |

---

## 2. 验证了设备执行链路

已实际证明：

```text
Pref命令
→ 设备本地功率环
→ 电流环和电气对象
→ Control.Pmeas
→ PCC功率变化
```

这说明当前实时模型中的设备控制链是有效的，不只是策略层产生了一个`cmd`数字。

---

## 3. 验证了命令与实测的准确关系

正确结论不是：

> 命令和实测长期明显不一致。

而是：

> 稳态平均时命令与实测基本一致；在约1 s的动态过渡阶段，两者明显不相等。

当前AGC内部用上一轮命令表示设备状态，而不是实际Pmeas。

试验二证明了这个近似在动态阶段并不严格成立，但还没有证明它一定导致闭环超调或振荡。

---

## 4. 没有证明什么

目前不能据此直接声称：

* `Ts_agc=0.1 s`不合理；
* 现有AGC一定有问题；
* 必须使用命令—实测融合；
* 论文方向已经确定；
* 三类资源需要不同控制器。

这些都需要下一项"理想通信下基础AGC闭环试验"验证。

# 七、与老师已有15项策略波形的区别

老师已有波形主要验证：

```text
给定输入和阈值
→ 策略是否产生正确的status/alarm/metric/cmd
```

15项策略的多数输出目前仍属于建议控制量，并未全部直接接管设备；如需完整实控，还需要策略仲裁和功率分配。 

我们试验二验证的是：

```text
设备收到真实功率命令
→ 实际逆变器怎样执行
→ PCC怎样响应
```

两者并不重复。

老师的波形回答"策略是否算出建议"，我们的试验回答"建议变成设备命令后，物理系统实际怎样动作"。

# 八、当前成果对项目和论文的作用

## 对工程

已经完成：

* PCC实际方向确认；
* 六类测量点的符号和缩放确认；
* 六路命令、六路实测和PCC的统一观测通道；
* 设备正常动态响应基准；
* V4/V5后续调试的分层观察条件；
* 40101及40109～40114正式接入的技术依据。

## 对论文

已经建立第一层问题证据：

```text
命令与实测在动态阶段存在约1 s的过渡差异
```

但是否形成论文创新，取决于下一项试验能否证明：

```text
这种动态差异
→ 实际造成基础AGC闭环性能下降
```

如果闭环仍然表现良好，则不应强行把命令—实测融合设为核心创新，而应更多关注通信数据陈旧、断线恢复或其他策略场景。

如果闭环出现重复分配、明显超调或振荡，则动态裕度、命令—实测融合或AGC周期协调就具有明确研究依据。

---

## 当前阶段一句话总结

> 实验一确定了整个系统的功率方向；实验二确定了三类设备如何执行功率命令。两项工作已经把当前RT-LAB模型从"可以运行的功能模型"推进为"功率方向明确、设备动态已知、具备板端接入和算法对比条件的实时实验平台"。
