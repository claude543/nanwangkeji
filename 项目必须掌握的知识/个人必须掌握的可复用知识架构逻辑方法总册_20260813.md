## 必须真正理解的几个问题

### 为什么功率环输出电流参考？

因为P/Q最终由电压和电流决定。在同步dq坐标里，控制dq电流是改变有功/无功最直接的中间量。

### 为什么电流环输出电压命令？

因为滤波电感中的电流不能被“直接命令跳变”。控制器真正能改变的是变流器输出电压：

```text
变流器输出电压变化
↓
L1两端压差变化
↓
di/dt变化
↓
实际电流变化
```

### Current Regulator三个主要输入

```text
IdIq_refs
= 目标dq电流

IdIqs
= 实测dq电流

VdVqs
= 实测dq电压
```

其中：

```text
IdIq_refs - IdIqs
→ PI纠偏

VdVqs
→ 进入前馈
```

# 4. RT-LAB实时化、多任务分核、Stubline

这是本项目非常有长期价值的一块。

## 必须掌握

### Cores=4不等于四个独立实时任务

一个大SM即使设置多核，也不代表复杂开关网络自动拆成多个独立实时求解问题。

真正的多任务结构是：

```text
SM_Master
SS_Slave
SS_Slave2
SS_Slave3
```

### 为什么必须拆

```text
Ts = 100 μs
```

意味着每个实时任务都必须在100 μs内完成。

所以：

```text
离线Simulink可运行
≠
OP5700可以实时运行
```

### 真正的拆分包含四层

```text
任务拆分
+
电气网络拆分
+
变压器边界显式化
+
普通控制信号拆分
```

### Stubline

```text
PMIO + Differential Stubline
= 跨实时任务保持真实电气关系
```

每台设备：

```text
A_pos / A_neg
B_pos / B_neg
C_pos / C_neg
= 6个PMIO端点
= 3条差分Stubline
```

### Memory

正确理解：

```text
Memory
= 任务时序解耦
= 打断当前步直接依赖
```

不是人为通信延时。

# 7. V4 Candidate—Commit状态一致性

不要把它只看成工程师的C程序细节。

它是一种通用的：

> **“内部状态必须跟真正成功发生的外部事实一致”**

的软件设计方法。

## 必须掌握

```text
正式AgcState
↓ copy
candidate_state
↓
AGC试算
↓
检查输出
↓
encode
↓
FC16
↓
成功
↓
commit正式状态
```

如果FC16失败：

```text
candidate丢弃
正式AgcState不推进
CMD_SEQ不推进
```

### UPDATED / HELD / ERROR

```text
UPDATED
= 新候选状态产生

HELD
= 没有新状态，继续使用最近正式结果

ERROR
= 本周期不能提交
```

### retry

重试只能：

```text
重发同一个候选报文
```

不能：

```text
同一批旧测量再跑一次AGC
```

# 9. 设备正常动态：为什么Pref≠Pmeas不能立刻判异常

这是论文方向中非常重要的一层。

## 必须掌握

```text
Pref变化
↓
Power Loop
↓
Current Loop
↓
PWM
↓
Converter
↓
LC
↓
Transformer
↓
Pmeas
```

需要真实时间。

最新专门辨识结果应记住量级：

```text
PV / ESS / EV
90%主要响应
约0.9～1.5 s
```

而：

```text
AGC更新周期 = 1 s
```

所以：

> **下一轮AGC重新判断时，上一轮设备可能仍处于正常动态响应中。**

这解释了为什么不能简单：

```text

→ 设备故障
```

# 15. 论文写作本身怎么学

第一次写论文，不应先学英文句子。

正确顺序：

```text
研究问题
↓
已有方法
↓
研究缺口
↓
所提方法
↓
需要的证据
↓
实验结果
↓
最后写Introduction / Abstract / Title
```

论文写作Skill适合：

```text
蓝图阶段
→ 检查论文逻辑

算法冻结后
→ 检查问题—方法对应

实验完成后
→ 检查主张—证据

投稿前
→ 期刊适配、审稿检查
```

不适合替我们发明算法或虚构实验。

# 17. 最值得长期记住的20条原则

1. 复杂模型先看能量流、控制流、反馈流、通信流，再看模块。
2. Simulink能离线跑，不等于实时机能跑。
3. 多核不等于自动多任务。
4. 电气跨任务和数字跨任务是两件事。
5. Memory首先是时序解耦，不是通信延时。
6. 接口必须有完整点表：地址、类型、scale、单位、符号、方向、来源、使用者。
7. 网络连通不等于数据可信。
8. 数据可信不等于可以控制。
9. 真实控制系统应该慢投入、快退出。
10. 心跳看“是否变化”，不是看“是否非零”。
11. 算法算出命令，不等于命令已经发布。
12. 命令成功发布，不等于设备已经物理执行完成。
13. 控制器正式状态应与最后真正成功发生的现实保持一致。
14. 复杂项目一次只改变最少关键变量。
15. 成功基线必须冻结。
16. Build、Load、Execute、Realtime、Functional是不同层级PASS。
17. Scope/Display适合观察，不天然等于正式证据。
18. 论文问题必须来自真实系统、真实代码、真实数据。
19. 文献检索不是为了证明“没人做过”，而是确定已有边界和真实缺口。
20. 论文最终必须形成“问题 → 方法 → 证据 → 结论”闭环。
