# 暑期南网科技项目：电气解耦、任务分核与差分 Stubline 完整理解

> 日期：2026-08-14  
> 用途：作为本项目后续理解 RT-LAB / ARTEMiS 多任务分核、电气解耦位置选择、普通 Stubline 与差分 Stubline 区别的长期参考。  
> 说明：本文以本项目实际经历为主。若历史记录与后续模型本体、Build/Execute 结果冲突，以后续实体验证为准。

# 0. 一页先看懂

原六逆变器模型的问题不是“不能仿真”，而是六台开关级逆变器、六套控制器/PWM、公共10 kV电网、PCC/线路/测量和上层控制集中在一个实时任务中。

目标实时步长：

```text
Ts = 100 μs
```

原六逆变器单步计算约：

```text
970~981 μs
```

因此必须从：

```text
一个大实时任务
```

变成：

```text
SM_Master
+
SS_Slave
+
SS_Slave2
+
SS_Slave3
```

但电气网络不能像普通程序一样剪线，因为跨边界的不只是数值，而是电压约束、电流平衡、功率交换和动态状态。

最终成功方案：

```text
官方已验证 RT-LAB Transformer-Stubline 母版
+
一个三相变压器拆成3个单相变压器
+
每个低压绕组两个真实端点全部暴露
+
每相1条 “2 with differential inputs” 差分 Stubline
+
每台设备3条差分 Stubline
+
在SS侧重新组成原来的Delta
+
普通控制/测量数值通过OpComm传递
```

六台设备最终：

```text
6 × 3 = 18条差分 Stubline
```

形成当前：

```text
1SM + 3SS
100 μs
Overrun = 0
```

的实时基础。

# 1. 为什么“一个 SM 配 4 核”不等于真正分核

最早采用：

```text
SM_circuit内部：
SSN Interface
XHP
Cores = 4
```

后来严格对照：

```text
三逆变器 Cores=4 → 约700 μs/步
三逆变器 Cores=1 → 仍约700 μs/步
```

准确结论是：

> 4 核配置存在，但主要重计算没有得到有效并行，性能仍接近单任务串行。

SSN主要优化电气状态空间求解，并不会自动把整个SM里的PLL、功率环、电流环、PWM、测量和普通控制都拆成独立RT-LAB实时任务。

因此最终转向：

```text
一个SM + 多个SS
```

---

# 2. 为什么普通 OpComm 不能代替电气连接

普通信号：

```text
Pref
Qref
Fref
Vref
Droop_On
GridOn
Vabc/Iabc测量值
```

只是普通数值，可通过：

```text
Mux → Memory → Outport → OpComm → Demux
```

传输。

但A/B/C电气端口同时包含：

```text
节点电压关系
KCL电流平衡
支路动态状态
开关网络约束
```

把Vabc/Iabc数字送到另一个任务，只是“告诉对方测量值”，不会让真实电流和功率跨过去。

因此本项目始终有两套跨任务连接：

```text
电气能量：
PMIO + Stubline

控制/测量数值：
OpComm
```

---

# 3. 为什么理想电线不能直接跨两个并行任务

若SM和SS由理想导线连接，同一离散时刻 \(k\) 必须满足：

\[
V_{SM}(k)=V_{SS}(k)
\]

以及：

\[
I_{SM}(k)+I_{SS}(k)=0
\]

于是：

```text
SM第k拍需要SS第k拍结果
SS第k拍又需要SM第k拍结果
```

形成：

```text
SM(k) ←→ SS(k)
```

这就是同一步直接耦合。

所以真正的电气解耦，是在两侧之间建立具有状态/传播关系的边界，让本步计算不依赖另一侧本步尚未算出的结果。

---

# 4. Stubline 真正做什么

没有Stubline时：

```text
SM(k) ←→ SS(k)
```

有Stubline后可以理解为：

```text
上一拍已确定的边界状态
          ↓
    ┌─────┴─────┐
    ↓           ↓
  SM(k)       SS(k)
    ↓           ↓
 各自完成本拍计算
          ↓
更新下一拍边界状态
```

所以Stubline同时做两件事：

```text
1. 保持两边真实的电压、电流、功率交换
2. 打断同一步直接电气依赖
```

但Stubline不是透明理想电线，它有R、L以及与固定步长相关的等效特性，因此必须验证其引入后系统仍与原模型物理等效。

# 5. 本项目实际尝试过的主要路线

| 阶段 | 方法 | 结果 |
|---|---|---|
| 1 | 一个 SM 内 SSN + XHP + Cores=4 | 没获得有效任务级并行 |
| 2 | SM+SS + 普通三相 Stubline 直接替换短 RL 馈线 | 网络切开，但严重改变无功和电压 |
| 3 | Coupled Stubline + Compensation | 补偿计算奇异，停止 |
| 4 | 普通三相 Stubline + 迁移变压器漏阻抗 | 离线基本等效，但 RT-LAB Build 仍判 SM/SS 串行 |
| 5 | 官方母版 + 3个单相变压器 + 3条差分 Stubline/设备 | Build成功，最终扩展到六设备实时运行 |

# 6. 第一版普通三相 Stubline：网络切开了，但物理系统被改坏

最初直接使用原短馈线参数：

```text
R = 0.065 Ω
L ≈ 0.66845 mH
Ts = 100 μs
```

结构：

```text
PCC / SM
↓
普通三相Stubline
↓
SS / 设备
```

这版已经把原39开关的大电气网络切成多个较小网络，例如：

```text
9
12
6
6
6
```

所以普通三相Stubline并不是“完全不能解耦”。

问题在于电气等效。

当时每条Stubline对应约：

```text
C ≈ 14.96 μF
```

多条叠加后：

```text
拆分模型：
PCC无功 ≈ 2042.8 kvar
PCC电压 ≈ 10422.8 V

原模型：
PCC无功 ≈ 0 kvar
PCC电压 ≈ 10021.7 V
```

即多出约：

```text
2.04 Mvar
```

容性无功，PCC电压抬高约4%。

因此第一版失败的准确结论是：

```text
计算网络切开：成功
物理等效：失败
```

# 7. Coupled Stubline + Compensation 为什么停止

发现额外无功来自Stubline等效电容后，尝试：

```text
Coupled Stubline
+
Compensation Block
```

但原始线路只有R、L，没有真实线路C。

当真实电容矩阵设为0时，补偿计算出现：

```text
NaN / Inf
补偿电感约9.75 H
```

发生奇异。

核心经验：

> 不能为了让某种补偿模型可用而人为编造原系统不存在的参数。

之后将原本真实存在的变压器漏阻抗迁移给Stubline。

当时换算约：

```text
R ≈ 1.363636 Ω
L ≈ 0.086812 H
```

Stubline等效电容从约：

```text
14.96 μF
```

降到约：

```text
0.1152 μF
```

单独改EV2后，PCC无功由约：

```text
2042.8 kvar
```

降到：

```text
1503.2 kvar
```

下降约：

```text
539.6 kvar
```

而EV2有功基本不变。

随后建立：

```text

```

```text

+
```

> 普通三相Stubline不是物理上不可用。

# 11. “差分”到底是什么意思

这里的差分：

```text
不是时间差分
不是 x(k)-x(k-1)
不是微分
```

而是两个电气端子之间的差。

一个单相绕组有两个端点：

```text
+
-
```

其绕组电压为：

\[
v_{diff}=v_{+}-v_{-}
\]

因此：

```text
2 with differential inputs
```

表达的是：

```text
两个电气端子
+
以两端之间的差分电压作为物理关系
```

特别适合浮置的两端绕组。

# 12. 为什么 Delta 低压绕组特别适合差分边界

本项目变压器：

```text
10 kV Yg
/
480 V Delta
```

Delta低压侧没有天然中性点。

三个单相绕组：

```text
A+ A-
B+ B-
C+ C-
```

Delta通过首尾连接形成：

```text
A+ 与 C- 连接
A- 与 B+ 连接
B- 与 C+ 连接
```

因此每个绕组本来就是一个浮置的“两端器件”。

自然的跨任务方式：

```text
A+ ─┐
    ├→ A相差分Stubline
A- ─┘

B+ ─┐
    ├→ B相差分Stubline
B- ─┘

C+ ─┐
    ├→ C相差分Stubline
C- ─┘
```

到SS后重新获得：

```text
A+ A-
B+ B-
C+ C-
```

再恢复Delta。

所以一台设备：

```text
3相 × 每相2端 = 6个PMIO端口
3相 × 每相1条差分Stubline = 3条Stubline
```

六台设备：

```text
36个SM侧PMIO端口
18条差分Stubline
```

# 13. 为什么要把一个三相变压器拆成三个单相变压器

完整三相变压器把三相绕组、Y/Delta内部连接和漏阻抗封装在内部，外部通常只能看到：

```text
A B C
a b c
```

但差分Stubline需要每相绕组的两个真实端点：

```text
A+ A-
B+ B-
C+ C-
```

因此必须把：

```text
一个三相变压器
```

展开为：

```text
3个单相变压器
```

获得每相的：

```text
2+
2-
```

两个独立端点。

目的不是“单相模型更准确”，而是：

> 把原本封装在三相变压器内部的真实绕组端子暴露出来，建立适合差分Stubline的任务边界。

# 16. 最终一拍内差分 Stubline 怎么工作

假设当前是第 \(k\) 个100 μs步。

SM中：

```text
10 kV电网
PCC
馈线
prim
变压器高压侧
单相变压器
```

SS中：

```text
Delta
LC
Two-Level Converter
Control System
PWM
```

差分Stubline位于中间。

双方利用上一拍已确定的边界/内部状态，各自独立完成本拍：

```text
CPU1：SM_Master(k)
CPU2：SS_EV(k)
CPU3：SS_ESS(k)
CPU4：SS_PV(k)
```

本拍结束后更新下一拍边界状态和内部状态。

这就是最终可以并行推进的核心。

# 17. PMIO、Stubline、OpComm、Memory分别做什么

## PMIO

```text
把SM/SS内部物理电气端点暴露到顶层
```

不是解耦算法本体。

## Stubline

```text
真实电气网络跨任务
+
形成状态/传播边界
+
切断同一步直接电气依赖
```

## OpComm

```text
跨实时任务传普通数值
```

例如：

```text
Vabc/Iabc读数
Pref
Qref
Fref
Vref
GridOn
```

不承载真实电气功率网络。

## Memory / Unit Delay

```text
普通数值信号的时序解耦
```

不能替代Stubline做电气网络解耦。

# 19. 哪些位置通常值得优先检查

## 19.1 真实输电线/电缆

本身有：

```text
传播特性
R/L/C
```

可能适合DPL或其他线路解耦模型，不需要一定找变压器。

## 19.2 变压器附近

经常是好的候选，因为有：

```text
漏电感
漏电阻
不同电压等级
明确设备/电网边界
```

但仍需判断：

```text
Y / Yg / Delta
切高压侧还是低压侧
漏阻抗怎么迁移
是否需要差分表示
```

有变压器不等于一定拆单相并切低压侧。

## 19.3 串联电抗器/滤波电感

也可能提供天然状态边界，但如果位于PWM、电流内环、LC/LCL高速闭环内部，随便切开可能影响控制稳定性。

本项目因此尽量把：

```text
Converter + LC + Control System + PWM
```

完整留在同一个SS中。

# 20. 哪些位置通常不是第一选择

最典型：

```text
理想公共母线 / PCC
```

因为它要求：

\[
V_1=V_2=\cdots=V_{PCC}
\]

以及：

\[
\sum I_i=0
\]

是强耦合节点。

若附近没有真实线路、电抗器、漏感或传播特性，直接在那里插入解耦元件很容易改变原系统。

所以通常沿设备支路继续寻找：

```text
PCC
↓
馈线 / 变压器 / 电抗器
↓
候选解耦边界
↓
设备
```

# 21. 以后找分核位置的正式步骤

## 第一步：找实时瓶颈

看：

```text
开关网络大小
各任务Max execution time
PLL/PWM/控制器集中情况
```

## 第二步：先规划任务

例如：

```text
SM：公共电网/PCC
SS1：设备组A
SS2：设备组B
SS3：设备组C
```

目标是负载尽量均衡。

## 第三步：找真正必须跨越的电气边界

检查：

```text
真实线路
变压器
电抗器
滤波电感
其他储能元件
```

## 第四步：检查拓扑

明确：

```text
三相三线/四线
Y/Yg/Delta
是否浮置
是否有中性点
```

## 第五步：选择解耦方式

可能是：

```text
DPL
普通Stubline
Differential Stubline
SSN相关方法
其他ARTEMiS结构
```

不能先假定一定用差分Stubline。

## 第六步：重新核算参数

问：

```text
Stubline的R/L代表什么真实元件？
原模型同一R/L是否还保留？
是否重复？
是否凭空增加原系统不存在的C？
```

## 第七步：只做一个支路原型

本项目最后成功就是从单EV2逐层Build。

## 第八步：离线等效验证

至少比较：

```text
PCC P/Q
PCC V/f
设备Pmeas
三相电流
PLL
稳态误差
暂态响应
```

## 第九步：RT-LAB Build

这是独立的一关。

本项目已经证明：

```text
Ctrl+D成功
+
离线基本等效
≠
RT-LAB一定允许并行
```

## 第十步：Load / Execute / Monitoring

最终确认：

```text
每个任务 Max execution time < deadline
Overrun = 0
模型时间与现实时间1:1
```

# 22. 判断候选分核位置，只问三个问题

### 1. 计算真的分开了吗？

```text
切这里后，重网络是否变成多个合理子网络？
```

### 2. 物理系统还是原系统吗？

```text
解耦元件到底代表什么真实东西？
```

# 26. 一句话真正掌握“解耦与分核”

> 分核不是把模型框拆开，而是先把计算任务分开，再在真实电气网络中找到合适的物理—数值边界，用具有状态或传播关系的电气解耦元件打断同一步直接依赖，同时保持原系统物理等效，最后还必须经过 RT-LAB 的 Build、实时调度和执行时间验证。

本项目最终选中：

```text
变压器低压侧浮置绕组
+
Differential Stubline
```

是因为这里同时满足：

```text
有真实漏阻抗可以表示
+
Delta绕组天然是两端差分结构
+
可以把快开关逆变器完整迁入SS
+
官方RT-LAB母版已经验证
+
最终能够真正并行Build
```

而不是因为所有模型都应该在变压器低压侧切。
