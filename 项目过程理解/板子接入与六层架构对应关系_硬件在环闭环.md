# 板子接入后与文档六层架构的对应关系

**结论：板子接入后的本质，是把文档"层4协调控制层"中的 `AGC_Controller` 从 Simulink 内部搬到真实控制器板子上，同时用真实的 Modbus TCP 双向通信替代文档"层5通信层"的内部通信仿真。层1电气主回路、层2测量层、层3全局电压/频率控制和层6逆变器本地控制仍留在 RT-LAB 中。**

原文档的六层结构是：电气主回路、测量层、全局控制层、协调控制层、通信层和本地控制层。

---

## 一、文档原来的 Simulink 闭环

文档中的原始闭环全部在 Simulink 内部完成：

```text
RT-LAB 电气主回路运行
        ↓
PCC 和设备测量
        ↓
Simulink 内部 AGC_Controller
        ↓
计算六路 Pref、agc_status、dP、remain
        ↓
模型内部 Modbus/RS485 通信仿真
        ↓
六台设备本地 Control System
        ↓
PWM、IGBT、滤波、变压器
        ↓
微电网功率发生变化
        ↓
再次测量
```

文档完整闭环中也明确写了：

```text
PCC Measurements 测量
→ AGC_Controller 按优先级分配设备 Pref
→ Modbus 组帧和设备解码
→ 本地控制环
→ PWM
→ 下一轮闭环
```

并且把 AGC 定义为秒级外层闭环，把功率环和电流环分别定义为毫秒级、微秒级内层闭环。

---

## 二、板子接入后，闭环发生了什么变化

板子接入后，不再由 Simulink 内部的 `AGC_Controller` 直接计算和输出命令。

新的闭环变成：

```text
RT-LAB 仿真微电网
        ↓
RT-LAB 采集真实仿真测量量
        ↓
测量量编码到 40101~40116
        ↓
板子通过 FC03 主动读取
        ↓
板子内部运行 C 版 AGC_Controller
        ↓
板子生成九路 AGC 输出
        ↓
板子通过 FC16 写 40001~40009
        ↓
RT-LAB 解码、判断有效性
        ↓
前六路命令接入六台设备 Pref
        ↓
设备本地 Control System 执行
        ↓
PWM、IGBT、电气主回路响应
        ↓
产生新的 PCC 功率和设备状态
        ↓
板子下一周期再次读取
```

因此，板子不是额外增加在原闭环外面，而是**替换了原闭环中负责微网级有功调度的 AGC 计算部分**。

---

## 三、板子和文档六层架构的对应关系

| 文档层级 | 原模型内容 | 板子接入后的安排 |
|---------|-----------|----------------|
| 层1 电气主回路 | 10 kV 母线、PV、ESS、EV、负荷、电网 | 完全留在 RT-LAB |
| 层2 测量层 | PCC P/Q/V/f、设备测量 | 留在 RT-LAB，并通过 40101~40116 发布给板子 |
| 层3 全局控制层 | Fref、Vref、PI 电压频率控制 | 继续留在 RT-LAB |
| 层4 协调控制层 | AGC_Controller、15项高级策略 | 基础有功 AGC 移到板子；15项策略暂时留在 RT-LAB |
| 层5 通信层 | 模型内部 Modbus RTU/RS485 仿真 | 由真实板子—OP5700 Modbus TCP 通信替代 |
| 层6 本地控制层 | 功率环、电流环、Droop、PWM | 完全留在 RT-LAB |

这意味着：

```text
板子负责"六台设备应该各出多少有功功率"
RT-LAB 负责"设备如何把功率指令变成电流、PWM 和实际电能"
```

---

## 四、层1：RT-LAB 继续充当真实微电网对象

文档中的层1包含：

* PV1、PV2；
* ESS1、ESS2；
* EV1、EV2；
* 10 kV PCC 母线；
* 负荷；
* 大电网；
* 线路和断路器。

板子不会直接计算 IGBT、线路、电流或电压。

板子只给出上层有功命令，例如：

```text
PV1 = 0.50 pu
ESS1 = -0.30 pu
EV1 = -0.60 pu
```

真正的电气响应由 RT-LAB 实时计算：

```text
Pref
→ 功率外环
→ 电流参考
→ 电流内环
→ PWM
→ IGBT
→ 实际功率
```

---

## 五、层2：测量层对应 40101~40116

文档中 PCC Measurements 是整个控制闭环的反馈源，提供：

```text
PCC 有功
PCC 无功
PCC 电压
PCC 频率
```

这些信号通过 Goto 广播给原模型中的 AGC 和高级策略。

板子接入以后，这些信号不仅在 Simulink 内部使用，还要经过：

```text
真实测量量
→ 缩放
→ 整数编码
→ OpOutput
→ Configuration
→ Holding Registers
→ 板子 FC03 读取
```

当前的 `201~216` 只是为了验证这条通道。

以后应逐步替换为：

| 寄存器 | 对应文档中的信号 |
|-------|---------------|
| 40101 | PCC 有功 `P_pcc_kW` |
| 40102 | PCC 无功 |
| 40103 | PCC 电压 |
| 40104 | PCC 频率 |
| 40105 | PV1 最大可用功率 |
| 40106 | PV2 最大可用功率 |
| 40107 | ESS1 SOC |
| 40108 | ESS2 SOC |
| 40109~40114 | 六台设备实际有功 |
| 40115~40116 | 状态或通信辅助量，最终另行冻结 |

其中对当前有功 AGC 真正必需的动态输入至少是：

```text
P_pcc_kW
Ppvmax1_kW
Ppvmax2_kW
SOC1
SOC2
```

这些量原本就在文档的协调控制层中生成或使用：PV 出力曲线提供光伏最大可用功率，SOC 模块提供储能状态，AGC 使用它们完成资源约束下的功率分配。

---

## 六、层3：Microgrid Supervisory Control 不移到板子

文档中的 `Microgrid Supervisory Control` 负责：

```text
PCC 电压、频率反馈
→ PI 调节
→ Fref、Vref
→ 六台逆变器本地控制
```

它不负责六台设备之间的有功功率分配，而是负责全网频率和电压基准。

因此当前阶段：

```text
板子负责有功 AGC
RT-LAB 继续负责 Fref/Vref
```

二者不是重复关系。

可以理解为：

```text
板子：决定每台设备发多少有功
Supervisory Control：决定全网电压和频率维持在什么水平
```

当前只做有功 AGC，所以板子不接管：

* 电压 PI；
* 频率 PI；
* Droop；
* PLL；
* 无功控制；
* PWM。

---

## 七、层4：AGC_Controller 从 Simulink 搬到板子

这是整个项目最核心的变化。

### 原模型

原来是：

```text
P_target
P_pcc
PV 最大功率
SOC
静态参数
        ↓
Simulink AGC_Controller
        ↓
九路输出
```

AGC 的任务是让 PCC 有功跟踪目标，并按以下顺序调节资源：

```text
dP > 0：
增加 PV
→ ESS 放电
→ 降低 EV 充电功率

dP < 0：
增加 EV 充电
→ ESS 充电
→ 限制 PV
```

文档对这套优先级和约束有明确说明。

### 板子接入后

变成：

```text
401xx 测量寄存器
+ JSON 静态参数
        ↓
板子 C 版 AGC_Controller
        ↓
40001~40009
```

JSON 暂时提供：

```text
P_target
enable
P_unit
P_dead
SOC_min
SOC_max
Ts_agc
PV_init
EV_init
```

RT-LAB 提供动态量：

```text
P_pcc
Ppvmax1
Ppvmax2
SOC1
SOC2
```

## 八、40001~40009 如何对应 AGC_Controller 输出

已经确认九路对应：

| 寄存器 | AGC 输出 | 后续作用 |
|------:|---------|---------|
| 40001 | `Ppv1_pu` | 接 PV1 Pref |
| 40002 | `Ppv2_pu` | 接 PV2 Pref |
| 40003 | `Pess1_pu` | 接 ESS1 Pref |
| 40004 | `Pess2_pu` | 接 ESS2 Pref |
| 40005 | `Pev1_pu` | 接 EV1 Pref |
| 40006 | `Pev2_pu` | 接 EV2 Pref |
| 40007 | `agc_status` | 只用于状态显示和检查 |
| 40008 | `dP` | 只用于显示、记录和对比 |
| 40009 | `remain` | 只用于显示、记录和能力不足判断 |

这里必须区分：

```text
40001~40006 = 真正设备命令
40007~40009 = AGC 运行结果和诊断量
```

最终只有前六路进入设备 Pref。

后三路不能接到设备控制口。

---

## 九、层5：真实 Modbus TCP 替代文档中的通信仿真

文档中原来的层5：

```text
AGC 输出
→ Modbus RTU 编码
→ RS485 延时/丢包
→ 设备解码
```

其目的本来就是模拟真实控制器和设备之间的通信非理想特性，包括延时、丢包和通信异常。

现在板子接入后，真实过程变成：

```text
RT-LAB Holding Registers
↔ Ethernet
↔ 板子 Modbus TCP 程序
```

板子作为 Master，主动发起：

```text
FC03：读取测量量
FC16：写入 AGC 输出
```

OP5700 作为 Slave，只负责响应。

因此从功能位置上看：

```text
文档的层5通信仿真
≈ 当前板子和 OP5700 之间的真实 Modbus TCP 通信
```

### 最终建议

外部板子模式下，不建议再把板子命令串行通过一次原模型内部的 RTU/RS485 仿真链路，否则会形成：

```text
真实 Modbus TCP
→ 又一层虚拟 Modbus RTU/RS485
→ 设备
```

这会叠加两套地址、缩放、延时和故障逻辑。

更清晰的方案是：

```text
外部模式：
板子 Modbus TCP 命令
→ 解码
→ 有效性检查
→ 直接进入六台设备 Pref 切换入口

内部模式：
原 Simulink AGC
→ 原模型原有路径
→ 六台设备 Pref
```

原内部 `AGC_Modbus_RS485_Link` 可以保留用于原模型基线验证，但在外部控制模式下应旁路。

---

## 十、层6：设备本地控制完全不由板子接管

板子输出的 `Ppv1_pu`、`Pess1_pu` 等只是功率参考。

它们进入设备以后，仍由文档中的 Control System 完成：

```text
Pref
→ Power Control Loop
→ Id/Iq_ref
→ Current Regulator
→ Vd/Vq
→ Vref Generation
→ PWM
→ IGBT
```

本地控制层包括 PLL、Droop、电压环、电流环、前馈解耦和相位补偿，这些全部留在 RT-LAB。

所以板子不是逆变器底层控制器，而是：

```text
微网层协调控制器
```

两者的层级关系是：

```text
板子 AGC：慢速、全局、资源分配
设备 Control System：快速、局部、跟踪 Pref
```

## 十一、板子接入后的完整闭环逐步对应

### 第1步：RT-LAB 电气对象运行

PV、ESS、EV、负荷和电网在 OP5700 中实时计算。

对应文档：

```text
层1 电气主回路
```

### 第2步：RT-LAB 测量状态

获得：

```text
PCC P/Q/V/f
PV 最大可用功率
SOC
设备实际功率
```

对应文档：

```text
层2 测量层
+ 层4的PV曲线和SOC模块
```

### 第3步：RT-LAB 发布测量量

```text
测量量
→ 缩放/编码
→ OpOutput
→ Configuration
→ 40101~40116
```

这是为外部板子新增的测量出口。

### 第4步：板子读取

板子主动发出：

```text
FC03
offset 100
quantity 16
```

对应文档中原本 AGC 直接获取测量输入的位置。

### 第5步：板子运行 AGC

```text
动态测量量
+ JSON 静态参数
→ C 版 AGC_Controller
```

对应文档：

```text
层4中的 AGC_Controller
```

### 第6步：板子生成九路输出

```text
六路设备有功指令
+ agc_status
+ dP
+ remain
```

### 第7步：板子写回 RT-LAB

```text
FC16
offset 0
quantity 9
```

对应文档：

```text
层5通信层
```

### 第8步：RT-LAB 解码和选择

前六路：

```text
INT16 raw
→ ×0.0001
→ pu
→ 限幅
→ 有效性判断
→ Switch
```

后三路：

```text
状态显示
日志
与内部 AGC 结果对比
```

### 第9步：六台本地控制器执行

```text
外部 Pref
→ 功率环
→ 电流环
→ PWM
→ IGBT
```

对应文档：

```text
层6本地控制层
```

### 第10步：微电网发生响应

PV、ESS、EV 实际功率改变，PCC 有功随之改变。

### 第11步：重新测量

新的 `P_pcc`、SOC、PV 可用功率再次送给板子。

闭环回到第3步。

## 十二、内部 AGC 和外部板子 AGC 如何共存

最终模型应保留两条路径：

```text
原 Simulink AGC 输出 ─────────┐
                             Switch → 六台设备 Pref
板子外部 AGC 解码输出 ────────┘
```

切换规则建议为：

```text
EXT_MODE = 0
→ 使用内部 Simulink AGC

EXT_MODE = 1 且 External_Valid = 1
→ 使用板子 AGC

板子断线/心跳超时/命令非法
→ 自动回退内部 AGC
```

这样做的作用是：

* 便于比较内部 AGC 与板子 C 版输出；
* 外部板子未完成时模型仍能运行；
* 通信异常时不会把旧命令永久保持；
* 可以逐步完成闭环，而不是一次性拆掉原模型。

## 十三、15项高级策略目前如何对应

当前阶段板子只接管基础有功 AGC，不接管全部15项高级策略。

因此层4会暂时拆成：

```text
板子：
基础 AGC_Controller

RT-LAB：
PV曲线
SOC计算
15项高级策略
日志和指标
```

文档明确指出，15项策略目前主要输出建议控制量，还没有全部接管设备命令，需要后续通过策略仲裁器形成最终实控。

所以当前没有必要把15项策略全部迁移到板子。

但最终接入设备 Pref 前，应保留安全仲裁层，例如：

```text
保护与并离网切换
优先于
板子有功 AGC
```

否则板子普通 AGC 命令可能与低压减载、黑启动或孤岛保护发生冲突。

## 十四、V1、V2 在整个闭环中的位置

### V1 验证了闭环的"返回命令半程"

```text
板子
→ FC16
→ RT-LAB 寄存器
→ OpInput
→ SC 显示
```

但尚未接设备 Pref。

### V2 验证了闭环的"双向通信通道"

```text
RT-LAB 固定值
→ FC03
→ 板子

板子固定值
→ FC16
→ RT-LAB
```

但此时：

* RT-LAB 输出还不是实际测量量；
* 板子还没有运行 AGC；
* 六路命令还没有驱动设备。

所以 V2 建立的是：

```text
通信闭环
```

不是：

```text
控制闭环
```

## 十五、最终可以用一句话概括

文档原来是：

```text
RT-LAB 内部测量
→ RT-LAB 内部 AGC
→ RT-LAB 内部通信仿真
→ RT-LAB 设备执行
```

项目最终要改成：

```text
RT-LAB 内部测量
→ Modbus TCP 发给板子
→ 板子运行 AGC
→ Modbus TCP 写回 RT-LAB
→ RT-LAB 设备本地控制执行
→ 微电网响应
→ 再次测量
```

也就是：

> **把文档中层4的 AGC"大脑"搬到板子，把层5从通信仿真变成真实通信，保留 RT-LAB 中的电气对象、测量、全局电压频率控制和逆变器本地控制，最终形成控制器硬件在环闭环。**
