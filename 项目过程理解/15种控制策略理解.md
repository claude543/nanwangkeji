# 结论

这15项策略**不是一条从策略1依次执行到策略15的串联系统**，也不是15套都会同时控制设备的完整控制器。

它更准确的定位是：

> **一个并行运行的"高级策略监测与建议池"**。

它读取同一批微电网状态量，让15个不同"专家"分别判断各自关注的问题，然后每个专家输出：

```text
状态 st
告警 al
评价指标 mt
建议命令 cmd
```

但这段代码没有完成：

```text
策略冲突处理
策略优先级仲裁
选择最终生效策略
把策略建议转换成六台设备命令
```

所以它目前更接近**高级策略计算核心或策略展示平台**，而不是能够单独完成闭环控制的最终控制器。代码一开始创建四个长度为15的输出数组，每个索引对应一种策略。

# 一、用"15名专家"理解整体作用

把微电网想成一家公司。

现场不断提供：

```text
PCC有功、无功
电压、频率
两台储能SOC
两台PV出力
通信状态
运行参数
```

会议室里坐着15名专家。

例如：

```text
AGC专家：
当前PCC功率距离目标差多少？

防逆流专家：
当前是否向电网反送过多功率？

光伏平滑专家：
光伏变化速度是否过快？

削峰填谷专家：
现在是否应该让储能放电削峰或充电填谷？

防孤岛专家：
电压、频率或通信状态是否出现孤岛迹象？
```

每名专家提交四张表：

| 输出       | 可以怎样理解         |
| -------- | -------------- |
| `st(i)`  | 第i项策略当前状态      |
| `al(i)`  | 第i项策略是否告警      |
| `mt(i)`  | 第i项策略的评价指标     |
| `cmd(i)` | 第i项策略提出的建议或修正量 |

但现在缺少一名"总调度长"。

总调度长应该解决：

```text
多个策略同时触发，听谁的？
防逆流和最大消纳发生冲突，谁优先？
AGC要求增加发电，削峰填谷又要求储能充电，怎么处理？
策略建议最终由PV、ESS、EV分别承担多少？
```

这个总调度长对应未来可能需要的：

> **策略仲裁器 + 运行目标生成器 + 资源分配器。**

而现有`AGC_Controller`主要承担最后的资源分配工作。

---

# 二、15项策略的正确总体控制链

完整系统理论上应当是：

```text
微电网测量量
    ↓
15项高级策略并行判断
    ↓
形成15组状态、告警、指标和建议量
    ↓
策略选择与冲突仲裁
    ↓
形成当前唯一的控制目标或运行模式
    ↓
AGC/资源分配算法
    ↓
六路PV、ESS、EV功率指令
    ↓
RT-LAB微电网响应
    ↓
产生新的测量量
```

当前代码实际完成的是：

```text
微电网测量量
    ↓
15项策略并行计算
    ↓
st、al、mt、cmd
```

中间的策略仲裁以及后面的六路设备分配并不在这段代码中。

因此不能直接把：

```matlab
cmd(1), cmd(2), ..., cmd(15)
```

相加后送给设备，也不能直接把`cmd`向量当成六台设备的功率指令。

# 三、为什么15个`cmd`不能直接混在一起

因为它们的物理意义和单位并不统一。

例如：

```text
cmd(2)：
PCC目标与实际功率的差值，属于有功功率修正量

cmd(3)：
无功功率指令

cmd(5)：
是否存在孤岛风险的0/1标志

cmd(8)：
低压低频减载量或减载级别对应量

cmd(10)：
周期计划形成的功率目标

cmd(14)：
黑启动阶段编号

cmd(15)：
并网/孤岛切换请求标志
```

这些量显然不能直接相加。

同样，`st`的含义也不完全统一：

* 策略2的`st=1`表示AGC跟踪处于允许误差内；
* 策略4的`st=1`表示发生反送越限；
* 策略8的`st`表示减载级数；
* 策略14的`st`表示黑启动阶段；
* 策略15的`st=1/2`表示不同运行状态。

所以`st`也不是统一的"策略已启用标志"。

这进一步说明：

> 当前四组输出主要用于各策略自身的监视与展示，还没有形成统一标准化的控制总线。

---

# 四、代码中的15项策略也不是完全彼此独立

总体上它们是并行策略，但有少数内部复用关系。

例如：

* 策略15使用策略5计算得到的`islandScore`；
* 策略13使用策略7的`tieErr`和策略12的`renewRate`；
* 策略11、12、13共用光伏发电量、外送电量和新能源消纳率等累计结果。

所以更准确地说：

> 15项策略大部分并行计算，少数策略共享前面已经计算出的中间变量；代码排列顺序不代表控制优先级。

代码里策略1写在策略2前面，不表示需求控制一定优先于AGC。当前代码根本没有定义这类优先级。

# 六、对于当前论文，你必须深入理解哪些策略

不需要理解全部15项。

根据当前论文总体方向，建议分成三个等级。

## 第一等级：必须深入理解

### 策略2：AGC跟踪KPI

代码计算：

```matlab
agcErr = abs(Pt-P);
cmd(2) = Pt-P;
```

它关注：

> PCC实际功率是否跟踪目标功率。

它输出：

* 当前误差大小；
* 误差百分比；
* 是否超过允许误差带；
* 需要的功率修正量。

这正是你当前`AGC_Controller`的控制任务。

---

### 策略7：联络线功率控制

代码计算：

```matlab
tieErr = P-Pt;
cmd(7) = -tieErr;
```

展开后：

```
cmd(7)=-(P-P_t)=P_t-P
```

而策略2：

```
cmd(2)=P_t-P
```

所以在当前代码里：

```text
cmd(2) = cmd(7)
mt(2)  = mt(7)
al(2)  = al(7)
st(2)  = st(7)
```

也就是说：

> **策略2和策略7在当前代码中数学上完全相同，只是名称和解释角度不同。**

策略2从"AGC跟踪性能"角度描述；策略7从"联络线功率控制"角度描述。但它们不是两套独立的控制算法。

因此论文中不应将二者包装成两个创新策略。

应把它们合并理解为：

> **PCC/联络线有功功率目标跟踪场景。**

这就是第一篇论文最需要理解的高级策略。

---

### 与基础AGC的关系

策略2/7只给出：

```text
当前功率差多少
需要向哪个方向修正多少
跟踪效果好不好
```

真正决定：

```text
PV承担多少
ESS承担多少
EV承担多少
```

的是`AGC_Controller`。

所以论文主链应理解为：

```text

        ↓

        ↓
RT-LAB：
验证实际功率跟踪效果
```

## 第二等级：需要理解到接口和边界层面

### 策略5：防孤岛

它根据：

```text
频率偏差
电压偏差
通信状态comm
```

产生一个简单的孤岛风险标志。

特别需要注意，代码中：

```matlab
comm < 0.5
```

也会直接令`islandScore=1`。

这是一种非常简化的设计：

> 通信异常被当成孤岛风险条件之一。

对于你的通信论文，需要知道它存在，但不建议把它直接作为第一篇论文的核心算法。

原因是：

```text
通信中断
≠
电网一定发生孤岛
```

通信故障和电气孤岛应当区别处理。

---

### 策略15：并离网无缝切换

策略15使用策略5产生的`islandScore`。

如果：

```text

且
islandScore>0.5
```

就进入切换状态，并开始累积切换计时。

你需要理解它是为了知道：

> 通信异常可能通过策略5进一步影响并离网切换策略。

但你当前论文不研究构网控制、同步和真正的并离网无缝切换，因此不必深入其状态机代码。

# 八、一个必须马上检查的符号问题

在这份高级策略代码中明确规定：

```matlab
pImport = max(P,0);
pExport = max(-P,0);
```

也就是：

```text
P>0：从上级电网购电
P<0：向上级电网送电
```

策略4、9、11等都按照这个符号使用`P`。

但我们之前分析现有AGC时发现，AGC动作逻辑可能隐含另一种PCC方向。

因此，在将策略2/7与`AGC_Controller`连接之前，必须完成：

```text
提高PV功率
→ 观察PCC_P数值增大还是减小
```

用真实模型确认符号。

这是后续论文和板端闭环前必须完成的接口一致性检查。

这15项策略可以用一句话概括：
