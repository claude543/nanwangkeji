```text
        ↓

        ↓

        ↓

        ↓
功率外环 / 电压外环
        ↓

        ↓
电流内环
        ↓

        ↓

        ↓

        ↓

        ↓

        ↕

        ↓

        ↓

```

其中有两种完全不同的“跨 SM/SS 信息”：

```text

```

这两个不要混。

# 问题 1：原模型中六逆变器为什么这样连接 PCC？为什么 PV2、EV2、ESS2 看起来并联，EV1 和 ESS1 连在一起，PV1 又直接相连？

## 回答

先纠正一个容易产生误解的说法：

**PV2、EV2、ESS2 并不是“零阻抗直接并联到 PCC”。**

原模型实际是：

```text
                            PV1
                             │
                             │  无独立馈线
                             │
PCC / 公共母线 ──────────────●
                             │
                             ├── Line_PV2  ── PV2
                             │
                             ├── Line_ESS2 ── ESS2
                             │
                             ├── Line_EV2  ── EV2
                             │
                             └── Line_ESS1 ──●── ESS1
                                             │
                                             └── EV1_Line ── EV1
```

也就是说，原模型一共保留了 **5 段短馈线**：

```text
PV2 一段
ESS2 一段
EV2 一段
ESS1 一段
EV1 一段
```

而：

```text
PV1
```

直接挂在公共母线上。

---

## 1.1 先把三个词讲清楚：馈线、径向、共享馈线

### 馈线是什么？

在当前模型里，可以先把馈线理解成：

> **公共母线和某台下游设备之间那一段带有电阻 R、电感 L 的实际线路。**

例如 PV2：

```text
PV2
↓
prim_PV2
↓
Line_PV2
↓
公共母线 / PCC方向
```

这里的 `Line_PV2` 就是 PV2 的馈线。

它不是一根“没有任何影响的理想导线”。只要有电流流过，它就会产生：

- 电阻损耗；
- 感抗；
- 线路压降；
- 本地端电压与公共母线电压之间的差异。

所以最简单的因果关系是：

```text
设备功率变化
↓
线路电流变化
↓
馈线R/L上的压降变化
↓
设备本地端电压可能变化
```

---

### 径向是什么意思？

径向网络可以理解成：

> **从上游母线走到某个下游设备，只有一条主要电气路径，不形成闭环。**

例如 EV1：

```text
PCC
 │
 └─ Line_ESS1
       │
       ●
       │
       └─ EV1_Line
              │
             EV1
```

从 PCC 到 EV1 只能沿：

```text
PCC
→ Line_ESS1
→ 中间节点
→ EV1_Line
→ EV1
```

这一条路走。

没有另一条线路从 EV1 再绕回 PCC 形成环路，所以这是一条径向支路。

---

### 共享馈线是什么意思？

继续看 ESS1 和 EV1：

```text
PCC
 │
 └─ Line_ESS1
       │
       ●──── ESS1
       │
       └─ EV1_Line ── EV1
```

对于 ESS1：

```text
PCC ↔ ESS1
```

要经过：

```text
Line_ESS1
```

对于 EV1：

```text
PCC ↔ EV1
```

也必须先经过：

```text
Line_ESS1
```

然后再经过：

```text
EV1_Line
```

所以 `Line_ESS1` 是 ESS1 和 EV1 **共同经过的上游线路**，这就是共享馈线。

而 `EV1_Line` 只属于 EV1 的下游支路，不是共享的。

---

## 1.2 “节点耦合”到底是什么意思？

这里的耦合不是：

```text
EV1控制器直接给ESS1控制器发信号
```

而是：

> **一台设备改变功率以后，通过共享的物理线路改变线路电流和节点电压，从而让另一台设备感受到电气环境变化。**

例如 EV1 增加充电：

```text
EV1增加充电
↓
EV1吸收的电流增大
↓
EV1_Line电流增大
↓
共享的Line_ESS1电流也随之变化
↓
Line_ESS1上的R/L压降变化
↓
ESS1所在中间节点电压变化
↓
ESS1的prim测量能够看到这个变化
↓
ESS1 Control System必须重新调整
```

所以即使：

```text
ESS1 Pref完全没有改变
```

EV1 的行为也可能让 ESS1 的本地电压发生轻微改变。

这就是：

> **同一径向馈线上的节点耦合。**

本质上是“通过电网发生相互影响”，不是控制器之间直接通信。

---

## 1.3 PV2、ESS2、EV2 为什么采用三条独立支路？

这三台设备各自经过一段 RL 馈线后接到公共母线：

```text
                 ┌─ RL ─ PV2
PCC公共母线 ─────┼─ RL ─ ESS2
                 └─ RL ─ EV2
```

这样三台设备虽然最终都属于同一个 PCC 系统，但不再拥有完全相同的电气端点。

如果把六台设备全部理想并在一个“零阻抗母线”上：

```text
设备1端电压
=
设备2端电压
=
……
=
PCC电压
```

那么模型会丢掉：

- 馈线压降；
- 馈线损耗；
- 不同设备电气距离差异；
- 某台设备通过线路阻抗影响本地端电压的现象；
- 不同设备本地电压与 PCC 电压之间的差异。

有了 RL 馈线以后：

```text
线路电流越大
→ R/L上的压降越明显
→ 设备本地端电压和PCC不再完全相同
```

这也是为什么每台逆变器需要使用自己的 `prim` 三相状态，而不是六台设备全部共用 PCC 的同一组 V/I。

---

## 1.4 为什么 ESS1 和 EV1 要做成这条两级径向支路？

实际结构：

```text
PCC
 │
 └─ Line_ESS1
       │
       ●──── ESS1
       │
       └─ EV1_Line ── EV1
```

这里的关键不是“ESS1 和 EV1 串联”。

**ESS1 本体和 EV1 本体并没有串联通过同一个电流。**

准确说：

- ESS1 接在一个中间节点；
- EV1 位于这个中间节点之后更远的位置；
- EV1 与 ESS1 共享上游 `Line_ESS1`；
- EV1 自己还额外经过 `EV1_Line`。

于是 EV1 的本地电气环境比 ESS1 更“远”，而且两台设备之间存在共享线路产生的物理耦合。

---

## 1.5 原模型为什么要故意这样接？到底有什么作用，要验证什么？

这个问题必须区分两件事。

### 模型能够直接确认的事实

原模型明确构造了不同电气位置：

```text
PV1
→ 直接接公共母线

PV2 / ESS2 / EV2
→ 各经过一段独立馈线

ESS1
→ 位于Line_ESS1后的中间节点

EV1
→ 在ESS1节点之后再经过EV1_Line
```

因此它客观上不是：

```text
六台完全相同的逆变器
+
六个完全相同的接入点
```

而是：

> **六台资源属于同一个微电网，但所处的本地电气环境并不完全相同。**

### 不能凭模型确认的事情

仅凭模型文件，无法证明老师当初一定是为了某一个具体试验指标才指定“PV1直连、EV1最远”。因此不能编成“老师就是为了验证某某现象”。

但是，这种拓扑产生的工程价值可以明确解释。

---

### 作用一：避免六台逆变器变成六个“理想母线复制品”

如果六台设备全部零阻抗直接并在一个理想节点：

```text
V_PV1
≈ V_PV2
≈ V_ESS1
≈ V_EV1
≈ V_PCC
```

那么虽然数量上有六台设备，但从网络位置上看，它们几乎没有区别。

加入馈线后：

```text
线路有R/L
↓
设备功率不同
↓
线路电流不同
↓
线路压降不同
↓
不同设备本地端电压可能不同
```

所以六台逆变器的本地控制器实际上是在不同电气条件下工作的。

---

### 作用二：验证本地逆变器控制器不是只能在理想接入点工作

例如：

```text
PV1
```

直接接公共母线，条件相对简单。

而：

```text
EV1
```

要经过两段线路，而且和 ESS1 共享一段上游馈线。

如果这些不同位置上的设备都能够：

```text
稳定PLL锁相
稳定进行P/Q控制
稳定跟踪Pref
保持电流内环稳定
```

说明 Control System 不是只能在一个完全理想、完全对称的接入点运行。

---

### 作用三：让“设备本地状态”和“PCC整体状态”成为两个真正不同的层次

加入馈线后：

```text
EV1的本地Vabc/Iabc
ESS1的本地Vabc/Iabc
PV2的本地Vabc/Iabc
PCC的Vabc/Iabc
```

不再必然完全相同。

于是模型真正需要：

```text
六套prim
+
一套PCC Measurements
```

六套 `prim` 回答：

> **每一台逆变器自己接入电网的位置现在是什么状态？**

PCC 回答：

> **六台设备和内部网络加在一起以后，整个微电网从外部上级电网看是什么状态？**

---

### 作用四：验证系统级 AGC 在“设备分散接入”情况下还能否完成总目标

当前层级实际上是：

```text
每台设备：
自己的prim
↓
自己的Control System
↓
保证本设备尽量执行Pref

整个微电网：
所有设备经过不同馈线汇聚
↓
PCC
↓
AGC看到PCC总功率
↓
再调整六路Pref
```

所以这个模型同时检验两层事情：

```text
设备层：
每台逆变器在自己的本地网络条件下能否正确执行

系统层：
六台设备分散接入并存在网络差异时，
AGC还能否把整个微电网的PCC功率调到目标
```

这就是这种连接方式真正的工程意义。

## 1.6 那为什么偏偏 PV1 直连、EV1 放最远？

从模型本身可以确认“它就是这样连接的”。

但是：

**仅凭模型文件，无法证明老师当时为什么具体指定“PV1直连、EV1最远、ESS1放在中间节点”。**

所以不要把下面这种说法写成事实：

> “老师一定是为了模拟某个具体园区的真实线路。”

目前没有证据支持这个具体结论。

我们能够确定的是：

> 这种拓扑客观上构造出了不同电气距离、独立馈线和共享馈线节点，比六设备理想并联更接近一个小型径向配电网络。

## 1.7 PCC 最终测到的是什么？“整个微电网对外交换功率”到底怎么理解？

PCC 是：

```text
Point of Common Coupling
公共连接点
```

可以把系统边界画成：

```text
       微电网内部
┌─────────────────────┐
│ PV1 / PV2           │
│ ESS1 / ESS2         │
│ EV1 / EV2           │
│ 内部馈线            │
└─────────┬───────────┘
          │
         PCC
          │
      上级10 kV电网
```

所以 PCC 是：

> **微电网内部与外部上级电网之间的共同边界。**

所谓“整个微电网对外交换功率”，就是问：

> **穿过 PCC 这个边界的净有功功率有多少，方向是从上级电网流入微电网，还是从微电网流向上级电网。**

当前项目内部统一方向：

```text
Ppcc > 0
→ 微电网向上级电网送电

Ppcc < 0
→ 微电网从上级电网购电
```

例如：

```text
Ppcc = -120 kW
```

表示：

```text
上级电网
↓ 约120 kW
PCC
↓
微电网内部
```

也就是整个微电网此时净购电约 120 kW。

如果：

```text
Ppcc = +80 kW
```

则表示：

```text
微电网内部
↓ 约80 kW
PCC
↓
上级电网
```

也就是整个微电网净向外送电约 80 kW。

---

## 1.8 为什么六台设备的功率最终会体现在 PCC 上？

假设一个最简单的工况：

```text
PV1 = 0
PV2 = 0
ESS1 = 0
ESS2 = 0

EV1 ≈ -60 kW
EV2 ≈ -60 kW
```

两台 EV 一共需要约：

```text
120 kW
```

内部又没有 PV 和 ESS 提供这 120 kW。

那么这部分能量只能来自：

```text
上级电网
↓
PCC
↓
内部馈线
↓
EV1 / EV2
```

所以 PCC 会看到大约：

```text
-120 kW
```

这正是此前模型基线实际得到的结果。

### 如果此时 PV 再发 40 kW 会怎样？

EV 仍然总共需要约 120 kW。

但其中约 40 kW 已经可以由微电网内部 PV 提供：

```text
PV
→ 40 kW
→ 微电网内部
```

所以外部电网只需要再提供大约：

```text
80 kW
```

于是 PCC 会从：

```text
-120 kW
```

向：

```text
-80 kW
```

方向变化。

所以 AGC 调 PV、ESS、EV 的最终目的，就是通过改变微电网内部的功率平衡，改变 PCC 上看到的净交换功率。

## 1.9 prim 和 PCC 明明最开始都只测 V 和 I，功率到底从哪里来？

这是一个非常重要的基础认识：

> **电功率本来就是由电压和电流共同计算得到的，不需要另外存在一个完全独立的“功率物理端口”。**

单相最简单的瞬时功率：

```text
p(t) = v(t) × i(t)
```

三相系统则可以写成：

```text
p(t)
=
va(t)·ia(t)
+
vb(t)·ib(t)
+
vc(t)·ic(t)
```

因此只要已经测到了：

```text
Va, Vb, Vc
Ia, Ib, Ic
```

功率信息实际上已经包含在这些电压、电流波形里。

---

### PCC 是怎样由 V/I 得到 P/Q 的？

PCC 原始测量首先只是：

```text
Vpcc = [Va,Vb,Vc]
Ipcc = [Ia,Ib,Ic]
```

然后进入：

```text
J2_PCC_Measurements
```

内部完成：

```text
Vpcc
↓
PLL
↓
当前基波频率和相角

Vpcc + Ipcc + PLL参考
↓
Power (PLL-Driven, Positive-Sequence)
↓
Ppcc
Qpcc
```

因此：

```text
PCC物理测量
先得到V/I

PCC Measurements算法
再由V/I计算P/Q
```

---

### prim 又是怎样由 V/I 得到单台设备 Pmeas/Qmeas 的？

同样道理。

例如：

```text
prim_EV1
```

最开始得到：

```text
EV1本地Vabc
EV1本地Iabc
```

然后：

```text
Vabc / Iabc
↓
送入EV1 Control System
↓
Measurements
↓
PLL / 坐标变换 / P-Q计算
↓
EV1 Pmeas
EV1 Qmeas
```

所以：

```text
prim
不是“直接输出功率的模块”

prim
先把真实三相V/I测出来

Control System内部
再把这些V/I加工成Pmeas/Qmeas
```

## 1.10 prim 与 PCC 到底是什么关系？

可以直接记这张表：

| 测量 | 位置 | 最初测量 | 后续得到 | 主要服务对象 |
|---|---|---|---|---|
| `prim_EV1` | EV1自己的高压接入点 | EV1本地 Vabc/Iabc | EV1 Pmeas/Qmeas、PLL状态 | EV1 Control System |
| `prim_ESS1` | ESS1自己的高压接入点 | ESS1本地 Vabc/Iabc | ESS1 Pmeas/Qmeas | ESS1 Control System |
| `prim_PV2` | PV2自己的高压接入点 | PV2本地 Vabc/Iabc | PV2 Pmeas/Qmeas | PV2 Control System |
| `PCC` | 微电网与上级电网边界 | PCC Vabc/Iabc | Ppcc/Qpcc、Freq、Vrms | AGC、Supervisor、策略 |

所以可以压缩成：

```text
prim：
看“这一台设备自己现在发生了什么”

PCC：
看“六台设备和内部网络加起来，
整个微电网现在对上级电网表现成什么”
```

这就是为什么：

```text
六个prim
+
一个PCC
```

并不是重复测量。

它们分别服务：

```text
设备级本地闭环
和
系统级协调闭环
```

## 1.11 把问题1的整个闭环最后串一次

```text
六台设备分布在不同网络位置
↓
不同馈线造成不同本地电气条件
↓
每台prim测自己的Vabc/Iabc
↓
各自Control System算Pmeas/Qmeas
并控制自己执行Pref
↓
六台设备的真实功率经过馈线汇聚
↓
PCC测Vpcc/Ipcc
↓
PCC Measurements算Ppcc/Qpcc
↓
AGC判断整个微电网对外功率是否达到Ptarget
↓
重新调整六台设备Pref
↓
六台设备再执行
↓
PCC再次变化
```

所以这个网络结构的真正意义不是为了“让图更像配电网”，而是：

> **让设备级控制面对不同本地电气条件，同时让系统级 AGC 只通过 PCC 观察整个微电网的最终综合效果，从而形成一个具有网络差异、设备本地反馈和系统级协调的完整闭环。**

---

# 问题 2：两电平变流器到底是什么？原理、输入输出、工作过程和作用是什么？

## 回答

可以先压缩成一句话：

> **Two-Level Converter 是真正执行功率变换的功率级；Control System 负责“算应该怎么开”，PWM 负责生成开关脉冲，两电平变流器负责按照这些脉冲真正把直流侧电能变成交流侧三相电压和电流。**

---

## 2.1 为什么叫“两电平”？

一个典型三相两电平变流器有：

```text
3个桥臂
×
每个桥臂2个可控开关
=
6个主要功率开关
```

结构可以简化成：

```text
DC+
 │
 ├─ 上管 ─┐
 │        ├── A相
 └─ 下管 ─┘
          ...
          B相
          ...
          C相
 │
DC-
```

对于某一个桥臂，它的输出节点在理想情况下主要在两种状态之间切换：

```text
接近 DC+
或
接近 DC-
```

所以叫：

```text
Two-Level
两电平
```

它不是说最终交流电压只有两个值。

因为三个桥臂高速 PWM 开关，再经过滤波器后，最终可以形成接近正弦的三相基波电压和电流。

---

## 2.2 在本项目里它的输入是什么？

要分成两类。

### 第一类：电气输入

来自直流侧：

```text
DC Voltage Source / DC Link
```

也就是变流器有真正可以交换的直流能量。

### 第二类：控制输入

来自：

```text
Control System
↓
Vpwm
↓
PWM Generator
↓
六路门极脉冲
↓
Two-Level Converter
```

所以 Two-Level Converter 自己并不知道：

```text
Ptarget是多少
Pref是多少
现在应该发电还是充电
```

这些判断都在控制器里完成。

变流器只执行：

```text
哪个开关什么时候导通
哪个开关什么时候关断
```

---

## 2.3 它的输出是什么？

交流侧输出的是高速开关形成的三相电压、电流：

```text
A
B
C
```

但这个波形本身含有明显的开关频率分量。

所以后面还需要：

```text
Two-Level Converter
↓
L / C 滤波
↓
变压器
↓
电网
```

滤波器把高频 PWM 开关成分压下去，主要保留需要的基波成分。

---

## 2.4 它究竟怎样把“Pref”变成真实功率？

不是：

```text
Pref
→ Two-Level Converter
→ 功率
```

而是经过完整控制链：

```text
Pref
↓
功率控制器
↓
算出需要的 Id / Iq
↓
电流控制器
↓
算出需要的 Vd / Vq
↓
abc/dq相关变换
↓
得到三相调制参考 Vpwm
↓
PWM Generator
↓
六路门极脉冲
↓
Two-Level Converter
↓
真实三相电压电流
↓
P、Q发生变化
```

因此：

> **变流器是执行器，Control System 才是控制逻辑。**

---

## 2.5 为什么 ESS、EV 可以充也可以放？

如果功率器件、直流侧和控制策略允许双向功率流，交流侧与直流侧之间就可以双向交换能量。

例如 ESS：

```text
ESS放电：
DC侧 → 变流器 → AC侧 → 电网
P > 0

ESS充电：
电网 → AC侧 → 变流器 → DC侧
P < 0
```

EV 在当前模型主要工作在充电区域，因此 Pref 通常为负。

PV 主要作为发电资源，因此主要工作在正功率区域。

---

## 2.6 你现在最值得掌握到什么程度？

不需要一开始就推导所有开关函数。

先做到：

1. 知道三相两电平桥为什么是 6 个开关；
2. 知道 PWM 的作用；
3. 知道 `Vpwm` 不是实际交流电压，而是调制参考；
4. 知道变流器输出后为什么要滤波；
5. 知道功率方向由控制环和能量条件共同决定；
6. 能把：
   ```text
   Pref → 控制器 → PWM → 变流器 → Pmeas
   ```
   完整说出来。

做到这一步，就已经足够继续理解当前项目。

---

# 问题 3：拆分前和拆分后的 prim 到底测什么？为什么又把测量的电压电流送回自己的 Control System？3 s 开 Droop 后到底是什么模式？

## 回答

这是整个项目最值得真正吃透的问题之一。

---

## 3.1 prim 不是 PCC 测量，也不是变流器低压侧测量

在原模型的一台设备内部，电气链大致是：

```text
DC Source
↓
Two-Level Converter
↓
inv 测量
↓
L/C滤波
↓
三相变压器
↓
prim
↓
A/B/C Connection Port
↓
馈线
↓
PCC
```

所以：

```text
inv
```

更靠近逆变器低压交流侧；

而：

```text
prim
```

位于变压器高压侧、设备准备接入外部电网的位置。

因此 prim 测量的是：

> **这一台设备自己在电网接入侧的三相端口电压和三相支路电流。**

当前项目里，它对应约 10 kV 高压侧本地接入点。

---

## 3.2 prim 的 Vabc、Iabc 与 PCC 的 V、I 有什么不同？

假设 PV2 通过一段馈线连接 PCC：

```text
PV2
↓
prim_PV2
↓
Line_PV2
↓
PCC
```

由于：

```text
Line_PV2 有 R 和 L
```

所以完全可能出现：

```text
PV2本地端电压
≠
PCC电压
```

同样，ESS1、EV1 处于不同节点时，本地电压也可能不完全相同。

所以：

```text
PCC Measurements
```

回答的是：

> “整个微电网和大电网交界点现在怎样？”

而：

```text
prim_EV1
prim_ESS1
...
```

回答的是：

> “这台具体逆变器自己接入电网的那个位置现在怎样？”

这是两个层级。

---

## 3.3 拆分前 prim 在哪里？

拆分前 prim 在每个设备子系统内部。

例如：

```text
ESS1_100kW
 ├─ Converter
 ├─ Filter
 ├─ Transformer
 ├─ prim
 └─ A/B/C
```

它输出：

```text
Vprim
Iprim
```

然后通过 Goto/From 等信号送回：

```text
Control System
```

也就是说：

```text
设备自己产生电压电流
↓
prim实际测量
↓
Control System看到真实结果
↓
下一步重新调整开关
```

这就是闭环。

---

## 3.4 拆分后 prim 在哪里？

拆分后物理功率级被分到：

```text
SS_Slave
SS_Slave2
SS_Slave3
```

但 prim 被保留在：

```text
SM_Master
```

其物理位置的含义没有改变：

```text
SS中的逆变器和滤波
↕
Differential Stubline
↕
SM中的变压器
↓
prim
↓
高压馈线
↓
PCC
```

因此：

> **拆分改变了计算任务所在的 CPU 子系统，但没有故意改变 prim 原来代表的物理测量位置。**

这非常重要。

---

## 3.5 拆分后 prim 的数据怎么又回到 SS 中的 Control System？

拆分后形成两条不同的路径。

### 真实电气路径

```text
SS Converter
↓
滤波器
↓
PMIO
↓
Differential Stubline
↓
SM变压器
↓
prim
↓
馈线/PCC
```

这是电路。

### 测量反馈路径

prim 把实际三相电压电流转换成普通 Simulink 数值：

```text
prim Vabc(3)
prim Iabc(3)
↓
SM 中 Mux
+
Fref
Vref
Droop_On
Pref
Qref
GridOn
↓
每台设备总共12个数值
↓
OpComm
↓
SS
↓
Demux
↓
Control System
```

所以：

> 电气能量通过 Stubline，测量数据通过 OpComm。

---

## 3.6 为什么“自己测出来的电压电流又给自己”？

因为控制系统必须是闭环。

如果没有反馈：

```text
Control System
→ 发出PWM
→ 之后不再知道设备发生了什么
```

这就是开环。

真实系统中：

- 电网电压会变化；
- 线路有压降；
- 功率不可能瞬时精准等于 Pref；
- 负荷和其他设备会影响本设备；
- 变流器和滤波器有动态。

所以控制器每个周期都必须重新看：

```text
现在实际 V 是多少？
现在实际 I 是多少？
现在实际 P、Q 是多少？
当前电网相角在哪里？
```

然后再决定下一拍怎么调。

---

## 3.7 Vabc / Iabc 在 Control System 内分别被拿去干什么？

大体有这些作用：

### 跟网控制 Grid-Following

Vabc 用于 PLL：

```text
Vabc
↓
PLL
↓
电网相角 theta
电网频率 f
```

然后 abc 电压、电流在这个同步角下变成 dq 量。

另外：

```text
Vabc + Iabc
↓
P/Q测量
↓
Pmeas / Qmeas
```

用于功率闭环：

```text
Pref - Pmeas
Qref - Qmeas
↓
PI
↓
电流参考
```

### 构网控制 Grid-Forming

同样需要真实 P、Q：

```text
Pmeas
Qmeas
↓
Droop
↓
新的频率/电压参考
```

所以无论 GFL 还是 GFM，都不可能完全脱离本地电压、电流测量。

---

# 3.8 “设备接入电网侧的三相状态”到底是什么意思？

这句话可以改写成：

> **控制器要看到的不是某个遥远 PCC 的统一状态，也不是变流器桥臂内部的开关电压，而是这一台逆变器经过滤波和变压器以后、真正接入外部交流网络那个端点的 Vabc 和 Iabc。**

例如 EV1：

```text
EV1 Converter
↓
滤波
↓
变压器
↓
prim_EV1  ← 这里就是 EV1 自己的“电网侧三相状态”
↓
EV1_Line
↓
ESS1节点
↓
Line_ESS1
↓
PCC
```

EV1 的本地状态和 PCC 不完全相同，这正是保留 prim 的原因。

---

# 3.9 3 s 时 Droop_On=1，到底是不是切成构网模式？

**不是。**

这是当前模型里最容易误判的地方。

要区分两个开关：

```text
Droop_On
和
GridOn / ConnectMode
```

它们完全不是一回事。

---

## Droop_On 的作用

原模型：

```text
t < 3 s：Droop_On = 0
t ≥ 3 s：Droop_On = 1
```

它进入：

```text
Droop Control 的 Enable
```

所以它表示：

> 允许构网分支中的 P-f、Q-V 下垂算法开始参与计算。

它不负责选择最终使用哪一套控制链。

---

## GridOn / ConnectMode 的作用

这才是真正决定：

```text
Grid-Following
还是
Grid-Forming
```

哪一条路径接到后面的公共电流内环。

我对照了当前 Control System 的 Switch 条件：

```text
ConnectMode > 0.5
```

时，选择的是带 `F` 后缀的 PLL / Power Control Loop 跟网路径；

否则才选择 Droop / Voltage Regulator 构网路径。

当前基线：

```text
GridOn = 1
```

所以：

```text
ConnectMode > 0.5
```

成立。

最终选择：

```text
Grid-Following 跟网控制
```

---

# 3.10 那是不是两种模式同时工作？

准确说：

> **两套分支可以同时在内部计算，但不是两套控制器同时控制同一逆变器。**

可以画成：

```text
                    ┌─ GFL分支 ──┐
Measurements ───────┤             ├─ Switch ─→ 公共电流内环 ─→ PWM
                    └─ GFM分支 ──┘
                              ↑
                         ConnectMode选择
```

3 s 以后：

```text
Droop_On=1
```

意味着：

```text
GFM/Droop分支开始正常计算
```

但：

```text
GridOn=1
```

仍然让 Switch 选择：

```text
GFL分支
```

所以当前的准确结论是：

> **3 s 后 Droop 分支“活着、在算”，但当前真正控制 PWM 的仍然是跟网路径。**

不是：

```text
GFL + GFM 同时叠加控制
```

更不是：

```text
Droop_On一开就自动变成构网
```

---

# 问题 4：拆分前逆变器内部 prim 右边的 A/B/C Connection Port，与拆分后的 PMIO 有什么区别？

## 回答

首先要澄清：

> **Connection Port 和 PMIO 不是“一个是电气端口、另一个是通信端口”。**

它们都属于物理电气网络接口这一类东西。

真正的区别在于：

```text
它们处在什么层级
是否跨 RT-LAB 实时任务
是否和 Stubline 配合
```

---

## 4.1 拆分前 A/B/C Connection Port 做什么？

原模型一台设备：

```text
设备Subsystem内部
↓
Transformer
↓
prim
↓
A / B / C Connection Port
↓
父层 sm_circuit 中的馈线
```

它的作用很简单：

> 把设备子系统内部的三相电气端点暴露给父层电路。

整个模型仍然属于同一个大的电气网络求解问题。

因此它并没有：

- 人为加入一步延时；
- 把状态空间方程切开；
- 让两个 RT-LAB 子任务独立计算。

可以理解为：

```text
只是“穿过Subsystem边界”
```

并没有穿过实时计算任务的解耦边界。

---

## 4.2 拆分后的 PMIO 做什么？

拆分后：

```text
SM_Master
和
SS_Slave
```

已经是不同实时子系统。

普通 Simulink 数值信号可以：

```text
OpComm
```

跨任务。

但真实电气网络不是一个普通数值信号。

你不能简单说：

```text
SM输出一个电压
SS输出一个电流
每100 μs互相发一下
```

因为电路方程原本是同一步里联立求解的。

因此新的物理边界需要：

```text
SM PMIO
↓
Stubline
↓
SS PMIO
```

PMIO 的作用是：

> 给 RT-LAB 实时子系统提供物理建模端口，使 Stubline 两端可以真正连接到不同的实时任务内部电路。

---

## 4.3 真正让 SM 和 SS “解耦”的到底是谁？

不是 PMIO。

是：

```text
Stubline
```

Stubline 内部具有一步传播延时，因此：

```text
本步 SM 的计算
不必等待
本步 SS 同时解完以后
才能建立当前方程
```

于是原本一个大联立电路可以拆成多个较小子网络。

所以要记：

```text
PMIO
= 物理接口

Stubline
= 具有一步延时的物理解耦元件

OpComm
= 普通数值通信
```

三者职责完全不同。

---

## 4.4 为什么拆分前每台只有 A/B/C 三个端点，拆分后看起来端点多了一倍？

因为原模型外部看到的是已经接好的三相变压器高压端：

```text
A
B
C
```

而成功分核方案把三相变压器拆成：

```text
3个单相双绕组变压器
```

低压侧再经过：

```text
3条 Differential Stubline
```

每一条差分 Stubline 表示一个浮置绕组，需要两个端点：

```text
a_high / a_low
b_high / b_low
c_high / c_low
```

所以：

```text
3个绕组 × 每个2端
=
6个物理端点
```

然后在 SS 内重新连接成 Delta：

```text
A绕组
B绕组
C绕组
↓
首尾相接
↓
三角形
```

因此端口数量增加不是“多了三相电”，而是：

> 为了显式保留每一个悬浮单相绕组的两个端点。

---

## 4.5 一个非常重要的认识

从 SLX 底层结构看，旧 Connection Port 本身也属于 Physical Modeling I/O 这一类端口表示。

所以：

> 不要把旧 Connection Port 和新 PMIO 想成两个完全不同的物理数学元件。

真正发生本质变化的是：

```text
旧：
一个大电网内部的Subsystem物理端口

新：
不同RT-LAB任务之间
PMIO + Stubline + PMIO
形成的物理解耦边界
```

---

# 问题 5：官方 Transformer Stubline 分核结构到底是什么？为什么拆变压器、为什么用差分、为什么 prim 留在 SM、为什么单相双绕组？普通 Stubline 为什么失败？

## 回答

先给最核心的结论：

> **我们并不是把原来的变压器随便拆开，而是利用原变压器本来就存在的漏阻抗，把低压侧漏阻抗“搬进” Stubline，让 Stubline 在尽量保持原物理参数的同时引入一个时间步的解耦延时，从而把 SM 和 SS 分到不同 CPU 任务。**

---

# 5.1 什么是 Stubline？

OPAL-RT 的 ARTEMiS Stubline 本质上是一种：

```text
具有固定传播延时的短传输线等效模型
```

在这里最关键的不是“它像不像一根真实电缆”。

最关键的是：

```text
它具有 1 个仿真步长的传播延时
```

当前：

```text
Ts = 100 μs
```

因此两端在数学上不再要求“同一个时间步瞬时联立”。

原本：

```text
SM电路
↔
SS电路
```

可能属于一个巨大的状态空间方程。

插入 Stubline 后，可以变成：

```text
SM子网络
↓
上一步的Stubline边界信息
```

和：

```text
SS子网络
↓
上一步的Stubline边界信息
```

分别计算。

这就是它能帮助实时分核的根本原因。

---

# 5.2 为什么叫“解耦”？

没有 Stubline 时，假设 SM 和 SS 通过理想电气连接直接相连：

```text
SM本步电压
取决于SS本步电流

SS本步电流
又取决于SM本步电压
```

于是两个任务必须在同一个方程里一起解。

有一步延时后：

```text
SM本步
使用已经知道的边界历史量

SS本步
也使用已经知道的边界历史量
```

两边不再形成同一步代数闭环。

因此：

```text
一个大矩阵
→
几个小矩阵
```

这会显著降低实时计算压力，也允许分配到不同 CPU 核。

---

# 5.3 为什么不能随便在任意位置插 Stubline？

因为 Stubline 不是“纯软件切口”。

它本身仍然有电气参数和传播特性。

如果随便找一根理想连接线插进去：

```text
原系统没有的动态
可能被你人为加进来
```

正确做法应该尽量利用：

```text
系统本来就有的阻抗/储能元件
```

作为数值解耦位置。

变压器漏感正好非常适合。

---

# 5.4 为什么官方方案把变压器高低压侧拆开？

原三相变压器每个绕组本来就有：

```text
绕组电阻 R
+
漏感 L
```

官方 Transformer Stubline 思路是：

```text
原变压器低压侧的 R、L
↓
从变压器模型内部拿出来
↓
放到 Stubline
```

于是：

```text
单相变压器本体的低压侧漏阻抗
设为 0

Stubline
使用原来低压侧同等的 R、L
```

这样 Stubline 并不是凭空增加一组新的串联阻抗。

而是：

> **把原来已有的低压侧漏阻抗换一种数学实现位置。**

---

# 5.5 当前模型里具体是怎么做的？

原模型每台设备使用一个三相：

```text
Yg / Delta
三相变压器
```

拆分后每台设备变成：

```text
3个 Single-Phase Multi-Winding Transformer
+
3条 Differential Stubline
```

例如每个单相变压器采用：

```text
额定容量 ≈ 110000 / 3
高压侧基准 = 10000 / sqrt(3) V
低压侧基准 = 480 V
```

高压侧三只单相变压器：

```text
一端接A/B/C
另一端共接地
```

重新形成：

```text
Yg
```

低压侧三个绕组经过差分 Stubline 进入 SS 后：

```text
首尾连接
```

重新构造：

```text
Delta
```

所以：

> 三个单相变压器不是把原来的三相变压器物理意义改掉，而是为了让每一个低压绕组能够独立跨越一个差分 Stubline 边界。

---

# 5.6 为什么必须用“单相双绕组”而不是保留一个完整三相变压器？

因为 Delta 低压侧的每一条绕组，本质上都是一个：

```text
两个端点之间的浮置绕组
```

例如：

```text
绕组AB
连接 A 和 B

绕组BC
连接 B 和 C

绕组CA
连接 C 和 A
```

它不是：

```text
A对地
B对地
C对地
```

所以最自然的做法是把三相变压器拆成：

```text
3个单相绕组
```

每一个绕组都保留两个真实端点。

然后每个绕组跨一条 differential stubline。

这样可以严格重构：

```text
Yg / Delta
```

连接。

---

# 5.7 “差分 Stubline”里的“差分”是什么意思？

这里的“差分”不是：

```text
电流差动保护
```

也不是微积分里的“差分”。

它指的是：

> **关心两个端点之间的电压差，而不是把某一个端点默认固定参考地。**

普通相对地思路：

```text
Va = A端对地
```

差分思路：

```text
Vab = A端 - B端
```

对于 Delta 绕组：

```text
绕组本来就是两个相节点之间
没有天然的中性点接地
```

所以差分形式非常匹配。

---

# 5.8 为什么说差分 Stubline 是“浮置”的？

因为它不要求：

```text
其中一端 = Ground
```

两个端点都可以随整个 Delta 网络一起浮动。

例如某个低压绕组：

```text
端点1
↕
绕组
↕
端点2
```

Stubline 只需要维持这个绕组两端之间的电气关系。

这与变压器 Delta 次级非常一致。

---

# 5.9 为什么 prim 必须留在 SM？

这不是因为“prim 计算量大”。

真正原因是：

> **prim 原本代表的是变压器高压侧、本地设备接入馈线的位置。**

而拆分后的高压网络：

```text
10 kV母线
馈线
PCC
高压侧变压器
```

全部都在 SM。

所以如果要保持原模型物理测量位置不变：

```text
prim
```

就应该继续放在高压网络这一边，也就是 SM。

然后它测出来的 Vabc/Iabc 再作为普通数值反馈：

```text
SM
→ OpComm
→ SS Control System
```

这样：

```text
物理测量位置不变
控制器输入语义不变
```

只是计算模块跨了 CPU。

---

# 5.10 为什么不能把 prim 也放到 SS 低压侧？

因为那样测到的就不是同一个物理量。

低压侧和高压侧之间还有：

```text
变压器变比
漏阻抗
连接组别
```

你如果把原来的高压侧测量直接换成低压侧测量：

```text
数值大小会变
相位/连接关系也可能变
控制器输入语义发生改变
```

这就不再是“只做实时分核、不改变原控制逻辑”。

所以我们坚持：

> **分核可以改计算位置，但尽量不改控制器原本看到的物理测量位置。**

---

# 5.11 普通 Stubline 和 Differential Stubline 的核心区别

| 项目 | 普通 Stubline | Differential Stubline |
|---|---|---|
| 主要电压定义 | 更接近相对公共参考/地 | 两端之间的差分电压 |
| 是否适合浮置绕组 | 不理想 | 适合 |
| Delta 次级 | 不自然 | 自然匹配 |
| 一个单相绕组需要的物理端点 | 常按相对参考处理 | 明确保留两个端点 |
| 本项目最终是否采用 | 否 | 是 |
| 是否都能提供一步延时解耦 | 可以 | 可以 |

所以：

> **“差分”解决的是边界的电气拓扑匹配；“Stubline”本身的一步延时解决的是实时计算解耦。**

这两个作用不要混成一个。

---

# 5.12 为什么我们之前用普通 Stubline 会失败？

这里也不能简单理解为：

```text
普通 Stubline = 错误模块
差分 Stubline = 永远正确
```

普通 Stubline 在适合的传输线和拓扑里完全可以使用。

我们之前的问题主要有两个。

---

## 原因一：当时试图拿很小的馈线电感直接做普通 Stubline 边界

这些短馈线的 L 很小。

而 Stubline 为了实现一个固定时间步传播延时，本身会形成相应的线路等效特性。

在我们的：

```text
小电感
+
100 μs 步长
```

组合下，等效出来的电容性影响变得不能忽略。

结果就是出现：

- 明显额外无功；
- PCC 电压偏高；
- 拆分前后波形不一致。

所以并不是“CPU拆不开”。

而是：

> **选择了一个不合适的物理参数作为 Stubline 边界，导致 Stubline 自己对原系统产生了过强影响。**

---

## 原因二：原变压器低压侧是 Delta 浮置网络

普通相对地 Stubline 并不是最自然的接口。

而官方差分 Transformer Stubline 方案直接针对：

```text
transformer
floating winding
Delta connection
```

进行了设计。

最终我们采用：

```text
变压器本来已有的低压侧漏 R/L
→ 搬进 Differential Stubline
```

同时显式重构 Delta。

这比：

```text
在外部短馈线上硬插普通Stubline
```

物理上和数值上都更合理。

---

# 5.13 为什么这个成功方案值得你真正学会？

因为它体现了实时仿真的一个非常重要思想：

> **实时分核不是“把模块平均分到几个CPU”这么简单，而是必须先找到可以在数学上解耦的物理边界。**

真正的问题是：

```text
电路方程在哪里可以断开？
断开以后怎样保留原来的物理动态？
怎样加入必要延时而不破坏结果？
```

这比“会拖 RT-LAB 模块”重要得多。

# 第二优先级：彻底区分 GFL 和 GFM

这个项目刚好给了你一个很好的双模式控制实例。

必须搞懂：

## Grid-Following

核心思路：

```text
电网已经存在
↓
PLL跟踪电网
↓
控制我注入多少P/Q
```

应该重点理解：

- PLL 为什么存在；

核心思路：

```text

↓
通过P-f、Q-V Droop调整

像电压源一样支撑系统
```

- P-f droop；
- Q-V droop；
- Voltage Regulator；
- 为什么 GFM 不依赖 PLL 作为最终相位基准；
- 为什么并网/离网时可能需要不同模式。

然后用当前项目再反证一次：

```text
Droop_On
≠
模式选择

GridOn / ConnectMode
才是模式选择
```

如果这一点能完全说清，你对这个 Control System 的理解就已经超过“看懂连线”。

# 第四优先级：认真学习这次 1SM + 3SS 分核，而不是只记操作步骤

这次分核非常值得反复理解。

真正应该学的是：

### 1. 为什么 100 μs 很重要？

因为实时仿真要求：

```text
每一个100 μs仿真步
必须在现实100 μs内算完
```

否则：

```text
Overrun
```

就意味着模型赶不上现实时间。

### 2. 为什么“4核”不等于自动快4倍？

因为一个耦合电路不能随便平均分给4个CPU。

必须：

```text
先从数学上解耦
↓
再分任务
```

### 3. Stubline 为什么能够解耦？

因为：

```text
一步延时
→
消除当前步直接馈通
→
大状态空间拆成多个子网络
```

### 4. 为什么最后是 1SM + 3SS？

因为：

```text
SM：公共高压网络/PCC/上层
SS1：2EV
SS2：2ESS
SS3：2PV
```

形成清晰的物理与任务边界。

这一类知识以后做：

- OPAL-RT；
- HIL；
- EMT实时仿真；
- FPGA/CPU协同；
- 大规模电力电子实时模型；

都会继续用到。

# 第五优先级：AGC 不要背代码，要学“状态是怎么推进的”

老师准备的 AGC 代码值得学，但学习方法不要是逐行背。

你应该先把它改写成普通语言：

```text
目标PCC
-
实际PCC
=
dP
```

然后：

### dP > 0

表示系统需要让 PCC 更“正”：

```text
先增加PV
↓
再让ESS放电
↓
再减少EV充电
```

### dP < 0

需要让 PCC 更“负”：

```text
先增加EV充电
↓
再让ESS充电
↓
最后降低PV
```

再理解：

- 为什么 PV 有 `PVmax`；
- 为什么 ESS 受 SOC 限制；
- 为什么 EV 的符号是负；
- 什么是 headroom / 剩余调节能力；
- `remain` 为什么存在；
- `status` 表示什么；
- 为什么 AGC 1 s 更新，而逆变器控制 100 μs 更新。

```text

但

```

> 一个控制器只要把总 PCC 误差压下去，并不代表内部资源分配就是合理的。

```text
为什么不同资源可能互相抵消？
为什么PCC正确不等于资源状态正确？
```

这已经直接进入后续论文真正的问题。

# 第七优先级：SOC 和 PVmax 应该学什么？

不需要先研究复杂优化算法。

先把基本物理含义学牢。

## SOC

本质：

```text
储能剩余能量 / 可用总能量
```

它不是功率。

需要理解：

```text
功率
经过时间积分
→
能量
→
SOC变化
```

以及：

```text
SOC低
→ 不应该继续大量放电

SOC高
→ 不应该继续大量充电
```

重点是学：

- 功率与能量的关系；
- 积分；
- 正负方向；
- 上下限；
- 初始条件；
- 标幺值。

## PVmax

它不是 PV 当前实际功率。

而是：

> 当前光照、温度等条件下，光伏最多还能发多少。

所以：

```text
Pmeas = 当前实际值
PVmax = 当前能力上限
```

这是“状态”和“能力”的区别。

以后看优化控制、调度和 VPP 文献都会反复遇到。

# 第九优先级：把 V3.2 / V4 的 candidate → commit 学懂

# 第十一优先级：论文阶段真正应该思考什么？

# 最后一页：把今天六个问题压缩成 15 句话

1. 六台逆变器不是全部理想并联，原模型用 5 段 RL 馈线构造了不同电气距离。
2. PV1 直接接主母线，PV2/ESS2/EV2各走一段独立馈线。
3. ESS1 位于中间节点，EV1位于更远的下游节点，因此二者共享一段上游线路并存在电气耦合。
4. Two-Level Converter 是功率执行级，不负责决定 Pref；控制器算调制参考，PWM出脉冲，变流器执行开关。
5. prim 测的是每一台设备自己在变压器高压侧、接入馈线位置的三相 Vabc/Iabc。
6. prim 不是 PCC 总测量，也不是变流器低压侧测量。
7. prim 的 V/I 回到 Control System 是闭环反馈，不是多余绕一圈。
8. “设备接入电网侧三相状态”就是每台设备自己的本地电网端口状态。
9. Droop_On=1 只让构网下垂分支开始计算，不等于模式切换。
10. 当前 GridOn=1，因此最终 Switch 仍选择 Grid-Following 跟网路径。
11. 两套 GFL/GFM 分支可以同时计算，但只有被 Switch 选中的一套真正接管后续公共电流内环和 PWM。
12. PMIO 是物理接口；Stubline 才是通过一步延时实现物理解耦的关键；OpComm 是普通数值通信。
13. Differential Stubline 适合两个端点都浮置的绕组，因此匹配 Delta 次级。
14. 成功分核方案不是凭空加线路，而是把变压器原有低压侧漏 R/L 搬进 Stubline，再用三个单相变压器重建原 Yg/Delta 结构。
15. 对你后续最有价值的学习顺序是：单逆变器闭环 → GFL/GFM → 电力电子功率级 → 实时分核 → AGC状态与资源分配 → V3.2/V4状态提交 → 论文中的执行状态失配与重构。

- 三相变压器可拆为三个单相变压器，并在 Stubline 后重新构造 Y/Delta 连接；
- 用于 RT-LAB 多任务解耦时，Stubline 应位于相应实时子系统的物理边界。
