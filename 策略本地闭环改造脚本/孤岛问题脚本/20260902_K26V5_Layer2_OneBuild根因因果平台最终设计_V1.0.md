# K26_V5｜第二层慢电压塌陷 One-Build 根因因果平台最终设计 V1.0

> 日期：2026-09-02  
> 本版取代 V0.1。  
> **本 Build 只服务“锁第二层根本原因”，不加入工作点重新寻找，不加入新的工程恢复算法。**

## 1. 本次明确不做什么

不加入：

```text
孤岛后自动重新寻找工作点
新的PLL/相角冻结算法
ESS1参数调节
ESS1限值放宽
新的OpWrite
新的跨任务OpComm
```

原因：这些都不是当前第二层根因试验必须变量。

尤其“重新寻找工作点”只有在我们先知道：

```text
究竟应该降低慢电压前馈
还是降低P/Q电流指令动态
还是问题其实来自ESS1能力
```

以后才能正确设计。

提前加入会污染根因试验。

---

## 2. 本次只主动改变两个因果入口

### A：五台GFL慢端口电压前馈

统一写成：

```text
最终电压前馈
=
切换前电压中心
+
慢变化保留比例 × (慢变化电压 - 切换前电压中心)
+
快速变化保留比例 × (原始电压 - 慢变化电压)
```

快速变化保留比例继续使用 Mode7，第二层正式试验固定目标为0。

只改变：

```text
慢变化保留比例
```

基线：

```text
1
```

第一刀：

```text
0.5
```

---

### B：五台P/Q外环形成的电流指令动态

旧C2保持不变。

在旧C2后增加：

```text
最终电流指令
=
切换前电流指令中心
+
功率动态保留比例 ×
(旧C2输出 - 切换前电流指令中心)
```

基线：

```text
1
```

第一刀：

```text
0.5
```

---

## 3. 为什么这两个入口有资格进入本轮

它们不是猜测。

第一条来自已经锁定的：

```text
端口电压
→ Current Regulator
→ Vconv
→ 电流
→ 母线
```

Mode7只证明快速部分必须削弱；慢部分仍100%保留，而慢塌陷随后出现。

第二条来自：

```text
P/Q控制
→ Id/Iq reference
→ Current Regulator
→ 实际电流
→ 母线
```

当前慢塌陷过程中多个GFL支路电流明显变化，因此必须判断这一动态是否参与。

两条正好是 GFL 侧最直接的两个慢母线作用入口。

---

## 4. 为什么这次不主动改PLL/frame

旧B1已经证明它不是第一层快速失稳的必要原因。

当前没有新证据证明：

```text
frame异常先于慢电压下降
```

所以本次不新增 frame 干预。

现有 GFL logger 已经继续记录：

```text
执行相角/频率
原始PLL相角/频率
```

如果本轮 MATLAB 证明它在慢电压下降前先异常，再升级成有证据支持的新分支。

这避免“想到一个可能性就预埋一个试验”。

---

## 5. Layer-2模式

独立新增：

```text
AA15_L2_MODE
```

只在：

```text
AA15_CAUSAL_MODE = 7
```

时有可能产生作用。

模式：

```text
0 当前Mode7同Build基线
1 只降低慢电压前馈
2 只降低P/Q电流指令动态
3 两者同时降低
```

Mode3不是默认运行。

只有 Mode1/Mode2 都显示贡献但单独不足时才运行。

## 6. 同Build基线为什么必须先跑

正式 Patch 增加了：

```text
电压中心状态
电流指令中心状态
两个比例状态
新的logger
ESS1诊断
```

所以必须先证明：

```text
CAUSAL_MODE=7

```

得到的结果与当前正式 Mode7 一致：

```text

慢电压塌陷仍按相近时间尺度复现
```

如果 Mode0不能复现：

```text
禁止解释Mode1/2
```

先查新Build透明性。

## 7. 为什么第一刀使用0.5

不是寻优。

它是中等强度的因果干预：

```text
1 → 0.5
```

足以改变该路径50%，同时比直接0更不容易制造C1/C2式长期冻结副作用。

但：

```text
0.5没有变化
```

不能机械宣布路径“绝对无关”。

根据结果可能需要同Build把运行时参数改到：

```text
0
```

做极端必要性测试。

区别是：

```text
0
```

只有在证据要求时才运行，不是默认第一刀。

---

## 8. 两个比例都带平滑接管

默认：

```text
每100us最多变化0.01
```

所以：

```text
1 → 0.5
约5ms完成
```

干预仍在 J1 前约20ms启动。

于是 J1 打开以前还有约15ms：

```text
新干预已经完全到位
但强网仍连接
```

可以验证干预本身没有先破坏强网运行。

---

## 9. 为什么不会等于C1

C1近似：

```text
所有端口电压变化永久不再进入
```

本轮慢前馈0.5：

```text
仍允许50%慢变化进入
```

而且快速部分和慢部分明确分开。

同时完整记录：

```text
PI是否持续爬升
频率是否漂移
实际功率是否失衡
```

因此即使新干预自己产生副作用，也能通过时间先后识别。

## 11. ESS1本轮只补诊断

现有G30已经保留：

```text
F22
F23
F24
F25
频率/角度
三相电压
P/Q反馈
```

新增13个标量：

```text
Voltage Regulator原始dq输出        2
最终电流参考饱和前                 2
最终电流参考饱和后                 2
Current Regulator实际使用Id/Iq     2
Current Regulator输出Vd/Vq         2

电压调节器Vd测量                   1
```

由此能回答：

```text

↓

↓
电流参考是否碰到±1.25限值
↓
实际电流是否跟上
↓
最终电压指令是否仍有能力
```

ESS1控制本身一个参数都不改。

## 15. 何时运行0.25或0

同一个Build运行时参数可修改。

只有：

```text
0.5已经明显改变结果
```

才运行0.25建立剂量响应。

只有：

```text
需要进一步做必要性极端验证
```

才运行0。

不进行0.4、0.3、0.2式无目标扫描。

## 18. 本Build什么时候算完成使命

不是“某一轮终于稳定”。

而是至少能把第二层问题分类成：

```text
慢端口电压路径主导
P/Q电流指令路径主导
两者交互
两者都不是主因
```

同时 ESS1证据必须告诉我们：

```text
它是否在塌陷开始以前已经触碰支撑限制
```

如果A/B都被排除，而ESS1也未先受限：

```text
才允许打开新的根因分支
```

不会继续凭猜测扩树。
