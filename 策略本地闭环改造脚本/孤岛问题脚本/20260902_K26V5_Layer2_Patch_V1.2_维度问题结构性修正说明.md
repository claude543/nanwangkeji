# K26_V5 Layer-2 Patch V1.2 修正说明

## 本次失败的真正原因

V1.1 的临时预检已经把 Iref 路径改成了标量 d/q 计算，但 VFF 路径仍让 MATLAB Function 直接接收并输出 width=2 向量。

在 Simulink / MATLAB Function 编译时：

- 信号总宽度为2；
- 但一维向量与二维列向量的“形状”仍可能欠定；
- 因此 `v_mode7` 在临时模型中仍无法完全确定维度。

所以 V1.1 失败在 Scratch 阶段，不是正式 K26_V5 改模阶段。

## V1.2 的结构性修复

V1.2 不再尝试修改当前已经验证过的：

`AA15_VFF_DQ_SHAPER`

它保持原样。

新结构变成：

```text
原始Vdq
   │
   ├──────────────┐
   ↓              │
当前Mode7 Shaper   │
   │              │
   ├─ Mode7Final  │
   ├─ Vslow       │
   └─ Kfast       │
          ↓       │
      新L2 VFF Wrapper
          ↓
   Current Regulator
```

新 L2 VFF Wrapper 内：

```text
Raw Vdq   → Demux → raw_d / raw_q
Vslow     → Demux → slow_d / slow_q

所有 MATLAB Function 输入/输出均为标量
↓
cand_d / cand_q
anchor_d / anchor_q
Kslow
↓
Mux
↓
width=2 Vdq
```

Iref 也保持同样原则：

```text
width=2 IdIq
↓
Demux
↓
全标量 MATLAB Function
↓
Mux
↓
width=2 IdIq
```

因此：

> 新增的 MATLAB Function 中已经不存在任何 width=2 向量输入或输出。

## Scratch 也重新设计

Scratch 不再自行重造 Mode7。

它直接从当前已审计、已成功运行的 K26_V5 中复制真实 `AA15_VFF_DQ_SHAPER` 到临时模型，然后把新 L2 wrapper 接在其后。

因此 Scratch 验证的是：

```text
真实现有 Mode7
+
新 L2 VFF wrapper
+
新 L2 Iref wrapper
```

而不是一个“长得类似”的临时替代结构。
